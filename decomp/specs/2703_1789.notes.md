# 2703:1789 指令覆蓋說明

差異測試的覆蓋率是 148/154 指令（96.1%）。未覆蓋的 6 條是同一段不可達的死碼：

| 位移 | 指令 | 原因 |
|---|---|---|
| +0x47 | `xor ax, ax` | 見下 |
| +0x49 | `add sp, 0Ch` | 同上 |
| +0x4C | `pop di` | 同上 |
| +0x4D | `pop si` | 同上 |
| +0x4E | `pop bp` | 同上 |
| +0x4F | `retf` | 同上 |

函式在 `+0x23` 檢查 `星域[+0x12] == 2`，成立就回 0。不成立則跳到 `+0x2C`，那裡**再檢查一次**同一個 byte
（`les bx,[bp+4]`、`cmp byte es:[bx+12h], 2`、`jnz +0x50`）。兩次檢查之間沒有任何寫入，所以第二次的
`jnz` 一定成立，緊接著的 `xor ax,ax … retf`（回 0 的收尾）永遠到不了。`docs/re/292` 已記「原版連寫了兩次」。

分母 154 − 6 條不可達指令 ＝ 148 條可達指令，分子也是 148，所以每一條可達指令都被執行過。這 6 條不可能被覆蓋，
所以未覆蓋的 6 條只能是它們，不是漏測。
覆蓋的路徑包含：編號 0、31 的提早回 0；無主回 0；駐軍回 0；未安定度四段階梯各一；提督營運非 0；
已失格數除法；回傳 1 與 0。提督營運為 0 的輸入原版 #DE（INT 0），探針把這種執行丟棄（向量檔標頭 `# discarded` 記數，丟棄遠少於收錄的 1,018 案），C 版回 0
只為避免 SIGFPE，不在比較範圍內。

死碼是否真的存在以位元組為準，不是推論：`decomp/tools/asm.sh 2703:1789` 的 `loc_35366` 區段。
