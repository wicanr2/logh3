# 068 — 增強 AI 的正常入口與模式生命週期

狀態：**CONFORMED**（2026-10-01，限下列策略接線與模式生命週期範圍）。
2026-10-06勘誤：使用者選擇啟用兩種戰術AI，正常戰場不再被動；第5項及停止線的被動政策由[120](120-active-tactical-ai.md)取代。戰略證據與模式生命週期保持。
工作項目：[Issue #87](https://github.com/wicanr2/logh3/issues/87)。
證據：[研究 357](../re/357-enhanced-ai-player-path.md)，基礎規則與設計來自
[017](017-computer-ai.md)、[029](029-strategic-ai-turn.md)、[031](031-fleet-refit.md)。

審查：DRAFT 的缺兵、載入覆蓋及占領命令門檻均由目前程式與正常 GUI 證據確認；
建隊／整補規則直接沿用已實作原版流程，強化版的參數與目標算法不改。
保留被動戰場裁決，未以假說補玩法，具備本範圍的輸入、失敗模式與驗收。

## 契約

1. `-ai -1` 保持原版戰略模式；`0–3` 選增強策略與既有難度，不調整常數。
   不合法值明確拒絕，不默默變成其他模式。正式入口使用單一設定方法。
2. 增強策略沿用原版建隊與整補，軍事費、庫存、提督、組成與維持費由原規則處理。
   只替換命令決策；攻入非己方目標須下 `MoveOccupy`，仍經正式 PlanStep 閘門。
3. 策略戰力由目前編制依權重 × 艘數 × 1000 ÷ 滿編逐組加總，不依底稿快取。
   有真實編制但戰力為零時保留零；只在欠缺編制／權重的既有診斷資源退回舊快取。
4. 模式／難度是執行期偏好，不進六份原版存檔。載入或新局重接原版建隊來源，
   重設上一局目標／冷卻暫態，但保留已選模式。缺原版資料時不製造替代艦隊。
5. 保留被動戰場裁決；電腦正常戰場不下令、不造成傷害。`Encircle` 的既有可選接線
   保留，不能把診斷模式的攻擊結果用作正常戰術增強的完成聲明。

## 驗收

- 兩側執行前固定 `0xD3DC167E`，正常新遊戲、編隊、實行：原版與增強都實際建敵方艦隊，
  增強命令確實不同。用現況艦數／命令／位置證明作用，不要求增強畫面與原版一致。
- 正常存進度／取進度後模式保持；原版模式與現有原版收據回歸仍通過。
- 增強攻勢在正式 PlanStep 可走入指定邊界目標；自己的集結位置仍用移動命令。
- 現況新編、戰損與零戰力不讀過期快取；對戰兩人座位不跑策略。
- 正式 CLI GUI 至少兩次完整重現；全產品測試通過，模式不進存檔。

停止線：這不是新增 AI 設計或 AI 勝率保證；不宣稱所有局面的包圍最優、不取消
被動戰場設定，不修改原版忠實模式的規則。

驗收結果：兩陣營正常新局與存讀、執行前固定種子、現況戰力及攻勢的正式
`PlanStep` 閘門均通過；正式 CLI 的兩模式各重現兩次，六檔三槽完全一致，
首回合／續回合的命令差異保持。全產品測試 `tools/gui.sh test ./internal/... ./cmd/...`
通過，既有原版正常回合／診斷整表回歸仍通過。完整範圍及雜湊見
[驗證 029](../playtest/029-enhanced-ai-player-path.md)。
