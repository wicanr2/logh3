# 115：戰略打行星的殘留守軍

狀態：CONFORMED，2026-10-05。範圍限本頁清單契約與五案。[#56](https://github.com/wicanr2/logh3/issues/56)。
來源[433](../re/433-strategic-assault-edges.md)及[完整索引](../internals/data/strategic-assault-edges.json)。

## 已證實的規則

- 戰略20B4:1497透過20B4:1512及0E7E仍呼叫203A:04D1，沒有固定0守軍的入口分支。
- 守軍來源是DS:9896筆數及98BA池清單；依陣營、Out、種類0／1、現在位置及行星查詢半徑篩選。
- 艘數累加飽和65535，再除100；反擊先將結果加防衛力，word回繞後除一般10／要塞20。
- 實際地形必須傳入定位。原版六次拒絕(936,1452)，正式Passable及typed終態符合；nil地形反例不同。
- 空清單時保持既有0守軍；近距／Out／遠距與地形五案的修法副本已通過限定欄位比較。

## 正式介面與生命週期

[434](../re/434-strategic-guard-lifecycle.md)固定原版雙跑證實8-1重建後，
8-5返回、下一星域27的1497／1512及載圖到返回均保留同一份55筆清單。
原版清單不按新星域篩選；查詢從目前原池讀取。

- `StrategicPlacement.Guard`每次反擊前接受當下行星記錄。nil只代表沒有清單來源的既有純規則入口。
- `NewStrategicGuard`接受Slot與明示池索引，先驗證所有索引，再保存索引副本；每次查詢重讀Slot原SHIP池。
- Game用戰後保留的`battleUnits`取得池索引，只用其Fleet／Squadron身份。不得用其艘數、座標、Out快取算守軍。
- 不添加星域或艦隊士氣篩選。Out、陣營、種類及半徑條件沿用已證實原版契約。
- 清單為空返回0。非空清單缺Slot、池越界或身份無法解析時回錯誤，停止逐星域流程；不當成0。
- Guard在攻擊降低防衛力後、反擊前呼叫；半徑依當下防衛力。加法先word回繞，再除10／20。
- 不改六份存檔格式，不把戰場工作清單新增到存檔。保存測試核對此次戰損、行星、功績與分數讀回。

## 驗收與聲明範圍

正式規則須重跑433的五案，帶實際地形的指定typed欄位零差，忽略地形的反例仍失敗。
Game須驗清單選擇、活原池、正常戰後保留與錯誤停止，再補保存／讀回與正常占領玩家路徑。
原池完整副作用另列限制；未驗完整六表前，不稱整份存檔same-state。
本規格READY只授權上述實作，058整項不因原版雙跑或副本通過升格。

## 原池寫回接線審查

正式typed接線的五案與保存已通過，但保存前與原版全表比較仍各有FLEET7、SHIP88 bytes差異。
共用20B4:1512的既有110原池常式在回合0，容器副本只放寬「池必屬目前星域」的入口驗證，
同五案完整六表、清單與seed均零差。探針為`tools/strategic_guard_raw_probe.sh`，
不是另一套反擊算式；原始五案固定種子及輸入不變。

因此READY接線增補以下契約：

- 新增`NewStrategicOccupation`，固定起始回合0，沿用110已驗的1512原池寫回與報告續接常式。
- 勝方入口的原池身份驗證保持；戰略入口只驗保留池索引界限，不要求屬新星域，也不擅加陣營／編制過濾。
- Game有Slot時同步目前六表與兩組分數，執行原池常式，逐則收集既有戰略報告，重讀艦隊；功績與分數只提交一次。
- 新遊戲尚無Slot且清單空時維持既有typed入口；非空清單缺Slot仍停止。這個既有資料生命週期不在本輪改寫。
- 正式Game在保存前先逐byte比較完整六表與清單，再驗六檔保存讀回。正常占領與勝方入口回歸須保持。
- 未覆蓋的星域、正常原版整回合及GUI不因五個注入案例升格。

## 限定驗收

正式規則及Game五案完整六表／清單／seed相同；六檔保存重讀、活原池與索引錯誤停止通過。
前一星域池可進戰略入口，戰場勝方入口仍拒絕異星域池；EndBattle保留池身份通過。
正常占領玩家路徑及既有勝方67案、保存、報告等待回歸保持，見[088](../playtest/088-strategic-guard.md)。
新遊戲沒有Slot的既有typed分支不外推完整原池；正常原版整回合與新GUI收據未在本輪宣稱。
