## 原版做什麼

每個回合，在逐座位取得控制**之前**、在月底那道十回合閘門**之前**，
`0654:0007` 先呼叫 `2B5F:02B2` 掃一次 32 個星域：

```
for 星域 k in 0..31:
    if 星域[+0x12] == 2:  continue          # 無主星域不補
    if 星域[+0x13] & 1:   continue          # 到自己首都的路徑成本 >= 0x400 → 不補
    上限 = 星域[+0x1A]（經濟力，32 位元）＋ 星域[+0x20]（防衛力，16 位元）
    補   = ⌊上限 ÷ 10⌋
    擁   = 星域[+0x12]
    星域[+0x68 + 擁×4] = min(星域[+0x68 + 擁×4] ＋ 補, 上限)   # 飛彈
    星域[+0x70 + 擁×4] = min(星域[+0x70 + 擁×4] ＋ 補, 上限)   # 艦載機
```

三件事要一起看，少一件就會做出「數字對得上但機制錯」的實作：

1. **只補擁有者那一份。** 每個星域的 `+0x68`／`+0x70` 各有兩格（帝國、同盟），
   補的只有 `星域[+0x12]` 指到的那一格；另一方那一格原封不動。
2. **上限是那個星域自己的經濟力＋防衛力**，不是全國的、也不是行星檔裡
   的原值。`PLADAT.DAT` 給的開局存量遠高於上限（奧丁 200000 vs 108600），
   所以**第一個回合就被夾下來**。
3. **這兩格是雙向的。** 回合尾巴的 `2703:12EB` 會把它們清零、再從每顆行星的
   `+0x3C`／`+0x40` 重新彙總；同一個回合尾巴的 `2703:051D` → `2703:0540`
   → `2703:0590` 則反過來按行星經濟力比例把星域層的量分回行星。
   **回充之所以有意義，是因為分配那一步在同一個回合裡發生**
   （`docs/re/273` §4 有執行期序列）。

## remake 實作

- `internal/rules/region_supply.go` 保存星域兩陣營存量、行星彙總、原版回充及
  `2703:0590` 的整數百分比分配；不混入七種艦艇池的另一份工作。
- `Game.advanceTurn` 在每回合計數進位後、AI 與月底結算之前呼叫
  `refillRegionSupply`，逐一處理 32 個星域。
- `TestRefillRegionSupplyMatchesOracle` 從 `re273_rpre.bin` 生出完整 4,032 bytes，
  與 `re273_rpost.bin` 逐位元組相同。
- `TestDistributeRegionSupplyRemainderGoesToLastLargestPlanet` 釘住整數捨去、餘數
  與同值最大行星規則；`TestAdvanceTurnRefillsRegionSupply` 釘住產品接線。

## remake 要做什麼

1. `internal/rules` 加星域記錄的兩個欄位常數與一支純函式，簽名大致是
   `RefillRegionSupply(record []byte)`：照上面那五行做，**不做別的**
   （擁有者、旗標、上限、補量、夾）。
2. `Game.advanceTurn`（或它呼叫的回合前段）**每個回合**對 32 格各跑一次，
   位置在月底結算之前——原版是 `0654:0007` 裡 `mod 10` 那道閘門之前。
3. 行星的 `+0x3C`／`+0x40` 要跟著動，照抄原版兩層：先以行星現值彙總星域
   兩陣營存量，完成擁有者回充後，再分配回各顆同陣營行星。對每個陣營：
   - `totalEconomy = Σ 同陣營行星經濟力`；為 0 就不分配；
     （原版 `2703:0590` 沒有這個判斷，總和為 0 時走 `3CC9:0020` 的除以零路徑，商 `0xFFFFFFFF`；遊戲內總和是否可能為 0 未知，見 `docs/internals/67`）
   - 每顆的整數百分比 `pct = floor(economy × 100 / totalEconomy)`；
     （原版是 `economy × 100` 的低 32 位元做有號 32 位元除法；經濟力約 5×10⁴ 時與此式等價，`>= 21,474,837` 才不同，見 `docs/internals/67`）
   - 飛彈、艦載機各寫 `floor(regionPool × pct / 100)`，並從餘額扣除；
   - 全部逐顆捨去餘額加給經濟力最大的行星；同值時後出現者取代前者。
4. 驗收：同一個輸入序列跑到回合 1，把 32 格的兩格與 `re273clamp` 的
   `re273_rpost.bin` 逐位元組比。

## 完整回合接線訂正（CONFORMED，取代上面歷史接線）

證據：[研究 353](../re/353-region-supply-turn-timing.md)，重生入口
`tools/region_supply_receipts.sh`。`supply84-stationed`／`-r2` 從相同完整
檢查點固定原版 RNG，12 個階段各 1 MB 記憶體及完整畫面／色盤逐位元組重現。
指定樣本涵蓋首都停駐艦隊補艦艇及兩種戰術存量、星域 1 無艦隊、全 32 格回充。

1. 命令開始不再彙總／回充／分配；現有開局契約仍依 [065](065-opening-runtime-tables.md)，
   開局彙總兩陣營七種艦艇與兩種補給，再只回充星域，不寫回行星。
2. 艦隊全部移動後、重數艦隊之前，`056A:0048` → `2703:051D` 對 32 格兩陣營
   分配七種艦艇與兩種補給；只讀當時星域池，不先重新彙總或回充。
3. 逐格 `1930:1572` → `1AAB:0FAF`：先向艦隊分配兩種補給，再無條件從行星
   彙總七種艦艇及兩種補給（`2703:12EB`），補足艦艇後無條件分配回行星
   （`2703:0540`）。無主星域仍依 063 跳過；負缺口夾零的既定裁決保留。
4. 回合尾巴 `2703:08DE` 的擁有者重算先經 `15D5` 刷新行星數、經濟比例、
   防衛力與防衛上限；態勢後的 `12EB` 再彙總各種庫存。比例不得留在開局值。
   此處 `0DA1` 只重算未安定度，不能連帶重刷星域經濟力及預估稅；
   `02E5` 的共同重算在下一座位回充之後。原版同盟首都回充時經濟力仍為
   65826，回充後才更新為 66530；提早刷新會把兩格上限各多加 704。
5. 下一個命令階段前，`0654:0015` → `2B5F:02B2` 只改星域兩種補給池，
   不彙總、不分配；位置在月初成長／稅率／交付之前。`0654:001A` 為返回位置，
   由固定原版記憶體的 `9A B2 02 5F 2B` 直接呼叫位元組及執行期命中確認。

審查：既有寫入端與新階段收據支持上述有限接線，准升 READY。

166 bytes、正常回合星域全表 74 bytes 不同。沒有新增允許差異區域。

驗收結果：分配後全 81 顆行星、下一座位回充後全 32 格星域及全 81 顆行星

星域 18／行星 15 bytes 差異，保存所有位置與原值，交 [#85](https://github.com/wicanr2/logh3/issues/85)
追查；這些不是允許差異，也不因庫存驗收通過而標為已解。
沒有注入的正式 GUI 全畫面色號／RGB 零差異，正常存讀檔、跨月交付及全產品
套件通過。收據：[對拍 026](../playtest/026-region-supply-turn.md)。
