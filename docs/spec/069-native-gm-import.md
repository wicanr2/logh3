# 069 — 原生 MDS 匯出與 GM 匯入階段

狀態：**CONFORMED**（2026-10-01，限下列階段）。工作項目：[#69](https://github.com/wicanr2/logh3/issues/69)。
證據：[研究 358](../re/358-native-gm-import.md)、[MDS 參考](../internals/17-mds.md)、
[音色庫定案](../re/356-player-music-library.md)。

審查：既有 Python 匯出器、22 首原始資料與保存 MIDI 是移植基準。
原生程式沿用既有輸出，不增加未知事件猜測；未確認時間語意保留近似警示。
玩家不需 Python／shell／Docker，由單一原生程式呼叫隨包工具；封裝不屬本階段完成聲明。

## 輸入與處理

1. MDS 原始 bytes → 固定四 bytes 的 typed events → MIDI format 1，48 ticks／拍。
   原始 M1 簽章、0x100 邊界、完整事件、FE FE FE FE 軌界與非空音符軌須驗證；
   拒絕截斷、損壞軌界及超過 1 MiB 的 MDS，沒有原版時測試 skip。
2. 以原有眾數／同票首次出現決定小節長度；超過 90% 小節引數 ≤2 才信任引數。
   保留既有通道夾到 0–15、raw 事件處理、FA BPM 近似及穩定排序，逐 byte 核對 22 首。
3. 命令 `music-import -gm-only -source <自備原版目錄> -output <曲庫目錄>`。
   當前階段須明示 `-gm-only`；選定或預設十一首 `_M`，拒絕 `_F` 而非改用 GM。
   合成器／編碼器預設在程式旁的 tools 目錄，音色庫在 soundfont/FluidR3_GM.sf2；
   診斷可明示絕對工具目錄／音色庫。不得從 PATH 找工具或下載玩家缺失依賴。
4. 啟動前驗 SF2 長度／SHA-256、工具檔存在及所有選定輸入的可解析性，
   原始輸入唯讀；輸出不能位於原版目錄內。不存在的來源、無效曲名、空清單明確失敗。
   每首合成／編碼有逾時；先在輸出內暫存，成功解碼 OGG 後再提交單曲。
   缺工具、合成或編碼失敗須明示，不寫假成功收據；保留先前成功曲目，不冒稱全批成功。
5. 收據保存來源／MIDI／OGG 雜湊、工具與 SF2 雜湊、完整參數、近似等級。
   OGG 位元流的序號等 metadata 可能不同，GM 以 MIDI 精確值及解碼 PCM 比較，
   不冒稱 GM 原版 MPU 音色一致，也不修改 FM 的 SOURCES.tsv 判準。

## 驗收與停止線

22 首真實 MDS 的 MIDI 與現有保存版逐 byte 一致；錯誤輸入、錯誤音色庫、缺工具、
輸出覆蓋原始目錄及 FM 錯誤分流均拒絕。真實 Linux 原生入口產生 GM OGG，
核對 44100 Hz、立體聲、可解碼、時長及非靜音，與舊命令生成的 PCM 比較。
至少再抽兩份特殊 GM：END_2 與 OPEN_M；輸出交給正式播放層解碼。
標準產品測試通過，來源未變、擁有權與容器清理核對。

不改遊戲存檔／音訊設定與播放選曲；FM、三平台封裝、實際聆聽及 loop 接點仍未完成。
本階段通過後 #69 仍保持開啟；只有整個玩家自產曲庫管線達到 Issue 判準才關閉。

驗收：22 首 MIDI 逐 byte 一致；十一首 GM 真實轉檔／正式播放層完整解碼通過，
三首 PCM 與舊命令完全一致；前置拒絕、跨平台程式建置及完整產品測試通過。
結果與實際身份見[驗證 030](../playtest/030-native-gm-import.md)。
