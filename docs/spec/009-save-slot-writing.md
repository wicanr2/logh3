# SPEC 009 — 存檔寫出

狀態：**CONFORMED**（已實作；讀一格再寫出去，六個檔與原版逐位元組相同）
證據：[`docs/re/41`](../re/41-save-files-are-the-runtime-tables.md)、
[`docs/internals/30`](../internals/30-save-format.md)
規格相依：[`005`](005-save-slot-loading.md)（讀存檔）

**2026-10-01 勘誤／延伸**：早期驗收只覆蓋未操作的載入存檔與新遊戲空表底稿。
實際編隊後不能一直保存全 FF 的 FLEET／SHIP；現況同步、正常玩家存讀與續回合
已由 [067](067-live-fleet-save.md)／[研究 355](../re/355-live-fleet-save.md) 補齊。
下文「空表」「尚未接 UI」等早期限制不得再當成現行保存入口；未知欄位仍按底稿保留。

## 要做什麼

存檔就是執行期那幾張表原樣寫出去，所以「存檔」沒有格式轉換——把手上的
表直接寫成六個檔，再更新 `SAVEDATA.IDX` 的目錄。

## 寫哪些

| 檔案 | 內容 |
|---|---|
| `STELLAR.DT?` | 星域表 32 × 126 |
| `PLANET.DT?` | 行星表 81 × 82（**去掉** `PLADAT.DAT` 的 64 bytes 檔頭）|
| `ADMIRAL.DT?` | 提督表 82 × 28 |
| `FLEET.DT?` | 艦隊表 32 × 122 |
| `SHIP.DT?` | 艦艇池 352 × 78 |
| `WORK.DT?` | 全域狀態 230 bytes |

`WORK` **只改解出來的三欄**（回合數 `+0x04`、軍事費 `+0x3E`、
總稅收 `+0x56`），其餘 227 bytes 照抄。那些還沒解，動它等於把不懂的
東西寫壞。`SAVEDATA.IDX` 同理——只改回合數與名稱，開頭那 12 bytes、
序號與 `FF FF` 原樣留著。

## 兩條硬規則

- **不寫進原版目錄**。輸出目錄由呼叫端給，`org_game/` 一律唯讀
  （`AGENTS.md` 的素材邊界）。
- **新遊戲的 `WORK` 用量到的底稿**。`WORK.DTX` 不存在，但 `WORK.DT?` 就是
  `ds:8F14` 起那 230 bytes（`docs/re/45`），所以新遊戲那一份可以量：
  量到的整塊在 [`data/work-796-01.json`](../internals/data/work-796-01.json)，
  回合 0、軍事費 50000、總稅收 10201。存新遊戲時拿它當底稿再蓋掉三個
  已解的欄位——**remake 沒有模型的那些欄位會停在 796 年 1 月的初值**，
  局面走得越遠越不準。艦隊表與艦艇池填 `FF`（開局沒有艦隊）。

## 驗收

- `internal/rules.TestSlotSaveRoundTrip`：讀第 9、第 10 格再寫出去，
  六個檔**逐位元組**與原版相同。
- `internal/rules.TestWriteSaveIndex`：把目錄寫回原值之後與原版一個 byte
  都不差；改回合數與名稱不會動到序號與時間戳。
- `internal/game.TestSaveSlotRoundTrip`：走完「取進度」那條玩家路徑
  （`docs/spec/007`）之後直接存到另一個目錄，六個檔與原版相同——
  只有 `STELLAR` 的未安定度那 32 個 byte 允許不同，因為載入時重算過
  （`docs/spec/006`）。

## 不在這份規格裡

- **「存進度」畫面的版面**：那張畫面只有 8 列（畫面 y ＝ 142 起、每 20 px），
  比「取進度」的 11 列少，而且選中的那一列畫成一條**色號 2 的實心條**、
  蓋掉文字。條子跟著點的位置走——收據 `save1e` 開畫面時停在第 162 列，
  改點滑鼠 y ＝ 102（畫面 142）之後條子就移到 142（收據 `save3e`）。
  少了哪三列、以及點下去之後怎麼輸入名稱，都還沒解，所以「點哪裡存到
  第幾格」還沒接起來。
- 存檔時間戳怎麼寫（`SAVEDATA.IDX` 開頭那六個 byte，`docs/spec/008`
  的解法只有一組樣本）。
- 新遊戲存檔裡那 227 bytes 的其餘欄位（見上）。
