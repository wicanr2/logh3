# SPEC 033 — 回合結束的星域歸屬鏈

狀態：**CONFORMED**（已實作；整條鏈的同狀態收據做出來了，三個局面逐格相同）
證據：[`docs/re/17`](../re/17-star-region-owner.md)（擁有者規則）、
[`docs/re/105`](../re/105-battle-does-not-capture-region.md)（戰鬥結束不寫 `+0x12`）、
[`docs/re/150`](../re/150-planet-capture-receipt.md)（佔領寫進行星記錄）、
[`docs/re/151`](../re/151-planet-capture-condition.md)、
[`docs/re/244`](../re/244-region-posture-recompute.md)（重建時機與順序）
相關：[`docs/spec/032`](032-region-posture.md)（`+0x13`／`+0x24` 怎麼算）

## 原版的鏈

```
戰鬥中：20B4:0503   打下行星 → 直接寫行星記錄 +0x11（以及庫存那幾格）
回合結束：
  for 星域 i:
      2703:159B(i)          ; 依行星重算 +0x12，回「有沒有變」
      易主的走 056A:0855    ; 通知那一側的座位
  2B99:0003                 ; 重建四張路徑表
  for 星域 i:
      2703:0933(i)          ; +0x13 的 bit0/bit2/bit3 與 +0x24
      2703:12EB(i)          ; 艦艇彙總
      2703:0DA1(i)          ; 未安定度
  判勝負                     ; 瓦爾哈拉落到同盟 → 5、巴拉特落到帝國 → 4
```

星域歸屬的規則是 `2703:15D5`：**全屬同一方才算那一方的，只要混雜就是
無主**（`docs/re/17`）。

**`+0x12` 不在戰鬥結束時寫**（`docs/re/105` 兩份收據）——它在回合結束
才依行星重算。所以「打下一顆行星，星域當場變色」不是原版行為。

## remake 缺的是什麼

原版整場戰鬥都直接改行星記錄，沒有「戰場副本」。remake 為了讓戰場層是
純函式而先複製一份（`BattlePlanetsFor`），**那份從來沒有寫回去**——
於是佔領、防衛力損失、要塞砲狀態與被打掉的存量打完就消失，每一場戰鬥
都從原始狀態重開。行星擁有者既然不變，星域擁有者也永遠不變，路徑表與
`+0x13` 跟著全部凍住。

## 做了什麼

1. **`rules.Planets.ApplyBattlePlanets(bp)`**：把 `+0x11`（擁有者）、
   `+0x14`（防衛力）、`+0x45`／`+0x50`（要塞砲）與 `+0x20`–`+0x40`
   （庫存）寫回行星表。`EndBattle` 呼叫它。
2. **`Game.recomputeRegions()`**：逐格 `Planets.RegionOwner` 寫回 `+0x12`，
   再用 `StarGraph.Postures` 重建路徑表並填 `+0x13`／`+0x24`。
   `advanceTurn` 在艦隊移動之後呼叫。

順手修掉一個讀法：`+0x50`（要塞砲方位）是 82 位元組記錄的**最後一個
word**，原本用 `le32` 讀，長度不足就回 0，所以那一格永遠讀成 0。改成
讀 16 位元。

## 不在這份規格裡

- **`056A:0855`（易主通知）**：它看 `ds:8F21`／`ds:8F22`（座位）決定要不要
  跳訊息，是畫面不是狀態。
- **`2703:12EB`（艦艇彙總）與 `2703:0DA1`（未安定度）**：remake 的面板各自
  現算，不需要這一圈。
- **判勝負**：remake 還沒有勝負條件。

## 戰鬥那條路徑

**原版打完會走完整條鏈**，證據就在 `docs/re/105` 那份 `s3win` 收據裡：
它記的兩個寫入點 `2703:0944` 與 `2703:0990` 是 `2703:0933` 的內部指令
（`and byte es:[bx+13h], 0F2h` 與 `or byte es:[bx+13h], 8`），而
`2703:0933` 只有兩個呼叫者——新遊戲初始化與 `2703:08DE`。戰鬥中不會是
前者。

那份收據看到 `+0x12` 沒變，是因為達希利的行星仍然混雜、重算出**同一個
值**，不是因為沒有重算。

所以 `EndBattle` 在把行星寫回之後也呼叫 `recomputeRegions()`。

**時機還沒釘死**：`s3win` 跑的是 `-press-every 2000000`，全程都有按鍵，
所以分不出那一圈是在同一次「實行」的尾巴跑的、還是下一次「實行」的開頭。
差別最多是地圖顏色早一次「實行」更新。要分辨得再跑一次，同時監看回合
計數器 `ds:8F18`（線性 `5DA48`）與那一格的 `+0x13`。

**月底結算沒有一起搬**：`advanceTurn` 遇到戰鬥仍然提早 `return`，
底下的月底那一段不會跑。原版在戰鬥回合會不會結算**沒有證據**，
不憑結構相似就搬過去。

## 整條鏈的同狀態收據

做出來了（`docs/re/246`）。新遊戲按一次「實行」，把星域 4 唯一那顆行星的
`+0x11` poke 成 1（`lin:5351B`），比對 poke 前後的 32 筆星域記錄：

| 星域 | 基準 `+0x12` `+0x24` `+0x13` | poke 後 |
|---:|---|---|
| 0 | 0　　0　00 | 0　　0　**08** |
| 2 | 0　 15　00 | 0　 15　**08** |
| 4 | **0**　**14**　**08** | **1**　**4218**　**09** |

星域 4 依行星重算成同盟、`+0x24` 變成到巴拉特的成本
`4218 ＝ 1024 × 4 ＋ 122`、bit0 跟著起來；鄰居 0 與 2 變成前線（bit3）。
`rules.BuildTables` ＋ `Postures` ＋ `Occupations` 拿傾印自己的狀態重算，
**三個局面**（S3 中局 18 支艦隊、新遊戲第一回合 3 支、以及 poke 之後）
的 `+0x24` 與 `+0x13` bit0–bit4 全部逐格相同
（`TestPosturesMatchOracleReceipts`）。

收據：[`data/region-posture-chain4.json`](../internals/data/region-posture-chain4.json)、
[`data/region-posture-s3ai6.json`](../internals/data/region-posture-s3ai6.json)。

## 還沒做：易主報告

原版每有一格易主就跳一則「**XX星系　已被敵軍占領。**」的報告
（`056A:0855`），而且它**擋住回合結束處理**——第一次跑收據時
`2703:08DE` 零次執行，就是停在那則報告上（`docs/re/246`）。
remake 的 `recomputeRegions` 只回「有幾格易主」，沒有把它變成畫面。
