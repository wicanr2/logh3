# 121：月初報告按鈕與下拉選單游標

狀態：**CONFORMED**（2026-10-06，限定本規格的remake輸入接線）。使用者回報 v.0.1.2 Linux 正常操作阻塞，授權修復。

依既有座標契約審查READY後實作，兩陣營可見按鈕、七列箭頭與百分比存讀通過。新Linux完整版真實X11兩倍率48張全圖零差，標準13套件通過；Windows／macOS同步重建，真機仍待驗。[107](../playtest/107-player-input-hotspots.md)保存結果，未升格原版精確事件碼或全遊戲parity。

入口：[驗收107](../playtest/107-player-input-hotspots.md)、[研究441](../re/441-player-input-hotspot-space.md)。

## 證據與審查

既有研究52確認 Game 公開滑鼠輸入是畫面座標，Cursor 原版座標低40像素。研究259最後勘誤明確指出會計報告熱區使用畫面減40的滑鼠座標。三份實際 JSON 的熱區均比繪製按鈕高40像素；原封包正常 X11 重現可見按鈕點擊無作用。三個選單的固定 Mouse 位置不由 Game.Frame 更新，造成可見游標停住。這些是既有契約的實作缺陷。

## 契約

1. Game 公開輸入維持畫面座標。只有會計、訂造及建造計畫的舊熱區在呼叫 HitTest 時轉換 y−40。其他畫面不變，原始 JSON 與格子證據保持。
2. 會計報告變更開預算計畫，確認開訂造報告。訂造報告變更開建造計畫，確認走現有右鍵關報告與月初結算路徑。建造計畫結束及右鍵返回訂造報告；已更新的百分比保留。確認及結束是 remake 按鈕接線，不新增原版精確事件碼宣稱。
3. 三種下拉選單、訂造報告及建造計畫的可見游標使用當前畫面滑鼠位置。既有固定收據位置不再控制正式玩家游標。這五份 Mouse 沒有位置特定裁切或補丁，不擴大其他疊層的修正範圍。
4. 建造計畫的動態數字先畫，再畫游標，避免數字蓋住箭頭。
5. 不改規則、存檔格式、AI、音訊或雙玩家／戰場驗收門檻。新修訂版打包，舊版交付保持。

## 驗收

- 回歸使用可見按鈕座標，驗兩份報告、預算返回、七列箭頭、建造結束與百分比存讀。
- 三種下拉選單及兩份訂造畫面的可見游標移動。
- 正式 GUI 由片頭、主選單、防拷正常進入，使用真實 X11 滑鼠與按鍵。帝國與同盟、1.5倍與2倍抽樣，核可見按鈕及選單項目並保存實際視窗截圖。
- 標準測試、新版包 manifest／SHA-256／正常啟動、擁有權與容器清理通過。不以 CLI 腳本代替實體輸入收據。
