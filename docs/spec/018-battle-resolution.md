## 資料

戰鬥期間每個分隊要帶的欄位（原版的艦艇記錄，`docs/internals/38`）：

| remake | 原版 | 用途 |
|---|---|---|
| `Faction` | `+0x00` | 陣營 |
| `Fleet` | `+0x01` | 所屬艦隊 |
| `Kind` | `+0x04` | 艦種 |
| `Ships` | `+0x08` | 現有艘數（會被扣）|
| `FullShips` | `+0x0A` | 滿編艘數 |
| `Attack` | `+0x16` | 攻擊力：決定射程，也是單擊係數的分子 |
| `X`／`Y` | `+0x28`／`+0x2A` | 現在的位置 |
| `TargetX`／`TargetY` | `+0x34`／`+0x36` | 要去的點——**空間查詢比的是這一組** |

## 射程（`READY`）

```
射程 ＝ Attack ÷ 200 ＋ 80
```

出處 `2350:0003`：`+0x16 ÷ 200 + 80` 寫進 `ds:A772`，另存一份 `÷4` 到
`ds:A774`。挑名單時用的門檻是 **`射程 × 2`**。

## 攻擊名單（`READY`）

`17A0:00AC(陣營, x, y, 門檻, 輸出)`：走參戰分隊名冊，收下同時滿足

1. `Faction` 等於參數；
2. 沒有被標成出局（原版看 `+0x1E` 的 bit7）；
3. `距離((x,y), (TargetX,TargetY)) ≤ 門檻`（歐氏距離）

的分隊，先陣營 0 再陣營 1，最後排序。

remake 這邊只需要「在範圍內的敵方分隊」，所以實作成

```go
func InRange(units []BattleUnit, x, y, limit, faction int) []int
```

回索引，呼叫端自己決定要哪一邊。**排序照原版還沒解**，remake 依名冊順序
——這一項標 `DRAFT`，不能拿去對拍。

## 一輪的總損失（`READY`）

`rules.BattleDamage`（`docs/re/86`）：

```
基本量 ＝ (艦種 1 艘數總和 ÷ 100 ＋ 艦隊 +0x14) ÷ (10 或 20)
距離項 ＝ 基本量 × (距離 ÷ 150) ÷ 5
攻擊力 ＝ (基本量 − 距離項) × 方向係數 ÷ 100
總損失 ＝ 攻擊力 × 100 ÷ 防禦係數 ＋ rand() mod 100
```

方向係數表 `[80,85,90,95,100,95,90,85]`，索引 `((|方位−朝向| ÷ 16) ＋ 1) ÷ 2 & 7`。

## 損失分攤（`CONFORMED`）

`rules.DistributeLosses`：按各分隊佔全隊現有艘數的比例分攤，餘數補給最大
的一支，每支至少留一艘，艦種 7 不扣。

## 什麼時候開戰

原版在雙方的艦隊走到同一個星域的那一刻直接切進戰術畫面
（`docs/internals/34`「怎麼走到」：載 S3 按六次「實行」，兩邊會合在
達希利就開戰）。remake 在推進回合、艦隊移動之後檢查一次：有星域同時
站著兩個陣營的艦隊就開戰。

**還沒解**：同時有多個星域符合時原版打哪一個（remake 取編號最小）、
幾支才算、能不能迴避。remake 走幾回合會合也不會與原版相同——移動是
「一回合走一格」，那本身是假設待驗（`docs/re/77`）。

## 玩家怎麼推進

原版：**同一點連點兩下**——第一下在游標處開一個小選單、第二下選中第一項
「實行」，等於結束我方輸入（`docs/internals/34`：`s3turn2` 連點兩次兩回，
畫面從第 1 回合走到第 3 回合）。

remake 目前只重現**輸入契約**，還沒把選單畫出來。選項與版面都量到了
（`docs/re/98`、`docs/internals/data/battle-menu.json`），框的逐層結構
還沒拆，所以畫出來的框會是近似的。右鍵取消第一下。

## 每回合的流程

```
1. 兩邊下令（戰略層／戰術層 AI，或玩家）
2. 分隊往目的地移動（rules.AdvanceBattle）
3. 結算——**以行星為中心**（`docs/re/99`）：
     for 每一顆有主的行星 P:
         量 ＝ Σ{艦種 0 或 1、陣營 ＝ P 的擁有者、距 P ≤ 防衛力÷25} 現有艘數
         for 每一支敵方艦隊 F:
             總損失 ＝ BattleDamage(量, P 的防衛力, P↔F 旗艦的距離,
                                   F 的朝向與方位, F 的防禦係數, 亂數)
             DistributeLosses(F, 總損失)
4. 回合數 ++
5. 打滿九個回合（`rules.MaxBattleTurns`）或一方歸零 → 結束
```

**哪些（行星, 艦隊）配對會交火、順序如何**，原版還沒逆向——這裡對每一顆
有主的行星、每一支敵方艦隊各算一次。

### 九個回合就結束

原版的主迴圈是 `while ds:8F1A < 9`（回合 0 起算），所以**一場戰鬥最多
九個回合**，畫面上印的是第 1 到第 9（`docs/re/92`）。remake 照這條走：
`battleTurn` 超過 `rules.MaxBattleTurns` 就把 `battleOver` 設起來。

另外原版有提早出口：每個回合結束時在游標處開一張**戰術選單**
（`12AA:02D4`）——實行／資料／撤退／取進度／存進度／設定／結束
（`docs/re/98`）。選「實行」繼續下一回合，選其餘六項跳出主迴圈。
選單的版面量完了（`docs/re/101`），remake 照畫、逐位元組相同；
`Game.battleClick` 實作「實行」與「撤退」；後四項的字串與戰略地圖上
「系統指令」的後四項一字不差，所以接到同一組畫面（取進度／存進度／
設定／結束）。**離開之後會不會回到這一場戰鬥還沒逆向**——remake 不動
戰場狀態，純粹換畫面。第二項「資料」的畫面取出來了（收據 `s3data`，`docs/re/109`）：它蓋掉
戰場、小地圖與狀態欄三塊（139,626 個像素），左邊一張大表、右邊兩塊窗。
**版面還沒逐位元組量**，所以 remake 對那一項維持「只關掉選單」。另外多一個保守條件：真的有一方歸零。

分攤那條**每支分隊至少留一艘**（`203A:0593` 的第四個參數為 0），所以光
靠消耗不會歸零——九回合的上限才是實際會生效的那一個。

### 走過但沒結果的兩條路

留著免得下一輪重跑（第三次換了入口才成功，見 `docs/re/92`）：

- **從 `1EC0:00B9` 往上追**：那個呼叫點所在的函式起點是 `1E9B4`，唯一
  的呼叫者是 `1E50A`。讀下來它是**另一條扣除算式**（依艦艇記錄 `+0x2E`
  的 0／1／2 分三支，各拿艦種表 `ds:B77C`／`ds:4E3A` 的不同 word 乘現有
  艘數），不是「戰鬥結束時清場」。所以「`1EC0:00B9` ＝ 殲滅」這個標籤
  本身要重新檢討。
- **找回合上限**：拿 `s3turn2`（第 3 回合）與 `s3fight`（多推八回合）
  兩份記憶體傾印對，找不到任何一個 byte 或 word 是 3 → 11。回合數存在
  哪裡還沒定位，所以也還沒辦法搜「跟上限比較」的指令。

第三條路走通了：**先用 remake 自己的字型把畫面上的數字反推出來**，再拿
數字去記憶體定位（`docs/re/92`）。回合數是 word 不是 byte，而且
`s3fight` 是第 5 回合不是第 11——前兩條路各卡在其中一個。

第 3 步用的是**艦隊層**那條（`21A0:0004` ＋ 比例分攤），而收據證明
**那正是原版在戰鬥裡跑的那一條**（`docs/re/97`：`-regs-at 20B4:1110`
探到六次，步數與扣除交錯；單擊那條 `2350:0023` 整場 0 次）。
所以這一步不是「remake 的取代」，是同一條。

單擊那條（`2350:0023` ＋ 分母 K 的橢圓，`docs/re/94`）解出來了但原版
沒在用，`rules.AttackCoefficient`／`ShipKindTable.SkirmishAttack` 留著
當保存成果，不接進結算。**在那之前艦隊層這條是 remake 明講的取代，不是對拍過的行為。**

## 分數

```
每扣一個分隊：分數[1 − 被扣一方的陣營] += 扣掉的艘數 ÷ 20
勝利點 ＝ 分數[0] − 分數[1]
```

除法**逐個分隊**做（`rules.ScoreDivisor`、`rules.BattleVictory`）。
狀態欄「帝國軍／同盟軍」印的就是這兩個分數，也就是各自打掉的量。

## 戰後

`EndBattle`：把戰場上剩下的艘數寫回艦艇池的 `+0x08`，重算艦隊戰力，
回戰略地圖。**星域不會易主**——兩份收據量過了（`docs/re/105`）：打滿
九回合、以及用 `-poke` 把同盟四十個分隊的存活艘數全部寫成 0 讓戰鬥
提早結束，星域記錄的 `+0x12` 都沒有被寫。所以 `EndBattle` 不動星域歸屬
是對的。還沒解的是戰後會不會撤退、分數怎麼結算，以及星域到底什麼時候
易主（`+0x12` 在整段遊玩裡的寫入者只有載入劇本那一支）。

雙方仍在同一個星域的話，下一回合會再打一場。原版是不是這樣還沒驗。

## 驗收

- `rules.EngagementRange` 對 `docs/re/90` 記的算式，單元測試；
- `rules.InRange` 對三個條件各一組樣本；
- 一場戰鬥推到一方歸零不會卡住、不會出現負的艘數；
- 九個回合打完 `battleOver` 會設起來，第八回合還不會
  （`TestBattleEndsAfterNineTurns`）；
- 打完會回戰略地圖，而且損失寫回了艦艇池（`TestBattleResultPersists`）；
- 從載入存檔一路按實行到開戰、再推十個回合，艘數會往下掉
  （`TestBattleStartsOnContact`、`TestBattleTurnsDeduct`）；
- 既有的畫面對拍（`TestBattleMatchesOracle`、`TestMinimapMatchesOracle`）
  不受影響。

同狀態對拍要等 K 解出來才有意義——在那之前這一份不會標 `CONFORMED`。
