# SPEC 006 — 載入時重算未安定度

狀態：**CONFORMED**（四個局面 ×32 個星域逐一相同，含參數不同的第 8 格）
證據：[`docs/re/43`](../re/43-unrest-full-disassembly.md)、
[`docs/re/34`](../re/34-unrest-formula-skeleton.md)、
[`docs/internals/26`](../internals/26-star-region-graph.md)
資料：[`docs/internals/data/unrest-at-load.json`](../internals/data/unrest-at-load.json)
執行器：dosgolem-logh3 `8c8af90`

## 要做什麼

存檔裡有未安定度那一欄，**原版載入時不用它**——整份重算。S3 那一格 32 個
星域裡有 22 個與檔案不同。畫面左下角與右側面板的治安都由它決定
（治安% ＝ `(200 − 未安定度) / 2`），所以讀完存檔一定要重算，
否則中局的畫面對不上。

## 算式

算出來的是**治安度**（0–200），存進記錄的 `+0x7D` 是它的補數。

```
擁有者 == 2（無主） → 未安定度 = 100，結束

v  = f1 − f2 − f3 + f4
`+0x13` bit 2 → v −= 30
v < 0 → v = 0
v = v × 統治者提督的 `+0x0E` / 100    （乘積只留低 16 位元、當有號數除）
v > 200 → v = 200
v += f6                       （f5 恆等於 0，見下）
v > 200 → v = 200
v -= 2 × 離自己首都幾步        （載入當下；遊戲進行中見 spec/042）
v < 0 → v = 0
未安定度 = 200 − v
```

**所有除法都往零截斷**（x86 的 `idiv`）。f1 裡有一步括號內是負數，
用「往下取整」會差 1，整支算下來差 2——32 個星域會錯掉 28 個。
乘統治者營運那一步是 `mul cx / cwd / idiv 100`，乘積到 `0x8000` 以上會變成負的
（`docs/spec/042`；出貨資料的局面裡碰不到）。

### f1 — 稅率、成長率與難度參數

```
a = Blend[擁有者] ; b = Rate[擁有者]
di = Base[b]
v0 = 成長率(+0x1E) > 0 ? +0x27 × 100 / 成長率 : di
v0 <= 25 → v0 = di
d = 100 + (v0 × 100 / di − 100) / 4
m = 回合數 % 10
blend = ((m + 5) × Table[a] + (14 − m) × Table[b]) / 19
f1 = blend × 100 / d
```

### f2 — 民心

```
f2 = (擁有者 == 帝國 ? +0x7C : 200 − +0x7C) / 10
```

### f3 — 鄰居（被減）

對每一個相鄰星域（`docs/internals/26` 的相鄰表）：

| 鄰居 | 加多少 |
|---|---|
| 與自己同陣營 | 鄰居 `+0x13 & 0x14` 才 +7 |
| 無主 | +3，鄰居 `+0x13 & 0x14` 再 +2 |
| 敵方 | +5，鄰居 `+0x13 & 0x14` 再 +2 |

### f4 — 行星（被加）

這個星域裡 `+0x12` 不為 0 的行星數 × 10。

### f5 — 提督（恆等於 0）

`2703:10FC` 把「在這個星域、`+0x00 == 0xFF`、`+0x09` 最高位有設」的同陣營提督
數成 `n × p × q ÷ 1000`，但交給開根號 `3310:0130` 的引數是清成 0 的那一格
（商的低位字搬進 ax、bx 清 0，推的是 bx 那一份），開根號 0 回 0——**與提督的
旗標、人數、能力都無關**（`docs/re/299` 第六節）。remake 不實作它。

### f6 — 艦隊（被加）

駐在這個星域、同陣營、狀態（`+0x08`）＝ 5 的艦隊：

```
f6 = Σ艦隊+0x0F × max(指揮官 +0x0B) × max(指揮官 +0x13) / 10000
```

指揮官是艦隊記錄 `+0x04` 指到的提督。

### 尾巴 — 距離

離自己首都（帝國 0、同盟 31）幾步，一步扣 2。**用相鄰圖的最短步數**
（`StarGraph.Hops`）——量到的 31 個回值與它逐一相同。把中點矩陣遞迴展開
的 `StarGraph.Steps` 在星域 15、22 兩處多一步，不能拿來用。

原版另有一條「路徑成本表 `ds:D062` 的值 >= `0x800` 就把治安度砍半」的分支，
但那張表**載入的當下整張是 0**（路徑計算跑過才填，`docs/re/43`），所以不會
走到。填好之後的樣子倒在 `docs/internals/data/star-distance.json`
（`docs/re/241`）——1024 格裡有 730 格超過門檻，所以那條分支在中局會走到：
遊戲進行中的重算讀的是照擁有者建好的表，砍半與「沿原版的路數步數」都照
位元組做，見 [`docs/spec/042`](042-region-unrest-recompute.md)（收據 `urx299c`）。

## 參數從哪裡來

`Blend`（`ds:8FD4`）、`Rate`（`ds:8FF8`）、統治者編號（`ds:8F4F`）與
回合數（`ds:8F18`）都在 `WORK.DT?` 對應區塊；統治者就是兩邊的內政
專任參謀。`Table`（`ds:4B28`）與 `Base`（`ds:147E`）才是只存在執行期的
常數。既有量測值記在 `unrest-at-load.json` 的 `params`，第 8 格另由
`WORK.DT8` 與 `load8unrest` 收據確認：

| 參數 | 新遊戲 796/1 | 第 8 格亞姆力札 | S2 諸神的黃昏 | S3 巴米利恩會戰 |
|---|---|---|---|---|
| `Turn` | 0 | 93 | 346 | 380 |
| `Ruler` | 帝國 16、同盟 60 | **帝國 32、同盟 60** | 帝國 16、同盟 60 | 同左 |
| `Blend` | **兩邊都是 2** | **兩邊都是 2** | 帝國 1、同盟 2 | 帝國 1、同盟 2 |
| `Rate` | 兩邊都是 2 | 同左 | 同左 | 同左 |
| `Table` | 170 150 130 90 60 | 同左 | 同左 | 同左 |
| `Base` | 50 75 100 150 200 | 同左 | 同左 | 同左 |

`Turn`、第 8 格的帝國統治者與各局面的 `Blend` 會不同。`Blend[帝國]` 在新遊戲是 2、
在較晚的 S2／S3 存檔都是 1——**那不是兩種難度設定，是同一個量在三百多回合之間
掉了一級**（`docs/re/207`）。

`Blend`（`ds:8FD4`）是一個 **0–4 的等級**，存檔的工作區塊 `+0xC0`
就是它（S2／S3 兩格讀出來都是帝國 1、同盟 2，與上表量到的相同）。
**動它的是電腦座位的戰略 AI**：回合開頭按那個陣營的軍事費設一次、
回合結尾除非月底否則歸零，兩次都接著整批重算全國稅率
（`2D10:0319`，`docs/re/222`、[`docs/internals/55`](../internals/55-blend-and-tax-rate.md)）。
玩家座位不跑 AI，所以玩家那一格不會被這條路徑改動。
另有一支 `±1`、只有真的變動才跳訊息的常式（`docs/re/206`；進入點是
`090A:0372`，呼叫鏈 `090A:0107`／`0120` → `090A:02AF` → `090A:0372`，
`docs/re/299`），在已量到的局面裡沒有被走到。

同一個量另外被兩處讀：`ds:8FD4[陣營] >= 3` 就把 AI 的建艦隊預算打七五折
（`docs/re/202`，換算過去就是軍事費不到 10000）；而且**寫下等級之後緊接著
`090A:0B93` 把該陣營每個星域的稅率（`+0x26`）整批重算**——收據
`turn260mem` 上同盟的 `Blend` 從 2 掉到 1，總稅收跟著從 10599 掉到 7852
（`docs/re/220`、`docs/re/223`）。那條算式與這一節的 `f1` 共用
`Base`，remake 的實作是 `rules.TaxRatePerMille`（`docs/spec/030`）。

## 驗收

- `internal/rules.TestUnrestAtLoad`：三個既有局面（新遊戲 796/1、S2、S3）
  各 32 個星域，算出來的未安定度與量到的**逐一相同**。
  S2、S3 的輸入直接讀存檔；新遊戲那一組的星域表載入時整份重算過，
  所以拿量到的記錄當輸入（`raw_at_load`）。
- `internal/game.TestLoadSlot8UnrestMatchesReceipt`：走產品的第 8 格載入路徑，
  以該格 WORK 的統治者 32／60、Blend 2／2、Rate 2／2 重算，32 格逐格與
  dosgolem `e0b6a03` 的 `load8unrest` 收據相同。方法與雜湊見
  [`docs/playtest/014`](../playtest/014-load-slot8-unrest.md)。
- `internal/screen.TestRegionPanelMatchesOracle/s3rgn`：面板上的治安改成
  算出來的，那塊 320×80 仍與原版逐位元組相同。

## 不在這份規格裡

- **載入時重算的不只未安定度**。拿 `STELLAR.DTX` 與新遊戲載入後的記憶體
  逐位元組比，這些位移會變：

  ```
  +12 +13 +16..+18 +1A +1E +20..+24 +26 +27
  +30..+65（每 4 bytes 動 2 bytes 的那段 u16 陣列）
  +68..+77（四個 u32）  +7C  +7D
  ```

  也就是擁有者、旗標、行星數、經濟力、成長率、防衛力、稅率、民心
  全部重算。這份規格只涵蓋最後一項（`+0x7D`）。

  **這張表只適用新遊戲**：讀存檔的時候那些欄位照存檔的用，
  只有 `+0x7D` 會重算（`docs/re/44`）。新遊戲那一份現在整張都算得出來
  （`rules.NewGameRegions`）——經濟力、成長率、民心、稅率、未安定度
  與量到的逐一相同，所以 `docs/spec/001` 那 15 份收據也改成算出來的。
  還沒解的只有旗標 `+0x13`（載入後只有 0 與 8，對未安定度沒有作用）
  與 `+0x30`–`+0x77` 那兩段陣列。
- **遊戲進行中的重算**：同一支算式在稅率或參謀一變、每次「實行」扣維持費
  之前、每個座位回合開頭與回合尾巴都整份重算，一次「實行」十一次
  （[`docs/spec/042`](042-region-unrest-recompute.md)、`docs/re/299`）。
- `+0x7C`（民心）、`+0x13`、行星 `+0x12` 三格的來源與變化。
