## 什麼時候出現

回合結束逐格重算擁有者那一圈裡，**每有一格易主就跳一則**
（`056A:078B` → `2703:159B` 回「有沒有變」→ `056A:0855`）。

**它是模態的，而且擋住後面所有處理。** 收據 `chain3` 就是證據：poke 一顆
行星讓星域 4 易主之後，`2703:159B` 只跑到第 5 格（星域 4）就停住，
`2703:08DE`（重建路徑表 ＋ 32 格態勢）**零次執行**。補右鍵按掉之後
（`chain4`）才變成 `2703:159B` 64 次、`2703:08DE` 1 次。

`056A:0855(星域記錄, 舊擁有者)` 先看 `ds:8F21`／`ds:8F22`（座位），
**兩個座位各跳一次**（各自呼叫 `056A:089D`）。

## 畫面

底是命令階段那一張（`docs/spec/005`／`screen-command-phase.json`），
標題換成 `ds:07E1` `戰略模式處理中`；電腦那一方跑的時候是 `ds:06E9`
`戰略模式思考中　　`。

量自收據 `chain3` 的 `screen.bin`（640×480，色號陣列）：

| 元件 | 位置 | 備註 |
|---|---|---|
| 訊息文字第 1 行 | 左上 `(336, 182)` | 星系名 ＋ `星系` |
| 訊息文字第 2 行 | 左上 `(336, 202)` | 列距 **20** |
| 星系名的字色 | **5** | 陰影色 3，在上一列 |
| `星系` 與第 2 行的字色 | **7** | 陰影色 3 |
| 訊息視窗內容底色 | 9 | |
| 頭像框 | `(544, 180)`–`(620, 276)` | 內部影像 72×93，與 `docs/re/112` 同尺寸 |

一行兩種字色對得上格式字串 `ds:087A` ＝ `\x1B[%d,%s\x1B[%d,星系`——
**兩個顏色控制碼**，星系名一個、`星系` 兩個字另一個。控制碼的解法與
`docs/internals/49` 的文字引擎同一套。

## remake 要改什麼

- 新增一個報告狀態，`Game.recomputeRegions()` 每偵測到一格易主就排一則。
  現在它只回「有幾格易主」，那個回傳值沒有人用。
- **順序**：報告要卡在擁有者重算那一圈裡，後面的路徑表重建與態勢重算
  要等它按掉——照原版。目前 remake 是一口氣跑完。
- **關掉的方式量過了**：`chain4` 用右鍵、`chain5` 用左鍵，兩份都讓
  `2703:159B` 跑滿 64 次、`2703:08DE` 跑 1 次，也就是**滑鼠任一鍵都能關**
  （兩份都點在地圖上的 `(300,200)`，沒有測其他位置）。**鍵盤不行**——
  `chain3` 全程 `-press-every 2000000` 一直在送鍵，照樣卡住。

## 對拍怎麼做

收據 `chain3` 的 `screen.png`／`screen.bin` 就是原版那一張。remake 要
走正常玩家路徑到同一個局面（新遊戲、一次「實行」、星域 4 易主），
比較右側面板那一塊的色號陣列。**局面要用注入的**（`docs/spec/014`）：
行星記錄陣列基底在線性 `0x53132`，星域 4 那顆的 `+0x11` 在 `lin:5351B`。
