# 061 — 戰場上的電腦方不造成傷害（刻意偏離原版）

狀態：**CONFORMED**（remake 規則；不對原版收據）
來源：使用者裁決（2026-09-17）：「強制改變 dos remake ai 進入戰場後都不攻擊」，範圍「完全不造成傷害」。
程式：`internal/game/passivebattle.go`；測試 `internal/game/passivebattle_test.go`。

## 規則

單人模式的戰場上（對戰模式兩邊都是人，照原版），電腦那一方（`1 − 玩家陣營`）：

1. **不下令**：電腦方的戰術 AI 不跑，電腦的艦隊留在原地。
2. **行星不開火**：行星互打（`rules.ResolveBattleTurn`）照原版算，但玩家分隊的結果還原、電腦那一方的得分拿掉——能傷到玩家的只有電腦的行星。
3. **要塞砲不開火**：電腦的要塞在開火那一步當作沒瞄準，狀態之後還原。
4. **不打行星、行星不反擊**：電腦艦隊不算「戰鬥」命令；玩家打電腦的行星時挨的反擊，玩家分隊還原。

玩家這一方照原版：玩家的艦隊、行星與要塞砲照常造成傷害，戰場結束判定照常。戰略層不受影響（遊戲本體預設本來就不掛戰略 AI）。

## 實作邊界

原版規則層（`rules.ResolveBattleTurn`、`FortressGunFire`、`PlanetAssault`）一行不改，差異全在遊戲層包起來；
`Game.originalBattleAI` 設為真就照原版（只有對拍原版戰場的測試會設）。所以原版戰場的逆向事實與對拍測試仍然成立。

## 驗證

第50輪補行軍入口後，障礙退縮的分隊現在座標與集結目標可能不同。
只略過AI下令仍會自動歸隊，違反既有「留在原地」要求。
READY補充：遊戲層對電腦方設定`MovementFleet.Frozen`；移動控制器保留它們的碰撞物件，
不初始化移動額度、不執行該組步進。原版對拍與雙人模式不設定此值，原版移動公式保持。
這是既有使用者裁決的接線修正，不能列為原版一致。

`TestBattleComputerDealsNoDamage`：同一場戰鬥（兩邊交給原版戰術層）打滿回合，玩家損失 0 艘、電腦分隊移動 0 次、電腦得分 0；
正對照照原版打同一場，玩家損失 918 艘、電腦分隊移動 138 次。
