## 要做什麼

「次月份預算計劃」（月初報告那條路，收據 `budget1`）與「徵稅計劃」
（命令階段那條路，收據 `tax1e`）**是同一個視窗**（128, 60, 384×340），
只有底層與數字不同。那十個數字原本量好畫死在兩份規格裡，現在從財政狀態算。

| 兩張的差別 | `budget1` | `tax1e` |
|---|---:|---:|
| 本月份 原定軍事費 | 0 | 60741 |
| 已支付 船艦建造費 | 0 | 15149 |
| 預估徵稅額 | 10741 | 10341 |
| 預估軍事費 | 60741 | 55933 |

四格的對應與三條算式由收據 `fiscalrows5` 逐格釘出來
（[`docs/re/239`](../re/239-budget-rows-mapped.md)）：把三個全域 poke 成
11111／22222／33333 之後，預估軍事費是 60741 − 66666 ＝ **−5925**、
船艦建造費仍然是 **15185**、剩餘軍事費 **−21110**（負數印紅色）。

三條算式在 `internal/rules.Budget`，`docs/re/12` 拿三組獨立資料對過。

## 兩張的「預估徵稅額」不是同一個數

- `budget1`（月初報告）印的是扣稅前的預估：**10741**。
  不調整預算時，後續實收也為 10741（`docs/re/35` 的十個增量總和），
  但此視窗還沒有真正扣稅；2026-10-01 的同狀態記憶體證據見研究 350。
- `tax1e`（徵稅計劃）印的是結算完之後重算的**下個月預估**：**10341**。

國庫也跟著差：報告那張是 50000（加稅之前），徵稅計劃那張是 45592
（加了稅、扣掉已付的造船費之後）。`60741 − 15149 ＝ 45592`。

## 驗收

`internal/screen.TestMainGameMatchesOracle` 的 `budget1` 與 `tax1e` 兩筆：
規格裡沒有那十個數字，畫的時候由 `BudgetPanel` 補上，**整張 640×480
逐位元組相同**。`tax1e` 的底層是命令階段那張，所以右側面板也是算出來的
（`docs/spec/002`）——那一塊要畫在**底板之後、疊上去的視窗之前**，
`MainGameWithBoard` 就是為了這個時機開的口。

`internal/game` 兩條正常玩家路徑（`TestBudgetPlanFromMainScreen`、
`TestCommandPhaseNavigation/徵稅計劃`）也都對得上。

## 錢的整條路現在是算出來的

扣款那一步也接上了（`docs/re/35` 之後補的）：

```
原定軍事費 = 上個月的軍事費 + 這次收到的稅       50000 + 10741 = 60741
船艦建造費 = 原定軍事費 × 25%                    60741 × 25%   = 15185
已支付     = 各列只買得起整數艘的部分相加        → 15149（零頭 36 退回）
軍事費     = 原定軍事費 − 已支付                 60741 − 15149 = 45592
預估徵稅額 = 結算後自己星域的徵稅額相加          → 10341
```

`15185 → 15149` 那一步是七次除法各自捨去的結果，
`rules.BuildPlan.Paid()` 算出來與畫面上「已支付」那一格**完全相同**
（`TestPaidMatchesOracle`）。

所以 remake 現在只需要劇本給的**一個**起始值：開場結算前的軍事費 50000
（`Resources.StartMilitary`）。796 年 1 月畫面上的每一個錢，包括月初報告
與徵稅計劃兩張的十個數字，都是從那裡算出來的。

**「結束」沒有導覽邏輯**：只是把最上層的疊圖關掉，畫面自然露出底下原本就在畫的那一層。
所以命令選單開的（徵稅／生產）回命令階段、月初報告開的（次月份預算計劃）回會計報告。
**不寫回任何變數、沒有確認框**。

**兩組箭頭都是即時重算**（同一次點擊、同一次重繪就看到新數字）：

- 稅率檔位改完連動預估徵稅額、預估軍事費、船艦建造費、剩餘軍事費，**還連右側面板的
  首都摘要一起重寫**（`fcmd-plan-tax` 是「艦隊 0：0」的回合開頭快照，
  按過箭頭的 `fcmd-plan-tax-up` 變成 1：0）——它跑的是與 AI 調整 blend 同一條
  `090A:0B93` → `090A:0E6D` 重算鏈。
- 建造費％只連動建造費與剩餘軍事費，**不影響稅收**。

**按住會連發**（`-click-hold 3000000` 時稅率一次跳兩階）。remake 只做「按一下動一格」，
連發是已知差異，與 ▲▼ 連捲（#60）同一件事。

### 徵稅箭頭呈現（2026-10-01，CONFORMED）

證據與輸入雜湊：[研究 350](../re/350-plan-arrows-retain-dim-colour.md)。
實作範圍為 #80 的徵稅兩組箭頭單次左鍵；按住連發仍由 #60 處理。
月初預算入口雖使用同一組原版箭頭，完整互動必須先解決 #82 的結算時序。

- 開窗四顆箭頭未轉色；懸停不轉色。點擊某顆，即使數值被上界夾住，該顆全部色號
  9 改成 8，其他色號不變。四顆各自保存此呈現狀態，游標移開及點別顆不重設；
  關窗再開全部重設。熱區仍用上表，繪圖也用同一組矩形；游標在轉色後才繪製。
- 呈現狀態屬於目前視窗，不改存檔格式、不寫遊戲規則或 RNG，不修改共享畫面規格。
- 稅率已在上界時財政不重算，但右側首都摘要仍刷新；`planarrow-clamp` 的艦隊數由
  回合開頭快照 0：0 變成現值 1：0。

重開、上界各有整張對拍，不使用排除矩形。正式 Ebiten 顯示層抽測正常玩家入口。
原版同序列至少重跑兩次、雜湊相同。所有原版素材仍由玩家自備。
實際結果：[收據 025](../playtest/025-plan-arrows.md)，八份正常入口完整畫面及 RGB 零差異，

### 月初預算互動與結算時序（2026-10-01，CONFORMED，#82）

修正前不能直接把命令階段的 `taxTotal` 畫進月初預算：原版在這個視窗還沒有扣稅，
當時 remake 的 `monthEndSeat` 已執行完 `CollectTax`；星域 0 的經濟力為 85020／82302。
加稅時兩側稅率都是 47，但總稅額為 16070／15472。此為實際結算生命週期缺口，
不是可用文字修補的差異；最初只改數字的試作已撤回，後續依下列 READY 契約修正流程。

已取得四顆月初原版收據；建造費＋：25→26、15185→15792、45556→44949；
稅率＋：稅額 16070、軍事費 66070、建造費 16517、剩餘 49553。
稅率標籤位於此規格 `report` 第 9 行，與徵稅 `overlay` 第 8 行不同。
開窗 `budget1` 的輸入 (432,300) 在當幀畫出游標 (432,340)，後續輸入才使用即時游標。

READY 審查：從扣稅前局面操作四顆箭頭 → 關預算 → 會計／訂造報告 →
命令階段的五組原版完整記憶體，已核對資金、實付及建造艘數；
[研究 351](../re/351-budget-settlement-after-reports.md) 與研究 255 的呼叫順序一致。
輸入／執行器版本與原始 bytes 的雜湊見該研究及其 JSON 索引。

單人流程採下列型別與時序契約：

- 月初成長及稅率重算仍只做一次；玩家之前的電腦座位照既有順序結算。
  玩家自己留在「待結算」狀態，保留未扣稅的星域／行星與資金；
  月報為 `rules.Budget` 預估，不能以結算後經濟力生成。
- 稅率及造船比例箭頭更新待結算預算；稅率標籤用 `report` 第 9 行。
  箭頭轉色契約與徵稅相同。開窗游標沿用既有原版快照，移動後才用即時座標。
  稅率重算還會填上右側原本空白的總稅收數字（研究 351），造船比例不會；
  沿用面板 `tax_total` 欄位的版面與字色。
- 關預算只退回會計報告；關會計只進訂造報告，兩者不收稅。
  訂造報告關閉後一次執行既有 `CollectTax` 與 `BuildPlan`：
  `rate = blend`、更新軍事費／實付／建造中、歸零已付維持及移動費，
  清待結算旗標，刷新下期預估與首都摘要。重複關窗不得再次收稅。
- 待結算為執行期流程，不擴張存檔格式；正常玩家只在報告全部關掉後存檔。
  若直接呼叫存檔 API 時仍待結算，明確拒絕，避免產生不能恢復流程的存檔。
  載入既有命令階段存檔不得殘留待結算旗標。
- 對戰跨月未知，本次保留原有處理；既有對戰入口與兩個單人陣營皆須回歸抽測。
  參謀／生產編輯的其他未證實分支不藉此猜補。

驗收：五組結算的財政欄位、建造艘數及全部星域／行星的經濟力、稅率欄位對原版；
整表差異另列總數與位移，財政之外的原有欄位不能冒稱本次已完成對拍；
四箭頭整張畫面、即時游標、稅率文字及 RGB 無未核准差異；
正常玩家入口到結算及存讀檔；既有月初、命令階段、跨月與兩陣營回歸。
原版同序列兩輪重播雜湊一致；GUI 以正式 renderer 抽樣。
原版檔與 dump 仍只留本機，產品不內嵌原版素材。

驗收結果：十份正常 GUI 全畫面色號／RGB 零差異；五條實際結算與財政欄位、
所有行星經濟力及存讀檔通過，原版完整記憶體兩輪一致。
