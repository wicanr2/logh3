# 159：新遊戲第一場戰鬥與新編艦隊配置

狀態：**限定CONFORMED**，第172輪。依據[研究450](../re/450-new-fleet-placement-and-new-game-slot.md)，驗收見[143](../playtest/143-new-game-first-battle.md)。範圍與限制見下。

## 範圍

沒存過檔的新遊戲可以進第一場戰鬥，新編艦隊在戰場上有正確座標。不改存檔格式、不改已配置艦隊的座標，也不改既有讀檔局的艦隊位置。

## 契約

1. `ensureSlot`在第一次需要原始表時建出Slot：保存，或有入口表的戰場入口。底稿與009相同：`WorkTemplate`加全FF的FLEET／SHIP。
2. 開局維持`g.slot`為nil。第一場戰鬥之前的新遊戲戰略路徑不變，含058的typed打行星分支；這段生命週期沿115。第一場戰鬥之後與「新遊戲存過檔」走同一條路。
3. 行軍到達時`g.slot`為nil：只記下來源星域，等建池再配置。這份記號放在`Game`，`rules.Fleet`維持與存檔同版面，讀檔與開新局時清掉，解散與全滅時移除該列。
4. 行軍到達時已有Slot而艦隊池索引是-1：先同步一次再配置。
5. 選中心的順序照`297B:0ABF`：入口表（來源, 目的），再來是該陣營的待命行星（`StandbyPlanet`＋`loadRegionPlanetSites`）。兩者都沒有時取該星域第一個入口，這是remake對原版越界讀取的刻意差異。
6. 正常戰場入口讀原池之前，補配置座標仍是零值的艦隊：中心與各組都在(0,0)才算。有到達紀錄用來源星域，否則用自己的星域，也就是`297B:08D8(艦隊, 星域, 星域)`。掃描全部艦隊，因為第一場戰鬥之後`Fleets()`會重讀原始表，來源記號不能留到之後。
7. 直接入場診斷（`StartBattle`）沿用既有近似佈陣，不補配置。
8. `disbandFleet`當場作廢原始表那一列，照`297B:025D`：+04／+05寫FF，前+0F組與+38那一筆艦艇+01寫FF、+38遠指標清0。

## 已知限制

- remake延到建池才配置，同一星域多支新編艦隊依艦隊表順序避讓；原版的配置順序不同（`t260_post`由環狀位置推得28、31、23）。受影響的是避讓後的中心位置，分隊數與地形判定不變。這一項沒有同狀態對拍，比較等級是`nearby-state`。
- 非首都新編艦隊的行星分支只有靜態證據。
- 存過檔再讀回的新遊戲沒有來源記號，還沒配置的艦隊依自己星域的規則配置。
- 沒有同戰場讀回，也不宣稱新遊戲整回合與原版同態。

## 驗收

- 重現：新遊戲、未存檔、純玩家輸入走到星域15的第一場戰鬥。修正前後都要有結果，修正前的堆疊要與使用者回報相同。
- 回歸：首都新編的中心與航向符合兩份原版傾印；行軍到達用來源入口；讀檔局新編艦隊到達後有座標；S3已配置艦隊不被移動；解散後同格重編可以同步。
- 繼續：第一場之後還能跑回合、再開戰、存檔，typed艦隊與原始表一致。
- 標準測試與兩平台正式執行檔的正常路徑。
