## 原版做什麼

### 寫入者只有一支

`+0x7D` 在遊戲裡只有 `2703:0DA1(星域記錄)` 在寫（兩條指令：`2703:0DB2` 無主寫
100、`2703:0EEF` 寫 `200 − 治安度`）。開機時另有兩次整塊初始化（`63A1:002D`、
C 啟動碼清 BSS 的 `0349:01EA`）與讀檔（`332E:04BB`，`STELLAR.DT?` 整張蓋掉），
都在遊戲開始之前或載入當下。

`2703:0DA1` 有三個呼叫端：

| 呼叫端 | 什麼時候 |
|---|---|
| `2703:0000`（`2703:01FD`）| 新遊戲初始化，一次 |
| `090A:0E6D` → `2703:02E5`（`2703:0337`）| 18 個呼叫點，見下 |
| `2703:08DE`（`2703:091D`）| 回合尾巴，逐格「態勢 → 彙總 → 未安定度」|

`090A:0E6D` ＝ `2703:02E5`（32 格：經濟力 ＝ 行星加總 → 累加預估稅 → **未安定度**）
＋ `090A:0E88(0)` ＋ `090A:0E88(1)`。凡是會動到經濟、稅率、參謀或艦隊的地方
都跑它；與未安定度有關的時點：

| 呼叫點 | 所在 | 時點 |
|---|---|---|
| `0654:0067`／`0654:011E` | 月底閘門 `0654:0034` | 每個座位回合開頭（月底那一趟兩次）|
| `2D10:0434` | `2D10:0319`（設 `Blend`）| AI 回合開頭與尾巴 |
| `2D10:030D`、`2D10:0208` | `2D10:0213`／`2D10:0143`（換參謀；後者是推論）| AI 回合尾巴 |
| `297B:05A6` | `297B:0546`（艦隊能力重算）| 編制一動：建艦隊、整補 |
| `056A:09F3` | `056A:09EB`（扣維持費）| 每次「實行」命令階段那一串的第一支 |
| `1213:0256` | 費沙事件包裝 | 費沙第一次易主 |
| 另外 9 處 | 未讀 | — |

### 一次「實行」

收據 `urx299w`（新遊戲、同盟是電腦）：

```
同盟座位開頭      0654:0034 → 090A:0E6D                  計數器 N
AI 回合           2D10:0319(1) → 090A:0E6D               Blend 一變
                  建艦隊、下命令 → 090A:0E6D ×4
                  2D10:0213 → 090A:0E6D                  內政參謀換人
                  2D10:0319(0) → 090A:0E6D               Blend 歸零（或月底照軍事費）
命令階段          056A:09EB → 090A:0E6D                  ← 叛亂讀的是這一次
                  … 民心、艦隊移動、叛亂判定與效果（這一段不重算）
回合尾巴          2703:08DE：重建路徑表，逐格 0933 → 12EB → 0DA1   計數器 N
                  計數器進位
帝國座位開頭      04F8:003E（重建路徑表）→ 0654:0034 → 090A:0E6D   計數器 N＋1
```

**每一次都整份重算、只由當下的局面決定**（`0DA1` 不讀別格的 `+0x7D`）。

### 算式

與 [`docs/spec/006`](006-unrest-at-load.md) 同一支，遊戲進行中有兩個輸入不同：

**尾巴讀的是照擁有者建好的路徑表**（`2703:0E7F` 起）：

```
d = 那個陣營的距離矩陣[首都][星域]            ; 2B99:028F，ds:D062／ds:D066
d >= 0x800（無號）→ 治安度 = 治安度 ÷ 2       ; 有號除，往零截斷
否則             → 治安度 −= 2 × 步數         ; 2B99:0450：從首都沿中點矩陣
                                              ; 一格一格走到這一格，走了幾步
```

路徑表由 `2B99:0003` 照 32 格的 `+0x12` 建（每個陣營一張距離矩陣、一張中點
矩陣），重建的時點是新遊戲初始化、回合尾巴 `2703:08DE`、座位回合開頭
`04F8:003E`。擁有者只在回合尾巴那一段會變，所以任何一次重算讀到的都是「照
現在的擁有者建的表」（收據 `rbx292_b` 映著的四張表與照擁有者建的逐格相同）。

載入存檔的當下讀到的是另一種（成本全部小於 `0x800`，步數等於相鄰圖的最短
步數），那一條留在 `docs/spec/006`。

**四個全域讀當下的值**：回合計數器 `ds:8F18`（f1 取 `% 10`）、`Blend`
（`ds:8FD4`）、`ds:8FF8`（月底收稅時 `Blend` 的快照，`2703:03AF`，`docs/re/252`）、
內政專任參謀 `ds:8F4F`（統治者）。計數器在回合尾巴之後才進位：同一次「實行」
裡 AI、扣維持費、回合尾巴那幾次用舊值，下一個座位回合開頭那一次用新值。

另外兩個位元組層級的細節（兩者在載入時也成立，出貨資料的局面裡量不出差別）：

- `× 統治者營運 ÷ 100` 是 `mul cx / cwd / idiv`：乘積只留低 16 位元、當有號數除。
- f5（同一格的提督）恆等於 0：`2703:10FC` 推給開根號 `3310:0130` 的是清成 0
  的那一格，與提督的旗標無關（`docs/re/299` 第六節）。

## remake

```go
rules.UnrestState{…, FleetList: g.fleets, Paths: graph.UnrestPaths(擁有者)}  // internal/rules/unrest.go
Game.recomputeUnrest(計數器)                                                 // internal/game/game.go
```

| 原版 | remake | 計數器 |
|---|---|---|
| `2D10:0319` → `090A:0E6D`（開頭、尾巴）；`2D10:0213` → `090A:0E6D` | `refreshBlend` 的尾巴 | `g.turn − 1` |
| `056A:09EB` → `090A:0E6D` | `advanceTurn` 扣維持費之前 | `g.turn − 1` |
| `2703:08DE` | `refreshRegionPosture` 的尾巴 | `g.turn − 1` |
| 下一個座位回合開頭 `0654:0034` → `090A:0E6D` | `finishTurn` 重算預估稅之後 | `g.turn` |
| `2703:03AF`：`ds:8FF8 ← Blend` | `monthEnd` 開頭 `rate = blend` | — |

- remake 的 `g.turn` 在 `advanceTurn` 開頭就先加一，原版的計數器到回合尾巴之後
  才進位，所以回合中那幾次是 `g.turn − 1`。
- `rate` 讀存檔時取 `WORK.DT?` 的 `+0xE4`、存檔時寫回（`rules.WorkFields.Rate`），
  新遊戲取 `UnrestParams.Rate`（2／2）。
- 路徑表每一次照現在的 `+0x12` 建（`StarGraph.UnrestPaths`）。
- 載入存檔當下那一次照舊走 `Slot.RecomputeUnrest`（`Paths` 為 nil，`docs/spec/006`）；
  新遊戲那一次照舊走 `NewGameRegions`。

## 驗收

`internal/rules/unrest_recompute_test.go`（收據自己的傾印）：

- `TestUnrestRecomputeAfterAITurn`：`rbx292_b` 32 格逐格相同；與 `rbx292_a` 比
  正好 14 格不同（同盟 13 ＋ 被 poke 成 255 的星域 1 回到 38）。
- `TestUnrestPathsAreTheLiveTables`：`rbx292_b` 映著的四張路徑表與
  `UnrestPaths` 逐格相同。
- `TestUnrestRecomputeAfterTurnEnd`：`rbx292d_reg_post` 32 格逐格相同（計數器 1）；
  計數器代 0 時同盟 13 格不符（反對照）。
- `TestUnrestRecomputeHalvesFarRegions`：`urx299c_post` 32 格逐格相同；星域 4
  計數器 0 時 128、1 時 127，不砍半是 71（反對照）。
- `TestRouteStepsWalksTheMidpointMatrix`、`TestRulerScaleKeepsLow16Bits`：
  步數與 `Route` 一致、乘法只留 16 位元。

`internal/game/unrest_recompute_test.go`（remake 自己走同一條玩家路徑：新遊戲 →
提督 13 的營運改成同一個值 → 系統指令 → 實行）：

- `TestUnrestSameStateAfterAITurn`（`rbx292` 的兩個注入）：AI 回合剛跑完，
  `Blend`、內政參謀與 32 格的 `+0x7D` 與 `rbx292_b` 逐一相同，14 格變動。
  這個時點夾在 `advanceTurn` 的第二、三步之間，所以照它的前兩步手動跑。
- `TestUnrestSameStateAfterTurn`（`rbx292d`）：整個「實行」跑完，32 格與
  `rbx292d_reg_post` 逐格相同——九格叛亂變無主、鄰居與路徑表跟著變、計數器進位。
- `TestUnrestSameStateRebellionReads`（`rbx292e`）：問了帝國 9 格、同盟 10 格，
  每一格的門檻都等於拿原版那一刻的未安定度與營運算出來的。

把 `recomputeUnrest` 拿掉，三支分別是 14 格、23 格不符與同盟 10 格裡 9 格門檻不同。
缺收據就 skip。

## 沒有驗到的

- **其餘的 `090A:0E6D` 呼叫端 remake 沒有接**：玩家那一方的指令（編制、整補等
  `297B` 那幾處）、費沙事件、`2E54` 與另外幾處沒讀的。原版在那些時點當場重算，
  remake 要到下一次「實行」的第一次重算才跟上——命令階段的面板與治安色會
  慢一步；叛亂讀的那一次之前 remake 一定重算過，所以判定不受影響。
- **戰鬥中的重算**：原版逐格開戰那一圈裡，戰鬥會動到艦隊（`297B:0546` 等），
  叛亂的效果（`2703:1908` 讀 `+0x7D` 決定翻幾顆）排在較小編號那幾格的戰鬥之後；
  remake 判完直接套效果，用的是命令階段那一次的值。同一回合裡同時有叛亂與
  戰鬥、而戰鬥又改了叛亂那一格的輸入時才會不同，沒有收據。
- **回合尾巴的交錯**：原版第 i 格讀到的是編號比它大的鄰居還沒更新的 `+0x13`，
  remake 全部更新完才算；只有在那一圈改了鄰居 bit2 時不同，而且下一個座位回合
  開頭那一次會覆蓋它。
- **讀存檔之後到第一次回合尾巴之間原版讀哪一份路徑表**沒有量。載入當下量到的
  是成本全部小於 `0x800` 那一種（`docs/spec/006`）；帝國座位開頭會重建
  （`04F8:003E`），同盟座位開頭在 `urx299w` 裡沒有看到重建。remake 一律照擁有者建。
- **AI 建艦隊當下**新艦隊的 `+0x08` 是 5，原版中途重算了四次（首都那一格的 f6
  跟著動）；remake 的 `buildFleets` 建出來就是移動中，那幾次也沒有跑。AI 回合
  結束時兩邊相同。
- **月底那一格的 `Blend` 上游早一回合**：`runBrain` 的月底分支用 `g.turn % 10 == 9`，
  對應的是原版計數器 8（`docs/re/299` 順帶）。月底收稅抄進 `rate` 的 `Blend` 因此與
  原版不同，之後同盟的 f1 跟著差；修法在 `runBrain`，不在這一支。
- 對戰模式沒有收據（兩邊都是人，只有扣維持費、回合尾巴與座位回合開頭那幾次）。
