# 067 — 現況艦隊與艦艇池存讀閉環

狀態：**CONFORMED**（2026-10-01，限下列保存／載入與欄位核對範圍）。工作項目：[Issue #86](https://github.com/wicanr2/logh3/issues/86)。

## 範圍與證據

沿用六份原版存檔，不增加格式或改玩法。`g.fleets` 是目前艦隊／編制的來源，
原始 `Slot.Fleet`／`Slot.Ship` 是未提升欄位的保留底稿。保存前同步兩表，
不能讓載入後的艦隊數、位置、命令、組成、艘數及存量退回舊值。

- 已證實：122-byte 艦隊與 78-byte 艦艇、32／352 筆、槽的 16-bit 池索引。
  來源：[艦隊表](../internals/33-fleet-table.md)、[艦艇池](../internals/64-ship-pool.md)。
- 已證實：空池以 `+01 == FF` 判定，由小到大配置；旗艦與艦種 7 索敵隊分開。
  原始定位 `2AD2:0029`／`:0151`、`297B:0066`，見[研究 344](../re/344-ship-pool-fields.md)。
- 已證實：編組更新把序號、隊形與星域寫入艦艇；索敵隊序號 FF、隊形 20、士氣 100。
  原始定位 `297B:03EB` 的 `0445 / 0452 / 045F / 048A / 0491 / 0498`。
- 已證實：速度的能力乘除、逐層整數截斷與機動力折減，及索敵隊獨立速度。
  固定原版記憶體 15 組編制＋4 組索敵隊，19 組全部三項速度零差異，詳見[研究 355](../re/355-live-fleet-save.md)。

## 同步契約

1. 已載入的池索引保留，不依編制排序重排。新組使用未配置標記 `Pool=-1`；
   第一次需要原始表時配置空槽。索敵隊另配置，不列入 `Composition`。
   配置時點是 remake 的資料物化，不宣稱與原版編輯器每次點格盤的內部池序列相同。
2. 同步先驗證全部索引、引用唯一性、組數上限與池容量，再於副本更新；失敗不寫出六檔，
   不修改底稿或現況編制。舊的未知欄位及無效槽的非使用欄位保留。
3. 寫入已建模的艦隊欄位、每組全部已建模欄位。行動的高四位保留。
   移除的艦隊／組只按已證實作廢方式處理，不能留下仍被當成有效的孤兒。
4. 新記錄先以 FF 建立底稿，再填已證實初始化及現況欄位。未知欄位不得猜補。
5. 保存本身不改變 AI 選取艘數的來源：統一讀現況編制。戰術部署／結算使用原始表前
   同步現況，避免戰後由舊表重新載入而抹掉之前的移動／新編隊。

## 驗收

- 正常帝國新遊戲編成 → 實行含同盟 AI 建隊的回合 → 系統存進度 → 系統取進度。
  比較雙方所有建模欄位、星域艦隊數、行星及下一個正常回合；執行前固定 seed。
- 原版出貨存檔未操作的 FLEET／SHIP 全表保存不變；操作後指定欄位更新，未知欄位保留。
- 用固定原版記憶體驗各分隊速度、索敵隊速度與保存後解析，不把內部存讀測試稱為原版 parity。
- 拒絕重複／越界索引及池滿，原始表不變；檢查池索引 255，不能將低位 FF 誤認成 FFFF。
- 全部正式產品測試及已有正常回合／畫面原版對拍仍通過。

停止線：本規格只保存已建模局面與已有原始底稿，不宣稱新增了所有原版戰術暫存欄位、
完整中途戰鬥保存或任意回合的全表原版一致性。原版輸入仍唯讀、原始 dump 不入 Git。

## 驗收結果

正常 GUI 存讀與再次保存的 FLEET 3904／SHIP 27456 bytes 全表零差異，雙方 1／3 支艦隊、
全部星域艦隊計數與完整行星保留。正常玩家路徑的存讀／下一回合對照、原版三份未操作整表、
原版非零位置／命令／編制樣本、19 組速度、容量拒絕與池索引 255 均通過。
縮編後部署與結算只使用 `+0F` 的現有組數，不讀後方舊槽。
全部正式產品套件通過。收據與完整命令見[對拍 028](../playtest/028-live-fleet-save.md)，
正式 GUI 重生入口為 `bash tools/live_fleet_save_check.sh`；欄位證據索引為
[`live-fleet-save.json`](../internals/data/live-fleet-save.json)。
