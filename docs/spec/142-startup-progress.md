# 142：正常啟動載入視窗

狀態：限定CONFORMED（2026-10-13）。正式Linux兩啟動器正常載入、實際階段與83張人物進度、缺檔錯誤視窗及退出通過；不宣稱Windows／macOS真機。結果見[驗證120](../playtest/120-system-dialog-polish.md)。使用者明確要求啟動時顯示小視窗及載入進度。

## 證據與審查

目前 cmd/gin3.main 在 ebiten.RunGame 前同步執行 bootstrap.Load、LoadIntro、UseSaveDir、game.New、presentation.Load 與音訊準備。正常玩家只能等待 stderr 的啟動文字，直到全部完成才出現視窗。這是已查證的啟動流程，不涉及 DOS 規則。

採用同一個 Ebitengine 視窗的載入狀態，完成後切換正常遊戲。沿已選定深藍金框，不改遊戲配置。以下窄範圍經程式審查後標 READY。

## 契約

1. 正常啟動先開小視窗，隨即載入資料。使用實際七階段：原版資料、開場動畫、存檔、初始局、HD圖像與字型、音樂音效、完成準備。標示階段數，不把階段比例說成耗時百分比。
2. HD人物圖另顯示已完成／實際待載入張數。沒有相應素材或音訊選項時明示略過，不能虛構處理。
3. 載入工作與主視窗更新分開；GPU圖片與視窗設定在遊戲更新執行緒完成。載入期間不推進 Game 時鐘、不處理遊戲輸入。
4. 完成後由同一個 RunGame 切換至原版既有片頭、倍率與輸入，不開第二個遊戲程序。script診斷入口保持既有流程。
5. 失敗時保留可讀錯誤視窗，可按結束或Escape；完整錯誤保留stderr。關閉載入視窗不得留下外部程序或容器。
6. 載入畫面使用可散布的思源黑體衍生小字集，保存來源雜湊與完整授權；不內嵌原版字型。

## 驗收

正常啟動擷取實際載入畫面及完成後片頭，核對階段與人物圖張數、視窗尺寸及不中途接受遊戲輸入。缺少原版資料驗錯誤視窗與正常結束。再跑系統視窗正常GUI及標準測試，避免啟動重構改變輸入、音訊與動畫。
