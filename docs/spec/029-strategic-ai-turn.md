## 這份規格要解決的問題

`docs/spec/017` 當時的判斷是「原版按『實行』時電腦不下任何命令」，
於是 `internal/ai` 的 `Original` 回 `nil`。那個判斷來自
`docs/re/79` 的量測，而量測的原因是**進入點沒被呼叫**，不是
「AI 決定不動」（`docs/re/175`）。原版有一整套戰略 AI，
收據 `s3aicomp` 證明它跑得起來（`docs/re/176`）。

這份規格描述那一套，並標出哪些部分還不能實作。

## 什麼時候跑

```
若 ds:8F23[ds:8F1E] != 1：不跑          ; 這個座位不是電腦
若 ds:8F46 != 0：清 0，這一次不跑        ; 「跳過一次」旗標
```

remake 對應：`World` 要能回答「這一回合是哪一方、那一方是不是電腦」。
`ds:8F46` 那個一次性跳過的來源（`0x2CCA7`，`[bp+08] >= 8` 之後設）
**還沒解**，remake 先不做。

## 一回合的順序

```
2D76:0002()   建艦隊
2D76:0732()   （未讀）
2E54:000C()   清表 → 逐艦隊決定 → 畫敵方兵力圖 → 算每格優先度
2E54:0344()   五個階段
```

### 清表

`ds:D50E`／`ds:D54E`／`ds:D5CE` 各 32 個 word 清 0，`ds:D60E` 清 0。

### 逐艦隊決定（`2E54:005D`，`docs/re/79`）

每一支先填 `+0x79 = 0xFF`；在**有戰鬥的星域**（`+0x13` bit2）
`2E54:16F5` 回非 0 就 `+0x79 = 3`、`ds:D5CE[所在星域]++`；
否則走 `2E54:1955`（往首都方向退一格）、`+0x79 = 0`。兩條都 `ds:D60E++`。

### 敵方兵力圖（`2E54:1A76`）

```
對每一支敵方艦隊 f（297B:131C(…, 0xFF, 2)）：
    行動 0 或 1 → 格 = 路徑上的下一格
    行動 5      → 格 = f 所在星域
    其餘        → 跳過
    ds:D54E[格] += f[+0x0F]
```

**收據對過**：`s3aicomp` 的四格全中，星域 25 是 69 ＝ 九支艦隊槽數之和。

### 每格優先度（`2E54:019F` → `2E54:0222`）

```
只算「與首都連通」而且「擁有者 ＝ 自己」的格子，其餘 0
ds:D50E[i] = Σ（相鄰、擁有者 ＝ 敵方的 n）:
    (n[+0x13] bit0 == 0 或 ds:D54E[n] > 4) ? 4 : 2
```

### 五個階段

| # | 常式 | 做什麼 | 能不能實作 |
|---|---|---|---|
| 1 | `2E54:035E` | 守首都：`n = min(ds:D54E[首都] ÷ 3 + 1, 16)`，先 `2E54:03C3(n)` 湊，缺的 `2E54:0513(n)` | `2E54:0513` 未讀 → **不行** |
| 2 | `2E54:0EC2` | `2E54:0F09` 取清單、`2E54:1001` 排序、只處理第一名 | 三支都未讀 → **不行** |
| 3 | `2E54:0725` | `ds:D58E[i] = 缺口 ÷ 4 ＋ 前線(0/1)`；反覆挑滿足率最低的格、`2E54:143F(格, 模式 0)` 取艦隊、`2E54:1B17` 指派 | **可以** |
| 4 | `2E54:08D3` | `2D54:0000` 重算 `ds:D50E`（攻擊目標分）→ `2E54:08E3` 重算 `ds:D58E`（缺口 ÷ 5 ＋ `RNG%4`）→ `2E54:0978` 依優先度降冪對 `ds:D58E != 0` 的格呼叫 `2E54:0AAB` | `2D54:0000` 的中段未讀 → **部分** |
| 5 | `2E54:119E` | `2D54:0000` → 32 格依 `2E54:11F2` 排序 → 只處理第一名 `2E54:1243` | 兩支未讀 → **不行** |

## 可以先實作的一塊：階段三

這一塊的每一步都有證據，而且不依賴未讀的常式。

```
對每個擁有者 ＝ 我方的星域 i：
    前線 = (ds:D50E[i] ÷ 2 >= 1) ? 1 : ds:D50E[i] ÷ 2
    缺口 = max(ds:D54E[i] − ds:D5CE[i], 0)
    ds:D58E[i] = 缺口 ÷ 4 + 前線
ds:D5AE[0..31] = 0
重複：
    格 = ds:D58E[g] != 0 之中 (ds:D5AE[g] × 100 ÷ ds:D58E[g]) 最小的那一個
         （ds:D58E[g] <= ds:D5AE[g] 視為 0xFF；首都 0／31 視為 0）
    沒有 → 結束
    艦隊 = 挑分數最高的候選（模式 0：完整度 ≥ 50、不要求編制滿、權重 3 2 8 1、主力門檻 0）
    沒有 → 結束
    若 艦隊[+0x06] == 格：（+0x08 != 5 時）+0x08 = 5、+0x07 = 0xFF
    否則：+0x08 = 0、+0x07 = 格
    ds:D5AE[格]++
```

候選分數（`2E54:1574`）：

```
無法戰鬥（+0x00 bit0）或走不到 → 0
分數 = (Σ 編制槽艦艇[+0x08] ÷ 10) × 艦隊[+0x3C] ÷ 100     ; 32 位元
     × 艦隊[+0x0F] ÷ 艦隊[+0x0E]
     × 權重[ 類別表[艦隊[+0x09]] ]
     × (艦隊[+0x08] != 5 且 艦隊[+0x07] == 目標 ? 2 : 1)
     ÷ (兩格距離 × 2 + 1)
     ÷ (主力槽數 < 主力門檻 ? 4 : 1)
分數 == 0 → 1
```

類別表（`ds:5F52`，16 格）：`0 0 0 0 0 2 0 0 0 0 1 1 2 2 3 3`。

## remake 需要補的資料

| 需要 | 現況 |
|---|---|
| 艦隊的編制槽與艦艇池（`+0x0F`／`+0x10`+／艦艇 `+0x04`／`+0x08`） | `internal/rules` 有艦艇但 AI 的 `World` 還沒接（`ai.World.Strength` 是預留的口）|
| 艦隊 `+0x09`（類別鍵） | remake 沒有這個欄位；來源那筆記錄未解（`docs/re/169`）|
| 艦隊 `+0x0E`（編制槽應有數） | remake 沒有；語意是假說（`docs/re/168`）|
| 星域 `+0x13` bit0／bit2 | bit2 ＝ 有戰鬥（強推論）；bit0 未解 |
| 星域圖的「下一格」與「走幾步」 | `rules.StarGraph` 有路徑表，要確認與 `2B99:0302`／`2B99:0450` 一致 |

## 不能做的

- **不要把階段一、二、五猜出來。** 那五支常式沒讀，猜出來的行為
  對不上原版，而且會讓「照原版」這個宣稱失效。
- **不要用 remake 自己的亂數去湊 `RNG % 4`。** 階段四要對拍就得先把
  原版 RNG（`3CD5:000C`）的呼叫次序完全對上；在那之前階段四只能做
  不含亂數的部分，或整段先不做。
- 預設仍然是**原版**行為；這份規格描述的就是原版，不是強化版
  （強化版在 `docs/spec/017` 的 `Focused`）。

## 驗收

實作之後要能重現收據 `s3aicomp` 的那一趟：同一個初始局面、
同一個座位設定，跑完之後 `ds:D54E`／`ds:D50E`／`ds:D58E`／`ds:D5AE`
與四支艦隊的 `+0x07`／`+0x08` 逐格相同。階段一、二、五還沒實作之前，
只能驗到階段三為止的中間狀態，而且要在報告裡寫明。
