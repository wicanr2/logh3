## 這份規格要解決的問題

`docs/spec/017` 當時的判斷是「原版按『實行』時電腦不下任何命令」，
於是 `internal/ai` 的 `Original` 回 `nil`。那個判斷來自
`docs/re/79` 的量測，而量測的原因是**進入點沒被呼叫**，不是
「AI 決定不動」（`docs/re/175`）。原版有一整套戰略 AI，
收據 `s3aicomp` 證明它跑得起來（`docs/re/176`）。

這份規格描述那一套，並標出哪些部分還不能實作。

## 什麼時候跑

```
若 ds:8F23[ds:8F1E] != 1：不跑          ; 這個座位不是電腦
若 ds:8F46 != 0：清 0，這一次不跑        ; 「跳過一次」旗標
```

remake 對應：`World` 要能回答「這一回合是哪一方、那一方是不是電腦」。
`ds:8F46` 那個一次性跳過的來源（`0x2CCA7`，`[bp+08] >= 8` 之後設）
**還沒解**，remake 先不做。

## 一回合的順序

```
2D76:0002()   建艦隊
2D76:0732()   （未讀）
2E54:000C()   清表 → 逐艦隊決定 → 畫敵方兵力圖 → 算每格優先度
2E54:0344()   五個階段
```

### 清表

`ds:D50E`／`ds:D54E`／`ds:D5CE` 各 32 個 word 清 0，`ds:D60E` 清 0。

### 逐艦隊決定（`2E54:005D`，`docs/re/79`、`docs/re/196`、`docs/re/197`）

每一支先填 `+0x79 = 0xFF`，再照三條分支改寫（順序就是原版的順序）：

```
+0x08 == 4          → +0x79 = 0，其餘什麼都不寫
+0x00 bit0 有設     → 這一格有戰鬥（+0x13 & 14h）、有敵方艦隊（+0x28／+0x29）、
                      或不是自己的（+0x12 != 陣營）→ 2E54:1955 往首都退一格；
                      三個條件都不成立 → +0x08 = 3、+0x07 = +0x06（原地出擊）。
                      兩條都 +0x79 = 0
+0x00 bit0 沒設     → 所在星域沒有戰鬥（+0x13 bit2）就整支不碰，+0x79 留 0xFF；
                      有戰鬥時 2E54:16F5 回非 0 → +0x79 = 3、ds:D5CE[星域]++，
                      否則 2E54:1955、+0x79 = 0
```

三條都 `ds:D60E++`。`+0x28`／`+0x29` 是兩個陣營各自在那一格的艦隊數
（`docs/re/199`），所以 bit0 那一路的三個條件講的是同一件事——
**這一格待不住就往首都退**。

留著 `0xFF` 的那些**正是後面五個階段的候選來源**（`2E54:143F` 要求
`+0x79 == 0xFF`）。

### 敵方兵力圖（`2E54:1A76`）

```
對每一支敵方艦隊 f（297B:131C(…, 0xFF, 2)）：
    行動 0 或 1 → 格 = 路徑上的下一格
    行動 5      → 格 = f 所在星域
    其餘        → 跳過
    ds:D54E[格] += f[+0x0F]
```

**收據對過**：`s3aicomp` 的四格全中，星域 25 是 69 ＝ 九支艦隊槽數之和。

### 每格優先度（`2E54:019F` → `2E54:0222`）

```
只算「與首都連通」而且「擁有者 ＝ 自己」的格子，其餘 0
ds:D50E[i] = Σ（相鄰、擁有者 ＝ 敵方的 n）:
    (n[+0x13] bit0 == 0 或 ds:D54E[n] > 4) ? 4 : 2
```

### 五個階段

| # | 常式 | 做什麼 | 能不能實作 |
|---|---|---|---|
| 1 | `2E54:035E` | 守首都：`n = min(ds:D54E[首都] ÷ 3 + 1, 16)`，先 `2E54:03C3(n)` 湊，缺的 `2E54:0513(n)` **在首都新編艦隊**（上限 16 支）| 全部已讀（`docs/re/181`、`docs/re/182`）→ **可以** |
| 2 | `2E54:0EC2` | 打**最近的無主星域**：收「擁有者 ＝ 2 且走得到」的格、依距離升冪、對第一名用模式 2 取**兩支**（湊不滿就不打）、`2E54:1B17(f, 1, 格)`。費沙（14）要先過 `2E54:0F93`（伊謝爾倫的歸屬 ＋ 回合門檻）| **可以** |
| 3 | `2E54:0725` | `ds:D58E[i] = 缺口 ÷ 4 ＋ 前線(0/1)`；反覆挑滿足率最低的格、模式 0 取艦隊、`2E54:1B17` 指派 | **可以** |
| 4 | `2E54:08D3` | `2D54:0000` 重算 `ds:D50E`（攻擊目標分 ＝ 路線表計數 × 2048 ÷ (敵方兵力+1)，路線由 12 種戰略態勢碼決定）→ `2E54:08E3` 重算 `ds:D58E`（缺口 ÷ 5 ＋ `RNG%4`）→ `2E54:0978` 依優先度降冪對 `ds:D58E != 0` 的格呼叫 `2E54:0AAB` | 含亂數 → **除亂數外可以** |
| 5 | `2E54:119E` | 收尾指派：依攻擊目標分挑第一名、`2E54:13A8` 在它的鄰居裡挑「自己的、離首都最近」的前進基地，把**所有還沒決定**的我方艦隊掃一遍 | **可以** |

擁有者碼：**0 帝國、1 同盟、2 無主**。全遊戲寫死的星域編號只有兩個——
13（伊謝爾倫，`2E54:0AAB` 的銅板）與 14（`2E54:0F09` 的特例）。

## 可以先實作的一塊：階段三

這一塊的每一步都有證據，而且不依賴未讀的常式。

```
對每個擁有者 ＝ 我方的星域 i：
    前線 = (ds:D50E[i] ÷ 2 >= 1) ? 1 : ds:D50E[i] ÷ 2
    缺口 = max(ds:D54E[i] − ds:D5CE[i], 0)
    ds:D58E[i] = 缺口 ÷ 4 + 前線
ds:D5AE[0..31] = 0
重複：
    格 = ds:D58E[g] != 0 之中 (ds:D5AE[g] × 100 ÷ ds:D58E[g]) 最小的那一個
         （ds:D58E[g] <= ds:D5AE[g] 視為 0xFF；首都 0／31 視為 0）
    沒有 → 結束
    艦隊 = 挑分數最高的候選（模式 0：完整度 ≥ 50、不要求編制滿、權重 3 2 8 1、主力門檻 0）
    沒有 → 結束
    若 艦隊[+0x06] == 格：（+0x08 != 5 時）+0x08 = 5、+0x07 = 0xFF
    否則：+0x08 = 0、+0x07 = 格
    ds:D5AE[格]++
```

候選分數（`2E54:1574`）：

```
無法戰鬥（+0x00 bit0）或走不到 → 0
分數 = (Σ 編制槽艦艇[+0x08] ÷ 10) × 艦隊[+0x3C] ÷ 100     ; 32 位元
     × 艦隊[+0x0F] ÷ 艦隊[+0x0E]
     × 權重[ 類別表[艦隊[+0x09]] ]
     × (艦隊[+0x08] != 5 且 艦隊[+0x07] == 目標 ? 2 : 1)
     ÷ (兩格距離 × 2 + 1)
     ÷ (主力槽數 < 主力門檻 ? 4 : 1)
分數 == 0 → 1
```

類別表（`ds:5F52`，16 格）：`0 0 0 0 0 2 0 0 0 0 1 1 2 2 3 3`。

## 不能做的

- **五個階段的骨架都讀完了**，剩下的未讀項（`0x1238D` 的費沙事件結算、
  `2E54:063C` 的排序鍵）都不影響主流程的形狀，
  但**在補上之前不得把它們猜出來**——猜出來的行為對不上原版，
  會讓「照原版」這個宣稱失效。
- **`ds:8F48`（費沙進入戰局）由誰設還沒讀完**，所以 remake 先讓它固定為 0，
  並在報告裡寫明態勢碼只會落在 0／4／8。
- **不要用 remake 自己的亂數去湊 `RNG % 4`。** 階段四要對拍就得先把
  原版 RNG（`3CD5:000C`）的呼叫次序完全對上；在那之前階段四只能做
  不含亂數的部分，或整段先不做。
- 預設仍然是**原版**行為；這份規格描述的就是原版，不是強化版
  （強化版在 `docs/spec/017` 的 `Focused`）。

## 要使用者裁決的一件事

證據上的關卡都關了，接下來只剩一個**會改變 remake 行為**的動作：
把 `internal/ai` 的 `Original` 從「什麼都不做」換成這份規格。

- **現況**：`Original` 回 `nil`。那是錯的（`docs/re/175`）——原版有 AI，
  只是既有收據都停在玩家的座位上，所以量不到。
- **換掉之後**：電腦座位每個戰略回合都跑一次 AI（`04F8:030E`，
  `docs/re/186`），敵方艦隊會動。影響範圍已經量完：
  - **25 份 1 MB 傾印**中只有被 poke 過的 `s3aicomp` 跑過 AI，
    其餘 24 份的 `ds:D60E` 與整張 `ds:D50E` 都是 0（`docs/re/189`）——
    原版在那些點也沒跑過，換掉不會產生差異。
  - **`turn260`／`turn320`／`turn450` 不一樣：AI 有跑**
    （`docs/re/198`）。對 `ds:D60E` 設監看重跑一次，抓到
    `2E54:1183` 與 `2E54:0837` 在第四次「實行」之後 3.7×10⁶ 步
    各動一次，一共指派三支艦隊。`internal/game` 的
    `TestExecuteTurnMatchesOracle` 拿整張畫面比這三張。
    **但換預設動不到它們**：那個局面下 remake 一支艦隊都沒有，
    而**原版的新遊戲也是零艦隊**——新遊戲樣板只有 `ADMIRAL.DTX`
    與 `STELLAR.DTX`，沒有 `FLEET.DTX`（`docs/re/200`）。
    原版那三支是電腦在第一個 AI 回合**自己建的**。
- ⚠ **測試的綠燈證明力有限**：`Game.runBrain` 在 `Resources.Graph` 是 nil
  時整段跳過，而 `internal/game` 測試共用的 `load()` **沒有載星域圖**
  （正式入口 `internal/bootstrap` 有）。所以「換了 `Original` 之後
  `go test` 還是綠」在目前的測試裡**不代表決策層被跑過**。
  要真的驗，得用有接圖的入口（`builder_test.go` 的 `reachBrainPhase`）。
- **建議**：換預設是安全的（`ai.Turn` 回空清單），但**單獨換它沒有作用**。
  真正擋在前面的是**階段一：建艦隊**（`2D76:0002`／`2E54:0513`）——
  `ai.Turn` 不含它，因為它產生的是新艦隊不是命令，`[]Order` 裝不下。
  從新遊戲開始的一局，先做那一段，電腦才會有艦隊可以指派。

**規格已經是 READY**（證據夠了），但 production path 仍然不動——
換掉 `Original` 是上面那個裁決，不是 READY 的自動後果。

## 驗收

實作之後要能重現收據 `s3aicomp` 的那一趟：同一個初始局面、
同一個座位設定，跑完之後 `ds:D54E`／`ds:D50E`／`ds:D58E`／`ds:D5AE`
與四支艦隊的 `+0x07`／`+0x08` 逐格相同。階段一、二、五還沒實作之前，
只能驗到階段三為止的中間狀態，而且要在報告裡寫明。

## 階段二與階段五的已知部分

### 階段二

```
候選 = { i : 星域[i].擁有者 == 無主 且 到首都走得到 }
      （星域 14 另有一道未讀的條件）
若 候選為空：結束
目標 = 候選中「到首都步數」最小的那一個
兩支 = 用模式 2 連取兩次最佳候選（取到就把 +0x79 標成 1）
若 不滿兩支：結束
對兩支都：已經在目標 ? (+0x08 = 5、+0x07 = 0xFF) : (+0x08 = 1、+0x07 = 目標)
```

模式 2 ＝ 完整度門檻 80（艦隊已在目標星域時 50）、要求 `+0x0F == +0x0E`、
權重 `3 4 0 0`、主力門檻 4。

### 階段五

```
目標格 = ds:D50E（攻擊目標分）最大的那一格
目標 = 2E54:13A8(目標格)                  ; ★ 未讀
對每一支 +0x79 還是 0xFF 的我方艦隊 f：
    f[+0x0F] == f[+0x0E]                     → 去首都，行動 2
    否則若 走得到目標：
        f[+0x3C] < 60 或 f[+0x08] == 3       → 去目標，行動 3
        否則                                  → 去目標，行動 0
    否則若 走得到首都                          → 去首都，行動 2
```

`2E54:13A8` 沒讀之前，階段五不能實作——「目標格」與「目標」不是同一個東西。

## 進軍路線表（`docs/re/178`）

攻擊目標分的「累積分」＝ 這一格在該陣營的進軍路線表裡出現幾次。
表在 `docs/internals/data/ai-advance-routes.json`；選哪一組由 `2D54:0163()` 的 **12 種戰略態勢碼**決定——伊謝爾倫（13）在誰
手上、費沙（14）在誰手上、`ds:8F48` 有沒有設（`docs/re/179`）。
**伊謝爾倫不在自己手上時路線表只有 `[13]`**，所以第一目標永遠是它。

費沙（星域 14）的門檻：伊謝爾倫（星域 13）還在敵方手上時不打，
除非回合數過門檻（帝國 238、同盟 318，十次「實行」一個月）。

一個陣營最多 16 支艦隊（`ds:8F49[陣營] < 16`）。

## 主動建艦隊的閘門與配額（`2D76:*`）

`2D76:0002` 是**迴圈**：閘門過了就 `2D76:01A5`（配額排序 ＋ 依序試建，
成功一類就 break、回 1），回非 0 就再繞一輪（`docs/re/210`）。
收據上同盟第一個回合建了三支，第四輪被錢擋掉。

```
2D76:0060()：能不能建
    ds:8F49[陣營] >= 16                       → 不建
    n = 現有艦隊數；n < 3                     → 回 n（不看錢）
    錢 = ds:8F6A[陣營×4]（總稅收）
    ds:8FD4[陣營] >= 3                        → 錢 = 錢 × 3 ÷ 4
    ds:8F72[陣營×4]（艦隊維持費）× 20 >= 錢    → 不建
    否則                                      → 回 n

2D76:011C()／2D76:01A5(總數)：每個類別 現有 − 總數 × 配額 ÷ 100（捨去）
    配額 40／45／5／10％，依差**升冪**排序（2D76:0251），最缺的先試
```

挑人選（`2D76:02FA`，`docs/re/203`）：對全部提督用 `2D76:0434` 算分、
依 `2D76:04FD` 排序，再抽一次亂數（0–`7FFF`h）分四層挑：

| 挑第幾名 | 條件 | 機率 |
|---|---|---|
| 第四 | `r >= 7000h`、筆數 >= 4、等級 >= 16 | 1／8 |
| 第三 | `r >= 6000h`、筆數 >= 3、等級 >= 16 | 1／8 |
| 第二 | `r >= 4000h`、筆數 >= 2、等級 >= 16 | 1／4 |
| 第一 | 其餘 | **1／2** |

條件不成立就往下一層試，不是直接落到第一名。

挑完之後 `2D76:0576(提督, 類別)` 從那一類的鍵裡等機率抽一個，
寫進提督 `+0x08` 的高四位（之後搬進艦隊 `+0x09`，`docs/re/204`）：
類別 0 是 `00 01 02 03 04 06 07 08 09`、1 是 `0A 0B`、2 是 `05 0C 0D`、
3 是 `0E 0F`——正好是 `ds:5F52` 的反表。

已實作成 `ai.BuildGate`／`ai.ClassQuotaOrder`／`ai.PickBuildAdmiral`／
`ai.PickClassKey`。**建艦隊那條路的反組譯到此讀完**，只剩
`ds:8FD4[陣營]` 的語意（它只影響閘門鬆緊）。`ai.Turn` 還不呼叫它們。

**整條已經串起來了**：`ai.BuildPass` 把六段接成一趟，
`OriginalStrategy.Build` 讓它成為一個 `ai.Builder`，
`Game.runBrain` 用型別斷言問一次、有實作才建（守「每陣營 16 支」與
「一位提督一支」兩道限制）。沒實作 `Builder` 的 `Brain`
（`Original`、`Focused`）完全不受影響。

**三件是 remake 自己決定的，不是量出來的**，都標在程式註解裡：

| 項目 | 原因 |

| 「沒有帶艦隊」用 remake 的艦隊表推 | 原版讀 `+0x09` bit7，但 `docs/internals/08` 記著載入時被夾成 `0x7F` 的待驗矛盾（過濾本身已照 `docs/re/208` 量到的做）|
| 配額平手時的次序 | 原版走 qsort（`3C6A:000D`），平手沒有保證 |
| 等級 > 43 的折算值 | 沒有觀察到那麼高的等級（`docs/re/205`）|

## 階段一的完整形狀（`docs/re/180`–`docs/re/182`）

```
n = min(ds:D54E[首都] ÷ 3 + 1, 16)
n -= 2E54:03C3(n)                       ; 先從現有的湊
若 n > 0：2E54:0513(n)：
    首都不是自己的 → 不做
    清單 = 28E0:0103(&清單, 首都, 25h, 0)      ; 提督編號
    依 2E54:063C 排序                          ; 等級 → 統率力 → 運用，三段降冪
                                               ; （docs/re/201、rules.SortAdmiralsForFleet）
    對每個提督（ds:8F49[陣營] < 16 且 n > 0）：
        艦種 = 提督[+0x08] & 0Fh
        若 星域[首都][+0x30 + 陣營×28 + 艦種×4] < ds:4E3A[陣營×208 + 艦種×26]：跳過
        槽 = 提督原本的槽（空著就重用）否則掃自己陣營 16 槽找第一個空的
        提督[+0x09] = 槽（同時清掉 bit7）
        提督[+0x07] 是 0FFh → 從 ds:5F78[編號] 填預設副官
        副官合格（五個條件）→ 副官[+0x09] = 同一個槽
        艦隊[槽][+0x08] = 5、[+0x07] = 0FFh、ds:D60E++、n--
```
