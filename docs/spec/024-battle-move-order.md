# 024 — 戰場的「移動」命令（分隊層）

狀態：**READY／已實作**（分隊層）。艦隊層（旗艦）的「移動」要再選一次
抵達朝向，**不在這一份**。
證據：`docs/re/119`、`docs/re/120`、`docs/re/121`。
收據：`s3cmdmove`（下了一次移動命令的記憶體）、`s3cmdrange`（選點狀態的畫面）。

## 流程

1. 命令選單第一項「移動」（四張分隊選單）→ 進入「等玩家點目的地」。
2. 這時右側的分隊面板留著（收據 `s3cmdrange` 上面板還在）。
3. 左鍵點戰場：
   - 點在戰場那一塊外面 → 取消。
   - 世界座標 `x` 不在 0–2031 或 `y` 不在 0–2023 → 取消。
   - 那一格過不去（`rules.BattleTerrain.Passable`，＝ 原版 `1588:04EA`）→ 取消。
   - 都過 → 分隊的目的地 ← 點到的世界座標，分隊行動 ← 0（移動）。
4. 右鍵取消，不動任何狀態。

世界座標 ＝ 畫面座標 − 戰場原點 ＋ 視野位移。收據驗過：點畫面
(200,200)、視野位移 (1040,540) → 寫進去的是 (1240,740)，
**沒有取整、沒有夾到範圍內**。

## 範圍圈是提示，不是限制

原版在選點時會畫兩個圖形（`docs/re/120`）：內圈是半徑
`(速度 × 8) ÷ 3 ＋ 8` 的正圓，外形是照回轉速率積分出來的可達邊界。
但點擊的檢查鏈裡**沒有距離判斷**（`docs/re/121`），所以圈外的合法格
一樣接受。

## 已知差異

| 差異 | 理由 |
|---|---|
| remake 不畫那兩個範圍圖形 | 內圈的公式量到了（`docs/re/120`，偏差 0.4 像素），外形的逐點重現還沒做 |
| 目的地不合法時 remake 只取消，不跳訊息 | 原版跳 `ds:4A24`「這是無法行動的地方。」。框已經可以畫了（`screen.DrawMessageBox`，圖塊來自 `FRAME.BLK`，收據 `s3msg` 的框那一圈 16,640 個像素 0 差異）；**還缺框裡那行字的排版與關閉時機**，所以還沒接上玩家路徑 |
| 旗艦的「移動」還不能用 | 要先逆向抵達朝向的選擇器 |

## 驗證

`TestMoveOrderSetsTarget`（走完整條玩家路徑：點分隊 → 點「移動」 →
點目的地）、`TestMoveOrderRightClickCancels`、`TestMoveTargetRejectsOutOfField`。
