# 141：系統視窗游標與讀檔取消

狀態：限定CONFORMED（2026-10-13）。正常Linux兩陣營原圖／HD、三劇本與存讀退出通過；戰術取消僅回歸測試，不外推正常戰術GUI。結果見[驗證120](../playtest/120-system-dialog-polish.md)。使用者回報讀取檔案及結束確認的游標停住，另回報主選單讀檔取消會直接進入帝國初始局。

## 證據與審查

已發行 v.1.2.0-20261012 Linux 程式由片頭、主選單、防拷、會計與訂造正常進入戰略。X11 分別開啟讀檔及結束確認，滑鼠由畫面座標 (300,240) 移至 (400,240)，兩組完整視窗逐像素相同；唯讀影格收據仍更新，右鍵均能返回戰略。原始收據留在 `workplace/modal131/before/`。

`Game.liveCursor` 缺少 StateLoadGame、StateSaveGame、StateLoadFaction 與 StateQuitConfirm。系統視窗 JSON 保存的是擷取當時的固定位置；保存及退出另有當時的局部重畫。保存及陣營選單補畫即時游標，可能同時留下固定游標。公開 MoveMouse 與 Click 仍更新座標。

主選單與戰術均可進入 StateLoadGame，但 RightClick 的通用返回分支固定設為 StateCommandPhase，沒有保存入口。New 已準備初始局，因此主選單取消時會顯示預備的帝國局。這是 remake 的返回接線缺漏。

審查採用既有畫面座標契約及使用者指定的取消語意，限定以下範圍，據此標 READY。不新增 DOS 原版對拍宣稱。

## 契約

1. 四張視窗由目前 Game 畫面滑鼠座標驅動游標，繪製沿既有 y−40 換算。
2. 游標在存檔列、陣營選單、確認按鈕及其他動態內容之後繪製。擷取時的局部重畫不得蓋住玩家游標或留下第二個固定游標。
3. 讀檔記住入口：主選單取消回主選單，戰略取消回戰略，戰術取消回原戰術畫面。取消不載入劇本、不開始新局、不推進回合。已開啟陣營小選單的右鍵語意沿088，不擴張為關閉。
4. 保留原始 JSON 與擷取證據。退出確認、保存及實際讀取規則、存檔格式、AI 與音訊保持。
5. 頂端功能列攔截輸入時，沿負座標隱藏遊戲游標。

## 驗收

- 回歸先證明即時游標與主選單取消失敗，再驗四視窗移動、確認按鈕上的完整游標、無固定殘影與三種返回入口。
- 正常 Linux GUI 由片頭進入，兩陣營、原圖／HD抽樣；三個額外劇本、保存重讀及退出取消／確認使用可見按鈕。
- 標準測試、修正程式正常啟動、來源雜湊、擁有權及容器清理。字型、音樂HD與啟動進度另行追蹤。
