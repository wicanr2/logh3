# SPEC 036 — 月底交付的船艦放到哪裡

證據：[`docs/re/264`](../re/264-ship-delivery-destination.md)（反組譯 `2B5F:001F` ＋ 收據 `shipdeliver3`／`shipdeliver4`）

[`docs/spec/035`](035-month-end-gate.md)（月底閘門與本體順序）

## 原版做什麼

月底本體的第一件事是 `2B5F:001F`：把 `ds:8F9C[陣營]` 那七個 32 位元的
「建造中」數量，**加**進兩個地方——

- 自己陣營**首都行星**的補充存量 `+0x20 + 艦種×4`
  （帝國奧丁 ＝ 星域 0 第 0 顆、同盟海尼森 ＝ 星域 31 第 4 顆）；
- 自己陣營**首都星域**記錄的艦艇彙總 `+0x30 + 陣營×0x1C + 艦種×4`。

七個艦種一次做完，不打折、不受行星擁有者影響，也不看那顆行星能不能
補給該艦種。緊接著的 `0654:0130`（船艦接收報告）印的就是同一組數字。

星域記錄那一份每回合會被 `2703:12EB` 從行星重算
（[`docs/internals/22`](../internals/22-stellar-dt.md)），**行星那一份是本體**；
兩邊都寫是為了同一回合內後續的讀取（新編艦隊走的是星域那一份）。

## remake 要做什麼

1. **每個陣營各留一份「建造中」**。目前只有玩家那一份（`Game.building`），
   電腦那一方每個月重算完就丟掉，於是永遠不交付。
2. 跨月結算時，**先交付上一份**，再算這個月的新計劃：對兩個陣營各做
   `capitalPlanet(f).Ships[k] += building[f].Ships[k]` 與
   `ReturnRegionShips(首都星域記錄, f, k, building[f].Ships[k])`。
3. 首都用 `ai.Capitals`（0／31）；首都行星是該星域切片的第 0 顆（帝國）
   與第 4 顆（同盟）——**不是「第一顆」通吃**，同盟那邊是切片的最後一顆。
4. 交付數量就是 `docs/spec/004` 已經算出來的 `BuildPlan` 各列船艦數，
   不另外取整或打折。

## 怎麼驗

同狀態驗證用 `shipdeliver4` 的兩份行星表：帝國從回合 9 跨到 10 的差是
`3790 1260 6830 630 4550 3250 1030`，只落在奧丁一顆上。remake 從同一份
開局狀態跑到同一個跨月點，首都行星那七格的增量要相同。

## 不在這一份裡

- `ds:8F9C` 的**寫入點**（訂造畫面把玩家輸入存進去的那一行）還沒定位，
  `docs/re/264` 只到「`0EF0:0B20` 把那個遠指標交給 `0F7A:0445`」。
  remake 這一側用自己的 `BuildPlan`，不受影響。
- **同盟那一側沒有收據**。`2B5F:001F` 讀 `ds:8F1D` 決定寫哪一組，與哪一方
  是玩家無關，所以兩個陣營都交付是強推論；量到的那一趟卡在帝國的接收報告
  上，同盟座位一次都沒跑（`docs/re/264`）。remake 兩邊都交付。
- **交付之後 `ds:8F9C` 由誰重填**：月底本體後面的訂造那一步
  （`0654:02E0`），`2B5F:001F` 自己不清。remake 這一側每個月底用新算出來的
  計劃覆蓋，與 `docs/spec/004`「建造中 ＝ 上一份計劃買到的船」一致。
