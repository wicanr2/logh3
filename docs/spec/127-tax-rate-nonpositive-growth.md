## 原版行為

對陣營 `side` 的每個星域（擁有者等於 `side`），成長率 `g` 是星域 `+0x1E` 的有號 word，`base` 是難度基價表 `ds:147E` 的第 `level` 格（dword）：

- `g <= 0`：`v ← base × 5 ÷ 100`，**直接寫入 `+0x26`（低位元組）**。不乘營運、不乘能力、不看民心、不夾限。
- `g > 0`：`v ← g × base ÷ 100`，再依序乘除營運與兩項能力、依民心倍率縮、最後夾在 1 到 200。

## 與 remake 的差距

`rules.TaxRatePerMille`（`internal/rules/newgame.go`）兩個分支共用後半：`g <= 0` 時 `v = base × 5 ÷ 100` 之後仍會繼續乘除與夾限。
差異測試轉接器 `internal/rules/decomp_taxrate_test.go`（環境變數 `LOGH3_DECOMP_TAXRATE`）實測：向量 761 案、比對 8074 個星域，

| 類別 | 星域數 |
|---|---:|
| 與原版相符 | 7820 |
| 成長率 <= 0，與原版不符 | 204 |
| 成長率 > 0，輸入域外不符（民心 > 200 的同盟側，或基價不在 50 到 200） | 50 |
| 成長率 > 0，輸入域內不符 | 0 |

也就是成長率 > 0 的主路徑與原版逐格相符，差距只在成長率 <= 0 這一條。

## 可達性

量到的開局狀態成長率都是正的。遊戲中成長率是否會降到 0 以下（天災、叛亂、月度成長更新）目前沒有證據，標 unknown。
無主星域的那一支（`090A:0DC0`，`rules.RecomputeNeutralTaxRates`）已經是這個形狀。
