## 轉移旗艦

1. 所有AI模式、玩家／CPU、兩陣營與雙人模式使用同一開關。戰場第0分隊由正艘數被擊毀為零才觸發。非戰鬥的戰略耗損與提督失蹤事件沿既有規則。
2. 候選為同艦隊、未離場、艘數大於零的一般分隊，艦種必須為0或1。索敵分遣隊、其他艦隊、巡航艦、已毀或已離場分隊排除。
3. 選艘數最多者；同艘數取較小的分隊序，完全相同再取既有單位序。選擇不取亂數，也不逐候選重擲。
4. 謬拉作為帶隊提督時必定轉移，不耗亂數；其他提督使用本場既有 `Rand.Next()%100 < 25`，約25%。副官是謬拉不保證成功。無候選或開關關閉不取亂數。
5. 成功後交換第0組與候選的編制引用及旗艦隊形槽，候選成為第0組。保持單位切片索引及池索引，避免交戰排程／目標引用錯位。艦隊位置改為新旗艦位置，不搬動任何艦艇、不增加艘數、不回補彈藥。原旗艦保持零艘，於既有末端清理作廢。
6. 每次擊毀最多判一次。成功後的新旗艦若再被擊毀，才有下一次機會。失敗後不在回合末或後續傷害重擲，沿既有全滅報告與提督失蹤。
7. 傷害演出的前後快照保留當次被擊毀的舊旗艦。規則在下一擊或下一階段前已使用新旗艦。艦隊交火、要塞砲及行星反擊的共用接點皆須抽測。
8. 原池編制、SHIP分隊序／隊形槽、typed編制／單位、艦隊座標同時同步。公開六表保存及讀回能保留新旗艦；不新增原版存檔欄位。戰術讀回整場重建仍由#48追蹤。

## 名將移動加成

- 新增獨立開關，預設開啟。僅在既有強化模式且萊因哈特或楊威利作為存活帶隊提督在場時，啟用規格 [140](140-hero-tactics-and-release.md)的1.5倍新移動額度。
- 關閉時，移動範圍及下回合新額度恢復一般值；不改目前已取得的剩餘額度，不累乘、不改原始速度。名將戰術AI仍啟用。
- 原版規則模式仍不啟用名將移動加成。切換設定不改艦隊資料及原版存檔格式。

## 設定與 Windows 啟動

- 系統設定顯示「轉移旗艦」與「名將移動加成」，各自開／關。偏好沿既有玩家存檔目錄的 `preferences.json` 保存；保留音色與未知鍵，缺鍵用預設，保存失敗不套用半套新設定。
- Windows封包未指定資源旗標時，從執行檔旁的 `original`、`data`、`art`、`music` 讀取；明確指定的旗標優先。開發工作樹沿既有預設。引擎包缺原版時明示錯誤，不回退載入另一份資料。
- 沿用既有 Docker／Wine 工具鏈；完整包及音訊僅本機。已發布tag與Release保持原身份。
