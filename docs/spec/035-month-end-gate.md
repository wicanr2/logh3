## 什麼時候結算

每個座位取得控制之前跑一次 `0654:0034`（`04F8:01B9`，玩家與電腦兩條路徑
都跑）。它自己帶閘門，**兩個條件同時成立**才做月底結算：

| 條件 | 意思 |
|---|---|
| `ds:8FF4[陣營] != 0` | 主迴圈在 `inc [8F18]` 之後把 `ds:8FF4`、`ds:8FF5` 都設 1；`0654:0034` 做完清掉自己那一格 → 一個陣營一個回合只結算一次 |
| `ds:8F18 mod 10 == 0` | 一個月十回合 |

三份收據，同一組點擊、同一個斷點、同一個命中步數 `#243674283`：

| 收據 | 旗標 | 回合 | 結果 |
|---|---|---|---|
| `monthgate7` | 0 | 380 | 只走共同尾巴 |
| `monthgateA` | 1 | 380 | 走進本體，停在月報畫面 |
| `monthgateB` | 1 | 381 | 只走共同尾巴 |

## 每個回合都跑的那一段

閘門不成立時跳到共同尾巴，**它每個座位回合都跑**：

```
090A:0E6D()
    2703:02E5()      32 格：2703:034E 重算經濟力 → 2703:0AB8(星域, 0) 累加預估稅
                     → 2703:0DA1 未安定度
    090A:0E88(0)     帝國：297B:10DE 維持費 → ds:8F72／ds:8F82；
    090A:0E88(1)     同盟：軍事費 ＋ 總稅收 − 維持費 − 移動經費 → ds:8F5A
ds:8FF4[陣營] ← 0
```

**這一段是冪等的。** `monthgate7` 與 `monthgateB` 各跑三趟（載入後一趟、
兩個座位各一趟），三趟的 20 筆逐筆累加值**完全相同**，總額都是 `0x334B`。
也就是說旗標 0 那一趟只是「照現在的狀態重算下個月的預估」，不改行星。

remake 對應：`Game.taxTotal[陣營]` ＝ `estimateTaxFor(陣營)`，維持費與移動
經費本來就是現算的（`fleetUpkeep`）。**每個回合都要重算**——中途打下一個
星域之後，右側面板與徵稅計劃上的預估徵稅額當回合就要跟著變。

## 閘門開著時多做的事

順序（`docs/re/255`）：

```
2B5F:001F()                         ds:8F18 != 0 才跑
0654:0130()                         月報：船艦接收（參數 ds:8F18 − 1 ＝ 上個月）
090A:0E6D()                         ← 共同尾巴那一支，先跑一次
0654:0486()                         月報
2B5F:0103(0)
0654:02E0()                         月報
ds:8F5A/5C[陣營] ← 2B5F:0103(1)     下一期的船艦建造費
2703:03AF()                         旗標 1：真正的收稅（只掃 +0x12 == ds:8F1D 的格子，
                                    逐行星扣、+0x27 ← +0x26），軍事費 += 總稅收
ds:8F62/64[陣營] ← ds:8F52/54[陣營]  原定軍事費留一份
ds:8F52/54[陣營] −= ds:8F5A/5C[陣營] 軍事費 −= 船艦建造費
ds:8F94/96[陣營] ← ds:8F5A/5C[陣營]  已支付的船艦建造費
ds:8F7A/7C[陣營] ← 0                 累計已付維持費歸零
ds:8F8A/8C[陣營] ← 0                 已支付移動經費歸零
（落到共同尾巴，090A:0E6D 再跑一次）
```

三支月報（`0654:0130`、`0654:02E0`、`0654:0486`）開頭都看
`ds:8F23[ds:8F1E]`——**只有玩家座位看得到**。

`090A:0E6D` 在這一趟出現兩次，所以**月底那個回合預估值被重算兩次**：一次在
`2703:03AF` 之前、一次在之後。收據 `monthgateD` 把座位 0 poke 成電腦讓月報
直接返回，`0654:0034` 只命中一次而 `ds:8F6A` 被歸零三次
（`2703:02F7` → `2703:03D5` → `2703:02F7`），第三趟的逐筆值與前兩趟全都不同
——真正改狀態的是 `2703:03AF`，第二趟 `090A:0E6D` 的用途是把預估值刷成結算
之後的。

## remake 要做到的

1. 月底結算的閘門 ＝ `回合 mod 10 == 0`，一個回合只跑一次。**已符合**
   （`Game.finishTurn`）。
2. 預估徵稅額**每個回合**重算，不是只有月底重算。
3. 月底那一趟的順序是「收稅進國庫 → 切造船預算 → 扣款 → 重算預估」，
   重算排在最後。**已符合**（`Game.monthEnd` 第 3 步）。

第 2 條的實作是 `Game.refreshTaxEstimate()`，`Game.finishTurn` 每個回合呼叫
一次（月底那一趟在 `monthEnd()` 之後，與原版共同尾巴的位置相同）。

`0654:0007` 在 mod 10 之前每回合都跑的那一支是 `2B5F:02B2`：32 格回充
飛彈與艦載機存量，與錢無關（[`docs/spec/039`](039-region-supply-pool.md)、
[`docs/re/273`](../re/273-region-supply-pool-refill.md)）。

## 收稅是逐座位的（2026-09-16 補，`docs/re/321`）

`2703:0AB8(星域, 旗標)` 旗標 0 只累加預估、**旗標 1 才從行星扣**，而旗標 1 只有
`2703:03AF` 會叫，它只掃這個座位陣營的格子。所以帝國座位扣帝國的、同盟座位扣
同盟的、無主星域永遠不扣（`0AB8` 一進去就把擁有者 2 擋掉）。單人模式帝國玩家的
月初畫面：帝國已扣、同盟與中立只有成長；同盟那一份等玩家按完「實行」輪到同盟
座位才扣。無主星域的稅率由 `090A:0B5E` 第三段 `090A:0DC0(2)` 每月重算 ＝ 成長率。

remake：`rules.MonthEndGrow` ＋ `rules.CollectTax(陣營)`；`Game.monthEnd` 做玩家之前的
座位與玩家自己，`Game.beginTurn` 在「實行」之後、`runBrain` 之前做玩家之後的座位。
收據 `monthwork3`（796/02 帝國命令階段：同盟 `+0x27` 仍是舊稅率）、`monthwork4`
（再一次「實行」之後：同盟座位跑過）、`fcmd-rinfo-ballat`／`-fezzan`（796/01 的
68282／103100）。沒接的：`0AB8` 開頭擋 `+0x13` bit0–bit2 的格子、首都丟了不累加
總稅收——讀出來了，沒有收據。
