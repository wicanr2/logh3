| 0103／011C | 提交目標word；最佳量初值FFFF，beam可用時取量並寫武器0，其他武器只在量嚴格較大時更新 |
| 018B | 從攻方+3E減最佳量，保持16位回繞；不是扣目標+3E |

無beam候選時，最佳量保持FFFF，武器沿最後一個候選預估留下的值。
三候選診斷中選中的102只有飛彈mask2，實際提交武器2；攻方+3E由3000變3001。
此項保留已證實原版行為，不能走手動命令的mask拒絕。不得自行改成最大預估武器。
control=1是座位查詢結果，不把陣營1一律當電腦。正式061單人CPU仍拒絕下令。

## 型別與失敗模式

輸入為攻方typed分隊、按100查詢次序的候選、各目標當前+3E、三能力、
目標朝向／已提交武器、攻方控制模式、FLEET+45及Rand。
輸出為每候選預估量與score、排序、目標索引／武器及攻方新的+3E。
量及score是uint16，庫存是有效uint32，能力與選擇倍率為byte。
不修改typed分隊、艘數、庫存、目標暫存或存檔；Game成功後才寫原池。
候選空可無Rand。其他情況缺Rand、重複目標、mask無效、資料表缺項、
能力／座標越界或零防禦，全部在RND與資料變動前回error。
零距離沿093已核准曲線首點，不讀原版未初始化stack。

Game須在完整欄位驗證後提交自己的+2C／+2E／+3E及候選+3C／+46／+48／+4A／+4C。
無候選只寫+2E=3。所有改動沿既有原池，不新增存檔格式。
手動100仍重查候選／mask；原版自動的上述錯誤不擴張到手動提交。

## 驗收與停止線

- 31案直接讀原版RAM／暫存器，比每個係數、百分比、三量、score、排序、所選索引與末端seed。
- Game比較原池命令、預估暫存及SaveSlot重讀；錯誤與061拒絕保持整表及seed。
- 標準產品測試必須通過。綠色測試只關閉此資料域，不代表正常玩家命令UI或完整演出。

正常來源→typed→規則已有093／100；本規格補自動選擇→原池→保存。
正式目標選單、跨艦隊排序、相位續接、099動畫與正常玩家路徑由092／056續驗。
不把31個受控局面、原版六tick標示或原版CPU診斷升格為正式玩家驗收。
