# 026 — 戰場的「補給」與「修理」

狀態：`READY`（規則已實作並對過原版資料；**畫面沒有做**，見下）

證據：`docs/re/131`、`docs/internals/44`、收據 `s3form` 的艦艇池。

## 觸發

運補艦（艦種 5）那張選單的第三項是「補給」，修護艦（艦種 6）那張的
第三項是「修理」。

## 誰能被點

同陣營、`+0x1E` bit7 沒設（沒出局）、距離 ≤ **收集半徑**，而且

| | 補給 | 修理 |
|---|---|---|
| 排除的艦種 | 5、6、7 | 6、7 |

**修理修得了運補艦，補給補不了補給艦。**「缺不缺」不是條件——補滿的
分隊照樣點得到，按下去給 0。

## 半徑

查**補給艦（艦種 5）／修理艦（艦種 6）**那一列的 `+0x06`（最高速度），
兩個陣營都是 30。原版同一個 6.4 算了兩次：

| 用途 | 算法 | 結果（16.16）|
|---|---|---|
| 收候選 | `速度 << 21 ÷ 5` | 12,582,912 ＝ 192.0 |
| 按下去確認 | `速度 × 0x66666` | 12,582,900 ＝ 191.99982 |

兩個都照抄。正好 192 像素的目標**列得出來卻按不下去**。

## 按下去做什麼

補給：

```
給飛彈   = min(目標艦種列[+0x10] × 目標 +0x08 − 目標 +0x0E, 補給艦 +0x0E)
給艦載機 = min(目標艦種列[+0x14] × 目標 +0x08 − 目標 +0x12, 補給艦 +0x12)
```

修理：

```
給 = min(目標 +0x0C − 目標 +0x08, 修理艦 +0x0E)
目標 +0x08 += 給
```

兩邊都是「兩個都 0 就什麼都不做」，而且**乘的是現有艘數不是滿編**。

## 已知差異（要收據才能補）

- 候選沒有高亮、選中沒有標記（`17A0:0427`／`17A0:05B2` 的畫法沒量）。
- 動手之後沒有結果訊息框（`1930:0AA2`／`1AAB:08FB`）。

半徑內沒有候選時跳的兩句（`ds:3F14`／`ds:403E`）已經照原版畫、照原版關
（`docs/re/138`）：`TestSupplyWithNoCandidateShowsMessage`。
