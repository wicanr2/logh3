## 已足夠描述的契約

下列標為 **proven**；靜態來源與受控實驗範圍分列於研究371。

1. `181B:00FA`先`1C03:0006`初始化，再依戰場清單順序逐艦隊：
   `1C03:006A(fleet)`、一般分隊`1C61:0153(fleet,j)`、索敵隊`j=FFFF`。
   任一回非0就重畫再跑整份清單；非0表示仍需處理，不等於座標必有變化。
2. 艦隊剩餘額度`+56/+58`無條件覆蓋成每回合額度`+52/+54`。
3. 一般分隊及啟用索敵隊的額度是有號32位16.16值`+24/+26`。
   初始化只讀巡航速度`+21`，新增量為`speed<<19`（速度×8×65536）。
   舊額度嚴格在`0<old<8<<16`時累加，其餘覆蓋。
   未啟用索敵隊（艦隊`+3A=FF`）不初始化其額度。
4. 分隊現在座標為`+34/+36`，集結點為`+28/+2A`。
   第0分隊與未啟用索敵隊走`1C61:0229`同步艦隊位置；其餘依完整Action分派。
5. 自主移動Action=0抵達時改Action=3並清額度。一般分隊在未抵達且額度不足8.0時
   也改Action=3並清額度；索敵隊不足一步則保留Action與額度。
6. Action=7F或3先依隊形重算集結點。7F的步長為艦隊`+49 bit0`設起時16、否則8；
   分隊`+16 bit1`設起再乘3/2。因此可為8／12／16／24。
   Action=3的步長固定8。門檻仍是額度至少8.0。
7. `1C61:0444`依指定步長算落點及通行結果，最後固定扣`8<<16`；
   前面雖算出實際距離，最後沒有用該距離扣額。研究372已補四種步長、斜向、夾界與受阻案例；
   第31輪正式分隊引擎已依此額度契約實作並驗證。

## 第31輪證據審查與正式接線契約

完整可丟棄模型依既有原版三邊界初態，初始化後每圈依清單順序執行艦隊、
一般分隊與索敵隊；33圈停止，7筆122-byte艦隊與55筆78-byte分隊全部零差異。
模型SHA-256：`b773090006858d456c004fad12b3a5137a031ec925ef48b0560ec6d342925593`。
只讀入entry與事先已證實的規則，end僅用於最後比較，不參與計算。
此為正式實作前的完整資料審查；正式引擎與玩家路徑結果另見下節。

- `BattleUnit`增加有號16.16 Budget及完整小地圖MarkerFlags／MarkerX／MarkerY；
  Action保留整byte，Out同步bit7。隊形沿用原版41槽與既有旋轉／夾界契約。
- `BattleFleet`載入完整Action、MoveFlags、ScoutMode(+3A)、ScoutState(+3B)、
  現在／備份／目標座標、兩種額度及朝向。原版不依Ordered布林略過艦隊。
- 旗艦、未啟用索敵隊只在目前位置不同時同步現在及目標位置；相同時保留目標。
  其他分隊只處理完整Action=0／3／7F，其餘不動。
- 一般分隊任何非0通行結果以欲前進候選避障；索敵隊遇FFFF改3、停座標並耗完額度；
  遇敵且Action非3則艦隊ScoutState=4、停座標耗完額度，Action不改。
  索敵隊Action=3遇敵才避障。回收時ScoutMode=FF、ScoutState=0，
  先將到點Action3改7F，再清小地圖bit7並設Action bit7（結果FF）。
- 小地圖移動沿用研究154的標記狀態機；已點著(bit6)的座標快照隨重畫更新，
  回收先擦標記，只有原本bit7／bit6均有時才清bit6，再清bit7。
  不保存DOS圖示指標、不新增航跡；082正式renderer讀+1A/+1C已畫快照、+19 bit7/6及低4位色號，回收後Out隱藏。
  回收後命中判定亦須排除Out，避免隱藏索敵隊遮住旗艦、阻擋正常再放出命令。
  圖示9依研究85代表不畫，不能當成一般圖塊貼上；離場Out亦不畫。
  第32輪入口／終態原版畫面審查確認移動中不畫游標，完成後恢復正常輸入顯示；
  限定呈現驗證見045，新35幀固定局面已對齊；其他局面仍按原門檻驗收。
  產品戰場畫布以原版色號3初始化上下外區；色號0在本色盤是藍色，不能當黑色。
- 正式Game以每次Tick執行一圈並讓產品renderer畫中間位置；輸入閘門比照第一階段，
  任一常式返回非0即續接，整圈皆0才續後續階段。不宣稱原版CPU步數／顯示時長相同。
- 既有可選自動戰術的移動意圖須轉成同一套命令：一般分隊Action=0，旗艦的意圖
  寫艦隊目的地、巡航額度與短程旗標，抵達朝向保留目前朝向。
  此為既有remake自動戰術的接線契約，不宣稱其AI選點與原版相同；
  規格061的被動電腦閘門保持有效，正常電腦不因此下令。
- 未放出的索敵隊另建本階段持有的typed紀錄，仍參與同步並回寫池；
  不加入可點選／攻擊的battleUnits。已放出索敵隊沿用現有正常命令入口。
- 保存時寫回SHIP的+05、+16低byte、+19、+1A/+1C、+1E、+24..2B、+34..37；
  FLEET寫回命令、朝向、額度與ScoutMode／State，未知byte保持。
