## 玩家契約

| 狀態／輸入 | 下一步 |
|---|---|
| 未啟用動畫，或動畫素材不齊 | 直接主選單，沿020 |
| 動畫中左鍵／右鍵／既有可送入Game的按鍵 | 直接主選單，沿020跳過契約 |
| 完整動畫自然播到最後一格，標題資源存在 | 保持末格約5.396秒，再進標題 |
| 標題中移動／右鍵／鍵盤 | 留在標題，計時繼續 |
| 標題中左鍵按下 | 主選單；同一事件不選陣營，放開不再提交 |
| 標題無左鍵，名義等待約15.442秒 | 清除動畫累加並從第0格重播，OPEN_M重新播放 |

末端1150、2000與標題9000參數及左鍵／逾時分支為 `proven`。
等待終點為倒數不大於3；秒數為 hardware-spec approximation。
沿用020的PIT頻率1193182 Hz／除數2048。停止追查ISR、逐週期重畫與中斷相位。
同一串正數 `Tick(d)` 決定同一結果；大步進剩餘時間帶到下一狀態，不丟掉。
只有最後可見格到標題的等待取代舊421索引所回1240；其餘逐格時程不改。

## 資料與呈現

- `bootstrap.LoadIntro` 用111正式parser載入 `SPTIT.350`，用既有16色換算載入 `SPTIT.RGB`。
- 動畫尾段349起用 `TITSPT.RGB`，末格保持同色盤；標題改用SPTIT，重播恢復BU16IBM。末格16色與雙跑逐byte相同，見431。缺TITSPT時沿020灰階fallback，不宣稱完整素材對拍。
- 兩檔齊全但損壞回錯，不以黑頁代替；缺任一檔時保留020的動畫→主選單fallback。
- 資源保存標題圖、色盤及從唯讀來源重建動畫的factory，不重用已耗盡XOR累加器。
- 完整640×350標題頁垂直置於640×480畫布的第65列，沿020畫布決定。
- 標題不畫游標、不疊文字。上下65列保持色號0，不豁免頁內像素。
- 新狀態追加，既有狀態編號、存檔格式與六張資料表不改。
- 標題沒有存檔UI；離場仍用既有主選單與正常防拷／劇本入口。

配樂要求沿原版 `OPEN_M`，動畫→標題不切換；標題→動畫先停止再重新要求同曲。
主選單要求停止。音源關閉時仍不播放。原版逾時重新讀OPEN_M已證實；實體裝置與人耳驗收仍屬#69。
原版素材只從玩家自備目錄讀取，不內嵌一般發行包。

## 驗收

1. 原版固定雙跑：標題與逾時畫面／palette相同；左鍵返回沿第96輪雙跑，右鍵／鍵盤由動態與靜態共同核實。
2. 正常bootstrap雙跑，不注入局面：完整421格→末格等待→標題；完整224000色號及16色符合原版標題。
3. 邊界前1 ns不轉場，期滿轉場；左右鍵／鍵盤、同事件防穿透、逾時清累加、第二輪自然標題與缺檔fallback。
4. 正式cmd/gin3正常60 Hz入口與真實X11，抽樣標題、拒絕右鍵／Enter、逾時重播及左鍵主選單；完整畫面／差分與區域統計保留。
5. 正式app音樂要求序列及標準 `go test ./internal/... ./cmd/... -count=1`，用GUI image＋Xvfb。

與原版標題比較為 `same-state`，限定原版350頁與remake `(0,65,640,350)`。
兩側沒有RND判定；不是整款遊戲或動畫逐秒同步聲明。其餘GUI全圖只宣稱與正式Game／renderer一致。
