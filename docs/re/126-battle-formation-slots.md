# 126 — 分隊每回合被排到哪裡：隊形槽位表

`docs/re/125` 把問題重新問成「分隊在沒有自己命令時，每回合被排到哪裡」。
這一輪解出來了，而且對收據 **9／9 完全相同**。

## 分派：分隊照自己的 `+0x1E` 動

`1C61:01D8`：

| 艦艇 `+0x1E` | 走哪一支 |
|---|---|
| 0（移動）| `1C61:03AA` ——照自己的目的地走 |
| `7F`（沒有命令）／3（歸隊）| **`1C61:029C`** |
| 1（編隊）／2（索敵）| 什麼都不做 |

`1C61:029C` 一進來就先叫 `2BE1:0059` 算「這個分隊該站哪裡」，然後：

- 已經站到位（`+0x34/+0x36 ＝ +0x28/+0x2A`）：行動是 3 就改回 `7F`
  （歸隊完成）；艦種 7 而且艦隊 `+0x3A != 0xFF` 就把索敵分遣隊收掉
  （`25DB:0535`、艦隊 `+0x3A ← 0xFF`／`+0x3B ← 0`、艦艇 `+0x1E |= 0x80` 出局）。
- 還沒站到位：用自己的行程 `+0x24`／`+0x26` 往目的地走一步。

## 隊形：`2BE1:0059`

```
槽索引 = 艦艇 +0x05
(ox, oy) = ds:59BA + 槽索引 × 4          ; 一筆兩個 word
(dx, dy) = 3A92:0001((ox,oy), 艦隊 +0x4A) ; 依艦隊朝向旋轉
艦艇 +0x28 ← clamp(艦隊 +0x5C ＋ dx, 0, 0x7FF)
艦艇 +0x2A ← clamp(艦隊 +0x5E ＋ dy, 0, 0x7FF)
```

**`ds:59BA` 是 41 個槽位的交錯格點**：

```
x =  64   y = −64 −32   0  32  64
x =  48   y = −48 −16  16  48
x =  32   y = −64 −32   0  32  64
x =  16   y = −48 −16  16  48
x =   0   y = −64 −32   0  32  64      ← 槽 20 ＝ (0,0)
x = −16   y = −48 −16  16  48
x = −32   y = −64 −32   0  32  64
x = −48   y = −48 −16  16  48
x = −64   y = −64 −32   0  32  64
```

5 × 5 ＋ 4 × 4 ＝ 41。欄距 16、同欄相距 32。**槽 20 是中心，旗艦站那裡**
——這正是 `docs/internals/38` 記的「艦隊 `+0x5C`／`+0x5E` 等於旗艦的位置」。
表倒在 [`data/battle-formation-slots.json`](../internals/data/battle-formation-slots.json)。

### 旋轉的捨去

拿收據 `s3fltmove`（艦隊在 (1330,941)、朝向 163）的九個分隊試三種捨去：

| 捨去 | 與收據不符 |
|---|---|
| 截斷（往 0）| 6／9 |
| floor（往 −∞）| 5／9 |
| **加 512 再算術右移 10 位** | **0／9** |

所以 `3A92:0001` 的算式是

```
dx = (x·cos256(a) − y·sin256(a) + 512) >> 10
dy = (x·sin256(a) + y·cos256(a) + 512) >> 10
```

與走一步那支（`2BE1:026F`，`docs/re/123`）**同一種捨去**，但夾的上限不同
（這裡 0x7FF、那裡 0x7EF／0x7E7）——再一次印證「捨去與夾法是逐呼叫端的」。

## 這也解釋了 `docs/re/125` 的觀察

那份收據裡引擎把艦隊行動從移動改成戰鬥，艦隊朝向跟著從 190 轉到 163；
**朝向一轉，41 個槽位整組跟著轉**，所以九個分隊全部拿到新目的地、
位移方向各不相同。看起來像「重排隊形」，實際上就是同一條算式。

## 還沒解

- 艦艇 `+0x05`（槽索引）是誰指派的、「編隊」怎麼改它
  （`2BE1:0328` 有動 `ds:D072 + +0x05 × 10`）。
- 行程 `+0x56`／`+0x58` 的扣法（`docs/re/125` 算不平）。
- `1C61:03AA`（分隊照自己的目的地走那一支）。
