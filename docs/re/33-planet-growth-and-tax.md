# RE 33 — 月底結算解出來了：成長與稅都是**逐行星**算的

日期：2026-09-07
執行器：dosgolem-logh3 `8c8af90`
狀態：**成長與扣稅 confirmed**（表、算式、五個實測點全對）。

`docs/re/30` 把「星域經濟力 ＝ 行星加總」與「稅從重算值裡扣掉」量出來了，
但反推到別的星域對不上（10892 vs 10813）。原因很簡單：
**成長與扣稅都是逐行星做的，捨去發生在每一顆行星上**，不是在星域的總和上。

## 先找到執行期的行星表

`docs/re/23` 找不到執行期的行星表（拿名稱當簽章在 640 KB 裡搜不到）。
改用暫存器：在累加點 `2703:0CA8` 記 `-regs-at`，看它從哪裡讀——

```
#121712628 SI=A79C ...
  [bp+] 00:B600 02:CB20 04:0000 06:0002 08:5313 0A:001C 0C:5313 ...
```

`[bp+06]` 每顆行星 ＋0x52（＝ 82，行星記錄長度），`[bp+08]` 是段 `5313`。
所以**行星表在 `5313:0000`，第一筆從 offset 2 開始**，
線性 `53132`。`[bp+0A]` 比 `[bp+06]` 多 `0x1A`——那是經濟力欄。

## 監看四顆行星，成長那一步就露出來了

星域 0（瓦爾哈拉）四顆行星的經濟力在線性 `5314C`、`5319E`、`531F0`、`53242`。
設監看跑到第一次跨月：

|---|---:|---:|---:|---:|
| 奧丁 | 52000 | 54132 | 2132 | 41.0 |
| 布倫希爾 | 9800 | 10329 | 529 | 54.0 |

四顆加起來 ＝ **85020**，正是累加迴圈最後寫進星域記錄的值。

## 扣稅也是逐行星

星域 0 的稅率是 32‰。逐行星捨去：

```
floor(54132×32/1000) = 1732
floor(10329×32/1000) =  330
floor(12624×32/1000) =  403
floor( 7935×32/1000) =  253
                       ----
                       2718
```

`85020 − 2718 ＝ 82302` ——**正是畫面上 796/1 的經濟力**。
在星域的總和上算會得到 `floor(85020×32/1000) ＝ 2720`，差 2，
`docs/re/30` 反推九個星域對不上就是這樣一顆一顆累積出來的。

扣完之後每顆行星自己也留著扣完的值（52400 / 9999 / 12221 / 7682，
合計 82302），下個月從這裡再長。

## 成長率：一張階梯表

`2703:0D47` 的反組譯（記憶體傾印 `27C00` 起 4 KB，手工解碼）：

```
mov word [bp+00],4A68     ; ds:4A68 ＝ 表頭
loop:
  les bx,[bp+00]
  mov ax,es:[bx+08]       ; 下一列的門檻（高位）
  mov bx,es:[bx+06]       ; 下一列的門檻（低位）
  les si,[bp+0E]          ; 行星記錄
  mov cx,es:[si+1C]       ; 經濟力（高位）
  mov si,es:[si+1A]       ; 經濟力（低位）
  cmp ax,cx / jnz / cmp bx,si
  jnb found                ; 下一列的門檻 >= 經濟力 → 就用這一列
  add word [bp+00],6       ; 一列 6 bytes
  jmp loop
found:
  les bx,[bp+00]
  mov ax,es:[bx+04]        ; 這一列的成長率
  les bx,[bp+0E]
  cmp word es:[bx+16],0BB8 ; 行星防衛力 vs 3000
  jnb done
  mov cx,3 / mul cx / shr ax,1   ; 防衛力 < 3000 → 成長率 ×3/2
done:
  ret ax
```

表在線性 `59598`（`ds:4A68`），一列 6 bytes ＝ 門檻（32 位元）＋ 成長率（16 位元），
32 列，倒進 [`data/growth-table.json`](../internals/data/growth-table.json)：

```
0→90‰  1000→82  2000→74  3000→68  4000→64  5000→62  6000→60  7000→58
8000→56  9000→54  10000→52  12000→51  14000→50  16000→49  18000→48
20000→47  25000→46  30000→45  35000→44  40000→43  50000→41  60000→39
70000→37  80000→35  85000→33  90000→32  95000→31  100000→30  120000→26
180000→18  200000→0  （最後一列門檻 0xFFFFFFFF、成長率 0）
```

五個實測點逐一相符：52000→41、9800→54、12000→52、7500→58、16000→50。
**經濟力越大成長越慢**，二十萬以上完全不長。

防衛力那個 ×3/2 是從程式讀出來的，還沒實測到——星域 0 四顆行星的防衛力
（9200／6300／7000／4800）都在 3000 以上。

## 加回去的那一步

`2703:0D1D` 起：

```
les bx,[bp+0E] / add bx,1A     ; 行星的經濟力欄
取 32 位元經濟力 → di:bx
call far 2703:0D47             ; ← 上面那支，回成長率
32 位元乘法（3CC9:0009）：經濟力 × 成長率
32 位元除法（3CC9:0020）：÷ 1000
add es:[si],bx / adc es:[si+02],ax   ; 經濟力 += 成長量
```

所以整個月底是：

```
對每一顆行星：
    經濟力 += 經濟力 × 成長率(經濟力, 防衛力) / 1000
    稅      = 經濟力 × 該星域稅率 / 1000        （捨去）
    經濟力 -= 稅
    總稅收 += 稅
星域經濟力 = Σ 該星域行星的經濟力
```

## 整個帝國跑一次：經濟力全對，錢差 9

拿 `PLADAT.DAT` 的原始值跑一次結算（稅率用星域記錄的 `+0x27`，
那是結算當下用的那一份），十個帝國星域結算後的經濟力與量到的 796/1
**逐一相符**；稅加起來 10732，而監看軍事費看到第一次跨月是
50000 → 60741，也就是 10741。

差 9。星域這一邊的稅被經濟力釘死了（稅 ＝ E′ − 結算後的經濟力），
所以那 9 不在星域迴圈裡——是別的收入，或累加那一支還被別處叫到
（`docs/re/29` 提過它會檢查 `[A7AE]`／`[B6F0]` 兩個旗標）。

## 順手看到的：未安定度是怎麼算的

`2703:0DA1` 那一支（下一個函式）就是 `docs/re/24` 找了很久的未安定度：

```
擁有者 == 2（無主） → 未安定度 = 100，結束
base = f(2703:0EF9) − f(2703:0FD7) − f(2703:100A) + f(2703:109D)
星域記錄 +0x13 的 bit 2 → base −= 30
base < 0 → base = 0
未安定度 = base × 統治者提督的 +0x0E / 100      （統治者：ds:8F4F[擁有者] 查
                                                 ds:B77C 的提督表，一筆 28 bytes）
未安定度 > 200 → 200
```

四支子函式還沒解，但**骨架與夾限已經確定**，而且解釋了為什麼
`docs/re/24` 在星域記錄裡怎麼找都找不到——它是算出來的，
而且要用到提督表。
