# RE 43 — 未安定度整支讀出來了：`+0x7D` ＝ 200 − 治安度

日期：2026-09-07
執行器：dosgolem-logh3 `8c8af90`
輸入：`workplace/code2703.bin`（`-dump-mem lin:27030:65280`，收據 `code2703`）
工具：`tools/scripts/disasm_funcs.py`（IDA 9.4 headless）
狀態：**從程式碼讀出來的**。頂層的結構與兩個夾限 confirmed；
六支子函式裡有四支要靠外部清單，語意還沒驗。

## 先解決工具：`GIN3PS.EXE` 是包過的

靜態反組譯 `GIN3PS.EXE` 沒有用——檔頭後面就寫著
`GLUE V1.70 -- Program Coder`，IDA 看到的是解包器。把
`docs/re/34` 手工解碼過的那幾支函式的位元組拿去 grep 原始檔，一個都找不到。

所以程式碼一律**從執行期記憶體倒**：

1. `-dump-mem lin:27030:65280` 倒出整個 `2703` 段（收據 `code2703`，
   跑到遊戲本體就夠，130,000,000 道指令）；
2. 前面補 `0x100` bytes 存成 `.COM`，IDA 就會當 16 位元載入；
   段內位移 X 落在「第一個段起點 ＋ 0x100 ＋ X」；
3. `tools/scripts/disasm_funcs.py` 從指定位址**線性逐條解**——
   不要用 `add_func`，IDA 把這段當資料，只會生出一條指令的假函式。

倒出來的內容與 `docs/re/34` 那份 4 KB 傾印重疊的部分逐位元組相同。

> IDA headless 的坑：`print` 不進 stdout，輸出檔要自己寫；而且
> **寫檔要指定 `encoding="utf-8"`**——中文寫進預設編碼會丟例外，
> 表現出來是「輸出檔存在但 0 bytes」，看不到任何錯誤訊息。

## 頂層：`2703:0DA1`

```
if R[+0x12] == 2:            # 無主
    R[+0x7D] = 100
    return

ruler = 提督表[ ds:8F4F[R[+0x12]] ]     # 統治者，提督表在 ds:B77C，一筆 28
v  = f1(R)                   # 2703:0EF9
v -= f2(R)                   # 2703:0FD7
v -= f3(R)                   # 2703:100A
v += f4(R)                   # 2703:109D
if R[+0x13] & 4: v -= 30
if v < 0: v = 0
v = v * ruler[+0x0E] / 100
if v > 200: v = 200
v += f5(R)                   # 2703:10FC
v += f6(R)                   # 2703:11EA
if v > 200: v = 200
if 2B99:028F(...) >= 0x800:
    v /= 2
else:
    v -= 2 × 2B99:0450(...)
if v < 0: v = 0
R[+0x7D] = 200 − v
```

**最後一行是關鍵。** 算出來的 `v` 不是未安定度，是**治安度**（0–200）；
存進記錄的 `+0x7D` 是它的補數。畫面上的治安 ＝ `(200 − 未安定度)/2`
（`docs/internals/22`）＝ `v/2`，兩邊接得起來。

`docs/re/34` 把中段那個 `× 統治者 +0x0E / 100` 當成整支函式的結尾，
所以拿實測值反推 base 才會怎麼湊都不對——後面還有 f5、f6 與兩段修正，
而且方向是相反的。

## 六支子函式

### f1 `2703:0EF9`：稅率、成長率與兩組難度參數

```
a = ds:8FD4[owner] ; b = ds:8FF8[owner]
di = word[ds:147E + b*4]                    # 32 位元陣列的低位字
成長率 = R[+0x1E]
v0 = 成長率 > 0 ? R[+0x27] × 100 / 成長率 : di
if v0 <= 25: v0 = di
d  = 100 + (v0 × 100 / di − 100) / 4
m  = ds:8F18 % 10
blend = ((m + 5) × ds:4B28[a] + (14 − m) × ds:4B28[b]) / 19
回 blend × 100 / d
```

`R[+0x27]` 是稅率那一格的**下一格**（稅率本身在 `+0x26`）。
`ds:4B28` 是一張以難度參數索引的 byte 表。

### f2 `2703:0FD7`：民心

```
回 (owner == 0 ? R[+0x7C] : 200 − R[+0x7C]) / 10
```

與 `docs/re/34` 讀到的一樣。796 年 1 月帝國一律 0、同盟一律 200，
所以開局這一項是 0。

### f3 `2703:100A`：鄰居（被減）

鄰居清單由 `2B99:03D9(R[+0x11], &清單, R[+0x12])` 取得，逐一：

| 鄰居 | 加多少 |
|---|---|
| 與自己同陣營 | 鄰居 `+0x13 & 0x14` 才 +7 |
| 無主 | +3，鄰居 `+0x13 & 0x14` 再 +2 |
| 敵方 | +5，鄰居 `+0x13 & 0x14` 再 +2 |

被**減**掉，所以敵對鄰居越多治安越低——這個方向講得通，
`docs/re/34` 覺得反直覺是因為當時以為算出來的是未安定度。

### f4 `2703:109D`：清單裡 `+0x12` 不為 0 的筆數 × 10（被加）

清單由 `2AF5:0036(R[+0x11], 0)` 取得，指標放在 `ds:CFF8`、
筆數放在 `ds:CFFC`，一筆 `0x52` ＝ 82 bytes ＝ 行星記錄長度；
比較的位移是 `+0x12`（行星的擁有者在 `+0x11`），差一格，
**這一格是什麼還沒驗**。收尾呼叫 `2AF5:00B6`。

### f5 `2703:10FC`：提督（被加）

清單由 `28E0:0103(R[+0x11], 0x24, 0)` 取得，是一串提督編號。
對每個與星域同陣營的提督：計數 `n`、取 `+0x0B` 的最大值 `p`、
`+0x13` 的最大值 `q`。

```
回 helper( n × p × q / 1000 )        # helper ＝ 3310:0130
```

### f6 `2703:11EA`：艦隊（被加）

清單由 `297B:131C(R[+0x11], 0)` 取得，是一串艦隊編號
（艦隊表 `ds:C074`，一筆 `0x7A` ＝ 122，`docs/re/40`）。
只算**與星域同陣營**而且 **`+0x08 == 5`** 的艦隊：
筆數不用，累加 `+0x0F` 成 `s`；再用艦隊的 **`+0x04` 當提督編號**
去提督表取 `+0x0B` 的最大值 `p`、`+0x13` 的最大值 `q`。

```
回 s × p × q / 10000
```

順帶解出三個艦隊欄位（`docs/re/40` 列為未解）：

| 位移 | 內容 |
|---|---|
| `+0x04` | 提督編號（提督表 `ds:B77C` 的索引）|
| `+0x08` | 狀態，`5` 才算進治安 |
| `+0x0F` | 一個累加進治安的量 |

## 還沒解的

- 四支清單函式（`2B99:03D9`／`2AF5:0036`／`28E0:0103`／`297B:131C`）
  回什麼、參數怎麼算。都在別的段，要各自倒出來。
- 尾巴那兩個呼叫：`2B99:028F` 回的值與 `0x800` 比，
  `3982:0329` 把 `R[+0x12]` 轉成什麼。
- 提督的 `+0x0B`、`+0x13`，行星的 `+0x12`。
- `ds:8F18`（f1 拿它 `% 10`，看起來是日期或回合）。

## 拿 32 個星域對了一次

`tools/scripts/unrest_model.py` 把上面這支寫成程式，跑 S3 那一格的 32 個
星域（`docs/internals/data/unrest-at-load.json`）。f1–f4 的輸入全部從
存檔與 `ds:` 參數取（S3：`ds:8F4F` ＝ 統治者 16／60、`ds:8FD4` ＝ 1／2、
`ds:8FF8` ＝ 2／2、`ds:147E[2]` ＝ 100、`ds:4B28` ＝ 170 150 130 90 60、
`ds:8F18` ＝ 380 ＝ 回合數）。

f6 照反組譯寫（同陣營、`+0x08 == 5` 的艦隊，`Σ+0x0F × maxP × maxQ / 10000`），
尾巴那一段當成 `v -= 2 × 離自己首都幾步`（相鄰圖跑 BFS）。

結果：

| 星域 | 算出來的治安度 | 量到的 | 差 |
|---|---:|---:|---:|
| 0 瓦爾哈拉（首都）| 187 | 187 | **0** |
| 14 費沙（1 支艦隊，f6 ＝ 7）| 188 | 188 | **0** |
| 25 干達巴爾（7 支艦隊，f6 ＝ 101，撞到 200 上限）| 190 | 190 | **0** |
| 其餘 13 個帝國星域 | | | 一律差 **2** |
| 11 個同盟星域 | | | 差 1～9，不是常數 |

**三個算得剛好**，其餘帝國星域一律差 2——那正好是「距離多算一步」的量
（`2 × 1`）。順序也對出來了：f5、f6 要在 `× 統治者能力` 與 200 夾限**之後**
才加，否則干達巴爾那 101 不會被切掉，也就對不上 190。

`f6` 對得上是強證據：費沙那支艦隊 `Σ+0x0F ＝ 8`、指揮官
（艦隊 `+0x04` ＝ 提督 9）的 `+0x0B` ＝ 98、`+0x13` ＝ 93，
`8 × 98 × 93 / 10000 ＝ 7`，而量到的差就是 7。艦隊 `+0x08 != 5` 的
（星域 23 的兩支、星域 28 的一支）算出來是 0，量到的也沒有多。

## 還差什麼

- **f5（提督那一項）沒實作**：清單由 `28E0:0103(星域, 0x24, 0)` 取得，
  篩選條件未知。不可能是「該星域所有同陣營提督」——首都有 17 個提督，
  照算式會遠超過 200 上限，而首都算出來剛好對。
- **距離的定義**：帝國那 13 個一律差 2，像是原版的步數比 BFS 多一步；
  但費沙與蘭提馬利歐兩個又剛好是 BFS。中點矩陣（`docs/internals/26`）
  遞迴展開的步數也試過，只有這兩個換位置，換一批對不上。
- 同盟那 11 個差 1～9 而且有奇數，表示還有一項會產生奇數——f5 的嫌疑最大。

## 順帶確認的欄位

- 提督 `+0x0A` ＝ **所在星域**：82 筆的取值是
  `{0:17, 13:2, 14:2, 23:4, 25:13, 27:9, 28:2, 31:33}`，
  與 S3 艦隊表記錄的所在星域（0／13／14／23／25／27／28／31）完全吻合，
  兩個首都各聚集最多人。
- 艦隊 `+0x04` ＝ 提督編號、`+0x08` ＝ 狀態（`5` 才算進治安）、
  `+0x0F` ＝ 累加進治安的量。三個都在 f6 對上之後成立。
