## 先解決工具：`GIN3PS.EXE` 是包過的

`GLUE V1.70 -- Program Coder`，IDA 看到的是解包器。把
`docs/re/34` 手工解碼過的那幾支函式的位元組拿去 grep 原始檔，一個都找不到。

所以程式碼一律**從執行期記憶體倒**：

1. `-dump-mem lin:27030:65280` 倒出整個 `2703` 段（收據 `code2703`，
   跑到遊戲本體就夠，130,000,000 道指令）；
2. 前面補 `0x100` bytes 存成 `.COM`，IDA 就會當 16 位元載入；
   段內位移 X 落在「第一個段起點 ＋ 0x100 ＋ X」；
3. `tools/scripts/disasm_funcs.py` 從指定位址**線性逐條解**——
   不要用 `add_func`，IDA 把這段當資料，只會生出一條指令的假函式。

倒出來的內容與 `docs/re/34` 那份 4 KB 傾印重疊的部分逐位元組相同。

> IDA headless 的坑：`print` 不進 stdout，輸出檔要自己寫；而且

## 頂層：`2703:0DA1`

```
if R[+0x12] == 2:            # 無主
    R[+0x7D] = 100
    return

ruler = 提督表[ ds:8F4F[R[+0x12]] ]     # 統治者，提督表在 ds:B77C，一筆 28
v  = f1(R)                   # 2703:0EF9
v -= f2(R)                   # 2703:0FD7
v -= f3(R)                   # 2703:100A
v += f4(R)                   # 2703:109D
if R[+0x13] & 4: v -= 30
if v < 0: v = 0
v = v * ruler[+0x0E] / 100
if v > 200: v = 200
v += f5(R)                   # 2703:10FC
v += f6(R)                   # 2703:11EA
if v > 200: v = 200
if 2B99:028F(...) >= 0x800:
    v /= 2
else:
    v -= 2 × 2B99:0450(...)
if v < 0: v = 0
R[+0x7D] = 200 − v
```

**最後一行是關鍵。** 算出來的 `v` 不是未安定度，是**治安度**（0–200）；
存進記錄的 `+0x7D` 是它的補數。畫面上的治安 ＝ `(200 − 未安定度)/2`
（`docs/internals/22`）＝ `v/2`，兩邊接得起來。

`docs/re/34` 把中段那個 `× 統治者 +0x0E / 100` 當成整支函式的結尾，
所以拿實測值反推 base 才會怎麼湊都不對——後面還有 f5、f6 與兩段修正，
而且方向是相反的。

## 六支子函式

### f1 `2703:0EF9`：稅率、成長率與兩組難度參數

```
a = ds:8FD4[owner] ; b = ds:8FF8[owner]
di = word[ds:147E + b*4]                    # 32 位元陣列的低位字
成長率 = R[+0x1E]
v0 = 成長率 > 0 ? R[+0x27] × 100 / 成長率 : di
if v0 <= 25: v0 = di
d  = 100 + (v0 × 100 / di − 100) / 4
m  = ds:8F18 % 10
blend = ((m + 5) × ds:4B28[a] + (14 − m) × ds:4B28[b]) / 19
回 blend × 100 / d
```

`R[+0x27]` 是稅率那一格的**下一格**（稅率本身在 `+0x26`）。
`ds:4B28` 是一張以難度參數索引的 byte 表。

### f2 `2703:0FD7`：民心

```
回 (owner == 0 ? R[+0x7C] : 200 − R[+0x7C]) / 10
```

與 `docs/re/34` 讀到的一樣。796 年 1 月帝國一律 0、同盟一律 200，
所以開局這一項是 0。

### f3 `2703:100A`：鄰居（被減）

鄰居清單由 `2B99:03D9(R[+0x11], &清單, R[+0x12])` 取得，逐一：

| 鄰居 | 加多少 |
|---|---|
| 與自己同陣營 | 鄰居 `+0x13 & 0x14` 才 +7 |
| 無主 | +3，鄰居 `+0x13 & 0x14` 再 +2 |
| 敵方 | +5，鄰居 `+0x13 & 0x14` 再 +2 |

被**減**掉，所以敵對鄰居越多治安越低——這個方向講得通，
`docs/re/34` 覺得反直覺是因為當時以為算出來的是未安定度。

### f4 `2703:109D`：清單裡 `+0x12` 不為 0 的筆數 × 10（被加）

清單由 `2AF5:0036(R[+0x11], 0)` 取得，指標放在 `ds:CFF8`、
筆數放在 `ds:CFFC`，一筆 `0x52` ＝ 82 bytes ＝ 行星記錄長度；
比較的位移是 `+0x12`（行星的擁有者在 `+0x11`），差一格，
**這一格是什麼還沒驗**。收尾呼叫 `2AF5:00B6`。

### f5 `2703:10FC`：提督（被加）

清單由 `28E0:0103(R[+0x11], 0x24, 0)` 取得，是一串提督編號。
對每個與星域同陣營的提督：計數 `n`、取 `+0x0B` 的最大值 `p`、
`+0x13` 的最大值 `q`。

```
回 helper( n × p × q / 1000 )        # helper ＝ 3310:0130
```

### f6 `2703:11EA`：艦隊（被加）

清單由 `297B:131C(R[+0x11], 0)` 取得，是一串艦隊編號
（艦隊表 `ds:C074`，一筆 `0x7A` ＝ 122，`docs/re/40`）。
只算**與星域同陣營**而且 **`+0x08 == 5`** 的艦隊：
筆數不用，累加 `+0x0F` 成 `s`；再用艦隊的 **`+0x04` 當提督編號**
去提督表取 `+0x0B` 的最大值 `p`、`+0x13` 的最大值 `q`。

```
回 s × p × q / 10000
```

順帶解出三個艦隊欄位（`docs/re/40` 列為未解）：

| 位移 | 內容 |
|---|---|
| `+0x04` | 提督編號（提督表 `ds:B77C` 的索引）|
| `+0x08` | 狀態，`5` 才算進治安 |
| `+0x0F` | 一個累加進治安的量 |

## 還沒解的

- 四支清單函式（`2B99:03D9`／`2AF5:0036`／`28E0:0103`／`297B:131C`）
  回什麼、參數怎麼算。都在別的段，要各自倒出來。
- 尾巴那兩個呼叫：`2B99:028F` 回的值與 `0x800` 比，
  `3982:0329` 把 `R[+0x12]` 轉成什麼。
- 提督的 `+0x0B`、`+0x13`，行星的 `+0x12`。
- `ds:8F18`（f1 拿它 `% 10`，看起來是日期或回合）。

## 拿 32 個星域對了一次

`tools/scripts/unrest_model.py` 把上面這支寫成程式，跑 S3 那一格的 32 個
星域（`docs/internals/data/unrest-at-load.json`）。f1–f4 的輸入全部從
存檔與 `ds:` 參數取（S3：`ds:8F4F` ＝ 統治者 16／60、`ds:8FD4` ＝ 1／2、
`ds:8FF8` ＝ 2／2、`ds:147E[2]` ＝ 100、`ds:4B28` ＝ 170 150 130 90 60、
`ds:8F18` ＝ 380 ＝ 回合數）。

f6 照反組譯寫（同陣營、`+0x08 == 5` 的艦隊，`Σ+0x0F × maxP × maxQ / 10000`），
尾巴那一段當成 `v -= 2 × 離自己首都幾步`（相鄰圖跑 BFS）。

結果：

| 星域 | 算出來的治安度 | 量到的 | 差 |
|---|---:|---:|---:|
| 0 瓦爾哈拉（首都）| 187 | 187 | **0** |
| 14 費沙（1 支艦隊，f6 ＝ 7）| 188 | 188 | **0** |
| 25 干達巴爾（7 支艦隊，f6 ＝ 101，撞到 200 上限）| 190 | 190 | **0** |
| 其餘 13 個帝國星域 | | | 一律差 **2** |
| 11 個同盟星域 | | | 差 1～9，不是常數 |

**三個算得剛好**，其餘帝國星域一律差 2——那正好是「距離多算一步」的量
（`2 × 1`）。順序也對出來了：f5、f6 要在 `× 統治者能力` 與 200 夾限**之後**
才加，否則干達巴爾那 101 不會被切掉，也就對不上 190。

`f6` 對得上是強證據：費沙那支艦隊 `Σ+0x0F ＝ 8`、指揮官
（艦隊 `+0x04` ＝ 提督 9）的 `+0x0B` ＝ 98、`+0x13` ＝ 93，
`8 × 98 × 93 / 10000 ＝ 7`，而量到的差就是 7。艦隊 `+0x08 != 5` 的
（星域 23 的兩支、星域 28 的一支）算出來是 0，量到的也沒有多。

## f5 為什麼是 0

`28E0:0103` 不是「取某星域的提督」，是一支**通用的提督篩選管線**：

1. 先把 82 筆全部收進緩衝區，跳過 `+0x00 == 0xFE` 的；
2. 第三個參數不是 `0xFF` 就先過一次**所在地**篩選（`28E0:0227`）：
   留下 `提督[+0x0A] == 該參數` 的——這正好再確認一次 `+0x0A` 是所在星域；
3. 之後照第四個參數的位元逐項再篩，每一位一支：

| 位元 | 篩選器 | 留下什麼 |
|---|---|---|
| 0x01 | `28E0:028E` | 與 `ds:8F1D` 有關（未讀）|
| 0x02 | `28E0:02F5` | 與 `ds:8F1D` 有關（未讀）|
| **0x04** | `28E0:035C` | `提督[+0x00] == 0xFF` |
| 0x08 | `28E0:03B6` | 未讀 |
| 0x10 | `28E0:0410` | 未讀 |
| **0x20** | `28E0:047E` | `提督[+0x09] & 0x80` |
| 0x40 | `28E0:04E3` | 未讀 |

f5 傳的是 `0x24` ＝ `0x04 ＋ 0x20`，所以它要的是
**「在這個星域、`+0x00 == 0xFF`、而且 `+0x09` 的最高位有設」的提督**。

而 `+0x09` **在載入時會被夾到 127**（`docs/internals/08`：`ADMIRAL.DTX`
與載入後的記憶體只差 6 個 byte，全部是 `> 127 → 127`）——夾成 `0x7F`
就把最高位清掉了。所以載入之後沒有任何提督通過這個篩選，
**f5 恆等於 0**。

這與量到的資料一致：首都瓦爾哈拉聚了 17 個提督，如果 f5 是
「該星域同陣營提督數 × 能力 × 能力 / 1000」，光首都就會遠超過 200 上限，
而首都恰恰是算得最準的一個。

（證據等級：`+0x09` 的夾限在新遊戲那條路徑上量到過；存檔那條路徑上
還沒直接倒過載入後的提督表——倒 S3 狀態那次差 16 bytes 就碰到
`ds:B77C`。所以這條是**強推論**，不是實測。）

## 還差什麼
- **距離的定義**。尾巴那兩支讀出來了：

  - `3982:0329(擁有者)` 回**首都星域**：帝國 0、同盟 31（`0x1F`）。
  - `2B99:0450(星域, 首都, 陣營)` 是一個計步迴圈：
    `while 首都 != 星域: 首都 = 2B99:0302(星域, 首都, 陣營); n++`。
    `2B99:0302` 挑該陣營的中點矩陣（`ds:D06A`／`ds:D06E`）再查
    `2B99:0349`，而查表回的是 `T[首都][星域]`，**`0xFF` 就回星域本身**。
  - `2B99:028F(首都, 星域, 陣營)` 讀的是**另一張表**：`ds:D062` 起的
    far 指標，索引 `[首都 × 32 + 星域]`，一格 **2 bytes**——32 × 32 的
    word 矩陣，與 `docs/internals/26` 那兩張 byte 中點矩陣不是同一張。
    回值與 `0x800` 比，大於等於就把治安度砍半。

  `ds:D062` 那張表也倒出來了。EMS 分頁框 `E0000` 起放著四張表，
  倒 8 KB 之後拿 `E1000`／`E1400` 與已知的兩張中點矩陣逐位元組比對
  **完全相同**，所以分頁框的內容是對的：

  | 位址 | 內容 |
  |---|---|
  | `E0000` | 帝國的 32 × 32 **word** 矩陣（`ds:D062`）|
  | `E0800` | 同盟的同一張（`ds:D066`）|
  | `E1000` | 帝國中點矩陣，32 × 32 byte（`ds:D06A`）|
  | `E1400` | 同盟中點矩陣（`ds:D06E`）|

  word 矩陣的值長這樣（第 0 列，首都 → 各星域）：
  `0, 16, 15, 1051, 14, 33, 30, 31, 46, 51, 1067, 1091, 2107, 60, 1070, 1102, …`
  ——高位元組永遠是 4 的倍數，低位元組像是某種成本。

  **但這張表對不上**：星域 12、22、23、25、28 的值都 ≥ `0x800`，
  照程式應該走「治安度砍半」那條，算出來會是 93 左右，量到的是 177。
  中點矩陣走一次也只有 1–2 步（`0 → 25 → 28`），配不出量到要的 0–7。

  最像的解釋是**這兩張表在載入的當下還沒填**：它們是路徑計算時才算出來的
  （`docs/re/28`），而未安定度是在載入那一步算的。表全零的話
  `2B99:028F` 回 0（< `0x800`，走減法那條），`2B99:0349` 查到 0
  就不是 `0xFF`……這條要驗，得在載入的當下倒一次那 8 KB。
  **下一步就是這個。**

  假設「載入時表是空的、每個非首都星域都只減 2」也不成立：代進去之後
  殘差又隨距離散開（−2、−4、−6、−8、−12）。

  **直接量出來了**：對 `2703:0ED6`（`2B99:0450` 回來的下一條）設
  `-regs-at`，載入 796 年 1 月那一輪的前 20 次回值是

  ```
  0 1 1 1 2 2 2 3 3 4 5 4 3 2 1 1 3 4 3 2
  ```

  ——0 到 5，正好是量到的差需要的量級（0–7），而且 `ES=E000`，
  表在算的當下是映著的。所以尾巴確實是 `v -= 2 × 步數`，步數是真的路徑步數。

  剩下的問題只有一個：**S3 載入的當下那張中點矩陣長什麼樣**。
  `-regs-at` 只印前 20 次，而那 20 次全被開機時 796/1 的那一輪用掉了；
  載入存檔是第二輪，印不到。要嘛讓 probe 支援「跳過前 N 次」，
  要嘛在載入的**那一瞬間**倒 EMS（本輪倒的時間點是 260,000,000 步，
  已經晚了，那時分頁框換成別的頁了）。
- 同盟那 11 個差 1～9 而且有奇數，表示還有一項會產生奇數——f5 的嫌疑最大。

## 順帶確認的欄位

- 提督 `+0x0A` ＝ **所在星域**：82 筆的取值是
  `{0:17, 13:2, 14:2, 23:4, 25:13, 27:9, 28:2, 31:33}`，
  與 S3 艦隊表記錄的所在星域（0／13／14／23／25／27／28／31）完全吻合，
  兩個首都各聚集最多人。
- 艦隊 `+0x04` ＝ 提督編號、`+0x08` ＝ 狀態（`5` 才算進治安）、
  `+0x0F` ＝ 累加進治安的量。三個都在 f6 對上之後成立。
