## 結論

1. **`297B:0332` 不是函式。** 它是 `297B:025D` 裡面 `call far 090A:0E6D` 那道指令的位址，
   同時也是 `025D` 開頭「槽沒在用」那個分支跳進去的地方。前一個位元組是
   `dec byte es:[bx]`，不是 epilogue。`docs/re/310` 跟 `docs/re/299` 的表列的是
   「`090A:0E6D` 的呼叫點」，所以 `297B:0332` 跟 `297B:03D2` 其實是**兩支解散常式裡
   呼叫重算的位址**，被誤標成函式入口。`03D2` 屬於 `297B:034A`。**proven**（位元組）
2. 解散常式其實只有兩支：`297B:025D(艦隊編號)`＝「**解散，艦艇還回星域**」，
   `297B:034A(艦隊遠指標)`＝「**全滅，艦艇不還**、提督記成失蹤、釋放戰場圖示」。
   整個常駐程式碼裡讓 `ds:8F49[陣營]`（艦隊數）減 1 的只有這兩處。**proven**
3. 呼叫者：`025D` ← `07F9:01EE`（出擊那條路，艦隊組成按中止）、`113A:06A6`
   （駐留命令走到目的地）。`034A` ← `0374:0888`（戰略階段全滅，包在
   `0374:073F`「…第N艦隊 …已經全滅。」裡）、`185C:016A`（戰場一回合結算完全滅）。**proven**
4. **玩家介面沒有「艦隊解散」這顆鈕。** 資料段有一張兩項選單 `ds:0D4E` ＝
   {「變更副官」`ds:0D3C`，「艦隊解散」`ds:0D45`}，但 58 份 1 MB 傾印的程式區裡
   **連 `4E 0D` 這兩個位元組都找不到**（`3C 0D`、`45 0D`、`50 0D` 當立即值載入也是 0 筆）。
   艦隊視窗「變更」真正用的是 `ds:2232` ＝ {副官，編組}。這張表是沒接上的殘留。**strong inference**
5. 玩家實際能解散艦隊的路是**作戰 → 駐留**：選目的地、按決定、實行，艦隊走到目的地那一刻就整支解散。
   目的地選**自己現在所在的星域**，下一次實行就地解散。確認框不會提到「解散」：
   「要駐留在帝國軍亞爾提那星系嗎？」（選自己所在星域時印「要待命於帝國軍瓦爾哈拉星系嗎？」，
   但寫進記錄的還是駐留）。回合報告印「已經駐留在星系上。」。**proven**（探索批次，見 §五）

## 一、`297B:025D(n)`：解散（艦艇還回星域）

線性 `0x29A0D`。前一支 `297B:0209`（等級→編制槽數）在 `+025C` 是 `retf`，入口正確。

```
f = ds:C074 + n × 122                         ; +0264..+027B
if f[+0x04] == 0xFF: goto L0332               ; +027D  槽沒在用：只做尾巴兩件事
28E0:054A(f[+0x04])                           ; +028B  提督 +0x09 |= 0x80（沒帶艦隊）
if f[+0x05] != 0xFF: 28E0:054A(f[+0x05])      ; +029E  副官同上
f[+0x04] = 0xFF; f[+0x05] = 0xFF              ; +02AA
r = ds:A79C + f[+0x06] × 126                  ; +02C0  艦隊所在星域
for i in 0 .. f[+0x0F]-1:                     ; +02D8
    2AD2:018C(r, word f[+0x10 + 4i])          ; +02F6  還一組
2AD2:018C(r, word f[+0x38])                   ; +0313  索敵分遣隊那一筆（不看 +0x3A）
r[+0x28 + f[+0x01]] -= 1                      ; +031A  星域的該陣營艦隊數
L0332:
090A:0E6D()                                   ; +0332  整份重算（經濟力、未安定度…）
ds:8F49[f[+0x01]] -= 1                        ; +0337  該陣營艦隊總數
retf                                          ; +0349
```

子函式：

- `28E0:054A(提督)`（`fcx-dissolve-28E0.txt`）：`提督[+0x09]` bit7 沒設就設起來（`or 80h`），
  其他都不動。**不寫 `+0x0A`**。**proven**
- `2AD2:018C(星域遠指標, 艦艇索引)`（`docs/re/228`，這次重讀位元組）：
  `艦艇 = [ds:CFB4] + 索引 × 78`；`艦艇[+0x04] != 7` → `2703:155B(星域, 艦艇)`；
  `艦艇[+0x38..+0x3B]` 遠指標不為 0 → `35D1:0102` 釋放；`艦艇[+0x01] = 0xFF`。**proven**
- `2703:155B(星域, 艦艇)`（`workplace/ida/d2703-own.txt`）：
  `星域[+0x30 + 艦艇[+0x00] × 28 + 艦艇[+0x04] × 4]`（dword）`+= 艦艇[+0x08]`（word）
  ＝ 陣營 × 7 種 × 4 bytes 的存量表，加上這一筆的艘數。remake 的 `rules.ReturnRegionShips`。**proven**
- `090A:0E6D()`：`docs/internals/22`／`29` 已記的整份重算。

## 二、`297B:034A(f 遠指標)`：全滅（艦艇不還）

線性 `0x29AFA`，前一個位元組 `+0349` 是 `025D` 的 `retf`。

```
if f[+0x6C..+0x6F] != 0: 35D1:0102(它)        ; +0365  戰場圖示物件（docs/internals/33）
if f[+0x04] == 0xFF: goto L03D2
28E0:057F(f[+0x04], 0)                        ; +037D
if f[+0x05] != 0xFF: 28E0:057F(f[+0x05], 0)   ; +0393
f[+0x04] = f[+0x05] = 0xFF                    ; +039F
星域[f[+0x06]][+0x28 + f[+0x01]] -= 1         ; +03CF
L03D2:
090A:0E6D()                                   ; +03D2
ds:8F49[f[+0x01]] -= 1                        ; +03E0
```

**不叫 `2AD2:018C`**。艦艇記錄由呼叫者先逐筆作廢，而且不還存量：

- `28E0:057F(提督, 旗標)`：`+0x09 |= 0x80`；`+0x00 ←` 旗標 0 時 `0x80`（失蹤）、非 0 時 `0`；
  `+0x02..+0x05 ← 0`。這裡傳 0 ＝ 失蹤，之後交給 `docs/re/307` 的命運判定。**proven**（位元組）
- `2AD2:01EF(艦艇遠指標)`：釋放 `+0x38` 遠指標並清 0、`+0x01 ← 0xFF`。**沒有** `2703:155B`。**proven**

| 呼叫點 | 所在函式 | 前置 |
|---|---|---|
| `0374:0888`（線性 `0x03FC8`）| `0374:073F(f)`：印 `ds:01CD`「%s第」＋編號＋`ds:01D3`「艦隊\n%s%s\n」＋`ds:01DE`「已經全滅。」（`3826:0307`），每組與 `+0x38` 走 `2AD2:01EF` | `0374:0608(星域)` 逐支：槽在用、在這一格、陣營 ≠ 星域 `+0x12`、`f[+0x00]` bit0；先 `0374:06BC(f)`，然後第 0 組艦艇 `+0x08 == 0` 就走 `073F`，否則走 `0374:0896`。`0374:0608` 的呼叫者沒查 |
| `185C:016A`（線性 `0x1872A`）| `185C:00F0(f)`：每組與 `+0x38` 走 `185C:01ED`（`1727:0298` 擦小地圖點 ＋ `2AD2:01EF`）| `185C:001D` 逐一掃戰場艦隊表 `ds:9898`（`ds:9894` 支）：`185C:00B2(f)`（第 0 組艦艇 `+0x08 == 0`）成立就叫 `185C:028E(f)` 再叫 `185C:00F0(f)`。`185C:0001` 被 `181B:040B` 呼叫 |

段值：`0x1872A` 的函式入口 `0x186B0` 被 `181B:0481` 用 `call far 185C:00F0` 叫到，所以段是
`185C`，不是 `181B`（`181B` 的切片從 `+0x0410` 起就是 `185C:0000`）。`0x03FC8` 的函式
`0374:073F` 被 `0374:0696` 用 `call far 0374:073F` 叫到。

## 四、「艦隊解散」字串與玩家入口

- `ds:0D45`（線性 `0x55875`）「艦隊解散」、`ds:0D3C`「變更副官」，兩項選單表 `ds:0D4E`：
  `01 00 3C 0D B3 54 | 01 00 45 0D B3 54`（啟用旗標 word ＋ 遠指標，與 `ds:0CE2` 一覽表、
  `ds:0D1E` 系統指令、`ds:2232` 變更 這幾張表的格式相同）。
- 引用：`imm_scan_all.py D4E D50 D56 D3C D45` 在全部 1 MB 傾印裡 0 筆（同一次掃描 `0CE2`、`0D1E`
  各命中一處（線性 `0x072D2`、`0x0735D`），當作正對照）；`scan_word.py` 在 58 份傾印的程式區（線性 `< 0x54B30`）
  搜任意位置的 `4E 0D`：56 份 0 筆，`intromem.bin`、`openmem.bin` 各 1 筆（`0x19DA4`，開場動畫階段，
  前後位元組 `a9 3c 94 | 4e 0d | 91 bf`，不是這張表的載入）。
- 真正的「變更」小選單是 `ds:2232` ＝ {`ds:2228`「副官」，`ds:222D`「編組」}（`docs/re/316`）。
- 結論：DOS 版常駐程式碼沒有任何地方用到「變更副官／艦隊解散」這張表，**玩家介面沒有明確的解散指令**。
  **strong inference**（理由：零引用、掃描器是逐位元組搜尋，不受定址模式限制、有正對照。
  殘留風險是某段只在特定畫面才載入、58 份傾印都沒涵蓋的程式碼）。
- 玩家實際能用的解散途徑：
  1. **作戰 → 駐留 → 目的地 → 決定 → 實行**，走到目的地時解散（`113A:06A6`）。確認框是一般的目的地確認：
     `ds:2DF6`「要%s…%s星系嗎？」＋動詞 `ds:22B4`「駐留在」，按鈕「中止／決定」。
     框裡**沒有**提到解散。回合報告：「帝國軍 第１艦隊／萊因哈特上將／瓦爾哈拉 出發前往 亞爾提那／已經駐留在星系上。」
  2. 駐留目的地點**自己所在的星域**：確認框印的是「要待命於…星系嗎？」（跟移動點自己那張同文字），
     但按決定之後記錄是 `+0x07 = 現在位置`、`+0x08 = 2`（駐留），下一次實行就地解散（報告「瓦爾哈拉 出發前往 瓦爾哈拉／已經駐留在星系上。」）。
  3. 出擊（提督分頁的「出擊」或戰略命令的出擊）走到艦隊組成時按「中止」（`07F9:01EE`）：
     剛建的那一支立刻拆掉（既有收據 `fcmd-fok-cancel`）。
