# RE 37 — 一覽表的五張清單在 796 年 1 月都是空的

日期：2026-09-07
執行器：dosgolem-logh3 `8c8af90`
收據：`lst1e`／`lst2e`／`lst3e`／`sortie1e`／`star1e`／`fltlst`（`-poke`）
狀態：「空的」是**原版行為 confirmed**；什麼時候會填 **未解**。

## 五張都是空的，不是三張

規格 JSON 掃過一遍，清單區（y 80–340）的文字行數：

| 畫面 | 收據 | 清單區文字行 |
|---|---|---:|
| 一覽表 → 艦隊資料 | `lst1e` | 0 |
| 一覽表 → 提督資料 | `lst2e` | 0 |
| 一覽表 → 敵將資料 | `lst3e` | 0 |
| 一覽表 → 星系資料 | `star1e` | 0 |
| 出擊命令 → 待命中提督資料 | `sortie1e` | 0 |

remake 這五張都是逐位元組對拍過的，所以**空的就是原版當下的樣子**
——不是 remake 少畫了東西。連星系資料那張也是空的，那張的地圖還會
換色、選中的星域畫成色 7（`docs/internals/13`），但清單本身沒有內容。

## 星域記錄的艦隊數不是清單的來源

星域記錄的 `+0x28`–`+0x2B` 是畫面左下角「艦隊 a：b」那兩個數字
（`docs/re/31` 用 `-poke` 定下來的）。清單是不是也讀它？

收據 `fltlst`：與 `lst1e` 同一組操作，只在第 170,000,000 步多注入
`lin:5F2F4 = 03 02 01 04`（星域 0 的那四個 byte），然後照樣開
一覽表 → 艦隊資料。

**畫面與 `lst1e` 差 0 個像素。**

所以那四個 byte 只是面板上的計數器，清單的資料在別的地方
——執行期一定另有一份艦隊表。

## 這代表什麼

「三張空的一覽表」原本記成 remake 的缺口，其實不是：原版在這個局面下
就是空的。真正未解的是**什麼東西會讓它們有內容**。開局沒有艦隊可以解釋
艦隊資料那張；提督、敵將、星系三張為什麼也空著還沒有答案。

下一步的方向是找那份艦隊表（而不是繼續戳星域記錄）：
`ADMIRAL.DT*` 載在 `ds:B77C`（一筆 28 bytes，`docs/re/33`），
艦隊表應該也在同一段附近；在清單畫面的繪製常式上設 `-regs-at`
就能看到它從哪裡讀。
