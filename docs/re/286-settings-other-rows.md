# 286 — 設定畫面剩下那幾行的值存在哪

日期：2026-09-11
資料來源：既有的 1 MB 執行期傾印 46 份（DGROUP 基底 `0x54B30`，
分派整段在**每一份**的同一個線性位址上）；出貨存檔
`org_game/extracted/WORK.DT8`／`DT9`／`DTA`；新遊戲底稿
`docs/internals/data/work-796-01.json`。**本輪沒有跑執行器**。
狀態：**confirmed**（`BUG!` 那張畫面的用途另標）

結論一句話：**三個值都在 `WORK` 裡，而且是連在音樂那三格後面的**——
`ds:8F36` 動畫效果、`ds:8F37` 動畫速度、`ds:8F38`（16 位元）訊息速度，
存檔位移 `+0x22`／`+0x23`／`+0x24`。四條互相獨立的路指向同一組數字。

## 一、分派整段在 `0x04681`

`docs/re/274` §5 只解了前三段（動作碼 0–11）。同一支常式一路比下去，
`042F:0391` ＝ 線性 `0x04681`，結尾在 `0x04816`：

```
  les  bx,[bp+02]                     ; 命中測試回來的熱區記錄
  mov  al,es:[bx+05]                  ; 動作碼
  … 0–2 → [8F33]、3–8 → [8F34]、9–11 → [8F35]（`docs/re/274` §5）…
  cmp  byte es:[bx+05],0C  jne +12    ; 12 訊息速度 ＋
    push 1  push [bp+04]  push bx  call far 042F:0655
  cmp  byte es:[bx+05],0D  jne +11    ; 13 訊息速度 −
    push 0  push [bp+04]  push bx  call far 042F:0655
  cmp  byte es:[bx+05],0E  jne +0D    ; 14 動畫效果 開啟
    mov  byte [8F36],1     call far 042F:0794
  cmp  byte es:[bx+05],0F  jne +0C    ; 15 動畫效果 關閉
    mov  byte [8F36],0     call far 042F:0794
  cmp  byte es:[bx+05],10  jne +0C    ; 16 動畫速度 普通
    mov  byte [8F37],0     call far 042F:07E8
  cmp  byte es:[bx+05],11  jne +0C    ; 17 快速
    mov  byte [8F37],1     call far 042F:07E8
  cmp  byte es:[bx+05],12  jne +0C    ; 18 最快
    mov  byte [8F37],2     call far 042F:07E8
  cmp  byte es:[bx+05],13  jne +07    ; 19 結束
    mov  word [bp+00],1                 ; ← 回傳值
  cmp  byte es:[bx+05],14  jne +07    ; 20 BUG!
    call far 3A9C:0000                  ; 另一張畫面（第六節）
  cmp  byte es:[bx+05],16  jne +05    ; 22 ＭＩＤＩ Ｉ／Ｆ
    call far 042F:08F8                  ; 寫回 MUSIC.INI（`docs/re/274` §10）
  mov  ax,[bp+00]  …  retf
```

**位元組簽章**（動作碼 14 那一段起，一路蓋到 19）：

```
C4 5E 02 26 80 7F 05 0E 75 0D C6 06 36 8F 01
```

三段 `A2`／`C6 06` 的寫入點：`0x04777`／`0x0478E`（`8F36`）、
`0x047A4`／`0x047BA`／`0x047D0`（`8F37`）。

## 二、訊息速度是 16 位元，加減各一支

動作碼 12／13 共用一支「按住不放就一直重複」的外皮（`042F:0655` ＝
`0x04945`），它按方向引數呼叫下面兩支之一：

```
042F:0705（0x049F5）  加          042F:0726（0x04A16）  減
  cmp  word [8F38],12C              mov  ax,0A
  jae  → 不動                       cmp  [8F38],ax
  add  word [8F38],0A               jb   → 不動
  重畫那個數字                       sub  [8F38],ax
  retf                              重畫那個數字
                                    retf
```

所以：**步進 10、上限 300**；減的那一支判的是「不到 10 就不動」，
從 10 減下去會變成 0 才停——**按到底是 0，不是 10**。

重畫（`042F:0747` ＝ `0x04A37`）把游標移到視窗的第 11 欄、第 12 列
（格式字串 `ds:0555` ＝ `"\x01[%d,%d,"`），再用 `ds:055E` ＝ `" %3d"`
印出來。四個半形靠右，右邊界因此固定在視窗第 13 欄的左緣 ＝ 畫面
x ＝ 384；收據 `settings1e` 量到的那兩格數字在 x ＝ 368／376，正好是
`"  90"` 的後兩個字元。

另外兩支重畫常式（`042F:0794`、`042F:07E8`）只做一件事：把那一組裡
選中的那一格底色換成 `0x27`、其餘 `0x87`——高四位是底色（2／8）、
低四位是字色（7）。這與收據上量到的 `fill: 2`／`fill: 8` 逐一相同。

## 三、「結束」與右鍵是同一條出口

設定畫面的訊息迴圈在 `0x0463A`：

```
  mov  si,0
loop:
  call far 3765:0036            ; 等一次輸入 → [bp+00]
  cmp  ax,1  jz  左鍵
  cmp  ax,2  jz  右鍵
  jmp  檢查
左鍵: push [bp+08]  push [bp+06]  call far 042F:0391   ; 熱區分派
      mov  si,ax                                       ; ← 回傳值
      jmp  檢查
右鍵: mov  si,1
檢查: or   si,si   jz → loop
      add  sp,0C   pop si  pop bp  retf
```

「結束」（動作碼 19）做的事只有 `mov word [bp+00],1`，也就是讓分派
回傳 1 → `si = 1` → 迴圈結束。右鍵（輸入結果 2）也是把 `si` 設成 1。
**兩條路收在同一個 `retf` 上**，所以「結束」與右鍵離開之後一定落在
同一張畫面。

這不等於「回哪一張」有答案了——回哪一張由呼叫端決定，那一段還沒查。
但它把 remake 目前用右鍵關的作法變成有證據的：兩者本來就該一樣。

## 四、三個值都進存檔

`WORK.DT?` 就是 `ds:8F14` 起的 230 bytes（`docs/re/45`），所以

| 存檔位移 | `ds:` | 寬 | 內容 |
|---|---|---:|---|
| `+0x22` | `8F36` | 1 | 動畫效果：1 開啟、0 關閉 |
| `+0x23` | `8F37` | 1 | 動畫速度：0 普通、1 快速、2 最快 |
| `+0x24` | `8F38` | 2 | 訊息速度 |

**四條獨立的路給出同一組數字**：

| 來源 | `+0x22` | `+0x23` | `+0x24` |
|---|---|---|---|
| 開機預設（`0x03A28`／`0x03A2C`／`0x039E1`）| 1 | 0 | 90 |
| 46 份執行期傾印的 `ds:8F36`–`8F39` | 1 | 0 | 90 |
| 出貨存檔 `WORK.DT8`／`DT9`／`DTA` | 1 | 0 | 90 |
| 新遊戲底稿 `work-796-01.json` | 1 | 0 | 90 |

出貨的三格存檔連原始位元組都一樣：`+0x22..+0x25` ＝ `01 00 5A 00`。

> ⚠ 與音樂那三格的差別：`ds:8F33`（音源）在新遊戲底稿裡是 0，因為那份
> 量在音源偵測之前（`docs/re/285` 第三節）。這三格不靠偵測，開機那一段
> 直接寫死，所以底稿裡就已經是最終值。

初始化那一段（`0x039C0` 起）順手也把音樂那兩格清成 0，與
`docs/re/274` §4 記的另一個寫入點是同一回事的兩個地方：

```
  mov  [8F1C],al            ; al ＝ 0
  mov  word [8F38],005A     ; ← 訊息速度 90
  …
  mov  cl,1
  mov  [8FF4],cl  mov [8FF5],cl
  mov  [8F36],cl            ; ← 動畫效果 1
  mov  [8F37],al            ; ← 動畫速度 0
```

## 五、三個值在原版各自控制什麼

三個都不是純裝飾，讀的一端都找得到（`global_xref.py` 掃 disp16：`8F36`
與 `8F37` 除了設定畫面自己的重畫之外，各只有一處讀取點）：

**`ds:8F36`（動畫效果）→ `0x395CF`。** 某支常式進門第一件事就是
`cmp byte [8F36],0; jnz 繼續`，是 0 就直接 `retf` 什麼都不做。

**`ds:8F37`（動畫速度）→ `0x34B31`**，在一段關中斷的臨界區裡：

```
  push ds  mov ax,54B3  mov ds,ax
  cmp  word [8EFE],0   jnz -7        ; 忙等上一次的倒數歸零
  mov  bx,8F10
  mov  al,[8F37]  xlat                ; ds:[8F10 + 動畫速度]
  xor  ah,ah
  mov  [8EFE],ax                      ; 這一格要等幾個 tick
```

`ds:8F10` 那張表是 `08 04 00` ＝ **普通 8 tick、快速 4、最快 0**。
它在 `ds:8F14` 的**前面**，所以是靜態的、不進存檔。

**`ds:8F38`（訊息速度）→ 送進 `3765:006C`（`0x376BC`）**。全份傾印裡
`push [8F38]` 共 15 處，其中 **14 處下一道指令就是 `call far 3765:006C`**；
唯一的例外是 `0x04A61`，那是設定畫面自己印那個數字。

```
wait(n):
  關中斷  mov [8EFE],n  開中斷
loop:
  問一次輸入（非阻塞）
  cmp word [8EFE],0  jz  出去          ; 倒數歸零
  cmp [bp+00],1      jz  出去          ; 左鍵
  cmp [bp+00],2      jnz loop          ; 右鍵
出去:
  關中斷  mov word [8EFE],0  開中斷  mov ax,1  retf
```

`ds:8EFE` 是計時器中斷在遞減的倒數器，動畫速度用的是同一格。所以
**訊息速度是「訊息停留幾個 tick」，數字大 ＝ 停得久**；等待途中按左鍵
或右鍵可以提早結束。

還有一處把它暫時加倍再還原（`0x0651A` 與 `0x18F52` 兩支形狀相同，
只差最後呼叫哪一支印字常式）：

```
  mov  ax,[8F38]  mov [bp+0100],ax
  shl  word [8F38],1          ; 這一則停兩倍久
  …印字…
  mov  ax,[bp+0100]  mov [8F38],ax
```

## 六、`BUG!` 開的是一張隱藏的除錯選單

2026-10-05勘誤：[研究432](432-settings-interface.md)以正常出貨入口及IDA原始bytes推翻本節可達性斷言。DS:04CC來自DS:0210，正常兩者為0，BUG!不可選。以下callee與七項寫端的歷史證據保持，不能當正常玩家入口。

動作碼 20 呼叫 `3A9C:0000`（`0x3A9C0`）。那支開一個視窗、掛上清單
`ds:902C`，跑自己的訊息迴圈；命中之後用跳躍表 `ds:908C` 分派：

| 動作碼 | 標籤 | 目標（`3A9C:`）| 做什麼 |
|---:|---|---|---|
| 0 | `自動１` | `00E3` | `mov byte [8F23],1` |
| 1 | `手動１` | `00EA` | `mov byte [8F23],0` |
| 2 | `自動２` | `00F1` | `mov byte [8F24],1` |
| 3 | `手動２` | `00F8` | `mov byte [8F24],0` |
| 4 | `顯示` | `00FF` | `or byte [8F1C],1`，接著重畫 |
| 5 | `不顯示` | `0119` | `and byte [8F1C],0FE`，接著重畫 |
| 6 | `結  束` | `0133` | `mov word [bp+00],1` ＝ 回傳 1 離開 |

七個標籤與七個跳躍目標逐一對上，沒有第八筆。

`ds:8F23[座位]` 就是 `docs/internals/54` 那一格「這個座位是不是電腦」
（0 玩家、1 電腦），`8F24` 是座位 1 的同一格。所以這張畫面是
**開發期用來把任一方切成電腦或人**的；`8F1C` 的 bit0 是另一個顯示開關
（用途未解）。三格都在 `WORK` 裡（`+0x0F`／`+0x10`／`+0x08`）。

這同時解掉一件舊事：`docs/internals/23` 把 `902C` 標成「屬於哪一張畫面
未知」——它屬於這裡。`BUG!` 熱區在 (400,60)，可選旗標是 1，但畫面上
既沒有框也沒有字（`docs/re/285` §二），所以只有知道位置的人點得到。

## 七、remake 接了什麼

`internal/game.settingsClick` 現在收 12–19：訊息速度上下箭頭、動畫效果
開關、動畫速度三選一、「結束」（走與右鍵同一條路）。值放在
`game.DisplaySettings`，跟著 `WORK` 的 `+0x22`–`+0x25` 存取
（`internal/rules.WorkFields`）。畫面上那個數字改走
`screen.GameWindow.SetFieldText`，靠右對齊到規格新增的 `msg_speed`
欄位——那個欄位由 `settings_hotspots.py` 從收據量到的那一行反推，
並用「右邊界 ＝ 上箭頭往左一格」自檢。

**沒接的兩筆**：`midi-if`（22）要先有 `MUSIC.INI` 的讀寫，
`bug`（20）要先有那張除錯畫面。

三個值目前沒有人讀：交戰演出、動畫節奏與訊息停留 remake 都還沒做。
接的時候三個語意在第五節。
