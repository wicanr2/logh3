# 122 — 抵達朝向怎麼選，以及艦隊每回合怎麼走

`docs/re/121` 收尾指出艦隊的「移動」是兩段互動。這一輪把第二段與
「實行」那一步的骨架讀出來。

## 第二段：抵達朝向 ＝ 目的地指向游標的方位

追蹤常式 `2583:03A9`，選點迴圈每一輪叫一次：

```
si, di = 目的地 (x, y)
若 游標 == 目的地：al ← 傳進來的預設朝向
否則             ：al ← 2BE1:011D(游標x − 目的地x, 游標y − 目的地y)
if al != ds:A77F:                  ; 朝向變了
    3870:01FC(ds:A77E, 2, al)      ; 更新畫面上那個圖形
    ds:A77F = al
回 al
```

`2BE1:011D` 是 atan2，回**一整圈 256** 的方位（與正弦表同一個定義，
`docs/internals/41`）。所以操作是：點完目的地之後，**游標繞著目的地
轉，指標跟著轉**，左鍵確定、右鍵取消（外層 `2583:02D9` 收到 1 就結束、
2 就回 `0FFFF`）。

`ds:A77E` 是那個圖形的代號、`ds:A77F` 是現在顯示的朝向。圖形的描述是

```
[+0]／[+2] = 目的地（各 ＋7）    [+4] = 朝向
[+5] = 4   [+6] = 4   [+7] = 1
[+8] = 0x40（64 ＝ 1/4 圈）      [+0A] = [+0C] = 0x20（32 ＝ 45°）
```

### 畫面上是一個會轉的十字（收據 `s3cmdface`）

收據 `s3cmdface`（點旗艦 → 點「移動」 → 點目的地畫面 (200,300)，
之後停在選朝向的狀態）量到：目的地上出現一個**四臂的開口十字**，
中心在 **(207,307)**——正好是點到的座標各 ＋7，與上面描述結構
`[+0]／[+2] = 選到的點（各 ＋7）` 一致。

四臂的位置（色 7）：

```
上  x ≈ 206，y 275–291
下  x ≈ 208，y 316–329
左  y ≈ 308，x 184–198
右  y ≈ 306，x 216–230
```

左右兩臂的 y 差 2 個像素、上下兩臂的 x 差 2 個像素——**整個十字是照
朝向轉過的**（那支艦隊的 `+0x4A` 是 190，游標停在目的地上所以用預設值）。
臂與中心之間有缺口（約 10 像素），臂長約 15 像素；`[+8] = 0x40`
（四臂相隔 90°）對得起來。逐像素的臂長與缺口還沒量到定案。

兩個範圍圖形在選朝向的時候**還留在畫面上**。

## 「實行」那一步：`1C03:01B5`

```
艦隊 +0x49 &= 0xFE
若 +0x5C／+0x5E ＝＝ +0x64／+0x66（已經到了）：
    +0x4A != +0x4C → 1C03:0524(艦隊, …, +0x4C)   ; 轉到抵達朝向
    回
方位 = 2BE1:011D(目標 − 現在)
若 方位 != +0x4A：
    1C03:0524(艦隊, …, 方位)                      ; 轉一步；回 1 ＝ 還在轉
    回 1 就把 +0x49 的 bit0 設起來
若 (32 位元) +0x58:+0x56 < 8：這一輪不前進
否則：
    距離 = 3310:0006(現在, 目標)
    距離 ≤ 8 → 直接把位置設成目標
    否則      → 按速度前進一段
```

所以艦隊的移動是「先轉向、再前進」，每回合各做一步；`+0x56`／`+0x58`
是一個 32 位元的行動額度，8 是一步的長度。

## 還沒解

- `1C03:0524`（轉一步：一次轉多少、什麼時候回 1）。
- 前進那一段的量（`+0x56`／`+0x58` 怎麼扣、與哪個速度有關）。
- `3310:0006`（兩點距離的算法與捨去）。
- 艦隊走了之後**各分隊怎麼跟**——remake 目前的模型是逐分隊各自往自己的
  目的地走（`rules.AdvanceBattle`），與原版的艦隊層移動不是同一件事。

## 對 remake 的影響

旗艦的「移動」**還不能接**：互動的兩段都問清楚了，但按下去之後要有
艦隊層的移動引擎才看得到效果，而那一段（上面四項）還沒逆向完。
接一個「按了沒反應」的選項比不接更糟，所以維持現狀
（`docs/spec/023`：旗艦的「移動」關著）。

分隊層的「移動」不受影響——它寫的是分隊自己的目的地，
`rules.AdvanceBattle` 已經會走（`docs/spec/024`）。
