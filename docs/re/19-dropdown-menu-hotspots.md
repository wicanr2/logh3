日期：2026-09-07

事實整理進 [`docs/internals/23`](../internals/23-hotspot-lists.md)

## 起點

命令列與系統選單的十二張畫面都對拍完了，但 remake 還接不上——
「點哪裡會開哪一張」沒有資料。頂層命令列那三格在熱區清單裡
（`0C52`），下拉出來的四個項目沒有。

## 掃不到，不是因為沒掃

選單開著的時候（點 `352,85` 之後）把 `54B30` 起的 64 KB 倒出來重掃，
找到 **25 份清單，位移與走到會計報告時那一份完全相同**。沒有多出來的。

⚠ 掃描腳本當時預設把結果寫進 `docs/internals/data/hotspot-lists.json`，
於是這一掃順手蓋掉了帶人工標籤的正式資料（git 還原）。輸出路徑已改成參數。

## 為什麼掃不到

`hittest-sites.json` 裡有一處呼叫的清單位移是 `null`——靜態解不出來。
去看那一段：

```
FF 76 08        push [bp+08]
FF 76 06        push [bp+06]
FF 36 50 F2     push [F250]
FF 36 4E F2     push [F24E]
FF 76 1A        push [bp+1A]      ; 清單 far 指標的段
FF 76 18        push [bp+18]      ; 位移
9A F9 01 A9 37  call far 37A9:01F9
```

其餘 26 處都是 `1E BB <位移> 53`（把資料段位移寫死），只有這一處**把清單
當參數收**。所以下拉選單的熱區不住在資料段的固定位置，靜態掃描結構上抓不到。

## 行為量得出來

要接 remake 其實只需要「點 (x,y) 會開哪一張」。這件事直接量：
每一組座標跑一份收據，拿結果畫面去比對已知的十二張。

十個資料點收斂到一條規則：**x 從母項目（命令列那一格）的左緣起算，
寬度是該選單裡最長那個標籤的字數 × 16，四個項目共用同一個寬度；
列高 20，第一列從畫面 y ＝ 120 起。**

| 點擊（滑鼠座標）| 結果 |
|---|---|
| (415,85) | 出擊命令 → 待命中提督資料 |
| (416,85) | 選單關掉，回主畫面 |
| (400,159) | 生產計劃 |
| (400,160) | 選單關掉 |
| (543,105) | 選單關掉 |
| (591,105) | 取進度 |
| (592,105) | 選單關掉 |
| (575,145) | 設定 |
| (576,145) | 設定 |
| (592,145) | 選單關掉 |

(576,145) 那一筆是關鍵：如果寬度照「設定」兩個字算，576 就該落在外面。
它落在裡面，而 592 落在外面——所以寬度取的是同一個選單裡最長的標籤
（「取進度」三個字，48 像素）。

## 還沒解的

在選單的 modal 迴圈裡看呼叫者傳了什麼進去。
