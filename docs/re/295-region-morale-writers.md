| `add bx/si/di,7Ch`（`83 C3 7C` 那一路，再用 `mod=00`）| `s3datamem` 線性 0–`0x54B30` | 1 處，`056A:0ADF` |

正對照：同一組掃描在 `+0x7D`（未安定度）上找得到 `2703:0DA1` 那一串已知的寫入點

扣掉四個讀取，`+0x7C` 的寫入點**只有下面四組**。

## 寫入者一：新遊戲初始化 `2703:0000`

```
2703:0087  26 c6 47 7c 00   mov byte es:[bx+7Ch], 0      ; 擁有者 0
2703:0091  26 c6 47 7c c8   mov byte es:[bx+7Ch], 0C8h   ; 擁有者 1
2703:009B  26 c6 47 7c 64   mov byte es:[bx+7Ch], 64h    ; 擁有者 2
```

逐格依行星重算擁有者（`2703:159B`）之後照擁有者設。**唯一的呼叫者**是
`0374:0327`（`9a 00 00 03 27`，線性 `0x03A67`）——新遊戲初始化那一支，同一支把
回合計數器 `ds:8F18` 歸零、把六位專任參謀設成開局值（軍事 6／79、情報 13／58、
內政 16／60），前一行
`0374:0322` 是 `2C5D:089A`（讀 `ADMIRAL.DTX` 與 `STELLAR.DTX`，槽位字元 `'X'`）。
收據 `mrx295` 的 `-regs-at 2703:0000` 只命中一次，`#58,357,433`。

## 寫入者二：每回合往擁有者的目標值走一格 `056A:0AA5`

```
056A:0AA5  cl = 0 ; 指標 = ds:A79C
  0ABE  26 80 7f 12 00   cmp byte es:[bx+12h], 0   → 目標 dx = 0
  0ACD  26 80 7f 12 02   cmp byte es:[bx+12h], 2   → 目標 dx = 100
                                                    否則 目標 dx = 200
  0ADF  83 c3 7c         add bx, 7Ch
  0AE2  26 8a 07         mov al, es:[bx]            ; 民心（byte）
  0AE5  30 e4            xor ah, ah                 ; 零延伸
  0AE7  2b c2            sub ax, dx
  0AEB  09 c0 / 79 05    or ax,ax / jns
  0AEF  26 fe 07         inc byte es:[bx]           ; 差 < 0 → +1
  0AF4  09 f6 / 7e 07    or si,si / jle
  0AFB  26 fe 4f 7c      dec byte es:[bx+7Ch]       ; 差 > 0 → −1
  0AFF  fe c1            inc cl ; 指標 += 7Eh ; 32 格
```

也就是

```
對每一格：
    目標 = 擁有者 == 0 ? 0 : 擁有者 == 2 ? 100 : 200
    民心 < 目標 → 民心 + 1
    民心 > 目標 → 民心 − 1
```

擁有者讀**星域記錄的 `+0x12`**，不是行星現算。民心零延伸之後才減，所以 255 在
帝國星域也是往下走，不會繞回。

### 什麼時候跑

唯一的呼叫點是 `056A:0034`（`9a a5 0a 6a 05`，線性 `0x056D4`），在
`056A:000C` 那一串裡——那一串就是 [`251`](251-turn-loop-and-battle-nesting.md)
主迴圈每一圈開頭（非續接戰鬥時）呼叫的命令階段處理：

```
056A:000C:
  056A:011C        日期與「戰略模式處理中」
  056A:0067        兩位軍事專任參謀的提督記錄 +0x02（32 位元）+= 50
  056A:0219        提督表 82 筆逐筆
  056A:09EB        逐支扣艦隊維持費（docs/re/236）
  056A:0AA5        ← 民心往目標走一格
  056A:03E0        32 支艦隊逐一移動（docs/re/78）
  2703:051D        星域的飛彈／艦載機存量分回行星（docs/re/273）
  2703:0853
  056A:0469        +0x13 bit1／bit2／bit4 那一圈（docs/re/245、292）
  （每一步之間夾一次 056A:0983：讀一次滑鼠事件，事件碼 2 時改 ds:8F23／8F24
   並跳訊息 ds:0902；沒有細讀）
```

所以**每按一次「實行」民心就走一格**，在逐格開戰與回合尾巴重算擁有者**之前**。
收據 `mrx295` 的 `-regs-at 056A:0AA5` 在三次「實行」各命中一次
（`#216,021,639`、`#324,936,238`、`#434,513,563`），每次都落在前後兩份傾印之間。

一格一回合只走 1，一個月十回合，所以**被打下來的星域要很久才會歸心**：帝國的星域
落到同盟手上，民心從 0 走到 200 要 200 個回合（20 個月）；叛亂變成無主的格子從 0
走到 100 要 100 個回合。那段期間稅率被 `m` 壓低、未安定度的 `f2` 也偏高。

## 寫入者三：費沙事件 `1213:03F5`

[`193`](193-phezzan-trigger-not-in-dump.md) 讀到費沙事件的包裝是
「`1213:025D`（本體）→ `1213:03F5` → `090A:0E6D`」，第二支沒讀。它就是第三個寫入者：

```
1213:03F5:
  bx = 0AE80h                         ; ds:A79C + 14 × 126 ＝ 費沙的星域記錄
  擁 = 費沙[+0x12]
  3982:022D(擁) != 0 → 回             ; 無主回 0FFh；電腦座位回 1（docs/re/140）
  t = ds:8F18                          ; 回合計數器
  pct = t >= 600 ? 0 : ds:328E[t ÷ 100]
  for i in 0..31:
      i == 14 → 跳過
      星域 i[+0x12] != 擁 → 跳過
      2AF5:0036(i, 0)                  ; 切到這一格的行星
      每顆行星：經濟力(+0x1A) −= 經濟力 × pct ÷ 100      ; 32 位元
  04D0  26 c6 47 7c 64   mov byte es:[bx+7Ch], 64h     ; 民心 ← 100
      2AF5:00B6()
```

**費沙落在人類玩家手上時**，玩家其餘每一格的行星都被砍掉一部分經濟力、民心一律
變成 100。兩個陣營的「站在敵方那一邊的民心」都從 0 變成 100：稅率的 `m` 從 0 變成
`100 × 參謀[+0x14] ÷ 100`、未安定度的 `f2` 從 0 變成 10，之後再照上一節一格一格
走回去。電腦方拿到費沙不受罰。

`3982:022D` 整支 35 bytes：`陣營 == 2 → 0FFh；否則 ds:8F21[ds:8F25 == 陣營 ? 0 : 1]`。
`ds:8F21`／`8F22` 在 `s3datamem` 是 0／1、`ds:8F25` 是 0。

扣經濟力的比例表 `ds:328E`（`s3datamem` 的線性 `0x57DBE`）：

```
ds:328E  32 28 1e 14 0a          50 40 30 20 10
ds:3293  0c 25 73 00             ＝ "\x0C%s"（1213:01B8 印訊息用的格式字串）
```

索引是 `回合 ÷ 100`，而閘門是 `回合 < 600`，所以索引會到 5——**第 5 格讀到的是
格式字串的第一個 byte `0x0C`**，回合 500–599 扣 12%。這是原版的越界讀，照原樣記。

觸發點仍然未解（`193`），這一段沒有收據。

## 寫入者四：整張表從檔案讀進來

`332E:04BB`（線性 `0x3379B`）：`sprintf("stellar.dt%c", 槽位)` 之後
`332E:08DB(名, ds:A79C, 0FC0h)`——`3D08:002C`（`AH=3Dh` 開檔）＋ `3D08:0009`
（`AH=3Fh` 讀）＋ `3D08:004E`（`AH=3Eh` 關檔），把 4032 bytes 整張蓋掉。
寫存檔是隔壁的 `332E:04F3` → `332E:0964`（`AH=3Ch` 建檔、`AH=40h` 寫）。

讀檔有兩個呼叫者：

| 呼叫點 | 槽位 | 之後 |
|---|---|---|
| `2C5D:08B1`（`2C5D:089A` 那一支）| `'X'`（新遊戲樣板）| 新遊戲初始化接著跑 `2703:0000`，民心被寫入者一蓋掉 |
| `2C5D:064C`（`2C5D:061A(槽)`）| `ds:5CB8[槽]` | 沒有 `2703:0000`，**民心照存檔的值** |

存檔裡的民心就是存檔當下的現值；三格存檔 `STELLAR.DT8`／`9`／`A` 裡全部等於擁有者
的目標值，是因為那三個局面沒有正在收斂中的格子，不是讀檔時重設。

## 順手：`056A:0468` 其實是前一支的 `retf`

`056A:000C` 那一串呼叫 `+0x13` 那一圈的位元組是 `9a 69 04 6a 05`——進入點是
**`056A:0469`**。線性 `0x05B08`（`056A:0468`）是 `cb`，前一支 `056A:03E0`
（艦隊移動）的 `retf`。`docs/re/245` 起一路記成 `0468`，`flagpass`／`rbx292c`
的 `-regs-at 056A:0468` 命中的是 `056A:03E0` 的返回，而那一支每回合也只跑一次，
所以「一次」「在 `2703:08DE` 之前」「在 `0374:0556` 之前」這幾個結論都還成立，
只是量到的步數早了 `2703:051D`＋`2703:0853` 那一段。
（與 `docs/re/255` 的 `090A:0E6A`／`0E6D` 同一種錯位。）

## 方法

**poke 的位址要用算的，不要手算。** `mrx295d` 要改的是 `+0x12`，位址是
`0x5F2CC + i × 126 + 0x12`；`report.txt` 的「改記憶體 lin:X（X）」只證明執行器
寫到了**你給的**位址，證明不了那個位址是你要的欄位。改完先拿傾印看那一格變了沒，
再看結果。

**擬合出來的參數要唯一，而且要有一格能分辨兩種讀法。** 稅率那一段靠 9 格擬合兩個
未知數，5 × 82 組裡只有一組；判「AI 先、民心後」靠的是 17 號那一格——另外三格
兩種讀法算出來一樣，單看它們什麼都分不出來。
