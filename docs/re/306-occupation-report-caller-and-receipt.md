# 306 — 單方面占據報告的呼叫鏈、四句分支與正常路徑收據

## 結論

`056A:0469` 逐格重算星域 `+0x13` bit4 後，`056A:053F` 只要看到**新的**
bit4 就呼叫 `056A:0571`；後者對兩個座位各呼叫一次 `056A:059E`。
`056A:059E` 先以 `3982:022D(座位陣營)` 跳過電腦座位，再以占據艦隊屬於
本座位與否、舊 bit4 是否已設，選四句之一。這條呼叫鏈與分支是
**已證實（proven）**。

原版輸入是執行期擷取的 `mrx056A.com`，SHA-256
`5bafdb75a75879472ef475819acc033b80d8c077d1ac8c905e0759d6d336ef6d`；
IDA 資料庫 `mrx056A.com.i64` SHA-256
`e5c3615cff33d0c4ec0050f9d86a877a3a005dbfa36f6586f085398e4496d183`。
工具是 IDA Pro 9.4；位址空間以下一律是原版 16-bit DOS
segment:offset。正式資料庫只讀，查詢在可丟棄副本執行。

## 原始控制流

IDA 輸出 `report056A-invasion-disasm.txt` SHA-256
`48dfa959c9d9c7d608ea830ca9269938340d67e93237d13a81c5aecb08584962`。
保留原始定位與 bytes：

```text
056A:055D  26 f6 47 13 02       test byte ptr es:[bx+13h],2
056A:0564  ff 76 08 53          push region far pointer
056A:0568  9a f3 06 6a 05       call far 056A:06F3       ; 叛亂

056A:0545  26 f6 47 13 10       test byte ptr es:[bx+13h],10h
056A:0553  9a 71 05 6a 05       call far 056A:0571       ; 單方面占據
056A:0581  9a 9e 05 6a 05       call far 056A:059E       ; 座位 0
056A:0595  9a 9e 05 6a 05       call far 056A:059E       ; 座位 1
```

`056A:059E` 的參數是 `(星域記錄, 座位陣營, 舊 +0x13)`。新 bit4 已由
呼叫者保證成立；`[bp+52h] & 10h` 是舊 bit4。分支化簡後：

| 占據艦隊 | 舊 bit4 | 字串 | 內容 |
|---|---:|---|---|
| 本座位 | 0 | `ds:0732` | `星系已被攻入／目前轉移至占領狀態。` |
| 敵座位 | 0 | `ds:0756` | `星系方面／已經被敵方艦隊侵入。` |
| 本座位 | 1 | `ds:0778` | `星系方面／占領行動持續進行中。` |
| 敵座位 | 1 | `ds:079A` | `星系上／敵方艦隊正在侵略中。` |

星系名字色仍取 `ds:6096[星域擁有者]`；第一句直接接在星系名後，換行後
才回到 `(336,202)`。報告呼叫同一個 `3826:0307`，所以沿用已證實的
72×93 情報參謀頭像與滑鼠事件碼 1／2 模態等待。

## 原版正常玩家路徑收據

批次 `workplace/oracle/occupation-report3/`，原版 `GIN3.COM` SHA-256
`770ed52607bf02584c125043830f22b19cc4b9a21f4909ad2f5f02d8fc8fd918`，
dosgolem-logh3 `e0b6a03`。輸入從新遊戲正常走到第一次「實行」，在
`#217000000`、`056A:0469` 前注入一個最小有效帝國艦隊槽：

```text
lin:60BA4 = 00 00   ; +0x00 旗標、+0x01 陣營
lin:60BA8 = 00      ; +0x04 != FF，297B:131C 的有效槽條件
lin:60BAA = 10      ; +0x06 所在星域 = 16（同盟領土，且無同盟艦隊）
```

`report.txt` 括號內實際位址與上述線性位址相同；`056A:059E` 命中 2 次。
畫面是「亞斯提星系已被攻入／目前轉移至占領狀態。」：

- `screen.bin`：`fa690ac9828134d72e4b3c7e9b6aca7af918943bdfc2f0d0df7154dc0cb0e930`
- `pal.bin`：`28b933fe81e79a380123b932302ba2dd8983bd3ac85a8f922e9e3b6ac1bd02e8`
- remake 的文字矩形 `(334,178)`–`(534,239)`：**0 像素差異**。

前兩次探索收據沒有被拿來裁決：第一次只改未使用槽的星域；第二次仍漏了
`+0x04 != FF`。IDA 讀出 `297B:131C` 的有效槽條件後，第三次才形成 bit4。

## 限制

原版在逐格迴圈裡每遇一則報告便暫停；remake 目前先算完整圈的 bit2／bit4，
再依星域編號逐則顯示。玩家可見文字、四句選擇、bit4 與後續阻塞已驗證，
但報告停住當下的整機記憶體與後續叛亂 RNG 位置不是完整 same-state。
此外，對戰模式原版會對兩個人類座位各顯示一次；目前 remake 跟既有易主
報告一樣，只替當前 `g.faction` 顯示。兩項都明列限制，不冒稱完整 parity。
