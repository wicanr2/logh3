# 186 — 一個回合跑兩個座位，電腦那個才叫 AI

`docs/re/175` 找到 AI 的閘門是 `ds:8F23[ds:8F1E] == 1`，但沒讀
「`ds:8F1E` 是誰推的」。這一輪把座位迴圈讀出來。

掃寫入點用的是 1 MB 完整傾印（`docs/re/181` 的工具洞）——
這些位址都在 `0x05xxx`、`0x12xxx`、`0x3Axxx`，`codeall.bin` 只涵蓋第二個。

## 一個座位的回合：`04F8:030E`

```
04F8:030E():
    ds:8F1D = ds:8F25[ds:8F1E]        ; 這個座位的陣營
    ds:8F1F = ds:8F29[ds:8F1E]
    04F8:0355(1)
    04F8:04C7()
    3765:0003(0)
    若 ds:8F23[ds:8F1E] == 1：         ; 這個座位是電腦
        2D10:0005()                    ; 整套戰略 AI（docs/re/175）
```

## 呼叫端把兩個座位都跑一遍

`0x05267`：

```
ds:8F1D = 0FFh
3705:0349(1)
ds:8F1E = 0；04F8:030E()
ds:8F1E = 1；04F8:030E()
```

另一處 `0x0510F` 是同樣的形狀，跑的是 `04F8:01B9()`（回非 0 就停）。

**所以「電腦要不要動」不是每回合擲一次的判斷，而是座位設定**：
`ds:8F23[座位]` 在開局選陣營那一頁決定（寫入點 `0x3AAA1` 寫 1、
`0x3AAA8` 寫 0），之後每個戰略回合兩個座位各跑一次 `04F8:030E`，
是電腦的那個就跑整套 AI。

## 那 `docs/re/79` 的零是怎麼來的

`s3ai6` 那一跑十二次「實行」之後 `ds:D60E = 0`、`ds:D50E` 整張 0
（`docs/re/175`），而座位表是 `ds:8F23[0] = 0`（玩家）、`[1] = 1`（電腦）
——照這一輪讀到的結構，座位 1 每個戰略回合都該叫 AI。

`docs/re/77` 量過同一組輸入：**十二次「實行」只有第一次是戰略回合，
其餘都落在伊謝爾倫的戰鬥畫面上**。所以能跑到 `04F8:030E` 的機會很少。
但「只有一次」與「一次都沒有」還是差一個，**這一格仍然對不齊**，
記成待驗——可能的方向是 `ds:8F46`（跳過一次的旗標，`docs/re/175`）
或者那一次戰略回合走的是 `0x0510F` 那一條路。

## 對 remake 的意義

這一條改變了「把 `Original` 換掉」的風險評估：**電腦座位每個戰略回合
都會跑 AI**，不是偶爾。所以換掉之後，任何跑到戰略回合的對拍都可能改變，
`turn260`／`turn320`／`turn450` 要重跑才知道。

## 還沒讀

`04F8:0355`、`04F8:04C7`、`04F8:01B9`、`3765:0003`、`3705:0349`、
以及 `0x05267`／`0x0510F` 兩條路各自的觸發時機。

## 2026-10-03入口定位追加勘誤

[研究386](386-active-seat-lifecycle.md)以IDA9.4函式邊界及原始bytes核對：

先前流程語意保留，0510F只作搜尋線索；不要拿它掃far call後以零結果否定呼叫者。
