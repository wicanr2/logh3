# RE 106 — 重算星域擁有者的那支常式

`docs/re/17` 的狀態行寫著「已解（載入後有 10 個星域被改成無主，**那一步
未解**）」。這一輪把那一步補上——**只補這一項**，規則本身與衍生欄位
`docs/re/17`／`docs/internals/22` 早就記完了。

## 誰寫 `+0x12`

收據 `ownS2`（`-watch 5F2CC-6028C`，整張星域表 32 × 126，S2 的移動序列
1.2e9 步）共 11,287 次寫入，其中打到 `+0x12` 的 95 次。扣掉開機時的
整批初始化（`63A1:002D`／`0349:01EA`）與載入劇本（`3D08:001A`），
剩下的**十次**全部來自同一處：

```
#68687214 星域  3：00 → 02   ← 2703:15CD
#68706930 星域 10：00 → 02
…
#68758321 星域 28：01 → 02
```

正是 `docs/re/17` 說的「載入之後有 10 個星域被改成無主」。

> `-watch` 印的 CS:IP 是**指令之後**的位址，所以真正寫的那條在 `+15CD`
> 之前——`2703:159B` 這支小函式的尾巴。

## `2703:159B`：算完、變了才寫、回報有沒有變

```
2703:159B(星域記錄):
    al = 2703:15D5(星域記錄)        ; 算出應該屬於誰
    if al != 星域[+0x12]:
        星域[+0x12] = al
        return 1                     ; 「變了」
    return 0
```

回傳值是給呼叫端用的（改了才要重畫星圖的勢力色，`docs/re/17`）。

## `2703:15D5`：邊算擁有者邊把衍生欄位重建

那支先把 `+0x16`／`+0x17`／`+0x18` 與 `+0x20`／`+0x22` 清成 0，
再逐一走過該星域的行星（一筆 82 bytes），依 `+0x11`：

| 行星 `+0x11` | 做什麼 |
|---|---|
| 0 帝國 | 帝國經濟力累加、`+0x16`＋＋ |
| 1 同盟 | 同盟經濟力累加、`+0x17`＋＋ |
| 其他 | `+0x18`＋＋ |

三種都會再把該行星的 `+0x1A`（經濟力，32 位元）加進總和、
`+0x20 += 行星 +0x14`、`+0x22 += 行星 +0x16`。走完之後：

- 每顆行星的 `+0x13` ＝ 該行星經濟力 × 100 ÷ 星域總經濟力；
- 星域 `+0x14`／`+0x15` ＝ 帝國／同盟經濟力 × 100 ÷ 總經濟力；
- 回傳值：

```
if 同盟行星 == 0 && 其他 == 0：回 0（帝國）
if 帝國行星 == 0 && 其他 == 0：回 1（同盟）
否則                          回 2（無主）
```

與 `docs/re/17` 從資料推出來的規則一字不差——現在是**從程式讀到的**。

驗算（收據 `s3tgt` 的傾印）：`+0x20`／`+0x22` ＝ Σ 行星 `+0x14`／`+0x16`
**32 個星域全對**；`+0x14`／`+0x15` 的百分比 **31 個全對**，
不符的是這一場戰鬥所在的星域 26（30／31 與 69／68 各差 1），成因未確認。

## 它只在載入時跑

`ownS2` 那 1.2e9 步裡，`+0x12` 在第 68.76M 步（載入劇本）之後**再也沒有
被寫過**——包括艦隊在星域之間移動的那幾次。配上 `docs/re/105`
（戰鬥打贏也不寫），可以說：

> **星域的擁有者是行星擁有者的函數，而且只在載入時重算一次。**

所以「什麼時候易主」這個問題要換成「**什麼時候有行星換手**」。

## 行星換手的三個寫入點（下一輪從這裡開始）

同樣用靜態掃描（找 `mov [?+11h], al` 與 `mov byte [?+11h], imm` 的位元組
樣式，不必再開收據），整份 1 MB 記憶體只有**三處**寫行星的 `+0x11`：

| 線性位址 | 寫什麼 | 樣子 |
|---|---|---|
| `2110C` | 某個記錄的 `+0x01`（＝陣營）| 前面先 `call 20B4:0681`，回 `0xFFFF` 或 0 就跳過 |
| `2231B` | 同上 | 前面先 `call 203A:0424` 再 `call 20B4:0E2C`，非 0 才寫 |
| `28B16` | 常數 **2（無主）** | 單獨一支小函式的開頭 |

前兩處寫完之後都做同一件事：

```
3C9C:000A(行星 + 0x20, 0, 0x1C)      ; 把 +0x20 起的 28 個 byte 清成 0
```

第一處還多一條 `行星[+0x3E] >>= 1`（某個值砍半）。

「陣營」的來源是一個記錄的 `+0x01`——艦隊記錄的 `+0x01` 正是陣營
（`docs/internals/33`），所以這兩處看起來就是**一支艦隊打下一顆行星**。
第三處把行星變成無主。

在一場實際打下行星的序列上量，看哪一處會跑、觸發條件是什麼。
