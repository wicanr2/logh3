# 123 — 艦隊每回合怎麼轉、怎麼走（以及走一步的確切算式）

`docs/re/122` 讀出了「實行」那一步的骨架。這一輪把裡面三件事讀完，
其中一件直接修掉 remake 既有的一個近似。

## 一個 32 位元的行動額度

艦隊記錄 `+0x56`／`+0x58` 是一個 32 位元的額度，轉向與前進都從它扣：

- 轉向一步扣 **8**（`1C03:0554`）。
- 前進一步扣**實際走的距離**（`1C03:02C6`；算出來是 0 就當 1）。
- 額度**不足 8 就這一輪不動**（轉向與前進兩邊都先比一次）。

額度怎麼補、與哪個速度有關，還沒讀。

## 轉向一步（`1C03:0554`）

```
差 = 2BE1:021B(目標朝向, 艦隊 +0x4A)        ; 帶正負號的最短角差
if |差| <= 艦隊 +0x4D（回轉速度）：
    艦隊 +0x4A += 差                        ; 一次轉到位，回 1
else:
    額度 < 8 → 回 0
    艦隊 +0x4A += sign(差) × 回轉速度
    額度 −= 8
    回 1
```

所以**每回合最多轉「回轉速度」那麼多**（單位是 1/256 圈）。

## 前進一步（`1C03:02C6`）

```
新位置 = 2BE1:026F(現在位置, 艦隊 +0x4A, 8)   ; 沿朝向走 8 像素
距離 = 3310:0006(現在位置, 新位置)             ; 32 位元；0 就當 1
額度 −= 距離
if 2583:040C(新位置, 艦隊 +0x01) == 0：
    艦隊 +0x5C／+0x5E ← 新位置
```

`2583:040C` 是「這個點站不站得住」（帶陣營參數，可能含避開其他單位）
——還沒讀。到目的地的判準在骨架那一段：距離 ≤ 8 就直接歸位
（`docs/re/122`）。

## 走一步的確切算式（`2BE1:026F`）

```
dx = (正弦表[(方位 + 0x40) & 0xFF] × 距離 + 0x200) >> 10     ; cos
dy = (正弦表[ 方位 ]              × 距離 + 0x200) >> 10     ; sin
x += dx；y += dy
x 夾進 0–0x7EF（2031）、y 夾進 0–0x7E7（2023）
```

正弦表是 `ds:573A`，一整圈 256、值 ＝ sin × 1024（`docs/internals/41`）。
**加 0x200 再右移 10 位就是四捨五入**（0x200 是除數的一半），
不是截斷；右移是算術右移，所以負值往 −∞ 收。

### 這修掉 remake 一個既有的近似

`internal/rules/terrain.go` 的 `LineOpen`（原版 `1588:0891` 的直線判定）
先前寫的是 `cos256(a) * step / 1024`——Go 的整數除法是**截斷**。
768 組（256 個方位 × 3 種距離）樣本裡有 **446 組**與四捨五入的結果不同，
而差一個像素就可能落到別的半格上、讓通行判定翻面。

現在改走 `rules.StepAlong`，照上面的算式（含夾範圍）。註解裡原本寫著
「原版真正走一步的 `2BE1:026F` 還沒逆向，所以自己算，落點可能差一兩個
像素」——那條註解同時被解掉了。

> 這條規則是**照反組譯釘的**（`TestStepAlongRoundsAndClamps`），
> 不是對收據：原版走一步的落點還沒取到 same-state 樣本。
