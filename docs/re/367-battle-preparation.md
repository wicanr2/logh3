## 正式共用規則的缺口及停止線

`1AAB:0D9F` 同時被自動行星補充與手動命令使用。`0E10` 保存原修理上限−原艘數，
`0E1B` 加艘數，`0E33` 加回原差值，`0E3F` 比滿編上限，`0E4A` 寫回 `+0C`。
有實際補充時，**修理上限 = min(16 位的原修理上限＋給出的艘數，滿編)**。
`PlanetReplenish` 漏寫此欄位；修正受[規格 079](../spec/079-battle-preparation.md) READY 子範圍約束。
沿垂直鏈查到 `Slot.ApplyBattleResult` 只寫艘數及索敵等級，亦漏掉已存在於 `BattleUnit`
的修理上限與兩格彈藥庫存。原版直接改同一筆78bytes，存檔保存整池；戰後不能丟掉這三格。
此回寫缺口列入同一READY子範圍；中途戰場存檔及其他八步仍不在本輪完成聲明。

完整第一階段仍 DRAFT：同艦隊分隊序已證實，但 `1930:0510`／`1AAB:04BD` 對其他艦隊
可能比較回 0，**跨艦隊競爭的完整排序 unknown**。行星沿用 donor 全域指標；
`A42E` 每筆更新、`A440` 只遇種類6才更新，其持續狀態不能猜成艦隊編號序。
士氣報告續接、正式回合回寫／存讀也尚須對拍。
防衛力低16位證據不能直接套到戰略 `20B4:15E1`：研究339「同一算式」需限一般低值案例，
戰略高值另查原始指令。不因此深挖標準 Borland library 或硬體 driver。

## 保留的失敗

首次 `battle79-preparation-a` 把 `-poke` 寫成「步數:位址」被 probe 拒絕；
正確為「`lin:位址@步數=bytes`」，失敗 report 不算收據。
IDA 首次 `024C` 查詢切進 `024B` 指令，無 JSON；內部 `-L` 日誌定位
`0x1044D` 解碼失敗，改用呼叫端證實的 `02B4` 與 `019D..02B3` 邊界後有有效輸出。
都是命令／工具問題，未改遊戲；新複本保留，不在正式資料庫反覆試跑。
