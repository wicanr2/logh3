## bit1 ＝ 叛亂

`docs/re/245` 把 `+0x13` 的 bit1 追到 `2703:1789`，讀出前置條件是
「不是首都、不是無主、而且該陣營在這一格**沒有駐軍**」，之後查統治者提督
記錄再擲 `亂數 % 400`，但後半段沒讀完，所以只寫成「像事件判定」。

`ds:086F` 是 **`發生叛亂。`**，而它的前一條 `ds:085D` 是
`\x1B[%d,%s\x1B[%d,星系`——「**〈星系名〉星系　發生叛亂。**」。
前置條件也完全講得通：**自己的星系、不是首都、沒有艦隊駐守，就有機率叛亂**。

所以 `+0x13` bit1 ＝ **這一格這回合發生叛亂**。`2703:1789` 的後半段
（亂數之後怎麼判、叛亂的效果是什麼）仍未讀，remake 還是只清不設。

## 一個 Big5 反斜線錯字

`ds:083A` 存的位元組是

```
b2e6 c2f7 a6a8 a5a1 42 bd54 a977 a5cd c1d9 a143
脫    離    成    央   B   確    定    生    還    。
```

中間夾著一個 ASCII `'B'`（`0x42`），讀起來是「脫離成央B確定生還。」。
原句應該是

```
b2e6 c2f7 a6a8 a55c a142 bd54 a977 a5cd c1d9 a143
脫    離    成    功    、   確    定    生    還    。
```

差別是 `A5 5C A1 42` 變成 `A5 A1 42`——**少了一個 `0x5C`**。
`功` 的第二個位元組正好是 `0x5C`，也就是 C 字串裡的跳脫字元 `\`；
編譯器把它當成 `\xA1` 的跳脫吃掉一個位元組，`A1` 留下、`42` 變成 `'B'`。
這是 Big5 在 C 原始碼裡的經典坑。

**但它不是系統性的**：同一張表的 `ds:08BC`（`部分行星我軍已成功進駐。`）
裡的 `功` 是完好的 `A5 5C`。同一個字在同一張表裡一好一壞，表示這兩條字串
不是同一個來源或同一道工序進去的。

**這種錯字照原樣保存，不修**——它是 1994 年那份中文化工作的一部分。

## remake 缺的

報告本身還沒做（`docs/spec/033` 末節）。做的時候：

- 標題兩種：玩家那一方是 `戰略模式處理中`、電腦那一方是 `戰略模式思考中`。
- 易主兩句分我方／敵方（`ds:08DA`／`ds:08EE`）。
- 名字與顏色用 `\x1B[%d,` 那組控制碼塞進去（`docs/internals/48` 的同一套）。
- **報告是模態的**：它擋住回合結束處理，按掉才會繼續（`docs/re/246`）。

## 一條方法

**畫面上讀得到的一句話，就是進資料段的鑰匙。** 這一輪不是從程式找字串，
是把畫面上那六個字編成 Big5 去掃記憶體，一次命中，整張表跟著出來——
而表裡的 `發生叛亂。` 又反過來把兩天前讀不完的 `2703:1789` 定了性。
