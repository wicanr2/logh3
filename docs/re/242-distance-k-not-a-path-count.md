# 242 — 距離表的 `k` 不是「路上有幾格不是自己的」

`docs/re/241` 把兩張距離矩陣倒出來，形狀是

```
值 = 1024 × k + 小成本          （k ＝ 高位元組 ÷ 4）
```

並留下「`k` 顯然與『路上有幾格不是自己的』有關，但還沒有量到定義」。
**量了，不是。**

## 怎麼測

離線的，不用跑容器：手上有距離矩陣、中點矩陣（`star-graph.json`）與
796/1 量到的星域擁有者（`month-rollover-796-01.json`）。

路徑用**中點矩陣遞迴展開**（與 `rules.StarGraph.Route` 同一支：
`T[i][j]` 是中點，`0FFh` 代表直接相連）。展開之後 **1024 對全部走得通**
——一開始把它當「下一跳」用，一半的對走不出來，那是錯的讀法。

## 十個候選，全部不成立

`tools/scripts/distance_k_probe.py`，比對的是 `4 × 候選 == 高位元組`：

| 候選 | 帝國 中／不中 | 同盟 中／不中 |
|---|---|---|
| 路上不是自己的（含兩端）| **692／332** | **743／281** |
| 同上，不含起點 | 652／372 | 697／327 |
| 同上，不含終點 | 652／372 | 697／327 |
| 同上，不含兩端 | 122／902 | 188／836 |
| 路上是敵方的（含兩端）| 415／609 | 360／664 |
| 同上，不含起點 | 417／607 | 366／658 |
| 同上，不含兩端 | 122／902 | 188／836 |
| 路上是無主的 | 371／653 | 353／671 |
| 步數 | 470／554 | 354／670 |
| 終點是不是自己的 | 212／812 | 288／736 |

最好的只有 **743／1024**（73%）。**七成不是答案**——一個查表用的整數
不會有三成例外。

## 兩個可能

1. **距離表走的不是中點矩陣那條路。** 中點矩陣是步數最短，距離表的低位
   元組是成本；成本最小的路可以不同。那樣的話「沿著中點矩陣數」本來就
   數錯了路。
2. `k` 數的不是擁有者，是別的欄位（例如星域 `+0x13` 的旗標）。

兩個都要「誰填這張表」才問得下去，而那個寫入點還沒找
（`docs/re/241` 末節）。分頁框會換頁，所以線性位址上的監看抓到的
不一定是這張表——要先解決那個。

## 一條方法

**消去也要留腳本。** 這十個候選跑一次不到一秒，但下一個人若沒看到結果，
會照「顯然與擁有者有關」再想一遍同一批。腳本留著、結果寫進表格，
下一輪就從「換一條路重數」或「換一個欄位」開始，不會從頭。

---

> 兩個可能裡的第一個成立、但不是主因（`docs/re/243`）：中點矩陣確實是
> **成本**最短路的見證，路本身沒數錯。真正的問題是 **`k` 加在邊上，不是格上**
> ——`2B99:007D` 對每一條邊檢查「兩端是不是都屬於自己」，是就不加、
> 否則 `+0x400`。這十個候選全部在數格子，所以全部落空。
> 正確的定義是「路徑上兩端不全屬於該陣營的**邊**數」，1024 格全中。
