## 為什麼要分類，而不是直接全部重錄

收據不進版控，重錄就是覆蓋。而「重錄」只保證畫面是新執行器跑出來的，
**不保證那份收據還證明得了它當初要證明的事**——如果時序一改，同樣的步數
落在別的時點，`own24` 那種「下拉選單開著」的收據就變成「選單關著」，
名字還在、用途沒了，而且看起來完全正常。

所以先用形狀把「同一個時點、只是畫得不一樣」與「根本停在別的時點」分開。
覆蓋前的原件留在 `workplace/oracle-prev/<批次>/`（只留最原始那一份）。

## 形狀二：左下角那塊摘要面板

`cmd1e` 的差異 2,265 個像素全部落在那塊裡。裁出來看：

```
舊（收據）      整塊空白，只剩外框
新（執行器修好） 同盟軍星系艾流塞拉
                治安  ----   行星 0/3   艦隊 0： 0
```

同樣 2,265 這個數字出現在 `cmd1e`／`lstmenu1e`／`sysmenu1e`／`load1e`／
`save1e`／`quit1e`／`tax1e`／`prod1e` 等等——**是同一塊、同一段文字**。

面板本身 remake 早就會畫（[`../spec/001`](../spec/001-region-summary-panel.md)
狀態 CONFORMED，版面在 `docs/internals/data/region-panel.json`）。缺的是
**什麼時候該填、什麼時候該清**：

- `main1e`（2.2 億步、同一條輸入序列的前綴）那塊是**空的**，而且新舊執行器
  逐位元組相同；
- `cmd1e`（2.3 億步，中間多一次 `180000000:352:85` 的點擊）那塊**有字**，
  內容是右鍵點過的星域 30（艾流塞拉，`internal/asset/rgn_at_test.go`）。

兩份只差一次點擊與一千萬步，面板卻從空的變成有字——**觸發條件還沒讀**。
remake 現在的行為等同「永遠空著」，所以這 40 份全部對不上。

**這一步不要用猜的補。** 面板填錯星域與面板空著，在對拍上都是紅的，
但前者會讓人以為做完了。

## 形狀四：步數要重新對準

`own24`／`pladump`／`rgndump`／`turn10` 四份的差異各 6,687 個像素，落在
`x[512,607] y[96,239]`。裁出來看：舊收據是**系統指令的下拉選單開著**
（再任／取進度／存進度／設定／結束），新的是**選單已經關了**，只剩
「系統指令」那顆按鈕與停在它上面的游標。

輸入序列一個位元組都沒改，變的是時序。`270` 量到新版走完開場動畫比舊版
**領先約一千萬道指令**，往後每一個「第 N 億步」都落在遊戲的另一個時刻。

所以這一類的處置不是重錄，是**把 `-clicks`／`-steps` 的步數重新挑一次**，
讓它再度停在原本要證明的那個畫面上。挑完要連「為什麼是這個步數」一起
寫進收據，否則下一次執行器再改又得從頭猜。

## 一個副作用：`go test ./...` 現在是紅的

重錄過的收據與 remake 對不上，測試就會開口——**那正是要的**。紅的內容
目前全部是形狀二（左下角面板）與形狀三（`cb1` 那 32 個像素）。

**不要為了把測試變綠去改回舊收據。** 舊收據是在會改寫遊戲程式碼的執行器
上錄的（`270`），它綠的時候證明的是 remake 與一份壞掉的原版一致。
