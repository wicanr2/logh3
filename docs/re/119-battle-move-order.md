# 119 — 「移動」寫的是哪一對座標（順帶推翻兩個欄位的語意）

命令選單的第一項「移動」在 `1CC5:0D1C`：

```
艦種列 = ds:4E3A + 陣營 × 208 + 艦種 × 26        ; 算了但這一支沒再用
call far 2583:00DE(艦艇 far ptr, …)             ; 互動選目的地，回 0 ＝ 取消
if 回傳非 0:
    艦艇 +0x1E ← 0                              ; 分隊行動設成「移動」
```

`2583:00DE` 選完之後做的事只有兩行：

```
艦艇 +0x28 ← 選到的 x
艦艇 +0x2A ← 選到的 y
```

## 控制實驗：那一對是「要去的點」，不是「現在的位置」

收據 `s3cmdmove`：與 `s3cmdsq3` 同一條前置序列、同一個注入，多兩下——
點「移動」，再點戰場上的 (200,200)。第 31 艦隊第 1 分隊的記錄前後：

| 位移 | 之前 | 之後 |
|---|---|---|
| `+0x1E` 低位元組 | `7F`（沒有命令）| `00`（移動）|
| `+0x28`／`+0x2A` | (1293, 830) | **(1240, 740)** |
| `+0x34`／`+0x36` | (1293, 830) | (1293, 830) |
| `+0x1A`／`+0x1C`（小地圖）| (1293, 830) | (1293, 830) |

點的是畫面 (200,200)，視野位移 (1040,540) → 世界 **(1240,740)**，
與寫進 `+0x28` 的值一個像素不差。**沒有取整、沒有夾到射程內。**

而那個分隊在畫面上**還停在原處** (253,290)：`s3cmdmove` 的畫面上八個
單位的圖塊全部落在 `+0x34`／`+0x36` 算出來的位置（`tools/scripts/unit_tiles.py`
的塊比對 0 個不符），小地圖座標也沒動。

所以：

```
+0x28／+0x2A  ＝ 要去的點
+0x34／+0x36  ＝ 現在的位置（畫面上畫的就是它）
```

`docs/internals/38` 原本把這兩對寫反了。之前對不出來是因為手上每一份
收據裡的參戰分隊都在停止狀態，兩對值相同——**要靠一次「只改目的地」
的控制實驗才分得開。**

## 艦隊選單那三項接到哪裡

分隊的「移動」與艦隊的「移動」**不是同一支**。艦隊選單
（`1CC5:070D`）的分派：

| 項目 | 進入點 | 做的事 |
|---|---|---|
| 移動 | `1CC5:0813` | 把艦隊 `+0x4D`（回轉速度）與 `+0x4E`（巡航速度）當參數傳給 `2583:0003` 選點 |
| 戰鬥 | `1CC5:08BD` | 同一支選點，速度換成 `+0x4D` 與 `+0x4F`（戰鬥速度）；選成功就 `+0x48 ← 1` |
| 索敵 | `1CC5:0966` | 先把艦隊 `+0x3A`／`+0x3B` 清成 0，再拿 `+0x38` 當艦艇池索引去擺索敵分遣隊 |

所以：

- **艦隊層的選點是帶速度上限的**（`2583:0003` 收兩個速度當參數），
  分隊層那支（`2583:00DE`／`2583:013D`）沒有。
- `docs/re/117` 記的「艦隊 `+0x3A` 不是 `0xFF` 或 `+0x3B` 不是 0 就關掉索敵」
  現在有了對稱的證據：索敵一開始就是把這兩個位元組清成 0。
- 「戰鬥」與「移動」的差別只在**用哪一個速度算上限**，以及寫進 `+0x48`
  的行動編號。

`2583:0003` 與 `2583:013D` 兩支選點迴圈的內容（畫什麼、怎麼夾上限）
還沒讀，所以 remake 這一輪不做「移動」——沒有 READY 的規格不動
production path。

## 對 remake 的影響

`rules.BattleUnit` 的 `X`／`Y` 與 `TargetX`／`TargetY` 是 `Deploy` 自己填的
（佈陣時兩者相同），沒有讀這兩個欄位，所以沒有跟著錯。受影響的是
`docs/internals/38` 與 `tools/scripts/unit_tiles.py`，兩邊都已改。
