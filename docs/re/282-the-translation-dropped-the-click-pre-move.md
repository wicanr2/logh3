# 282 — 重錄後分隊面板消失：旗標翻譯掉了每次點擊的 20 萬步前移

日期：2026-09-11
執行器：`logh3-oracle` `2e9dd3b`（舊收據錄在 `logh3-com-support` `ef5be47`）
狀態：**confirmed**（補回前移之後，`s3cmdfl3` 與舊收據**全畫面 640×480
逐位元組差 0**）

位置與內容與舊收據逐位元組相同。

| | 右側面板 |
|---|---|
| 舊收據 | 帝國軍　第13艦隊／楊威利／戰艦 2977／艦隊士氣值 99／艦隊行動 移動／光線砲 17862／飛彈 11908／戰鬥機 26793 |
| 新收據 | 帝國軍：輸入／宇宙曆：799 03 02／第５回合／勝利點：1／帝國軍：31／同盟軍：30／達希利 |

## 先排除「停在別的遊戲時點」

[`276`](276-what-the-executor-fix-changed-on-screen.md) 把重錄後對不上的
收據分成五種形狀，其中一種是「時序一改，同樣的步數落在別的時刻」。
這一份**不是**那一種：

- 點擊在第 1,395,000,000 道指令。`-dump-at` 在點擊後 10 萬～5,000 萬步
  之間取了 13 個時點（`1395100000`…`1445000000`），**每一張都與最終
  收據逐位元組相同**——畫面在點擊後 10 萬步就定住，之後 6,500 萬步
  一個位元組都沒變。
- 同一次跑加 `-watch-screen 100000 -screen-delta 2000`，1,394,000,000 到
  1,460,000,000 之間**只報告一次變化**（`#1395100000`，5,384 個像素），
  也就是點擊那一次重畫；沒有「畫了又被蓋回去」的第二次。
- `workplace/check/s3cmdfl3.bin`（上一輪獨立跑的第二份）與收據的
  `screen.bin` SHA-256 相同 → 新結果是決定性的，不是抽到的。

新舊收據的差異也不像「另一個局面」：全畫面差 5,670（sq3 是 5,754）個
像素，其中面板區以外只有 118（sq3 只有 14）個——小地圖一條 9 像素的
標記、y=241 那一列 13 個像素，以及 `s3cmdfl3` 上那個單位外框由色 5
變成色 2 的 16×16。戰場、選單、小地圖其餘部分完全一樣。

## 根因：兩份報告的滑鼠事件序列不同

probe 的報告會印出送進 `int 33h` 事件回呼的每一筆。兩份一比就露出來：

```
舊（ef5be47）  送出 108 次   #1394800000 旗標 01 於 (298,369)   ← 移動
                            #1395000000 旗標 02 於 (298,369)   ← 按下
                            #1398000000 旗標 04 於 (298,369)   ← 放開
新（2e9dd3b）  送出  88 次   #1395000000 旗標 01 於 (298,369)
                            #1395000000 旗標 02 於 (298,369)
                            #1398000000 旗標 04 於 (298,369)
```

**移動事件從「按下前 20 萬道指令」變成「與按下同一道指令」。**
一手來源在舊 probe 自己：

```go
// ef5be47:cmd/probe/main.go:227
// moveLead 是「移動事件比按下早多少道指令」。要留給程式把新位置處理完，
// 否則按下時它手上還是舊座標。
const moveLead = 200_000
```

舊版每一次腳本點擊都在 `at − moveLead` 送一次 `EvMove`，而且**不管座標
有沒有變都送**（直接寫 `d.Mouse.X/Y` 再 `MouseEvent`）。新版 main 的
`-clicks` 在同一道指令裡 `MoveMouse` ＋ `PressMouse`，而
`MoveMouse`（`internal/dos/bios.go:586`）**座標沒變就直接 return**——
這就是 108 → 88 少掉的那 20 筆。要前移得自己加 `-click-premove`，
而且它是**依輪詢次數**算的，不是步數。

`tools/scripts/translate_receipt_flags.py` 的 docstring 列了三處語法差異
（`-clicks` 的欄位順序與分隔符、`-cmdline` → `-args`、`-dump-mem` 的
位址寫法），**沒有提到 `moveLead`**——翻譯把它整個掉了。

## 驗證：補回前移，全畫面差 0

`-clicks` 沒有「只移動不按下」的寫法，但 `-mouse-x/-mouse-y/-mouse-at`
剛好能補**最後那一次**點擊的前移（這個手法 `docs/re/66` 的 `fleet1eB`
已經用過）。同一組旗標加上

```
-mouse-x 298 -mouse-y 369 -mouse-at 1394800000
```

跑出來的事件序列與舊版一字不差（01@1394800000、02@1395000000、
04@1398000000），畫面與舊收據 `47c708ec…`（640×480、307,200 bytes）
**全畫面差 0、面板區差 0**。

一起被排除掉的：舊收據不是被舊執行器的 MCB 改寫污染出來的。輸入
一樣的時候，修好的執行器把同一張畫面逐位元組重現得出來。

兩份收據都照這個方法重錄（`workplace/flags-new/*.txt` 各加
`-mouse-x`／`-mouse-y`／`-mouse-at 1394800000`，座標就是那一次點擊的座標），
`dosgolem 2e9dd3b`：

| 收據 | 重錄後 `screen.bin` SHA-256 | 與 `oracle-prev` 的原件 | 獨立第二跑 |
|---|---|---|---|
| `s3cmdfl3` | `47c708ec…` | 相同（全畫面 0） | `tools/check_receipts.sh` 0／0 |
| `s3cmdsq3` | `417b7740…` | 相同（全畫面 0） | `tools/check_receipts.sh` 0／0 |

`internal/screen.TestUnitPanelMatchesOracle` 兩張各 **0／20,480**，
`TestCommandMenuMatchesOracle` 三張照樣 0。

## 順帶量到的：分隊面板是移動事件帶起來的

`docs/re/117`／`docs/spec/023` 寫的是「點下去的同時右側換成分隊面板」。
這一輪的對照把它切開了：**按下**照樣開出艦隊選單（移動／戰鬥／索敵，
框與內容逐位元組相同），但移動與按下同一道指令時**面板不換**。
面板要的是先有一次純移動事件——與 [`277`](277-region-panel-follows-the-cursor.md)
量到的左下角星域摘要同一個形狀（跟著游標，不是跟著選取）。

證據等級 `strong inference`：目前只證明「移動事件與按下分開」是必要的，
還沒證明面板讀的是游標底下那一格（沒有量過「游標移到別的分隊上、
不按下」會怎樣）。remake 現在把面板綁在「選單開著」上
（`internal/game.unitPanelView`），兩份收據都對得上，先不動。

## 還有多少份受影響

`workplace/receipt-triage.json` 裡 149 份對不上的收據，差異七成以上落在
右側面板 (480,242)–(607,401) 的有 **12 份**：

```
s3cmdfl3 5,670   s3cmdsq3 5,754   s3cmdsq3v 5,754   s3cmdoff 5,712
s3cmdface 5,764  s3cmdrange 5,764 s3cmd4 4,984      s3rec137 5,754
s3form 5,814     s3msg 5,794      s3plinfo 4,526    decwatch2 268
```

這一輪只修了 `s3cmdfl3`／`s3cmdsq3` 兩份（`workplace/flags-new/*.txt` 各
加三個旗標）。其餘十份與「22 份只差游標位置」那一批
（`276` 的形狀一）很可能同源，但**沒有逐份驗過，不當成已知**。

**翻譯腳本本身沒有改。** 讓它自動補前移等於改掉全部 455 份的旗標，
那要連帶重錄一遍——是父層決策，留給使用者裁。腳本只加了一道保護：
`flags-new/<批次>.txt` 已經存在而且內容與這次翻出來的不同時**不覆蓋**，
印一行請人確認（要蓋掉用 `--force`），免得手補的前移被下一次 `--all`
無聲洗掉。

## 2026-10-03補證

[研究389](389-battle-input-display.md)補了本篇缺少的正常純移動反例。
移入另一己方分隊會換摘要，同分隊保持，移至空白或右面板恢復戰場摘要。
五組原版獨立雙跑及IDA資料流支持這個限定觸發；不追認本篇未重跑的其餘舊收據。
