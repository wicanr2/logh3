# 112 — 「資料」點一列開出來的艦隊詳細資料

`docs/re/111` 解完「資料」那張表之後，記憶體裡還有一組沒被用到的字串
（「指揮官 %s%s」「等級 %2d　經驗值 %6lu」「副官」「艦隊士氣值　統率力…」）。
這一輪確認它們屬於**點表上某一列開出來的下一層**，並把版面量出來。

## 怎麼走到

收據 `s3data` 的序列，最後再點一下表上的第一列（滑鼠 `200,90` ＝
畫面 `(200,130)`），跑到第 1,250,000,000 步：收據 `s3detail`。

## 版面（量自 `s3detail`）

- **視窗與「資料」同一個**：外框 (20,64)–(459,414)，內層面板
  (36,84)–(443,394)。所以它是換掉表格那一層，不是另開一個視窗。
- **頭像** (355,102)–(426,194)，72 × 93。
- **文字十四列，列距 20**：y ＝ 102、122、142、…、362，
  與表格那一層的列距相同。
- **三欄**：標籤 x ＝ 48／176／304，數值靠右對齊到 x ＝ 160／288／416。
  提督與副官那幾行的名字從 x ＝ 112 起。
- 右半的小地圖與狀態欄照舊不動。

與「資料」那一層逐像素比，改變的範圍是 x 32–519、y 80–399——
比視窗還寬，因為頭像那一塊壓到了視窗右緣之外。

## 數值的顏色：色 5 ＝ 副官在那一項比提督高

十二個數值裡有**五個是色 5**（光線砲 101、巡航速度 26、戰鬥機 98、
戰鬥速度 16、占領 94），其餘色 7。

這支艦隊的提督是第 12 號（舒坦梅茲）、副官第 28 號（奈西巴哈）。
把 `docs/internals/33` 那 11 項的來源位移逐一取出來比：

| 項 | 位移 | 提督 | 副官 | 合成 | 副官較高 |
|---:|---:|---:|---:|---:|:-:|
| 0 | +15 | 97 | 105 | 101 | ✔ |
| 1 | +16 | 94 | 92 | 94 | |
| 2 | +17 | 98 | 99 | 98 | ✔ |
| 3 | +19 | 91 | 97 | 94 | ✔ |
| 4 | +18 | 105 | 89 | 105 | |
| 5 | +12 | 95 | 97 | 97 | ✔ |
| 6 | +13 | 97 | 87 | 97 | |
| 7 | +20 | 81 | 85 | 85 | ✔ |
| 8 | +22 | 105 | 105 | 105 | |
| 9 | +23 | 106 | 105 | 106 | |
| 10 | +14 | 102 | 100 | 102 | |

**副官較高的剛好五項，畫面上色 5 的剛好五個。** 而且三個值直接對上：
101（第 0 項）、98（第 2 項）、94（第 3 項）。

第 2 項值得注意：副官 99 > 提督 98，但前五項是「取一半」
（`(98+99)/2 ＝ 98`），**合成值與提督相同、顏色仍然變了**——所以
判準是「副官的值有沒有比提督高」，不是「合成值有沒有變」。

**下一節把它從反組譯讀出來了**，不再是推論。

## 十二個欄位各從哪裡來（confirmed，反組譯 `0x14BA1`–`0x14F60`）

格式字串 `\x03[%d, %3u` 的第一個參數就是**顏色**——顏色是算出來當
參數傳進去的，不是繪圖層自己判斷的。每一個數值前面都有同一段：

```
cmp  word [bp+24h],0        ; 有沒有副官（艦隊 +0x05 ≠ FF）
jz   → 用色 7
les  bx,[bp+0Eh] / mov al, es:[bx+X]    ; 副官記錄的第 X 個位移
les  di,[bp+0Ah] / mov cl, es:[di+X]    ; 提督記錄的同一個位移
cmp  al,cl
jbe  → 色 7      否則 → 色 5
or   al,90h
```

所以**色 5 ＝ 副官在那一項比提督高**（定案，不再是推論）。
`or al,90h` 是屬性位元，與顏色無關。

數值本身逐一讀出來：

| 畫面 | 來源 | 顏色比的提督位移 | 收據的值 |
|---|---|---|---:|
| 艦隊士氣值 | 艦隊 `+0x3C` | （沒有顏色參數）| 100 |
| 回轉速度 | 艦隊 `+0x4D` | `+13` | 11 |
| 巡航速度 | 艦隊 `+0x4E` | `+12` | 26（色 5）|
| 戰鬥速度 | 艦隊 `+0x4F` | `+12` | 16（色 5）|
| 統率力 | **提督 `+0x0B`** | （沒有顏色參數）| 93 |
| 運用 | 艦隊 `+0x46` | `+23` | 106 |
| 營運 | 艦隊 `+0x47` | `+14` | 102 |
| 占領 | 艦隊 `+0x40` | `+19` | 94（色 5）|
| 光線砲 | 艦隊 `+0x3D` | `+15` | 101（色 5）|
| 飛彈 | 艦隊 `+0x3E` | `+16` | 94 |
| 戰鬥機 | 艦隊 `+0x3F` | `+17` | 98（色 5）|
| 防禦 | 艦隊 `+0x41` | `+18` | 105 |

八個能力欄的「艦隊位移 ↔ 提督位移」完全符合
`rules.AbilitySources`（`{15,16,17,19,18,12,13,20,22,23,14}` 對
`+0x3D`–`+0x47`）：`+0x3D`←15、`+0x3E`←16、`+0x3F`←17、`+0x40`←19、
`+0x41`←18、`+0x46`←23、`+0x47`←14。沒有出現在這張畫面上的是
`+0x42`←12、`+0x43`←13、`+0x44`←20、`+0x45`←22——而 `+0x42` 與
`+0x43` 正是三個速度的顏色比的那兩個位移，也就是**速度是從那兩項
算出來的**（與 `docs/internals/33` 的「`+0x4E` 由艦隊能力 `+0x42` 算」
一致）。

兩件順帶的更正（已寫進 `docs/internals/33`）：

- 艦隊記錄 `+0x3C` 是**艦隊士氣值**，不是「機動力」。它被寫死成 100
  沒錯，但那是士氣的初值。
- `+0x4D`／`+0x4E`／`+0x4F` 是**回轉速度／巡航速度／戰鬥速度**。
  `+0x4E` 同時就是「一回合的步數」——同一個數字，這裡是它在畫面上
  的名字。

下半段（部隊那五行：艦種名、艘數、四組裝備的現有／最大與單位）
還沒對到艦艇記錄的欄位。

## 下半段那五行（confirmed，反組譯 `0x15030`–`0x152D0`）

格式字串：

```
ds:3924  '  %-8s                %4d／  %4d隻'
ds:3947  '部隊士氣值 %3u'      ds:3956  '  %-14s  %6ld／%6ld門'
ds:398F  '最高速度   %3u'      ds:399E  '  %-14s  %6ld／%6ld發'
ds:39D7  '戰鬥速度   %3u'      ds:39E6  '        發射裝置  %6ld／%6ld座'
ds:3A28  '耐久力     %3u'      ds:3A37  '  %-14s  %6ld／%6ld架'
```

沒有搭載那一項時改印 `  光線砲　　非搭載`／`  飛彈　　非搭載`／
`  艦載機　　非搭載`。

| 畫面 | 來源 | 收據（艦種 0 戰艦）|
|---|---|---:|
| 艦種名 | 遠指標表 `ds:613A` ＋ 艦種 × 4 | 戰艦 |
| 艘數 | 艦艇 `+0x08`／`+0x0A` | 3000／3000 |
| 部隊士氣值 | **艦艇 `+0x06`**（與表上那一欄同一個欄位）| 100 |
| 最高速度 | 艦種列 `+0x06` | 30 |
| 戰鬥速度 | 艦種列 `+0x07` | 14 |
| 耐久力 | **（艦種列 word `+0x16` ＋ word `+0x18`）÷ 2** | (100＋95)÷2 ＝ 97 |
| 第一組（門）| 名字索引 `+0x0A`、乘數 `+0x0B` | 索引 0、×6 → 18000 |
| 第二組（發）| 名字索引 `+0x0E`、乘數 `+0x10` | 索引 5、×4 → 12000 |
| 發射裝置（座）| 搭載旗標同 `+0x0E`、乘數 `+0x0F` | ×2 → 6000 |
| 艦載機（架）| 名字索引 `+0x12`、乘數 `+0x13` | 索引 10、×12 → 36000 |

- 數量是 **艘數 × 乘數**，用 `3CC9:0009` 那支 32 位元乘法算的
  （所以格式是 `%6ld`）。
- 名字索引 `0xFF` ＝ 沒搭載。
- 武器名同樣是遠指標表，在 `ds:5162`，索引 × 4。
- 耐久力那兩個 word 就是 `docs/internals/40` 記的「橢圓的兩個半軸」
  （艦種 0 是 100／95）——**畫面上的耐久力是兩個半軸的平均**。

## remake

「點在標籤以外」→ 關掉整張「資料」。上下半段的來源都對完了，

## 點第 N 列開的就是第 N 個分隊

收據 `s3detail_row2`：同一條序列，最後一下改點滑鼠 `200,130`
（＝畫面 y 170 ＝ 表上第 2 列）。開出來的下半段是**第３部隊**，
其餘（指揮官、副官、十二個數值）與第 0 列那一份完全相同。
所以列號直接對到分隊序號，上半段是整支艦隊共用的。

## 在明細裡點一下 → 整個「資料」關掉

收據 `s3detail_back`：點開第 0 列的明細之後，再點一下滑鼠 `200,200`
（＝畫面 (200,240)，落在視窗裡）。結果**兩層一起關掉、直接回到戰場**
——不是退回上一層的表。右鍵才是一層一層退。

## 順帶撞見一個沒見過的顯示模式

`s3detail_back` 收尾那張畫面的戰場**不是原來的樣子**：

- 戰場整片黑底、只有虛線格線；
- 單位畫成**艦種字母**（Ｂ／Ｃ）加上一個外框，旗艦那格是 `13`；
- 右側狀態欄整塊換掉，印的是選中那個分隊的資料：
  「帝國軍　第13艦隊／第５部隊／戰艦 3000／部隊士氣值 100／
  艦隊行動 待命／光線砲 18000／飛彈 12000／戰鬥機 36000」。

進「資料」之前（收據 `s3data0`）戰場還是正常的圖塊與 sprite，
所以這個模式是「資料」帶進去的。**整張還沒量**——版面、字母怎麼擺、
右側面板的欄位、怎麼切回正常模式都未解。remake 目前只把
「點一下關掉整個『資料』」照做，不畫這個模式。
