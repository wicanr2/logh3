# 195 — `2E54:005D` 沒有決定每一支，還有一道過濾沒讀到

把各層串成一個回合（`ai.Turn`）之後，一支冒煙測試抓到一個落差。

## 落差

原版 `2E54:005D` 逐艦隊跑一趟，把 `+0x79` 從 `0xFF` 改寫：
`2E54:16F5` 回 1 → `+0x79 = 3`，回 0 → 走 `2E54:1955`、`+0x79 = 0`
（`docs/internals/54`）。**兩條分支都不再是 `0xFF`。**

而 `2E54:143F` 挑候選的第三個條件就是 `+0x79 == 0xFF`
（`docs/re/168`）。所以**只要 `2E54:005D` 決定了一支，後面五個階段就
再也挑不到它**。

如果它決定了每一支，五個階段就永遠沒有候選——但收據不是這樣。

## 收據說的

`s3aicomp` 跑完（`docs/re/176`）同盟六支艦隊的 `+0x79`：

| 槽 | `+0x79` | 誰寫的 |
|---|---|---|
| 16、17、29、30 | **0** | `2E54:005D`（沒事做那一條）|
| 28、31 | **1** | 後面的階段（`2E54:0C27`／`0C83`／`0DE3` 只寫 1）|

**28 與 31 是被後面的階段挑走的**，代表 `2E54:005D` 跑完之後它們的
`+0x79` 還是 `0xFF`——**那一趟並沒有決定每一支**。

## 所以還有一道過濾

`docs/re/79` 的反組譯裡看得到一條早退：
`if +0x08 == 4 → +0x79 = 0、ds:D60E++、下一支`。但那是**決定**，不是跳過。
真正讓 28／31 保持 `0xFF` 的條件還沒讀出來——可能在
`2E54:005D` 的迴圈開頭（某個 `continue`），也可能 `2E54:16F5` 有第三種
傳回值。

`ds:D60E = 5` 也是一條線索：同盟那一趟有六支在用的艦隊，決定計數器卻是
**5**——**剛好少一支**。若 `2E54:005D` 每決定一支就 `++`，那就是有一支
被跳過了；但被後面階段寫成 1 的有**兩支**，所以「跳過的那一支」與
「後面挑走的兩支」對不起來，這裡還缺一塊。

## 目前的處理

`ai.Turn` 照已知的行為做——**兩條分支都標成已決定**，並在程式碼註解與
這一篇裡寫明後果：在那道過濾讀出來之前，`Turn` 的階段二／三／五
實務上挑不到候選。**不猜一個過濾條件把它「修好」**，那會讓 remake 的
行為看起來合理但對不上原版。

## 下一步

對 `2E54:005D` 設 `-regs-at`，在 `s3aicomp` 那個局面上逐支看它怎麼走
——尤其是槽 28 與 31。機器現在 load 46，這一跑與另外兩跑一起排著。
