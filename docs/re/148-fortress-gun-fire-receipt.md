# 要塞砲開火的收據：17 支分隊、艘數逐一相同

[`docs/re/147`](147-fortress-gun-damage.md) 把算式讀完了，但整條鏈都是
靜態讀出來的。這一輪把它對上收據。

## 兩次執行比不出來

第一版的做法是「跑兩次，只差 `+0x45`（0 ＝ 不打、3 ＝ 打），比最後的
記憶體」。結果 69,619 個 byte 不同，兩個計分器**一個漲一個跌**——
跌代表兩次執行走的是完全不同的時間線。

成因在 `20B4:019B`：

```
（打行星的目標挑選，逐支艦隊）
    ...近距離那一段：艦隊[+0x70] |= 1
    if 距離 > 門檻: 跳過
    if 行星[+0x12] != 0 且 行星[+0x45] == 3: 跳過      ; ★
    艦隊[+0x70] |= 2
```

**一座瞄好的要塞砲會讓敵方艦隊那一回合不對這顆行星發動攻擊**（較遠的
那個距離帶）。所以 `+0x45` 不只是「這一步要不要開火」，它從回合的第二
個階段就開始影響戰術 AI，兩次執行從那裡分岔。

改成**同一次執行、在要塞砲那一步的前後各倒一份**（`-dump-mem-at`）。
時點用 `-regs-at 181B:03BA,181B:03BF` 量：呼叫在第 1,483,866,589 道指令，
回來在第 2,008,051,438 道——中間 5.24 億道都是開火動畫。

## 收據

`s3gunfire2`：S3、第 63 顆行星（雷奧米爾）poke 成有要塞、座標移到
(1360, 700)、防衛力上限留 12800、`+0x45` ← 3、`+0x50` ← 64（正下方）。
前後兩份 1 MB 傾印在 `workplace/gunpre.bin`／`gunpost.bin`。

`internal/rules.TestFortressGunMatchesOracle` 驗到：

| 項目 | 結果 |
|---|---|
| 候選集合裡每一支的射程判定 | **33 支逐一相同**（17 支在內、16 支在外）|
| 每一支扣掉的艘數 | **17 支逐一相同**，連兩個 `rand()` 都對上 |
| 艦艇 `+0x0C` | 17 支逐一相同（掉 `實扣² ÷ 滿編`）|
| 艦艇 `+0x0E`／`+0x12` | 17 支逐一相同（按剩餘比例縮減）|
| 計分器 `ds:8FE4`／`ds:8FEC` | 各 ＋989 ＝ **逐支** `⌊實扣 ÷ 20⌋` 的和（總和再除會得到 996）|

亂數怎麼接上：傾印裡有 `ds:94DC` 的種子，而那兩個 `rand()` 是進了
`2264:0EE3` 才取的，順序完全由排序決定（帝國的比較函式 `2264:052F`：
艦隊編號遞減、`+0x03` 遞增、索引遞增）。從種子往下走，17 支的兩個
亂數逐一對上。

`+0x3C` 的三個值也順帶釘住了：**0xFF ＝ 沒被列進候選、1 ＝ 在射程裡、
0 ＝ 是候選但在射程外**。第一版拿 `!= 0` 當「命中」，336 支全部算成命中。

## 差點對不上的那一支：`atan2(0, 0)` 回 64

17 支裡有一支（艦艇 135，艦種 1）站在**要塞正上方**，距離 0——那是
poke 行星座標時撞上去的。它被打光 3000 艘，而算出來只有 1602。

成因是 `2BE1:011D` 的邊界行為：它**只看 dx 是不是 0**，是就把比值當成
`0xFFFF` 去查反正切表，得到 64，dy 是多少都一樣——**包含 dy 也是 0**。
remake 的 `atan256` 在 (0,0) 早退回 0，於是防禦係數算成 55 而不是 50，
基準從 2400 掉到 2175，量從 3364（夾成 3000）掉到 1602。

改掉之後 17 支全對，其餘既有測試也全過。

## 可重用的規則

- **要比「某一步做了什麼」，就在同一次執行的前後各倒一份；不要跑兩次
  去比。** 兩次執行只要有任何一個旗標影響到更早的階段，差異就會擴散
  到整場。這裡的旗標甚至看起來只跟第五個階段有關。
- **時點用 `-regs-at` 量，不要猜。** 呼叫與回來的步數差了五億道指令
  （動畫），猜一個「夠晚」的步數會夾到後面的階段。
- **邊界值的早退要對著原版看。** `atan2(0,0)` 在數學上沒有定義，
  兩邊各自選一個答案就會差；而它只在「單位正好站在中心」時才發生，
  平常的測試碰不到。
