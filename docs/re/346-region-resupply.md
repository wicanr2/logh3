## 二、骨架

```
1AAB:0FAF(星域編號):
    r = ds:A79C + 星域編號×126
    if r[+0x12] == 2: return                     ; 無主星域直接回
    1AAB:1235(星域編號)                           ; ① 修護艦重置（不分陣營）
    ds:8F1D = r[+0x12]                            ; 這一格的擁有者
    清單 = 297B:131C(1, 星域編號)                 ; ② 擁有者停在這一格的艦隊
    2703:12EB(r)                                  ; ③ 從行星重算這一格的存量
    for 艦種 in 0..6:                             ; ④
        存量 = &r[+0x30 + 擁有者×28 + 艦種×4]      ;   32 位元
        候選 = 1AAB:13BE(艦種, 清單)               ;   這些艦隊裡同艦種的編制組
        sort(候選, 1AAB:145F)
        for c in 候選:
            if 存量 == 0: break
            給 = min(c.滿編 − c.現有, 存量)
            if 給 == 0: continue
            c.現有 += 給
            c.修理上限 += min(給, c.滿編 − c.修理上限)
            存量 -= 給
            舊飛彈, 舊艦載機 = c.+0x0E, c.+0x12
            2703:14CF(c, 給)                       ;   覆寫兩格（`docs/re/345`）
            c.+0x0E += 舊飛彈；c.+0x12 += 舊艦載機   ;   呼叫端自己加回舊值
    2703:0540(星域編號)                            ; ⑤ 存量按經濟力分回行星
    for f in 清單: 1261:0067(f, 1)                 ; ⑥ 士氣重算，當場印報告
    ds:8F1D = 0xFF
```

## 三、挑哪些艦隊：只看所在星域與陣營

`297B:131C(旗標, 星域, buf)` 先收全部 32 格非空的艦隊，再過兩道濾網：

- `297B:13C3`：`艦隊[+0x06]`（所在星域）＝＝這一格；
- `297B:142A`：`艦隊[+0x01]`（陣營）＝＝`ds:8F1D`，只在 `旗標&1` 時跑。

**兩道都沒有檢查 `+0x08`（移動狀態）。** 回合跑到這一步時艦隊移動階段已經
結束，所以條件實際上是「這一回合結束時人在這一格的擁有者艦隊」，不是字面的
「停駐」。本輪樣本的 `+0x08` 剛好是 5，沒有另外造一個 `+0x08 ≠ 5` 的局面驗，
**這一條標 strong inference**。

`1AAB:1235` 傳 `旗標 = 0`，所以它掃的是**這一格所有陣營**的艦隊。

## 四、修護艦重置（`1AAB:1286`）

```
1AAB:1286(艦隊):
    for j in 0..艦隊[+0x0F)-1:
        船 = 池[艦隊[+0x10+4j] 的 word]
        if 船[+0x04] != 6: continue        ; 只處理修護艦
        船[+0x10](word) = 0
        船[+0x0E](word) = 船[+0x08]        ; 32 位元欄位 ← 現有艘數
```

**這關掉 `docs/re/131` 留的「修理艦 `+0x0E` 初值哪來的」**：艦種 6 在艦種表
的兩個係數都是 0（`docs/re/345`），所以建立時那一格是 0；每回合的這一支才把它
設成「目前有幾艘修護艦」。`docs/re/131` 量到的 974／1000 就是某次執行完的快照。

## 五、候選的優先序（`1AAB:145F`）

比較兩個候選（艦艇池索引），依序比：

1. `+0x03 == 0` 的優先——**旗艦那一組先拿**；
2. `+0x08`（現有艘數）**由小到大**——越殘破的先補；
3. `+0x01`（陣營）——同一次呼叫裡必然相同，死代碼；
4. `+0x03`（分隊序號）由小到大，最終 tie-break。

**沒有按比例分配**：照這個順序一組一組拿 `給 = min(滿編 − 現有, 存量)`，
存量歸零就 `break` 掉整個艦種。存量夠的話每一組都補到滿編。

`1AAB:13BE` 收候選時**不篩掉已滿編的**（滿編的組 `給` 算出來是 0，跳過即可），
也**不會碰索敵分遣隊**——它只走 `+0x10` 起的十組編制陣列，外層迴圈也只跑艦種 0–6。

## 六、執行期驗證

局面用 `-poke` 造：帝國第 1 艦隊（旗艦那一組艦種 0，停在首都星域 0）
`+0x00 ← 0x01`（士氣低落）、`+0x3C ← 40`、艦艇池 #0 的 `+0x08 ← 100`
（滿編仍是 3000）。命中在 `#432905951`，`[bp+0]` ＝ 0 確認處理的是星域 0。

| 對象 | 位移 | 補充前 | 補充後 |
|---|---|---:|---:|
| 星域 0 | `+0x30`（艦種 0／陣營 0 存量）| 75000 | **72100** |
| 艦艇 #0 | `+0x08` 現有艘數 | 100 | **3000** |
| 艦隊槽 0 | `+0x00` 旗標 | `0x01`（bit0 低落）| `0x04`（bit2 待印、bit0 已清）|
| 艦隊槽 0 | `+0x3C` 士氣 | 40 | **100** |

`需要 ＝ 3000 − 100 ＝ 2900`、`給 ＝ min(2900, 75000) ＝ 2900`，存量的 −2900
與艘數的 ＋2900 完全對上。星域 0 除了 `+0x30` 那四個位元組之外 122 bytes 全不動
——與「`2703:0590` 只寫行星欄位、不再倒扣 `region[+0x30]`」一致
（`docs/re/273` 留的疑點，本輪確認）。

`+0x00` 停在 `0x04` 而不是 `0x00`，證實這個時間點 `1261:0067` 已經跑完
`1261:032B`（重算）但還沒跑到 `1261:0104`（印完清 bit2）——當時卡在報告視窗的
模態等待裡。`docs/re/333` 的骨架因此釘到位元組層級。

**順便補上 `docs/re/273` §四留的座標**：那份文件記的「`2703:0540` 還有兩處
呼叫點 `0x1BC90` 與 `0x2B183` 沒查」，`0x1BC90` 就是本文的 `1AAB:0FAF +11E0`。
`0x2B183` 仍未查。

## 七、報告的條件

`1261:0067(f, 1)` 的內容 `docs/re/333` §三已解，remake 也已經有
（`rules.RecomputeMorale`／`strategicMorale`、`game.moraleReports`）；本輪只是
把它接到這個呼叫點。具體到補充的情境：**補充把某一組的 `+0x08` 抬上去，讓
重算出的士氣 `+0x3C ≥ 50`，而補充前 bit0 是 1（低落）** —— 兩者同時成立就設
bit2，旗標 ＝ 1 於是當場印「士氣值已經恢復，可以進行戰鬥。」。

## 還沒解的

- **多出來的 108600 是誰加的**：兩格存量的增量比 `2703:14CF` 的算式各多 108600，
  而那正是星域 0 的 `+0x68`／`+0x70`（帝國飛彈與艦載機存量，＝ 瓦爾哈拉經濟力
  81300 ＋ 防衛力 27300）。所以有一支把星域層的飛彈／艦載機整批補給進了那一組
  艦艇。最可能是 `1930:1572`（排在 `0FAF` 之前、同一格序列、還沒讀，`1930` 是
  補給那一段）。詳見 `docs/re/345` 末節。
- `+0x0C`（修理上限）抬升的算式是位元組層級的 proven，但樣本進來時它已經
  等於滿編，只驗到「夾住不超過滿編」這個退化情形。
- 濾網不看 `+0x08` 這件事只有 strong inference（見 §三）。
- `1930:1572`（序列裡排在 `0FAF` 之前那一支）與 `0374:0919`／`0AF2` 都沒讀。
