# RE 78 — 按下「實行」之後那條呼叫鏈

執行器 dosgolem-logh3 `20e4583`。材料是 `s2ai0` 的整份 1 MB dump，
工具是 `tools/scripts/callchain.py`（往上追呼叫者）與
`tools/scripts/ida_trace.py`（在段傾印上反組譯）。

起點是 `docs/re/77` 找到的移動函式，一路往上：

```
04F8:006A （函式 04FEA）
  → 06E8:000B （06E8B）
    → 06E8:00A4 （06F24）
      → 06E8:01E8 （07068）   ← 命令分派：switch 五個 case
        → 04F8:05ED （0556D）  ← 被四個 case 各呼叫一次
          → 056A:03E0 （05A80） ＝ **32 筆艦隊逐一跑移動**
            → 113A:0350 → 113A:047D
```

## 最底層：32 筆艦隊的迴圈（`056A:03E0`）

```
5AAF  mov word [bp+02],0C074h   ; 表在 ds:C074
5AB4  mov [bp+04],ds
5AB7  mov byte [bp+00],0        ; i = 0
5ABB  cmp byte [bp+00],20h      ; i < 32
5AC1  les bx,[bp+02]
5AC4  cmp byte es:[bx+4],0FFh   ; +0x04 是 FF 就跳過
5AD8  call far 113A:0350        ; 這一筆要不要動
5AE0  mov [bp+01],al            ; 上一筆的回值帶進下一筆
5AE6  add word [bp+02],7Ah      ; 下一筆 ＝ +122
```

把 `docs/internals/33` 記的三件事一次全證實了：**表在 `ds:C074`、
32 筆、每筆 122 bytes、`+0x04` 是 `0xFF` 代表沒在用**。

## 分派那一層（`06E8:01E8`）＝ 點擊分派

```
01F5  push [bp+12h] / [bp+10h] / ds:0BEE / ds:9518
0205  call far 37A9:01F9        ; ★ 拿座標去找視窗，回 ax:bx（far ptr）
0216  兩個都 0 → 沒點到任何視窗，什麼都不做
021D  mov bl,es:[bx+5]          ; 視窗結構的 +5
0223  cmp bx,4  ja 預設          ; 0–4 五個 case
022A  jmp [跳表 + bx*2]
```

`37A9:01F9` 進去第一件事就是 `call far 341B:039D`——那正是
`docs/re/24` 記的**視窗命中測試**（`tools/scripts/window_list.py` 的
說明就是照它寫的），接著再呼叫 `341B:044A` 把座標換算成格子。
所以這一層是**「點到哪個視窗」的分派**，不是命令佇列。

這也說得通：「實行」本來就是點出來的（系統指令 → 實行），
所以整條鏈是**點擊 → 分派 → 跑一趟 32 筆艦隊**。

五個 case 裡有四個長得一模一樣，只差一個常數 0／1／2／3：

```
xor ax,ax            (或 mov al,1 / 2 / 3)
mov [8F1F],al        ; ★ 階段編號
mov bl,[8F1E]
mov [bx+8F29],al     ; ★ 每個玩家一份的同一個編號
call far 04F8:05ED   ; → 艦隊移動那一趟
```

所以按下去之後是：**照點到的視窗設一個編號（0–3），
再跑一趟 32 筆艦隊的處理**。

## 這條鏈給後續什麼

- `ds:8F1F` 是那個編號、`ds:8F29` 起是「每個玩家一份」的同一份東西，
  `ds:8F1E` 是索引（`docs/re/48` 注意過 `ds:8F1D` 與玩家有關）。
  四個 case 只差常數 0–3，所以**同一趟艦隊處理跑得出四種模式**。
- 艦隊處理這一趟是**每一筆都跑**（32 筆全掃），不是只處理被點的那一支
  ——電腦的艦隊也會經過 `113A:0350`。它們之所以不動，是 `+0x08` 是 5
  （`docs/re/77`），**不是因為沒被處理到**。

## 還沒做

- 四個編號 0–3 分別對應什麼（`ds:8F1F` 被誰讀）。
- `ds:9518`／`ds:0BEE` 是什麼（傳給命中測試的兩個位址）。
- **電腦在哪裡寫別人的 `+0x07`／`+0x08`**：那才是 AI 下命令的地方。
  最直接的作法是對艦隊表整段設監看、跑一個**電腦真的會動**的局面
  （先找到 `+0x08` 不是 5 的敵方艦隊），看誰寫那兩個欄位。
  這條解出來，`docs/spec/017` 的 `Original` 那一欄才填得起來。

## 誰會寫「目的地」與「動不動」——AI 的候選名單

與其再跑十分鐘的收據，直接掃位元組找會寫 `+0x07`／`+0x08` 的指令
（`tools/scripts/find_writers.py`）。`+0x08` 的寫入點很少，是最好的篩子：

| 位址 | 寫的值 | 同一帶有沒有一起寫 `+0x07` |
|---|---|---|
| `0F095` | 5 | 有（`0F09A`）|
| `0F0FC` | 2 | 有（`0F101`）|
| `11A52`／`11B41` | 5 | 有（`11A57`／`11B46` 寫 `0xFF`）|
| `298C8` | 5 | — |
| `2E656` | 3 | 有（`2E65F`）|
| `2E96A` | 5 | 有（`2E96F`）|
| `2E9AC`／`2EA10` | `al` | — |

`+0x08` 目前在 dump 裡只看過 0、1、5，但程式還會寫 2 與 3
——**還有兩種狀態沒見過**。

### `0F095`／`0F09A` 是玩家那一側

往上追（`callchain.py`）落在 `0DEA:1037`，那一支開頭把五個旗標
（`ds:121B0` 起 `+5A`／`+60`／`+66`／`+6C`／`+72`）設成 1，接著

```
105C  al = 艦隊的 +0x06（所在星域）
1062  cx = 7Eh                       ; 星域記錄 126
1069  si = A79Ch + 星域×126
1076  test byte es:[si+13h], 6       ; ★ 星域記錄的 +0x13 的 bit1／bit2
107F  al = es:[si+12h]（擁有者）
1086  cl = 艦隊的 +0x01（陣營）
108A  cmp al,cl                      ; 這一格是不是自己的
1090  不是的話把其中四個旗標清成 0
109F  test byte es:[bx],1            ; 艦隊記錄的 +0x00 bit0
```

五個旗標＝**這支艦隊現在能下哪幾種命令**（能／不能，一項一個 byte），
判斷依據是所在星域的擁有者與 `+0x13`。所以這一組是**玩家的艦隊命令
選單**，不是 AI。

`+0x13` 又出現了一次：`docs/re/77` 量到打起來時它從 8 變 12、
接管中立星域時變 24，這裡用 `& 6` 去測——那兩個 bit 是「這裡有事」。
