# 166 — 攻勢的分配：派去「集結點」，不是直接派到目標

`docs/re/165` 把 `+0x07` 的寫入點夾到兩處。這一輪兩處都讀了。

## `2E54:03C3`：不是它

那一支的 `+0x07` 寫的是 `al`，而 `al` 從 `cmp es:[bx+4], 0FFh` 之後
一直是 `0FFh`——**「已經在首都的艦隊就地待命」**（`+0x08 = 5`、
`+0x07 = 0FFh`、`+0x79 = 3`、`ds:D60E++`）。

不過它順手證實了一件事：

```
起點 = (ds:8F1D == 0) ? 0 : 16
迴圈 16 次
```

**艦隊槽是固定分陣營的：0–15 帝國、16–31 同盟**（`ds:C074`，一筆 122）。
拿 `dm_pre.bin` 驗，32 個槽的 `+0x01` 正好是前 16 個 0、後 16 個 1，
沒在用的是 `0xFF`。

## `2E54:0CD2`：這一支才是分配

```
2E54:0CD2(目標星域 [bp+48], 艦隊指標陣列 [bp+42], 幾支 [bp+46], …)

    ; 一、挑集結點
    鄰居 = 2B99:03D9(&清單, 目標星域, ds:8F1D)
    我方首都 = 3982:0329(ds:8F1D)
    集結點 = 鄰居裡「擁有者 ＝ ds:8F1D」而且
             2B99:028F(鄰居, 我方首都, ds:8F1D) 最小的那一格

    ; 二、逐支派
    對陣列裡的每一支艦隊：
        d = 2B99:028F(艦隊[+0x06], 集結點, 艦隊[+0x01])
        若 d >= 0x800：跳過                    ; 走不到
        艦隊[+0x08] = (艦隊[+0x06] == 我方首都) ? 3 : 0
        艦隊[+0x07] = 集結點
        艦隊[+0x79] = 0
```

**目的地是集結點，不是目標本身。** 集結點的挑法與回防
（`docs/re/164`）用的是同一組工具——`2B99:03D9` 取鄰居、`2B99:028F`
量到首都幾步——差別只在**以誰的鄰居為候選**：回防看**自己腳下**那一格
的鄰居，攻勢看**目標**那一格的鄰居。所以攻勢是「先到目標旁邊自己的
地盤集合」。

`2B99:028F` 回 `>= 0x800` 代表走不到，那一支就不派。

`+0x08` 這裡出現第三個值：**3**（在首都出發時用），與 0（移動）、
5（不動）並列（`docs/internals/33`、`docs/re/79`）。

## 還沒解

`2E54:0CD2` 的呼叫者——**目標星域與那一串艦隊是誰選的**。
`docs/re/165` 的形狀（算缺口 → 依缺口排序）指向同一趟裡的排序結果，
但呼叫點還沒找。
