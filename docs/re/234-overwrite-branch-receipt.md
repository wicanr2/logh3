# 234 — 「覆蓋同槽」那一條有收據；`docs/re/232` 的「被刷回來」是誤判

`docs/re/232` 說艦隊槽 23 的組 `[2]` 注入「沒有存活」，推論成
「有東西會把 `[2]` 從別處刷回來」。**那是把傾印時點看錯了。**

## 監看直接問

同一條輸入序列，同一個注入，加一條監看：

```
-poke 'lin:616B4@230000000=02' -watch 616B4-616B4
```

```
[watch] #213289998 616B4: FF → 03  ← 0FF4:12BB   ; 建艦隊填 [2]
[watch] #213292708 616B4: 03 → 00  ← 3C6A:013F   ; qsort 交換
[watch] #213293036 616B4: 00 → 03  ← 3C6A:0145   ; qsort 交換
[watch] #230000000 616B4: 03 → 02  ← 3765:00D3   ; 注入
[watch] #242632789 616B4: 02 → 03  ← 2D76:0BE5   ; ★
```

`2D76:0BE5` ＝ 線性 `0x2E345`，那是 `2D76:0A44` 裡的

```
26 88 44 02   mov es:[si+2], al        ; 組[2] = 最終艦種
```

`#242632789` 在 `2D76:0732` 進入（`#242631032`）之後 **1757 道指令**，
也就是**整補自己寫的**。

## 所以那一條分支其實觸發了

艦隊槽 23（提督 47，類別鍵 `0C`，編制 6／6 全滿），樣板第 1 格是 `(3,5)`：

```
a = 3（樣板直接給的）
2D76:0C4F(艦隊, 3, 5)：組2 的槽是 5、但 [2] 被改成 2 ≠ 3 → 回 2
編制已滿 → 但 n != 0，走覆蓋那一條：target = 2
2AD2:018C 拆掉組2 → 艘數還回星域
重建：0FF4:0E5A(星域20, 3) != 0 → 艦種 3，min(4000, 滿編 2000) = 2000
組2[2] = 3                                    ← 監看 #242632789 ✓
```

還回去與拿回來是同一個數，所以星域待命部隊前後相同；艦艇索引也一樣
（`2AD2:018C` 標成空槽之後 `2AD2:0029` 拿到同一格）。**傾印看不出來，
監看看得出來。**

## `docs/re/232` 錯在哪

`refit3` 的整補在 `#242631032`，而那一跑的「前」傾印取在 `#242800000`
——**晚了 169k 道指令**。兩份傾印都是整補之後的狀態，當然一模一樣。

會取錯是因為沿用了 `refit2` 的時點：`refit2` 的注入（改艘數）讓整補
延到 `#243072663`，`refit3` 的注入沒有改變執行路徑長度，整補留在
`#242631032`。**同一組時點對前一跑成立，對這一跑不成立。**

`docs/re/232` 記的另一半（「編制已滿要犧牲一組」）不受影響：那一條的
證據是艦隊槽 28 的 `[3]` 從 99 變回 10，而 99 是注入寫的、只有整補會改它。

## 對 remake

三條分支現在都有收據了。「覆蓋同槽」釘在
`TestRefitOverwritesWrongKindInSlot`。

**注入造出來的是「組 `[2]` ≠ 艦艇 `+0x04`」的人工狀態**，原版自己不會
產生；remake 的 `FleetGroup` 用單一 `Kind` 表示不到那個歧異，所以測試
用一致的狀態（艦種 2、滿編 4000）跑同一條分支——測的是「找到同槽但
艦種不同就覆蓋那一槽」，不是那個歧異本身。

## 一條方法

**「注入沒有存活」與「傾印取錯時點」長得一模一樣。** 判斷之前先問
「這份傾印真的在事件之前嗎」——步數是知道的，比對一下就好。
更穩的做法是**注入配監看**：監看會把「誰在什麼時候寫了什麼」直接說出來，
不必靠兩份傾印的差去推。

**注入改變執行路徑長度時，時點要跟著重算；沒改變時，沿用是對的。**
兩者都要驗，不能假設。
