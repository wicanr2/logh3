# 229 — 整補整條鏈讀完了，而且它只有 AI 會跑

`docs/re/228` 留的四支加上還艘數那一支都讀了。整補從此是一條封閉的鏈，
只剩 `297B:03EB` 迴圈之後那一小段。

## 只有 AI 會跑

`farcall_to.py` 對三個入口掃全傾印，各一個呼叫者：

| 常式 | 呼叫者 |
|---|---|
| `2D76:0732` | `2D10:011C`（AI 回合，`docs/internals/54`）|
| `2D76:07BA` | `2D76:0732` |
| `2D76:0A44` | `2D76:0732` |

**與建立艦隊那條不一樣**：`297B:0066` 是玩家與 AI 共用的
（`docs/re/217`），整補**只有 AI 有**。玩家要補編制走「艦隊編成」的
另一條路。

## 剩下四支

### `0FF4:0E5A(星域編號, 艦種)`

線性 `0x10D9A`：把 `ds:9872` 設成那一格的遠指標，再叫 `0FF4:0E84`。
＝「那一格這個艦種編得出幾組」（`docs/re/216`）。

### `0FF4:131E(艦隊, 艦種)`

線性 `0x1125E`：把 `ds:9872` 設成艦隊所在星域，再叫 `0FF4:1350`。
＝ 照 `ds:295C` 換一個艦種（`docs/re/216`、`docs/re/226`）。

兩支都只是「先設好 `ds:9872` 再轉呼叫」的包裝。

### `2D76:0C4F(艦隊, 艦種, 隊形槽)`

線性 `0x2E3AF`：掃第 1 組起找 `組[3] == 隊形槽` 的那一組——

```
找到而且 組[2] == 艦種 → 回 −1      ; 已經是對的，這一格不用補
找到但艦種不同         → 回 那一槽  ; 覆蓋它
都沒找到               → 回 0       ; 新增一組
```

### `2D76:0D40(艦隊)` ＋ `2D76:0DB2(樣板, 隊形槽, n)`

線性 `0x2E4A0` 與 `0x2E512`。`2D76:0DB2` 回「這個隊形槽**沒有**出現在
樣板的前 n 組裡」——出現回 0、沒出現回 1。`2D76:0D40` 拿它掃第 0 組起，
回第一個「隊形槽已經不在樣板前 `+0x0F` 組裡」的槽，找不到回 `0FFh`。

也就是**編制滿了要犧牲一組時，挑的是樣板已經不要的那一組**。

### `2703:155B(星域, 艦艇)`

線性 `0x2858B`：

```
星域[+0x30 + 艦艇[+0x00] × 28 + 艦艇[+0x04] × 4]（32 位元）+= 艦艇[+0x08]
```

＝ `2703:1433`（從存量扣，`docs/re/215`）的反向：**把現有艘數整批還回
星域待命部隊**。陣營取的是艦艇記錄的 `+0x00`，不是艦隊的。

## 整補的完整規則

```
2D76:0732():
    對 32 個艦隊槽：自己的、在自己星域、那一格沒戰鬥（星域[+0x13] & 4 == 0）
        2D76:07BA(艦隊)     ; 併殘部
        2D76:0A44(艦隊)     ; 補到應有組數

2D76:07BA(艦隊):            ; 星域 ＝ 艦隊[+0x06]
    對第 1 組起：現有×4 < 滿編×3（不到七成五）
        總和[艦種] += 現有；缺編數[艦種]++
    對艦種 k = 0..6，缺編數[k] != 0：
        滿編 = ds:4E3A[陣營][k].word0
        需要 = 滿編 − (總和[k] mod 滿編)
        星域待命部隊[陣營][k] >= 需要 → 總和[k] += 需要
        總和[k] ÷ 滿編 == 0 → 這個艦種不動
        否則對第 1 組起、艦種 == k 而且不到七成五的：
            2AD2:018C(星域, 艦艇)       ; 艘數還回星域、那一筆作廢
            組[2] = 0FFh；組[3] = 已拆數；已拆數++
    已拆數 != 0：
        qsort(第 1 組起, 2D76:0CAF)     ; [2] 升冪、相同比 [3]
        艦隊[+0x0F] −= 已拆數
        297B:03EB(艦隊編號, 0)          ; 組序同步回艦艇記錄

2D76:0A44(艦隊):
    艦隊[+0x09] == 0FFh 或 艦隊[+0x08] == 4 → 回
    樣板 = ds:2BC6 + 艦隊[+0x09] × 20 + 2
    旗艦艦種 = 第 0 組那筆艦艇的 [+0x04]
    對 i = 1 .. 艦隊[+0x0E]−1：
        a = 樣板[0] == 0 ? 旗艦艦種 : 樣板[0]        ; **無條件**，與 0FF4:11F4 不同
        n = 2D76:0C4F(艦隊, a, 樣板[1])
        n == −1 → 下一個樣板槽
        0FF4:0E5A(星域, a) != 0 ? 艦種 = a : 艦種 = 0FF4:131E(艦隊, a)
        艦種 == 0FFh → 下一個樣板槽
        n != 0                      → 2AD2:018C 拆掉組[n]；目標 = n
        n == 0 且 +0x0F == +0x0E    → 目標 = 2D76:0D40(艦隊)（0FFh 就跳過），拆掉它
        n == 0 且 沒滿              → 目標 = +0x0F；+0x0F++
        組[目標][2] = 艦種；組[目標][3] = 樣板[1]
        組[目標][0..1] = 2AD2:0029(艦隊, 艦種, 0)
        qsort(第 1 組起, 2D76:0CAF)
```

## 仍然沒讀

`297B:03EB` 迴圈之後那一段（用 `艦隊[+0x38]` 那一筆艦艇），
以及 `2D76:0A44` 收尾在 qsort 之後還有沒有別的。兩處都不影響上面的規則。

## remake

規格草稿在 [`docs/spec/031`](../spec/031-fleet-refit.md)，狀態 **DRAFT**
——反組譯齊了，但**整補沒有收據**：已有的 `turn260mem` 是開局那一趟，
三支新艦隊全部滿編，一組殘部都沒有，走不到這條路。要驗得先做一份
「打過仗之後」的收據。

## 一條方法

**掃呼叫者不只回答「誰呼叫」，也回答「該放哪一層」。** 整補三支各只有
一個呼叫者、全在 AI 的段裡，所以它是 AI 的行為不是共用規則——這一點
決定了 remake 該把它放進 `internal/ai` 那條路而不是 `internal/rules`
的共用編制。同一個掃描，`297B:0066` 得到的是相反的答案
（兩個呼叫者，玩家與 AI 共用，`docs/re/217`）。
