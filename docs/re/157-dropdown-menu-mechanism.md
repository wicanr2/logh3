# 157 — 下拉選單解了：它有自己的一套，不走熱區清單

`docs/re/19` 找不到下拉選單的熱區，`docs/re/156` 排除了「那一處把清單
當參數收的命中測試就是它」。這一輪直接問原版：**選單根本不呼叫命中
測試**，它有自己的選單元件 `3667:*`，用格子座標算出點到第幾列。

## 收據先證明「不是它」

`sysmenuhit2`（旗標見下）在主畫面點「系統指令」(544,85)，25 秒後再點
選單裡的 (560,125)，最後倒畫面。整段 `-regs-at 37A9:0201`（命中測試的
`mov bp,sp` 之後）只抓到**一次**：

```
#180000515 …
  [bp+] 00:63EB 02:0055 04:0220 06:1F7E 08:01A0 0A:06E8
        0C:955C 0E:54B3 10:0C52 12:54B3 14:0220 16:0055
```

回位址 `06E8:01A0` 就是命令列那一處呼叫（`hittest-sites.json` 的線性
`0701B`，五位元組的 call 之後正好是 `06E8:01A0`）；`[bp+0C]` ＝ 視窗
`ds:955C`、`[bp+10]` ＝ 熱區清單 `ds:0C52`——都與既有紀錄相同。

**點選單那一下沒有再進命中測試**，而畫面確實換掉了：`sysmenuhit2` 的
`screen.bin` 與收據 `save1e` **逐位元組相同**（存進度）。所以選單的
判定走的是別的路。

## 那條路

命令列的處理是 `06E8:017C`：拿命中測試回來的熱區 `+0x05`（項目索引）
分派到三支，一支一個下拉選單。

```
06E8:017C(視窗far)
    熱區 = 37A9:01F9(ds:955C, ds:0C52, 視窗far)
    switch 熱區[+0x05]:
        0 → 06E8:034A     ; 戰略命令
        1 → 06E8:0435     ; 一覽表
        2 → 06E8:04BC     ; 系統指令
```

三支的骨架相同（以系統指令為例）：

```
06E8:04BC()
    描述 = 堆疊上的 0x26 bytes
    3667:0004(描述, ds:0D1E, 33, 3, 5, 3, 9, 97h, 27h, 98h)   ; 建選單
    341B:0145(描述)                                            ; 畫
    描述[+0x1C] = 0FFh                                         ; 目前反白的列
    項 = 3667:00F2(描述)                                       ; modal：等玩家選
    3667:00CB(描述)                                            ; 收掉
    switch 項（0–4）
```

參數對得起收據量到的可點範圍（`docs/internals/23`）：

| 選單 | 進入點 | 項目表 | 格x | 格y | 項數 | 寬（格）| 可點 x |
|---|---|---|---|---|---|---|---|
| 戰略命令 | `06E8:034A` | `ds:0CA6` | 21 | 3 | 4 | 4 | 352–415 |
| 一覽表 | `06E8:0435` | `ds:0CE2` | 27 | 3 | 4 | 4 | 448–511 |
| 系統指令 | `06E8:04BC` | `ds:0D1E` | 33 | 3 | 5 | 3 | 544–591 |

項目的矩形是 **(格x ＋ 1, 格y ＋ 1 ＋ n)、寬格 × 1**：格子是 16×20，
所以系統指令第 0 列的畫面座標是 x ＝ 34 × 16 ＝ 544、
y ＝ 4 × 20 ＋ 40 ＝ 120（那個 ＋40 是畫布偏移，`docs/internals/52`）
——與量到的完全相同。**「寬度取最長標籤」那個規律的來源是參數裡的
寬格**，不是逐項算的。

## 命中測試是算出來的，不是查表

`3667:00F2(描述)`：

```
描述[+0x0E] = 0FFh
3765:00BF(描述, 0)                       ; 等事件
若 341B:039D(事件far) != 描述[+0x1A]：跳過   ; 不是這個視窗
341B:044A(視窗far, 事件far, &格x, &格y)  ; 滑鼠 → 視窗內的格子座標
若 格x 或 格y 是 0FFh：沒選到
否則 索引 = 格y                           ; **就是列號**
```

所以熱區清單裡永遠找不到它——**它沒有清單**。

## 項目表：一筆 6 bytes

```
+0x00  啟用旗標（0 ＝ 這一項變灰）
+0x01  0
+0x02  far 指標 → Big5 標籤（補空白補到「寬格」個字）
```

| 表 | 內容 |
|---|---|
| `ds:0CA6` | 出擊命令／情報收集／徵稅計劃／生產計劃 |
| `ds:0CE2` | 星系資料／艦隊資料／提督資料／敵將資料 |
| `ds:0D1E` | **實行**／取進度／存進度／設定／結束 |

**系統指令有五項，第一項是「實行」**（＝結束回合）。標籤全部補空白到
三個字（「實行␣␣」「設定␣␣」「結束␣␣」），這就是可點寬度是 3 格的原因。

`06E8:034A` 在建選單之前會先寫 `ds:0CA6` 與 `ds:0CB8`（第 0 筆與第 3 筆
的啟用旗標）：拿 `3982:0329(ds:8F1D)`（自己陣營的首都星域）去比目前
選的星域，不相同就把「出擊命令」與「生產計劃」關掉。

## 收據

`sysmenuhit`／`sysmenuhit2`，dosgolem `ef5be47`。旗標：

```
-tick 20000 -press 1,3,8,enter -press-at 105000000 -press-every 2000000
-steps 230000000
-clicks '300,170,40000000,3000000;300,170,95000000,3000000;
         544,85,180000000,3000000;560,125,205000000,3000000'
-rclicks '300,200,130000000,3000000;300,200,155000000,3000000'
-regs-at 37A9:0201 -regs-from 179000000 -regs-max 60
```

一次約 54 秒。`sysmenuhit` 是同一組去掉最後那一下點擊、改成把滑鼠移進
選單——**移動不觸發任何命中測試**，也就是說判定只發生在按下的那一刻。
