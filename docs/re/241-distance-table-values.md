# 241 — EMS 裡那兩張距離矩陣的數值取到了

`docs/re/185` 說 `2B99:028F` 查的 32×32 word 矩陣「在 EMS 分頁框裡，
數值還沒取到」——拿平面傾印去讀得到的是別的頁的位元樣式。
挑對時刻就讀得到。

## 挑時刻

分頁框在**載入的當下**放著那四張表。倒四個時點的 8 KB
（收據 `emsdist3`，7.5×10⁷ 條指令）：

| 時點 | `E1000` 與中點矩陣[帝國] | `E1400` 與中點矩陣[同盟] |
|---|---|---|
| `#68700000` | 不符 | 不符 |
| `#69000000` | 不符 | 不符 |
| `#70000000` | **相符** | 不符 |
| `#72000000` | **相符** | **相符** |

**用兩張已知的中點矩陣當校驗**（`star-graph.json` 裡逐位元組比對）：
`#72000000` 那一份兩張都相符，所以那一刻頁框裡確實是這四張表。
`E0000` 第 0 列是 `0, 16, 15, 1051, 14, 33, 30, 31 …`，
與 `docs/re/43` 當年記下的完全相同。

## 資料

`tools/scripts/distance_table.py` 倒成
[`docs/internals/data/star-distance.json`](../internals/data/star-distance.json)
（兩張 32×32，20 KB）。**校驗寫進腳本**：中點矩陣對不上就直接中止，
所以拿錯時點的傾印不會產出假資料。

## 形狀

| | 帝國 | 同盟 |
|---|---|---|
| 對角線 | 0 | 0 |
| 對稱 | **否** | **否** |
| 高位元組 | 0 4 8 12 16 20 24 28 32 | 0 4 8 12 16 20 24 |
| 最大值 | 8340 | 6239 |
| `>= 0x800` 的格 | 730／1024 | 652／1024 |

**不對稱**，所以它是有方向的成本，不是距離。高位元組永遠是 4 的倍數
（`docs/re/43` 也注意到了），所以值可以看成

```
值 = 1024 × k + 小成本          （k ＝ 高位元組 ÷ 4）
```

`2B99:028F` 的回值與 `0x800` 比，也就是 **k >= 2 才算「遠」**。

兩張表比對：**低位元組有 706／1024 格相同**，高位元組的差都是 4 的倍數
（−24 到 ＋16）。同一對星域常常走同一條路、只是 `k` 不同，例如

```
0 → 3   帝國 1051 ＝ 1024 + 27    同盟 2075 ＝ 2048 + 27
0 → 5   帝國   33 ＝    0 + 33    同盟 2081 ＝ 2048 + 33
```

`k` 顯然與「路上有幾格不是自己的」有關，但**還沒有量到定義**——
剩下 318 格低位元組不同，表示兩邊有時走不同的路。

## 與未安定度那條分支的關係

`docs/spec/006` 記著「路徑成本表的值 >= `0x800` 就把治安度砍半，
但載入的當下值都遠小於 `0x800`」。兩件事都對：**載入時整張是 0**
（`docs/re/43`：表是路徑計算跑過才填），這一份是填好之後的樣子，
730 格超過門檻。所以那條分支在**開局**不會走到，中局會。

## 還沒解

- 高位元組的 `k` 的定義（與擁有者的關係）。
- 低位元組的單位（值域 113 種，10–148）。
- 這張表什麼時候被重算——擁有者一變應該就要重算，但寫入點還沒找。

## 一條方法

**分頁的記憶體要用「已知內容」當校驗，不能只靠位址。** 同一個線性位址
在不同時刻是不同的頁；這一輪四個時點裡只有一個是對的，而分辨它們的
唯一辦法是拿旁邊那兩張**已經知道內容**的表去比。校驗要寫進腳本，
不是寫在文件裡——下一個人重跑時錯的時點會直接中止，而不是產出假資料。
