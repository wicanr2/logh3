### 更正：`+0x02` 不是「首都星域」

`docs/re/42` 原本寫「`+0x02` 首都星域（帝國0、同盟31）——只有這兩個值，
跟著陣營走，不是艦隊所在星域」。本輪反組譯 `2AD2:0029`（`+006D`–`+0074`）
與 `297B:03EB`（既有 `docs/re/228` 已經引用過的同一行）都明白寫著
`艦艇[+0x02] = 艦隊[+0x06]`（所在星域，逐筆同步），沒有任何一處讀「首都」
表。`re/42` 那三格存檔剛好只看到 0／31，合理的解釋是**當時取樣的艦隺剛好
都還沒離開首都星域**（新遊戲存檔或會戰初期常見）——是取樣巧合，不是欄位
語意。**這條更正只留在這裡（`docs/re/` 是逐次調查紀錄）；`docs/internals/`
若要更新，正文應直接寫「所在星域」，不必重複本段推翻過程**（`rulebook/63`）。

## 三、配置與作廢

### 3.1 `2AD2:0151()`：怎麼挑一個空的池索引（本輪新解，proven 位元組）

```
2AD2:0151():
    i ← 0
    ptr ← ds:CFB4/CFB6（池遠指標）
    while i < 0x160 (352):
        if 池[i].+0x01 == 0xFF:
            return i                  ; ★ 找到就馬上回傳，不繼續往後找
        i++; ptr += 0x4E (78)
    return 0xFFFF                     ; 352 筆全滿
```

**線性掃描、由索引 0 往上找第一個 `+0x01 == 0xFF` 的槽（first-fit）**，
不是空閒鏈結串列、也不記「上次用到哪」。這解釋了：

- `docs/re/317` 觀察到「收據裡新組拿到 2、3、4…（1 已被用掉）」——因為
  0、1 已被同一支艦隊的旗艦與索敵分遣隊占用（見 3.2），下一個空位自然是 2。
- `docs/re/232` 觀察到「`2AD2:018C` 把那一筆標成空槽之後，`2AD2:0029`
  再配置時拿到同一格」——因為線性掃描只要那一格的索引比其他空格小，
  一定先掃到它。

沒有找到任何「跳過已標記」或「記憶上次配置點」的邏輯；池滿時回
`0xFFFF`，呼叫端（`2AD2:0029`）**沒有檢查這個哨兵值**——如果 352 筆真的
用滿，`0xFFFF × 78` 會算出一個溢位的位址，後續讀寫會打到別的資料。
這是原版沒做邊界檢查的一個潛在 bug，remake 不必模仿，但如果要對拍
「艦艇池滿」這種邊界狀況，要知道原版在這裡不會報錯、只會寫壞記憶體。

### 3.6 `0FF4:000A`「決定」往下寫的是誰——釐清任務描述裡的一個時序誤解

任務描述問「`0FF4:000A` 的『決定』分支往下是哪一支在寫這些記錄」。
反組譯之後要指出一個時序上的重點（`docs/re/317` 已經寫過，這裡把它
講清楚，避免以為「決定」才配置艦艇）：

- **配置艦艇（呼叫 `2AD2:0029`）發生在使用者點格盤放一組的那一刻**
  （`0FF4:0C80`，或「陣形」樣板逐一放置時的同一支），**不是**按「決定」
  那一刻。
- 「決定」（`0FF4:10C1`）做的事只是：把編輯器的工作表（`ds:977A`／
  `ds:981E`，玩家操作期間的暫存區）**逐筆抄進艦隊記錄的 `+0x10` 陣列**、
  寫 `艦隊[+0x0F] ← 現有組數`。它**不會**再呼叫一次 `2AD2:0029`。
- 「中止」（`0FF4:1127`）反過來：把工作表裡曾經放過的組**全部呼叫
  `2AD2:018C` 退回存量**，再把進來時備份的艦艇記錄／星域存量整塊複製
  回去。

所以「配置」與「決定」是兩個獨立時間點：**配置在放置當下就發生
（有立即的存量副作用），決定只是把「這次編輯的結果」定案寫回艦隊
記錄。** 中途按「中止」，已經配置出來的艦艇記錄會被 `018C` 作廢並退錢，
不會留下孤兒記錄。

## 五、會改這幾格的地方與算式——`1261:03FB`、`203A:0593`

這兩支任務裡點名的函式，**`docs/re/330` §3.5／§6 已經逐行反組譯過**

**寫的欄位**：艦艇 `+0x08`（現有艘數）、`+0x0C`（修理上限）、`+0x0E`／
