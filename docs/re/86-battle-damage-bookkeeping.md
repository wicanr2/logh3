# 86：戰鬥扣艦艇的那支常式與它的善後

## 怎麼找到的

`docs/re/85` 量到戰鬥會扣艦艇，但只有兩個數字。這一輪用 `-watch`
盯住同盟第 16 艦隊旗艦分隊的艘數欄（線性 `691DC`，一個 word），
跑完整條序列，抓到三次寫入：

```
#1158741688  0BB8 → 0B93   ← 203A:06C0    3000 → 2963
#1185826490  0B93 → 0BB8   ← 1AAB:08CC    2963 → 3000
#1248637773  0BB8 → 0B86   ← 203A:06C0    3000 → 2950
```

扣的是 `203A:06C0` 那一支；`1AAB:08CC` 會把它加回去，還沒讀。

## 善後做了哪些事

`203A:06C0` 起（`tools/ida.sh script seg203A.com`）：

```
+06C0  mov  cx, [bp+4]           ; 這次的損失
+06C3  sub  es:[bx+0Ch], cx      ; 艦艇記錄 +0x0C 跟著扣
+06CA  mov  al, es:[bx+1]        ; 艦艇記錄 +0x01
+06D0  mov  cx, 7Ah              ; 122 ＝ 艦隊記錄的長度
+06D3  mul  cx
+06D7  mov  si, 0C074h           ; ds:C074 ＝ 艦隊表
+06DA  add  si, ax
+06DE  call far 1261h:67h        ; 對那支艦隊做善後
```

所以**艦艇記錄的 `+0x01` 是它屬於哪一支艦隊**（艦隊表的索引），
而 `+0x0C` 與 `+0x08`（現有艘數）是同步扣的——`docs/internals/38`
量到這兩個欄位同值，原因在這裡。

接著把損失計進兩份統計：

```
+06F5  mov  ax, [bp+2]
+06F8  mov  cx, 14h
+06FD  div  cx                   ; 損失 ÷ 20
+0703  mov  cl, [bp+0]           ; 3982:250 回來的索引
+070A  shl  si, 1 ×2             ; ×4
+070E  add  [si-701Ch], bx       ; ds:8FE4[i] 32 位元累加
+0712  adc  [si-701Ah], ax
+0716  add  [si-7014h], bx       ; ds:8FEC[i] 同樣
+071A  adc  [si-7012h], ax
```

`[bp+26h]`／`[bp+28h]` 非 0 時，還會拿損失的一半呼叫 `203A:743`。

再往前的 `203A:0600` 那一段在更新**提督的戰績**：`ds:4E3A` 起、
一筆 `0xD0`（208）位元組的表，對 `+0x0E` 與 `+0x12` 兩個 32 位元
欄位做加減（`3CC9:20`／`3CC9:9` 是 32 位元的除法與另一個運算）。

## 損失怎麼分攤到各個分隊

呼叫 `203A:0593` 的地方有六處，其中兩處相鄰（線性 `21CB6` 與 `21D1B`）。
把那一帶切出來反組譯（`21A0:0250` 起），看到的是**把一支艦隊的總損失
按比例分給各分隊**的迴圈：

```
+0250  mov  si, 64h              ; 100
+025B  call far 3CC9h:9          ; 這個分隊的量 × 100（32 位元乘）
+0260  mov  si, [bp+0Ah]
+0267  call far 3CC9h:20h        ; ÷ 全隊的量  → 百分比
+0272  mov  bx, [bp+2Eh]         ; 這一輪的總損失
+027F  call far 3CC9h:9          ; × 百分比
+028B  call far 3CC9h:70h        ; ÷ 100
+0290  mov  [bp+2], bx           ; ＝ 這個分隊該扣多少

+0293  cmp  word [bp+30h], 0     ; 旗標為 0 時有上限
+029C  cmp  bx, ax               ;   要扣的 ≥ 現有？
+02A3  dec  ax                   ;   那就扣到只剩一艘
+02A4  mov  [bp+2], ax

+02B6  call far 203Ah:593h       ; 真的去扣，回傳實際扣掉的
+02C0  sub  [bp+6], ax           ; 待扣的減掉
+02C3  add  [bp+8], ax           ; 已扣的加上
+02C9  add  word [bp+10h], 4     ; 下一個分隊槽（4 位元組一筆）
```

所以規則是：

1. 一支艦隊這一輪的總損失，按**各分隊佔全隊的比例**分攤；
2. 每個分隊算出來的數先被「留一艘」的上限夾住（`[bp+30h]` 非 0 時
   不夾——大概是殲滅的情形，還沒確認）；
3. 實際扣掉的由 `203A:0593` 回傳（`min(現有艘數, 要扣的)`），
   沒扣滿的部分留在待扣量裡繼續往下一個分隊分。

「一輪的總損失」`[bp+2Eh]` 由更上層決定，那還沒讀到。

## 扣一個分隊：`203A:0593`

```
+059E  cmp  byte es:[bx+4], 7    ; 艦種 7 直接回現有艘數，不扣
+05B3  mov  ax, es:[bx+8]        ; 現有艘數
+05B7  cmp  ax, [bp+24h]         ; 與要扣的比
+05BF  mov  cx, [bp+24h]         ; 取小的 → 實際扣掉的
+05D3  call far 3CC9h:9          ; 實扣 × …
+05DB  mov  si, es:[si+0Ah]      ;   ÷ 滿編艘數（+0x0A）
+05E3  call far 3CC9h:20h
+05EE  mov  al, es:[bx+4]        ; 艦種
+05F7  mov  cx, 1Ah              ; × 26
+0603  mov  cx, 0D0h             ; 記錄 +0x00 × 208
+060C  mov  di, 4E3Ah            ; ds:4E3A ＋ 兩者
```

`ds:4E3A` 那張表一筆 **208 ＝ 8 × 26** 位元組，也就是**每個艦種一段
26 位元組**，用艦艇記錄的 `+0x00` 選是哪一筆。

接著把艦艇記錄的 `+0x0E` 與 `+0x12`（都是 32 位元）按
「剩下 ÷ 原有」的比例縮小——那兩個欄位是隨艘數等比例遞減的量。

艦種 5 有特例（跳過 `+0x0E` 那一段），艦種 7 完全不扣。

## 那支函式的邊界

`203A:04D1`–`0592` 是另一支函式：跑過一支艦隊的分隊，把**艦種 1**
的現有艘數加總（溢位就飽和成 `0xFFFF`），最後除以 100 回傳。開頭是

```
+04D1  push bp / si / di
+04D4  sub  sp, 2CEh            ; 718 bytes 的區域變數
+04DA  mov  ax, [bp+2DAh]       ; 參數：一個 far ptr
+04E2  mov  ds:0A766h, ax       ; 存進 ds:A764／A766
```

中段（`+0500` 起）是**跑過一支艦隊所有分隊的迴圈**：

```
+050C  call far 17A0h:0ACh      ; 回分隊數
+0528  mov  ax, [bp+si+4]       ; 第 i 個分隊的池索引
+052B  mov  cx, 4Eh             ; 78 ＝ 艦艇記錄長度
+052E  mul  cx
+0530  mov  cx, ds:0CFB6h       ; 艦艇池 far ptr
+0534  mov  si, ds:0CFB4h
+0544  mov  al, es:[si+4]       ; 艦種
```

——與 `docs/internals/38` 量到的欄位完全一致（池的 far ptr 在
`ds:CFB4`、一筆 78、`+0x04` 是艦種）。

## 分母與餘數

第一趟迴圈（`21A0:01A9`）跑過分隊做兩件事：把現有艘數加總當分母
（`[bp+0Ah]`），同時記下**現有艘數最多的那一支**（`[bp+18h]`）。

分攤完之後 `21A0:02D0` 檢查還有沒有沒扣掉的，有的話**全部補在那一支
最大的身上**。

## 驗證到什麼程度

`s3turn2` → `s3fight` 那八個回合，同盟第 13 艦隊九個分隊掉的數字是
`23 23 23 23 23 40 30 15 15`。照上面的規則算（總損失 215）：按比例是
`23×5 ＋ 30 ＋ 30 ＋ 15 ＋ 15 ＝ 205`，餘下的 10 補在最大的那一支
（組 5，4000 艘）上 → `40`。**九個數字全部相同。**

**但這是累積值，不是一輪的量。** 同一場的第 16 艦隊照同樣算法會差 4
（每一輪的艘數都在變，取整誤差累積）。要真正驗單輪，得知道那一輪的
總損失是多少——而那正是還沒解的部分。目前 `-watch` 只抓到兩筆單輪的
扣除量（3000 → 2963、3000 → 2950）。

## 一輪的總損失怎麼算

分攤那支函式（`21A0:017D`）只有一個呼叫者，就在同一段的
`21A0:0136`。那支函式從線性 `219BE` 開始（`20A0:0FBE`），
總損失是這樣堆出來的：

**基本量**（`20A0:0FBE`）

```
+0FC9  cmp  byte es:[bx+12h], 0   ; 攻擊方艦隊記錄的 +0x12
+0FD0  mov  word [bp+6], 0Ah      ;   0 → 除數 10
+0FD7  mov  word [bp+6], 14h      ;   非 0 → 除數 20
+0FE2  call far 203Ah:4D1h        ; 艦種 1 的艘數總和 ÷ 100
+0FEC  add  ax, es:[bx+14h]       ; 加上艦隊記錄的 +0x14
+0FF2  div  word [bp+6]
+0FF5  mov  [bp+2], ax            ; ＝ 基本量
```

也就是

```
基本量 ＝ (艦種 1 的艘數總和 ÷ 100 ＋ 艦隊 +0x14) ÷ (+0x12 為 0 ? 10 : 20)
```

`203A:04D1` 那支「艦種 1 的艘數加總 ÷ 100」原來是為這裡準備的。
`+0x12` 與 `+0x14` 是艦隊記錄裡還沒命名的兩個欄位——`+0x12` 是個
旗標（非 0 時傷害砍半），`+0x14` 是個加成。

**距離的衰減**（`21A0:0004`）

`3310:0006` 是兩點的距離：先取 X 與 Y 差的絕對值，任一邊是 0 就直接
回另一邊，否則用 `dx × √(1 + (dy ÷ dx)²)` 算（`39B5:5C` 除、
`39B5:0C` 乘、`3310:14B` 開根號）——避免平方時溢位的寫法。

參數是「目標的 `+0x5C`／`+0x5E`」與「攻擊方的 `+0x46`／`+0x48`」，
所以**艦隊記錄的 `+0x46`／`+0x48` 是另一份座標**。


```
+0007  push es:[si+46h]          ; 對方艦隊記錄 +0x46
+0013  push es:[di+5Eh]          ; 我方 Y
+0022  push es:[bx+5Ch]          ; 我方 X
+002B  call far 3310h:6          ; → 32 位元
+0037  mov  si, 96h              ; 150
+003F  call far 3CC9h:70h        ; ÷ 150
+0057  call far 3CC9h:9          ; 基本量 × 上面那個
+005C  mov  cx, 5
+0063  call far 3CC9h:70h        ; ÷ 5
+0068  sub  [bp+2], bx           ; 從基本量扣掉
```

**攻擊方向的加成**（`21A0:006E`）

```
+006E  ax ＝ 兩邊的 X 差
+0081  ax ＝ 兩邊的 Y 差
+0091  call far 2BE1h:11Dh       ; atan2 → 相對方位（一圈 256）
+009E  push es:[bx+4Ah]          ; 攻擊方艦隊的朝向 +0x4A
+00A3  call far 2BE1h:24Ah       ; 兩個角度做運算
+00AE  call far 3982h:22h        ; → 0–7 的方向索引
+00C6  mov  si, [bx+47D0h]       ; ds:47D0 的係數表
+00D0  call far 3CC9h:9          ; 基本量 × 係數
+00DC  call far 3CC9h:70h        ; ÷ 100
```

`ds:47D0` 那張表倒出來是

```
80  85  90  95  100  95  90  85
```

八個方向、單位是百分比，**最多差 20%**。索引 4 那格是 100，
其餘往兩側遞減——索引怎麼對到實際方向還沒確定（`3982:22`
沒讀），但「從某個方向打傷害多兩成」這件事是確定的。

**亂數**（`21A0:011C`）

```
+011C  call far 3CD5h:0Ch        ; 亂數
+0121  mov  cx, 64h
+0125  idiv cx
+0127  add  [bp+4], dx           ; 加上 0–99
```

**防禦係數**（`20A0:10E8`）

```
+10E8  mov  si, 64h              ; 100
+10ED  call far 3CC9h:9          ; 攻擊力 × 100
+10F7  mov  al, es:[si+40h]      ; 目標艦隊記錄 +0x40
+10FD  mov  cl, es:[si+41h]      ; 目標艦隊記錄 +0x41
+1103  mul  cx
+110A  div  cx                   ; ÷ 100  → 防禦係數
+1114  call far 3CC9h:20h        ; 攻擊力 × 100 ÷ 防禦係數
```

那兩個欄位在 `s3turn2` 裡是 78–120，算出來的防禦係數 69–140。

整條算式：

```
基本量 ＝ (艦種 1 艘數總和 ÷ 100 ＋ 艦隊 +0x14) ÷ (10 或 20)
距離項 ＝ 基本量 × (3310:6 的量 ÷ 150) ÷ 5
攻擊力 ＝ (基本量 − 距離項) × 方向係數 ÷ 100
總損失 ＝ 攻擊力 × 100 ÷ 防禦係數 ＋ 亂數 mod 100
```

## 第二條路徑：`2350:00EF`

`203A:0593` 的六個呼叫點裡，`21CB6` 與 `21D1B` 是上面那條（艦隊層的
分攤，後者是「餘數補給最大的那一支」）。`235EF` 是另一條，直接對
**一筆艦艇記錄**扣：

```
+00A0  idiv cx                   ; 亂數 % 某數 → dx
+00A4  ax ＝ [bp+0] ＋ [bp+6]
+00B0  ax ＝ [bp+0]；sar ax,1    ; [bp+0] ÷ 2（有號）
+00B8  ax ＝ ([bp+0]+[bp+6]) − [bp+0]÷2
+00BC  dx ＝ 亂數餘數 ＋ ax
+00C1  es:bx ＝ 目標艦艇記錄 +0x08（現有艘數）
+00CA  超過現有就夾成現有
+00DB  小於 0 就夾成 0
+00EF  call far 203Ah:593h       ; 扣
```

量是這樣算出來的（函式從 `2350:0023` 開始）：

```
+0037  call far 2264h:0FC3h      ; → 分母 K
+0044  mov  ax, es:[bx+16h]      ; 攻擊方的 +0x16
+004A  div  word [bp+2]          ; ÷ K
+0053  mov  bx, es:[bx+8]        ; 目標的現有艘數
+005B  mov  si, 28h              ; 40
+0060  call far 3CC9h:9          ; 目標艘數 × 40
+006C  call far 3CC9h:9          ; × (+0x16 ÷ K)
+0073  mov  si, 3200h            ; 12800
+0078  call far 3CC9h:20h        ; ÷ 12800   → 基準量
+0084  call far 3CD5h:0Ch        ; 亂數
+008A  idiv word [bp+0]          ;   % 基準量
+0097  call far 3CD5h:0Ch        ; 再一個亂數
+00A0  idiv cx                   ;   % 100
+00A4  ax ＝ 基準 ＋ (亂數 % 基準)
+00B2  sar  ax, 1                ; 基準 ÷ 2
+00B8  ax ＝ 上面兩者相減
+00BC  dx ＝ (亂數 % 100) ＋ ax
```

也就是

```
基準 ＝ 目標現有艘數 × 40 × (攻擊方 +0x16 ÷ K) ÷ 12800
量   ＝ 基準 ＋ (亂數 % 基準) − 基準 ÷ 2 ＋ (亂數 % 100)
```

**量級對得上實測**：目標 3000 艘、攻擊係數取 1 的話基準是 9，
量落在 4 到 111 之間——`-watch` 觀測到的 37 與 50 正好在裡面。
所以戰鬥實際扣的走的是這一條，而不是艦隊層那條分攤。

### 分母 K：`2264:0FC3`

```
+0FCE  mov  al, es:[bx+1]        ; 艦艇記錄 +0x01 ＝ 所屬艦隊
+0FD4  mov  cx, 7Ah              ; × 122 → 艦隊表 ds:C074
+0FE8  mov  al, es:[si+3Dh]      ; 艦隊記錄 +0x3D（能力值之一）
+0FF2  mov  al, es:[di+4]        ; 艦艇記錄 +0x04 ＝ 艦種
+0FF8  mov  cx, 1Ah              ; × 26
+0FFE  mov  al, es:[bx]          ; 艦艇記錄 +0x00
+1003  mov  cx, 0D0h             ; × 208
+100C  mov  bx, 4E3Ah            ; → ds:4E3A 的表項（8 艦種 × 26）

+1021  ax ＝ 目標 +0x48 − 攻擊方 +0x36
+1030  ax ＝ 目標 +0x46 − 攻擊方 +0x34
+103C  call far 2BE1h:11Dh       ; atan2 → 相對方位
+1049  push es:[bx+4Ah]          ; 艦隊的朝向
+104E  call far 2BE1h:24Ah       ; 角度差
+1058  mov  bx, [bp+18h]+18h     ; 表項 +0x18
+106C  call far 3CC9h:9          ; 乘
+107B  mov  si, [bp+18h]+16h     ; 表項 +0x16
```

所以 K 是「艦種在 `ds:4E3A` 那張表裡的兩個欄位（`+0x16`／`+0x18`）」
配上方向算出來的——**方向在這條路徑上也有影響**，只是走的是另一張表。

`+0x34`／`+0x36` 是分隊的目標座標（`docs/internals/38`），所以這裡的
方向是「從攻擊方的目標點指向被攻擊方」。

往下（`2264:107B`）：

```
+1081  mov  si, es:[si]          ; 表項 +0x16
+1088  call far 3CC9h:20h        ; 除
+109C  push es:[bx]              ; 表項 +0x18
+10A5  push es:[bx]              ; 表項 +0x16
+10A8  call far 3870h:643h
+10BA  add  bx, 40h              ; 角度差 ＋ 64
+10C1  mov  ax, [bx+573Ah]       ; ds:573A ＝ **正弦表**（一圈 256、×1024）
+10CD  shl  ×6                   ; × 64
+10DB  call far 39B5h:0Ch        ; 乘
```

`ds:573A` 那張表已經倒出來了（`docs/internals/41`）——所以這條路徑
的方向影響是**連續的餘弦**（`角度差 ＋ 64` 就是 cos），與艦隊層那條
走 8 格係數表的不一樣。

`ds:4E3A` 的內容也倒出來了（`docs/internals/40`）。K 還差
`3870:643` 與 `39B5:0C` 之後那幾步沒讀。
## 第三條路徑：`1EC0:00B9`

```
+0090  mov  cx, 0Ah
+0094  idiv cx                   ; 亂數 % 10
+0096  add  [bp+6], dx           ; 量 ＋＝ 0–9
+009C  mov  al, es:[bx+1]        ; 艦艇的所屬艦隊
+00A5  mov  cx, 7Ah              ; × 122 → 艦隊表
+00AE  push cx / si              ; **艦隊表的位址當第四、五個參數**
+00B0  push [bp+6]               ; 量
+00B9  call far 203Ah:593h
```

量比另外兩條小（只加 `亂數 % 10`），但**第四個參數非 0**——那正是
`21A0:0293` 判斷「要不要留一艘」的那個旗標。所以**這條會把分隊
打到 0**，是殲滅用的路徑。

## 第四、第五條路徑：兩個「整隊按比例扣」的呼叫點

`03E0:0068` 與 `1920:00DA` 是同一個骨架的兩份拷貝，跟前面三條都不一樣：
它們不算傷害，只是**把一支艦隊的每個分隊依固定規則削一刀**。

兩邊的迴圈完全一致——

```
mov  al, [bp+i]            ; 分隊序號
les  bx, <艦隊記錄>
mov  cl, es:[bx+0Fh]       ; 分隊數
cmp  al, cl
jnb  結束
les  bx, <分隊槽指標>
mov  ax, es:[bx]           ; 艦池索引
mov  cx, 4Eh               ; 78 bytes 一筆
mul  cx
mov  cx, ds:0CFB6h         ; 艦池 far ptr
mov  si, ds:0CFB4h
add  si, ax                ; → 這個分隊的艦池記錄
...
push 0 / push 0 / push 量 / push 記錄 far ptr
call far 203Ah:593h
inc  byte ptr [bp+i]
add  word ptr [bp+槽], 4   ; 分隊槽 4 bytes
jmp  迴圈
```

第三、四個參數都是 0，所以兩條路徑**都留一艘**。差別只在「量」怎麼來。

| 呼叫點 | 量 |
|---|---|
| `03E0:0068` | `min(滿編艘數 ÷ 6, 現有艘數)`——`es:[si+0Ah] ÷ 6`，超過現有就取現有 |
| `1920:00DA` | `現有艘數 × [bp+0Ah] ÷ 100`——`es:[si+8]` 乘上一個百分比再除 100 |

`03E0:0068` 的 `÷6` 是寫死的立即數 `mov bx, 6`，不是查表也不是參數。
`1920:00DA` 的百分比是函式自己的區域變數，設定的地方還沒追。

兩者都不帶亂數。定值的削減比較像**撤退／補給／解散**這類結算，
不像戰鬥——戰鬥那條（`2350:00EF`）的量帶亂數而且量級大得多。
這是形狀上的推斷，還沒有實測支持，標 `hypothesis`。

## 分母 K 讀了一半：`2264:0FC3`

`量 ＝ 目標艘數 × 40 × (攻擊方 +0x16 ÷ K) ÷ 12800` 裡的 K 由
`2264:0FC3` 算，逐行讀到一半，已經看得出它吃哪些東西：

```
艦隊    ＝ ds:C074 ＋ 攻擊方艦艇 +0x01 × 122
[bp+2]  ＝ 艦隊 +0x3D                       ; 艦隊能力第一項
表項    ＝ ds:4E3A ＋ 陣營 × 208 ＋ 艦種 × 26   ; 艦種表（docs/internals/40）
方位    ＝ atan2(目標 +0x48 − 攻擊方 +0x36, 目標 +0x46 − 攻擊方 +0x34)
索引    ＝ 方向索引(方位, 艦隊 +0x4A)          ; 同 docs/re/88 那一套
r       ＝ 表項[+0x18] ÷ 表項[+0x16]          ; 兩個 word 相除（32 位元）
c       ＝ 正弦表[索引 ＋ 64] × 64             ; ＝ cos(索引)
... 再走 3870:0643、39B5:000C、39B5:005C 幾支定點運算
```

形狀像是**橢圓的極座標半徑**（`表項[+0x16]`、`表項[+0x18]` 當兩個半軸，
`cos` 進去算 `1 − …`），也就是艦種的攻擊力**有方向性**。要下定論得先把
那三支定點常式讀完。

這一段順帶把艦種表 `ds:4E3A` 的兩個 word 定位了：`+0x16`（word[11]）與
`+0x18`（word[12]）是這個比值的分母與分子。

## 第一條路徑的量級對不上實測

拿 `s3turn2` 的欄位值算：帝國第 13 艦隊打同盟第 16 艦隊，基本量是
`(0 ÷ 100 ＋ 82) ÷ 10 ＝ 8`，防禦係數 100，所以總損失至多
`8 ＋ 99 ＝ 107`；分攤到旗艦分隊（佔全隊 13%）是 13 艘上下。

而 `-watch` 觀測到的單輪扣除量是 **37 與 50**——大一個量級。

`203A:0593` 有**六個呼叫點**。上面那條（艦隊層的分攤）算出來只有
十幾艘，而實際扣的走的是 `2350:0023` 那條——量級對得上。所以這條
艦隊層的算式雖然逐行讀出來了，**它不是戰鬥結果的主要來源**，
可能用在別的時機（例如整批結算）。

**戰損本身帶亂數**——這是遊戲的設計，不是取樣問題。那個產生器是
標準的線性同餘，已經解出來並驗過（`docs/re/87`）。
