## 五、與 `3982:022D` 對照的人類座位判斷（回答問題 4）

`3982:022D(陣營)`（既有文件，見 `docs/re/295`／`330`）：`陣營==2 ? FF : ds:8F21[陣營==ds:8F25 ? 0 : 1]`——**先把「陣營」映射成「座位」，再查該座位是不是電腦**，用在「某個特定陣營的人是不是人類」這種場合（例如打行星報告要知道「攻擊方那個陣營是不是人類」）。

`0374:0489` **沒有呼叫 `3982:022D`**，做法更直接：**固定對座位 0 查 `ds:8F21`、對座位 1 查 `ds:8F22`**，各自獨立判斷、互不影響：

```
ds:8F21 == 0  → 座位 0 是人類 → 用 ds:8F25（座位 0 的陣營）印一次
ds:8F22 == 0  → 座位 1 是人類 → 用 ds:8F26（座位 1 的陣營）印一次
```

因為完全不看「這一仗跟這個座位有沒有關係」（不比對星域擁有者、不比對艦隊陣營），**兩個人類座位在同一次戰鬥觸發時都會各收到一次通知，即使打的不是自己的艦隊**。這與「這一格有戰鬥」（`+0x13` bit2，第七輪已確認）是唯一的觸發條件；`0489` 本身不重複判斷是否真的有戰鬥。**proven（位元組）**；「這是設計上的廣播式戰情通知，不是特定艦隊的戰報」屬於 **strong inference**（語意合理，但沒有找到官方文件或使用者手冊佐證這個設計意圖）。

若兩個座位都是人類：`3826:0307`（見 §二）在 `ds:8D0A` 尚未開啟時才呼叫 `3603:0006` 建視窗，第二次呼叫沿用同一個視窗、只是 `\x0c` 清空重印——**同一個視窗被連續用兩次，各自完整跑一次 §三的等待**，不是合併成一次。**proven（位元組，`3826:0356` 的開窗判斷只看 `ds:8D0A==NULL`）**

## 六、等待怎麼結束（回答問題 3）

`0374:04B8` 本身不直接呼叫 `3765:006C`；等待邏輯全部包在 `3826:0307` 裡（`workplace/ida/fcx-turnrep-3826.txt` `+0345..0349`：`push word ptr ds:8F38h; call far 3765h:6Ch`）——本輪重讀了這幾行位元組，**確認 `3826:0307` 確實用 `ds:8F38` 呼叫 `3765:006C` 等待，不是憑印象**。`3765:006C` 本身的「左／右鍵按下才結束、放開與鍵盤不算」的實作是既有文件（`docs/internals/61-turn-transition-windows.md` §「等待」）在更早的回合已經逐位元組讀過的結論，本輪沒有重新反組譯 `3765:006C`，是**引用既有 proven 結論**，不是本輪新證據。

本輪新增的位元組證據：**`ds:8F38` 在兩份傾印裡都是 `5A 00`＝十進位 90**，與既有文件「訊息速度預設 90」的說法在這兩局存檔裡對上（這是「這兩局存檔目前是 90」的證據，不是「這個欄位恆為 90」的證據——`ds:8F38` 是可變全域，理論上可能被別處改寫，本輪沒有掃它的寫入者）。

## 七、其他觀察（非五題範圍內，但讀 04B8 時發現）

- `0374:04B8` 在印報告**之前**先 `3705:0349(0)`（整張地圖依擁有者色重繪、順帶把 `ds:F182` 重設為 `0xFFFF`）再 `3705:03FD(星域,5)`（把目前這一格塗成色 5）；印完之後只呼叫 `3705:02BA()`（因為 `ds:F182` 已經是 `FFFF`，這支直接回、不還原）＋`3705:0418()`（上畫面）。**結果是這一格的色 5 高亮在函式返回後不會被清掉**，要等下一次外層呼叫 `3705:0349` 且參數非 0（或下一回合開頭的整片重繪）才會消失。這與 `docs/re/335-ai-order-command-kind.md` 描述另一種報告（星域易主）的「印完 `3705:02BA`＋`0418`，不還原」是同一個慣用組合，**strong inference**（沒有另外拿收據驗證色 5 真的留到下一格才被蓋掉）。

## 八、五題總結

1. **`0374:0489(星域 word)`**：收一個參數（目前格 `ds:8F17`，由 `0374:03E8` 的 `+0434` 傳入）。依序對座位 0（`ds:8F21==0`）與座位 1（`ds:8F22==0`）各自判斷是不是人類，是的話用該座位的陣營（`ds:8F25`／`ds:8F26`）呼叫 `0374:04B8(星域, 陣營)` 印一次報告。`04B8` 組字串（見 2）、開/沿用持久視窗、等待、返回；`04B8` 不修改任何遊戲狀態（沒看到寫入艦隊／星域／提督表，只動地圖著色與視窗/等待相關的顯示狀態）。proven（位元組）。
2. **報告框走 `3826:0307` 持久視窗**（byte-confirmed，`0374:04B8 +053E call far 3826:0307`），格式字串是 `ds:01A9`「`\x03[%d,%s\x03[%d,星系內\n`」（19 bytes）＋`ds:01BD`「`發現敵方艦隊。\n`」（15 bytes，純字面無參數）；`%s` 直接讀「目前格」星域記錄（`ds:A79C + 星域×126`）開頭的 Big5 名稱欄位（`docs/internals/22` 既有 confirmed 的欄位表）；兩個 `%d` 是「該星域擁有者色（`ds:6096[擁有者]`）」與「還原色 `0x97`」。**頭像＝`ds:8F4D[陣營]`（觸發報告的那個人類座位自己的陣營）——是報告者自己的情報專任參謀，不是敵方或任何一支艦隊的提督**；本輪逐位元組重讀 `3826:0307`／`3826:0356` 核對了「座位≠`FFFF`時查`ds:8F4D[座位]`」這條規則，不是照抄舊文件。proven（位元組）。
3. **等待**：`3826:0307` 內部呼叫 `3765:006C(ds:8F38)`；`ds:8F38` 本輪兩份存檔讀到的值都是 90（`5A 00`），與「預設 90 tick」一致（但只是這兩局存檔的觀測值，不是恆定值的證明）。左鍵或右鍵按下都能提早結束（沿用既有 `docs/internals/61` 對 `3765:006C` 本身的 proven 結論，本輪沒有重新反組譯 `3765:006C`）。
4. **只對人類座位印，且與 `3982:022D` 的做法不同**：`0489` 直接查 `ds:8F21`（座位 0）／`ds:8F22`（座位 1），不經過 `3982:022D` 的「陣營→座位」映射，也不比對這場戰鬥跟哪個座位有關——**只要這一格這回合有戰鬥，兩個人類座位都各收到一次通知**（兩者都是人類時，同一視窗連續開兩次、各自完整等待）。proven（位元組）。
5. **呼叫者**：對兩份獨立傾印做 far call ＋ 段內 near call 全量掃描，`0374:0489` 只有一個呼叫點——`0374:03E8` 的 `+0434`（已知的那一處），**沒有找到其他呼叫者**。`0374:04B8` 同樣只被 `0489` 內部的兩處（`+049A`、`+04AF`）呼叫。盲點：兩種掃描都抓不到間接呼叫（跳表／暫存器目標），本輪沒有另外驗證是否存在這種呼叫。proven（位元組，附盲點說明）。
