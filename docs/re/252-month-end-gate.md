# 252 — 月底結算掛在哪：`2703:03AD`，閘門是回合數的十的倍數

`docs/re/251` 確定了「戰鬥不會讓回合結束被跳過」，但留著
「月底結算實際掛在哪一支還沒定位」。定位了。

## 怎麼找的

呼叫圖沒用——這一支跟 `056A:0468`、`056A:078E` 一樣走模組管理器的間接
向量，`farcall_to.py` 與段內 `E8` 掃描都是 0 處（拿 `2703:0853` 做正對照
有 5 處，所以掃描器沒壞）。

改從**錢**下手：掃整份傾印裡出現 `52 8f`（`ds:8F52` ＝ 軍事費）的指令，
17 處裡有一處是**加法**：

```
lin 2745B  01 b7 52 8f   add [bx+8F52h], si     ; si ＝ ds:8F6A[陣營]（總稅收）
lin 2745F  11 8f 54 8f   adc [bx+8F54h], cx
```

其餘是減法（`056A:09EB` 的維持費、`113A:0729` 的移動費，`docs/re/236`、
`237`）與讀取。往回找函式開頭，落在 **`2703:03AD`（線性 `0x273DD`）**。

## `2703:03AD`

```
273E7  bl = ds:8F1D                    ; 目前陣營
273ED  al = ds:8FD4[陣營]              ; Blend
273F1  ds:8FF8[陣營] = al              ; ← 難度索引從 Blend 抄過來
27400  ds:8F6A[陣營] = ds:8F6C[陣營] = 0   ; 總稅收歸零
2740B  for 星域 i in 0..31:
2741E    if 星域[+12h] != ds:8F1D: 跳過      ; 只算自己的
27430      2703:0AB8(星域, 1)                ; 算這一格的稅並累加（docs/re/26）
2743B      星域[+27h] = 星域[+26h]           ; 稅率抄成「結算當下用的那一份」
2745B  ds:8F52[陣營] += ds:8F6A[陣營]        ; 軍事費 += 總稅收
```

`ds:8FF8[陣營] ← ds:8FD4[陣營]` 那一行順帶解掉了 `docs/re/34` 留的
「`ds:8FD4`／`ds:8FF8` 是兩張以陣營索引的表」——**後者是前者在月底的快照**。
`+0x26` → `+0x27` 那一行也對上 `docs/re/33`（結算用的是 `+0x27`）。

## 閘門：回合數是十的倍數

`ds:8F18` 是回合計數器，一個月十回合（`docs/re/26`）。直接 poke 它：

| 批次 | poke | `2703:03AD` 有沒有跑 |
|---|---|---|
| `monthgate` | `ds:8F18 = 9` @ `#211000000` | **沒有**（回合在 `#221191746` 進位成 10）|
| `monthgate2` | `ds:8F18 = 10` @ `#211000000` | **有**，從 `#212220099` 起 |

兩份都在按下「實行」（`#210000000`）之後、`2703:08DE`（回合結束，
`#218908267`）之前。所以**閘門是「這一回合的回合數是十的倍數」，
而且在那一回合的處理裡跑，不是在回合結束之後**。

## 對照 `docs/re/251` 的主迴圈

```
056A:000C()              ; 這一回合的命令階段  ← 月底結算在這一串裡
0374:03E8(…)             ; 逐格開戰
056A:078E()              ; 回合結束
ds:8F18 ++
```

`056A:000C` 跑在 `0374:03E8`（開戰）**之前**，而量到的觸發時點也在
`2703:08DE` 之前。所以**月底結算在戰鬥之前**——戰鬥更不可能讓它被跳過，
`docs/spec/033` 那個缺口可以收掉。

## remake 的順序差異

remake 的 `advanceTurn` 是

```
turn++ → runBrain → 扣維持費 → 移動 → 開戰 → endOfTurn → 跨月結算
```

**跨月結算在最後**。原版是在**最前面**（`056A:000C` 那一串），
`docs/re/236` 量到的鏈也是這個順序：月底結算（同盟 50000 → 61087 →
45848）→ AI 回合 → 維持費 426 → 移動 492 → 44930。

這是一個**還沒修的順序分歧**。動它會改到錢的流向，而錢有既有收據撐著
（`TestFirstAITurnMatchesReceipt`），所以要先有一份「同一回合裡月底、
AI、維持費三者先後」的收據再改，不在這一輪順手動。

## 還沒解

`2703:03AD` 的**呼叫者**還是沒找到（間接向量）。量到的觸發是成串的
（`monthgate2` 裡一輪約 32 次、再一輪約 70 次），所以「誰呼叫它、
一個月底呼叫幾次」還沒解——這一輪確定的是**閘門條件**與**相對位置**。

## 一條方法

**函式進入點掃不到時，改掃它一定會動的那個變數。** 月底結算的呼叫者走
間接向量，怎麼掃都是 0 處；但它一定會把稅加進軍事費，而
`add [bx+8F52h], si` 在整份傾印裡只有一處。
**從「它一定會寫哪裡」找，比從「誰呼叫它」找可靠。**

---

> **位址錯了兩個位元組，閘門那一段的結論收回**（`docs/re/253`）：
> `0x273DD` 是前一支的 `pop bp`，真正的進入點是 `0x273DF` ＝ `2703:03AF`。
> 拿正確位址重跑，`monthgate3`（poke 10）與 `monthgate4`（poke 9）
> **都只在 `#155479789` 跑一次、時點相同**——那是新遊戲初始化算一次稅，
> 不是月底。本文的「閘門是回合數的十的倍數」與「月底結算在開戰之前」
> 兩句不成立。靜態讀出來的那一段（只有一處加法、`ds:8FF8` ← `ds:8FD4`、
> 累加流程）不受影響。
