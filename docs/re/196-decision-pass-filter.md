# 196 — 那道過濾：`+0x00` bit0 沒設、又不在交戰格，就不決定

`docs/re/195` 從收據推出「`2E54:005D` 沒有決定每一支，還有一道過濾」。
這一輪把 `2E54:005D` 讀完，過濾就在裡面。

## `2E54:005D` 的骨架

```
對 i = 0 … 31：
    若 艦隊[+0x04] == 0FFh：下一支                 ; 沒在用
    若 艦隊[+0x01] != ds:8F1D：下一支              ; 不是我方
    艦隊[+0x79] = 0FFh                             ; ★ 先填未定
    星域 = ds:A79C + 艦隊[+0x06] × 126
    若 艦隊[+0x08] == 4：艦隊[+0x79] = 0、ds:D60E++、下一支

    若 艦隊[+0x00] bit0 有設：
        參 = (ds:8F1D == 0) ? 星域[+0x29] : 星域[+0x28]
        若 星域[+0x13] & 14h（bit2｜bit4） 或 參 != 0：
            …（未讀完）
        若 星域[+0x12] == 艦隊[+0x01]：
            艦隊[+0x08] = 3、艦隊[+0x07] = 艦隊[+0x06]     ; 原地出擊
        否則：2E54:1955(艦隊)                              ; 往首都退一格
        艦隊[+0x79] = 0、ds:D60E++、下一支
    否則（bit0 沒設）：
        若 星域[+0x13] bit2 沒設：**下一支**（`+0x79` 留著 0FFh）★
        若 2E54:16F5(艦隊) != 0：艦隊[+0x79] = 3、ds:D5CE[星域]++、ds:D60E++
        否則：2E54:1955(艦隊)、艦隊[+0x79] = 0、ds:D60E++
```

## 過濾就是那一條

**艦隊 `+0x00` bit0 沒設、而且所在星域 `+0x13` bit2（有戰鬥）也沒設
→ 這一趟不碰它，`+0x79` 留著 `0xFF`。**

`2E54:143F` 挑候選要求 `+0x79 == 0xFF`（`docs/re/168`），所以**正是這些
艦隊才會被後面五個階段挑走**——`docs/re/195` 從收據推的結論對上了。

`s3aicomp` 上 `+0x79` 是 1 的槽 28 與 31 就是這一類：`+0x00` bit0 沒設、
所在星域沒有戰鬥。

## 順帶：`+0x13` 的 bit4

`docs/internals/22` 把星域 `+0x13` 的 bit4 標成未解。這裡它與 bit2
**一起被測**（`test byte es:[bx+13], 14h`），而且只出現在 `+0x00` bit0
有設的那一路。bit2 是「這一格有戰鬥」（`docs/re/173`），
所以 bit4 是同一類的旗標（形狀推論，還沒解）。

## 艦隊 `+0x00` bit0

`docs/internals/33` 記「把艦隊分成兩類，`2E54:005D` 依它走不同的判斷」，
`docs/re/168` 記 `2E54:1574` 把它當「無法戰鬥」而直接回 0 分。
兩邊一致：**bit0 有設的那一類不走 `2E54:16F5` 的戰力比較，
也不會被評分挑上**——它們在 `2E54:005D` 就被處理完（原地出擊或退一格）。

## `ds:D60E` 還差一格

收據上同盟六支在用、`ds:D60E = 5`。照這一輪的讀法，被跳過的（`+0x79`
留 `0xFF`）應該有兩支（28、31），那 `ds:D60E` 該是 4。**差一格**。
可能是 `ds:D60E` 在別處也被加，或那兩支其中之一其實走了別條路。
要對 `2E54:005D` 設 `-regs-at` 逐支看才能定；機器現在 load 45，排著。

## 還沒讀

`+0x00` bit0 有設那一路裡「`星域[+0x13] & 14h` 或 `星域[+0x28/29] != 0`」
之後的那一段。
