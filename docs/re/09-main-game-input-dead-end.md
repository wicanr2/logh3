# RE 09 — 遊戲本體的輸入：熱區是「相對視窗原點的格子」

日期：2026-09-06
執行器：dosgolem-logh3（`-watch-screen`／`-keys-at`／`-regs-at` 的堆疊傾印）
狀態：**已解**。

## 事件怎麼進到遊戲裡（confirmed）

遊戲不直接讀 `int 33h`，它有自己的環狀事件佇列（容量 16，一筆 12 bytes）：

```
3765:00BF  取事件
  00CC  cmp word [F24C],0    ; 佇列長度，0 就回傳「沒有事件」
  00D6  les bx,[F248]        ; 頭指標
  0110  add word [F248],0C
36AD:0568  mov [F24C],ax     ; 滑鼠回呼／鍵盤 ISR 入隊
```

一筆的內容是 `{type, 時間戳, x, y, …}`；`type=1` 是按下、`type=4` 是放開。
主迴圈 `0654:07B0` 取到 `type=1` 就呼叫 `0654:07F7`。

## 命中測試（confirmed）

`0654:07F7` 拿座標去 `37A9:01F9` 找「點到哪個東西」，找不到就什麼都不做。
熱區清單在 `DS:09D6`，每筆 12 bytes：

| 位移 | 內容 |
|---|---|
| +0 | 格子 x |
| +1 | 格子 y |
| +2 | 寬（格） |
| +3 | 高（格） |
| +4 | 啟用旗標，0 ＝ 跳過 |
| +8 | far 指標（該項的處理常式或資料） |

`FF FF` 是清單結束。

**座標是格子，而且是相對視窗原點的。** 換算在 `341B:044A`：

```
044F  mov ax,[bp+0E] / shr ax,4      ; 格子 x ＝ 像素 x / 16
045B  sub al,es:[bx+5]               ;   再減掉視窗原點的格子 x
0465  mov ax,[bp+10] / div 20        ; 格子 y ＝ 像素 y / 20
0473  sub al,es:[di+6]               ;   再減掉視窗原點的格子 y
```

會計報告那個畫面的視窗原點是格子 `(10,3)`，兩個熱區是 `(17,13)` 與
`(17,12)`、各 2×1 格，換算成像素就是 **(432,320)–(463,339)** 與
**(432,300)–(463,319)**。點下去畫面立刻換掉。

## 這一題為什麼難找

畫面上那兩個小方塊看起來就在輸入框那裡，照著像素點 `(448,350)`
差了一整格——**熱區在方塊上方 20 個像素**。而且不管點哪裡都毫無反應、
也沒有任何錯誤，所以「點擊沒送到」與「點錯地方」在畫面上完全一樣。

以下假說都花了一輪才排除，每一個都有實驗反證：

| 假說 | 反證 |
|---|---|
| 點擊沒送到 | 佇列裡有正確的 type 與座標 |
| 沒送移動事件、游標位置不同步 | 補送 `EvMove` 之後行為不變 |
| 位置不對（隨便掃） | 7×4 網格 28 點、8 個星球位置全掃過 |
| 要按鍵 | space／esc／enter／方向鍵／數字全試過 |
| 音樂沒跑起來 | `-adlib` 後行為不變 |
| 垂直回掃卡住 | `3DAh` 的回掃位元本來就會變 |

轉折點是**印出堆疊上的參數**（`-regs-at` 現在會傾印 `[bp+0]` 起的 12 個
word）：只看暫存器看得到「呼叫了誰」，看不到「拿什麼去呼叫」。
拿到轉換後的格子座標 `(8,10)`，跟輸入的像素 `(288,270)` 一比，
原點 `(10,3)` 就出來了。

兩個熱區各自打開一個新畫面：

  戰艦 3790、高速戰艦 1260、巡航艦 6830、航空母艦 630、驅逐艦 4550、
  運補艦 3250、修護艦 1030，各配部隊數。
- **次月份船艦建造計劃**：預算分配的百分比、上下箭頭、金額、船艦數、
  部隊、建造中——這是第一個看到的**可操作介面**。
