# 143 — 補給面板印什麼

`docs/re/140` 找到「選對象時右側面板由 `1930:0AA2` 印」。這一篇把它印的
內容讀出來。視窗是哪一個、多大，見 [`142`](142-status-panel-window.md)：
`ds:9890`，內容 **8 × 8 格**，左上角在格 (30,10)。

## 印的順序

```
1930:0AA2(補給艦, 目標)
    3982:022D(補給艦[+0] 陣營) != 0 → 直接回        ; 電腦方不畫
    ds:9B7A = 0FFFD
    艦種列 = ds:4E3A ＋ 陣營 × 0xD0 ＋ 艦種 × 0x1A
    滿載量 = 艦種列[+0x10]／[+0x14] × 艘數（3CC9:0009 32 位元乘法）

    3617:003A(視窗, ds:3F29 "\x0c%s  第", 陣營名 ds:60F4[陣營])
    3982:0038(視窗, 艦隊記錄[+2])                    ; 艦隊編號
    3617:003A(視窗, ds:3F31 "艦隊")
    3617:003A(視窗, ds:3F36 "運輸艦      %4u", 補給艦[+8])
    3617:003A(視窗, ds:3F46 "飛彈      %6lu", 補給艦[+0E]/[+10])
    3617:003A(視窗, ds:3F55 "戰鬥機    %6lu", 補給艦[+12]/[+14])
    目標 != NULL：
        3617:003A(視窗, ds:3F64 "%-8s    %4u", 艦種名 ds:613A[目標艦種], 目標[+0])
        3617:003A(視窗, ds:3F70 "飛彈    ")  …
```

## 版面靠「剛好一整列」做出來的

格式字串裡**沒有換行**（`\x0a`），只有開頭那個 `\x0c` 清空。分行是靠
**每一段剛好佔滿 8 格**、寫到第 9 格自動折行（`3617:02A5` 先比
`[+1C]` 與 `[+0B]`，`docs/re/141`）：

| 字串 | 全形 | 半形空白 | 數字 | 合計 |
|---|---:|---:|---:|---:|
| `運輸艦      %4u` | 3 格 | 6 ＝ 3 格 | 4 ＝ 2 格 | **8 格** |
| `飛彈      %6lu` | 2 格 | 6 ＝ 3 格 | 6 ＝ 3 格 | **8 格** |
| `戰鬥機    %6lu` | 3 格 | 4 ＝ 2 格 | 6 ＝ 3 格 | **8 格** |

所以那些看起來像「排版用的空白」其實是**對齊到視窗寬度的填充**，
少一個空白整個面板就會錯位。

## 顏色是字串自己帶的

陣營名表 `ds:60F4`（一筆 4 bytes 遠指標）指到的不是純文字：

```
ds:60BA  \x03[150,帝國軍\x03[151,
ds:60CD  \x03[149,同盟軍\x03[151,
ds:60E0  \x03[151,中立軍\x03[151,
```

`\x03[n,` 是換顏色（`docs/re/141`）。150 ＝ `0x96` ⇒ 底 9 字 6、
149 ＝ `0x95` ⇒ 底 9 字 5，印完切回 151 ＝ `0x97`。

帝國 ⇒ 字色 6、同盟 ⇒ 字色 5，正好是 `docs/internals/34` 量右側狀態欄
時記成「陣營色」的那兩個色號。**狀態欄是不是也走這張表還沒讀**（那一列
的印法在 `1CC5:*`／`1D00:*`），但顏色由字串自己帶著這件事已經確定——
remake 目前把它當成版面常數（`screen-battle.json` 的 `faction_ink`），
畫出來一樣，機制不同。

艦種名表在 `ds:613A`，八筆：戰艦／高速戰艦／巡航艦／航空母艦／驅逐艦／
運補艦／修護艦／偵察艦。兩張表都抄進
[`data/faction-and-kind-names.json`](../internals/data/faction-and-kind-names.json)。

## 每一段都剛好一格／一列

`3982:0038(視窗, 編號)` 的兩條路都只佔**一格**：

```
編號 < 10  → ds:8E86 "\x06%d\x07"   ; 開半形轉全形 → 一個全形數字 → 關
編號 >= 10 → ds:8E8B "%2d"           ; 兩個半形塞一格
```

所以第 0 列是 陣營名(3 格) ＋ 兩個半形空白(1 格) ＋「第」(1 格) ＋
編號(1 格) ＋「艦隊」(2 格) ＝ **剛好 8 格**。整個面板的分行都是這樣
擠出來的，沒有一個換行字元。

## 什麼時候不畫

開頭的 `3982:022D(陣營)`：陣營 2（中立）回 `0xFF`；`ds:8F25` 等於該陣營
時回 0；否則回 `ds:8F21`／`ds:8F22`（那一方是不是電腦控制）。回非 0
就整支跳過——**電腦方動手時不畫面板**。

第一次呼叫（`1930:06BD`）傳的目標是 **NULL**（`xor ax,ax; xor bx,bx`），
所以剛進選對象狀態時只印前四列。

## 進 remake

`ui.TextBuffer.Printf`（`%s`／`%c`／`%d`／`%u`，含 `-`／`0`／寬度／`l`；
沒見過的轉換原樣輸出，不猜）。格式化出來的位元組與字串本身走同一條
`PutByte`，所以控制碼、全形前後半與自動折行都由那一層處理。

`screen.SupplyPanelSpec`／`DrawSupplyPanel`／`DrawSupplyEndButton`，
版面與六段格式字串在
[`data/supply-panel.json`](../internals/data/supply-panel.json)。

## 「結束」鈕是另一個視窗

`1629:0154`（在 `1930:0AA2` 之後、進迴圈之前呼叫）：

```
3603:0006(&視窗 ds:9BF8, 色 0x97, 格 (34,17), 4 × 1 格, 旗標 0)
    旗標 0 → 不加框，實際就是 4 × 1 格
視窗[+2] = 0x10                       ; 左端
    3617:003A(視窗, ds:3C42 "  ")
視窗[+2] = 0x08 ; 視窗[+1] = 0x87      ; 本體
    3617:003A(視窗, ds:3C45 "結束")
視窗[+2] = 0x20 ; 視窗[+1] = 0x97      ; 右端
    3617:003A(視窗, ds:3C4A "  ")
視窗[+2] = 0
341B:0145(視窗)
```

**按鈕就是三段旗標**（`docs/re/138` 那三個裝飾位元），不是元件。
格 (34,17) ⇒ 像素 (544, 380)；收據上量到的非底色範圍是 x 558–593，
正好是「第 0 格的最後兩行 ＋ 第 1–2 格 ＋ 第 3 格的前兩行」。

## 收據 `s3sup`

前置序列同 `s3cmdsq3`，注入改成 **390 bytes**（艦艇紀錄 137–141）：
五筆的陣營都寫 0，其中 137 的 `+0x04` 再寫 5（運補艦）。
單一 `-poke` 只能寫一段連續範圍，而候選要求同陣營——只改一筆的話
半徑內一個同陣營單位都沒有（最近的約 196 像素、半徑 192），所以要把
同一支艦隊那幾筆一起改。最後多點一下 (270,290)（分隊選單第三項）。

面板那個視窗的 8 × 8 格（16,384 個像素）與收據**逐位元組相同**。
