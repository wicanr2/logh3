## 怎麼找到的

主畫面的熱區清單（`54B3:09D6`）倒出來只有兩筆就 `FF FF` 結束，
所以主畫面點不出第三個畫面。往下走只能靠既有分支上的按鈕——
於是在**次月份預算計劃**那一頁做座標掃描：一次跑五個候選位置，
每次點完都傾印，比對「與前一張差幾個像素」。

| 點的位置 | 與前一張的差 | 是什麼 |
|---|---|---|
| (472,285) | 463 px | 改動數字（造船比例 25% → 26%）|
| (472,325) | 48,857 px | **開出新畫面：796 年 1 月份會計報告** |
| (410,370)／(458,370)／(490,370) | 0 px | 沒有作用 |

先前直接猜按鈕位置點 (463,370)，畫面 0 差異——猜座標的命中率太低，
掃描才問得出來。

## 這一組數字驗證了什麼

`docs/re/12` 的三條公式是從**預算計劃**那一頁的數字推出來的。
這一頁是**另一個畫面自己算的**，而且造船比例已經被改成 26%，
所以是獨立的第二組資料：

| 公式 | 驗算 |
|---|---|
| 合計收入 ＝ 軍事費餘額 ＋ 稅收 | 50,000 ＋ 10,741 ＝ 60,741 ✓ |
| 船艦建造費 ＝ 合計收入 × 比例（捨去）| 60,741 × 26% ＝ 15,792.66 → **15,792** ✓ |
| 總計 ＝ 合計收入 − 船艦建造費 | 60,741 − 15,792 ＝ **44,949** ✓ |

而且「軍事費餘額 50000」正是 `docs/re/12` 在記憶體 `5DA82` 看到的那個
dword——先前只能說「猜是國庫」，現在畫面自己把名字印出來了。

測試：`internal/rules` 的 `TestBudgetAtOtherPercent`。
