# 111 — 戰術選單「資料」的版面

`docs/re/109` 取到畫面、只量了粗略的塊。這一輪照專案量版面的既有做法
（`tools/scripts/screenspec.py` 的框剝離、格點抽字、字碼反查）把骨架
逐像素量出來。

## 它蓋掉哪一塊

`s3data0` 是**同一條輸入序列停在選「資料」之前**（第 1,090,000,000 步）
的同狀態底圖。與 `s3data` 逐像素比：

```
左側 x 16–462、y 60–419 全部連續改變（140,989 個像素）
右下狀態欄 (465,220)–(623,419)  0 個像素不同
右上小地圖 (465,59)–(623,219)   216 個像素不同
```

右上那 216 個是**戰場自己的動畫**（色 3↔7 對稱互換 83 對 ＝ 視野方框在
閃，其餘是單位標記），不是「資料」畫的。所以這張畫面只換掉左邊那一塊，
右邊兩塊維持戰鬥畫面原樣。

## 文字是字串引擎畫的，不是逐欄擺位

三張表頭在記憶體裡是三條完整的 48 位元組字串（線性 `0x580D5` 一帶），
連空白都寫死：

```
艦隊資料                        艦數  最大  士氣
行星資料          經濟力  防衛力  補給  BHCADTE
敵艦隊資料                      艦數  最大  士氣
```

48 位元組 ＝ 24 個全形格。把它從 x ＝ 48 開始畫，全形進 16、半形進 8，
量到的位置就全部對上：

| 字 | 字串裡的格 | 算出來的 x | 量到的 x |
|---|---:|---:|---:|
| 艦數 | 16 | 304 | 304 |
| 最大 | 19 | 352 | 352 |
| 士氣 | 22 | 400 | 400 |
| 經濟力 | 9 | 192 | 192 |
| 防衛力 | 13 | 256 | 256 |
| 補給 | 17 | 320 | 320 |
| BHCADTE | 20 | 368 | 368 |

`BHCADTE` 是**七個半形字母**，每個進 8：B(368) H(376) C(384) A(392)
D(400) T(408) E(416)。點陣逐格取出來對得上，而且 `BHCADTE` 這個字串
在記憶體裡出現三次（`0x569D6`、`0x580D5`、`0x5D94A`），旁邊還有小寫的
`bhcadte` 與 `PLPFZ`／`AD`／`012BMF` 幾張短字母表。**七個字母各代表
什麼還沒解**。

同一塊還有整列的格式片段：

```
%-16s    %6u    %6u    Mo:  Mx:  Fo   Fx   o  x
M*:F* *******              ← 不是自己的行星就整段印這條
第？艦隊  第？部隊          ← ？ 是兩個半形數字填進去
%-18s    ？  %s    ？？／？？    ？    %4u  ／%4u     %3u
```

艦隊那一列從 x ＝ 48 起算：`第`(格0) ＋ 兩個半形數字(格1) ＋
`艦隊`(格2–3) ＋ 兩個空白(格4) ＋ `%-18s`(格5–13，x128 起) ＋
艦種(格14，x272) ＋ `%4u`(x304) ＋ `／`(x336) ＋ `%4u`(x352) ＋
三個半形空白 ＋ `%3u`(x408)——與量到的位置逐一相同。

字串裡還夾著 `\x01[%d,%d,` 這種跳脫（`ESC [ a , b ,`），所以**同一行
可以換色**，這就是最左欄色 6、其餘色 7 的來源。

再往下還有一段目前這張畫面上沒出現的：「指揮官 %s%s」「等級 %2d
經驗值 %6lu」「副官」「無」「艦隊士氣值　統率力」——點某一列大概還有
一層明細，未取證。

## 還沒解的

- `BHCADTE` 七個字母的意義，以及 `o`／`x`／`*` 的判準。
- 十四列滿了之後怎麼捲動。
- 「指揮官／副官／經驗值」那一段在哪裡出現。

## 逐位元組對上之後的修正

照上面的量測畫出來之後與收據逐像素比，有三處要改（改完三個分頁都是
0／160,920，見 `docs/spec/021`）：

- **標籤框是 66 寬**（x 32–97），不是 65；右緣與下緣的暗邊算在框裡。
- **標籤裡的小方塊是 11 × 11**（(36,85) 起）：外面還有一層外凸的立體邊
  （上左 7、下右 3），裡面才是上面量到的 9 × 9 色 15 圈。中間 5 × 5
  **沒選中時是色 9**（視窗底色），選中才填色 2。
- **右邊那一欄是三塊**，不是一條槽：(434,120,14,20)、(434,140,14,240)、
  (434,380,14,20)。上下兩塊與表列同高。

另外兩件與字有關的：

- 全形斜線的字碼是 **`A1FE`**，不是 python 的 big5 編碼器吐出來的 `A241`
  （兩個都是「／」，字形不同：`A1FE` 的斜度較陡、兩像素寬）。
- **最左那一欄的顏色是擁有者的陣營色**（帝國 6、同盟 5），不是固定的
  色 6：行星那一張裡雷奧米爾（帝國）是 6，謝拉德與達希利（同盟）是 5。
  對應的是「不是自己的行星就整段印 `M*:F* *******`」——同一份判斷。

## 文字引擎：一格 16 像素

`docs/internals/31` 早就寫過「字碼 < 0x80 是兩個半形字塞在同一格」，
這張畫面把**為什麼一定要併格**逼了出來：立體邊與加粗都是**整格
一起做**的。

- 加粗是 `v | v>>1`。整格 16 位元一起做的時候，左半那個字最右一行
  加粗出來的那一行會落到右半的地盤上；拆成兩個 8 位元去做，兩邊都
  被丟掉。症狀是粗體的半形字右邊少一豎（表頭 `BHCADTE` 的 E）。
- 立體邊要**整格先畫完再畫兩個字身**。一個字一個字畫（陰影、字身、
  陰影、字身）的話，右半那個字的陰影會蓋掉左半那個字的最後一行
  （`Mo:` 的 M 右邊那一行被 `*` 的陰影吃掉）。

兩條都改進 `internal/ui`（`halfPass`、`DrawCellClipped`），既有的
十幾張畫面重跑全部維持 0。
