# 125 — 真的下一次艦隊移動再按實行：量到什麼

收據 `s3fltmove`：與 `s3cmdrange` 同一條前置序列與注入，之後
點旗艦 → 點「移動」 → 點畫面 (200,300) → 在同一點確定朝向 → 開戰術選單
按「實行」，最後傾印記憶體。第 28 艦隊的記錄前後：

| 位移 | 之前 | 之後 |
|---|---|---|
| `+0x48` 艦隊行動 | 0（移動）| **1（戰鬥）** |
| `+0x4A` 現在朝向 | 190 | **163** |
| `+0x4C` 目標朝向 | 168 | **190** |
| `+0x5C`／`+0x5E` 現在位置 | (1330, 941) | (1330, 941) |
| `+0x60`／`+0x62` | `FFFF`／`FFFF` | **(1330, 941)** |
| `+0x64`／`+0x66` 目的地 | (1320, 812) | **(1240, 840)** |
| `+0x52`／`+0x54` 每回合行程 | 240 | **160** |
| `+0x56`／`+0x58` 剩餘行程 | 430,448 | 249,108 |

## 下命令那一段完全對上

點的是畫面 (200,300)，視野位移 (1040,540)（原點 (16,60)）→ 世界
**(1240,840)**，與寫進 `+0x64`／`+0x66` 的值一個像素不差。
`+0x60`／`+0x62` 從 `FFFF` 變成現在的位置——那一格是**下命令時才寫的
原點備份**（`docs/re/120` 讀到的那兩行）。`+0x4C` ＝ 190 ＝ 確定朝向時
游標停在目的地上，所以用了預設值（艦隊當時的 `+0x4A`），與
`docs/re/122` 的規則相符。

## 轉向的規則得到獨立驗證

從 (1330,941) 指向 (1240,840) 的方位是 **162.34**（一整圈 256）→ 163。
而 `+0x4A` 正好從 190 變成 163。用 `docs/re/123` 的規則走：

```
第一步：|190 − 163| ＝ 27 > 回轉速度 15 → 轉 15 → 175
第二步：|175 − 163| ＝ 12 ≤ 15        → 一次到位 → 163
```

**兩步，第二步剛好落在「一次轉到位」那條分支上。** 這是從畫面／記憶體
獨立量到的，不是把反組譯再讀一次。

## 但是：引擎把命令改掉了

`+0x48` 從 0（移動）變成 **1（戰鬥）**，而且 `+0x52`／`+0x54`（每回合行程）
跟著從 240 變成 160 —— 240 ＝ 巡航速度 30 × 8、160 ＝ 戰鬥速度 20 × 8。
所以**行動一改，每回合的行程就跟著換成對應的速度**。

> 這推翻 `docs/internals/33` 對 `+0x52`／`+0x54` 的「整場只在開戰時寫一次」。

艦隊自己**沒有前進**（`+0x5C`／`+0x5E` 沒變）：剩餘行程 430,448 換算成
16.16 是 6.57，不到一步（8.0 ＝ 524,288），所以這一回合只轉得動、走不動。
（那個剩餘值一開始就不到一步，所以這一輪也還沒看到「每回合補滿」那一步；
補的時機與扣的量對不上——花掉 181,340 ≈ 2.77，兩次轉向若各扣 8.0 應該是
1,048,576。**扣法還沒解。**）

## 分隊全部動了，但不是跟著移動命令

九個分隊的現在位置全部變了，而且**目的地被寫成與新位置相同**，
`+0x1E` 一直是 `7F`（沒有自己的命令）：

```
組1 (1266,944) → (1282,983)      組3 (1362,939) → (1354,920)
組4 (1394,938) → (1378,899)      組6 (1365,1003) → (1396,969)
```

位移方向互不相同（有的往右下、有的往左上），不像跟著一個移動命令走，
**像是照新的行動（戰鬥）重排隊形**。旗艦（組 0）沒動，位置仍等於艦隊的
`+0x5C`／`+0x5E`。

所以 `docs/re/124` 最後那一項還沒解，而且問題要換個問法：
**不是「艦隊的目的地怎麼散給分隊」，而是「分隊在沒有自己命令時，
每回合被排到哪裡」**。要在**附近沒有敵人**的局面再量一次才分得開
——這一次引擎把移動改成戰鬥，兩件事混在一起了。

## 對 remake 的影響

旗艦的「移動」仍然不接。這一輪確認了下命令那一段（寫哪三對欄位）
與轉向的規則，缺的是「分隊每回合被排到哪裡」與行程的扣法。
