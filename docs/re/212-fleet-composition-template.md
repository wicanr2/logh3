# 212 — 新編艦隊的編制從 `ds:2BC6` 的樣板來，`[2]`／`[3]` 的來源解出來了

`docs/re/211` 的結論是「remake 建出來的艦隊是空的，下一步是讓它分到
艦艇」。這一輪追原版怎麼填那些編制槽。

## 呼叫鏈

```
2D76:0611(提督編號):
    07F9:023B(提督) == 0 → 回 0                    ; 存量不夠，編不成
    提督[+0x09] &= 7Fh；提督[+0x09] = 07F9:03AC()  ; 配艦隊槽
    提督[+0x07] == 0FFh → 從 ds:5F78[編號] 填副官
    07F9:033A(提督) != 0 → 副官[+0x09] = 提督[+0x09]
                         否則 → 提督[+0x07] = 0FFh
    槽 = 297B:0066(提督編號)
    艦隊 = ds:C074 + 槽 × 122
    艦隊[+0x09] = 提督[+0x08] >> 4                 ; 類別鍵（docs/re/204）
    0FF4:11F4(艦隊, 類別鍵)                         ; ← 填編制
    297B:03EB(槽, 1)
    2703:0853()
    回 1
```

**`0FF4:11F4` 才是填編制的那一支**（線性 `0x11134`）。

## `ds:2BC6`：一個類別鍵 20 bytes

```
樣板 = ds:2BC6 + 類別鍵 × 20                       ; 10 組 × 2 bytes
艦隊[+0x0F] = 1                                    ; 先算一組
對 i = 1 .. 艦隊[+0x0E] − 1：                      ; 應有組數
    a = 樣板[i].第一個 byte
    （星域擁有者 == 1 且 a == 0 時改用 1）
    v = 0FF4:0E84(a)
    …（a 與星域擁有者、v 與 4 的比較決定要不要改用 0FF4:1350 換一個）
    槽[i][+2] = a
    槽[i][+3] = 樣板[i].第二個 byte
```

`docs/internals/33` 記著編制槽是「每組 4 bytes：`[0..1]` 艦艇池索引、
`[3]` 隊形槽索引、**`[2]` 未知**」。現在知道 **`[2]` 與 `[3]` 都是從這張
樣板抄過來的**，而 `[2]` 會拿去和星域的擁有者比——它是一個與陣營同值域
的東西，**確切語意仍未解**。

表已經倒成 `docs/internals/data/fleet-composition-templates.json`
（`tools/scripts/fleet_templates.py`）。十六個鍵的第一組都是
`(0, 20)`，其餘各不相同。

## 還沒讀完的

- `0FF4:0E84(a)` 與 `0FF4:1350(艦隊, a)`：決定實際採用哪一個值。
- **艦艇池索引（槽 `[0..1]`）在哪裡填**——那才是「從首都存量分到艦艇」
  的那一步，還沒定位。
- `艦隊[+0x0E]`（應有組數）是誰設的：`0FF4:11F4` 讀它當迴圈上界，
  但這一支沒有寫它。

## 對 remake 的意義

`ai.NewFleet` 要長出編制的話，缺的東西按順序是：

1. `+0x0E`（應有組數）從哪來；
2. 艦艇池索引怎麼從星域存量分出來；
3. `[2]`／`[3]` 照樣板抄（**這一項現在有資料了**）。

第 3 項可以先做，但沒有第 1、2 項它撐不起維持費——所以這一輪**不動
`ai.NewFleet` 的形狀**，只把樣板表倒進版控。

## 一條方法

**一層一層往下讀的時候，每讀完一層就把該層的資料表倒出來。**
樣板表是這一輪唯一「即使上下游都還沒讀完也不會過期」的產物——
它是原版的位元組，不是推論。剩下三個未讀項全部是程式邏輯，
可以下一輪再接。
