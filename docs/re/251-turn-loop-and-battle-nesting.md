# 251 — 回合的主迴圈：戰鬥是巢狀的，而且一個回合打完所有交戰星域

`docs/spec/033` 留著一個沒有證據的缺口：「`advanceTurn` 遇到戰鬥提早
`return`，月底結算那一段不跑——原版在戰鬥回合會不會結算沒有證據」。
把主迴圈讀完就有證據了，而且順帶抓到 remake 的第二個分歧。

## 找法

`flagpass` 量到回合計數器 `ds:8F18` 的寫入者是 `0374:03DD`
（`docs/re/245`）。那個位址往回退幾個位元組就是主迴圈的尾巴。

## 主迴圈：`0374:0343`（線性 `0x03A83`）

```
03AA5  loop:
         if [bp+0] == 0:
             04F8:000E()              ; 非 0 → 整個結束
             ds:8F1D = 0FFh
             3705:0349(1)
             056A:000C()              ; 這一回合的命令階段
             起始星域 = 0；續接 = 0
         else:
             [bp+0] = 0
             起始星域 = ds:8F17；續接 = 1
         0374:03E8(起始星域, 續接)     ; ← 戰鬥都在這裡面
         非 0 → 整個結束
         056A:078E()                  ; 回合結束：重算擁有者 → 2703:08DE → 判勝負
         非 0 → 整個結束（勝負分了）
03B1D    inc word [8F18]              ; ← 回合 +1
         ds:8FF5 = ds:8FF4 = 1
         jmp loop
```

順序與 `flagpass` 量到的一致（`056A:0468` → `2703:08DE` → 計數器進位，
前兩個都在 `056A:078E` 裡面）。

## `0374:03E8`：逐格開戰

```
03B33  ds:988E = 0
03B38  ds:8F17 = 起始星域
03B52  loop:
03B55    if ds:8F17 >= 32: 回 0                 ; 掃完了
03B5C    test byte 星域[+13h], 4                 ; ← bit2「這一格雙方都有艦隊」
03B61    jz   下一格
03B67      cx = 續接 ? ds:8F1A : 0FFh            ; 戰鬥回合（續接時接著打）
03B74      0374:0489(…)
03B7B      3826:03DA()
03B87      12AA:000E(ds:8F17, 戰鬥回合)          ; ← 開打（12AA ＝ 戰鬥模組）
03B91      回值非 0 → 直接回（帶出去結束整個迴圈）
03B9C    下一格：0374:0556(星域記錄)
03BB7    inc byte ds:8F17；星域記錄 += 126
         jmp loop
```

兩件事：

1. **戰鬥是巢狀呼叫。** `12AA:000E` 回來之後這一圈**繼續往下掃**，
   掃完才回到主迴圈，主迴圈才跑 `056A:078E` 與 `ds:8F18++`。
   所以「打了一場仗」**不會**讓這個回合的其餘處理消失。
2. **一個回合會把每一個 `+0x13` bit2 有設的星域都打完**，不是只打一格。
   起始星域是參數，續接時從 `ds:8F17` 接著掃——所以戰鬥可以中斷再續跑。

## remake 的兩個分歧

`advanceTurn` 現在是

```go
if r := g.contestedRegion(); r >= 0 {
    g.StartBattle(r)
    return
}
```

- **只打編號最小的那一格**，其餘交戰星域這一回合不會打。
- **跳過回合結束的尾段**（月底結算）。星域重算已經由 `EndBattle` 補上
  （`docs/spec/033`），月底那一段還沒。

原版兩件都不是這樣。修法是把「掃下一個交戰星域」與「回合尾段」接到
戰鬥結束之後，等同 `0374:03E8` 的迴圈加上主迴圈的尾巴。

## 還沒讀

`056A:000C`（命令階段驅動，月底結算應該在它或它的 callee 裡）、
`04F8:000E`、`0374:0489`、`0374:0556`、`3705:0349`。
**月底結算實際掛在哪一支還沒定位**——這一輪確定的是「戰鬥不會讓它被跳過」，
不是「它在哪裡」。

## 一條方法

**先找那個一定會動的計數器，再往回讀。** 回合的主迴圈不好用呼叫圖找
（模組管理器的間接向量掃不到），但 `ds:8F18` 每回合一定加一次，
監看抓到寫入者之後往回退幾個位元組，整個迴圈就攤開了。

watch的0374:03DD是執行後IP。inc真正位址0374:03D9，dosgolem線性3B19，bytes `ff06188f`。
主迴圈順序與戰場巢狀結論保持；上文舊位址保留供回查。
