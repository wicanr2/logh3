# 258 — `軍事費 ＝ 原定軍事費 − 已付建造費 − 累計已付維持費 − 已付移動經費`

`docs/internals/27` 一直掛著一句「`原定 − 建造費 − 那三項` 仍然對不上實際的
軍事費——**還有沒找到的支出項目**」。沒有沒找到的支出項目，是那一句裡的
「那三項」拿錯了兩格。

## 手上其實一直有非零的樣本

開局那兩個月（`796/1`、`796/2`）除了造船沒有別的支出，`ds:8F72`、`ds:8F7A`、
`ds:8F82`、`ds:8F8A`、`ds:8F94` 裡有四個是 0——**那個局面分不開「本回合的
預定額」與「累計已付」**，兩種讀法都成立。

`docs/re/256` 把 `WORK.DT?` 的整個全域區塊換算完之後，三格存檔就是現成的
非零樣本，一次六組（三格 × 兩個陣營）：

| 存檔 | 陣營 | 原定軍事費 | 已付建造費 | 累計已付維持費 | 已付移動經費 | ＝ | 軍事費 |
|---|---|---:|---:|---:|---:|---|---:|
| `DT8` | 帝國 | 120533 | 8801 | 15155 | 6577 | ＝ | **90000** |
| `DT8` | 同盟 | 47942 | 9030 | 12412 | 11500 | ＝ | **15000** |
| `DT9` | 帝國 | 178563 | 8957 | 14238 | 5368 | ＝ | **150000** |
| `DT9` | 同盟 | 49957 | 9035 | 7992 | 2930 | ＝ | **30000** |
| `DTA` | 帝國 | 160000 | 0 | 0 | 0 | ＝ | **160000** |
| `DTA` | 同盟 | 30000 | 0 | 0 | 0 | ＝ | **30000** |

**六組全中。** 而且四個 `DT8`／`DT9` 的軍事費是 90000／15000／150000／30000
這種整數——那是劇本給的起始值，減出來剛好落回去，不是湊的。

扣的是三個**累計**欄位：`ds:8F94`、`ds:8F7A`、`ds:8F8A`。
`ds:8F72`（本回合維持費）與 `ds:8F82`（本回合移動經費）**不在這條減法裡**
——它們是這一回合還沒發生的預估，由 `297B:10DE` 每個回合重算一次
（`docs/re/255`），混進來會重複算。

## 三個累計欄位的生命週期

```
每個回合   ds:8F7A += Σ 艦隊 +0x0A      （056A:09EB，docs/re/236）
           ds:8F8A += 走了的艦隊 +0x0C  （113A:0729，docs/re/237）
月底       ds:8F94 ← ds:8F5A            （0654:0034，docs/re/255）
           ds:8F7A ← 0
           ds:8F8A ← 0
           ds:8F62 ← ds:8F52            （收完稅之後的軍事費）
```

所以徵稅計劃「已支付」那一欄印的是**這個月到現在為止**付掉的三筆，
而「本次預定」那兩格是下一回合要付的預估。

## remake

`rules.Treasury.Remaining()` 從 `Budget − ShipPaid − Paid()`
（`Paid()` 把四格全加起來）改成 `Budget − ShipPaid − FleetUpkeep − Movement`。
`Paid()` 本身不動——它服務的是**畫面上那四列的加總**，有自己的收據
（`fiscalrows5`，`docs/re/239`）。

`Game` 多兩格累計（`paidUpkeep`／`paidMove`），每個回合跟著扣款一起加、
月底歸零；徵稅計劃改用 `currentTreasury()`，「本次預定」兩格現算。
`rules.Slot` 也跟著多讀寫 `ds:8F62`／`ds:8F94`／`ds:8F7A`／`ds:8F8A`，
所以載入第 8／9 格存檔時那一欄會有真正的數字，不再是四個 0。

## 一條方法

**「對不上」先懷疑自己挑的欄位，再懷疑有沒找到的東西。** 這一句掛了很久，
而推翻它需要的資料一直躺在 `org_game/extracted/` 裡——缺的不是新收據，是
把已知的欄位表套到已有的檔案上。判斷點：**當一條等式在「大部分項是 0」的
局面成立、在別的局面不成立時，錯的通常是項的選擇，不是少了一項。**
