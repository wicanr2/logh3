# 175 — AI 沒動不是因為它決定不動，是它根本沒被呼叫

`docs/re/79` 量到「決定計數器 `ds:D60E` 十二回合後還是 0、全部艦隊的
`+0x79` 都還是 `0xFF`」，當時的結論寫成「原版按『實行』時電腦不下任何
命令」。`docs/re/162`–`docs/re/174` 把整套 AI 讀出來之後，這個結論與
程式碼互相矛盾——所以回頭查了進入點。

## 進入點是 `2D10:0005`，前面有兩道閘門

```
; 0x052C8（注意：這個位址在 codeall.bin 的範圍之外）
mov  bl, ds:8F1E                  ; 現在輪到哪個座位
cmp  byte [bx+8F23h], 1           ; 這個座位是不是電腦
jne  跳過
call far 2D10:0005                ; ← 整套 AI

; 2D10:0005 自己
若 ds:8F46 != 0：把它清 0，直接回      ; 「跳過這一次」的旗標
2D10:0319(1)
2D76:0002()      ; 建艦隊（docs/re/169）
2D76:0732()
2E54:000C()      ; 清表 ＋ 逐艦隊決定 ＋ 填優先度（docs/re/170）
2E54:0344()      ; 五個階段（docs/re/174）
2D10:0038()
ds:8F46 = 0
```

## 收據上的值

`s3ai6`／`s3turn2`／`dm_pre` 三份記憶體傾印同一組值：

| 位址 | 值 | 意思 |
|---|---|---|
| `ds:8F1E` | 0 | 現在是座位 0 |
| `ds:8F23[0]` | **0** | 座位 0 **不是**電腦 |
| `ds:8F23[1]` | 1 | 座位 1 是電腦 |
| `ds:8F25[0]`／`[1]` | 0／1 | 座位 0 ＝ 帝國、座位 1 ＝ 同盟 |
| `ds:8F1D` | 0 | 目前處理的陣營 ＝ 帝國（由 `ds:8F25[ds:8F1E]` 抄過來）|
| `ds:8F46` | 0 | 沒有要跳過 |
| `ds:D60E` | 0 | 決定了 0 支 |
| `ds:D50E[0..31]` | 全 0 | 優先度表整張沒被填過 |

`ds:D50E` 整張是 0 這件事最直接：`2E54:019F` 只要跑過一次，前線的格子
就不會是 0。**所以 `2E54:000C` 從來沒跑，`2D10:0005` 從來沒被呼叫**——
閘門 `ds:8F23[ds:8F1E] == 1` 在這些收據上是假的。

`ds:8F46`（唯一一處寫 1 在 `0x2CCA7`，條件是某個 `[bp+08] >= 8` 之後
先呼叫 `042F:0006`）不是原因，它是 0。

## 修正

`docs/re/79` 的「原版按『實行』時電腦不下任何命令」**要收窄**成：

> 那些收據停在**玩家的座位**上（`ds:8F1E = 0`、`ds:8F23[0] = 0`），
> AI 的進入點沒有被呼叫。這不是「AI 決定不動」，是「AI 沒有被叫到」。

「電腦回合真的會派兵」還需要一份收據——要讓 `ds:8F1E` 走到座位 1
（或直接 `-poke` 把 `ds:8F23[0]` 寫成 1）再看 `ds:D60E`／`ds:D50E`。

## 方法上的一條

`tools/scripts/farcall_to.py` 掃的是 `workplace/codeall.bin`，
而那份傾印只有 **`0x09000`–`0x3E000`**。`2D10:0005` 的唯一呼叫點在
`0x052C8`，**在範圍外**，所以「共 0 處」不是「沒有人呼叫」，
是「這份傾印裡沒有」。**回報 0 個呼叫者的時候要先講清楚掃的範圍。**
