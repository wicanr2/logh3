# 178 — 原版 AI 有寫死的進軍路線，而且費沙要等伊謝爾倫

`docs/re/174` 讀 `2D54:0000`（重算攻擊目標分）時，中段有一條
「0xFF 結尾的清單」沒讀。這一輪把它走出來——那是**寫死的進軍路線表**。

## 路線表怎麼找到的

```
n = 2D54:0163()                          ; 0–7，未讀
表 = (ds:8F1D == 0) ? ds:5EF2[n] : ds:5F22[n]      ; 遠指標
對 表 指到的遠指標陣列（0:0 結尾）的每一份清單：
    對清單裡每個星域 r（0xFF 結尾）：ds:D50E[r]++
```

之後 `ds:D50E[i]` 再乘上 `2048 ÷ (ds:D54E[i] + 1)`（`docs/re/174`），
所以「累積分」就是**這一格在這一組路線裡出現幾次**。

走表的腳本：`tools/scripts/ai_script_lists.py`，
資料：`docs/internals/data/ai-advance-routes.json`。

## 路線本身

帝國的每一條都終止於**巴拉特**（星域 31，同盟首都），同盟的每一條都
終止於**瓦爾哈拉**（星域 0，帝國首都）。例如帝國 `n=1` 的六條：

```
波列多 → 蘭提馬利歐 → 傑姆席德 → 凱利姆 → 德奧里亞 → 巴拉特
波列多 → 干達巴爾 → 巴米利恩 → 馬爾•亞迪特 → 流卡斯 → 艾流塞拉 → 巴拉特
波列多 → 干達巴爾 → 巴米利恩 → 達希利 → 萊加爾 → 特利布拉 → 巴拉特
艾爾•法西爾 → 蘭提馬利歐 → 波列多 → 干達巴爾 → 巴米利恩 → 馬爾•亞迪特 → 流卡斯 → 艾流塞拉 → 巴拉特
艾爾•法西爾 → 蘭提馬利歐 → 波列多 → 干達巴爾 → 巴米利恩 → 達希利 → 萊加爾 → 特利布拉 → 巴拉特
亞斯提 → 迪亞馬特 → 傑姆席德 → 凱利姆 → 德奧里亞 → 巴拉特
```

同盟 `n=2`：

```
伊謝爾倫
香陶 → 亞爾提那 → 瓦爾哈拉
香陶 → 卡斯特羅普 → 菲列亞 → 瓦爾哈拉
亞爾維斯 → 亞爾提那 → 瓦爾哈拉

```

**路上的每一格都會加分，所以被越多條路線經過的樞紐分數越高**——
巴米利恩、亞爾提那這種格子自然成為 AI 的重心，而那不是另外寫的規則，
是路線表相加的結果。

## 兩個單獨一格的目標：伊謝爾倫與費沙

`[13]` 與 `[14]` 各自成一條「路線」。查名字：
**星域 13 ＝ 伊謝爾倫、星域 14 ＝ 費沙**。這解釋了兩個先前只知道是
「寫死的星域編號」的地方（`docs/re/167`、`docs/re/177`）。

### 費沙的門檻：`2E54:0F93()`

`2E54:0F09` 收無主星域時，星域 14（費沙）要多過這一關：

```
2E54:0F93():
    若 ds:8F48 != 0：回 1
    伊謝爾倫 = ds:AE02                       ; ＝ ds:A79C + 13 × 126
    若 ds:8F1D == 0（帝國）：
        若 伊謝爾倫[+0x12] == 1（同盟的） 且 ds:8F18 < 238：回 0
        回 1
    若 ds:8F1D == 1（同盟）：
        若 伊謝爾倫[+0x12] == 0（帝國的） 且 ds:8F18 < 318：回 0
        回 1
    回 0
```

**AI 不會在伊謝爾倫還在敵方手上的時候去打費沙**——除非撐過門檻回合數。
`ds:8F18` 是回合計數器（`2D10:0319` 拿它 `% 10 == 9` 判月底，
所以十次「實行」一個月）：帝國 238、同盟 318，換算約 23.8 與 31.8 個月。
**兩邊的耐性不一樣，而且是寫死的。**

`ds:8F48` 那個「一設就直接放行」的旗標由誰寫還沒查。

## 這一段對 remake 的意義

`docs/spec/029` 原本把「攻擊目標分」的累積分標成未讀。現在它是可以
實作的：一張資料表 ＋ 一次計數。反而**不能**照抄的是 `2D54:0163()`
回的那個 `n`（0–7）——選哪一組路線的規則還沒讀。

## 還沒讀

`2D54:0163`（選哪一組路線）、`ds:8F48` 的寫入點、`2E54:13A8`（階段五的
目標，形狀是「在鄰居裡挑一個」）、`2E54:0513` 的後半（已知：
`ds:8F49[陣營] >= 16` 就停——**一個陣營最多 16 支艦隊**——
每個候選走 `2D76:0611`）。
