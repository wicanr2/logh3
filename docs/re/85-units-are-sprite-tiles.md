# 85：戰場上的單位是 `SPRITE.SPR` 的 16×16 圖塊

## 怎麼讓單位進畫面

`docs/re/82` 的收據裡戰場上一個單位都沒有，原因在 `docs/re/84`：
那一場停在輸入階段，雙方都沒動。這一輪把同一條序列往後多推八個
回合（收據 `s3fight`，1,400,000,000 步），同盟那六支就壓進視野了。

順帶量到**戰鬥開始結算**：同盟第 13 艦隊的艘數從 27,000 掉到
26,785，第 16 艦隊從 22,000 掉到 21,602。帝國那一支玩家沒下令，
原地沒動也沒損失。

## 單位長什麼樣

戰場區逐格比地形，這次多出 2,405 個不是地形的像素，分成一批
**16×16** 的方塊，色彩比地形豐富（用到 2、11–15）。

把其中一塊轉回 planar 位元組去原版檔案裡搜，命中

```
SPRITE.SPR @ 0x2180（第 67 塊，128 bytes 對齊）
SPRITE.SPR @ 0x2500（第 74 塊）
```

`SPRITE.SPR` 是 9,600 bytes ＝ **75 塊 16×16**（`docs/internals/10`
量的是 16×20，那是星域地圖的用法；同一個檔在戰場上按 16×16 取）。

## 畫在哪

分隊的世界座標（`+0x28`／`+0x2A`，`docs/internals/38`）直接換算成
畫面位置，**圖塊的左上角對齊座標**：

```
畫面 x ＝ 16 + 世界 x − 視野欄 × 16
畫面 y ＝ 60 + 世界 y − 視野列 × 20
```

`s3fight` 的視野是格 (66,30)。視野內的十四個分隊逐一換算，位置
全部落在畫面上那些 16×16 方塊的左上角。舉一個：同盟第 16 艦隊的
旗艦分隊在世界 (1320,812)，算出畫面 (280,272)，而畫面上那一塊
正是 `SPRITE.SPR` 第 67 塊。

## 哪個艦種畫哪一塊還沒解完

視野內十四個分隊裡有九個在畫面上比得出塊號（其餘幾個被相鄰的
單位疊住，或落在戰場邊緣）：

| 艦種 | 塊 | 樣本 |
|---:|---:|---:|
| 1 | 67 | 3 |
| 2 | 74 | 3 |
| 6 | 74 | 1 |
| 0 | 74 | 1 |

艦種 1 與 2 各三個樣本都一致；艦種 6 與 0 各只有一個樣本，而且與
艦種 2 撞號，所以**塊號不是單純由艦種決定**。要一場單位不重疊的
戰鬥才問得清楚。

## 收據

`s3fight`：序列同 `s3turn2` 再多八對雙擊（第 1,080,000,000 步起
每 30,000,000 步一對），`-steps 1400000000`，
`-dump-mem lin:0:1048576`。
