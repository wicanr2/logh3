# 154 — 艦艇 `+0x19` 是小地圖標記的開關，不是航跡

`docs/re/132` 讀 `1727:0207` 時把它當成「偵察隊走過會留下一條線」，
並把小地圖 y 的對應列為未定案。這一輪把繪圖那一端讀完，兩件事同時
有了答案：**那 40 列的偏移在 `3C5B:00B2` 裡面**，而 `1727:0298` 是把
同一個點 XOR 回去——畫上去的點會被擦掉，不留線。

## 40 列的偏移在 framebuffer 位移那一支

```
3C5B:00B2(bx = x, cx = y)
  ax = cx << 4          ; y × 16
  cx = ax
  ax = ax << 2 + cx     ; y × 80
  bx = (bx >> 3) + ax + 0C80h
  retf                  ; bx ＝ framebuffer 位移
```

`0x0C80` ＝ 3200 ＝ 40 × 80，也就是**第 40 條掃描線**。
`docs/internals/42` 的畫面圖塊表用同一個常數當起點
（`mov di, 0C80h`）。所以這一支收的是 **640×400 邏輯畫布**的座標，
落到 640×480 的實體畫面要再加 40 列。三件事對得起來：

- 戰場：`3870:0296` 算出來的左上角是 (16, 20)（`docs/re/135`），
  實體量到的是 (16, 60)（`docs/internals/34`）。
- 滑鼠：`screen_y = mouse_y + 40`（`docs/re/52`）。
- 底圖 `ANI_PNL0.A98` 畫在 y ＝ 40（`docs/internals/37`）。

`docs/re/135` 寫「範圍圖形那條路徑沒有這個偏移」，指的是 `3870:0296`
自己不加——偏移在它下游的 `3C5B:00B2`，兩邊不衝突。

## 於是那個點就是小地圖上的分隊點

```
1727:0324(x, y, 色)
    若 ds:A426 == 0：回
    39D7:08F4((x >> 4) + 1E0h, (y >> 4) + 24h, 色)
```

實體像素 ＝ `(480 + x/16, 36 + 40 + y/16)` ＝ `(480 + x/16, 76 + y/16)`。
小地圖的原點是 (480, 75)（`docs/internals/data/screen-battle.json`），
所以這個點就是

```
小地圖 x ＝ 世界 x ÷ 16
小地圖 y ＝ 世界 y ÷ 16 ＋ 1
```

——`docs/re/89` 從收據量出來的那一條，連 `+1` 都對上。那個 `+1`
（規格裡的 `unit_row_bias`）當時是量出來的，現在從碼上推得出來。

## `1727:0298` 是擦掉，不是再畫一次

```
1727:0298(艦艇)
    al = 艦艇[+0x19]
    需要 bit7 有、bit6 有、ds:A426 != 0
    1727:0324(艦艇[+0x1A], 艦艇[+0x1C], al & 0Fh)
    艦艇[+0x19] &= 0BFh                ; 清掉 bit6
```

底層是 XOR。`39D7:08F4` 寫入前呼叫 `2376:1810(ah = 色)`，那一支設
Graphics Controller 的四個暫存器：

| index | 值 | 意思 |
|---|---|---|
| 5 | `0x00` | Mode ← 寫入模式 0 |
| 0 | 色 | Set/Reset ← 顏色 |
| 1 | `0x0F` | Enable Set/Reset ← 四個平面都用 |
| 3 | `0x18` | Data Rotate/Function：function 欄位 ＝ 11b ＝ **XOR** |

同一點、同一個顏色再寫一次就還原成底下的值。`docs/re/89` 從畫面量到
「分隊那一層是 XOR 上去的」，與這裡一致。

所以低 4 位存顏色不是順手記著——**擦的時候要用同一個顏色 XOR 回去**，
不重算。`+0x19` 是這樣一個狀態機：

| 位元 | 意思 |
|---|---|
| bit7 | 這個分隊要在小地圖上點 |
| bit6 | 目前點著 |
| bit3–0 | 點下去用的顏色（陣營 0 → 5、陣營 1 → 9、其他 → 4）|

`+0x1A`／`+0x1C` 是「那個點畫在哪」，擦的時候要用。

## 開關在 `1727:02E2`

```
1727:02E2(艦艇, 旗標)
    若 旗標 == 0 且 艦艇[+0x17] == 0：
        1727:0298(艦艇)                ; 擦掉
        艦艇[+0x19] &= 7Fh
    否則：
        艦艇[+0x19] |= 80h
        1727:0207(艦艇)                ; 點上去
```

`+0x17` 是索敵的顯示層級（`docs/internals/38`）。這一支只讀了碼，
沒有收據：`s3fight` 裡艦隊 12 的八個分隊 `+0x17` 全是 0，小地圖照樣
點（`docs/re/89`）。所以「`+0x17` 掉到 0 就會被擦掉」還缺一張看得到
它發生的收據，remake 不照這一條改畫法。

## 拿既有傾印驗

`workplace/s3fight.bin`（艦艇池線性 `0x668B2`、148 筆、78 位元組一筆）：

```
bit6 有的：      80 82 83 84 85 86 87 88 109 135 137 138 139 140 141 147
+0x1A != FFFF：  80 82 83 84 85 86 87 88 109 135 137 138 139 140 141 147
```

**兩組完全相同**，而且就是 `docs/re/89` 對出來的那十六個分隊。把
`(480 + [+0x1A]/16, 76 + [+0x1C]/16)` 代進 `s3fight` 的 `screen.bin`，
十六個像素的顏色是 6／4（陣營 0：`3^5`／`1^5`）與 10／14
（陣營 1：`3^9`／`7^9`），其中艦艇 135 那一點是 6 ＝ `15^9`——底下先
填了行星的 15。與 `docs/re/89` 逐點相同。

把墨色 XOR 回去，十六個點的底色是 3（格線／上緣）、1（底色）、
7（視野框 `3|4`）與 15（行星）——全部是小地圖那五層畫得出來的顏色，
沒有一個落在外面。

腳本：`tools/scripts/minimap_mark_check.py`。沒有跑新收據，全部從既有
傾印算出來（`workplace/s3fight.bin`、`workplace/oracle/s3fight/screen.bin`）。
