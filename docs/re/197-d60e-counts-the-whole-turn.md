# 197 — `ds:D60E` 數的是整個回合，不是逐艦隊決定那一趟

`docs/re/196` 讀完 `2E54:005D` 之後留了一格對不上：收據 `s3aicomp` 上
同盟六支在用、`ds:D60E = 5`，照過濾的讀法應該是 4。

掃一下遞增點，殘留就消失了。

## 十處遞增點

`fe 06 0e d6`（`inc byte [D60E]`）在 1 MB 傾印裡有 **10 處**：

| 位址 | 在哪一支 |
|---|---|
| `0x2E607`、`0x2E67A`、`0x2E6AF`、`0x2E6CA` | `2E54:005D`（逐艦隊決定的四條路）|
| `0x2E978`、`0x2E9BB`、`0x2EA1F`、`0x2EA37` | `2E54:03C3` 一帶（守首都湊人那一支，`docs/re/166`）|
| `0x2EB68` | `2E54:0513`（階段一新編艦隊，`docs/re/180`）|
| `0x2ED77` | `2E54:07D8`（階段三的指派，`docs/re/172`）|

唯一的清 0 在 `0x2E588`（`2E54:0048` 一帶，回合開頭）。

**所以它數的是「這一回合總共處理了幾支」**——逐艦隊決定、守首都湊人、
新編、階段三的指派都算。`docs/re/79` 記的「這一趟決定了幾支」範圍太窄。

`s3aicomp` 的 5 因此不必等於決定那一趟的數目，**`docs/re/196` 的殘留
不存在**。

## 順帶把 `2E54:005D` 的另一路讀完

`+0x00` bit0 **有設**的那一類（`docs/re/196` 標未讀完的那一段）：

```
參 = (ds:8F1D == 0) ? 星域[+0x29] : 星域[+0x28]
若 星域[+0x13] & 14h（bit2｜bit4） 有設 → 2E54:1955（退一格）
否則若 參 != 0                        → 2E54:1955
否則若 星域[+0x12] != 艦隊[+0x01]      → 2E54:1955
否則 → 艦隊[+0x08] = 3、艦隊[+0x07] = 艦隊[+0x06]   ; 原地出擊
+0x79 = 0、ds:D60E++
```

**只有「這一格沒有戰鬥、`星域[+0x28/29]` 是 0、而且這一格是自己的」
才原地出擊，其餘一律往首都退一格。** 兩條都寫 `+0x79 = 0`，
所以這一類艦隊**不會**留給後面的階段。

`星域[+0x28]`／`+0x29` 是一對以陣營分的欄位，語意未解。

## 一條方法

**一個計數器對不上的時候，先掃它有幾個遞增點。** 這裡花的是一支
四行的腳本，換掉的是一次 9×10⁸ 步的長跑；而且結論不是「量出來多少」，
是「**這個數本來就不是我以為的那個量**」——量測不會告訴你這件事。

---

> 遞增點是**十一**處不是十處：這一輪掃的是 `fe 06 0e d6`（`inc`），
> 漏掉 `2E54:1183` 的 `add byte [D60E], 2`（`docs/re/198`）。
> 「它數的是整個回合」這個結論不受影響。
