# 259 — 月底跳三張報告，不是一張

`docs/re/255` 讀出 `0654:0034` 在閘門裡依序呼叫三支只有玩家座位看得到的
函式（`0654:0130`、`0654:0486`、`0654:02E0`）。這一篇把三張畫面實際抓下來，
順帶解掉「月報怎麼關」這個一直擋住收據的問題。

## 月報怎麼關

`monthgateA` 停在第一張報告上跑滿 400M 步，`monthgateC` 在同一個位置補了
16 次點擊在「確認」鈕上——**兩次都沒關掉**。兩個原因：

1. **`-press` 送的鍵是有限的。** `-press 1,3,8,enter` 只有四個掃描碼，
   從 `-press-at` 起每 `-press-every` 步送一個，送完就沒了。防拷問答用掉
   四個之後，後面幾億步一個鍵都沒有——「按 Enter 關不掉」其實是根本沒按。
2. **一次點擊不夠。** 有效的序列是**左鍵點在「確認」上、再補一次右鍵**，
   兩者間隔幾百萬步；`monthgateC` 只有左鍵，關不動。
   `-watch-screen 2000000` 一眼就看得出來：`monthdismiss` 那一趟畫面在
   `#246M`（7638 px）、`#252M`（24444）、`#258M`（24218）、`#264M`（83271）
   各變一次，正好是三張報告依序退場再露出地圖介面。

可用的配方（`monthdismiss`／`monthreports`）：

```
-clicks   '…;466,368,<步數>,3000000'      左鍵點「確認」
-rclicks  '320,240,<步數+3M>,3000000'     右鍵補一下
每張報告一組，間隔 6M 步
-dump-at  '<步數+1.5M>:/src/workplace/xxx.png'   一次跑把每張都倒出來
```

## 開局只有兩張

`0654:0034` 裡那一行 `cmp word [8F18], 0` / `jz 065A7` 跳過的正是
`2B5F:001F` 與 `0654:0130`——**第 0 回合沒有「上個月」，所以不跳接收報告**。
收據 `openreports`（新遊戲、帝國）：第一張是 `796年 1月份會計報告`，
右鍵一下之後是 `796年 1月份船艦訂造報告`（署名 **梅克林格准將**——軍階
取自提督記錄，S3 那份是上將），再一下才到地圖介面。

這解釋了 `main1e` 為什麼要按兩下右鍵：那兩下關的是**兩張不同的報告**。

## remake

三張畫面都已經有了（`StateShipDelivery`、`StateMainGame`、`StateShipOrder`），
缺的是串起來：

- 開局：`StateMainGame` 右鍵 → **`StateShipOrder`** → 右鍵 → 地圖介面。
  本來第二下右鍵是在同一張上再數一層，等於**訂造報告從來沒被顯示過**。
- 跨月：`StateShipDelivery` 按掉 → `StateMainGame` → 右鍵 → `StateShipOrder`
  → 右鍵 → 地圖介面。本來按掉接收報告就直接回地圖。
- 從會計報告那顆「變更」熱區點進訂造報告時，右鍵退回會計報告（用
  `reportLayer` 分得開「報告串」與「熱區」兩條路）。

對戰模式那一路（`StateVersusAccount`）照舊只數層數——**中間那張是不是
訂造報告還沒量過**，`vs5`／`vs6` 的收據綁在現行行為上。

## 一條方法

**「輸入沒有效」要先確認輸入真的送出去了。** 這一輪卡在月報上兩次，
第一次的根因是 `-press` 的鍵早在幾億步前就送完了——**症狀與「按了沒反應」
完全一樣**。`-watch-screen` 是這類問題最便宜的第一步：它回答的是
「這一下到底有沒有改變任何東西」，不必猜是座標錯、時點錯還是機制不同。

## 補：訂造報告的右鍵一律到地圖介面

上面把 remake 的「從熱區進來的訂造報告，右鍵退回會計報告」寫成一種模型，
**那是沒量過的**。量了（收據 `orderback`，新遊戲帝國）：

```
#128M  會計報告                        （96ac4908…）
       -clicks 448,330                 會計報告上的熱區
#145M  796年 1月份船艦訂造艦報告        （89ee353e…，戰艦 3790／1）
       -rclicks 300,200
#168M  地圖介面                        （106538c7…）
```

`#168M` 那張與報告串那一路（`openreports` 的第二下右鍵，`#172M`）**是同一張
畫面**。所以右鍵從訂造報告一律露出地圖介面，兩條路進來都一樣。

順帶一個座標上的坑：`ship1` 的旗標是 `-clicks 448,330`，也就是
**命中判定吃的是畫面座標，不減 40**（游標繪製才是滑鼠座標 ＋40，
`docs/re/52`）。第一次量這一題時把 448,330 換算成 448,290 送出去，
點了完全沒反應——而「沒反應」和「機制不是這樣」看起來一樣。
熱區本身在 `screen-main-game.json`：`(432,320)` 32×20（訂造報告）、
`(432,300)` 32×20（次月份預算計劃）。

## 再補：報告是右鍵關的，左鍵那幾下沒有作用

上面「左鍵點『確認』再補一次右鍵」那個配方是**過度歸因**。收據
`mreponlyr`（S3 跨月，只給右鍵）：

```
#245M  接收報告        d2244eae…
       -rclicks 320,240,246000000
#250M  會計報告        6a2bae39…
       -rclicks 320,240,252000000
#256M  訂造報告        ba52698f…
       -rclicks 320,240,258000000
#265M  地圖介面        e5cab815…（與 monthreports 的 #270M 同一張）
```

**三下右鍵就走完整串**，左鍵一下都不需要。

那幾下左鍵為什麼沒有作用，也弄清楚了：熱區在
`screen-main-game.json` 是 `(432,300)` 與 `(432,320)`，各 32×20，而畫出來的
「變更」「確認」在**畫面**座標 `(452,340)`／`(452,360)`。兩者其實同一列
——熱區用的是**滑鼠**座標（畫面座標 −40），所以在滑鼠座標下熱區是
`x 432–463`、按鈕是 `x 452–482`，**重疊在 452–463**。我點的 `x = 466`
剛好落在熱區右邊界外面：

| 點在（滑鼠座標） | 結果 | 收據 |
|---|---|---|
| `448,330` | 開訂造報告 | `ship1` |
| `466,368` | **什麼都沒發生** | `acctok` |
| `466,349` | **什麼都沒發生** | `acctchg` |

`acctok`／`acctchg` 兩份的畫面雜湊與點之前**完全相同**（`96ac4908…`）。

remake 跟著把接收報告接上右鍵（本來只有左鍵那一路，而左鍵的落點還沒量過）。
