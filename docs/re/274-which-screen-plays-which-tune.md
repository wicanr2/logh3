## 一、檔名是三支執行檔各自 `sprintf` 出來的

三個格式字串，三支執行檔各一個，**互不重疊**：

| 執行檔 | 格式字串 | 位置 | 生出來的檔 |
|---|---|---|---|
| `OPEN.EXE` | `open_%c.mds` | 檔案位移 `0x482E` ＝ 執行期 `ds:031E` | `OPEN_F`／`OPEN_M` |
| `GIN3PS.EXE` | `bgm_%1d%c.mds` | `ds:69F4` | `BGM_0`–`BGM_7` × `F`／`M` |
| `ENDING.EXE` | `end_%1d%c.mds` | 檔案位移 `0xF80C` ＝ `ds:A2AC` | `END_1`／`END_2` × `F`／`M` |

所以 22 首的歸屬第一層就分乾淨了：開頭動畫 2 首、本體 16 首、結局 4 首。

`GIN3PS.EXE` 是 GLUE 封裝的，字串與程式碼都從執行期傾印讀；
`OPEN.EXE`／`ENDING.EXE` 是普通 MZ，直接讀檔（第八節）。

找法：在 `/orig` 與四份 1 MB 傾印裡掃 `[A-Z0-9_]{1,12}\.(MDS|INI)`，
再用「字串位址 − 立即值」投票找出 DGROUP 基底
（`workplace/immref.py`，同一份傾印裡只有一個基底能同時解釋兩個以上的字串）。
`GIN3PS` 的 DGROUP 基底 `0x54B30` 與 `tools/scripts/read_ds_string.py` 用的
是同一個，交叉對得上。

## 二、`GIN3PS.EXE` 的載入常式與它的兩個外皮

**位元組簽章**（載入常式入口，`load_bgm(bufOff, bufSeg, 曲號, 字元)`）：

```
8A 46 4E 3C 66 74 04 3C 46 75 06 C6 46 00 00 EB 04 C6 46 00 01
```

```
  mov  al,[bp+4E]          ; 第四個引數 ＝ 'f' 或 'm'
  cmp  al,'f'   jz  +4
  cmp  al,'F'   jnz +6
  mov  byte [bp+00],0      ; F → 0
  jmp  +4
  mov  byte [bp+00],1      ; 其他 → 1
  mov  al,[bp+4E]  xor ah,ah  push ax        ; %c
  mov  al,[bp+4C]  xor ah,ah  push ax        ; %1d
  push ds  mov bx,69F4  push bx              ; "bgm_%1d%c.mds"
  push ss  lea bx,[bp+02]  push bx
  call far <sprintf>
  push 6D60                                  ; 讀進來的上限 28,000 bytes
  push [bp+4A]  push [bp+48]                 ; 緩衝區 far 指標
  push ss  lea bx,[bp+02]  push bx           ; 檔名
  push [bp+00]
  call far <開檔＋讀＋關檔>                   ; 失敗就整段重來
```

往上兩層只有兩個呼叫端，差別只在那個字元：

```
  mov al,'f'  push ax  push [bp+06]  call <配置緩衝區>  push ax  push bx
  call far <load_bgm>   ; ← 'f'
  call far <啟動 OPL 播放>

  mov al,'m'  push ax  push [bp+06]  call <配置緩衝區>  push ax  push bx
  call far <load_bgm>   ; ← 'm'
  call far <啟動 MPU-401 播放>
```

兩個外皮收尾呼叫的是不同的播放啟動常式，而那兩支分別坐落在音樂模組裡
OPL 那一段與 MPU 那一段（偵測 OPL 的 `in al,388h` 與初始化 MPU 埠的常式各在
自己那一段的開頭）。所以：

> **`_F` ＝ FM 音源（OPL），`_M` ＝ MPU-401／GM。** confirmed。

⚠ **不要拿檔頭曲名去推這件事，會推反。** `OPEN_F.MDS` 的曲名寫
`OPEN MIDI For 01:28`、`OPEN_M.MDS` 寫 `OPEN_OPS 1:28 TAKE 10/23`——
字面看起來剛好相反。曲名是作曲者自己的工作標籤，不是證據；
程式碼與收據才是（見第六節：出貨的 `MUSIC.INI` 把 MIDI 介面設成「無」，
收據裡讀進去的一律是 `_F`）。

## 三、選 `_F` 還是 `_M`：兩個位元組

**裝置遮罩 `ds:934E`**（開機偵測的結果）：

| 位元 | 意義 | 怎麼設 |
|---|---|---|
| bit0（值 1）| 有 MPU-401 | `MUSIC.INI +4` 的埠不是 `FFFF` 也不是 `0`，且初始化成功 |
| bit1（值 2）| 有 FM 音源 | `in al,388h` 之後 `and al,F0h` 為 0 |

FM 偵測的簽章：`BA 88 03 EC 24 F0 74 04 33 C0`
（`mov dx,388; in al,dx; and al,F0; jz 有; xor ax,ax` ＝ 回 0 表示沒有）。

**玩家設定 `ds:8F33`**：`0` ＝ MIDI、`1` ＝ ＦＭ、`2` ＝ 關閉。
開機時照偵測結果給預設值——**有 MIDI 就用 MIDI**：

```
  test byte [934E],1  jz  +7
  mov  byte [8F33],0        ; 有 MPU → MIDI
  jmp  +13
  test byte [934E],2  jz  +7
  mov  byte [8F33],1        ; 只有 OPL → ＦＭ
  jmp  +5
  mov  byte [8F33],2        ; 都沒有 → 關閉
```

同一段接著把三格選單的「可選」旗標設成偵測結果（`ds:03DC`／`03E8`／`03F4`
分別是那三筆選單記錄的 `+4`），所以沒有 MIDI 介面時「ＭＩＤＩ」那一列點不下去。

播放派工（簽章 `F6 06 4E 93 03 75 02 5D CB`）：

```
  test byte [934E],3   jz  → 直接 retf        ; 兩種音源都沒有就不播
  等到目前這首停下來
  mov  byte [F2F6],0
  cmp  byte [bp+0A],0  jnz 走「先 ＦＭ」那一半
  ; 先 MIDI：[934E] bit0 → 'm' 外皮、[F2F6]=1；否則 bit1 → 'f' 外皮、[F2F6]=2
  ; 先 ＦＭ：反過來
```

`ds:F2F6` 是「現在是哪一種音源在播」（1 MIDI／2 ＦＭ／0 沒播）。

`[bp+0A]` 那個「偏好」引數由 `ds:8F33` 算出來（`8F33 != 0` → 偏好 ＦＭ），
而且 **`8F33 == 2` 時整個播放呼叫被跳過**：

```
  cmp byte [8F33],2   jz → 不播
```

## 四、選第幾首：`ds:8F34` 與 `ds:8F35`

播放的唯一入口（簽章 `80 3E 35 8F 02 75 08 A0 34 8F 88 46 00 EB 08 A0 35 8F 04 06`）：

```
play_music(戰鬥嗎):
  if 戰鬥嗎 == 0:        曲號 = [8F34]
  elif [8F35] == 2:      曲號 = [8F34]
  else:                  曲號 = [8F35] + 6
  偏好 = ([8F33] != 0)
  if [8F33] == 2: return
  派工(曲號, 0, 偏好)
```

- `ds:8F34` ＝ 平時配樂，`0`–`5` → `BGM_0`–`BGM_5`
- `ds:8F35` ＝ 戰鬥配樂，`0` → `BGM_6`、`1` → `BGM_7`、`2` → 沿用平時那一首

開新遊戲時兩格都被設成 0（簽章 `31 C0 A2 34 8F A2 35 8F CB`），所以**出廠預設是
`BGM_0`＋`BGM_6`**。

## 五、這三格就是設定畫面上的三行

設定畫面的熱區處理把命中的動作碼分成三段（`es:[bx+5]` 是動作碼）：

| 簽章 | 動作碼 | 做什麼 |
|---|---|---|
| `3C 02 77 15 A2 33 8F` | 0–2 | `[8F33] = 碼`，重畫音源那一列，**接著試聽平時曲** |
| `3C 03 72 1B 3C 08 77 17 04 FD A2 34 8F` | 3–8 | `[8F34] = 碼 − 3`，重畫清單，**接著試聽** |
| `3C 09 72 11 3C 0B 77 0D 04 F7 A2 35 8F` | 9–11 | `[8F35] = 碼 − 9`，重畫清單，**不試聽** |

十二筆選單記錄在 `ds:03D8` 起，一筆 12 bytes

| 4 | `02FE` | `英雄交響曲` | `BGM_1` |

## 七、什麼時候換曲

`play_music` 在全份傾印裡只有 8 個 far call 呼叫點：

| 線性（`chain_pre.bin`）| 引數 | 在哪 |
|---|---|---|
| `0x04423` | 0 | 某張畫面收尾之後恢復平時曲（呼叫端語意 **未解**）|
| `0x046EA` | 0 | 設定畫面選了音源之後試聽 |
| `0x04710` | 0 | 設定畫面選了平時曲之後試聽 |
| `0x181E2` | 0 | 一段初始化序列的最後一步（**強證據**：前面連著六個同段呼叫，外面用 `ds:9B7E` 擋重入）|
| `0x1DFB8` | 1 | 戰鬥端（先釋放兩個緩衝區再換曲）|
| `0x1EDD0` | 1 | 戰鬥端 |
| `0x2C635`／`0x2C710` | 0 | 「請將操作磁碟片放入Ａ磁碟機中」對話框關掉之後恢復 |

**行為面由收據釘死**（`s3assault`，同一份裡重複三次）：

```
#430895901 read block_2.blk        ← 進戰場（戰術畫面）
#1140710374 read bgm_6f.mds        ← 交戰演出開始，換戰鬥曲
#1140829686 read comani.bmg …      ← 交戰演出的人物動畫，連續數十次
#1169283675 read bgm_3f.mds        ← 演出結束，換回平時曲
#1230766575 read bgm_6f.mds        ← 下一次交戰
…
```

所以：

- **主選單與防拷問答沒有配樂。** `GIN3PS.EXE` 從啟動（`#68.6M`）到答完防拷題
  （`-press` 在 `#105M`）之間**一個 `.MDS` 都沒開過**，第一首在 `#117.0M`
  ——也就是進遊戲本體的時候（confirmed，`key1`／`main1e`／`chain1` 三份一致）。
- **戰略層與戰術畫面（戰場）用的是同一首**：`BGM_3F` 從載完存檔一路撐到
  `#1140M`，中間已經進過戰場（`block_2.blk`、`map26.cmp`）。
- **戰鬥曲只在交戰演出那一段**（`ANI_PNL1.A98` ＋ `COMANI.BMG` 那串），
  演出結束就換回平時曲。

## 八、`OPEN.EXE` 兩條路都寫死 `'m'`——`OPEN_F.MDS` 是死素材

`OPEN.EXE` 的結構與 `GIN3PS.EXE` 一模一樣（同一份音樂模組：同樣的
`cmp 'f'/'F'` 判斷、同樣的 `6D60` 上限、同樣的裝置遮罩 → 兩個外皮），
**只有一件事不一樣**：兩個外皮都送 `'m'`。

```
FM 那一支：  … mov al,6D ('m') … call far <play>  … call far <啟動某一支>
MIDI 那一支：… mov al,6D ('m') … call far <play>  … call far <啟動另一支>
```

整個執行期映像裡 `B0 66`（`mov al,'f'`）與 `B0 46`（`'F'`）**一次都沒有出現**
（`B0 46` 唯一那一處在 `0x19D37`，不在音樂模組）。對照組：`ENDING.EXE` 的
同一對外皮是 `6A 66`（push `'f'`）與 `6A 6D`（push `'m'`），兩個都在。

結論：**不論偵測到什麼音源，開頭動畫一律讀 `OPEN_M.MDS`**，
`OPEN_F.MDS` 在出貨的遊戲裡永遠不會被打開。confirmed
（程式碼 ＋ 457 份收據裡 689 次 `open_m.mds`、0 次 `open_f.mds`）。

這也解釋了 `docs/internals/19` §播放環境早就記下的那一行。

> 順帶更正一件事：`OPEN.EXE` 與 `ENDING.EXE` **不是** GLUE 封裝檔。
> 只有 `GIN3PS.EXE` 的檔頭帶 `GLUE` 字樣（位移 `0x36`）、`cparhdr=5`、
> 重定位筆數 0；另外兩支是正常 MZ（`cparhdr` 64／128，重定位 168／502 筆），
> 字串明碼、而且本輪直接從檔案把它們的音樂模組反組譯出來。
> `OPEN.EXE` 的檔案位移與執行期位址是固定差：DGROUP 在檔案 `0x4510`、
> 在 `openmem.bin` 是 `0x75A0`，兩邊的 `ds:0116`／`ds:031E` 都指到
> `music.ini` 與 `open_%c.mds`。

## 九、`ENDING.EXE`：曲號就是命令列的第二個數字

```
  les  bx,[bp+08]                 ; argv
  push es:[bx+0A]  push es:[bx+08]
  call far <atoi>                 ; atoi(argv[2])
  mov  [bp-02],ax                 ; ← 曲號
  …  atoi(argv[1]) 必須等於 9 …
  push 0        ; 偏好 ＝ 先 MIDI
  push 0
  mov  al,[bp-02]  push ax
  call far <派工>
  cmp  word [bp+06],2  jz … （兩套結局演出分岔）
```

`docs/internals/16` 已經釘過 `9 1` ＝ 帝國勝利、`9 2` ＝ 同盟勝利
（收據 `ending-empire`／`ending-alliance`，分別開 `ENDT*.VO5` 與 `ENDD*.VO5`）。
那個 `2` 原封不動變成 `end_%1d%c.mds` 的 `%1d`，所以：

> **`END_1` ＝ 帝國勝利結局、`END_2` ＝ 同盟勝利結局。** confirmed（反組譯）。

`_F`／`_M` 走的是同一套裝置判斷（`ds:2B4A` 是它的裝置遮罩、`ds:A872` 是
它從 `MUSIC.INI +4` 讀來的 MPU 埠），所以出貨設定下是 `END_1F`／`END_2F`。

**還沒有收據**：既有的兩份結局收據只跑了 40,000,000 道指令，還沒走到載入配樂
（檔案存取只到 `ENDT40.VO5`／`ENDD40.VO5`）。要把這一條從「反組譯 confirmed」
再加一層實跑證據，需要一份步數更長的 `ENDING.EXE` 收據。

## 十、`MUSIC.INI` 的六個位元組

出貨內容 `00 00 01 FF FF FF`，六個位元組，**和 `MUSIC.ORG` 逐位元組相同**
（`RESSOUND.COM` 只做一件事：`COMMAND /C COPY music.org *.ini`，
把設定還原成出廠值）。

| 位移 | 寬 | 內容 | 等級 |
|---|---:|---|---|
| `+0` | 1 | 三支執行檔都沒有讀過 | **未解** |
| `+1` | 1 | 同上 | **未解** |
| `+2` | 1 | 音效裝置：只有 `GIN3PS.EXE` 讀，連同 `gin3sp.voc` 一起交給音效初始化 | 強證據 |
| `+4` | 2 | **MPU-401 基底埠**；`FFFF` 或 `0` ＝ 沒有 MIDI 介面 | confirmed |

`+4` 的來源是遊戲自己的「ＭＩＤＩ Ｉ／Ｆ」選單，七選一，選完寫回 `MUSIC.INI`：

| 選項 | `ds:` 文字 | 寫進 `+4`（埠表 `ds:0564`）|
|---|---|---|
| 0 | `0246` `無` | `FFFF` |
| 1 | `0255` `Roland : 300H` | `0300` |
| 2 | `0264` `Roland : 320H` | `0320` |
| 3 | `0273` `Roland : 330H` | `0330` |
| 4 | `0282` `Roland : 332H` | `0332` |
| 5 | `0291` `Roland : 334H` | `0334` |
| 6 | `02A0` `Roland : 336H` | `0336` |

寫回的程式碼：`mov bx, 選項; shl bx,1; mov ax,[bx+0564]; les bx,[F138];
mov es:[bx+4],ax`，接著重跑一次音樂模組的初始化再存檔。

所以「`MUSIC.INI` 怎麼在 `_F` 與 `_M` 之間選」的正確說法是：
**它不直接選。** 它只說有沒有 MIDI 介面、在哪個埠；
有就 `_M`、沒有就退到 `_F`、兩種都沒有就不播。之後玩家還可以在設定畫面
改成別的，而改完的值跟著存檔走，不回寫 `MUSIC.INI`。

出貨值是「無」，所以**開箱即用的原版一律是 `_F`（FM）**。

## 十一、一個對執行器的觀察（不是本作的結論）

本作的 FM 偵測不是標準的 AdLib 偵測序列，而是
`in al,388h; and al,F0h; jz 有`。dosgolem 的 `0x388` 讀取**預設回 `0`**
（`internal/machine/machine.go` 註解寫得很清楚，理由是讓標準偵測序列失敗、
開機快很多），但那個 `0` 對**這一支**判斷式來說剛好等於「有 OPL」。

也就是說：**不加 `-adlib` 跑本作，遊戲照樣認為有 FM 音源**，
所以既有收據才會一路讀 `_F`。這對本輪的結論沒有影響（出貨設定本來就是
「有 OPL、沒有 MIDI」＝ `_F`），但如果將來要驗「三種音源都沒有時安靜」
那條分支，得先讓 `0x388` 回 `0xFF`。這一點留在這裡，沒有改執行器。

## 十二、為什麼本輪沒有跑執行器

開工時 `~/cht/dosgolem-logh3` 的工作樹是髒的，而且**在本輪進行中又變髒了一次**
（先是三個未追蹤檔，後來 `cmd/probe/observe.go` 等三個已追蹤檔也變成 modified）
——另一個 session 正在那邊做 OPL → VGM 的匯出。
`AGENTS.md` 的硬規則是「收據綁執行器版本」，在一個正在被別人改的工作樹上
產出的收據沒有版本可綁；而且 `WORKLOG.md` 上一輪才記過 `-clicks` 的旗標語法
已經換過一次。所以本輪改用既有收據 ＋ 靜態反組譯，把需要實跑的那一項
（`END_?` 的檔案存取紀錄）明確留成待辦，不拿一份綁不住版本的收據充數。
