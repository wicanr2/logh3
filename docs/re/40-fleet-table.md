# RE 40 — 艦隊表在 `ds:C074`，一筆 122 bytes

日期：2026-09-07
執行器：dosgolem-logh3 `8c8af90`
收據／傾印：`s2empire`、`workplace/explore/fleets-s2.bin`
狀態：**位址、步長與計數迴圈 confirmed**；欄位語意 **未解**。

## 怎麼找到的

`docs/re/39` 猜 `ds:9592` 是艦隊名冊，`-poke` 兩次都沒讓畫面變——
因為**面板讀的是星域記錄的 `+0x28`**（`docs/re/31` 早就用 poke 定過），
不是那裡。改用對的工具：

在星域 0 的艦隊欄（線性 `5F2F4`）設監看，載入 S2 時看到

```
#242830505  5F2F4: 02 → 00  ← 2703:087A     歸零
#242830901  5F2F4: 00 → 01  ← 2703:08CE     ＋1
#242831029  5F2F4: 01 → 02  ← 2703:08CE     ＋1
```

所以 `2703:08CE` 在一個「掃艦隊、把數量記到所屬星域」的迴圈裡。
對它設 `-regs-at`：

```
#121689134  BX=C074
#121689142  BX=C0EE
#121689150  BX=C168
#121689158  BX=C1E2
```

BX 每次 ＋**0x7A ＝ 122**。艦隊表就在 `ds:C074`，一筆 122 bytes。

`ds:C074` 正好是提督表的結尾：`B77C + 82 × 28 = C074`（`docs/re/33`）。
兩張表首尾相接。

> 順帶一提：`docs/re/39` 倒的 48 KB 是 `ds:0000`–`ds:BFFF`，
> **差 0x74 bytes 就碰到艦隊表**——所以那次對照才看不到它。
> 下次倒資料段至少要到 `ds:D000`。

## S2 的內容

倒 4,880 bytes（40 筆；表其實只有 32 筆，後面 8 筆是別的東西）：
前 32 筆裡大多不是全零。沒在用的那幾筆整筆填 `FF`，
只留 `+0x02`／`+0x03` 兩個編號與 `+0x6C`–`+0x6F` 的四個 0。

第 0 筆（S2，帝國）：

```
+00  00 00 01 00 00 20 02 0E 01 00 BA 00 DD 00 0A 0A
+10  00 00 00 14 02 00 00 18 03 00 00 19 04 00 00 1C
+20  05 00 00 1E 06 00 02 20 07 00 02 21 08 00 02 22
+30  09 00 02 23 0A 00 06 1D 01 00 FF 00 64 7A 75 70
+40  80 77 75 79 78 82 75 82 04 FF 51 51 51 0F 22 16
+50  FF FF FF FF FF FF FF FF FF FF FF FF 88 04 B4 02
+60  FF FF FF FF 88 04 B4 02 FF FF FF FF 00 00 00 00
+70  FF FF FF FF FF FF FF FF FF FF
```

看得出來的形狀（**都還是假說**）：

| 位移 | 觀察 |
|---|---|
| `+0x02`／`+0x03` | 兩個編號，逐筆遞增（第 0 筆 `01 00`、第 1 筆 `02 01`、第 2 筆 `03 02`）|
| `+0x0A`–`+0x0D` | 兩個 word（186／221、212／247）——像座標 |
| `+0x10`–`+0x37` | 十組 4 bytes，形狀 `編號 00 x 型別`——像編制內的十支部隊 |
| `+0x3C` 起 | `64` ＝ 100，接著 11 個 0x69–0x82（105–130）——像一組能力值 |
| 未用的整筆 | `FF` 填滿 |

## 計數迴圈整支解出來了

倒 `2703:0853` 起那 320 bytes 手工解碼：

```
; 先把每個星域的兩個計數格清掉
mov byte [bp+00],0 / mov word [bp+02],A79C     ; i = 0，星域表
loop1:
  cmp byte [bp+00],20 / jnb loop2              ; i < 32
  les bx,[bp+02]
  mov es:[bx+29],al / mov es:[bx+28],al        ; 星域 +0x28、+0x29 ← 0
  inc byte [bp+00] / add word [bp+02],7E       ; 下一筆（126）
  jmp loop1

; 再掃艦隊表
loop2:
  mov byte [bp+00],0 / mov word [bp+06],C074   ; j = 0，艦隊表
  cmp byte [bp+00],20 / jnb done               ; ← **32 筆**
  les bx,[bp+06]
  cmp byte es:[bx+04],FF / jz next             ; +0x04 ＝ FF → 這一筆沒在用
  mov al,es:[bx+06]                            ; +0x06 ＝ 所在星域
  mul 7E / add si,A79C                         ; → 該星域的記錄
  add si,28                                    ; +0x28
  les di,[bp+06]
  mov al,es:[di+01]                            ; +0x01 ＝ 陣營
  add si,ax                                    ; +0x28 ＋ 陣營
  inc byte es:[si]                             ; ← 2703:08CE
next:
  inc byte [bp+00] / add word [bp+06],7A       ; 下一筆（122）
  jmp loop2
```

於是四個欄位定下來（**confirmed**，從程式讀的）：

| 位移 | 內容 |
|---|---|
| `+0x01` | 陣營（0 帝國、1 同盟）|
| `+0x04` | `0xFF` ＝ 這一筆沒在用 |
| `+0x06` | 所在星域編號 |
| 表長 | **32 筆**（`ds:C074` 起 32 × 122 ＝ 3,904 bytes，到 `ds:CFB4`）|

星域記錄的 `+0x28`／`+0x29` 就是「這個星域裡帝國／同盟各有幾支艦隊」，
每次都是重數出來的。

> 面板上的敵方那一格讀的是 `+0x2B`（`docs/re/31` 用 poke 定的），
> **不是這支迴圈寫的 `+0x29`**——那一格另有來源，
> 大概是「你看得到的敵方艦隊」（`docs/re/23` 早就注意到兩邊看到的不是同一組）。

## 拿 S3 對照：哪些欄位是「身分」、哪些是「局面」

同一條路載進 S3「巴米利恩會戰」（第三個槽，滑鼠 `300,282`）再倒一次表。
S3 有 **18 筆在用**，帝國那幾支全部擠在星域 25——與劇本名對得上。

兩邊都在用的 17 筆逐欄相減：

**一個 byte 都沒變的**（＝ 隨劇本走的身分／編制，不是局面）：

```
+0x00 +0x01 +0x02 +0x03 +0x05 +0x0B +0x11 +0x12 +0x13 +0x15 +0x19 +0x1D
+0x34–0x37 +0x39–0x3C +0x48 +0x49 +0x50–0x5B +0x60–0x63 +0x68–0x79
```

**17 筆全部都變的**（＝ 局面）：

```
+0x06（所在星域，已確認）
+0x07
+0x4A +0x4B +0x4C
+0x5C
+0x64
```

`+0x5C` 與 `+0x64` 在 S2 第 0 筆都是 `88 04 B4 02`（1160 與 692 兩個 word），
一模一樣的兩組——**像是「現有」與「上限」兩份同樣的東西**。
`+0x4A`–`+0x4C` 在 S2 第 0 筆是 `51 51 51`（三個 81）。
都還沒有畫面可以對，先記形狀。

`+0x10`–`+0x33` 那十組 4 bytes 裡，每組的第 4 個 byte（`14 18 19 1C 1E
20 21 22 23 1D`）兩邊完全一樣，前三個會變——所以那一欄是**種類**，
前面幾個是隨局面變的數量或編號。

## 還沒回答的

  ——兩個局面的艦隊不同，相減就能框出哪些欄位是什麼。

---

`+0x10` 起那十個 4-byte 槽是指向 `SHIP.DT?` 艦艇池的索引，
`+0x5C`／`+0x64` 那兩份一樣的數與該艦隊第一個艦艇的相同——見
[`docs/re/42`](42-ship-pool.md)。

`+0x04` ＝ 提督編號、`+0x08` ＝ 狀態、`+0x0F` ＝ 一個累加進治安的量，
在未安定度那支函式裡對上了——見 [`docs/re/43`](43-unrest-full-disassembly.md)。
