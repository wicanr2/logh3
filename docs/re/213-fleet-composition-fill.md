# 213 — `0FF4:11F4` 整支：艦艇是 `2AD2:0029` 產生的，填完還會排序

`docs/re/212` 讀到編制槽的 `[2]`／`[3]` 從 `ds:2BC6` 的樣板抄過來，
但「艦艇池索引（`[0..1]`）在哪裡填」還沒定位。這一輪讀完了。

## 整支

線性 `0x11134`（`0FF4:11F4(艦隊, 類別鍵)`）：

```
星域 = ds:A79C + 艦隊[+0x06] × 126
ds:9872 = 那個星域的遠指標              ; 之後幾支都從這裡拿
樣板    = ds:2BC6 + 類別鍵 × 20
艦隊[+0x0F] = 1                         ; 第 0 組（旗艦）當作已經在了
槽指標  = 艦隊 + 0x14                   ; 從第 1 組開始
i = 1

對 i = 1 .. 艦隊[+0x0E] − 1：           ; 應有組數
    a = 樣板[i][0]
    星域擁有者 == 1 且 a == 0 → a = 1
    v = 0FF4:0E84(a)
    a == 星域擁有者 且 v < 4 …           ; 兩個條件決定要不要換
    v == 0 → a = 0FF4:1350(艦隊, a)；a == 0FFh → 結束
    槽[i][+2] = a
    槽[i][+3] = 樣板[i][1]
    槽[i][+0..1] = 2AD2:0029(艦隊, a, 0)   ; ★ 產生一筆艦艇，回池索引
    艦隊[+0x0F]++
    樣板前進 2、槽前進 4

qsort(艦隊 + 0x14, 艦隊[+0x0F] − 1, 4, 0FF4:0FF2)   ; 第 1 組起排序
```

三件事定下來了：

- **艦艇是 `2AD2:0029(艦隊, 艦種, 0)` 產生的**，回傳值就寫進槽的
  `[0..1]`——那是 `docs/re/211`／`212` 一直在找的「分到艦艇」那一步。
- **第 0 組不在這支裡填**。它把 `+0x0F` 直接設成 1、從第 1 組開始，
  所以旗艦那一組是別處放進去的。
- **填完會排序**：第 1 組起、元素 4 bytes、比較器 `0FF4:0FF2`。
  第 0 組不參與——與「第 0 組是旗艦」一致。

## 還沒讀的

| 位址 | 還缺什麼 |
|---|---|
| `2AD2:0029(艦隊, 艦種, 0)` | 產生艦艇：艘數從哪來、有沒有從星域 `+0x30` 的存量扣 |
| `0FF4:0E84(a)` / `0FF4:1350(艦隊, a)` | 決定實際採用哪個艦種 |
| `0FF4:0FF2` | 排序鍵 |
| `艦隊[+0x0E]` | 應有組數是誰設的——這一支只讀不寫 |

`+0x0E` 那一項最關鍵：它是迴圈的上界，也就是「這一支要幾組」。
收據 `turn260mem` 上三支的 `+0x0F` 是 6／4／4（`docs/re/209`），
所以 `+0x0E` 至少是這些值。

## 對 remake 的意義

`ai.NewFleet` 要長出編制，缺的四項按依賴排：

1. `+0x0E`（應有組數）——沒有它連迴圈都跑不起來；
2. `2AD2:0029` 的艘數與扣存量；
3. `0FF4:0E84`／`0FF4:1350` 的艦種決定；
4. `[2]`／`[3]` 抄樣板（**已經有資料**，`docs/re/212`）。

**這一輪仍然不動 `ai.NewFleet`**：只有第 4 項齊了，做出來的編制會是
「槽有值但沒有艦艇」，比空的更難除錯。

## 一條方法

**先把一支函式讀完再決定要不要實作它。** `docs/re/212` 停在一半時，
「`[2]`／`[3]` 有樣板了，可以先做」看起來成立；讀完才知道同一個迴圈裡
還有一個 `2AD2:0029` 產生艦艇、而且結束時整批要排序——**先做一半會
得到一個結構上不完整的編制**。多讀一輪的成本是一次 dump。
