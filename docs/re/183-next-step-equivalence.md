# 183 — 「下一步走哪一格」＝ 中點矩陣的定點迭代

`docs/spec/029` 把「`ThreatMap` 的下一格用 `Route[1]` 代替原版
`2B99:0302`，等價未驗」列為接上主流程的兩道關卡之一。這一輪把
`2B99:0302` 讀完，關卡可以劃掉——**不是驗過，是證出來的**。

## `2B99:0302(a, b, 陣營)`

```
3BAA:0062(0, 6)                                  ; 未讀（不影響傳回值）
矩陣 = (陣營 == 0) ? ds:D06A : ds:D06E           ; 遠指標
回 2B99:0349(a, b, 矩陣)
```

## `2B99:0349(a, b, m)`

```
v = m[b][a]
若 v == 0FFh：回 a
否則：回 2B99:0349(v, b, m)
```

**`b` 固定不動，`a` 一直被換成 `m[b][a]`，直到 `a` 與 `b` 直接相連**
（矩陣值 `0xFF`）為止，回那個 `a`。也就是**與 `b` 相鄰、在 `b`→`a`
那條路上的那一格**。

`2E54:1A76` 的呼叫是 `2B99:0302(艦隊[+0x07], 艦隊[+0x06], 艦隊[+0x01])`
＝ `(目的地, 所在, 陣營)`，所以 `b` ＝ 所在——回的是**這一支下一步會
走到的那一格**（`docs/re/173` 當時是從用法推的，現在是讀出來的）。

## 與 remake 的 `Route[1]` 是同一個值

`rules.StarGraph.Route(i, j)` 的展開是
`walk(i, v) ++ walk(v, j)`，其中 `v = T[i][j]`。第一個元素之後那一格，
只由左半 `walk(i, v)` 決定，而 `walk(i, v)` 又展開成 `walk(i, T[i][v]) ++ …`
——**第一步就是把第二個索引一路換成 `T[i][·]` 的定點**，
與原版把 `a` 換成 `m[b][a]` 完全相同（`m[b][a]` 的 `b` 就是 `i`）。

所以 `2B99:0302(to, from, f)` ≡ `Route(from, to, f)[1]`。

實作成 `rules.StarGraph.NextStep(from, to, faction)`（直接做定點迭代，
不展開整條路），並加了一個測試：**兩張矩陣、所有走得通的星域對**，
`NextStep` 與 `Route[1]` 逐一相同（1800 對以上）。

## 一個踩到的坑：中點矩陣在 EMS 裡

想拿 `workplace/s3ai6.bin` 直接比對 `ds:D06A`／`ds:D06E` 指到的矩陣與
`data/star-graph.json`，結果 **1010／1024 格不同**。

原因不是資料錯了：兩個遠指標解出來是 `0xE1000`／`0xE1400`，
那是 **EMS 頁框**（`data/star-graph.json` 的 note 早就寫了「原版把兩張
32×32 的中點矩陣放在 EMS 裡」，`docs/re/28`）。**平面記憶體傾印看到的
是傾印當下映在頁框裡的那一頁**，不見得是矩陣那一頁。

> 教訓：**位址落在 `0xA0000`–`0xEFFFF` 的資料，不能拿平面傾印當真相**。
> 要嘛在確定頁面映射的時刻取，要嘛像 `docs/re/28` 那樣從程式的讀取點取。
