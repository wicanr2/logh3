# 140 — 「補給」／「修理」選對象時畫什麼

`docs/re/131` 停在「選的時候候選是怎麼呈現的，還沒找到對應的程式碼」。
把 `1930:05EC` 的模態迴圈讀完就有答案了，而答案有一半是否定的。

## 迴圈長這樣

```
1930:05EC(補給艦)
    17A0:00AC(陣營, x, y, 半徑高字, 0, &清單)   ; 收候選
    17A0:016C(&清單, &清單, 篩選函式 1930:0485)
    一個都沒有 → 3826:0005(2, 0x97, ds:3F14) 然後回
    ds:A436 = 0FFFF
    1930:0AA2(補給艦, 清單)                     ; ← 畫右側面板
    1629:0154()
    165F:044D(補給艦, 0)                        ; ← 掛範圍圖形
    重複：
        1629:0005(&事件)                        ; 等輸入
        事件 == 1（左鍵）→ 1930:0769 → 1930:0815（命中哪一筆、動手）
                            並再跑一次 1930:0AA2（更新面板）
        事件 == 2（右鍵）→ 17A0:0427（重排順位）＋ 17A0:05B2（重發順位）
                            並設離開旗標
    165F:04AA()                                 ; 收掉圖形
    1629:022D()
```

**迴圈裡沒有任何「逐個候選畫點什麼」的呼叫。** 候選不會被標亮、
選中的也不會多一個記號——玩家看到的只有那個範圍圈與右側面板。
這一條是讀完整支常式得到的否定結論，不是「找不到所以推測沒有」。

## 範圍圈：`165F:044D` → `165F:09D9`

`165F:044D(單位, 旗標)` 最多掛六個圖形，id 記在 `ds:A41A`–`ds:A41F`
（`0xFF` ＝ 沒有），`165F:04AA` 逐個丟給 `3870:0072` 收掉。
旗標 0 且**艦種是 5 或 6**（補給艦／修理艦）時走 `165F:09D9`，其餘走
`165F:090E`。

`165F:09D9` 建的描述是：

```
[+0]／[+2] = 單位 +0x34／+0x36 各 ＋8      ; 佔位框中心
[+4] = 0        傾角
[+5] = 5        色號
[+6] = 1        形狀 ＝ 圓（docs/re/135）
[+7] = 1        要畫
半徑 = 艦種列[+0x06]（最高速度）× 32 ÷ 5
```

`× 32 ÷ 5` 就是那個 6.4——**與 `SupplyListRange` 的 `<<21 ÷ 5` 是不同的
算式**（一個是整數、一個是 16.16），目前每個速度都給同一個數，但寫在
`rules.SupplyRangePixels` 裡分開放，哪天差一個數才知道是誰錯。

另一個 `165F:07CA` 讀的是**艦隊**記錄（`ds:C074 + 艦隊 × 0x7A`）的 `+0x4A`
朝向，是那組轉向／朝向圖形，不是查詢範圍。

**行星版沒有這一段**：`1930:0DA2`（行星補給）與 `1AAB:0A33`（行星補充）
都不呼叫 `165F:044D`（整份程式碼裡它只有三個呼叫端：`1930:06DE`、
`1AAB:0679`、`2583:...`）。所以行星的補給不畫圈。

## 面板：`1930:0AA2`

`3982:022D(陣營)` 回非 0 就整支跳過（**電腦方不畫**）。否則把
`ds:9B7A` 設成 `0FFFD`，再用 `3617:003A(視窗 ds:9890, 格式字串 ds:3F29,
陣營名 ds:60F4[陣營], …)` 把「艦隊名／運輸艦數／飛彈／戰鬥機」印進
右側那個視窗。動手之後（`1930:0802`）會再跑一次，所以它同時是
「選的時候顯示現況」與「動完更新」。

> `docs/re/131` 把 `1930:0AA2` 記成「動手之後的結果訊息」，只說對了一半
> ——它在進迴圈之前就先跑一次。

`3617:003A` 是全遊戲的「印字進視窗」，**611 個呼叫端**；它背後是
`3617:0059` → `3ACA:0079`（printf）＋ `3617:0099`（輸出回呼，兩張控制碼
跳表 `ds:6BCC`／`ds:6BDC`）。整套文字排版還沒逆向，這是後面最大的一塊。

## 進 remake

`rules.SupplyRangePixels`、`screen.DrawSupplyRange`、
`game.supplyRangeCircle`。面板要等 printf 那一套。

## 可重用的規則

- **「找不到」與「沒有」是兩件事，而分辨它們的方法是把整支常式讀完。**
  這裡讀完迴圈之後可以說「候選沒有高亮」，而不是「候選的高亮還沒找到」
  ——前者是可以拿去改規格的結論，後者只是待辦。
- **同一個數字用兩條算式算出來時，程式碼裡也要有兩條。** `× 32 ÷ 5` 與
  `<<21 ÷ 5` 現在每個輸入都同值；合併成一條會在它們哪天分岔時變成一個
  找不到的差異。
