# RE 102 — 戰場上一回合走多遠

`docs/re/80` 量到兩支艦隊一回合分別走約 233 與 325，當時寫「大概跟機動力
（`+0x3C`）有關，還沒驗」。這一輪把整條鏈拆完，remake 走出來的落點與
原版**逐像素相同**。

## 機動力不是答案

先看 `s3tgt` 的傾印：十八支艦隊的 `+0x3C` **全部是 100**。所以差別不在那裡。

## 盯座標欄位

收據 `s3move`（`-watch 613A0-613A3`，同盟 16 的 `+0x5C`／`+0x5E`）印出
139 次寫入。移動不是「一回合跳一次」，是**逐格動畫**：

```
[watch] #1025728241 613A0: 50 → 4C  ← 1C03:031B     x −4
[watch] #1025728243 613A2: FC → F5  ← 1C03:0322     y −7
```

每一步 (−4,−7)，長度 √65 ＝ 8.06 ——**和直線通行判定（`1588:0891`）
用的 8 是同一個**。一回合 29 步，兩回合各 29 步。

## 行程是一個預算

`1C03:01B6` 的迴圈：

```
loop:
    若 艦隊[+0x56/+0x58]（32 位元）< 8：這一回合走完
    (nx,ny) ＝ 從 (+0x5C,+0x5E) 沿朝向 +0x4A 前進 8      ; 2BE1:026F
    d ＝ 距離((+0x5C,+0x5E), (nx,ny))                      ; 3310:0006，16.16
    若 d ＝ 0：d ← 1
    艦隊[+0x56/+0x58] −= d
    r ＝ 能不能站(nx, ny, 陣營)                            ; 2583:040C
    若 r ＝ 0：+0x5C ← nx；+0x5E ← ny
```

`+0x56`／`+0x58` 是 **16.16 定點的剩餘行程**。收據 `s3budget`
（`-watch 6139A-6139D`）看得很清楚：

```
#950404985  +0x58 ← 00F0          ; 240.0
… 29 次 −8.06 …                    ; 剩 6.06
#1018713732 +0x58 ← 00F0          ; 下一回合再填 240.0
```

## 能不能站

`2583:040C(x, y, 陣營)`：

```
若 !可通行(x,y)：回 0xFFFF        ; 1588:04EA，就是 docs/re/100 那張地形表
r ＝ 撞到誰(x, y, 陣營)            ; 17A0:06D7
若 r ＝ 0xFFFF：r ← 0
回 r
```

所以**戰場移動與集結點的直線判定用同一套地形規則**。

## 預算從哪來

每回合開頭由 `1C03:004F`／`1C03:0053` 從 `+0x52`／`+0x54` 複製過來，而
`+0x52`／`+0x54` 整場只在開戰時寫一次（`307D:1468`）：

```
al = 艦隊[+0x4E] ; cwd → dx:ax
di = ax ; 左移 19 位（shl di,1 / rcl dx,1 × 19）
艦隊[+0x54] = dx ; 艦隊[+0x52] = di
```

左移 19 位再當 16.16 讀 ＝ **× 8**。所以

> **一回合的行程 ＝ 艦隊 `+0x4E` × 8 像素 ＝ `+0x4E` 步。**

傾印裡十八支全部對得上：

| 艦隊 | `+0x4E` | 行程 | ÷ 8 |
|---|---|---|---|
| 同盟 16 | 30 | 240 | 30 |
| 同盟 17 | 33 | 264 | 33 |
| 同盟 28 | 30 | 240 | 30 |
| 同盟 29 | 30 | 240 | 30 |
| 同盟 30 | 26 | 208 | 26 |
| 同盟 31 | 41 | 328 | 41 |

同盟 31 的 328 正是 `docs/re/80` 量到的「每回合約 325」。

## `+0x4E` 自己

整份 1 MB 記憶體裡寫 `[?+4Eh]` 的指令**只有一處**（線性 `0x2A810`）。
那支對艦隊的每一組編制跑一圈取最小值：

```
分隊[+0x21] ＝ 艦種列[+6] × 艦隊能力[+0x42] ÷ 80
艦隊[+0x4E] ＝ min(各分隊[+0x21])
```

同一段還寫死 `艦隊[+0x3C] = 100`——難怪十八支的機動力都是 100。
旁邊的 `+0x4D`（÷ 100）與 `+0x4F`（÷ 60）是同一批算出來的姊妹欄位。

**`艦種列[+6]` 是哪一張表還沒對出來**，所以這一項停在「知道算式、
不知道輸入」。

## remake

`rules.AdvanceBattle` 照這條改：沿指向目標的方位每次走 8，行程餘額用
8.8 定點扣（截成整數會多走一步——原版 29 步會變 30 步），每一步先問
`BattleTerrain.Passable`。

用收據的起點與目標跑兩個回合：

```
第 1 回合：(1536,1840) → (1420,1637)，走了 233
第 2 回合：(1420,1637) → (1306,1434)，走了 232
```

**兩個回合的落點與原版收據逐像素相同。**

原版沿的是艦隊**現在的朝向** `+0x4A`，另有一支慢慢轉向 `+0x4C` 的邏輯
（`1C03:0361`）還沒逆向；這一段路上朝向已經指著目標，所以對得上。
轉彎中的落差還沒量。
