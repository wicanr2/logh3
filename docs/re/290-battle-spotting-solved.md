`docs/worklist.json` 的 `battle-seen-flag` 寫著「`+0x17` 被看到時設成 3，
設成 3 的**時機**還沒讀出來」。**那個前提本身就錯了**：一般情況下
沒有人把 `+0x17` 設成 3，它是**每被看到一輪加一、上限 3**。
「直接寫 3」只有兩個特例，而那兩處 `docs/re/85` 早就找到了——
少掉的是中間那支真正的索敵常式。

## 為什麼 `docs/re/85` 會漏掉它

`docs/re/85` 找寫入點的方法是「在記憶體裡搜 `26 C6 47 17` 之類的指令編碼」
——只收 `mov es:[reg+17h], imm` 與 `mov es:[reg+17h], al` 這兩種形狀。
真正的索敵常式走的是另一條：

```
25570  83 C3 17        add bx,17h          ; 先把基底加上去
25573  B0 03           mov al,3
25575  26 38 07        cmp es:[bx],al
25578  74 17           jz  → 25591
2557A  26 FE 07        inc byte es:[bx]    ; ← +0x17 ＋＋，這一條搜不到
```

`+0x17` 的位元組在 `83 C3 17` 裡，離 `FE 07` 三個位元組遠，
任何「找 `disp8 == 0x17`」的掃描都看不到它。這正是
[`docs/re/288`](288-fleet-record-remaining-fields.md) 補進
`field_xref.py` 的那個洞——本輪它一跑就把這兩處 `add reg,17h` 列了出來
（另一處 `0x2972D` 是別的結構的 word 讀取，不是寫入）。

同一份掃描裡還有兩個假陽性，形狀與 `re/288` 的 `FF 74 4B` 一樣：
`034A4` 是 `3C 09`（`cmp al,9`）接 `74 17`（`jz`）、
`04700` 是 `3C 08` 接 `77 17`（`ja`）——都是跨指令邊界的巧合。

## 整條鏈

每個回合結束時（`181B:000A` → `181B:0262`，線性 `0x18412`），
**兩個座位各跑一次**索敵：

```
18427  31 C0 / 50 / 9A F8 00 26 25     2526:00F8(座位 0)
18431  B0 01 / 50 / 9A F8 00 26 25     2526:00F8(座位 1)
```

### `2526:00F8`（線性 `0x25358`）：誰在看

```
陣營 = ds:8F25[座位]
對在場艦隊清單（ds:9898、筆數 ds:9894）裡 艦隊[+0x01] == 陣營 的每一支：
    2526:0198(艦隊)
對目前星域的行星切片（ds:CFF8、顆數 ds:CFFC）裡 行星[+0x11] == 陣營 的每一顆：
    2526:022C(行星)
```

### `2526:0198`（線性 `0x253F8`）：一支艦隊有兩隻眼睛

```
ds:A776/A778 ← 艦隊 far ptr ; ds:A77A/A77C ← 0      ; 報告用的「這次是誰看到的」
2526:01FE(艦艇池 + 艦隊[+0x10] × 78)                 ; 旗艦分隊
25437  26 80 7F 3A FF   cmp byte es:[bx+3Ah],0FFh
2543C  74 1C            jz  → 2545A                  ; 沒放偵察隊就到此為止
2526:01FE(艦艇池 + 艦隊[+0x38] × 78)                 ; 索敵分遣隊
```

**只有旗艦分隊（第 0 組）跟偵察隊在看**，其餘分隊沒有視野。

### `2526:01FE`（線性 `0x2545E`）：半徑

```
25465  26 80 7F 04 07   cmp byte es:[bx+4],7        ; 艦種
2546A  75 05            jnz → 25471
2546C  B8 FA 00         mov ax,0FAh                 ; 250
25471  B8 C8 00         mov ax,0C8h                 ; 200
25482  9A 6D 02 26 25   2526:026D(艦艇[+0x34], 艦艇[+0x36], 半徑, 艦艇[+0x00])
```

艦種 7 是偵察隊（`docs/internals/40` 的代號字母只有 `BHCADTE` 七種，
艦種 7 不在裡面；`docs/internals/38` 也記著它不扣血、圖塊固定 9）。
所以**旗艦看 200 像素、偵察隊看 250**。

注意最後一個參數取的是**分隊自己的 `+0x00`**，不是艦隊記錄的 `+0x01`。
兩者平常一致，但注入過的收據會不一樣（見下面 `s3fltmove` 那一段）。

### `2526:022C`（線性 `0x2548C`）：行星也在看

```
ds:A776/A778 ← 0 ; ds:A77A/A77C ← 行星 far ptr
半徑 = 2AF5:01F7(行星)
2526:026D(行星[+0x46], 行星[+0x48], 半徑, 行星[+0x11])
```

`2AF5:01F7`（線性 `0x2B147`）：

```
2B14E  26 8B 47 14      mov ax,es:[bx+14h]      ; 行星 +0x14 防衛力
2B152  B9 DC 05         mov cx,05DCh            ; 1500  → 下限
2B15F  B9 70 17         mov cx,1770h            ; 6000  → 上限
2B16C  B9 19 00         mov cx,19h              ; ÷ 25
```

**行星的索敵半徑 ＝ clamp(防衛力, 1500, 6000) ÷ 25**，也就是 60–240 像素。

### `2526:026D`（線性 `0x254CD`）：查一圈、逐筆升級、再報告

```
敵方 = 3982:0250(陣營)                                  ; (陣營 == 0) ? 1 : 0
n    = 17A0:00AC(敵方, x, y, 半徑, &清單)               ; 半徑內的敵方分隊
n    = 17A0:016C(&清單, &清單, 2526:02D7)               ; 逐筆升級，留下「有變的」
若 n != 0: 2526:033B(&清單, n, 陣營, x, y)              ; 發現敵艦隊的報告
```

`3982:0250`（線性 `0x39A70`）整支只有 12 個位元組：
`55 89 E5 8A 4E 06 08 C9 75 05 B8 01 00 EB 02 31 C0 5D CB`
——參數是 0 回 1、否則回 0，就是「另一邊」。

`17A0:016C`（線性 `0x17B6C`）是個 filter：走 `0xFFFF` 結尾的清單，
跳過 bit15 設起來的項，`call far [bp+14h]` 叫回呼，
回非 0 的才寫進輸出清單。輸入與輸出是同一個緩衝，所以是就地過濾。

### `17A0:00AC`（線性 `0x17AAC`）：半徑內的敵方分隊

走在場分隊清單（`ds:98BA`、筆數 `ds:9896`），逐筆三道關：

```
17AFC  26 8A 04         mov al,es:[si]          ; 艦艇 +0x00 陣營
17AFF  3A 46 1A         cmp al,[bp+1Ah]         ; == 敵方？
17B06  26 F6 44 1E 80   test byte es:[si+1Eh],80h
17B0B  75 43            jnz → 17B50             ; +0x1E bit7 設起來 → 不列入
17B1D  9A 06 00 10 33   3310:0006(中心x, 中心y, 艦艇[+0x34], 艦艇[+0x36])
17B2C  9A B9 00 C9 3C   32 位元比較：距離 ≤ 半徑 << 16
```

`+0x1E` bit7 是「不會被選進攻擊名單」（`docs/internals/38`、`docs/re/90`）。
**佈陣時偵察隊的 `+0x1E` 被寫成 `0xFF`、其餘分隊寫 `0x7F`**
（線性 `0x2A124` 與 `0x2A184`），所以**偵察隊看得到別人，別人看不到它**。

### `2526:02D7`（線性 `0x25537`）：這一格就是「看到」

```
2553F  8B 7E 10         mov di,[bp+10h]         ; 參數 ＝ 艦艇池索引
25549  B9 4E 00         mov cx,4Eh              ; × 78
25560  83 C6 16         add si,16h
25563  26 F6 04 01      test byte es:[si],1     ; +0x16 bit0 這一輪看過了？
25567  75 28            jnz → 25591             ; 看過了 → 回 0
25569  26 80 0C 01      or byte es:[si],1       ; +0x16 |= 1
25570  83 C3 17         add bx,17h
25573  B0 03            mov al,3
25575  26 38 07         cmp es:[bx],al          ; +0x17 已經是 3？
25578  74 17            jz  → 25591             ; 是 → 回 0
2557A  26 FE 07         inc byte es:[bx]        ; ★ +0x17 ＋＋
25580  C7 46 04 01 00   mov word [bp+4],1       ; 回值 ＝「層級有變」
25585  3A D0            cmp dl,al
25587  75 08            jnz → 25591
2558C  26 C6 47 18 02   mov byte es:[bx+18h],2  ; 升到 3 才寫 +0x18 ← 2
```

所以：**一輪最多升一級，要連續被看到三輪才會到 3**，
而 `+0x18 ← 2` 是「升到 3 的那一刻」附帶的，不是「被看到」附帶的。
回值餵給上面那個 filter，所以報告只列「這一輪顯示層級真的變了的」。

### 衰減：`2526:000E`（線性 `0x2526E`）→ `2526:005A`（線性 `0x252BA`）

`docs/re/85` 讀過，不改寫。要補的是**時機**：它由
`12AA:0245`（線性 `0x12CE5`）在回合開頭呼叫，條件是那支的參數非 0。

一個回合的順序因此是

```
12AA:0245   回合開頭 → 2526:000E → 2526:005A   ; 沒被看到就掉一級，然後清 +0x16 bit0
  …移動、接觸、扣血…
181B:000A → 181B:0262 → 2526:00F8 ×2           ; 索敵：設 +0x16 bit0、+0x17 ＋＋
ds:8F1A ++                                      ; 回合數（docs/re/92）
```

## 兩個「直接寫 3」的特例

### 一：戰略層打行星，而那個星域有主（線性 `0x22447`）

`20B4:18C2`（線性 `0x22402`）把一支艦隊的**所有**分隊設成
`+0x17 ← 3`、`+0x18 ← 2`。唯一的呼叫點在 `20B4:1662`（線性 `0x221A2`）：

```
2220E  26 C6 47 48 01   mov byte es:[bx+48h],1   ; 艦隊行動 ← 戰鬥
22213  C4 7E 2A         les di,[bp+2Ah]          ; 第一個參數 ＝ 星域記錄
22216  26 80 7D 12 02   cmp byte es:[di+12h],2
2221B  74 0B            jz  → 22228              ; 星域無主 → 不揭露
22221  9A C2 18 B4 20   20B4:18C2(艦隊)
```

第一個參數是星域記錄：呼叫端 `20B4:1512`（線性 `0x22052`）最後才
`push [bp+30h] / push [bp+2Eh]`，而那一對是 `ds:A79C + 星域 × 126`
（`docs/internals/53` 的呼叫鏈原本把這一格寫成「`…[+0x12] != 2`」，
沒說是誰的 `+0x12`）。星域 `+0x12` ＝ 擁有者，2 ＝ 無主
（`docs/internals/22`、`docs/re/106`）。

所以規則是：**在有主的星域裡打行星，攻方整支艦隊立刻現形**；
無主星域沒人看著，攻方不現形。

### 二：電腦在第 7 回合之後完全看不到敵人（線性 `0x30246`）

`3009:0003`（線性 `0x30093`）是**電腦座位**的戰鬥處理
（呼叫端 `12AA:037C`，線性 `0x12E1C`，條件 `ds:8F23[ds:8F1E] == 1`）：

```
300A5  83 3E 1A 8F 06   cmp word ds:8F1A,6
300AA  72 05            jb  → 300B1              ; 回合 < 6 就跳過
300AC  9A 8D 00 09 30   3009:008D()
```

`3009:008D`（線性 `0x3011D`）分兩趟：

```
第一趟：對 艦隊[+0x01] != ds:8F1D 的每一支、每一個分隊
    301A6  26 80 7C 17 00   cmp byte es:[si+17h],0
    301AD  BF 01 00         mov di,1             ; 只要有一個 != 0 就記著
第二趟（只有 di == 0 才跑）：對同一批分隊
    3023F  26 80 4C 16 01   or  byte es:[si+16h],1
    30246  26 C6 44 17 03   mov byte es:[si+17h],3
    3024D  26 C6 44 18 06   mov byte es:[si+18h],6
```

**回合 ≥ 6（畫面上的第 7 回合起）、而且目前這一方一個敵方分隊都看不到，
就把敵方全部揭露，停在第 3 級六個回合**——`+0x18` 給 6 而不是 2 就是
為了撐住。這是防僵局的規則，不是索敵。

`+0x17` 只有一份、由雙方的索敵共同推動，看起來像簡化，其實不會衝突：
一個分隊的敵人只有一方，所以 `+0x17` 的意思就是「敵方現在看它看得多清楚」。

## 清成 0 的三處

| 線性 | 位元組 | 什麼時候 |
|---|---|---|
| `0429D` | `26 C6 44 17 00` | 某個星域的所有艦隊：`+0x48` ← 4（待命）、每個分隊 `+0x17` ← 0 |
| `2A12B` | `31 C0` ＋ `26 88 47 17` | 佈陣：一般分隊（同時 `+0x16` ← 0、`+0x19` ← `3Fh`、`+0x1E` ← `7Fh`）|
| `2A18B` | `31 C0` ＋ `26 88 44 17` | 佈陣：偵察隊（`+0x1E` ← `0FFh`）|

## 掃描的完整性

> 本檔的線性位址一律指**指令起點**（含 `26` 段前綴）。`field_xref.py`
> 印的是 opcode 的位址，比這裡大 1；下表那一欄照工具的輸出寫。

`field_xref.py` 在 `+0x17` 上開出 122 處 ＋ 2 處 `add reg,17h`。逐一用
`struct_window.py` 的鄰居判過基底是哪一張表（艦隊 122／星域 126／
行星 82／艦艇 78 共用同一段 disp8 值域）：

| 線性 | 鄰居位移 | 屬於 |
|---|---|---|
| `188C3` | `+04 +11 +16 +17 +18` | **星域**（重算這個星域的三種行星數）|
| `2863E`／`286A6` | `+11 +12 +16 +17 +18 +1A +1C +20 +22` | **星域**（`2703:15D5`，`docs/re/106`）|
| `2A12C`／`2A18C` | `+16 +17 +19 +1E +28 +2A +34 +36`（＋艦隊 `+0F +38 +5C +5E`）| **艦艇**（佈陣）|
| `3CC22` | `+01 +05 +07 +09 +0B +0D +15 +17` | 程式庫，word 寫入 |
| `2972D` | 無 | 別的結構的 word **讀取**，不是寫入 |

艦艇 `+0x17` 的**寫入者總共九處**：`0429D`、`2A12B`、`2A18B`（← 0）、
`25328`／`25332`／`2533C`（衰減）、`2557A`（＋＋）、`22447`／`30246`（← 3）。

正對照在同一次掃描裡：`+0x18` 找得到 `2558C`、`2244E`、`3024D`、`25322`，
`+0x16` 找得到 `25569`、`3023F`、`25344`——掃描在已知有人用的位移上
都開得了口，才拿它去問未知的。

## 分布對得上：`tools/scripts/scout_vision.py`

把上面的規則重算一次，跟傾印裡的 `+0x17` 並排。觀測者 ＝ 每支在場艦隊的
旗艦分隊（200）＋ 已放出的偵察隊（250）＋ 己方在這個星域的行星
（`clamp(+0x14,1500,6000) ÷ 25`）；候選 ＝ 在場分隊清單裡陣營為敵方、
`+0x1E` bit7 沒設、距離在半徑內的。

| 傾印 | 回合 | 在敵方視野內 | 其中 `+0x17 != 0` | 視野外但 `+0x17 != 0` |
|---|---:|---:|---:|---:|
| `s3ai6` | 0 | 0 | 0 | 0 |
| `s3turn2`／`dm_pre`／`dm_post`／`s3datamem` | 2 | 0 | 0 | 0 |
| `s3fight`／`s3kinds`／`s3kinds2`／`s3flag` | 4 | 8 | 7 | 1 |
| `s3fltmove` | 4 | 38 | 33 | 0 |
| `s3cmdmove` | 4 | 8 | 7 | 1 |

逐筆看那些「例外」，一個都不是例外：

- **在視野內但 `+0x17 == 0` 的，全部是偵察隊**（組號 `0xFF`、艦種 7、
  `+0x1E == 0xFF`），而且它們的 `+0x16` 也是 `0x00`——索敵那一趟從來
  沒碰過它們。`s3fltmove` 那五個、其餘各一個，零例外。
- **在視野外但 `+0x17 != 0` 的**，`s3fight` 系列是同盟第 28 艦隊的旗艦
  分隊，離最近的觀測者 **22.4 像素**，`+0x17` 是 1——上一輪還在圈內、
  這一輪正在掉。

`s3fltmove` 是最好的一份：`+0x16` bit0 **全部是 1**（傾印切在索敵之後、
下一輪衰減之前），而艦隊 31 的組 0–2 是 `+0x17 == 3`、`+0x18 == 2`，
組 3–6 是 `+0x17 == 2`、`+0x18 == 0xFF`。**只有升到 3 的那三筆有 `+0x18`**
——這正是 `2526:02D7` 那個 `cmp dl,al / jnz` 的形狀，
沒有第二種規則做得出這個分布。

`docs/re/85` 當初把「組 0–2 停在 2、組 3–6 掉到 1」解釋成
「它們是在不同時間被看到的」，方向對但機制講反了：不是「被看到時設 3
再往下掉」，是**一直被看著所以一級一級往上爬**，只是那一場還沒爬到頂。

### 注入過的收據要另外看

`s3cmdmove` 與 `s3fltmove` 走的是 `s3cmdrange` 的注入序列
（`docs/re/119`、`docs/re/125`），裡面把某一筆的 `+0x00` 改成了 0
好讓玩家點得開命令選單（`艦艇 +0x00 == ds:8F1D` 才開）。
於是 `s3fltmove` 裡同盟第 28 艦隊的旗艦（池 #109）`+0x00` 是 0，
它**因此變成一隻帝國的眼睛**，把周圍七個同盟分隊照亮——
第一版的對照工具拿艦隊記錄的 `+0x01` 當觀測方陣營，
那七筆就成了「視野外卻被看到」的假例外。改成讀分隊自己的 `+0x00`
（`2526:01FE` 真正 push 的那一格）之後歸零。

**注入過的收據不是壞收據，但它的每一格都要當成可能被改過。**

## 順帶解掉的三件事

- **`docs/re/160` 的「148 筆 `+0x17` 全程 0」是負對照，現在有解釋**：
  那兩份傾印停在第 2 回合，**視野內一個敵方分隊都沒有**，所以誰都沒有
  被看到過。同一支工具在同一份傾印上算出「在敵方視野內 0 筆」。
- **`docs/re/132` 的「偵察隊自己的視野效果還沒解」**：偵察隊就是
  `2526:0198` 的第二隻眼睛，半徑 250（艦種 7），而且自己因為
  `+0x1E == 0xFF` 不會被敵方看到。
- **`docs/internals/53` 的「若 …`[+0x12] != 2`」那個沒有主詞的條件**：
  主詞是星域記錄，`20B4:18C2` 做的事是把攻方艦隊整支揭露。

## 方法

**「這個欄位被設成 N」跟「這個欄位怎麼變成 N」是兩個問題，前者答對了
不代表後者也對。** `docs/re/85` 找到了三個寫入點，其中兩個真的寫 3，
於是「被看到時設成 3」看起來像是讀出來的結論——實際上它是從
**三個樣本裡的兩個**推出來的，而少掉的第四個寫入點才是主要路徑。
掃描漏一條，結論不會空白，會變成一個自洽但錯的規則。

**值的分布這一次兩個方向都給了訊號，但要先有程式才讀得懂。**
`+0x18` 只在三筆記錄上有值、其餘是 `0xFF`——單看分布會以為那是壞資料；
配上 `2526:02D7` 的 `cmp dl,al / jnz` 就知道那是「只有升到 3 才寫」。
同一份分布，先讀程式與先看數字會得到不同的結論。
