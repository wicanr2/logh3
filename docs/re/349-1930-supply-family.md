## 一、`1930:019D()`：戰場第 ① 步的補給（P，位元組）

**沒有參數。** 兩個迴圈：

- **迴圈 A**：走場上分隊清單（`ds:98BA` × 筆數 `ds:9896`），對**艦種 5（補給艦）**
  呼叫 `1930:02B4(船)`。半徑 ＝ 艦種 5 那一列的 `+0x06`（30）`<< 21` 再 `÷ 5`
  ＝ 16.16 定點的 **192.0**，存進 `ds:A43A`／`ds:A438`（與 `docs/re/131` 一致）。
- **迴圈 B**：走本星域的行星切片（`ds:CFF8`／顆數 `ds:CFFC`），跳過無主（`+0x11 == 2`），
  對每顆呼叫 `1930:03AB(行星)`。

兩支的形狀相同：`17A0:00AC` 收候選 → `17A0:016C` 用 `1930:0485`／`10B2` 篩 →
`3C6A:000D` 用 `1930:0510` 排序 → 逐一 `1930:0944`／`113E` 搬，來源空了就 break。

**這整批就是分隊命令選單「補給」那條路已經解過的同一批**（`docs/re/131`），
`019D` 是自動版。

- 篩選：同陣營、艦種 ∉ {5, 6, 7}、距離 ≤ 半徑。
- 排序：`+0x01`（擁有者艦隊槽號）→ `+0x03`（組序）升冪。
  **不是**自家星域補充那一套「旗艦優先 ＋ 殘破優先」（`docs/re/346` §五）。
- 搬：`給 = min(來源存量, 列[+0x10 或 +0x14] × 目標[+0x08] − 目標[+0x0E 或 +0x12])`；
  來源扣、目標加；人類座位（`3982:022D == 0`）才印訊息。

> **來源有兩種**：補給艦的 `+0x0E`／`+0x12`，**以及有主行星的 `+0x3C`／`+0x40`**
> （`1930:113E` 與 `0944` 逐指令同構，只差來源欄位）。remake 要補第 ① 步的話
> 兩種都要，只做補給艦會少一半。

## 二、`1930:1572(星域)`：那塊 108600 的來源（P，位元組 ＋ P，收據）

```
1930:1572(idx):
    r = ds:A79C + idx×126；ds:8F1D = r[+0x12]
    清單 = 297B:131C(1, idx)          ; 與 1AAB:0FAF 同一支、同旗標
    for f in 清單: 1930:15F4(ds:C074 + f×122, r)
    ds:8F1D = 0xFF

1930:15F4(f, r):
    for j in 0..f[+0x0F)-1:            ; 編制陣列，碰不到索敵分遣隊
        c  = 池[word(f[+0x10+4j])]
        列 = ds:4E3A + c[+0x00]×208 + c[+0x04]×26
        缺飛彈   = 列[+0x10] × c[+0x08] − c[+0x0E]     ; 32 位元帶符號減
        缺艦載機 = 列[+0x14] × c[+0x08] − c[+0x12]
        w = r[+0x12] × 4                               ; 用星域擁有者當索引
        給飛彈   = min(r[+0x68+w], 缺飛彈)             ; ★ 無號比較
        給艦載機 = min(r[+0x70+w], 缺艦載機)           ; ★ 無號比較
        c[+0x0E] += 給飛彈 ；c[+0x12] += 給艦載機
        r[+0x68+w] −= 給飛彈；r[+0x70+w] −= 給艦載機
```

- **不是整批搬、不是按比例**：逐組取 `min(星域存量, 補到滿的缺口)`，**先到先拿**
  ——前面的組拿光，後面的組拿 0。
- **沒有任何艦種過濾**：艦種 5（補給艦）與 6（修護艦）也一起補。
- 索引用的是 `r[+0x12]`（星域擁有者）而不是艦艇的 `c[+0x00]`。候選已被 `297B:142A`
  篩成同陣營，實務上兩者相同。

### 星域那一側的扣，兩個呼叫之後就被抹掉（P）

`0374:0556` 的序列是 `1930:1572` → `1AAB:0FAF`，而 `1AAB:0FAF` 的第 ③ 步是
`2703:12EB(r)`。本輪把它讀出來了：它 `memset(r+0x30, 0, 0x38)`、
`memset(r+0x68, 0, 8)`、`memset(r+0x70, 0, 8)`，再從每顆行星的 `+0x20`／`+0x3C`／`+0x40`
重算。

所以 `1930:15F4` 扣掉的那些**只是同一次呼叫裡的共用預算，不是跨回合的消耗**——
這正解釋了收據裡 `+0x68`／`+0x70` 補充前後都是 108600。

## 三、收據逐值對上（P，收據）

`fcmd-supply-mem` 的池 #0（帝國艦種 0，滿編 3000、被 poke 成 100 艘）：

| 欄位 | 補充前 | 補充後 |
|---|---:|---:|
| `+0x0E` 飛彈 | 12000 | **132200** |
| `+0x12` 艦載機 | 36000 | **179400** |

艦種表帝國艦種 0：`+0x10 = 4`、`+0x14 = 12`。

```

            12000 + 108600 = 120600

            120600 + 11600 = 132200 ✓

艦載機同理： 36000 + 108600 = 144600；12×2900 = 34800；144600 + 34800 = 179400 ✓
```

## 四、順手挖到的原版 bug（P，位元組；可達性 S）

三支搬運（`0944`／`113E`／`15F4`）的缺口都是**帶符號**減（`sub`／`sbb`），
卻用**無號**比（`jb`／`jbe`）。目標超編時缺口變成接近 2³²，`min` 於是選「來源全部」
——**來源被抽乾**。本輪的收據就是走這個分支（poke 把艘數壓到 100，兩格存量留在
3000 艘的值，缺口因此為負）。

推論（**沒有執行期收據**）：艦種 **6（修護艦）**的 `+0x10`／`+0x14` 都是 0，
而 `1AAB:1286` 每回合把它的 `+0x0E` 設成艘數（`docs/re/346` §四）
→ `1930:15F4` 走到修護艦那一組時缺口必為負 → **整格存量被它吃光，排在後面的組
當回合拿 0**。吃進去的量隨後又被 `1286` 與 `2703:12EB` 兩邊抹掉，所以唯一看得到的
後果就是「後面的組補不到」。

要定案：在 `1930:1572` 與 `1AAB:0FAF` 之間 `-peek` 星域的 `+0x68`。本輪沒做。

**使用者裁決（2026-09-19）：不照抄，缺口夾 0。** remake 算出負的缺口就當 0（不補），
不模仿無號比較的溢位。理由是那是明顯的算術 bug，把它寫進新程式碼的代價高於
逐位元組一致的價值；代價是**如果玩家局面走到「某一組超編」，艦艇存量會與原版分岔**
——列進規格 063 的已知差異。

## 五、三支的關係

**完全不同的三份程式碼**，各有自己的 prolog／epilog，沒有共用子函式，也不是同一支的
兩個入口。但 `1930:0944`（`+0979`–`+0A82`）、`1930:113E`（`+1146`–`+127C`）、
`1930:15F4`（`+163B`–`+17AD`）三段「算缺口 → 取 min → 加減」**逐指令同構**，
是同一段原始碼被複製或 inline 了三次（**S**）。

段 `1930` 是補給那一族：手動 `05EC`、戰場 `019D`、戰略 `1572` 三條路共用
`0485`／`0510`／`0944`／`0AA2`。
