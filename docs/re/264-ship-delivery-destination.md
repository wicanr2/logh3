# 264 — 月底交付的船艦進首都行星

日期：2026-09-10
執行器：dosgolem-logh3 `ef5be47`（未提交檔案 0 個）
收據：`shipdeliver3`、`shipdeliver4`（同一組輸入，兩趟逐位元組相同）
狀態：**confirmed**

`docs/re/21` 解出月底交付的**數量**就是生產計劃上的「建造中」那一欄，
交付之後那些船進了哪裡一直空著。這一輪把它補上：進**自己陣營首都行星**的
補充存量，同時記進首都星域的艦艇彙總。

## 交付本體 `2B5F:001F`

月底本體的第一支（`docs/spec/035`）。從 `workplace/mem-main.bin` 切段
（`tools/scripts/seg_to_com.py`）給 IDA 反組譯：

```
2B5F:001F:
    if ds:8F1D == 0:  星域 = 0,    行星 = 0        ; 帝國
    else:             星域 = 0x1F, 行星 = 4        ; 同盟
    2AF5:0036(星域, 0)                             ; 切到那個星域的行星切片
    星域記錄 = ds:A79C + 星域 × 126
    行星記錄 = ds:CFF8 + 行星 × 82
    建造中   = ds:8F9C + 陣營 × 0x1C
    for 艦種 k in 0..6:
        v = 建造中[k]                              ; 32 位元
        星域記錄[0x30 + 陣營×0x1C + k×4] += v
        行星記錄[0x20 + k×4]             += v
```

兩個加總目標都是既有欄位：星域記錄 `+0x30`／`+0x4C` 是雙方七艦種的艘數
（`docs/internals/22`），行星記錄 `+0x20 + 艦種×4` 是補充存量
（`docs/internals/29`）。**加，不是設**；而且七個艦種一次做完，不打折。

星域 0 的第 0 顆是**奧丁**、星域 31 的第 4 顆是**海尼森**，兩邊的首都行星。

## `ds:8F9C` — 建造中的船艦

新的全域：`2 陣營 × 7 艦種 × 32 位元 ＝ 56 bytes`，線性 `0x5DACC`。
大小由 `2B5F:000A` 佐證，它把 `ds:8F9C` 起 `0x38` bytes 清成 0
（`3C9C:000A(ds:8F9C, 0, 0x38)`），全份程式碼只有 `0x03A6C`（`0349:05DC`）
一個呼叫點，在新遊戲初始化那條線上。

它落在 `WORK.DT?` 全域區塊 `+0x88`–`+0xBF` 那個先前空著的洞裡
（`docs/internals/30`），存檔可以直接驗：

| 存檔 | 帝國 | 同盟 |
|---|---|---|
| `WORK.DT8` | 2200 730 3970 380 2650 2200 630 | 2010 690 3260 390 3630 1940 540 |
| `WORK.DT9` | 2240 740 4040 390 2690 2240 640 | 2010 690 3260 410 3630 1940 540 |
| `WORK.DTA` | 全 0 | 全 0 |

另外兩處參照都是**讀**：`0654:01A4`（船艦接收報告的內容繪製，
造艦數那一欄）與 `0EF0:0B20`（生產計劃的一列，同時顯示
`ds:8FD6` 的百分比與這裡的建造中）。寫入走 `0EF0:0B20` 把
`(ds, ds:8F9C + 陣營×0x1C + 艦種×4)` 這個遠指標交給 `0F7A:0445`
那個欄位事件迴圈——**這一段是強推論，還沒看到存入指令本身**。

## 量測

`shipdeliver4`：新遊戲從頭跑 1,700,000,000 步，24 次「實行」點擊，在
1,620,000,000 與 1,690,000,000 兩點各倒一份行星表（`lin:53132:6642`）、
星域表（`lin:5F2CC:4032`）與回合計數器（`lin:5DA48:2`）。兩點的回合分別是
9 與 10，跨月夾在中間。

行星補充存量 `+0x20` 的差（81 顆全掃，只有五顆變動）：

| 行星 | 星域 | 差 |
|---|---|---|
| 0 奧丁 | 0 第 0 顆 | **3790 1260 6830 630 4550 3250 1030** |
| 51 帕謬爾 | 21 第 0 顆 | 高速戰艦 −210 |
| 52 阿爾畢夏斯 | 21 第 1 顆 | 高速戰艦 −403 |
| 53 梅爾格利德 | 21 第 2 顆 | 高速戰艦 −226 |
| 54 傑姆席德 | 21 第 3 顆 | 高速戰艦 −773 |

奧丁那一列與 796 年 1 月的船艦接收報告（`docs/re/21`）以及生產計劃的
「建造中」欄逐個相同。星域 21 那四筆合計 −1612，與星域表上同盟在
星域 21 的高速戰艦減少量相同，是 AI 編組時就地扣存量
（`2703:1433`，`docs/re/215`），與交付無關。

星域表 `+0x30` 這一側同時量到帝國在星域 0 增加同一組數字，符合
`2B5F:001F` 兩邊都寫；不過星域記錄那份每回合會被 `2703:12EB` 從行星
重算（`docs/internals/22`），所以**行星那份才是本體**。

同盟這一趟沒有交付——海尼森的 `+0x20` 完全沒動。這一局同盟的建造中
是不是 0 沒有量，先不寫結論。

## `2AF5:0036(星域, 旗標)` — 切換目前星域的行星切片

順手讀出來的：

```
cum = Σ_{i < 星域} ds:CFB8[i]                  ; 每星域的行星數（32 個 word）
ds:51B0/51B2 ← ds:CFF8/CFFA                    ; 備份目前切片
ds:CFFD      ← ds:CFFC                         ; 備份目前顆數
ds:CFFC      ← ds:CFB8[星域]
ds:CFF8/CFFA ← ds:5336/5338 + cum × 82         ; ds:5336 是整張行星表的遠指標
```

`docs/internals/29` 說 `ds:CFF8` 是「目前星域的行星切片」，這支就是設它的人；
`ds:CFB8` 那 32 個 word 與 `PLADAT.DAT` 的檔頭相同。

## 決定性

`shipdeliver3` 與 `shipdeliver4` 是兩趟獨立執行，同一組旗標，兩點的星域表
逐位元組相同：

## 方法：先夾出跨越點，再挑欄位

第一趟（`shipdeliver`）在 1,700M 與 1,890M 各倒一份星域表，**沒有差異**，
差點寫成「交付不進 `+0x30`」。兩份的回合計數器都是 10——跨月發生在 1,700M
之前，兩個取樣點在同一側。倒完 1 MB 全記憶體（`shipdeliver2`）也一樣，
因為問題不在倒多少，在取樣點。

改成一次跑裡設五個時點各倒一份小塊（星域表 ＋ 回合計數器），跨越點就夾出來了。
**倒之前先確定兩個取樣點真的在跨越點兩側**，判準要跟著一起倒——回合計數器
只有 2 bytes，成本可以忽略。
