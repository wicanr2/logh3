# RE 79 — 一支逐艦隊決定要做什麼的迴圈（`2E54:005D`）

執行器 dosgolem-logh3 `20e4583`；材料是 `s2ai0` 的 1 MB dump，
工具 `tools/scripts/find_writers.py`（找寫 `+0x07`／`+0x08` 的指令）、
`callchain.py`（往上追）、`ida_trace.py`（反組譯）。

`docs/re/78` 列的候選名單裡，`2E65F`（寫 `+0x07`）與 `2E656`（寫 `+0x08 = 3`）
落在同一支函式 `2E54:005D`。

## 它做什麼（從程式讀出來，**confirmed**）

```
0069  指標 = ds:C074，i = 0
0071  i < 32
007F  +0x04 == FF → 跳過
008C  cmp 艦隊的 +0x01, ds:8F1D      ; ★ 只處理這個陣營的艦隊
0098  +0x79 = 0FFh                   ; 先標成「還沒決定」
00A1  星域記錄 = ds:A79C + [+0x06]×126
00B9  if +0x08 == 4 → +0x79 = 0、ds:D60E++、下一支
00D1  test 艦隊 +0x00, 1
      ├─ bit0 = 1：
      │   00DE  對方在這一格的艦隊數（陣營 0 讀 +0x29、陣營 1 讀 +0x28）
      │   00F7  test 星域 +0x13, 14h
      │   00FE  對方艦隊數 == 0？
      │   0104  星域擁有者 +0x12 == 自己？
      │        三個條件都成立 →  +0x08 = 3
      │                          +0x07 = +0x06   ★ 目的地 ＝ 現在這一格
      │        否則 → call 2E54:1955、+0x79 = 0、ds:D60E++
      └─ bit0 = 0：
          0143  test 星域 +0x13, 4
          014A  call 2E54:16F5 → ax
                ax != 0 → +0x79 = 3、`[星域×2 - 2A32h]`++、ds:D60E++
                ax == 0 → call 2E54:1955、+0x79 = 0、ds:D60E++
0191  指標 += 7Ah，下一支
```

## 讀出來的新事實

- **`+0x79`（記錄的最後一個 byte）是「這回合的決定」**：先填 `0xFF`，
  再依情況改成 0 或 3。
- **`ds:8F1D` 是「現在處理哪一個陣營」**（`docs/re/48` 早就注意到它與
  玩家有關）。這一趟是**逐陣營跑的**。
- **`+0x08` 還有 3 與 4 兩種狀態**：4 在這裡被當成「跳過」，3 是這一支
  自己寫的。加上先前確認的 5（不動）與 0／1（會走），至少五種。
- `+0x08 = 3` 那一支同時把 **`+0x07` 設成自己現在的星域**——等於
  「就地待命」。發生條件是：這一格是自己的、對方在這一格沒有艦隊、
  而且星域 `+0x13` 的 bit2／bit4 都沒設。
- `ds:D60E` 是這一趟「決定了幾支」的計數器。
- `[星域×2 - 0x2A32]` 是一張**依星域索引的 word 陣列**，某個條件成立時 ++。

## 它**還沒被看到跑過**（收據 `s2ai`）

對 `ds:8F1D`（陣營選擇器）與同盟第 16 支的 `+0x79`（決定碼）設監看，
S2 局面按四次實行：

```
[watch] #66162324 613BD: 00 → 03  ← 載入
[watch] #68658443 613BD: 03 → 00  ← 載入
[watch] #68674090 613BD: 00 → FF  ← 載入
（之後四次實行，兩個位址都沒有再被寫過）
```

`s2ai12`（十二次實行）那份 dump 也一致：

```
ds:8F1D = 0    ds:D60E = 0    全部 18 支的 +0x79 都是 0xFF
```

`ds:D60E` 是這一趟「決定了幾支」的計數器，**十二回合後還是 0**
——所以 `2E54:005D` 在單人模式按「實行」這條路上**一次都沒有執行**。

所以上面那些結論的等級要講清楚：**程式邏輯是讀出來的（confirmed），
但「原版電腦就是這樣行動」還沒有被觀察到**。這一段可能是

- 只在對戰模式或特定局面跑；
- 掛在別的時機（月底、戰鬥結束）；
- 或者在這個版本裡根本沒有被接上。

呼叫鏈往上是 `2D76`／`2C5D` 那一整個子系統
（`2E54:005D` ← `2D76:0DB2` ← `2D76:0D40` ← `2D76:0A44` ← `2D76:0732`
← `2C5D:0AAA` ← `2C5D:082E` ← `2C5D:0756` ← `2C5D:02ED`），
下一步是找出那個子系統的入口在什麼時候被呼叫。

## 這是不是 AI

形狀完全吻合：**逐陣營、逐艦隊、看敵我與地盤、寫出一個決定碼**，
而且 `2E54:1955` 明確會替艦隊下移動命令。但上一節說了，**這條路還沒被
看到執行過**，所以「這就是電腦的 AI」仍然是 strong inference。

要釘死得先找到它會跑的情境——最可能的是對戰模式或某個特定局面。

## `2E54:16F5`：先看是不是在自己首都，再比周邊

```
1700  星域記錄 = ds:A79C + 艦隊 +0x06 × 126
171B  陣營 == 0 且 星域 == 0   → 回 1        ; 帝國在瓦爾哈拉
1735  陣營 == 1 且 星域 == 1Fh → 回 1        ; 同盟在巴拉特
174D  否則：
      call 297B:131C(緩衝區, 星域, 1)        ; 蒐集這一格的某種清單
      call 297B:131C(緩衝區2, 星域, 2)       ; 另一種
      call 3982:0250(陣營)                   ; 陣營相關（3982:0329 是首都）
      call 2E54:1876(星域, 陣營, 緩衝區) ×2  ; 兩邊各算一次再比
```

前兩個分支是「這一支就在自己的首都」。之後那一段**蒐集這一格的周邊
資料，對兩個陣營各算一次再比**——形狀就是「這裡我方還是敵方佔優」。
`docs/re/79` 上面那個迴圈拿它的回值決定 `+0x79` 要不要填 3。

## `2E54:1876`：一群艦隊的戰力總和

`2E54:16F5` 對兩個陣營各叫一次的就是它。參數是「一串艦隊索引 ＋ 幾筆」。

```
1897  逐筆取索引 → 艦隊記錄 = ds:C074 + idx × 122
18B6  test 艦隊 +0x00, 1 → 有就跳過這一筆
18C3  si = 記錄 + 0x10                 ; 十組 4 bytes 的編制表
18D2  cl = 記錄 +0x0F                  ; ★ 這一支有幾組
18DD  ax = 這一組的第一個 word
18E0  ax × 4Eh(78)                     ; 艦種表的記錄長度
18E9  far ptr 艦種表 = ds:CFB4／ds:CFB6
18F7  bl = 艦種記錄 +0x04
18FD  al = [bx + 6032h]                ; 拿 +0x04 當索引查 ds:6032 那張小表
190A  si = 艦種記錄 +0x08              ; 一單位幾艘（docs/re/69）
1912  32 位元乘：al × (+0x08)
1919  再乘 1000
1926  si = 艦種記錄 +0x0A
192E  再除以它
1933  32 位元累加
193C  下一組（+4）
```

也就是每一組貢獻

```
    ds:6032[艦種 +0x04] × 艦種 +0x08 × 1000 ÷ 艦種 +0x0A
```

加起來就是這一群艦隊的**戰力值**（32 位元）。

三件新的：**`+0x0F` 是這一支有幾組編制**、`+0x10` 起每組的第一個 word 是
**艦種索引**（乘 78 查表，與 `docs/internals/32` 的 78 bytes 一筆相符），
以及艦種記錄的 `+0x04`／`+0x0A` 各參與一次。

## `2E54:1955`：**電腦下命令的地方**

`2E54:005D` 那個迴圈判斷不出「就地待命」時走的就是它。

```
1960  星域記錄 = ds:A79C + 艦隊 +0x06 × 126
197A  al = 星域 +0x12（擁有者）
197E  cmp al, ds:8F1D            ; 這一格是不是自己的
1986  test 星域 +0x13, 4         ; 這一格有沒有事
198D  兩個條件都過（自己的、沒事）：
1990    +0x08 = 5                ; 停住
1995    +0x07 = 0FFh
199A    +0x79 = 3
199F  否則：挑一個要去的地方
19C1    call 2B99:03D9(緩衝區, 陣營, 現在的星域) → 候選幾個
19D4    call 3982:0329(陣營)                     → 自己的首都星域
19E2    逐一看候選：
19FB      候選的星域記錄 = ds:A79C + 候選 × 126
1A1C      call 2B99:028F(候選, 首都, 陣營)       → 距離／成本
1A26      比目前最小的還小？
1A2E      而且候選的擁有者 == 自己的陣營？
1A3F      是 → 記下它
1A54    有選到 → **`+0x08 = 0`、`+0x07` = 選到的星域**   ★ 下命令
1A62    沒選到 → `+0x08 = 5`、`+0x07 = 0FFh`             ; 停住
```

`1A5C` 那一行就是「電腦替一支艦隊下移動命令」。判斷的內容講白話是：

> **這一格是自己的而且沒事 → 待著；否則退回「離自己首都最近的、
> 屬於自己的」星域。挑不到就原地不動。**

也就是說，原版這一層是**防守型的收攏**：它會把艦隊往家裡拉，
**不會自己挑一個進攻目標**。`docs/spec/017` 的強化版要補的正是這一段。

（`2B99:028F` 與 `docs/re/28` 量到的 `2B99:0450`「兩個星域走幾步」是同一
家族；`3982:0329` 就是那份文件裡的「陣營的首都星域」。）
