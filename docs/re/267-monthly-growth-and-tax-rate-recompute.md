## `0654:0007`：一個月只跑一次，而且跑在逐座位之前

`docs/spec/035` 記著這一支「內容還沒讀」。讀出來是：

```
0654:0007():
    if ds:8FF4 == 0 or ds:8FF5 == 0: return    ; 兩格都要還沒被清 → 一個月一次
    2B5F:02B2()                                 ; 每回合都跑（在 mod 10 之前）
    if ds:8F18 mod 10 != 0: return
    2703:0BF2()                                 ; 32 格：成長 ＋ 重算成長率
    090A:0B5E()                                 ; 重算稅率
```

`2703:0BF2` 是 32 格的迴圈，逐格呼叫 `2703:0C26`：

```
2703:0C26(星域記錄):
    2AF5:0036(星域記錄[+0x11], 0)        ; 切到該星域的行星切片
    舊 = 0；星域記錄[+0x1A] = 0
    for 每顆行星:
        舊 += 行星[+0x1A]
        2703:0CED(行星)                   ; 行星[+0x1A] += 經濟力 × 成長率 ÷ 1000
        星域記錄[+0x1A] += 行星[+0x1A]
    星域記錄[+0x1E] = (星域記錄[+0x1A] − 舊) × 1000 ÷ 舊
```

最後那一行是重點：**成長率用這個月實際長了多少反推**，不是沿用開局那一份。

`090A:0B5E` 分三段：

```
ds:8F1D = 0; 090A:0B93(ds:8FD4)     ; 帝國，用自己的 Blend 當難度下標
ds:8F1D = 1; 090A:0B93(ds:8FD5)     ; 同盟
ds:8F1D = 2; 090A:0DC0(2)           ; 無主星域走另一支（未讀）
```

`090A:0B93` 就是 `rules.RecomputeTaxRates` 對應的那一支，它讀
`ds:8F4F + 陣營`——**內政專任參謀**那一格（`WORK` 的 `+0x3B`），不是統治者。

## 月底的正確順序

```
0654:0007（一個月一次，逐座位之前）
    32 格成長 → 重算每格的成長率 → 重算兩個陣營與無主的稅率
每個座位的 0654:0034
    2703:02E5(0) 估／2703:03AF(1) 收 → 用**新**稅率收稅 → 錢的結算
```

也就是**先長、重算成長率、重算稅率，然後才收稅**。remake 原本把成長與
收稅綁在同一趟（`MonthEndRegion`），而且兩格都不重算。

## remake 的修法

`MonthEndTotals` 拆成兩趟：第一趟 `GrowRegion` 全部成長並用
`GrowthFromChange(前, 後)` 寫回 `+0x1E`；中間呼叫端重算稅率
（`Game.recomputeAllTaxRates`，走原版 `090A:0B5E` 的兩段）；第二趟
`TaxRegion` 用新稅率收稅。

改完 `TestMonthEndMatchesWorkBlock` 的七個欄位加建造中那七格全部相同，
既有十份畫面收據仍逐位元組相同。

## 全 32 格對過一次：同盟那一側還有兩個缺口

`monthwork3` 的星域表涵蓋全部 32 格，而稅率是 `0654:0007` 在**逐座位之前**
重算的，所以同盟與無主那些格子在那份傾印裡也是重算後的。全表對下來：

- **十個帝國星域全中**（經濟力、稅率、成長率）。
- **同盟那十三格**的稅率原本整齊地是原版的四分之三左右
  （`44/56`、`55/70`、`40/53`、`36/47`…）。追下去是稅率算式要乘的那位提督：
  原版 `090A:0B93` 讀 `ds:8F4F + 陣營`（**內政專任參謀**），remake 寫死
  `UnrestParams.Ruler = [16, 60]`。拿**提督 63** 重算那十三格
  **13/13 全中**，拿 60 **一格都不中**。
- 但 796/1 的同盟開局畫面 `main1eAlly` 逐位元組要的是 **60**：改成 63 之後
  那張差 457 個像素。

兩個值各有收據，所以 **`ds:8F4F` 不是常數**——`work-796-01.json` 量自第
71,200,000 步（防拷畫面之前）是 60，`monthwork` 從第 300,000,000 步起量到的
都是 63。同一類的事 `docs/re/248` 已經遇過一次：`ds:8F4D`（報告頭像）範本是
58、執行期是 75，當時另外開了一個 `Reporter` 欄位裝執行期值。

**改的時機與規則還沒查**，所以 remake 先留 60（保住 `main1eAlly`），
同盟的月底稅率因此偏低約四分之一。`TestAllianceTaxRateNeedsRuntimeStaff`
把兩半都釘住了。

同盟的**經濟力**還差一截（例如 R15 remake 11782、原版 13222），那是**量測
的側邊效應不是 bug**：收稅是逐座位做的，而那一趟同盟座位在回合 10 一次都
沒跑，所以原版那些格子是「長完但還沒被課稅」。

無主星域裡 R24、R28 兩格另外對不上（原版稅率 48／50，遠低於它們的成長率
67／69，而其餘無主格子的稅率等於成長率）。成因是**已知的**：原版在回合
1–9 之間有六顆無主行星翻成同盟（威爾勃恩、烏魯瓦希、克雷貝爾、巴多列斯克、
卡札威爾、利歐貝魯提，星域 24／25／28），星域擁有者是從行星現算的，所以
那兩格在原版是同盟的、在 remake 還是無主，稅率自然走不同的分支。

那六顆**不是被「收編」，是被打下來的**（[`docs/re/161`](161-neutral-planets-are-taken-not-annexed.md)）：
戰略地圖上的打行星 `20B4:1662`（呼叫鏈見
[`docs/internals/53`](../internals/53-strategic-planet-assault.md)）。
remake 只有戰場那條 `rules.PlanetAssault`，戰略回合那條還沒接——
所以這是「戰略層 AI 沒動」的下游，不是新的未知。

## 兩處位址勘誤

- `docs/internals/29` 記月底重算星域經濟力的位址是 `2703:0CA8`。那是**函式
  中間**（`adc es:[si+1Ch], ax`，累加迴圈裡的一行），全份 1 MB 傾印裡沒有
  一個 `call far 2703:0CA8`。函式起點是 `2703:0C26`，呼叫者是 `2703:0BF2`。
- 測試環境原本沒有 `UnrestParams`，於是稅率重算整段是 no-op——加上去之前
  這個修法在測試裡看起來完全沒有效果。

## 方法：偏差的形狀會指到單一原因

六個欄位一起偏，但比例不同（＋74／＋70／＋4／＋10 艘）。把它們沿著算式
往上游推，全部收斂到同一個輸入（實收的稅）——所以不必逐個修，
只要找那一個輸入為什麼偏。

再往上一層：稅 ＝ Σ 經濟力 × 稅率。兩個因子都不同時，**先看哪一個是另一個
的函數**——稅率吃成長率、扣稅改經濟力，所以稅率是因、經濟力是果。
先驗未安定度（十格全同）把「稅率的另一個輸入」排除掉，剩下的只有成長率。
