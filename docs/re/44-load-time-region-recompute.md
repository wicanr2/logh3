# RE 44 — 載入時重算星域表：經濟力與成長率

日期：2026-09-07
執行器：dosgolem-logh3 `8c8af90`
收據：`newload`、`watchgrow`
工具：`tools/scripts/disasm_funcs.py`（記憶體 → `.COM` → IDA，`docs/re/43`）
狀態：**經濟力與成長率 confirmed**（新遊戲那條路徑 32 個星域逐一相同）；
稅率 **未讀**。

## 載入時到底重算了哪些欄位

拿 `STELLAR.DTX` 與新遊戲載入後的記憶體逐位元組比（收據 `newload`，
第 71,200,000 道指令），會變的位移：

```
+12 擁有者   +13 旗標   +16..+18 三個陣營的行星數   +1A 經濟力
+1E 成長率   +20..+24 防衛力   +26 +27 稅率
+30..+65（每 4 bytes 動 2 bytes 的那段 u16 陣列）
+68..+77（四個 u32）   +7C 民心   +7D 未安定度
```

`+0x7D` 已經解掉了（`docs/spec/006`）。這一份查的是經濟力與成長率。

## 誰寫的

對星域 0 的 `+0x1E`（線性 `5F2EA`）設監看：

```
#68680670  5F2EA: 06 → 2D  ← 2703:018B      成長率 ＝ 45
#70860160  5F2F2: 05 → 20  ← 090A:0DAF      稅率  ＝ 32
```

成長率在 `2703` 段，稅率在 `090A` 段（還沒讀）。

## `2703:00A0` 起那個迴圈

```
星域記錄的 +0x1A/+0x1C ← 0                 ; 經濟力歸零
清單 = 2AF5:0036(星域, 0)                   ; ds:CFF8 指標、ds:CFFC 筆數
對清單裡每一筆（一筆 0x52 ＝ 82 bytes ＝ 行星記錄）:
    經濟力 += 行星[+0x1A]（32 位元）
    rate    = 2703:0D47(行星)
    Σ      += 行星[+0x1A] × rate / 1000 + 行星[+0x1A]
成長率 = (Σ − 經濟力) × 1000 / 經濟力       ; <= 0 就不寫
```

**經濟力 ＝ 該星域行星的 `+0x1A` 相加**——`docs/re/30` 是從數字推出來的，
這裡在程式碼上確認了。

`2703:01BD` 另外做一件事：`+0x27 ← +0x26`。所以 `+0x27` 是「上個月的稅率」
的副本，未安定度的 f1 用的就是它（`docs/spec/006`）。

## 每顆行星的成長率：`2703:0D47`

```
p = ds:4A68                       ; 一列 6 bytes ＝ {門檻 u32, 千分率 u16}
loop:
  下一列門檻 = [p+6..9]
  下一列門檻的高位字 != 經濟力高位字 → 停
  下一列門檻的低位字 >= 經濟力低位字 → 停
  p += 6 ; 回 loop
rate = [p+4]
行星[+0x16] < 3000 → rate = rate × 3 / 2
```

表的內容與 `docs/internals/data/growth-table.json` 逐列相同（S3 那一輪倒的）。
**防衛力用的是 `+0x16`，不是畫面上那個 `+0x14`**——兩格在量到的資料裡數值
一樣，所以先前分不出來。

「高位字不同就停」是個會咬人的細節：經濟力超過 65535 的時候，
迴圈在第一列就停，直接拿最高的那個千分率。

## 對不上的地方

照上面寫成程式跑 S3 那一格：**32 個星域裡 15 個算得剛好**，其餘 17 個差 1–6，
而且多半是記錄比算出來的**高**。

反推每個星域需要的 Σ，差額落在 +1 到 +31 之間。舉兩個定得住的例子
（單行星星域，成長率就等於那顆行星的千分率）：

| 星域 | 行星經濟力 | 表查到的千分率 | 算出來 | 記錄 | 反推需要的千分率 |
|---|---:|---:|---:|---:|---:|
| 13 伊謝爾倫 | 7,572 | 58 | 57 | 57 | 58（**對**）|
| 24 馬爾•亞迪特 | 3,151 | 68 | 67 | 73 | **74**（表上一列）|

星域 5 的兩顆行星（6,138 與 4,145）也要有一顆用「上一列」才湊得出 62。
但星域 13 用上一列就會變成 59，反而錯——所以**不是整體差一列**，
千分率也不是只看經濟力的函式。

試過但都不對的假設：防衛力改用 `+0x14`／`+0x16`／星域合計、
比較改成 `>`、除法改成四捨五入、加上 `+0x12` 或 `+0x18` 的線性修正。

## 結案：算式是對的，比錯了局面

先把 `2AF5:0036` 讀出來確認清單：

```
起點 = Σ 前面星域的行星數（word 陣列在 ds:CFB8）
ds:CFFC = 這個星域的行星數
ds:CFF8/CFFA = 行星表基底（far ptr 在 ds:5336）+ 起點 × 0x52
```

就是「這個星域的行星」，指標指到記錄開頭，沒有偏一格。所以
`docs/re/43` 的 f4 比的 `+0x12` 確實是行星的 `+0x12`，不是擁有者。

清單沒問題，那問題就在**拿錯局面對**了。改用新遊戲那一輪的資料
（收據 `newload`，`PLADAT.DAT` 的行星對載入後的星域表）：

**32 個星域的經濟力與成長率全部逐一相同，一個都不差。**

原因是**載入存檔不會重算這兩欄**：`STELLAR.DT9`／`STELLAR.DTA` 與載入後的
記憶體只差 `+0x7D`（`docs/re/41`）。存檔裡的成長率是存檔當下寫進去的，
而行星的經濟力之後又長過，兩者不同步——拿它們互相驗算當然對不上。
差的方向也吻合：記錄多半比算出來的**高**，因為當初算的時候經濟力比較小、
查到的千分率比較大。

所以載入時重算的範圍分兩種：

| 局面 | 重算什麼 |
|---|---|
| 新遊戲（`STELLAR.DTX`）| 上面那張位移表全部 |
| 讀存檔（`STELLAR.DT[89A]`）| **只有 `+0x7D` 未安定度** |


## 稅率：`090A:0CC0` 起（只讀了一半）

新遊戲載入時稅率由 `090A:0DAB` 寫進 `+0x26`：

```
mov es:[bx+26h], al          ; bx 是星域記錄，迴圈步長 0x7E ＝ 126
```

寫進去之前先夾在 1–200：大於 200 取 200（`3CC9:00B9` 是 32 位元比較），
不大於 0 取 1。

夾限之前是一段分段縮放。`[bp+2]` 是一個比值——`(某個值 × [bx+0x14]) / 100`
——然後：

| 比值 | 做什麼 |
|---|---|
| > 150 | 值 × 30 / X |
| > 100 | 值 × 50 / X |
| > 50 | 值 × 75 / X |

（`3CC9:0009` 是 32 位元乘、`3CC9:0070` 是 32 位元除。）

**還沒讀的**：`[bp+4]:[bp+6]` 進迴圈時是什麼、`[bx+0x14]` 與 `[si+0x14]`
分別指哪一張表。要接著往前讀 `090A:0C00` 附近那一段。

## 民心 `+0x7C` ＝ 擁有者決定

載入之後 32 個星域一個不差：

| 擁有者 | 民心 |
|---|---:|
| 帝國 | 0 |
| 同盟 | 200 |
| 無主 | 100 |

三份資料都成立——新遊戲載入後的星域表，以及 `STELLAR.DT9`／`STELLAR.DTA`
兩格存檔（存檔裡本來就存著這個值，一個例外都沒有）。

未安定度的 f2 是 `(帝國 ? +0x7C : 200 − +0x7C) / 10`，所以這條規則等於
**f2 恆為 0**——除非之後有機制會改動民心。

## 旗標 `+0x13`：載入後只有 0 與 8

新遊戲載入後 18 個星域是 8、其餘是 0，與擁有者沒有對應關係。
但未安定度只看它的 **bit 2（`& 4`）** 與鄰居的 **`& 0x14`**，
`8` 兩個都不中——所以 796 年 1 月這一欄對未安定度沒有作用。
這一格代表什麼還沒解。

## 796 年 1 月的未安定度：只差稅率

把上面幾條湊起來（擁有者與行星數從 `PLADAT.DAT`、經濟力與成長率照
`RegionEconomyAndGrowth` 算、民心照擁有者、旗標當 0、艦隊沒有、
提督讀 `ADMIRAL.DTX`、難度參數量到的那組），796 年 1 月
**32 個星域的未安定度算出來與量到的完全相同**。

唯一還得靠量的輸入是**稅率 `+0x26`**（f1 用的 `+0x27` 是它的副本）。
稅率的算式讀到一半（見上一節），把它解掉，796 年 1 月的整張星域表
就能從原版檔案重建，`docs/spec/001` 那 15 份收據也就不必再抄量到的值。
