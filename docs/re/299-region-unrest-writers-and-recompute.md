## 五、遊戲進行中的算式：與載入時那一支相同，差在兩個輸入

算式就是 `2703:0DA1`（[`docs/spec/006`](../spec/006-unrest-at-load.md)）。遊戲
進行中要換的只有兩樣：

**尾巴讀的路徑表。** `2703:0E7F` 起：

```
d = 2B99:028F(首都, 星域, 擁有者)      ; 距離矩陣 ds:D062／ds:D066 的 [首都][星域]
d >= 0x800（無號）→ 治安度 ÷ 2
否則             → 治安度 −= 2 × 2B99:0450(星域, 首都, 擁有者)
```

`2B99:0450` 是 `while 首都 != 星域: 首都 = 2B99:0302(星域, 首都, 擁有者); n++`，
`2B99:0302` → `2B99:0349` 沿中點矩陣（`ds:D06A`／`ds:D06E`）找下一格——
也就是從首都沿原版的路一格一格走、數步數。`2B99:028F` 的兩個座標都是
`mov al/bl, [bp+x]` 取 byte，`0DA1` 推的 `word es:[bx+11h]` 高位元組
（擁有者）不影響。

路徑表由 `2B99:0003` 照星域 `+0x12` 建（`2B99:007D` ＋ `2B99:01B1`，兩個陣營各
一次），呼叫者三處：新遊戲初始化 `2703:0195`、回合尾巴 `2703:08E4`、座位回合
開頭的 `04F8:0050`（`04F8:003E`；`urx299w` 在 `#200M` 之後只量到帝國座位那一次）。
擁有者只在回合尾巴那一段會變，所以任何一次 `090A:0E6D` 讀到的表都等於「照現在
的 `+0x12` 建的表」。`rbx292_b` 那一刻 EMS 分頁框 `D000` 正映著四張表
（`ds:D062`–`D06E` 指向 `D000:0000／0800／1000／1400`），與 `BuildTables` 照
那一刻的擁有者建出來的逐格相同。

載入存檔的當下量到的是另一個樣子（成本全部小於 `0x800`、步數與相鄰圖的
最短步數相同，`docs/re/43`），`docs/spec/006` 那一條不動。

**那一刻的四個全域。** 回合計數器 `ds:8F18`（f1 取它 `% 10`）、`Blend`、
`ds:8FF8`、內政專任參謀 `ds:8F4F`，全部讀當下的值。回合計數器在回合尾巴
`2703:08DE` 之後才進位，所以同一次「實行」裡 AI、扣維持費、回合尾巴那幾次
用的是舊值，座位回合開頭那一次用的是新值。

## 六、f5 恆等於 0，理由與 `43` 寫的不同

`43` 說 f5（`2703:10FC`，同一格的提督）恆等於 0，是因為提督的 `+0x09` 載入時
被夾到 127、最高位清掉，過不了 `0x20` 那道篩選。**這個理由不成立**：
`s3datamem` 有 25 位、`rbx292_b` 有 68 位提督 `+0x00 == FF` 而且 `+0x09` 最高位
有設（新遊戲的提督表本來就是 `0x80`–`0x8F`；`2D10` 讓現任卸任時也寫 `0x80`），
而且都在首都——`28E0:035C` 與 `28E0:047E` 兩道篩選都是「留下符合的」，首都那一格
一定過得了。

真正的理由在 `2703:10FC` 的尾巴：

```
2703:11C4  9a 20 00 c9 3c     call far 3CC9:0020     ; n × p × q ÷ 1000，商在 ax:bx
2703:11C9  89 d8              mov ax, bx             ; 低位字搬到 ax
2703:11CB  31 db              xor bx, bx             ; bx 清成 0
2703:11CD  89 46 5a           mov [bp+5Ah], ax
2703:11D0  89 5e 58           mov [bp+58h], bx
2703:11D3  ff 76 58           push word [bp+58h]     ; ← 推的是清成 0 的那一格
2703:11D6  9a 30 01 10 33     call far 3310:0130
```

`3310:0130(x)` 把 `x` 當高位字組成 32 位元、交給 `3310:014B`（牛頓法開根號），
`3310:014B` 開頭 `mov ax,[bp+12h] / or ax,[bp+10h] / jnz` ——引數是 0 就直接回 0。
所以 f5 的引數永遠是 0、回值永遠是 0，**與提督的旗標、人數、能力都無關**。
結論（f5 ＝ 0）不變，remake 照舊不實作它。

## 七、`× 統治者營運 ÷ 100` 只留 16 位元

```
2703:0E33  8b 46 00           mov ax, [bp+0]        ; 治安度（已夾在 >= 0）
2703:0E39  26 8a 4f 0e        mov cl, es:[bx+0Eh]   ; 統治者的營運
2703:0E3F  f7 e1              mul cx                ; dx:ax
2703:0E41  b9 64 00           mov cx, 100
2703:0E44  99                 cwd                   ; ← dx 被 ax 的符號位蓋掉
2703:0E45  f7 f9              idiv cx
```

乘積到 `0x8000` 以上就被當成負數除。營運最高 133（`ADMIRAL.DTA`），治安度要到
247 以上才會碰到——f1 最大約 215，要再加上 f4 的幾顆行星。出貨資料的局面裡
沒有量到，remake 照位元組做（`rules.rulerScale`）。

- `Game.recomputeUnrest(計數器)` 接在四個地方：`refreshBlend` 的尾巴
  （`2D10:0319`／`2D10:0213` → `090A:0E6D`）、`advanceTurn` 扣維持費之前
  （`056A:09EB`）、`refreshRegionPosture` 的尾巴（`2703:08DE`）、`finishTurn`
  的預估稅之後（下一個座位回合開頭的 `0654:0034`）。`monthEnd` 開頭抄
  `rate = blend`（`2703:03AF`）。

同狀態驗收見 [`docs/spec/042`](../spec/042-region-unrest-recompute.md)。

## 順帶

- **`0x09413` 不是進入點。** `docs/re/206`、`207` 讀的 `Blend ±1` 那一支，
  線性 `0x09412` 是 `55`（`push bp`），前面是 `5e 5d cb`——進入點是
  **`090A:0372`**，`0x09413` 是 prologue 的第二個 byte。拿 `0x09412` 掃 far call
  有一處：`090A:030A`（在 `090A:02AF` 裡），`090A:02AF` 又有 `090A:0107`、
  `090A:0120` 兩個呼叫點。`207`／`220` 的「一個呼叫者都沒有」是 3a-1 第一條那種零。
  再往上沒有追。
- **remake 的 AI 月底分支早一個回合。** `runBrain` 用 `g.turn%10 == 9` 判月底，
  但 remake 的 `g.turn` 在 `advanceTurn` 開頭就先加了：第一次「實行」AI 跑的時候
  原版 `ds:8F18` 是 0（`rbx292_b`）、remake 的 `g.turn` 是 1。原版的條件是
  `ds:8F18 % 10 == 9`，對應的是 `(g.turn − 1) % 10 == 9`。`TestMonthEndKeepsBlend`
  把 `g.turn` 設 8 再按實行，對的是原版計數器 8；收據 `monthblend` poke 的是 9，
  跑完是 10。`ai-seat-order` 記的「回合 10 的同盟 `Blend` 兩邊不同（原版 2、
  remake 0）」與這個差一格的結果相同。這一輪沒有改（不在這一條的範圍）。
- **新艦隊建出來時 `+0x08` 是 5。** 時間線裡星域 31 每建一支艦隊就被重算一次、
  治安度多 6，下完命令又回去。remake 的 `buildFleets` 建出來是 `Parked == false`；
  AI 回合結束時兩邊都已經在移動，結果相同。

## 三條方法

**監看只報變動：一格「沒有寫入」要先問值有沒有變。** `docs/spec/006` 的「跨月
不重算」就是拿 `watchmonth3` 對星域 0 的監看下的結論——星域 0 是帝國首都，
一整個月重算了幾十次，值一直是 36。要數「有沒有跑」得在呼叫端下 `-regs-at`。

**斷點下在呼叫端、監看下在欄位，兩份合併成時間線。** 十一次重算、各自在誰之後、
改了哪幾格，一次跑就排得出來；比拿前後兩份傾印猜中間發生了什麼直接得多。

**「照現在的局面重算一次」對不上的傾印，先問它是不是倒在一串處理的中途。**
這一輪 55 份裡沒有一份需要改算式；對不上的都是傾印那一刻的輸入在最後一次重算
之後又變了。
