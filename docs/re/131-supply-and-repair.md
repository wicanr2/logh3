# 131 — 「補給」與「修理」（`1930:05EC`、`1AAB:0583`）

分隊命令選單第三項的兩張表（`docs/internals/44`）。兩支的骨架一模一樣，
只差查表的艦種與訊息字串，所以一起讀。

## 骨架

```
半徑 = f(艦種列[+0x06])                       ; 見下
17A0:00AC(陣營, 自己 +0x34, 自己 +0x36, 半徑, 0, &清單)
清單 = 17A0:016C(清單, 清單, cs:篩選函式)
若 清單為空：
    3826:0005(2, 0x97, 訊息)                  ; 跳訊息框，結束
畫出候選並進模態迴圈（1629:0005）
    左鍵 → 1930:0815／1AAB:07C6：命中哪一筆，動手
    右鍵 → 結束
```

| | 補給 | 修理 |
|---|---|---|
| 進入點 | `1930:05EC` | `1AAB:0583` |
| 查的艦種列 | `ds:4E3A + 陣營×208 + 0x82`（**艦種 5**）| `+0x9C`（**艦種 6**）|
| 篩選函式 | `cs:0485` | `cs:043D` |
| 沒有候選時的訊息 | `ds:3F14`「沒有需要補給的船艦。」| `ds:403E`「沒有需要修理的船艦在附近。」|
| 動手 | `1930:0944` | `1AAB:0879` |
| 存半徑的地方 | `ds:A438`／`ds:A43A` | `ds:A43C`／`ds:A43E` |
| 存發令者的地方 | `ds:A42E`／`ds:A430` | `ds:A440`／`ds:A442` |

**半徑查的是補給艦／修理艦那個艦種的那一列，不是發令分隊自己的。**
兩個陣營的艦種 5 與 6 的 `+0x06`（最高速度）都是 30。

## 同一個 6.4 算了兩次，而且兩次不一樣

收集候選時（`1930:05CF`）：

```
bx:ax = 速度 << 21          ; shl bx,1 / rcl ax,1 跑 21 次
半徑  = (bx:ax) ÷ 5         ; 3CC9:0070
```

30 → `62,914,560 ÷ 5` ＝ **12,582,912** ＝ 正好 192.0。

按下去確認時（`1930:08D6`）：

```
半徑 = 速度 × 0x00066666    ; 3CC9:0009；cx 是高字、dx 是低字
```

30 → **12,582,900** ＝ 191.99982。`0x66666` 是 6.4 的 16.16 **截斷**值。

兩者差 12／65536 個像素。落在那條縫上的目標**列得出來卻按不下去**。
remake 兩個都照抄（`rules.SupplyListRange`／`rules.SupplyRange`）。

> `3CC9` 那組 32 位元常式的暫存器配置是 **cx 高字、dx 低字**
> （`1C03:0524` 扣 8.0 時 `sub …, si`／`sbb …, cx` 配 si=0、cx=8，
> 也就是 `0x00080000`）。搞反了會把 `0x66666` 讀成 `0x66660006`。

## 補給搬什麼（`1930:0944`）

```
滿載飛彈   = 目標艦種列[+0x10] × 目標 +0x08（**現有**艘數）
滿載艦載機 = 目標艦種列[+0x14] × 目標 +0x08
給飛彈   = min(滿載飛彈   − 目標 +0x0E, 補給艦 +0x0E)
給艦載機 = min(滿載艦載機 − 目標 +0x12, 補給艦 +0x12)
兩個都是 0 → 什麼都不做
補給艦 +0x0E −= 給飛彈；補給艦 +0x12 −= 給艦載機
目標   +0x0E += 給飛彈；目標   +0x12 += 給艦載機
```

全部是 32 位元。**乘的是現有艘數不是滿編艘數**——打掉一半的分隊，
補滿之後也只有一半的彈藥；這與戰損把 `+0x0E`／`+0x12` 按
「剩下 ÷ 原有」等比例縮小是同一套邏輯（`docs/internals/38`）。

艦載機用的是 `+0x14`（滿量），不是分隊面板印的每艘幾架 `+0x13`
——艦種 5 這兩格是 6 與 24，分得開。

確認那一關另外要求**目標與補給艦同陣營**（`1930:08EC`）與距離
≤ 半徑（`1930:0920`）。

## 修理搬什麼（`1AAB:0879`）

```
給 = min(目標 +0x0C − 目標 +0x08, 修理艦 +0x0E)
給 == 0 → 什麼都不做
目標   +0x08 += 給
修理艦 +0x0E −= 給
```

上限是 `+0x0C`，**不是**分隊面板印的滿編 `+0x0A`。收據 `s3form` 那 148 筆
裡有 16 筆打過：13 筆的 `+0x0C` 與 `+0x0A` 相同，另外 3 筆
（艦隊 31 的艦種 2）掉了 84／69／69 艘而 `+0x0C` 只掉 1 ——
所以那三筆最多修回 83／68／68。

修理艦的存量放在它自己的 `+0x0E`，與補給艦的飛彈同一格；收據裡
艦種 6 的 `+0x0E` 等於它的艘數（974／1000），而艦種列 `+0x10` 是 0
——所以那一格的初值不是走補給那條公式。

## 候選怎麼收

`17A0:00AC(陣營, x, y, 半徑高字, 0, &清單)`：

```
i = 0；收到 0 個
while i < ds:9896:                       ; 場上的分隊數
    艦艇 = ds:CFB4 + ds:98BA[i] × 78     ; ds:98BA 是場上分隊的池索引陣列
    若 艦艇[+0x00] != 陣營：跳過
    若 艦艇[+0x1E] & 0x80：跳過           ; 出局的不算
    若 距離((x,y), 艦艇[+0x34/36]) > 半徑：跳過
    *清單++ = ds:98BA[i]
    i++
*清單 = 0xFFFF                            ; 結尾標記
回 收到幾個
```

**半徑只取高字**（`1930:0656` 只 push `ds:A43A`），所以收集用的是
16.16 的整數部分——192.0 剛好沒有小數，這一步不影響。

`17A0:016C(來源, 目的, 篩選函式)` 就地再篩一遍：跳過 bit15 設起來的
（那是行星，`ds:CFF8` 一筆 0x52 bytes），其餘呼叫篩選函式，回非 0 就留下。

| | 補給 `1930:0485` | 修理 `1AAB:043D` |
|---|---|---|
| 陣營 | 要相同 | 要相同 |
| 排除的艦種 | **5、6、7** | **6、7** |
| 距離 | ≤ 收集半徑 | ≤ 收集半徑 |

差別只有一個：**修理修得了運補艦，補給補不了補給艦**。

篩選函式**沒有檢查對方缺不缺**——所以「沒有需要補給的船艦。」那個訊息
其實是「半徑內沒有可補的對象」，全部補滿時照樣有候選、按下去給 0。
這是原版的行為，remake 照抄。

## 候選不是「畫」出來的，是給每個候選寫一個順位

原本以為 `17A0:0427`／`17A0:05B2` 是畫高亮，讀完發現不是：

- **`17A0:0427` 是排序**。它把清單交給 `3C6A:000D`（通用排序）配上
  比較函式 `17A0:044B`，而那支比的是**艦艇記錄 `+0x30`**
  （行星則是記錄 `+0x44`）。
- **`17A0:05B2` 是發順位**。從 `0x80` 開始，沿著排好的清單一筆一筆
  遞減寫回去：艦艇走 `17A0:064B`（寫 `+0x30`，旗艦另外把值傳進
  艦隊記錄）、行星走 `17A0:06A4`。

所以「候選看起來不一樣」是**單位自己身上多了一個位元組**，不是疊上去的
圖形。`+0x30` 這一格 `docs/internals/38` 原本沒有記。

## 還沒解

- `+0x30` 排序前是誰填的（比較函式讀它、發順位也寫它，兩邊用同一格）。
- 一般繪製怎麼讀 `+0x30`（畫面上實際變成什麼樣子）。
- 動手之後的結果訊息（`1930:0AA2`／`1AAB:08FB`，格式字串 `ds:4059`
  配陣營名 `ds:60F4`）。
- 修理艦 `+0x0E` 初值的來源，以及 `+0x0C` 在戰損時到底扣多少。
