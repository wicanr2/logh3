# 445 — 通用差異測試框架與 runtime 輔助函式

日期：2026-10-09。`docs/re/443` 的試點是手寫的探針，每個函式都要重寫。這份紀錄是通用化之後的框架與它驗證的第一批函式。
契約在 [`spec/124`](../spec/124-decomp-reference-oracle.md)，入口在 [`decomp/README.md`](../../decomp/README.md)。

## 框架

| 元件 | 做什麼 |
|---|---|
| 描述檔 `decomp/specs/<SEG_OFF>.json` | 入口、呼叫慣例、參數（`word`、`byte`、`dword`、`farptr`、`nearptr`、`reg`）、回傳值（`ax`、`dxax`、`pack:ax,bx,…`、含 `flags`）、基底保存狀態與其 SHA-256、函式位元組的雜湊 |
| `decomp/harness/diffprobe.go` | 在 dosgolem 內直接呼叫原版函式。依描述檔產生參數；用 `WatchReads` 取得函式實際讀過的位元組當突變候選；以「執行過的指令位址」做覆蓋率回饋；記錄回傳值與堆疊以外的全部記憶體寫入 |
| `decomp/test/check_diff.c` | 載入同一份基底傾印，套用相同突變，跑 C 參考實作，比對回傳值與整個 1 MB 的寫入集合 |
| `decomp/include/gin3_mem.h` | C 端的 1 MB 記憶體模型，`LIN(seg,off)` 保留 8086 的 16 位元位移回繞 |
| `decomp/specs/<id>.mutants.json` | 該函式的突變清單，`decomp/tools/mutants.py` 逐一套用到 C 版，每個都必須被向量檔抓到 |
| `decomp/tools/diff_run.sh`、`diff_all.sh` | 單一函式與全部函式的入口 |

設計上的重點：

- 不需要為每個資料結構寫亂數產生器。突變只針對函式讀過的位元組，值取邊界值、±1、16 位元邊界與均勻隨機。
- 覆蓋率是可量化的宣稱：分母是 IDA 在該函式範圍內辨識的指令數（`decomp/ledger/insns.tsv`），分子是測試輸入實際執行過的指令位址。
- 比對全部副作用而不是個別輸出區：原版函式寫了哪些 byte、寫了什麼值，C 版必須完全相同。
- 收錄策略：有新覆蓋或輸出簽章新穎的案例一律收；其餘普通案例收到配額為止。只收新穎案例會讓輸出種類少的函式失去對突變的鑑別力。
- 以下情況的執行不收：執行了 INT、寫了 I/O 埠、寫了平面視訊記憶體、超過 200,000 步。

批次 `r2`，種子 20261009，`decomp/tools/diff_all.sh r2`，向量檔雜湊為前 16 字元。

|---|---|---:|---|---:|---|
| `203A:0424` | 戰略艦隊攻擊力 | 556 | 64/64 | 0／5 | `27ce9ef38bfcb7a0` |
| `3CC9:0009` | 32 位元乘法 | 926 | 12/12 | 0／3 | `8005cbf68025d5d9` |
| `3CC9:0020` | 32 位元無號除法 | 907 | 42/42 | 0／3 | `dee22c7833b157b0` |
| `3CC9:0070` | 32 位元有號除法 | 915 | 30/30 | 0／2 | `664161a0dfdc34e0` |

全部零不符，回傳值與寫入集合都相同。同一批次名在不同函式下各自一個子目錄。

## 發現

- `3CC9:00B9` 結尾有 `pop ax`，`AX` 回來時不變，輸出是旗標。`docs/internals/51` 原本寫「相同時 `AX ← −1／0／1`」，不成立，已改正文。
- `203A:0424` 在新框架下的覆蓋率是 64/64，舊版 5006 案的結論不變。
- 6 個函式涵蓋 `GIN3PS.EXE` 內被呼叫次數最多的幾支：`3CC9:0009` 有 150 個呼叫者，`3CC9:00B9` 82、`3CC9:0020` 72、`3CC9:0070` 62、`3CD5:000C` 54。

## 踩到的問題

- 第一版探針不是決定性的：Go 的 map 走訪順序隨機，讀取集沒排序，突變候選順序跟著變，兩次產生的向量檔雜湊不同。排序之後相同。
- 第一版只收輸出簽章新穎的案例，`3CC9:00B9` 只剩 9 案，突變「高位字不同也當成比低位字」存活。加入普通案例配額之後 608 案，該突變被抓到。
- 中斷攔截要在擷取基準 CPU 之前裝，否則每次還原 CPU 都會蓋掉。

## 限制

- 平面視訊記憶體的**讀取**不經過 `WatchReads`，也沒有計數器，讀到 `A0000` 的輸入不會被丟棄，C 版會與原版不同。目前候選函式沒有這種行為，遇到時要在描述檔限制指標範圍。
- 旗標只比較 OF、SF、ZF、CF，跳躍條件用得到的只有這四個。
- 覆蓋率只計函式自己的指令，被呼叫函式的覆蓋由它們自己的描述檔負責。
- 原版函式含 `int`、I/O、視訊寫入的，這個框架不測。
- 基底狀態只有一個時，只有該狀態下合法的指標與結構能到達。戰場函式需要戰場狀態當基底（`fcmd-battle-base.state` 等），尚未使用。
