# 96：艦艇記錄的 `+0x46`／`+0x48` 整場都是 `0xFFFF`

`docs/internals/38` 把艦艇記錄的 `+0x46`／`+0x48` 記成「攻擊時的暫存座標
——回合之間都是 `0xFFFF`，只有在算傷害的那一刻才有值」。要把每回合的
結算改成「照攻擊名單逐一開火」就得知道誰寫它，所以這一輪盯著看。

## 兩個獨立的證據都說沒有

**watch（收據 `s3aim`）**：盯艦隊 31 旗艦分隊（艦池第 135 筆）的
`+0x46`–`+0x49`，跑完整條 `s3fight` 序列（14 億步，含九個回合的戰鬥），
**只有四次寫入**，全部是載入時 `3C9C:001C` 把它填成 `0xFFFF`：

```
#68674863 6921A: 00 → FF  ← 3C9C:001C
#68674863 6921B: 00 → FF  ← 3C9C:001C
#68674863 6921C: 00 → FF  ← 3C9C:001C
#68674863 6921D: 00 → FF  ← 3C9C:001C
```

戰鬥期間一次都沒有動過。

**靜態掃描**：`s3fight` 的傾印裡，艦池前 200 筆 `+0x46`／`+0x48`
**沒有一筆**不是 `0xFFFF`。

## 所以

「只有在算傷害的那一刻才有值」這句沒有證據支持——至少在這一場裡，
那兩格從頭到尾就是 `0xFFFF`。

`2264:0FC3` 拿 `[bp+2Eh]` 的 `+0x46`／`+0x48` 去減另一筆記錄的
`+0x34`／`+0x36` 算方位，**那個 `[bp+2Eh]` 不會是艦艇記錄**，否則每次
算出來的都是同一個退化的方向。它比較可能是戰鬥局面那筆記錄——
`2264:089F` 的呼叫端把兩邊的分數存進同一筆記錄的 `+0x2C`／`+0x2E`
（`docs/re/92`），那筆記錄還沒被辨識出來。

## 下一步怎麼問

`-regs-at 2264:0FC3` 抓進入時的暫存器與堆疊，看 `[bp+2Eh]` 那個 far
指標指到哪一段——落在艦池、艦隊表還是別的地方，一次就分得出來。

## 收據

`s3aim`：序列同 `s3fight`，加 `-watch 6921A-6921D`。
