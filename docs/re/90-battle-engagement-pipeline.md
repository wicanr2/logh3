# 90：一次攻擊是怎麼發動的

`docs/re/86` 解出「扣幾艘」的算式之後，還缺「誰打誰、什麼時候打」。
這一輪把發動端讀完了。

## 怎麼找到的

`2350:0023`（算扣幾艘的那支）沒有任何 `9A 23 00 50 23` 形式的呼叫點——
因為同一個線性位址可以寫成不同的 `段:偏移`。改成**掃所有 `9A` 開頭的
far call，把 `(段 << 4) + 偏移` 算出來比對**，一次就找到唯一的呼叫點
`2264:089F`（編碼寫成 `2264:0EE3`）。

## 三層

```
2264:080B   走攻擊名單，逐一發動
  └ 2264:089F   一次攻擊：畫動畫 → 算量 → 套用 → 再畫
       ├ 2350:0023   算這一擊扣幾艘（docs/re/86）
       └ 2264:0CFE   把量套用到目標
```

### 名單：`ds:A49A`

`2264:080B(筆數, 目標 far ptr)`：

```
for i in 0..筆數-1:
    idx  ＝ ds:A49A[i]                 ; 艦池索引
    艦艇 ＝ 艦池 ＋ idx × 78
    艦隊 ＝ ds:C074 ＋ 艦艇[+0x01] × 122   ; 同一支艦隊連著時不重算
    2264:089F(艦艇, 艦隊, 目標)
```

`ds:A76C` 是「這一擊還沒扣」的旗標：`2264:080B` 進迴圈前設 1，
`2264:089F` 在扣血之前清 0。清 0 的那一段前面有一個 `cmp ds:A76C,0 / je`，
跳過的是一次 `2264:0E19` 呼叫（畫面上的收尾），**扣血本身不受旗標影響**
——跳躍落點正好是扣血那一串 push 的第一個位元組。

### 名單怎麼來：`17A0:00AC` 的空間查詢

建名單的常式先算射程再查兩次：

```
17A0:00AC(陣營, x, y, 門檻, 輸出表 far ptr) → 命中數
```

它走**參戰分隊名冊**（`ds:98BA`，筆數在 `ds:9896`；`s3fight` 是 55 筆），
逐筆取艦艇記錄，收下同時滿足三個條件的：

- `+0x00`（陣營）等於參數；
- `+0x1E` 的 bit7 **沒有**設起來；
- `距離( (x,y), (+0x34,+0x36) ) ≤ 門檻`——距離用 `3310:0006`（歐氏），
  比較走 32 位元（`3CC9:00B9`）。

命中的艦池索引依序寫進輸出表，最後補一個 `0xFFFF` 當結尾，回傳命中數。

呼叫端連查兩次，**陣營 0 一次、陣營 1 一次**，第二次接在第一次後面寫；
兩次都用同一個門檻。查完再用比較器 `2264:036E` 對整張表排序
（`17A0:016C`）。

查詢的中心點是傳進來那筆記錄的 **`+0x46`／`+0x48`**——就是
`docs/internals/38` 記的「攻擊時的暫存座標，回合之間都是 `0xFFFF`」。

### 射程：`2350:0003`

```
射程      ＝ 艦艇記錄 +0x16 ÷ 200 ＋ 80     → ds:A772
ds:A774   ＝ 射程 ÷ 4
```

查詢用的門檻是 **`射程 × 2`**（呼叫端把 `ds:A772` 左移一位）。
`+0x16` 同時也是扣血算式的攻擊係數分子（`docs/re/86`），所以它是
分隊的攻擊力：**攻擊力越高，射程越遠、單擊越重**。

## 還沒解

- 比較器 `2264:036E` 用什麼排序（決定開火順序）。
- 名單裡兩個陣營都有，而目標是固定的一個——`2264:089F` 裡哪一步
  把同陣營的濾掉還沒讀。
- `2264:0CFE` 套用時除了扣艘數還做了什麼。
- 扣血算式裡 `2264:0FC3` 回的分母 K。
