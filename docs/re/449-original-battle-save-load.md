## 輸入與定位

原版`GIN3.COM` SHA-256 `770ed52607bf02584c125043830f22b19cc4b9a21f4909ad2f5f02d8fc8fd918`，bundle SHA-256 `de905aa0b5a666aa9d31dce36f43a5584f1842950c39d7e1b1f97c72e0d79673`。

S3父狀態來自專用副本`workplace/fcmd/fcmd-s3-base.state`，265888 bytes，SHA-256 `0155f63e373582b76a3b7ee54eccbef5ae2626481e09a68550b5fddc580146d7`，與既有[WORK收據](../internals/data/battle-work-control.json)的`original_parent`相同。
本次沒有重新證明父狀態之前的冷啟動過程，正常續行、保存及第二次冷啟動均完整記錄，無局面或seed注入。

原始執行定位為DOS CS:IP；WORK位移以DS:8F14為0。下列RAM線性基址只適用本次程式及機器配置：STELLAR `0x5F2CC`、PLANET `0x53132`、ADMIRAL `0x602AC`、FLEET `0x60BA4`、SHIP `0x668B2`、WORK `0x5DA44`。它們由實際保存bytes與RAM定位核對，不當成跨版本常數。

## 讀回前後的完整六表

比較保存DT0與冷啟動抵達12AA:02D4的完整RAM，不遮罩。

| 表 | 實際差異 |
|---|---|
| STELLAR、PLANET、ADMIRAL | 全表相同 |
| FLEET | 位移1570，艦隊12的+6A，1→9 |
| SHIP | 位移6287／6443／6521／6599／6677／6755／6833／6911，均為+2F圖示快取，變為9 |
| WORK | +2A..2D四bytes；座位1鏡頭1312,1660→1184,1440，座位0仍192,100 |

本案WORK+0C..14九個控制bytes與戰略／戰術回合、分數保持。不能以此推論所有雙人或同盟保存皆已核對。
RNG位於WORK外的DS:94DC，保存前為`2E C6 5B AE`，冷啟動後為`7E 16 DC D3`。本次原版未從六表還原該seed；不新增remake保存seed的欄位，也不要求讀回後沿保存前骰序。
座位1鏡頭與圖示快取改變是已證實差分；是否所有續讀都用同一重建演算法，仍需窄幅控制證據。

## 修正範圍與剩餘問題

[145](../spec/145-battle-save-return.md)經DRAFT、C／D證據審查READY後，只修戰術保存成功返回。狀態、分隊命令、鏡頭、分數及亂數不變，失敗不離開保存畫面；正常GUI與正負回歸見[驗收125](../playtest/125-battle-save-return.md)。
remake的LoadSlot仍回戰略，戰術保存讀回也仍經陣營選擇。這兩項與本案原版不同，保留為#48下一閘門。須先核同盟／雙人分支、鏡頭及圖示重建、目前戰術與整局計分的續接；不能直接呼叫新戰場初始化而清掉保存回合及命令。

早期`battle79-normal-r44-a/entry.state`與`normal89-r55-work-a/machine.state`已不存在，本輪沒有重驗那些歷史收據。其原文件及索引保持可追溯。
A版檢查器錯用主機大小寫判斷，漏認原版實際寫出的lowercase檔名；B版用BIOS鍵佇列，防拷畫面未收到IRQ1。兩者屬工具問題，輸出保留，不列產品缺陷或正式通過收據。
