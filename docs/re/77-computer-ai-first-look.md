## `+0x07` ＝ 目的地星域

載進來的當下就有值，而且不是每一支都有：

| 艦隊 | 所在 | `+0x07` |
|---|---:|---:|
| 帝國 8、14（在 23 波列多）| 23 | 25 |
| 帝國 12（在 28 巴米利恩）| 28 | 26 |
| 同盟 16、17、28、29、30、31（在 27 萊加爾）| 27 | 26 |
| 其餘 12 支 | | 0 |

按六次「實行」之後，**每一支有值的都走到了那一格**，而且 `+0x07` 變成 255：

```
第  8 筆（帝國）+06 23→25  +07 25→255
第 12 筆（帝國）+06 28→26  +07 26→255
第 14 筆（帝國）+06 23→25  +07 25→255
第 16／17／28／29／30／31 筆（同盟）+06 27→26  +07 26→255
```

星域記錄那一側跟著改：23 的帝國艦隊 2→0、25 的 7→9、28 的 1→0、
27 的同盟艦隊 6→0，而 26 達希利變成**帝國 1 支、同盟 6 支**。

所以（**confirmed**，八支艦隊八次一致）：

> `+0x07` ＝ 這一支要去的星域，**255 ＝ 沒有命令**（到了就填回 255）。

`+0x08` 在抵達的同時全部從 0／1 變成 5；`+0x4A`–`+0x4C`（三個相同的數）
與 `+0x5C`／`+0x64` 那兩組座標也整批改寫。語意還沒解。

## S2「諸神的黃昏」跨月十二回合（收據 `s2ai0`／`s2ai12`）

一定跨得過月底。18 支艦隊，載入時的命令：

| 陣營 | 所在 | `+0x07` | 支數 |
|---|---:|---:|---:|
| 帝國 | 2 亞爾提那 | 14 費沙 | 4 |
| 帝國 | 7 亞爾維斯 | 14 費沙 | 2 |
| 帝國 | 8 亞姆力札 | 13 伊謝爾倫 | 3 |
| 帝國 | 0 瓦爾哈拉 | 255（無）| 2 |
| 同盟 | 31 巴拉特 | 4 菲列亞 | 4 |
| 同盟 | 13 伊謝爾倫 | 0 瓦爾哈拉 | 3 |

十二回合之後：

| 艦隊 | 移動 | 命令 |
|---|---|---|
| 帝國 ×2（在 7）| 7 → **14** | 到了，`+07` 填回 255 |
| 帝國 ×3（在 8）| 8 → **13** | 到了，`+07` 填回 255 |
| 帝國 ×3（在 2）| 2 → **6** | `+07` 還是 14——**走到一半** |
| 帝國 ×2（在 0）| 沒動 | `+07` 255 → **0** |
| **同盟全部 7 支** | **完全沒動，一個 byte 都沒變** | |

### 一回合走一格是錯的

帝國那三支從 2 走到 6 花了**十二回合還沒走完**（`2 → 6 → 14`，路徑表的
中繼點就是 6）。另外幾支一格也走了好幾回合。所以移動**不是一回合一格**。

`+0x5C`／`+0x5E` 那兩個 word 在移動的艦隊上大幅改寫（第 0 支
`(1160,692) → (256,1080)`），沒移動的完全不動——**看起來是戰略地圖上的
連續座標**，艦隊每回合走一小段，跨過邊界時 `+0x06` 才換成新的星域。
**假設待驗**，要對 `+0x06`／`+0x5C` 設監看才釘得住。

### 電腦這十二回合什麼都沒做

同盟那七支（四支在巴拉特、命令是菲列亞；三支在伊謝爾倫、命令是瓦爾哈拉）
**逐位元組完全沒變**——沒移動、也沒有被指派新命令。帝國這邊唯一的「新命令」
是瓦爾哈拉那兩支的 `+07` 從 255 變成 0，而它們本來就在星域 0，等於沒動。

三種解釋還分不出來：

1. 原版的戰略 AI 本來就很少動（或只在特定條件下動）；
2. AI 的決策不在「實行」這條路上，而在別的時機；
3. 同盟那幾支的目的地太遠，連續移動十二回合還沒跨出巴拉特——
   但那樣 `+0x5C` 應該會變，而它沒有。

第 3 點自己站不住，所以真正的候選是 1 與 2。

### 星域記錄的 `+0x13` ＝ 這裡有敵我對峙

帝國三支走進伊謝爾倫（13）之後，那裡同盟三支的
`+0x6A` 從 255 變成 **9**、帝國那三支變成 **1**，`+0x6E` 都變成 1、
`+0x6F` 都變成 113——與 S3 達希利那場戰鬥完全同一組值。
星域記錄的 `+0x13` 同時從 8 變成 12。

所以 `+0x6A`／`+0x6E`／`+0x6F` 是**進入戰鬥**時填的，`+0x6A` 分陣營
（帝國 1、同盟 9）。費沙（14）那裡 `+0x13` 變成 24 ——費沙是中立，
帝國走進去是接管不是打仗，值不一樣。

## 移動只發生了一次（收據 `s2move`）

拿 S2 同一條路，對第 0 支艦隊的 `+0x06`–`+0x5D` 設監看，按六次實行。
載入之後那一段整個範圍只被寫了**五次**：

| 指令數 | 位址 | 變化 | 寫的人 |
|---|---|---|---|
| #240,054,127 | `+0x06`／`+0x5C` | 載入存檔：星域 2、座標 1160 | `3D08:001A` |
| #378,882,583 | `+0x06` | **2 → 6** | `113A:05CE` |
| #403,547,975 | `+0x5C` | 1160 → 256 | `297B:0B03` |
| #403,549,269–271 | `+0x4A`–`+0x4C` | `0x51` → `0xFC` | `297B:0BAB`／`0BAF`／`0BB3` |

六次「實行」的點擊落在 375M／525M／675M／825M／975M／1125M。
兩次寫入（378M、403M）都屬於**第一次**實行；**第二到第六次一個 byte 都沒動**。

`+0x07` 從頭到尾是 14（費沙），沒被清掉、也沒被重下——命令還在，
艦隊卻不走了。

所以：

> **這一支在六次實行裡只走了一格**，而且是第一次實行走的。
> 之後即使命令還在也不再前進。原因未解。

這也解釋了 `s2ai12` 的結果：不是「走得慢」，是**走一格就停**。目的地
剛好相鄰的那幾支因此看起來「到了」，目的地在兩格外的那三支就卡在半路。

候選解釋（都還沒驗）：一次「實行」只走一格且要重新下令；移動要消耗
某種資源；或者存檔裡本來就只剩一格的移動量。

**下一步是靜態的**：`113A:05CE` 是寫「所在星域」的那一行，
`297B:0B03` 是寫座標的那一行。往上找它們的函式與呼叫者，
比再跑幾份收據便宜得多。

## 移動函式：`113A:0350`（判斷）與 `113A:047D`（走一格）

從監看給的寫入位址往上追（`tools/scripts/xref_linear.py` 找呼叫者、
`tools/scripts/ida_trace.py` 在段傾印上反組譯）。

### `113A:0350` — 這一支這回合要不要動

```
0357  bx = 艦隊記錄 + 8
035D  al = [+0x08]              ; 移動狀態
0360  or al,al   jz  036B       ; 0 → 檢查是不是到了
0367  cmp al,1   jnz 0389       ; 1 → 檢查是不是到了；其餘直接跳過檢查
036B  al = [+0x06]（所在）  cl = [+0x07]（目的地）
0376  cmp al,cl  jnz 0389
037D  [+0x08] = 5               ; ★ 到了：標成停止
0384  [+0x07] = 0FFh            ; ★ 到了：清掉命令
0389  cmp [+0x08],5
0391  jnz 03A0
0393  → +08 == 5：呼叫別的東西，**不移動**
03A0  → 否則：call 113A:047D 走一格
```

所以（**confirmed**，程式讀出來的）：

> **`+0x08` ＝ 移動狀態。5 ＝ 這一支不動；0 或 1 ＝ 會走。**
> 走到目的地的當下同時寫 `+0x08 = 5` 與 `+0x07 = 0xFF`。

拿 S2 的兩份 dump 對照，完全對得起來：

| 艦隊 | 載入時 | 十二回合後 |
|---|---|---|
| 帝國 2／3／5／7／14（`+08=1`）| 目的地相鄰 | 到了，`+08=5`、`+07=255` |
| 帝國 0／12／15（`+08=1`）| 目的地兩格外 | 走到中繼點 6，`+08` 還是 1、命令還在 |
| 帝國 4／8／11（`+08=5`）| — | 沒動 |
| **同盟全部七支（`+08=5`）** | 有目的地 | **沒動** |

**先前那句「電腦十八回合什麼都沒做」要修正**：不是電腦不下命令，是
同盟那七支的 `+0x08` 一開始就是 5——劇本把它們設成不動。這是**局面的
設定，不是 AI 的行為**，所以那兩份收據其實**沒有觀察到 AI**。

（`+08=1` 的那幾支在十二回合裡也只走了一格，這件事仍未解——見上一節
`s2move` 的監看。走一步之後為什麼沒有第二步，要往上追呼叫者。）

### `113A:047D` — 走一格

```
0485  from = [+0x06]   陣營 = [+0x01]   dest = [+0x07]
04A7  call far 2B99:0302        ; ★ 查下一跳（docs/re/28 那張表）
04B6  星域記錄 stride = 7Eh(126)，表在 ds:A79C   ; 與 docs/re/22 相符
04DF  比 from 記錄的 +0x12（擁有者）與自己的陣營
04F2  比 next 記錄的 +0x12
      兩格都不是自己的 → 走另一條路（呼叫別支後結束）
0526  cmp [+0x08],1             ; 下一格不是自己的時候，要 +08==1 才繼續
0545  dest != next 時呼叫一支函式，回 0 就把 [+0x07] 改寫成 next
05CA  [+0x06] = next            ; ★ 監看抓到的那一行
05E6  ds:B77C + [+0x04]×28 + 0x0A = next   ; ★ 提督表的「現在位置」
05ED  副官（+0x05）不是 FF 的話同樣寫一份
```

兩件新東西：

- **移動要看擁有者**：現在這一格或下一格是自己的才照常走；兩格都不是
  自己的另有處理（大概是遭遇或補給）。
- **`ds:B77C` 是執行期的提督表**，每筆 28 bytes，`+0x0A` 是所在星域
  ——提督詳細資料上的「現在位置」就是它，移動時由這支順手更新。
