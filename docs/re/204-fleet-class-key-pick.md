# 204 — `2D76:0576`：建艦隊之前抽一個艦隊類別鍵

`2D76:02FA` 挑完提督之後、呼叫 `2D76:0611` 把艦隊建出來之前，
中間夾著 `2D76:0576(提督, 類別)`。那是建艦隊那條路最後一段沒讀的。

它做一件事：**把艦隊類別鍵（0–15）抽出來，寫進提督 `+0x08` 的高四位。**

## 反組譯

線性 `0x2DCD6` 起（段 `2D76`）：

```
2D76:0576(提督編號, 類別):
    提督 = ds:B77C + 編號 × 28
    類別 > 3 → （跳過設定，原版沒有防守；呼叫端只給 0–3）
    表 = 跳躍表 ds:602A[類別] 選出來的那一張
    n   = 表[0]                       ; 筆數
    提督[+0x08] &= 0Fh                ; 清掉高四位
    r = 3CD5:000C()
    提督[+0x08] |= 表[1 + r % n] << 4
```

跳躍表 `ds:602A` ＝ `05A4 05AE 05B8 05C2`，四個分支各指到一張表：

| 類別 | 表 | 內容（第一個 byte 是筆數）|
|---|---|---|
| 0（未命名，`+20`）| `ds:5F62` | `09` ＋ `00 01 02 03 04 06 07 08 09` |
| 1（占領，`+19`）| `ds:5F70` | `02` ＋ `0A 0B` |
| 2（防禦，`+18`）| `ds:5F6C` | `03` ＋ `05 0C 0D` |
| 3（運用，`+23`）| `ds:5F74` | `02` ＋ `0E 0F` |

## 這四張表就是 `ds:5F52` 的反表

`ds:5F52` 是「類別鍵 → 類別」那張 16 格表（`docs/re/190`）：

```
5F52: 00 00 00 00 00 02 00 00 00 00 01 01 02 02 03 03
```

把它反過來查：類別 0 對應鍵 `0 1 2 3 4 6 7 8 9`、類別 1 對應 `A B`、
類別 2 對應 `5 C D`、類別 3 對應 `E F`——**與上面四張表逐項相同**。

所以整條路是：配額算出「最缺哪一類」→ `2D76:0576` 從那一類的鍵裡
**等機率抽一個** → 寫進提督 `+0x08` 高四位 → `0x2DE66` 再把它搬到
艦隊記錄的 `+0x09`（`docs/internals/33`）。

`+0x08` 的低四位是**艦種**（`07F9:023B` 拿它查星域的艦艇存量），
高四位是**類別鍵**——同一個 byte 裝兩件事。

## 建艦隊那條路讀完了

| 段 | 狀態 |
|---|---|
| `2D76:0060` 閘門（上限／少於三支／維持費 × 20） | `docs/re/202` |
| `2D76:011C`／`01A5`／`0251` 配額與排序 | `docs/re/202` |
| `2D76:02FA` 挑人選四層（1/2、1/4、1/8、1/8）| `docs/re/203` |
| `2D76:0576` 抽類別鍵 | 本篇 |
| `2D76:0611` 新編一支（配槽、預設副官）| `docs/re/181` |
| `2E54:0513` 守首都那條補法 ＋ `2E54:063C` 排序 | `docs/re/201` |

**只剩 `ds:8FD4[陣營]` 的語意未解**，而它只影響閘門的鬆緊。

## 一條方法

**看到一張表，先找它的反表在不在手上。** `ds:5F52` 早就記在
`docs/re/190` 裡，這四張表逐項對得起來——於是「表的內容抄對了沒」
不必另外驗，兩份資料互為校驗。抄錯一個 byte 就對不起來了。
