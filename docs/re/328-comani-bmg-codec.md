`docs/internals/20` 先前解不開的原因：把段的起點當成目錄寫的位移，實際要 +2，
所以每段的欄位都錯位兩個 byte（`byte[3]/[5]/[11]` 全 0 其實是格數、格種後的旗標、欄數的高位元組）；
而且只有第 0 格可能是 `.AMG` 格，後面多半是 XOR 格，整段套 `.AMG` 狀態機一定吃不光。

## 一、檔案結構

```
+0        u16   目錄長度 = 10 × 筆數（2540 → 254 筆）
+2        目錄，每筆 10 bytes：char[4] 名、u16 長度、u32 位移
+2+位移   段（長度 bytes）；第一段在 2542，段與段之間沒有洞，最後一段收在檔尾
```

段：

```
+0   u16  格數 n（4–14；5 最多，167 段）
+2   第 0 格，接著第 1 格 …
格：
+0   u8   格種：0 覆寫（210 格）／1 XOR（1,228 格）
+1   u8   旗標，1,438 格全是 0（程式碼 inc si 跳過，沒讀）
+2   u16  到下一格的距離，從 +4 起算（下一格 ＝ +4 ＋ 此值）
+4   u16  VRAM 位移，相對於視窗原點：列 × 80 ＋ 位元組欄（mode 12h 一列 80 bytes）
+6   u16  直行數 w（位元組欄，一欄 8 像素；高位元組全 0，只讀低位元組）
+8   u16  高 h：格種 0 是「組數」（×2 列），格種 1 是列數（高位元組全 0）
+10  壓縮資料
```

所有格都落在 32 欄 × 102 列裡（量到的最大範圍剛好 102 列、32 欄）＝ 視窗 256×102。
段的第 0 格：53 段是格種 0、201 段是格種 1。依名字尾碼：`D0` 45 段第 0 格全是覆寫格，
`AB`／`AM`／`AF`／`D1`／`D2` 幾乎全是 XOR 格。

`ANI_PNL1.A98` 就是一段「只有 1 格、格種 0」的同格式資料
（`01 00 | 00 00 84 32 00 00 50 00 C8 00`），也由同一支 `348A:01DC` 畫
（`fcx-bmg-frames`：#1140140562，x=0,y=0，指標 3D22:60BE）。
`docs/internals/37` 說「+0 u32 固定 1、+4 size−6」其實是「u16 格數 1、格種 0、旗標 0、u16 距離」。

## 二、程式碼

呼叫鏈（`3958:0041`，交戰演出畫圖）：

```
3958:0041(記錄far, si=靜圖?, di=動畫?)
  ds:8F36（動畫效果）== 0 → 直接回
  組四字名（見 §四）→ 332E:0D1C(名, &緩衝 ds:F138)   ; 開檔、seek 位移+2、讀長度
  x = 記錄+0（陣營）==0 ? 1 : 47；y = 4
  di != 0 → [記錄+6 != FF → 3B74:031A(記錄+6)] ; 348A:0228(x, y, 緩衝)  整段每一格
  否則                                        ; 348A:01DC(x, y, 緩衝)  只畫第 0 格
```

`3A8D:003A`：`VRAM 基底 = y×320 + x + 0x0C80` ＝ 像素 (8x, 40+4y)；x=1,y=4 → (8,56)，x=47 → (376,56)。

```
348A:01DC(x, y, buf far)            348A:0228(x, y, buf far)
  base = 3A8D:003A(x, y)              base = 3A8D:003A(x, y)
  si = buf + 2                        n = [buf]; si = buf + 2
  畫 1 格                             畫 n 格
每格：
  kind = [si]; si++
  0281: 等 ds:8EFE 計時器到 0，再設 ds:8EFE = ds:8F10[ds:8F37 動畫速度]（每格的間隔）
        si++（旗標）; next = si+2+[si]; si += 2
        di = base + [si]; si += 2
  kind == 0 → 02BA   否則 → 036C
  si = next
```

格種 0（`348A:02BA`／`02F9`／`032E`；`2376:17B8` 設 GC：write mode 0、set/reset 關、replace、bit mask FF）：

```
dh = w; dl = h; mask = 1（sequencer map mask，plane 0）; 起點 = di
loop:
  a, b = lodsw
  若 a != b: 寫 [di]=a, [di+80]=b, di += 160, 組數--（到 0 → 換直行）
  若 a == b: c = [si], cnt = [si+1], si += 2
             重複 cnt 次：寫 [di]=a, [di+80]=c, di += 160, 組數--（到 0 → 換直行）
  換直行：di = 起點 + 欄號; 組數 = h; 欄數-- 到 0 → 欄號歸 0、mask <<= 1；mask == 0x10 就結束
```
（重複組的計數可以跨直行、跨 plane；cnt=0 在原版是 65536 次，檔案裡沒出現。）

格種 1（`348A:036C`／`03A3`／`03E1`；`2376:17E0` 設 GC：reg5=08 → read mode 1、reg3=0x18 → XOR、
reg7=0 → color compare 讀回全 1、bit mask FF）：

```
loop:
  a = lodsb
  a != 0: and es:[di], a   ; 讀回 FF，所以寫入值 = a，XOR 模式 → plane[di] ^= a
          di += 80; 列--（到 0 → 換直行）
  a == 0: n = lodsb        ; 跳過 n 列
          while n >= 剩下列數: n -= 剩下列數; 換直行（可跨 plane，最後一個 plane 走完就結束）; n == 0 就停
          否則 列 -= n; di += 80·n
```

換直行、換 plane 與格種 0 相同，只是高是列數。收尾 `2376:1852` 把 GC／sequencer 還原。

## 三、對照收據

比較等級：`same-state`（同一份檢查點 `eng-t5.state`、同一點擊序列）；比較區域只取兩個視窗
左 (8,56) 256×102、右 (376,56) 256×102，戰場方塊不比。模型是「截圖 → 四個 plane → 照上面的
偽碼畫 → 轉回色號」，先驗證截圖 → plane → 截圖來回相同。腳本 `workplace/bmg/parse.py`、
`workplace/bmg/anim_verify.py`。

所以那批差異是取樣時點，不是解碼。

## 四、名字怎麼組（`3958:0041`，記錄指標 `[bp+1Ah]`）

表（`ds:8E16` 起，傾印 `ppd0-mem.bin` 線性 `0x54B30+`）：
`8E16 = "EF"`（陣營）、`8E1A = "BHCADTEPLPFZ"`（單位種類）、`8E28 = "AD"`、`8E2C = "012BMF"`、
`8E34 = B1 B2 B3 B4 B5 B6 BA B9 B8 BF B7 BD BB BC BE DD …`。

```
[0][1]: 記錄+1（種類）是 9／10／11 → 'P' ＋ 8E1A[種類]（PP／PF／PZ）
        否則 [0] = 8E16[記錄+0]（E 帝國／F 同盟）
             [1] = 記錄+4 != 0 ? 8E1A[記錄+1] : 8E34[記錄+5]（0xB1… 是個別艦的代碼）
[2][3]: si 旗標 → "D0"
        否則 [2] = 8E28[記錄+2]（A／D）
             [2]=='D' → [3] = 8E2C[記錄+3]（0／1／2）
             [2]=='A' → [3] = 8E2C[3 + 記錄+3]（B／M／F）；種類 10／11 且 記錄+3==1 時例外：陣營 0 → 'M'、否則 'F'
```

記錄欄位的語意（`+2` 行動、`+3` 子類、`+5` 個別艦、`+6` 音效）只從這支函式的用法推，**hypothesis**。
從匯出的圖看：`AB` 是光束、`AM` 是飛彈、`AF` 是艦載機；`D0` 整段是「被打」那一串（靜圖＋中彈爆炸）、
`D1`／`D2` 是更重的中彈——都只是看圖，**hypothesis**。
