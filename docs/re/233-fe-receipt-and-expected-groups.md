# 233 — `0xFE` 有收據了，而且 `+0x0E` 會在補編制的迴圈中途被改回

`docs/re/226` 從反組譯讀出「`0xFE` ＝ 艦種 5 與 6 挑目前組數少的那個」，
但沒有收據。這一輪做了一份，順帶量到一件在跑之前才剛從
`297B:05B2` 讀出來的事。

## 收據 `refit4`

同一條輸入序列，注入下在 `#230000000`：

| 注入 | 目標 |
|---|---|
| `lin:6190A=06 02` | 艦隊槽 28 的 `+0x0E`（應有組數）＝ **6**、`+0x0F`（現有）＝ **2** |
| `lin:601DC=…` | 星域 30 同盟待命部隊：艦種 0–4 清成 **0**、5 與 6 各 **30000** |

傾印 `refit4_pre.bin`（`#242500000`）與 `refit4_post.bin`（`#246000000`），
整補在 `#242631032`。

```
前  編制 2/6   組0 艦艇#0 艦種0 槽20 3000/3000
               組1 艦艇#2 艦種0 槽10 3000/3000
    待命部隊 [0 0 0 0 0 30000 30000]

後  編制 4/4   組0 艦艇#0  艦種0 槽20 3000/3000
               組1 艦艇#2  艦種0 槽10 3000/3000
               組2 艦艇#30 艦種6 槽12 1000/1000
               組3 艦艇#31 艦種6 槽29 1000/1000
    待命部隊 [0 0 0 0 0 30000 28000]
```

## `0xFE` 那一格

```
樣板鍵 04 第 1 格 (0,10)：a = 旗艦艦種 0
    2D76:0C4F：組1 的槽就是 10、艦種也是 0 → −1，跳過
第 2 格 (0,12)：a = 0
    0FF4:0E5A(星域30, 0)：存量 0 → 0 → 要換
    0FF4:1350：艦種 0 的替代順序 2 → 4 → FE → 3 → 1
        候選 2：存量 0 → 跳過
        候選 4：存量 0 → 跳過
        0FEh：0FF4:1404 數出 n5 = 0、n6 = 0
              n5 >= n6 → **先試 6** → 30000 ÷ 1000 = 30 ≠ 0 → 回 6
    艦種 6、槽 12、1000 艘                        ← 傾印 艦艇#30 ✓
第 3 格 (6,29)：a = 6（樣板直接給的，不走替代）
    0FF4:0E5A(星域30, 6) = 29000 ÷ 1000 = 29 ≠ 0 → 用 6
    艦種 6、槽 29、1000 艘                        ← 傾印 艦艇#31 ✓
待命部隊[6] 30000 − 1000 − 1000 = 28000           ← 傾印 28000 ✓
待命部隊[5] 一動都沒動                            ← 傾印 30000 ✓
```

**`docs/re/226` 讀出來的「一樣多先試 6」成立。**

## `+0x0E` 中途被改回

注入把應有組數寫成 6，但整補之後傾印裡是 **4**，而且只補了兩組——
第 4 格（`(5,16)`）沒有做。

原因在 `297B:05B2(艦隊, 提督, 副官)`（線性 `0x29D62`）的第一件事：

```
艦隊[+0x0E] = 297B:0209(提督[+0x06])        ; 等級 → 應有組數
接著把提督與副官的 +0x0F／+0x10／+0x11／+0x13／… 揉成
艦隊[+0x3D]…+0x47 那一串能力值
```

而 `2D76:0A44` **每補一組就叫一次 `297B:03EB(艦隊編號, 0)`**
（線性 `0x2E398`），它的尾段接 `297B:0546` → `297B:05B2`
（`docs/re/230`）。所以：

```
i = 2：補上一組 → 297B:05B2 把 +0x0E 從 6 改回 4
i = 3：補上一組
i = 4：迴圈條件 i < 艦隊[+0x0E] ＝ 4 → 停
```

**迴圈上界是每一圈重讀的，而且迴圈自己會改它。** 正常玩的時候
`+0x0E` 本來就等於 `297B:0209(提督等級)`，所以這條看不出來；
把它 poke 成別的值才會浮出來。

## remake

`rules.Refit` 的 `want` 是固定參數。原版那個「重算成提督等級對應的值」
在正常局面下是恆等變換（`rules.FleetSlots` 算的就是同一個數），
所以 remake 不模擬它——**但這是一個刻意的簡化，記在這裡**。

`TestRefitBalancesFiveSixFromReceipt` 用 `want = 4`（原版收斂到的值）
從兩組開始跑，四組與待命部隊都與收據相同。

`docs/re/230` 列的「沒讀」少一支：`297B:05B2` 讀完了。

## 一條方法

**先讀完再跑，讀到的東西會變成預測。** `297B:05B2` 是在這一跑開始之後、
結果回來之前順手讀的，讀到「它會覆寫 `+0x0E`」的當下就知道
「應有 6 會被改回 4、只會補兩組」——收據回來正是如此。
**同一份證據，先讀的是預測，後讀的只是解釋。**
