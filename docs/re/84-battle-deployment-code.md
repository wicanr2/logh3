# 84：進戰場時艦隊被放到格上，座標 ＝ (欄×16, 列×20)

## 做法

`docs/re/83` 解出分隊的座標欄位之後，剩下的問題是「誰寫的、什麼時候寫」。
拿 dosgolem 的 `-watch` 監看三段位址跑完 `s3ai6` 的整條序列：

| 監看 | 是什麼 | 結果 |
|---|---|---|
| `5E724`–`5E727` | 值剛好是 (1056,600)，懷疑是視野原點 | **一次都沒被寫** |
| `668DA`–`668DD` | 帝國第 1 艦隊旗艦分隊的 `+0x28` | **一次都沒被寫** |
| `611B8`–`611BB` | 帝國第 13 艦隊的 `+0x5C` | 六次，最後兩次在第 383,234,730 步 |

沒被寫的兩個一樣有資訊：那個 (1056,600) 不是執行期算出來的視野原點，
而分隊的座標是**檔案讀進來的**（DOS 讀檔直接填緩衝區，不經過
記憶體寫入路徑），不是進戰場時算的。

## 佈陣的程式碼

最後兩次寫入來自 `297B:0AFF` 與 `297B:0B0D`：

```
+0AE7  call far 113A:0D2C        ; 傳入 [bp+1Ch] 與 bp
+0AEE  or   ax, ax
+0AF0  jz   ...                  ; 回 0 ＝ 放不下
+0AF2  mov  al, [bp+0]           ; 挑好的格欄
+0AF7  mov  cx, 4
+0AFA  shl  ax, cl               ; × 16
+0AFC  les  bx, [bp+16h]         ; 艦隊記錄
+0AFF  mov  es:[bx+5Ch], ax      ; X ＝ 欄 × 16
+0B03  mov  al, [bp+1]           ; 挑好的格列
+0B08  mov  cx, 14h
+0B0B  mul  cx                   ; × 20
+0B0D  mov  es:[bx+5Eh], ax      ; Y ＝ 列 × 20
```

16 與 20 就是戰場圖塊的寬高（`docs/internals/36`），所以**艦隊是放在
格上的**，座標是格的左上角。`113A:0D2C` 挑格，還沒讀。

量到的值對得上：帝國第 13 艦隊寫進去的是 (416,280) ＝ 格 (26,14)。

## 目標座標是複製來的

同一支常式往下：

```
+0B7A  mov  ax, 3F4h             ; 1012
+0B80  add  bx, 5Eh
+0B83  sub  ax, es:[bx]          ; 1012 − Y
+0B87  mov  ax, 3F8h             ; 1016
+0B90  add  si, 5Ch
+0B93  sub  ax, es:[si]          ; 1016 − X
+0B9D  call far 2BE1:011D        ; 拿那兩個差算出一個 byte
+0BA7  mov  es:[bx+4Ah], al
+0BAB  mov  es:[bx+4Ch], al
+0BAF  mov  es:[bx+4Bh], al
+0BBC  mov  es:[si+64h], ax      ; +0x64 ← +0x5C
+0BCC  mov  es:[bx+66h], ax      ; +0x66 ← +0x5E
```

`+0x64`／`+0x66` 是從現在位置複製過去的——這就是為什麼剛進戰場時
兩組座標一樣（`docs/internals/34`）。

`+0x4A`／`+0x4B`／`+0x4C` 三個位元組被填成同一個值，由「艦隊相對
(1016,1012) 的位移」算出來。1016 與 1012 距整張戰場的中心
(1024,1020) 各差 8，`2BE1:011D` 還沒讀，所以那個值是什麼還不能斷言。

## 順帶排除的

戰場畫面畫好之後就不再重畫：監看單位該出現的那個 VGA 位址
（`A4277`），最後一次寫入在第 435,089,493 步，而戰場畫面在那之後
還存在四億多步。同一次執行倒出來的十二張畫面（第 870,000,000 步起
每 2,500,000 步一張）**逐位元組完全相同**，所以單位也不是在幀之間
閃爍——這個局面的戰場上就是沒有單位。

## 收據

`s3draw`（`-watch A4277-A4279` ＋ 十二張 `-dump-at`）與
`s3init`（`-watch` 三段）。
