# RE 109 — 戰術選單第二項「資料」開的是什麼

`docs/re/98` 解出戰術選單的七個選項時，第二項「資料」只知道名字。
`docs/re/101` 把選單接進 remake 時也只能把它當成「關掉選單」。
這一輪把畫面取出來了。

## 怎麼走到

`docs/re/101` 量到選單開在游標處、第一項的反白帶頂端等於游標的 y，
一項高 20。所以**在同一個 x、往下 20 個像素**點第二下就選到「資料」：

```
第一下  滑鼠 (240,200)   → 選單開在畫面 (225,221)
第二下  滑鼠 (240,220)   → 落在第 1 項
```

收據 `s3data`：`s3menu` 的序列，把第 1,095,000,000 步那一下從
`240,200` 改成 `240,220`，跑到第 1,200,000,000 步。

## 它蓋掉整個戰場

與戰場畫面（收據 `s3ai6`）比，**139,626 個像素不同**，範圍
**x 16–573、y 60–419**——戰場、小地圖與狀態欄那三塊全部被蓋掉。
外圈的金屬邊框（`ANI_PNL0.A98`）還在。

版面的粗略形狀（每 8 個像素取一點）：

```
左邊    一張大表：頂上一塊表頭（三列一組的欄位），下面十幾列資料，
        佔 x 約 16–463、y 約 60–419
右上    一塊窗，佔小地圖原本的位置（x 約 465–623、y 約 60–208）
右下    另一塊窗，x 約 465–623、y 約 215–419
```

左表每 20 個像素一列、列與列之間有一條色 7 的分隔線，
與其他清單畫面（`docs/internals/28` 那一族）是同一種版面語言。

## 還沒做

**版面還沒逐位元組量。** 這個專案量畫面版面有現成的做法
（`tools/specs.sh` 加 `tools/scripts/*_spec.py`，其他十幾張畫面都是這樣
量出來再寫進 `docs/internals/data/screen-*.json`）——下一輪照那條路走，
先量框與列距，再讀表裡的欄位是什麼。

在那之前 remake 的 `Game.battleClick` 對第二項維持「只關掉選單」，
**不畫憑空捏的畫面**。
