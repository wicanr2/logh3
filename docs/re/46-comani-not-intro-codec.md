# RE 46 — `COMANI.BMG` 不是開頭動畫那套編碼

日期：2026-09-07
工具：`tools/scripts/anim_codec.py`
狀態：**否定結論 confirmed**（253 段一段都吃不光）。

## 為什麼要試

開頭動畫的編碼解出來了（`docs/re/36`）：XOR-RLE，一格四個 plane、
每個 plane 後面接一個分隔位元組。`COMANI.BMG` 也是動畫封存檔
（`docs/internals/20`，目錄結構已確認、每一段的編碼未解），
最省事的假設是「同一套」。

## 先確認解析器是對的

把 `docs/re/36` 的語法寫成 `tools/scripts/anim_codec.py`，跑開頭動畫：

```
開頭動畫：374 格裡對不上的 0，吃到 1764911／1764911 bytes
```

每一格吃掉的位元組數與 `IBMFLS16.350` 的長度表逐一相同，整個檔案吃光——
與 `docs/re/36` 的結論一致，所以解析器沒問題。

## 結果：一段都不是

拿同一套語法去試 `COMANI.BMG` 的 253 段，每一段搜尋「每個 plane 幾格」
（1–4000）看能不能剛好吃掉那一段的長度：

```
COMANI：0／253 段能用同一套語法吃光
```

**一段都沒有。** 所以戰鬥動畫不是同一套編碼，也不是「同一套但換個尺寸」。

## 看起來像有段頭

前三段的開頭：

```
EBAB (1289)  0f 00  04 00  01 00  66 00  4f 06  0e 00  46 00  00 3b …
EBAF (4998)  00 40  08 00  01 00  14 00  f3 0f  02 00  04 00  02 00 …
EBAM (2904)  00 b2  05 00  01 00  7c 00  24 03  15 00  37 00  00 1b …
```

第三個 word 都是 `0001`，第二個 word 是小數字（4／8／5）——像是段頭而不是
資料。但三段的第一個 word 差很多（`000F`／`4000`／`B200`），
還看不出是什麼。
