# 292 — 叛亂讀完了：`2703:1789` 的後半段、效果與報告

日期：2026-09-11
執行器：dosgolem-logh3 `e0b6a03`（未提交檔案 0 個）
收據：`rbx292`（一格叛亂，報告停在畫面上）、`rbx292d`（九格叛亂，逐顆行星）、
`rbx292e`（門檻壓在 225–625，哪幾格叛亂完全由亂數決定，32 格逐格相同）
狀態：判定式、效果、報告 **confirmed**（反組譯 ＋ 三份收據逐格／逐顆相同）

[`245`](245-region-flag-bits-one-and-four.md) 把星域 `+0x13` 的 bit1 追到
`2703:1789`，讀出前三道閘門就停了；[`247`](247-strategy-report-strings.md)
從訊息表把它定性成「叛亂」。剩下的兩句——**亂數怎麼判、叛亂的效果是什麼**
——這一輪讀完了，而且兩邊都有收據。

## 判定：`2703:1789(星域編號, far* 已失格數)`

```
星域 = ds:A79C ＋ 編號 × 126
編號 == 0（瓦爾哈拉）或 == 31（巴拉特）        → 回 0
星域[+0x12] == 2（無主）                        → 回 0       ← 原版連寫了兩次
星域[+0x28 ＋ 擁有者] != 0（自己在這一格有駐軍）→ 回 0

提督 = ds:B77C ＋ ds:8F4D[擁有者] × 28          ; 情報專任參謀（docs/internals/30）
r1 = 亂數() % 400 ; 亂數() 再抽四次丟掉
r2 = 亂數() % 400 ; 亂數() 再抽四次丟掉         ; 一格共抽十次

u = 星域[+0x7D]（未安定度 0–200）
門檻 = u < 50  ? u ÷ 3
     : u < 100 ? u ÷ 2
     : u < 150 ? u × 3 ÷ 4
     :           u × 4 ÷ 3
門檻 = 門檻 × 100 ÷ 提督[+0x0E]（營運）
門檻 = 門檻 ÷ (已失格數[擁有者] ＋ 1)

回 (r1 ＋ r2) < 門檻 ? 1 : 0                    ; 無號比較
```

亂數是 `3CD5:000C`＝`3CC9:00CC`（[`87`](87-original-rng.md)）。`cwd`＋`idiv 400`
之後餘數是 0–399，因為產生器只回 0–32767。**每一格用掉十次**：第 1 次與第 6 次
拿去用，其餘八次抽了就丟——序列要對得上就得照抽（同一個慣用法在
[`288`](288-fleet-record-remaining-fields.md) 的 `307D:0921` 也出現過）。

### 四段階梯不是連續的

未安定度每跨一段門檻就跳一級，落差很大：

| 未安定度 | 49 | 50 | 99 | 100 | 149 | 150 | 200 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 門檻（營運 100、沒失過格）| 16 | 25 | 49 | 75 | 111 | 200 | 266 |
| 每回合叛亂機率 | 0.09% | 0.2% | 0.8% | 1.8% | 3.9% | 12.6% | 22.2% |

（`r1 ＋ r2` 是兩個 0–399 相加，門檻 T ≤ 400 時 `P = T(T+1)/2 ÷ 160000`。）

**治安好的時候等於不會發生**：開局那一批未安定度是 27–50，門檻只有 9–16，
一格一回合大概萬分之一。三份執行期傾印跑重播都是 32 格全 0——這也是
bit1 至今一次都沒被觀測到的原因，不是規則沒接上。

### `已失格數` ＝ `2703:09DD`

`056A:0468` 那一圈開頭先算一次，兩個位元組：

```
對每一格：擁有者 == 2 跳過；ds:B75C[i] == 2 跳過；ds:B75C[i] == 擁有者 跳過
          否則 out[ds:B75C[i]]++
```

`ds:B75C` 那 32 格**只有一個寫入者**：`2703:0068`（線性 `0x27098`，
`global_xref.py` 掃 disp16，四處命中三讀一寫）。它在 `2703:0000` 那支
**載入時的初始化迴圈**裡——同一圈把 `+0x13`／`+0x28`／`+0x29`／`+0x2C`／`+0x2E`
歸零、用 `2703:159B` 依行星重算擁有者、再依擁有者把民心 `+0x7C` 設成
0／200／100。所以 `ds:B75C[i]` ＝ **載入當下那一格的擁有者**，中途不更新。

`out[f]` 因此是「**f 從載入到現在已經丟掉幾格**」，而它是叛亂機率的**分母**：
丟得越多，剩下的領地反而越不容易再叛。`s3ai6`／`s3datamem` 兩份傾印算出
「同盟已失 2 格」，與 [`54`](54-two-regions-flip-at-month-end.md) 記的
「月底有兩個星域易主」對得上。

## 誰讀 bit1：`0374:0556`

`field_xref` 式的掃描找不到讀取點，因為讀的是 `test es:[bx+13h], 2`
而它在另一個段。`imm_scan_all.py` 掃 `ds:085D` 那個格式字串的立即值，
從報告那一端反著把整條路拉出來：

```
0374:03F8 起的逐格迴圈（計數器 ds:8F17 ＝ 0..31）
  ├ +0x13 bit2（雙方都有艦隊）→ 0374:0489（戰報）＋ 12AA:000E（進戰鬥）
  └ 否則 → 0374:0556(星域記錄)
             1930:1572(編號) / 1AAB:0FAF(編號) / 0374:0608 / 0374:0919 / 0374:0AF2
             +0x13 bit4（單方面占據）→ 20B4:1497(編號)
             否則 → 2703:1B48(編號)   無主格裡再跑掉一顆行星
                    2703:1CD7(編號)   逐顆行星回復防衛力
                    2703:1D85(編號)   要塞砲歸零
             +0x13 bit1（叛亂）→ 2703:1908(編號, 0)，然後 `and 0FDh` 把 bit1 清掉
             +0x2C ＝ +0x2E ＝ 0
```

**同一次「實行」裡就處理掉**：收據 `rbx292c` 量到 `056A:0468` 在
`#218,119,706`、`0374:0556` 在 `#218,388,836`，設旗標的那一圈在前，
讀旗標的那一圈在後。bit1 是「這一輪內部傳一次的訊號」，不是會留到下一回合的狀態
——所以任何一份傾印看到的 `+0x13` bit1 都會是 0，除非正好停在那 27 萬道指令之間。

## 效果：`2703:1908(星域編號, 全部旗標)`

```
星域 = ds:A79C ＋ 編號 × 126
2AF5:0036(編號, 0)                  ; 把「目前星域的行星切片」切到這一格
星域[+0x12] = 2                     ; 擁有者 ← 無主
把切片裡每一顆行星的遠指標收成陣列，qsort(3C6A:000D) 用 2703:1A5A 比較器
                                    ; 比的是行星 +0x1A 經濟力（32 位元），**遞減**
n = 1 ; 照順序 = 真
全部旗標 != 0            → n ＝ 整格行星數
否則 未安定度 > 160      → n ＝ 整格行星數
否則 未安定度 > 120      → n ＝ min(2, 行星數)
否則 未安定度 > 80       → n ＝ 1
否則                     → n ＝ 1，但「照順序」＝ 假
照順序 → 從切片第 0 顆起，往後 n 顆各跑 2703:1ADB
否則   → 從切片最後一顆起，往前 n 顆各跑 2703:1ADB
```

`2703:1ADB(行星)`：

```
行星[+0x11] = 2                                   ; 擁有者 ← 無主
行星[+0x1A] −= 行星[+0x1A] ÷ 3                    ; 經濟力剩三分之二（32 位元）
若 行星[+0x14] × 3 < 行星[+0x16]:  行星[+0x14] = 0
否則                               行星[+0x14] −= 行星[+0x16] ÷ 3
                                                  ; 防衛力扣掉上限的三分之一，扣不夠就歸零
```

星域的擁有者、行星數與經濟力每回合都會依行星重算，所以 `+0x12 = 2` 那一行
其實是暫時的；**真正留下來的是行星的 `+0x11`**。開局那種「一格三顆全是帝國」
的星域掉一顆之後變成 2／0／1，重算出來的擁有者正好也是 2（無主）——
收據裡九格全部如此。

### 排序排了沒有用

`2703:1908` 花了一趟 qsort 把行星依經濟力遞減排好，**然後兩個迴圈都不看那個陣列**
——都是拿 `ds:CFF8`／`ds:CFFA` 這個原始切片直接走（`a1 fa cf` / `8b 1e f8 cf`）。
排好的指標陣列在 `[bp+0Ch]`，迴圈的指標在 `[bp+08]`，兩個位置不同。
所以「先掉最有錢的那顆」這個顯然的意圖**沒有生效**：實際掉的是切片裡的
第 0 顆（照順序）或最後一顆（未安定度 ≤ 80）。

這是 1994 年那份原始碼帶著的 bug，**照原樣保存，remake 要重現它**
——不是「排序的結果」，是「排序無效」。

### 另一個呼叫端：費沙事件

`2703:1908` 全份只有兩個呼叫者。第二個在線性 `0x124AC`，就在
[`192`](192-phezzan-event.md) 讀到一半的那支 `0x1238D`（費沙事件）裡，
而且正是那一篇列為「還沒讀」的**走清單那一段**：

```
對鄰接清單（0xFF 結尾）裡的每一格：
    那一格的擁有者 != 費沙那一格的擁有者 → 跳過
    那一格 +0x28 ＋ 擁有者 != 0（有駐軍）→ 跳過
    2703:1908(那一格, 1)                  ; 旗標 1 ＝ **整格行星全部叛離**
```

所以費沙事件不只搬走八成經濟力，還會讓**同一個陣營、沒有駐軍的鄰接星域整片脫離**。
（費沙那一段的其餘細節仍照 `192`；這裡只補上清單那一段的語意。）

## 順手解掉的三格

讀 `0374:0556` 那條鏈的時候，三支每回合都跑的常式一起讀了：

- **`2703:1CD7(星域)` ＝ 防衛力回復**。逐顆行星，最多九輪，每輪
  `防衛力 += 上限(+0x16) × +0x18 ÷ 100`，到上限就停。
  **`docs/internals/29` 記成「`+0x18` 未知，值 1–5」的那一格，是回復率（百分比）**
  ——一回合最多補上限的 9×(1–5)%。
- **`2703:1D85(星域)`**：逐顆行星，要塞旗標 `+0x12` 非 0 的把 `+0x45` 歸零、
  `+0x50` 設 `0xFFFF`（要塞砲狀態與瞄準每回合重置，`docs/internals/50`）。
- **`2703:1B48(星域)`**：擁有者是 2 而且 `+0x18`（其他陣營的行星數）非 0 的格子，
  從「還沒變成無主」的行星裡**隨機挑一顆**跑 `2703:1ADB`。也就是說
  **一格一旦變成無主，裡面剩下的行星會一顆一顆跟著跑掉**，直到整格都是無主。

## 三條方法

**讀不到消費者的時候，從輸出那一端反著拉。** `+0x13` bit1 的讀取點
在另一個段，結構欄位掃描看不到；但畫面上那句話一定要有格式字串，
而格式字串的位址一定會以立即值出現在某一條 `mov bx, imm16` 裡。
掃那個立即值一次命中 `056A:073B`，整條 `0374:0556 → 2703:1908` 跟著出來。
（`find_imm.py` 對這個值回 0 處——它只掃線性 `0x10000`–`0x54B30`，
而 `056A` 段落在 `0x056A0`、`0374` 段落在 `0x03740`，整段在過濾器外面。
`tools/scripts/imm_scan_all.py` 從線性 0 掃起、掃全部 1 MB 傾印才看得到——
**零是過濾器的形狀**，同 [`288`](288-fleet-record-remaining-fields.md) 的第一條。）

**「排序了」不等於「用了排序的結果」。** 這一輪差一點把「叛亂先掉最有錢的行星」
寫進規格——比較器確實照經濟力遞減排，但排完的陣列一個位元組都沒被讀。
收據裡九顆全是切片的最後一顆，如果沒有那份收據，錯的規則會一路寫進 remake。

**模態報告會把逐格迴圈切一半。** `rbx292` 只走到第 2 格就停了，而它的
`+0x13` 表看起來完全正常——沒有任何東西會說「這一圈沒跑完」。
