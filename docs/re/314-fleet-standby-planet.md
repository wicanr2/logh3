## 結論

1. 作戰選單第 4 項「待命」不走目的地迴圈：`0DEA:1037` 區塊 C 叫
   `0DEA:1320(艦隊)` 開一張 18×11 的視窗疊在艦隊視窗上——標題「指定待命行星」、
   「<陣營>第Ｎ艦隊  提督」、「星系 <所在星域>」、艦隊所在星域的行星一顆一顆鈕、
   左邊一張 128×128 的單色小圖（那個星域的戰場地圖縮的）、每顆鈕一條引線
   拉到小圖上那顆行星。
2. 點行星鈕換反白；「決定」與**右鍵**都把反白那一顆回給呼叫端：`+0x08 ← 5`、
   `+0x07 ← 行星在星域內的序號`，算「有改」關艦隊視窗（`fcmd-standby-done`、
   `fcmd-standby-rclick`）。「中止」清掉反白再回；沒反白時「決定」與右鍵都回
   `0xFF`——不改記錄、不算有改，艦隊視窗留著（`fcmd-standby-cancel`）。
3. 之後再開艦隊視窗，第 7 列印「待命行星 <行星名>」，名字用擁有者陣營色
   （`0DEA:04C0` 的第二個分支，`fcmd-standby-reopen`）。清單那一列**沒有記號**
   （`+0x08` 仍是 5，星域沒有戰鬥）。
4. 小圖是把 128×102 的圖塊每格縮成一個像素：欄不縮、列每 5 列重用一列來源
   （102 → 128），「有東西」＝ 圖塊不是 0／1／5，另外載入地圖時已經把格線塞進
   圖塊（列 %12＝0、欄 %15＝0 的空格）。最後一列的來源是第 102 列——超出地圖，
   原版讀到緩衝區後面的東西，128 個像素是垃圾。
5. 反白換色之後原版只重畫**變過的格子**（`341B:02E5`），所以被點過的鈕蓋在
   引線上面、沒點過的鈕引線仍壓在字上——差一個像素就是這條規則
   （`fcmd-standby-pick` 的 (288,250)）。

## 二、視窗與文字（`0DEA:14D2`、`1433`、`3982:00B6`）

色 0x97——畫面 x 128–447、y 120–379（外框含），內容原點格 (9,5) ＝ 畫面 (144,140)。

`14D2` 的列印順序（格式字串在 `docs/internals/data/fleet-standby-panel.json`）：

| 順序 | 呼叫 | 內容 |
|---|---|---|
| 1 | `3617:003A(win, ds:2689)` | `\x0c指定待命行星\n` |
| 2 | `3982:00B6(win, 艦隊)` | `%s第`（`ds:60F4[陣營]` 帶色陣營名，與艦隊視窗同一張表）、`3982:0038` 全形編號、`艦隊  %s`（`ds:6428[提督]` 姓名）|
| 3 | `3617:003A(win, ds:2698, 星域記錄)` | `\n      星系      %s\n`——星域記錄開頭就是名字，**不換色**（0x97）|
| 4 | `37A9:000F(win, ds:2248)` | 熱區表上啟用的鈕（§三）|
| 5 | 艦隊 `+0x08 == 5` 且 `+0x07 != 0xFF` | `ds:971C ← 表[+0x07]`，`37A9:02B1(win, 那一筆, 0x27)` 反白 |

`1433`：五筆行星熱區的標籤是 `ds:9720 + 17i` 的緩衝區，先抄 16 個空白
（`ds:2672`），再對 `i < ds:CFFC` 的那幾筆 `sprintf("%-16s", 行星記錄)`（名字在
記錄開頭）並把 `[+4]` 啟用旗標設 1；其餘設 0。`37A9:004C` 畫鈕時
`[+6] != 4 且 [+4] == 0` 的跳過——所以四顆行星只畫四顆鈕，第五列空著。

熱區表 `ds:2248`（12 bytes 一筆，`FF FF` 結尾）：

| 筆 | 格 (x,y) | 寬×高 | 碼 | 標籤 |
|---|---|---|---|---|
| 0–4 | (9, 4+i) | 8×1 | i | `ds:9720+17i`（執行時填）|
| 5 | (15,10) | 2×1 | 5 | 決定 `ds:223E` |
| 6 | (12,10) | 2×1 | 6 | 中止 `ds:2243` |

鈕的顏色 0x87、反白 0x27；鈕格的旗標 `0x08`（本體）＋ 左右端各一格
（`0x10`／`0x20`）——中止的右端格 (14,10) 與決定的左端格是**同一格**，兩個旗標
都設，畫出來左右各兩個像素。

`37A9:02B1` → `0332`：只把**本體那幾格**（不含左右端格）的顏色 byte 換掉，再
`341B:02E5(win)`。`02E5` 只重畫與畫面格表不同的格子——直接塗在畫面上、不經
格表的小圖與引線不會被擦掉，被點過的鈕則蓋到引線上面。收據
`fcmd-standby-pick`：第 1 顆（布連娜）反白之後 (288,250) 從引線的 6 變回字的 7，
其餘三顆鈕上引線照壓。

## 四、小圖（`1727:05C6`、`1588:073C`／`078C`、`2376:0B44`）

`1588:00F6` 載入 `MAP<nn>.CMP`（128 欄 × 102 列）之後先塞格線：

```
073C：列 0, 12, 24, …（< 102）整列：圖塊 0 → 3
078C：每列欄 0, 15, 30, …（< 128）：圖塊 0 → 4；圖塊 3 → 2
```

`1727:05C6(buf, 地圖)`：

```
來源列指標 = 地圖；acc = 0
for 輸出列 py in 0..127:
    for px in 0..127:  bit = ds:3C8C[圖塊] & ds:3CCC[px & 7]   ; 每 8 個湊一個 byte
    acc = (acc + 8) % 10
    if acc == 0（py = 4, 9, 14, …）: 來源列指標退回 128   ; 下一列重用同一列來源
```

即 `來源列 = py − ⌊py / 5⌋`：0,1,2,3,4,4,5,6,7,8,8,…；py 127 → 102，超出
102 列——讀到的是緩衝區後面 128 bytes 的圖塊值（`fcmd-standby` 那一列 57 個
像素亮、71 個暗，與地圖無關）。`ds:3C8C` 那張表：圖塊 0／1／5 → 0，其餘 →
0xFF；`ds:3CCC` 是 `0x80 >> k`。

驗證：`tools/scripts/minimap_probe.py 0 workplace/oracle/fcmd-standby/screen.bin`
對 128×127 的小圖只在引線經過的列報差（那些像素是 §五的線），其餘 0。

## 六、寫入之後：艦隊視窗的「待命行星」（`0DEA:04C0` 第二分支）

`+0x08 == 5` 且 `+0x07 != 0xFF`：`2AF5:0036(艦隊+6, 0)` 選星域的行星表，
行星 ＝ `ds:CFF8 + 0x52 × +0x07`，印「待命行星 」後 `3982:0263(win, 行星+0x11,
0xFFF0, 行星)`——名字用擁有者色（`fcmd-standby-reopen`：布連娜 色 6）。
所以 `+0x07` 在 `+0x08 == 5` 時是**星域內的行星序號**，不是星域
（`docs/internals/33` 已改）。
