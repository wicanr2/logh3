# 226 — 替代清單裡的 `0xFE`：艦種 5 與 6 挑目前少的那個

`docs/re/216` 把 `ds:295C` 的替代順序表倒出來了，但清單裡的 `0xFE`
只寫了「不是艦種，是一個特例標記，`0FF4:1350` 對它有獨立分支，
還沒讀」。那個分支讀完了，整段連同它呼叫的 `0FF4:1404` 一起。

## `0FF4:1350(艦隊, 艦種)`

線性 `0x11290`：

```
清單 = ds:295C + 艦種 × 6
逐個往下：
    == 0FFh → 回 0FFh                       ; 換不到
    == 0FEh →
        0FF4:1404(艦隊, &n5, &n6)
        n5 >= n6 → 先試 6 再試 5
        n5 <  n6 → 先試 5 再試 6
        兩個都 0FF4:0E84 == 0 → 換下一個候選
    其他     → 0FF4:0E84(候選) != 0 就回它
```

## `0FF4:1404(艦隊, &n5, &n6)`

線性 `0x11344`：把 `n5`、`n6` 清 0，走這支艦隊**現有的** `+0x0F` 組
（從第 0 組、也就是旗艦開始），`[2] == 5` 就 `n5++`、`[2] == 6` 就 `n6++`。

所以 `0xFE` 的意思是：**在艦種 5 與 6 之間挑這支艦隊目前組數少的那個**
——一個平衡規則，不是又一個候選艦種。一樣多的時候先試 6。

`0xFE` 只出現在艦種 0–4 的清單裡，位置都在中段（`docs/re/216`），
也就是說「常規艦種都換不到的時候，才去動 5／6 這兩種」。

## remake

`rules.BuildComposition` 的 `substitute` 補上這一格（`balanceFiveSix`），
測試 `TestBuildCompositionBalancesFiveAndSix`：只給 5 與 6 存量時，
樣板要艦種 0 的那幾組會 6、5、6、5 輪流填，兩種的組數差不超過一。

**`ds:295C` 的替代表現在整張都讀得懂了**，`0FF4:11F4` 的艦種挑選
（`docs/re/224`）連同它呼叫的三支（`0E84`／`1350`／`1404`）也全部讀完。

## 一條方法

**清單裡的哨兵值要當成「另一條規則」而不是「另一個值」。** `0xFF` 是
結尾、`0xFE` 是一段平衡邏輯——兩個都在同一張表裡，但一個是資料邊界、
一個是控制流。倒表的時候把哨兵一起倒出來是對的，但別急著把它們歸成
同一類。
