# 207 — `ds:8FD4` 就是未安定度公式的 `Blend`，而且它會在遊戲中變動

`docs/re/206` 掃出 `ds:8FD4[陣營]` 是一個 0–4 的等級，並說「名字還不知道」。
**名字早就有了。**

## 它在 remake 裡已經有名字

`internal/rules/unrest.go`：

```go
// Blend／Rate 以陣營索引（`ds:8FD4`／`ds:8FF8`），都是查 Table 的下標；
// Rate 同時是查 Base 的下標。
Blend, Rate [2]int
```

`docs/spec/006` 也記著量到的值：

| | 新遊戲 796/1 | S2 | S3 |
|---|---|---|---|
| `Blend`（`ds:8FD4`）| 兩邊都是 **2** | 帝國 **1**、同盟 2 | 帝國 **1**、同盟 2 |

而那一節留了一個問題：

> `Blend[帝國]` 在新遊戲是 2、在兩格存檔都是 1——看起來是難度或某個
> 開局選項，**來源還沒找**。

## 來源找到了：它不是開局選項，是會動的

線性 `0x09413` 那一支（`docs/re/206`）：

```
f(delta):
    delta > 0 且 ds:8FD4[陣營] < 4 → ++
    delta < 0 且 ds:8FD4[陣營] > 0 → --
    真的變了 → 090A:0B93(新值) → 090A:0E6D()      ; 顯示層，跳訊息
```

**所以「新遊戲 2、兩格存檔都是 1」不是兩種難度設定，是同一個量在
三百多回合之間掉了一級。** S2 是第 346 回合、S3 是第 380 回合
（`docs/spec/006`），帝國那一格從 2 掉到 1，同盟停在 2。

`090A:0B93(新值)` 拿它去查 `ds:147E`（＝ `Base`，`50 75 100 150 200`）
再做一串 32 位元乘除——所以它在未安定度以外還有別的用途。

## 誰在動它，還沒找到

`0x09413` 在整份 1 MB 傾印裡**一個呼叫者都沒有**：沒有 far call
（`farcall_to.py` 枚舉所有段值，0 處）、也沒有 near call（全傾印掃 `e8`，
0 處）。與費沙事件的觸發點同一個形狀（`docs/re/193`）——呼叫端多半在
沒載入的 overlay，或走執行期填的間接呼叫。

所以「**什麼事件會讓它升降**」仍然未解，而那正是要命名它的最後一步。

## 對 remake 的意義

兩件事接起來了：

- 建艦隊的預算門檻（`2D76:0060` 的 `>= 3`，`docs/re/202`）讀的是
  **同一個量**，remake 已經以 `UnrestParams.Blend` 的名義在算未安定度時用它。
- `Game.OriginalBrain()` 的 `Support.Money` 目前回 `tight = false`，
  等於當成 0——**而量到的開局值是 2**。要接上只要把 `Blend[電腦那一方]`
  傳進去；門檻是 3，所以開局仍然不會觸發，但存檔載進來之後就有差。

**這一輪沒有改那一行**：`Blend` 目前只在載入時算一次未安定度用，
把它接進 AI 之前要先確定 remake 有在維護它（`docs/spec/006` 說它
「不在原版資料檔裡，只能從記憶體量」）。

## 一條方法

**寫「名字未知」之前，先在自己的 `docs/` 與程式裡 grep 那個位址。**
`ds:8FD4` 在 `docs/re/34`、`docs/spec/006` 與 `internal/rules/unrest.go`
都出現過，而 `docs/re/206` 仍然把它記成無名。這是同一個坑的第二次
（第一次是 `+0x28`／`+0x29`，`docs/re/199`）——**兩次都不是難，是沒查**。
