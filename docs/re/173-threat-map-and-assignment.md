# 173 — `ds:D54E` 是敵方下一步的兵力分布

`docs/re/172` 只能說 `ds:D54E`／`ds:D5CE` 是「需求／現有」的形狀。
這一輪把兩個累加點都讀了，名字可以定下來。

## `2E54:1A76()` ＝ 畫敵方的兵力圖

`2E54:000C` 的第二階段，位址 `0x2FFB6`。

```
筆數 = 297B:131C(&清單, 0FFh, 2)          ; 旗標 2 ＝ 敵軍，星域 0FFh ＝ 不限
對清單裡每一支艦隊 f：
    依 f[+0x08]（行動）：
        0 或 1（移動中）→ 格 = 2B99:0302(f[+0x07], f[+0x06], f[+0x01])
        5（不動）        → 格 = f[+0x06]
        其餘            → 跳過
    ds:D54E[格] += f[+0x0F]               ; 編制槽數
```

**`ds:D54E[星域]` ＝ 敵方艦隊「下一步會在這一格」的編制槽總數。**
移動中的艦隊算在**下一格**，不是現在那一格——所以這是一張**預測**的
威脅圖，AI 是照敵人下一步的落點布防，不是照現況。

`2B99:0302(目的地, 起點, 陣營)` 回路徑上的下一格（推論自這個用法；
與 `2B99:028F`「走幾步」、`2B99:0450`、`2B99:03D9`「取鄰居」同一組）。

## `ds:D5CE` ＝ 這一格有幾支決定留守

累加點在 `2E54:005D`（逐艦隊決定，`docs/re/79`）裡，`0x2E6AD`：

```
若 星域[+0x13] bit2 且 2E54:16F5(艦隊) != 0：
    艦隊[+0x79] = 3
    ds:D5CE[艦隊[+0x06]]++
    ds:D60E++
```

同一支常式的另一條路（`0x2E650`）寫 `+0x08 = 3`（從首都出擊）、
`+0x07 = +0x06`；再另一條寫 `+0x79 = 0` 並且也 `ds:D60E++`。
所以 **`ds:D60E` ＝ 這回合已經決定了幾支**，`ds:D5CE` ＝ 決定碼 3 的那些。

順帶把星域 `+0x13` **bit2** 釘住了：它是 `2E54:16F5`（`docs/re/162`／
`docs/re/163` 那一支）的入口條件，而 `docs/internals/34` 早就量到
**進入戰鬥時 `+0x13` 從 8 變成 12**——8 是 bit3、12 是 bit3｜bit2。
兩個獨立的觀察指向同一件事：**bit2 ＝ 這一格有戰鬥**（強推論，
還沒抓到寫入點）。所以 `ds:D5CE` 數的是「在有戰鬥的格子裡決定留下來」
的艦隊。

## 兩者相減

`docs/re/172` 的算式因此讀作：

```
ds:D58E[我方星域] = (敵方下一步的槽數 − 我方已決定留守的支數) ÷ 4
                  + (是前線 ? 1 : 0)
```

兩個量的**單位不同**（一個是槽數、一個是支數），程式就是直接相減。
`÷ 4` 大致把槽數換算回支數。這不是筆誤，是原版的算法。

## `2E54:0842()` ＝ 挑最缺的那一格

```
最佳 = 0FFh；最佳值 = 0FFh
對 i = 0 … 31：
    若 ds:D58E[i] == 0：跳過
    v = 2E54:088F(i)                 ; D5AE × 100 ÷ D58E；夠了回 0FFh
    若 v < 最佳值：最佳 = i；最佳值 = v
回 最佳
```

回**滿足率最低**的那一格（`0xFF` ＝ 沒有）。「夠了」回 `0xFF` 正好是
最大值，自然被排除。`2E54:07D8` 每指派一支就 `ds:D5AE[格]++`，
滿足率上升，下一輪自然換一格——**貪心的輪流補**。

## `2E54:1B17(艦隊, 行動, 星域)` ＝ 指派

```
若 艦隊[+0x06] == 星域：            ; 已經在那裡了
    若 艦隊[+0x08] != 5：
        艦隊[+0x08] = 5             ; 不動
        艦隊[+0x07] = 0FFh
否則：
    艦隊[+0x08] = 行動              ; 2E54:07D8 傳 0 ＝ 移動
    艦隊[+0x07] = 星域
```
