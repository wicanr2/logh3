# 180 — 提督 `+0x09` 的低七位就是他帶的艦隊槽

`docs/re/177` 把階段一（`2E54:0513`）讀到一半就停了。這一輪讀完，
順帶解掉一個從 `docs/internals/08` 就掛著的欄位。

## `2E54:0513(還缺幾支)`

```
若 首都星域[+0x12] != ds:8F1D：不做
筆數 = 28E0:0103(&清單, 首都, 25h, 0)
若 筆數 == 0：結束
qsort(清單, 筆數, 1, 2E54:063C)              ; 比較兩個提督記錄（ds:B77C，一筆 28）
對 i = 0 … 筆數−1：
    若 ds:8F49[ds:8F1D] >= 16：結束           ; 上限
    若 還缺幾支 == 0：結束
    若 2D76:0611(清單[i]) == 0：跳過
    提督 = ds:B77C + 清單[i] × 28
    基底 = (ds:8F1D == 0) ? 0 : 16
    艦隊 = ds:C074 + (基底 + 提督[+0x09]) × 122
    艦隊[+0x08] = 5                          ; 不動
    艦隊[+0x07] = 0FFh
    ds:D60E++
    還缺幾支--
```

清單裡的元素是**提督編號**（`2E54:063C` 拿它去查 `ds:B77C`，
一筆 28 bytes ＝ 提督表）。

## 提督 `+0x09`

`docs/internals/08` 只記到「載入時被夾成 127」與「最高位是一個旗標」
（`docs/re/43` 的不穩條件）。這裡看到了低七位：

```
艦隊 = ds:C074 + (陣營基底 + 提督[+0x09]) × 122
```

**提督 `+0x09` 的低七位 ＝ 這個提督帶的艦隊槽**（陣營內的編號，
帝國 0–15、同盟 16–31 由基底補上）。最高位是另一件事，
而且 `2D76:0611` 進門就把它 `AND 7Fh` 清掉。

## `2D76:0611(提督編號)`

```
提督 = ds:B77C + 編號 × 28
若 07F9:023B(提督) == 0：回 0
提督[+0x09] &= 7Fh
07F9:03AC(提督)
…（後半未讀）
```

形狀是**新編一支艦隊**（強推論）：它在 `2D76:*`（建艦隊那一段）裡，
回非 0 之後呼叫端立刻拿 `提督[+0x09]` 當艦隊槽去寫欄位——
也就是說這一支跑完之後那個提督才有艦隊。`ds:8F49[陣營] >= 16` 這道
上限與艦隊表每邊 16 個槽一致（`docs/internals/33`）也支持這個讀法。

所以階段一「守首都還缺 n 支」的補法是**在首都新編 n 支並留在原地**
（`+0x08 = 5`、`+0x07 = 0xFF`），不是把別處的艦隊調回來。

## 還沒讀

`07F9:023B`／`07F9:03AC`（編艦隊的兩半）、`2D76:0611` 的後半、
`28E0:0103` 的 `0x25` 是什麼、`2E54:063C` 比的是提督的哪一項。
