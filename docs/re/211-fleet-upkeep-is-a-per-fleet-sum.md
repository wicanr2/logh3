# 211 — 艦隊維持費是逐艦隊加總，而 remake 建出來的艦隊是空的

建艦隊的閘門靠「維持費 × 20 追上總稅收」收手（`docs/re/202`、
`docs/re/210`）。remake 沒有算維持費，所以那個迴圈會建到上限。
這一輪追維持費是怎麼算的。

## 誰算它

`ds:8F72` 的 32 位元寫入只有兩處，其中一處在線性 `0x09F41`：

```
push 陣營
call far 297B:10DE
mov si,陣營 / shl si,2
mov [si+8F74],ax / mov [si+8F72],bx      ; 艦隊維持費 = 回傳值
```

`297B:10DE(陣營)`（線性 `0x2A88E`）：

```
A = 0；B = 0
對艦隊表 32 筆（ds:C074，一筆 122）：
    +0x04 == 0FFh   → 跳過                  ; 沒在用
    +0x01 != 陣營   → 跳過
    A += 297B:116C(艦隊)                    ; 32 位元
    B += 297B:12FB(艦隊)                    ; 32 位元
ds:8F82[陣營 × 4] = B
回 A
```

所以：

- **`ds:8F72`（艦隊維持費）＝ Σ `297B:116C(艦隊)`**
- **`ds:8F82` ＝ Σ `297B:12FB(艦隊)`** ——`docs/internals/27` 把它記成
  「還沒認出來的第三項」，它與維持費**同一個形狀**：也是逐艦隊加總。

兩個都只算「在用、而且是自己陣營」的艦隊。

## 逐艦隊那一支在走編制

`297B:116C(艦隊)`（線性 `0x2A91C`）走的是艦隊記錄的編制槽：

```
指標 = 艦隊 + 0x10                          ; 編制槽
對 i = 0 .. 艦隊[+0x0F] − 1：               ; **現有**組數
    艦艇索引 = 槽[i] 的前兩個 byte
    艦艇記錄 = ds:CFB4 遠指標 + 艦艇索引 × 78
    …（每艘的那一項還沒讀完）
```

**per-fleet 的量來自它帶的艦艇**，不是艦隊本身的常數。收據
`turn260mem` 上同盟建的三支編制是 6／4／4 組、維持費合計 426
（`docs/re/209`），平均一組約 30——但那取決於各組的艦種與艘數，
一個資料點推不出算式。

## 對 remake 的意義：缺的不是算式

就算把 `297B:116C` 讀完，remake 現在也算不出非 0 的維持費——
**`ai.NewFleet` 只帶提督、星域、類別鍵與副官，沒有編制**。
原版建出來的三支有 6／4／4 組艦艇，那些艦艇是從首都的艦艇存量
（星域 `+0x30` 起）分出去的；remake 的 AI 建艦隊完全沒碰那一段。

所以「換掉 `Original` 會建到十六支」的根因是兩層：

1. `ai.NewFleet` 沒有編制 → 維持費恆為 0 → 閘門的錢那一項永遠通過；
2. 就算補上維持費的算式，沒有編制也還是 0。

**下一步是「AI 建的艦隊要從首都存量分艦艇」**（`07F9:02CB` 檢查存量的
那一段之後應該就有分配），不是先把 `297B:116C` 讀完。順序反了會做出
一個永遠算 0 的函式。

## 一條方法

**追一個「值永遠是 0」的欄位時，先問「輸入有沒有」再問「算式對不對」。**
這一輪本來要去讀 `297B:116C` 的每艘成本；讀到它走的是艦隊的編制槽才
發現 remake 那邊編制是空的——算式讀完也用不上。
**缺的是上游，不是這一層。**
