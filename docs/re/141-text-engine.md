# 141 — 印字進視窗：跳脫碼與內容緩衝區

`3617:003A` 是全遊戲的「印字進視窗」，**611 個呼叫端**。補給面板、行星
情報窗、結果報告全部卡在它後面，所以它是目前最大的一塊。

## 三層

```
3617:003A(視窗, 格式字串, 參數…)
    3617:0059：ds:F120/F122 = 視窗、ds:F124 = 0
               3ACA:0079(格式字串, 參數…, 輸出回呼 3617:0099)
    3617:0099(字元)：一個位元組一個位元組寫進**視窗自己的內容緩衝區**
```

**它不畫像素**。真正上畫面是另一趟：`34CB:01A4` 把內容格搬進畫面格表
`ds:D81E`，`2376:040E` → `2376:0E0D` 再畫（`docs/re/138`）。所以排版與
繪製是分開的兩件事。

內容緩衝區一格 4 bytes：字碼 word ＋ 顏色 byte ＋ 旗標 byte。

## 視窗的文字欄位

| 位移 | 內容 |
|---|---|
| `[+01]` | 顏色（低四位字色、高四位底色）|
| `[+02]` | 旗標（裝飾位元，見 `docs/internals/47`）|
| `[+0B]`／`[+0C]` | 內容格寬／格高 |
| `[+0E]`／`[+10]` | 內容緩衝區 |
| `[+1A]` | bit7 半形轉全形、bit6 可捲動（bit0 是「結構自己配的」，與文字無關）|
| `[+1B]` | 上一個位元組是雙位元組字的前半 |
| `[+1C]`／`[+1D]` | 游標欄／列 |
| `[+1E]`／`[+20]` | 游標指標 ＝ `[+0E] ＋ 列 × [+0B] × 4 ＋ 欄 × 4`（`3617:04CE`）|

## 一個可見位元組（`3617:02A5`）

```
若 [+1C] >= [+0B]：[+1B] = 0；換行
若 [+1B] != 0：                       ; 這是後半
    內容[游標] |= 字元；[+1B] = 0；[+1C]++；[+1E] += 4
否則：
    內容[游標][+2] = [+1]（顏色）
    內容[游標][+3] = [+2]（旗標）
    若 [+1A] & 0x80 且 0x20 <= 字元 <= 0x7E：
        內容[游標] = 3B6B:0002(字元)   ; 半形轉全形，一個字佔一格
        [+1C]++；[+1E] += 4
    否則：
        內容[游標] = 字元 << 8；[+1B] = 1   ; 等後半
```

所以**沒開轉全形時，任何位元組都是雙位元組序列的前半**——ASCII 就變成
「兩個半形塞一格」，正好對上繪製那一端 `2376:0E0D` 的
「高位元組 < 0x80 ⇒ 兩個半形」。

## 換行（`3617:03BE`）

`[+1C] = 0`、`[+1D]++`；還在範圍內就直接算指標。超出最後一列時看
`[+1A] & 0x40`：設了就把內容往上搬一列、最後一列清空；沒設就停在
最後一列。

## 跳脫碼

碼表在 `ds:6BDC`（12 筆），參數狀態表在 `ds:6BCC`（8 筆）。參數是
**十進位**，由 `3617:038A` 逐位收：`[` 跳過、數字累加、**其他任何字元
結束並提交，而且那個字元被吃掉不會印出來**。

| 碼 | 參數 | 作用 |
|---|---|---|
| `0x01` | `[欄,列` | 設游標（狀態 1 → `[+1C]`，狀態 4 → `[+1D]`）|
| `0x02` | `[Δ欄,Δ列` | 相對移動（狀態 2 → 5）|
| `0x03` | `[色` | `[+1] = 值` |
| `0x06` | — | `[+1A] |= 0x80`（半形轉全形 開）|
| `0x07` | — | `[+1A] &= 0x7F`（關）|
| `0x08` | `[旗標` | `[+2] = 值`（裝飾位元）|
| `0x0A` | — | 換行 |
| `0x0C` | — | `[+1B]`／`[+1C]`／`[+1D]` 歸零、游標回起點、`35AA:0068` 清空 |
| `04`／`05`／`09`／`0B` | — | 表上指到 default，什麼都不做 |

所以 `ds:2DF6` 那句 `要%s\x03[%d,%s\x03[%d,%s星系嗎？` 是「印一段、換個
顏色、再印一段」；`ds:3F29` 開頭的 `\x0c` 是「先把面板清乾淨」。

## 進 remake

`ui.TextBuffer`（緩衝區 ＋ 跳脫碼狀態機）與 `ui.DrawTextBuffer`
（一格的順序：底色 → 立體邊 → 字 → 裝飾）。

**驗收**：把訊息框整個改走這條通用路徑重畫一次，與收據 `s3msg` 的
22 × 6 格逐位元組相同（`TestTextBufferRedrawsMessageBox`）。原本那三支
專用的繪製函式因此拿掉——同一件事只留一套機制。

**還沒抄的**：`3B6B:0002` 那張半形轉全形的對照表。沒有它，`0x06` 那個
模式畫出來會與原版不同；目前 remake 走到那條路會先原樣塞進高位元組，
**用到的地方要先量收據**。

## 可重用的規則

- **一件事只留一套機制。** 訊息框原本有三支專用繪製函式，各自對過收據
  都是 0 差異；但通用路徑一做出來，那三支就是第二套會各自漂移的實作。
  通用版一次就對上同一份收據，於是專用版整批刪掉。
- **驗收新機制要拿舊機制驗過的同一份收據。** 這套引擎唯一有同狀態收據
  的視窗就是訊息框；先讓它重現那 42,240 個像素，再談別的視窗。
