# 227 — AI 回合的第二步 `2D76:0732`：逐支艦隊整補

`docs/internals/54` 把 AI 的一回合寫成

```
2D10:0319(1) → 2D76:0002(建艦隊) → 2D76:0732 → 2E54:000C → 2E54:0344 → 2D10:0038
```

中間那一支從來沒讀過，`CONTEXT.md` 一直把它掛在「還沒讀」。這一輪讀了
外層與被它呼叫的兩支的骨架。

## `2D76:0732`：挑要整補的艦隊

線性 `0x2DE92`，沒有參數，掃 32 個艦隊槽：

```
對 i = 0..31：
    艦隊 = ds:C074 + i × 122
    艦隊[+0x04] == 0FFh              → 跳過      ; 空槽
    艦隊[+0x01] != ds:8F1D           → 跳過      ; 不是自己的
    星域[+0x12] != 艦隊[+0x01]       → 跳過      ; 不在自己的星域
    星域[+0x13] & 4 != 0             → 跳過      ; 那一格有戰鬥
    2D76:07BA(艦隊)
    2D76:0A44(艦隊)
```

星域取的是艦隊 `+0x06` 那一格。**所以整補只發生在自己的、沒有交戰的
星域**，與「留在敵境的艦隊補不了」這個直覺一致。

## `2D76:07BA(艦隊)`：把缺編的組併掉

線性 `0x2DF1A`。三個迴圈，中間那個以艦種為單位：

```
一、掃第 1 組起（旗艦不算）：
       現有(艦艇[+0x08]) × 4 < 滿編(艦艇[+0x0A]) × 3   ; 不到七成五
       → 該艦種的「現有總和」+= 現有；該艦種的「缺編組數」++

二、對艦種 k = 0..6，缺編組數 != 0 才做：
       滿編 = ds:4E3A[陣營][k] 的 word 0
       需要 = 滿編 − (現有總和 mod 滿編)
       星域待命部隊[+0x30 + 陣營×28 + k×4]（32 位元）>= 需要
           → 現有總和 += 需要
       n = 現有總和 ÷ 滿編
       n == 0 → 這個艦種不動
       否則掃第 1 組起，艦種 == k 而且不到七成五的：
           2AD2:018C(星域, 艦艇索引)
           組[2] = 0FFh；組[3] = 已拆數；已拆數++

三、已拆數 != 0：
       qsort(艦隊+14h, 艦隊[+0x0F] − 1, 4, 2D76:0CAF)
       艦隊[+0x0F] −= 已拆數
       297B:03EB(艦隊[+0x03], 0)
```

形狀是「**把同艦種的零星殘部湊成整數組**」：先算現有總和差多少湊得滿
一組，星域的待命部隊夠就補進去，然後把那幾組拆掉重排，組數收斂到
`總和 ÷ 滿編`。

## `2D76:0A44(艦隊)`：把缺的組補回應有數

線性 `0x2E1A4`。

```
艦隊[+0x09] == 0FFh → 回          ; 沒有類別鍵
艦隊[+0x08] == 4    → 回          ; 這一趟跳過它
樣板 = ds:2BC6 + 艦隊[+0x09] × 20 + 2
旗艦艦種 = 艦艇池[艦隊+0x10 那一筆][+0x04]
i = 1
while i < 艦隊[+0x0E]:            ; 應有組數
    …（照樣板往下補，還沒逐行讀）
```

**`艦隊[+0x09]` 就是建艦隊時抽的類別鍵**（`docs/re/204`），這裡拿它
再查同一張樣板；旗艦艦種同樣是從第 0 組的艦艇記錄 `+0x04` 讀的，
與 `0FF4:11F4` 那條一致（`docs/re/224`）。

## 還沒讀

- `2AD2:018C(星域, 艦艇索引)`：拆一組的時候做什麼（艘數還不還給星域）。
- `2D76:0CAF`：`2D76:07BA` 用的比較器（**不是** `0FF4:0FF2`）。
- `297B:03EB(艦隊編號, 0)`：拆完之後那一支。
- `2D76:0A44` 的迴圈本體。

四支都在「整補」這一層，所以 remake **這一輪不實作**——半條鏈接上去
會讓艦隊的艘數往一個沒驗過的方向漂。

## 對 remake 的意義

在此之前 `2D76:0732` 是個完全的黑箱，`docs/spec/029` 只能說「AI 回合
中間有一步沒讀」。現在知道它是**整補**、只在自己沒交戰的星域發生、
而且會動艦隊的組數與星域的待命部隊——這三件事決定了它該擺在
remake 的哪一層（`rules` 的艦隊編制，不是 `ai` 的決策）。

## 一條方法

**先讀出「它會改什麼」再決定要不要往下讀。** 這一支的外層 0x81 個
位元組就講完了「哪些艦隊會被碰」，中間那支的三個迴圈講完了「改的是
組數與待命部隊」。到這裡已經足夠回答「要不要現在實作」——答案是不要，
而那個答案不需要把四支被呼叫的都讀完。
