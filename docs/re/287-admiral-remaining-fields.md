## 掃描方法與正對照

Borland 把 `unsigned char` 欄位讀進 int 運算式時固定編成
「`8A /r disp8` ＋ 清高位元組」。拿這個形狀掃整份 1 MB 傾印
（`tools/scripts/loadbyte.py`，本輪新增），基底限 `si`／`di`／`bx`／`bp`：

| 提督位移 | 十進位 | 命中（含 `[bp+…]`）| 其中不是 `[bp+…]` 的 |
|---|---|---:|---:|
| `+0x14` | `+20` | 25 | 16 |
| `+0x15` | `+21` | 4 | 4 |
| `+0x16` | `+22` | 13 | 2 |
| `+0x17` | `+23` 運用 | 11 | 11 |
| `+0x18` | **`+24`** | 8 | **0** |

`+0x17`（運用）是正對照：它有十一處，分布在畫面、排序、AI 與能力合成裡，
與 `docs/internals/08` 已知的用法對得起來。`[bp+…]` 那些是堆疊區域變數，
不是提督記錄——例如 `07F9` 段那張艦隊組成畫面把十一個艦隊能力抄到
`[bp+0x3F]`–`[bp+0x49]` 再逐格印（見下）。

另外用 `field_xref.py` 把 **所有** 存取形式（`cmp`／`test`／`inc`／字組讀寫）
也掃了一遍：`+0x18` 在程式碼範圍內有 30 處帶段前綴的存取，逐處看下來
**全部屬於別的結構**——`cmp byte es:[bx+18h],0` 那幾處與同一段裡的
`+0x16`／`+0x17` 一起出現，而 `+0x17` 被寫成 2／1／0，那是艦艇記錄的
「顯示層級 3→2→1→0」與「停在第 3 級的剩餘輪數」（`docs/internals/38`）；
`8B 47 18` 那批是遠指標搬運。提督記錄的能力值域是 80–140，
拿去跟 0 比較沒有意義。

四份不同階段的傾印（戰場、回合 260、月底、主畫面）跑同一支掃描，
**五個位移的命中數逐格相同**——程式影像沒有隨階段換頁，所以
「沒有消費者」不是取樣取到沒載入的那一頁。

| 消費者 | 位址 | 算式 |
|---|---|---|
| 稅率重算 | `090A:0B93`（進入點線性 `0x09C33`，讀 `+20` 在 `0x09D65`／`0x09DBE`／`0x09DF2`）| 見下 |
| 治安分段 | `090A:124E`（進入點線性 `0x0A2EE`，讀 `+20` 在 `0x0A45B`）| `段 = 未安定度 × 100 ÷ +20 ÷ 50`，夾 0–3；不是自己的星域一律 4（`docs/re/63`，remake 的 `SecurityMapColour`）|
| AI 建艦隊類別 0 的評分 | `2D76:049F` | `分數 = 基底 × 統率力 ÷ 100 × (+20)`（`docs/re/190`）|
| **戰鬥層的 `ds:D61A`** | `307D:03B5`（進入點線性 `0x30B85`，讀 `+20` 在 `0x30C11`）| 見下，本輪新解 |

稅率那一支（remake 的 `rules.TaxRatePerMille` 已經實作，13/13 對過）：

```
v = 民心項 × (+20) ÷ 100            ; 帝國取民心、同盟取 200 − 民心
若 v > 150： 稅率 = 稅率 × 30 ÷ (+20)
否則 v > 100：稅率 = 稅率 × 50 ÷ (+20)
否則 v >  50：稅率 = 稅率 × 75 ÷ (+20)
```

讀的是**內政專任參謀**（`ds:8F4F[陣營]`）那一筆；治安分段讀的是
**情報專任參謀**（`ds:8F4D[陣營]`）那一筆。同一格、兩個職位、
兩個都是「把民心／未安定度縮放成分段」的除數。

### 新解：`307D:03B5` 把 `+20` 當成戰鬥中的完整度門檻

`307D:001B` 是戰場上逐支艦隊跑的那一層。它在挑行動之前先算一次：

```
307D:03B5(艦隊記錄):
    現有 = 滿編 = 0
    for i in 0 .. 艦隊[+0x0F]-1:                 ; 逐組編制
        艦艇 = ds:CFB4 + 艦隊[+0x10 + i×4] × 78
        滿編 += 艦艇[+0x0A]；現有 += 艦艇[+0x08]
    完整度 = 現有 × 100 ÷ 滿編                    ; 百分比
    ds:D61A = (艦隊[+0x44] × 50 ÷ 100 > 完整度) ? 1 : 0
```

`艦隊[+0x44]` 就是提督與副官逐項取大之後的 `+20`（下一節）。所以門檻是
**`+20` 的一半**（值域 80–140 → 40–70%）：艦隊打到剩下不到那個百分比，
`ds:D61A` 就設起來。

呼叫端 `307D:001B`（進入點線性 `0x307EB`）緊接著**用三分之一的機率把它清掉**：

```
call 307D:03B5
若 ds:D61A != 0 且 3CD5:000C() mod 3 == 2：ds:D61A = 0
```

`ds:D61A` 全份只有兩個讀取點，另一個在 `307D:0A53`（線性 `0x31267`）：

```
307D:0A53(…, 艦隊記錄):
    提督 = ds:B77C + 艦隊[+0x04] × 28
    權重 = (艦隊[+0x09] == 0xFF) ? 128 : ds:603A[艦隊[+0x09]]   ; 類別鍵 → 基礎權重
    若 ds:D61A != 0： 權重 ×= 2                                  ; ★
    權重 = 權重 × 提督[+0x15] ÷ 100                              ; ★ +21
    for i in 0..7： (ds:D6BC 起每 6 bytes 一格)[i] = 307D:0B41(ds:605A[i], 權重, …) × ds:6062[i]
```

`ds:603A` 是 16 個 word（類別鍵 → 權重）：
`100 100 120 140 140 40 120 120 120 100 120 140 60 60 300 300`。
八個選項那一段（`ds:605A`／`ds:6062`／`307D:0B41`／`ds:D6BC`）**還沒讀**，
所以只能說到「`+20` 決定何時進入這個模式、`+21` 縮放權重」，
不能說那八個是什麼。

## `+22`（`+0x16`）：只有一條路，通到「挑不挑得中最好的目標」

`+0x16` 在提督記錄上唯一的非 `[bp+…]` 讀取點就是能力合成
（`297B:05B2`，進入點線性 `0x29D62`，讀 `+0x16` 在 `0x29F5D`–`0x29F7A`）。反組譯把
`docs/re/70` 從收據反推的那張對照表變成直讀的：

```
線性 29F2B  提督[+0x14] 與 副官[+0x14] 取大 → 艦隊[+0x44]
線性 29F5D  提督[+0x16] 與 副官[+0x16] 取大 → 艦隊[+0x45]
線性 29F85  提督[+0x17] 與 副官[+0x17] 取大 → 艦隊[+0x46]
線性 29FB6  提督[+0x0E] 與 副官[+0x0E] 取大 → 艦隊[+0x47]
```

而艦隊 `+0x45` 在整份傾印裡**只有一個讀取點**：`1F6F:024C`（進入點線性 `0x1F93C`，
讀取點 `0x1F96C`）。它的上一層 `1F6F:005D`（線性 `0x1F74D`）是戰場上一個分隊
挑攻擊目標：

```
1F6F:005D(本方艦艇記錄):
    艦艇[+0x2E] = 0xFF
    n = 1F6F:02D2(艦艇, …)               ; 收候選，索引倒進 ds:A49A，回筆數
    若 n == 0：結束
    for i in 0..n-1： 1F6F:061F(艦艇, 候選[i])    ; 逐個算分
    qsort(ds:A49A, n, 2, 1F6F:01D1)      ; 比較器：A 的 +0x46 > B 的 +0x46 → −1（分數大的排前面）
    k = 1F6F:024C(艦艇, ds:A49A, n)      ; ★ 0／1／2
    艦艇[+0x2C] = ds:A49A[k]             ; 選中的目標
```

`1F6F:024C` 就是吃 `+0x45` 的那一支：

```
1F6F:024C(艦艇, 清單, n):
    艦隊 = ds:C074 + 艦艇[+0x01] × 122        ; +0x01 ＝ 這個分隊屬於哪一支艦隊
    r = 3CD5:000C() × 艦隊[+0x45] ÷ 100        ; 32 位元
    若 r <  8192 且 n >= 3：回 2
    若 r < 16384 且 n >= 2：回 1
    回 0
```

亂數是 0–32767，所以 `+0x45` 愈大、`r` 愈大、愈不容易落進兩道門檻，
**愈常拿到排序後的第 0 筆（分數最高的那個目標）**：

| 艦隊 `+0x45` | 取最佳 | 取第二 | 取第三 |
|---:|---:|---:|---:|
| 80 | 37.5% | 31.3% | 31.3% |
| 100 | 50.0% | 25.0% | 25.0% |
| 140 | 64.3% | 17.9% | 17.9% |

（候選不足時上限跟著降。）所以 `+22` 是**選攻擊目標時挑中最佳選項的機率**
——功能講得完，名字仍然沒有。

順帶留一個待查：`docs/internals/38` 記艦艇 `+0x46`／`+0x48`「整場都是 `0xFFFF`、
戰鬥期間沒有任何寫入」（`docs/re/96`）。但這條路上的比較器就是拿 `+0x46`
排序的，而 `mov es:[bx+46h],ax` 全份有兩處（線性 `0x1FFDA` 在同一個 `1F6F`
段、`0x2B0C0`），`1F6F:061F` 本身也把 `+0x48`／`+0x4A`／`+0x4C` 清成 0。
`docs/re/96` 的觀察窗大概沒有涵蓋挑目標那條路——**沒有重驗，先記著**。

## `+24`（`+0x18`）：沒有消費者，而且值域根本不是能力值

兩件事一起指向「它不是第十四個能力」：

1. **沒有任何讀取指令**（上面的掃描，四份傾印一致）。它也**不被抄進艦隊
   記錄**（`docs/internals/33` 那十一格裡沒有它），四個檔案版本的值
   **完全相同**（存檔不會改它）。
2. **值域不對**。`docs/internals/08` 寫「`+11…+24` 實測值域 0x50–0x8C
   （80–140）」——那句對 `+11…+23` 成立，對 `+24` 不成立：

| 位移 | 最小 | 最大 | 相異值 | 跨版本一致 |
|---|---:|---:|---:|---|
| `+20` | 68 | 134 | 37 | 否 |
| `+21` | 80 | 144 | 42 | 是 |
| `+22` | 72 | 138 | 42 | 是 |
| **`+24`** | **5** | **100** | **20** | 是 |

`+24` 的值幾乎都是 5 或 10 的倍數（最常見的是 40、90、10、80、20），
82 筆只有 20 個相異值。形狀像百分比或機率檔位，不像那十三格連續的能力值。
**但這是分布，不是證據**——沒有消費者就沒有語意，這裡不給它名字。

最省力的下一步不是再掃一次：**原版說明書附的提督資料表**應該把十四格
都印出來（防拷問答就是要玩家去查那張表，`ds:8D10` 的字串寫著
「請查閱提督資料表／輸入照片上%s提督／%s能力數值：」）。
`docs/re/65` 已經記過畫面欄名與防拷問答對不上，推測紙本欄名與畫面不同。

**「還剩什麼」的清單會比 repo 本身老。** 這一條未完成項列著五格未知，
其中兩格的答案分別躺在 `docs/re/77` 與 `docs/re/204` 的正文裡，

**負面結論要挑一個有正對照的形狀。** 「掃不到 `+0x18`」本身不能下結論；

先讓掃描在已知答案上開口，再去問未知的。
