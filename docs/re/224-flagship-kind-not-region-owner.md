# 224 — 樣板給 0 時看的是**旗艦的艦種**，不是星域擁有者

`docs/re/216` 把 `0FF4:11F4` 的艦種挑選寫成

```
樣板 ds:2BC6 給 a
星域擁有者 == 1 且 a == 0 → a = 1
```

那個 `+0x12` 讀的是**艦隊記錄**不是星域記錄。艦隊的 `+0x12` 是
**第 0 組（旗艦）的 `[2]`**，也就是旗艦的艦種。

## 收據直接分得開

`turn260mem` 三支艦隊都在星域 31（巴拉特，擁有者 ＝ 同盟 1），
所以「星域擁有者」對三支是同一個值；旗艦艦種（提督 `+0x08` 低四位）
不是：

| 艦隊 | 類別鍵 | 旗艦艦種 | 樣板 `[2]` | 艦艇 `+0x04` |
|---|---|---|---|---|
| 提督 52 | `04` | **0** | 0 0 0 6 | **0 0 0 6** |
| 提督 55 | `0B` | **1** | 0 0 0 0 | **1 1 1 1** |
| 提督 47 | `0C` | **0** | 0 3 3 5 6 0 | **0 3 3 5 6 0** |

提督 52 那一支把「擁有者 1 就把 0 換成 1」直接否掉了：同一格、同一個
擁有者，樣板給 0，原版填的就是 0。

## 反組譯

線性 `0x11134` 起（＝ `0FF4:11F4`）：

```
0FF4:11F4(艦隊, 類別鍵):
    ds:9872 ← 艦隊[+0x06] 那一格星域的遠指標
    樣板 = ds:2BC6 + 類別鍵 × 20 + 2        ; 跳過第 0 組
    艦隊[+0x0F] = 1                          ; 旗艦已經有一組
    旗艦艦種 = 艦隊[+0x12]                   ; ＝ 第 0 組的 [2]
    i = 1
    while i < 艦隊[+0x0E]:
        a = （旗艦艦種 == 1 且 樣板[0] == 0）? 1 : 樣板[0]
        v = 0FF4:0E84(a)                     ; 那一格這個艦種編得出幾組
        若 (a == 旗艦艦種 且 v < 4) 或 v == 0：
            a = 0FF4:1350(艦隊, a)           ; 照 ds:295C 換
            a == 0FFh → 這一組跳過
        組[2] = a；組[3] = 樣板[1]
        組[0..1] = 2AD2:0029(艦隊, a, 0)
        艦隊[+0x0F]++；i++；樣板 += 2
```

`docs/re/216` 留的「`a == 星域擁有者 且 v < 4` 那一段」也在這裡：
比的同樣是**旗艦艦種**，意思是「跟旗艦同艦種的那幾組，那一格至少要
編得出四組才用它，不然換一個」。

## remake

`rules.BuildComposition` 兩處改掉：條件換成 `AdmiralKind`、補上
`v < 4` 那一條；旗艦那一組的 `[3]` 改成取樣板第 0 組的（十六個鍵
第 0 組都是 `(0, 20)`，所以收據分不出它是查表還是寫死）。

改完之後**三支的維持費與收據逐支相同**：

| 提督 | 運用 `+0x47` | 維持費 `+0x0A` |
|---|---|---|
| 52 | 128 | **85** |
| 55 | 120 | **124** |
| 47 | 102 | **217** |

合計 426 ＝ `ds:8F72[同盟]`。釘在 `TestFirstAITurnMatchesReceipt`。

組的順序也對上了：`0FF4:0FF2` 的比較器是「`[2]` 升冪、相同再比 `[3]`
升冪」（`docs/re/225`），補上之後三支的編制與收據**逐組相同**。

## 一條方法

**同一個位移在不同記錄裡是不同的欄位。** `+0x12` 在星域記錄是擁有者、
在艦隊記錄是第 0 組的 `[2]`；`les bx,[...]` 之後 `bx` 指的是誰，決定
那一行讀的是什麼。讀的時候要把「這個 `bx` 是哪一種記錄」寫下來，
不要憑位移的既有印象填語意。
