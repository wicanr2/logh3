# 273 — 每回合的 `2B5F:02B2`：星域的飛彈／艦載機存量回充

日期：2026-09-11
執行器：dosgolem-logh3 `6841e68`（未提交檔案 0 個）
收據：`re273stock`（監看星域 0 的 `+0x68`，`-regs-at 2B5F:02B2`）、
`re273clamp`（回充前後各倒一份 32 格星域表）、
`re273rate`（先把存量 poke 成 0 與 65536，隔離出每回合補多少）
反組譯：`workplace/ida/seg2B5Fr.com`（從 1 MB 傾印切段給 IDA）
狀態：**confirmed**

`docs/spec/035` 與 `docs/spec/038` 都把 `2B5F:02B2` 掛著「每回合都跑，內容
未讀」。讀出來是一件與月底無關的事：**每個回合把每個星域的飛彈與艦載機
存量往上補一成，補到「經濟力＋防衛力」為止**；補給線被切斷的星域不補。

## 一、先驗「它每回合都跑」

`docs/re/255` 記過這條鏈，但那是二手；這裡重跑一次。

**閘門與呼叫順序**（`tools/ida.sh script seg0654.com disasm_funcs.py
/work/d0654_007_re273.txt 7:2D`，輸出 `workplace/ida/d0654_007_re273.txt`；
`seg0654.com` 的這一段與三份 1 MB 傾印的線性 `0x06547` 起逐位元組相同）：

```
0654:0007:
  +0007  80 3e f4 8f 00     cmp  byte [8FF4], 0
  +000C  74 25              jz   +0033（retf）
  +000E  80 3e f5 8f 00     cmp  byte [8FF5], 0
  +0013  74 1e              jz   +0033（retf）
  +0015  9a b2 02 5f 2b     call far 2B5F:02B2     ← 在 mod 10 之前
  +001A  a1 18 8f           mov  ax, [8F18]
  +001D  b9 0a 00           mov  cx, 10
  +0020  33 d2  f7 f1       xor dx,dx; div cx
  +0024  09 d2  74 01       or dx,dx; jz +0029
  +0028  cb                 retf                    ← 餘數非 0 就在這裡結束
  +0029  9a f2 0b 03 27     call far 2703:0BF2      ← 月底：成長＋重算成長率
  +002E  9a 5e 0b 0a 09     call far 090A:0B5E      ← 月底：重算稅率
```

上面那道閘門是「兩格旗標都還沒被清」，**不是**月底閘門：主迴圈在
`inc [8F18]` 之後把 `ds:8FF4`／`ds:8FF5` 都設 1，逐座位的 `0654:0034`
才各清掉自己那一格（`docs/re/251`、`docs/re/255`）。所以
`0654:0007` 一個回合跑一次，而 `2B5F:02B2` 在它裡面無條件跑。

**呼叫點只有一個。** 三份互相獨立的 1 MB 傾印（`monthblend`、`s3ai6`、
`t260_post`）掃 `9A B2 02 5F 2B`，各只有 1 處，都在線性 `0x06555`
＝ `0654:0007+0x15`。同一份傾印再往上掃：

```
9A 07 00 54 06（call far 0654:0007）→ 1 處，線性 04F94 ＝ 04F8:0014
9A 0E 00 F8 04（call far 04F8:000E）→ 1 處，線性 03AAB
9A 0C 00 6A 05（call far 056A:000C）→ 1 處，線性 03ACD
```

`0x03AAB` 與 `0x03ACD` 在同一段連續的位元組裡（主迴圈，`docs/re/251`）：

```
03AAB  9a 0e 00 f8 04   call far 04F8:000E     ; 一個回合（逐座位）
03AB0  89 c7            mov  di, ax
03AB2  09 c0  74 07     or ax,ax; jz +7        ; 非 0 → 收掉主迴圈
03AB7  83 c4 06 5f 5e 5d cb                    ; retf
03ABE  c6 06 1d 8f ff   mov  byte [8F1D], FFh
03AC3  b8 01 00 50      push 1
03AC5  9a 49 03 05 37   call far 3705:0349
03ACD  9a 0c 00 6a 05   call far 056A:000C     ; 回合尾巴那一串
```

**執行期對上了。** 收據 `re273clamp` 用 `-regs-at 2B5F:02B2`，275,000,000
道指令裡**命中兩次**：`#121702390`（回合 0）與 `#268295513`（回合 1）。
`re273stock` 跑完 peek `lin:5DA48`（`ds:8F18`）＝ `01 00` ＝ 回合 1。
**回合 1 不是 10 的倍數，它照樣跑了**——不是月底限定，斷言成立。

## 二、`2B5F:02B2` 的本體

```
2B5F:02B2:
  +02B2  55 56 57 83 ec 12 89 e5    push bp/si/di; sub sp,12h; mov bp,sp
  +02BA  c6 46 00 00                mov  byte [bp+00], 0        ; k = 0
  +02BE  c7 46 0a 9c a7             mov  word [bp+0A], 0A79Ch   ; 星域表
  +02C3  8c 5e 0c                   mov  [bp+0C], ds
  +02C6  80 7e 00 20                cmp  byte [bp+00], 20h      ; k < 32？
  +02CA  72 03 / e9 cd 00           jb 本體 / jmp 收尾
  +02CF  c4 5e 0a                   les  bx, [bp+0A]
  +02D2  26 80 7f 12 02             cmp  byte es:[bx+12h], 2    ; 擁有者 == 無主？
  +02D7  74 07                      jz   跳過
  +02D9  26 f6 47 13 01             test byte es:[bx+13h], 1    ; 態勢旗標 bit0？
  +02DE  74 03                      jz   本體
  +02E0  e9 af 00                   jmp  跳過
  ── 本體 ──
  +02E3  c4 5e 0a                   les  bx, [bp+0A]
  +02E6  26 8b 4f 1c                mov  cx, es:[bx+1Ch]        ; 經濟力高位
  +02EA  26 8b 77 1a                mov  si, es:[bx+1Ah]        ; 經濟力低位
  +02EE  26 8b 7f 20                mov  di, es:[bx+20h]        ; 防衛力（16 位元）
  +02F2  31 d2 03 f7 13 ca          xor dx,dx; add si,di; adc cx,dx
  +02F8  89 4e 04  89 76 02         [bp+02] = 上限 = 經濟力 ＋ 防衛力
  +02FE  89 c8 89 f3 31 c9          ax:bx = 上限
  +0304  be 0a 00  87 d6            cx:dx = 10
  +0309  9a 20 00 c9 3c             call far 3CC9:0020          ; 無號 32 位元除
  +030E  89 46 08  89 5e 06         [bp+06] = 上限 ÷ 10
  ── 兩格各做一次，只差 +68h／+70h ──
  +0314  c4 76 0a 83 c6 12          si → 星域記錄 +0x12
  +031A  26 8a 1c 30 ff d1 e3 d1 e3 bx = 擁有者 × 4
  +0326  c4 7e 0a 83 c7 68 03 fb    di → 星域記錄 +0x68 ＋ 擁有者×4
  +032E  26 8b 45 02 26 8b 1d       ax:bx = 現有存量
  +0335  03 5e 06 13 46 08          ax:bx += 上限 ÷ 10
  +033E  8b 4e 04 8b 76 02          cx:si = 上限
  +0344  3b c1 75 02 3b de 77 02    32 位元無號比較
  +034E  89 c8 89 f3                超過上限就取上限
  +0352  26 89 45 02 26 89 1d       寫回
  +0359 …+0392                      同一段對 +0x70
  +0392  fe 46 00                   k++
  +0395  83 46 0a 7e                星域指標 += 126
  +0399  e9 2a ff                   回迴圈頭
  +039C  83 c4 12 5f 5e 5d cb       收尾
```

寫成規則：

```
for 星域 k in 0..31:
    if 星域[+0x12] == 2:          continue      # 無主不補
    if 星域[+0x13] & 1:           continue      # 補給線斷了不補
    上限 = 星域[+0x1A]（經濟力，32 位元）＋ 星域[+0x20]（防衛力，16 位元）
    補   = ⌊上限 ÷ 10⌋
    擁   = 星域[+0x12]
    星域[+0x68 + 擁×4] = min(星域[+0x68 + 擁×4] ＋ 補, 上限)   # 飛彈
    星域[+0x70 + 擁×4] = min(星域[+0x70 + 擁×4] ＋ 補, 上限)   # 艦載機
```

`+0x68`／`+0x70` 是什麼由 `docs/re/244` 定：`2703:12EB` 每回合把每顆行星的
`+0x3C`（飛彈存量）與 `+0x40`（艦載機存量）按**行星擁有者**累加到星域記錄的
`+0x68 + 擁有者×4`／`+0x70 + 擁有者×4`。所以這兩格是「這個星域這一方手上
有多少飛彈／艦載機」，而 `2B5F:02B2` 補的就是它。

`+0x13` 的 bit0 ＝「到自己陣營首都的路徑成本 `>= 0x400`」，也就是路上至少
有一條邊的兩端不全是自己的（`docs/re/243`、`docs/re/244`）。**被切斷補給線
的星域不再回充**——這是那個位元目前唯一讀到的第二個用途（另一個是
`2E54:0222` 的鄰居篩選）。

## 三、收據

### 全 32 格：回充後正好等於「經濟力＋防衛力」

`re273clamp` 在回合 1 的 `2B5F:02B2` 前後各倒一份 32 × 126 的星域表
（`#268290000` 與 `#268330000`）。把上面那五行規則整個套上去：

```
tools/py.sh tools/scripts/region_stock_check.py \
    workplace/re273_rpre.bin workplace/re273_rpost.bin
→ 有主且算式相符 23、依規則跳過 9、不合 0
```

| 類別 | 格數 | 結果 |
|---|---:|---|
| 擁有者 0／1 | 23 | `+0x68[擁]` 與 `+0x70[擁]` **兩格都正好等於經濟力＋防衛力** |
| 擁有者 2（無主） | 9 | 前後完全不動（全 0） |
| 每一格「另一個陣營」那一半 | 32 | 前後完全不動 |

抽三格看數字（前 → 後）：

```
R0  帝國  經濟 82302 防衛 27300  上限 109602   108600 → 109602
R21 同盟  經濟 26238 防衛 25400  上限  51638    51300 →  51638
R31 同盟  經濟 65826 防衛 27500  上限  93326    92600 →  93326
```

23 格全部撞到上限，是因為回合尾巴的 `2703:12EB` 剛把它們設成行星加總，
而開局的行星存量本來就已經在上限的九成以上，一次回充就滿。

### 隔離「補多少」：把存量 poke 到低點

全部都撞上限的話，量不出速率。`re273rate` 在同一個時點（`#268290000`，
`2B5F:02B2` 命中之前）把星域 0 的兩格 poke 開：

| 欄位 | poke 進去 | 回充後 | 期望 |
|---|---:|---:|---|
| `+0x68[0]` 飛彈 | 0 | **10960** | `⌊109602 ÷ 10⌋` ＝ 10960 |
| `+0x70[0]` 艦載機 | 65536 | **76496** | 65536 ＋ 10960 ＝ 76496 |

兩格互不相干、低於上限時不夾。速率與夾法**confirmed**。

### 監看：誰在寫這一格

`re273stock` 用 `-watch 5F334-5F337` 盯星域 0 的 `+0x68`（線性
`0x5F2CC + 0x68`）。整趟只有三種寫入者：

```
#60572505…#60573253  2703:13ED／13F1   載入後第一次彙總 → 199488（≒ 行星檔的 200000）
#121702822           2B5F:0359         → 108600（＝ 當時的上限，被夾）
#263395078…#263395825  3C9C:001C 清 0 後 2703:13ED 重新彙總 → 108600
#266002202…#266002949  同上            → 108600
#268295943           2B5F:0359         → 109090（＝ 當時的上限，被夾）
```

## 四、這一筆不會被回合尾巴蓋掉——它先被分回行星

`2703:12EB`（行星 → 星域）每個回合尾巴都跑，看起來會把回充蓋掉。實際上
中間還有一支反方向的：

```
056A:000C（主迴圈，線性 03ACD 呼叫）
    …
    2703:051D()              ; 線性 056E5；32 格各跑一次 2703:0540
        2703:0540(k)
            2AF5:0036(k, 0)              ; 切到該星域的行星
            2703:0590(星域記錄, 0)        ; 帝國那一份
            2703:0590(星域記錄, 1)        ; 同盟那一份
    …
```

`2703:0590` 讀星域記錄的 `+0x30`（艦艇）、`+0x68`、`+0x70`，數出該陣營在這
一格的行星經濟力總和與最大的那顆，再按比例把星域層的量分配回各行星。
**逐行讀完的只有艦艇那一段**（`2703:06E0` 起的七輪：
`星域[+0x30 + 陣營×0x1C + 艦種×4] × 比例 ÷ 100` 寫進一個遠指標、
從另一個遠指標扣掉餘額）；飛彈與艦載機那兩段只讀到它把
`+0x68`／`+0x70` 載進區域變數（`2703:05DD`／`2703:05F2`），分配本體還沒讀。

呼叫點：`2703:051D` 在整份 1 MB 裡只有 1 處（線性 `0x056E5`）；
`2703:0540` 有 3 處（`0x2755F` ＝ `2703:052F`，也就是 `051D` 那個 32 格迴圈
自己；另外兩處在 `0x1BC90` 與 `0x2B183`，還沒查是什麼路徑）。

**執行期看得到這件事發生**：`re273stock` 的監看序列裡，`#60.5M` 的彙總
得到 199,488（行星還是 `PLADAT.DAT` 的原值），`#121.7M` 的回充把星域層夾成
108,600，到了 `#263.4M` 再彙總一次，得到的**又是 108,600**——行星身上的
飛彈存量在這中間從 199,488 變成了 108,600。整趟沒有任何補給命令，
唯一能改行星存量的就是這條分配鏈。

把 `PLADAT.DAT` 的原值與執行期傾印逐格對，也是同一個結論：

```
R0  檔案 200000 → monthblend 108600      R1  檔案 150000 → 43700
R2  檔案 100000 → 39000                  R5  檔案 100000 → 22200
```

也就是說開局檔案給的存量遠高於上限，**第一個回合就被夾到經濟力＋防衛力**，
之後才在那個水位上按一成一成回充。

分配的確切算式（比例怎麼取、餘數給誰）**還沒讀**。

## 五、remake 缺什麼

`internal/rules` 與 `internal/game` 裡：

- **沒有星域層的 `+0x68`／`+0x70`。** `internal/rules/region.go` 的欄位常數
  只到 `+0x7D`，`0x68`／`0x70` 一次都沒出現。
- **沒有任何一處回充行星的 `+0x3C`／`+0x40`。** `internal/rules/planetcmd.go`
  的 `planetMissiles = 0x3C`／`planetFighters = 0x40` 只被 `PlanetSupply` 扣，
  沒有加回去的路徑。
- `internal/game/game.go` 的 `advanceTurn` → `endOfTurn` → `finishTurn`
  整條回合流程裡沒有對應的步驟。

影響：

1. **行星的飛彈與艦載機存量在 remake 裡只減不增。** 戰場上用行星「補給」
   補分隊會寫回行星記錄（`docs/spec/019` 已對拍），所以打得越久差越多。
2. **開局的存量水位就不一樣。** 原版第一個回合把 `PLADAT.DAT` 的
   200000／150000／100000 夾成經濟力＋防衛力（帝國奧丁那一格 200000 → 108600），
   remake 沿用檔案原值。同一顆行星能補出去的量，remake 從第一個回合起就偏高。
3. **補給線的意義沒了。** 原版被切斷（`+0x13` bit0）的星域停止回充，
   remake 沒有這個懲罰。

規格寫在 [`docs/spec/039`](../spec/039-region-supply-pool.md)（DRAFT）。

## 六、位元組簽章

三份互相獨立的傾印（`monthblend`、`s3ai6`、`t260_post`）逐一驗過，**各只有
一處命中**：

| 位置 | 簽章 |
|---|---|
| `2B5F:02B2` 進入點 | `55 56 57 83 EC 12 89 E5 C6 46 00 00 C7 46 0A 9C A7 8C 5E 0C 80 7E 00 20` |

## 七、方法：反組譯先給假說，資料才給等級

反組譯讀出「補到經濟力＋防衛力為止」只是讀出來的，不是驗過的。真正把它
釘死的是**兩份互相獨立的資料**：

- 既有的 1 MB 傾印裡，23 個有主星域的兩格**同時**等於經濟力＋防衛力，
  9 個無主星域一格都沒動——這種巧合不會發生；
- 一次 `-poke` 把兩格拉到上限以下，回充量與算式逐位元組相同。

反過來說，只靠傾印也不夠：全部撞上限的狀態下，`+cap/10`、`+cap/5`、
`直接設成 cap` 三種寫法給出的畫面完全一樣。**要量速率就得先把狀態
poke 到量得出來的地方**（`docs/spec/014`），不是多跑幾個回合等它自己出現。

## 八、還沒解

- `2703:0590` 把星域層的量分回行星的確切算式（比例、餘數、最大那顆行星的
  角色）。
- `+0x13` bit0 有設的星域停止回充，這件事沒有收據——開局到回合 1
  沒有任何一格的 bit0 是 1（`re273clamp` 的 32 格旗標欄全是 `00` 或 `08`）。
  要驗得 poke 一格的 bit0 再看它那一回合有沒有被跳過。
- 星域經濟力在同一個回合內會變（`re273stock` 量到 81300 → 81790 → 82302），
  月底成長 `2703:0C26` 之外還有別的寫入者，沒追。
