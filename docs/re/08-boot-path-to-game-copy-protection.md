## 1. 完整流程

`GIN3.COM`（launcher）→ `OPEN.EXE`（開場，mode 10h）→ `GIN3PS.EXE`（本體，mode 12h）。
中間有三道要玩家動手的閘門，**每一道不過，程式就原地不動**（不是當掉，
也不會有任何畫面提示）：

| # | 閘門 | 畫面 | 通過方式 | 觀測到的步數 |
|---|---|---|---|---|
| 1 | 開場動畫 | mode 10h | 滑鼠左鍵（走 `int 33h AX=5` 的按下累計） | 點在 #40M，程式在 #50,368,552 領走計數，隨即結束 |
| 2 | 主選單 | mode 12h | 滑鼠左鍵（**只走事件回呼**） | 進 mode 12h 於 #68,658,859；點在 #95M |
| 3 | 防拷問答 | 頭像＋三行提問 | 鍵盤輸入數值＋Enter | 送鍵於 #105M 起 |

閘門 1 與閘門 2 收輸入的路不一樣，這點花掉最多時間：主選單**只從
`int 33h AX=000Ch` 登錄的回呼收按下**（遮罩 `001F`、handler `36AD:021D`），
輪詢那條路它只用來拿座標畫游標。所以「游標會動、`AX=3` 也回報按著
12,520 次、按下的統計躺著沒人領」三件事同時成立，畫面卻毫無反應——
機制與判準寫在 dosgolem `docs/spec/013-mouse-event-callback.md`。

## 2. 防拷問答（confirmed）

畫面文字（Big5，取自 framebuffer）：

```
請查閱提督資料表
輸入照片上帝國軍提督
占領能力數值：
```

左側是一張提督頭像，右下是輸入框。這是手冊查表式保護：玩家要從
紙本資料表找出照片上那位提督的「占領能力」，把數值打進去。

檔案存取的證據鏈（`FileOps`）：

```
#95019090 read admiral.dtX @0    2296 bytes   ← 能力值表整份載入
#95161354 seek face.amg → 0
#95161378 read face.amg @0       6 bytes      ← 索引表第 0 筆
#95161399 seek face.amg → 498
#95161421 read face.amg @498     3348 bytes   ← 第 0 張頭像
```

`FACE.AMG` 索引第 0 筆 ＝ `(size 3348, offset 498)`，也就是**第 0 號頭像**。
`ADMIRAL.DTX` 第 0 筆記錄（28 bytes）的 `+11` ＝ `0x8A` ＝ **138**。
輸入 138 之後畫面直接進遊戲本體（796 年 1 月會計報告），
所以 `+11` 就是「占領能力」欄位（confirmed，一個資料點）。

**這一版的題目是固定的**：執行器決定性，同一序列跑兩次收據逐位元組相同。
題目會不會隨局面或亂數換人（真機上是否每次不同）＝ 未知。

## 3. 鍵盤輸入（confirmed）

本體自己裝 `int 09h`（`348A:0002`，設於 #68,658,882），所以 BIOS 緩衝區
那條路沒用，要走 IRQ1 送掃描碼（dosgolem `docs/spec/012` §1）。
`-press "1,3,8,enter" -press-every 2000000` 八次 IRQ 全部收到。
