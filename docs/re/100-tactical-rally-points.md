# RE 100 — 戰術層往哪裡帶：地圖上埋了集結點

`docs/re/80` 量到一場六對一的戰鬥裡，敵方六支艦隊有四支的目標點是同一個
**(1168,1160)**，當時不知道那個數字從哪來。這次直接盯著艦隊記錄的目標欄位
（同盟 16 的 `+0x64`，線性 `0x613A8`）看誰寫它。

收據 `s3tgt`（執行器 dosgolem-logh3 `20e4583`，`-watch 613A8-613AB`，
1.15e9 步），四個位元組總共被寫 24 次，最後一次是：

```
[watch] #937580422 613A8: 00 → 90  ← 31DB:03A0
[watch] #937580422 613A9: 06 → 04
[watch] #937580426 613AA: 30 → 88  ← 31DB:03AC
[watch] #937580426 613AB: 07 → 04
```

`0x0490` ＝ 1168、`0x0488` ＝ 1160。寫它的是 **`31DB:01B6`**。

## 候選點是一張表

那支函式從 `ds:0D70C` 抽點，表是 4 位元組一筆的 (x, y)，筆數在
`ds:0D78C`。倒出來剛好七筆：

```
(816,660) (368,800) (672,920) (1168,1160) (864,1220) (1328,1540) (1040,1660)
```

`docs/re/80` 裡「停住」的同盟 30 其實站在第 5 筆 (1328,1540) 上——它不是
不動，是已經到了。

七個點全部落在 `(欄×16, 列×20)` 的格點上。拿 `MAP26.CMP` 對照
（`docs/re/81` 的 RLE）：

| 點 | 格 | 圖塊 |
|---|---|---|
| (816,660) | (51,33) | 1 |
| (368,800) | (23,40) | 1 |
| (672,920) | (42,46) | 1 |
| (1168,1160) | (73,58) | 1 |
| (864,1220) | (54,61) | 1 |
| (1328,1540) | (83,77) | 1 |
| (1040,1660) | (65,83) | 1 |

**整張 `MAP26.CMP` 裡圖塊 1 剛好只出現七次，就是這七格。**
32 張圖每張都有 4–13 個，是作者一格一格埋進去的。

> 行星用的是圖塊 6，偏移取格子中央 `(欄×16+8, 列×20+12)`（`docs/re/89`）；
> 集結點取的是格子的左上角，兩者是不同的產生器。`docs/re/80` 裡同盟 28
> 的目標 (1320,812) 是行星雷奧米爾，不在這張表裡。

## 怎麼挑

`31DB:01B6(艦隊, 參考點x, 參考點y, &目標x, &目標y)`：

### 1. 先框一個範圍

```
w ＝ |艦隊x − 參考x|      loX,hiX ＝ 兩者的小、大
h ＝ |艦隊y − 參考y|      loY,hiY ＝ 兩者的小、大
若 w ≥ h：Y 這一邊撐開成 w，中心放在 (艦隊y+參考y)/2
否則    ：X 這一邊撐開成 h，中心放在 (艦隊x+參考x)/2
```

也就是**以艦隊與參考點為對角線的方框，補成正方形**。

### 2. 挑出框內的候選

逐筆掃 `ds:0D70C`，落在框內（嚴格大於 lo、嚴格小於 hi）而且不等於艦隊
現在位置的收進一個陣列。

### 3. 隨機抽，抽不中就抽下一個

```
n ＝ 候選數
loop:
    i ＝ rand() % (n+1)          ; 3CD5:000C
    若 i == n：目標 ＝ 參考點，結束      ← 1/(n+1) 的機率直接壓過去
    p ＝ 候選[i]
    若 通得過(艦隊位置, p) 而且 通得過(p, 參考點)：目標 ＝ p，結束
    否則把候選[i] 從陣列裡刪掉（memmove），n−−，沒得挑就結束
```

所以「六支裡四支指同一個點」不是集火邏輯，是**框內候選本來就少**——
七個點裡落在框內的往往只有一兩個，抽到同一個的機率很高。

## 「通得過」＝ 沿直線每 8 像素試一格

`1588:891(x1,y1,x2,y2)`：

```
loop:
    若 (x1,y1) == (x2,y2)：回 1
    d ＝ 距離(x1,y1,x2,y2)              ; 3310:6，16.16
    若 d < 8：(x1,y1) ← (x2,y2)，continue
    dir ＝ 方向(x2−x1, y2−y1)           ; 2BE1:11D
    (x1,y1) ← 從 (x1,y1) 沿 dir 前進 8  ; 2BE1:26F
    若 可通行(x1,y1)：continue
    回 0
```

`1588:4EA(x,y)` 檢查一個 **16×16 的佔位框**壓到的每一個半格：

```
for 半格欄 c ＝ x>>3 .. (x+15)>>3
    for 半格列 r ＝ y/10 .. (y+15)/10
        若 阻擋(c,r)：回 0
回 1
```

半格是 8×10——圖塊 16×20 的四分之一。`1588:621(c,r)`：

```
圖塊 ＝ 地圖[(r>>1)×128 + (c>>1)]        ; 1588:672，遠指標在 ds:3C1A
遮罩 ＝ ds:9BB4[圖塊]                    ; 1588:693
象限 ＝ (r&1)×2 + (c&1)
回 遮罩 & ds:3C3E[象限]
```

倒出來的兩張表：

```
ds:3C3E ＝ [0, 2, 4, 8]
ds:9BB4 ＝ 圖塊 0–7、14、15、22、23、30、31 是 00，其餘全部 0F
```

**遮罩只有 00 與 0F 兩種值**，所以四位元的象限設計實際上沒被用到——
一個圖塊要嘛整格通、要嘛整格不通。可通行的是圖塊 0–7 與 8–31 裡
每組的後兩個；32 以上全部阻擋。行星（圖塊 6）與集結點（圖塊 1）都通得過，
所以艦隊可以站在行星上——`docs/re/80` 的同盟 31 旗艦就站在雷奧米爾。

象限表第 0 項是 `00`，意思是每個圖塊的左上四分之一永遠算通行。佔位框
是 16×16，橫豎都至少壓到兩個半格，所以這件事在多數情形下看不出來；
這裡照實記，不推測作者的意圖。

## 對 remake 的意義

戰術層的目標不是「敵人在哪」，是**地圖上埋好的集結點**，而且要
「從我這裡走得到、從那裡也走得到參考點」。這同時解掉兩件事：

- `docs/re/80` 的 (1168,1160) 是集結點 3；
- 原版一回合走 200–300 像素卻要六回合才接觸，因為它是**沿著集結點
  一段一段走**，不是直線衝向敵人。
