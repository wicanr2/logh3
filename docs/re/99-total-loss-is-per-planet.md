# 99：一輪的總損失是「艦隊對行星」，不是「艦隊對艦隊」

remake 的每輪總損失比原版小了五倍（實測：remake 平均 56、最大 106，
原版收據量到 **290**）。順著算式往上讀，發現不是係數錯，是**餵錯了
整張表**。

## 基本量那一段

總損失那支函式從 `219BE` 開始：

```
les bx, [bp+2Ah]                  ; ← 傳進來的第一筆記錄
cmp byte ptr es:[bx+12h], 0
jne  → 除數 ＝ 20
除數 ＝ 10
call far 203A:04D1(那筆記錄)      ; 回一個數
add  ax, es:[bx+14h]              ; ＋ 那筆記錄的 +0x14
div  word [bp+6]                  ; ÷ 除數
mov  [bp+2], ax                   ; ＝ 基本量
```

而 `203A:04D1` 裡：

```
push es:[bx+48h]                  ; 那筆記錄的 +0x48
push es:[bx+46h]                  ; +0x46
push es:[bx+11h]                  ; +0x11
call far 17A0:00AC                ; 空間查詢（docs/re/90）
```

`17A0:00AC(陣營, x, y, 門檻, 輸出)`——所以那筆記錄的 `+0x11` 當**陣營**、
`+0x46`／`+0x48` 當**座標**。

## 哪張表長這個形狀

| 表 | `+0x11` | `+0x12` | `+0x14` | `+0x46` | `+0x48` |
|---|---:|---:|---:|---:|---:|
| 艦隊 12 | 0 | 0 | 82 | 26218 | 65284 |
| 艦隊 28 | 0 | 0 | 113 | 33650 | 65280 |
| 艦隊 31 | 0 | 1 | 137 | 32121 | 65025 |
| 行星 雷奧米爾 | 0 | 0 | 127 | **1320** | **812** |
| 行星 謝拉德 | **1** | 0 | 216 | **776** | **1612** |
| 行星 達希利 | **1** | 0 | 92 | **1256** | **1652** |

**艦隊記錄的 `+0x46`／`+0x48` 根本不是座標**（那是能力的第 9、10 項，
`docs/re/95`），而且 `+0x11` 三支都是 0，當陣營用分不開兩邊。
**行星記錄的 `+0x11` 是擁有者（0 帝國／1 同盟）、`+0x46`／`+0x48` 是
星域地圖上的位置**（`docs/re/89` 解出來的那一組），`+0x14` 是**防衛力**
（`docs/internals/29`，實測 92–216，正好落在先前記的「82–144」那個範圍
往上一點）。

形狀只有行星表對得上。

## 所以那條算式是什麼

```
基本量 ＝ (行星附近該陣營的艦艇量 ＋ 行星防衛力) ÷ (10 或 20)
距離項 ＝ 基本量 × (行星到艦隊的距離 ÷ 150) ÷ 5
```

距離那一段（`21A04` 起）拿的是**行星的 `+0x46`／`+0x48`** 與另一筆記錄
的 `+0x5C`／`+0x5E`——後者是艦隊記錄的戰場座標（`docs/re/95`）。
兩筆記錄的形狀因此都定了：**第一個參數是行星、第二個是艦隊**。

也就是說，這條算的是**艦隊打行星（或行星打艦隊）那一次的量**，
不是兩支艦隊互打。

## 對 remake 的影響

`rules.BattleDamage` 的 `Kind1Ships` 與 `Bonus` 現在餵的是**艦隊**的欄位
（艦隊 `+0x14`、該艦隊艦種 1 的艘數總和），所以量級小了五倍——
`+0x14` 拿到的是 82–137，而行星防衛力是 92–216；艘數那一項更是完全
不同的集合（行星周圍 vs 一支艦隊裡）。

要對上就得先把**行星**接進戰場模型：戰場上有行星（`docs/re/89` 已經
在小地圖上畫出來了），總損失要以行星為中心算。這一步還沒做。

## 收據

`s3fight` 的記憶體傾印；量級的對照來自 `s3dist`（`-regs-at 20B4:1110`
的 `[bp+06h]` 從 290 開始往下扣）與 remake 的
`TestBattleLossMagnitude`。
