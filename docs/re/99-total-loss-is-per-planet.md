# 99：一輪的總損失是「艦隊對行星」，不是「艦隊對艦隊」

remake 的每輪總損失比原版小了五倍（實測：remake 平均 56、最大 106，
原版收據量到 **290**）。順著算式往上讀，發現不是係數錯，是**餵錯了
整張表**。

## 基本量那一段

總損失那支函式從 `219BE` 開始：

```
les bx, [bp+2Ah]                  ; ← 傳進來的第一筆記錄
cmp byte ptr es:[bx+12h], 0
jne  → 除數 ＝ 20
除數 ＝ 10
call far 203A:04D1(那筆記錄)      ; 回一個數
add  ax, es:[bx+14h]              ; ＋ 那筆記錄的 +0x14
div  word [bp+6]                  ; ÷ 除數
mov  [bp+2], ax                   ; ＝ 基本量
```

而 `203A:04D1` 裡：

```
push es:[bx+48h]                  ; 那筆記錄的 +0x48
push es:[bx+46h]                  ; +0x46
push es:[bx+11h]                  ; +0x11
call far 17A0:00AC                ; 空間查詢（docs/re/90）
```

`17A0:00AC(陣營, x, y, 門檻, 輸出)`——所以那筆記錄的 `+0x11` 當**陣營**、
`+0x46`／`+0x48` 當**座標**。

## 哪張表長這個形狀

| 表 | `+0x11` | `+0x12` | `+0x14` | `+0x46` | `+0x48` |
|---|---:|---:|---:|---:|---:|
| 艦隊 12 | 0 | 0 | 82 | 26218 | 65284 |
| 艦隊 28 | 0 | 0 | 113 | 33650 | 65280 |
| 艦隊 31 | 0 | 1 | 137 | 32121 | 65025 |
| 行星 雷奧米爾 | 0 | 0 | 127 | **1320** | **812** |
| 行星 謝拉德 | **1** | 0 | 216 | **776** | **1612** |
| 行星 達希利 | **1** | 0 | 92 | **1256** | **1652** |

**艦隊記錄的 `+0x46`／`+0x48` 根本不是座標**（那是能力的第 9、10 項，
`docs/re/95`），而且 `+0x11` 三支都是 0，當陣營用分不開兩邊。
**行星記錄的 `+0x11` 是擁有者（0 帝國／1 同盟）、`+0x46`／`+0x48` 是
星域地圖上的位置**（`docs/re/89` 解出來的那一組），`+0x14` 是**防衛力**
（`docs/internals/29` 記的就是 16 位元，實測 2200–5400）。

形狀只有行星表對得上。

## `203A:04D1` 到底加了什麼

迴圈裡對每一筆命中的艦艇記錄：

```
mov al, es:[si+4]      ; 艦種
or  al,al
jz  收                 ; 艦種 0 → 收
cmp al,1
jne 下一筆             ; 不是 0 也不是 1 → 跳過
收: 累計 += es:[si+8]  ; 現有艘數（32 位元，夾在 0xFFFF）
...
結束: ax ＝ 累計 ÷ 100
```

所以它是 **`Σ{艦種 0 或 1} 現有艘數 ÷ 100`**——不是只有艦種 1，
而且那個 `÷100` 是在這支裡面做的（先前記在外層算式裡，位置對、
歸屬錯）。

查詢的門檻來自 `2AF5:01F7(行星)`：

```
ax ＝ 行星 +0x14（防衛力）
夾在 1500 與 6000 之間
÷ 25
```

行星防衛力是 **word**（`add ax, es:[bx+14h]` 是 16 位元加），實測
2200–5400——不是我先前按 byte 讀到的 92–216。所以門檻是
`防衛力 ÷ 25`，落在 **88–216**（雷奧米爾 2687 → 107、達希利 4700 → 188）。

## 所以那條算式是什麼

```
量     ＝ Σ{艦種 0 或 1、陣營 ＝ 行星擁有者、距行星 ≤ 60} 現有艘數
基本量 ＝ (量 ÷ 100 ＋ 行星防衛力) ÷ (10 或 20)
距離項 ＝ 基本量 × (行星到艦隊的距離 ÷ 150) ÷ 5
```

距離那一段（`21A04` 起）拿的是**行星的 `+0x46`／`+0x48`** 與另一筆記錄
的 `+0x5C`／`+0x5E`——後者是艦隊記錄的戰場座標（`docs/re/95`）。
兩筆記錄的形狀因此都定了：**第一個參數是行星、第二個是艦隊**。

也就是說，這條算的是**艦隊打行星（或行星打艦隊）那一次的量**，
不是兩支艦隊互打。

## 尾段照原樣，沒有別的陷阱

方向係數表 `ds:47D0` 是用 **word** 索引的（`mov si,[bx+47D0h]`，
`shl bx,1`），值仍然是 `[80,85,90,95,100,95,90,85]`——高位元組是 0，
所以先前按 byte 讀剛好一樣。防禦係數確實取自**艦隊**記錄的
`+0x40 × +0x41 ÷ 100`。最後 `＋ rand() % 100` 再丟給分攤
（`20B4:103D` → `20B4:1110`，`docs/re/97`）。

## 對 remake 的影響

`rules.BattleDamage` 的 `Kind1Ships` 與 `Bonus` 現在餵的是**艦隊**的欄位
（艦隊 `+0x14`、該艦隊艦種 1 的艘數總和），所以量級小了五倍——
`+0x14` 拿到的是 82–137，而行星防衛力是 92–216；艘數那一項更是完全
不同的集合（行星周圍 vs 一支艦隊裡）。

**行星已經接進戰場模型了**（`rules.BattlePlanet`、`BattlePlanetsFor`、
`ResolveBattleTurn`）：星域的行星從行星表取擁有者、防衛力與 `+0x12`，
位置掃該星域的地圖（圖塊 6 依列序對到行星，`docs/re/89`）。結算改成
以行星為中心：一顆行星對每一支敵方艦隊算一次。

S3 星域 26 接出來的三顆與收據完全相同：雷奧米爾 (1320,812) 帝國、
謝拉德 (776,1612) 同盟、達希利 (1256,1652) 同盟。

### 戰術層也要以行星為目標

原版量到的目標點裡有一個是 **(1320,812)**——那正是雷奧米爾的座標
（`docs/re/80` 的同盟第 28 艦隊）。所以戰術層會把艦隊帶向**敵方的行星**，
不是只追著敵艦跑。`ai.OriginalTactic` 照這條改：目標優先取最近的敵方
行星，沒有行星才退回最近的敵方單位。

### 量級對上了

兩邊真的壓到行星上之後：

```
remake：72 次交火，總損失平均 273、最大 532
原版收據：290
```

**同一個量級。** 先前平均 48 是因為單位停在入口格上沒動——距離項
（`基本量 × (距離 ÷ 150) ÷ 5`）把基本量吃光了。量級的比較只有在
**幾何可比**的時候才有意義，這一點寫進測試註解了。

`docs/re/80` 另一個目標點 (1168,1160) 還沒解——它不是那三顆行星裡的
任何一顆。

### 數字對上了

拿雷奧米爾（防衛力 2687）與視野內約 30,000 艘算一次：

```
量 ÷ 100 ＝ 300
基本量   ＝ (300 ＋ 2687) ÷ 10 ＝ 298
方向係數 80–100 → 攻擊力 238–298
防禦係數（艦隊 +0x40 × +0x41 ÷ 100）≈ 101 → 236–295
＋ 亂數 %100  → 236–395
```

**收據量到的 290 就落在這個範圍裡。** 算式與所有係數都對得上了。

remake 的量級小五倍，原因只有一個：`Bonus` 餵的是艦隊 `+0x14`
（82–137），而原版餵的是**行星防衛力**（2200–5400）。

## 收據

`s3fight` 的記憶體傾印；量級的對照來自 `s3dist`（`-regs-at 20B4:1110`
的 `[bp+06h]` 從 290 開始往下扣）與 remake 的
`TestBattleLossMagnitude`。
