## 一、清單長什麼樣

版面就是通用的那一套（`docs/internals/23`），一筆 12 bytes：

```
+0 格x  +1 格y  +2 寬（格）  +3 高（格）
+4 可選旗標  +5 動作碼  +6 元件種類  +7 0
+8 far 指標 → Big5 標籤，或三個位元組的動作碼（FF 17 00 ＝ 加）
```

## 二、位址自己會驗：20 個框逐一對上

規格 `screen-settings.json` 的 `overlay` 視窗有 20 個小框，量自收據
`settings1e`（與熱區清單是**兩條獨立的路**：一邊是畫面上的連通分量，
一邊是資料段裡的位元組）。兩邊的對應關係全中：

- 18 個一般按鈕：框 ＝ 熱區左右各 **＋2** 像素、上下對齊，寬 ＋4
  （`docs/re/68` 量到的同一條規則）。
- 2 個上下箭頭（元件種類 6）：框與熱區**一樣大、對齊**，沒有那 2 像素。
- 框上印的字與清單 `+8` 指到的 Big5 字串**逐字相同**（20 個框全部）。

沒有框的兩筆也各有解釋：

- `MIDI`（可選旗標 0）：出貨的 `MUSIC.INI` 把「ＭＩＤＩ Ｉ／Ｆ」設成
  「無」，開機偵測因此把 `ds:03DC` 寫成 0（`docs/re/274` §3），
  那一格點不下去、框也不畫。46 份執行期傾印裡 `ds:03DC` 全是 0、
  `03E8`／`03F4` 全是 1。
- `BUG!`：可選但畫面上什麼都沒有——沒有框、沒有字。它在 (400,60)，落在設定視窗
  上緣那一帶（標題「遊戲設定」那一行的右側）。**做什麼未解**。

反過來也成立：20 個框每一個都被某一筆熱區認領，沒有剩下的。

## 三、三格的現值：46 份傾印一致

| `ds` | 值 | 意思 |
|---|---:|---|
| `8F33` | 1 | ＦＭ |
| `8F34` | 0 或 3 | 新遊戲 0；載 `*.DTA` 的那幾份 3 |
| `8F35` | 0 | 全艦攻擊 |
| `934E` | `02` | 裝置遮罩：有 OPL、沒有 MPU-401 |

與收據 `settings1e` 上反白的那三格（`ＦＭ`、`波琍璐`、`全艦攻擊`）互相印證
——反白 ＝ 框的填色 2，其餘是 8。

> ⚠ **`work-796-01.json` 的 `+0x1F` 是 0，那不是反例。** 那份範本量自
> 第 71,200,000 步（防拷畫面之前），而音源偵測要到進遊戲本體才跑
> （`docs/re/274` §7 的 `0x181E2`：第一首 `.MDS` 在 #117M）。
> 所以範本停在偵測之前的 0，執行期與三格出貨存檔都是 1。

## 四、為什麼形狀掃描會漏掉它（補一條成因）

`docs/re/156` 已經記過「掃形狀會漏、要從呼叫點解」，但沒說這一份為什麼
落選。原因在 `hotspot_scan.py` 的判準之一：「`+5` 從 0 開始**逐筆遞增**」
——它把 `+5` 當成項目索引。這份清單的 `+5` 是**動作碼**，最後一筆是 22、
跳過 21，連續性在那裡斷掉，整段因此不算數（掃描要求整段連續 ＋ 結尾
`FF FF`）。

所以 `+5` 的正確說法是**動作碼**，不是索引：多數清單兩者剛好相同，
這一份不是（`docs/internals/23` 的欄位表已改）。

順帶修掉一個文件落差：`docs/internals/23` 的 markdown 表只列了形狀掃描
那 25 份，`docs/re/156` 補的七份（含這一份）一直只在
`data/hotspot-lists.json` 裡。七份已經補進表。

## 五、被推翻的舊斷言

`docs/internals/23` 原本把清單 `902C`（`自動１`／`手動１`／`自動２`／
`手動２`／`顯示`／`不顯示`／`結束`）標成「像是音源選擇（假說）」，
理由是 `MUSIC.INI` 與 `.MDS` 各有兩個版本。

**推翻**：音源選擇在 `ds:03D8` 這一份，標籤是 `MIDI`／`ＦＭ`／`關閉`，
而且動作碼直接寫 `ds:8F33`（`docs/re/274` §5）。`902C` 那七項與音源無關，
它屬於哪一張畫面**仍然未知**。

> 後續：`902C` 屬於 `BUG!` 那個沒有框的熱區開的隱藏除錯選單
> （[`286`](286-settings-other-rows.md) §六）。

## 六、remake 接了哪幾行

接了音樂那三組（`internal/game.settingsClick`：動作碼 0–2／3–8／9–11）。
點完立刻換底色是 remake 自己每幀重畫得到的；原版是選完重畫那一列或
整張清單。**試聽也不必另外做**：`cmd/gin3` 每幀問一次「現在該播哪一首」，
而 `internal/audio.TuneFor` 只看音源與平時配樂——原版「選音源／選平時曲
會試聽、選戰鬥曲不會」那個差別在這裡自然成立。

沒接的那幾筆（清單裡有、remake 還沒有對應狀態）。
**下面這張表只剩 22 還成立**——12–19 已在 [`286`](286-settings-other-rows.md)
解出並接上：
