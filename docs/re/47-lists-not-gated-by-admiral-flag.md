# RE 47 — 五張空清單：不是提督 `+0x09` 那個旗標擋的

日期：2026-09-07
執行器：dosgolem-logh3 `8c8af90`
收據：`s3sortie`、`s3poke09`、`s3poke09b`
狀態：**否定結論 confirmed**（poke 寫進去了、畫面一個像素都沒變）。

## 假設從哪來

`docs/re/43` 解未安定度的時候發現：提督篩選管線 `28E0:0103` 的其中一支
（位元 `0x20`、`28E0:047E`）只留 `提督[+0x09] & 0x80` 的人，而 `+0x09`
**載入時會被夾到 127**（`docs/internals/08`），最高位一定是 0——所以那一項
恆為空。

`docs/re/37` 那五張一直是空的清單，看起來就像同一回事。

## 先確認清單真的是空的

載入 S3「巴米利恩會戰」（有 18 支艦隊）之後開「出擊命令」，
畫面上是「待命中提督資料」——**十四列全空**（收據 `s3sortie`）。
所以不是「這個局面沒有資料」。

## 直接 poke 那個旗標

把提督 0／1／2 的 `+0x09` 在載入之後（第 270,000,000 步）改成 `FF`
再開清單（收據 `s3poke09`）：

```
poke 之後與原本不同的像素 0
```

一個像素都沒變。為了排除「poke 沒寫進去」，同一條路再跑一次並把
提督表倒出來（收據 `s3poke09b`）：

```
提督 0/1/2 的 +0x09 = [255, 255, 255]
```

**寫進去了，畫面還是空的。** 所以那一支篩選器不是清單空掉的原因。
