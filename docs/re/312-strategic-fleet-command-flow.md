## 結論

玩家派艦隊的入口**不在戰略命令選單裡**，在戰略地圖介面右下角的「艦隊」
分頁：點清單的一列就開那支艦隊的視窗，視窗右下角三顆鈕 作戰／變更／結束。
「作戰」拉出五項 移動／占領／駐留／輸送／待命，前四項接著把地圖露出來讓
玩家點目的地（地圖依可達性重新著色），點了跳確認框「要移動至帝國軍亞爾提那
星系嗎？」，按「決定」就把目的地寫進艦隊記錄 `+0x07`、動作碼寫進 `+0x08`，
關掉視窗回到地圖，清單那一列多一個小圖示。

```
戰略地圖介面
  └─ 右下角「艦隊」分頁，點第 N 列（內容區熱區 0BEE[0]）
       06E8:01E8 → [ds:9582]＝0AD0:01B6(x,y) → 0AD0:0272(列) → 0DEA:0003(艦隊索引)
       └─ 艦隊視窗（27×19 格，內容 25×17，鈕在 21C0：作戰／變更／結束）
            ├─ 結束、右鍵 → 回地圖
            ├─ 變更 → 兩項小選單 副官／編組（本輪只看到、沒讀）
            └─ 作戰 → 五項選單 移動／占領／駐留／輸送／待命（反白跟游標）
                 ├─ 右鍵、點在項目外 → 關選單
                 ├─ 移動／占領／駐留／輸送 → 0DEA:12CC → 113A:0003 目的地選取
                 │     地圖露出來、依允許表著色；左鍵點星域：
                 │       不在允許表 → 「這是無法前往的星系。」（確認）
                 │       在允許表   → 「要<動詞>…星系嗎？」 中止／決定
                 │     右鍵 → 回艦隊視窗
                 │     決定 → 艦隊[+0x07]＝目的地、[+0x08]＝動作碼 → 090A:0E6D → 回地圖
                 └─ 待命 → 0DEA:1320「指定待命行星」（行星清單，本輪只看到）
```

## 一、清單那一列怎麼變成艦隊視窗（proven）

主畫面的事件分派 `06E8:01E8` 對右下角那塊做命中測試（清單 `ds:0BEE`、視窗
`ds:9518`），動作碼 0 是內容區（cell (0,7) 18×5），1–4 是四個分頁。內容區
命中之後**經兩個函式指標**分派：`[ds:9582](x, y)` 再 `[ds:957E]()`，
最後 `341B:02E5(9518)` 重畫。艦隊分頁裝的是 `0AD0:01B6`／`0AD0:002A`；
換分頁時 `04F8:05ED` 會換掉這兩個指標（沒讀）。

`0AD0:01B6(x, y)`：`341B:044A` 把滑鼠座標換成視窗 9518 的格子，
列 7–11 且欄 < 17 → `0AD0:0272(列 − 7)`；欄 17 列 7／11 → `0AD0:0236(0／1)`
（清單上下捲）。

`0AD0:0272(列)`：`索引 = ds:9593（捲動位移）＋ 列`，`≥ ds:9592（筆數）`就
什麼都不做；否則把那一列反白（`3603:00DB(9518, 0x20, 0, 列＋7, 0x11)`），
呼叫 **`0DEA:0003(ds:9594[索引])`**（`ds:9594` 是這一格星域的自軍艦隊
索引清單，由 `0AD0:0000` 用 `297B:131C(&9594, 星域, 1)` 填），回來再把
反白還原（`0x80`）。

`0DEA:0003(艦隊索引)`：`0DEA:0040(艦隊)` 開視窗並印內容、
`0DEA:0F33(艦隊)` 是視窗的互動迴圈（命中測試呼叫點 `0DEA:0FA1` 用清單
`ds:21C0`）、`0DEA:0F16()` 收尾。

### 執行器的坑

`-load-state` 之後 `-clicks` 一律沒反應，而 `AX=3` 的輪詢看得到按鍵
——**存檔沒有帶 `AX=000Ch` 登記的事件常式**，而這個遊戲的按下只從事件回呼
進去（`docs/re/09`）。症狀與「點的位置不是熱區」一模一樣。修在 dosgolem
`b5485eb`（規格 004 §4.18）；判準是報告裡「int 33h 事件常式 … 送出 […]」
那一行要在。**用舊狀態檔做的點擊實驗都不算數**——查過 `docs/`，本輪之前
沒有任何文件引用「`-load-state` ＋ 點擊」的收據（`docs/playtest/011` 的
`-load-state` 只配 `-poke`），`workplace/oracle/s3data-scroll-*` 那批探索
輸出沒被任何結論引用，所以沒有東西要重錄。

### 滑鼠座標是 640×400 的

事件回呼與命中測試拿到的是驅動程式的 0–639 × 0–399，畫面是 640×480，
**畫面 y ＝ 滑鼠 y ＋ 40**（`docs/internals/31`：640×400 置中）。
`cmd/play` 的座標已經是畫面座標（`move 300 210` ↔ 收據 `300:170`），
本文以下**收據旗標用滑鼠座標、版面用畫面座標**，兩者只差 y 的 40。

熱區 → 畫面：`x ＝ (視窗[+5] ＋ 1 ＋ 格x) × 16`、`y ＝ 40 ＋ (視窗[+6] ＋ 1 ＋ 格y) × 20`
（`docs/internals/23` 的規則，換成格子寫）。艦隊視窗的結構在 `7944:0006`

## 三、作戰選單與分派（proven）

五項在視窗右下 (464,300)–(527,419) 那塊小框，項目字串 `ds:21F0` 起
（移動／占領／駐留／輸送／待命），一項一列 20 像素，滑鼠座標 y 260／280／
300／320／340 起各 20；反白跟著游標走（`fcmd-menu` 停在第三項、
`fcmd-menu-hover` 移到第一項）；點在項目外或右鍵只關選單（`fcmd-menu-rclick`）。

選了第 n 項之後的分派（`0DEA:11xx`，反組譯 `fcx0DEA-b.txt` +8A73 起）：

| 項目 | n | 做什麼 | 決定之後 `+0x08` | 收據 |
|---|---|---|---|---|
| 移動 | 0 | `0DEA:12CC(艦隊, 0, "移動至")` → 目的地選取 | **0** | `fcmd-done`：`+0x07 FF→02`、`+0x08 05→00` |
| 占領 | 1 | 同上，動詞「占領」；允許的是**敵方與中立**星域 | （沒錄到決定）| 對自己的星域 →「這是無法前往的星系。」；對費沙先跳參謀警告「占領費沙自治領地可能會導致費沙的經濟力流向同盟軍。」（`ds:2F06`）|
| 駐留 | 2 | 同上，動詞「駐留在」 | **2** | `fcx-act-305`（探索批次） |
| 輸送 | 3 | 同上，動詞「輸送物資至」 | **3** | `fcx-act-322` |
| 待命 | 4 | `0DEA:1320(艦隊)`「指定待命行星」：列出**現在位置**的行星 | 5，`+0x07` ← 回傳值 | `fcx-standby-alt`（只看到畫面） |

動詞表 `ds:22CE`（五個 far 指標 → `22A8` 移動至／`22AF` 占領／`22B4` 駐留在／
`22BB` 輸送物資至／`22C6` 待命於）。

`0DEA:12CC(艦隊, n, 動詞)`：n ＝ 1 時允許的擁有者是 `(3982:0250(陣營) ＝ 敵方, 2 ＝ 中立)`，
否則 `(自己的陣營, 0xFF)`；再呼叫 `113A:0003`。

回來的目的地 r：
- `r == 0xFF`（取消）：不動。
- `r == 艦隊[+0x06]`（點的是現在位置）：`+0x08 != 5` 就寫成 `5`、`+0x07 ← 0xFF`
  ——**點自己所在的星域 ＝ 取消既有命令**（確認框的動詞換成「待命」，`fcmd-self`）。
- 否則 `+0x08 ← n`、`+0x07 ← r`。
- 有改就 `0DEA:03F9`／`0DEA:04C0` 重印視窗內容、`341B:02E5` 重畫，回 1 給
  `0DEA:0F33` 的迴圈，迴圈接著關窗（`fcmd-done` 直接回地圖；那一步沒細讀）；
  沒改（取消）就 `341B:02A3(艦隊視窗)` ＋ `3958:0215(頭像)`——**`341B:02A3`
  是「把視窗提到最上層重畫」不是關窗**（strong inference）：目的地選取進場時
  對地圖視窗 `ds:F144` 與左下角 `ds:953A` 各做一次，地圖就蓋住艦隊視窗的
  左半、右半照舊露著（`fcmd-pick`）；取消時對艦隊視窗做一次，整張視窗回來，
  頭像不在字元平面上所以另外補畫（`fcmd-pick-rclick`）。
- 結尾一律 `090A:0E6D`（未安定度重算的共同尾端，`docs/re/310` 的 `0EF0:025E`
  就是這裡）。

## 四、目的地選取（proven）

`113A:0003(艦隊, 擁有者A, 擁有者B, 動詞)`：

```
ds:9884 ← 動詞；ds:9888 ← 艦隊[+0x06]（現在位置）
113A:00BE(艦隊, &允許[32], A, B)          ; 建允許表 ＋ 地圖重新著色
迴圈：3765:0036(&事件)                     ; 等滑鼠事件
    左鍵 → r = 113A:01AB(x, y, &允許)；r != 0xFF 就結束
    右鍵 → 結束（r = 0xFF）
    移動 → 113A:02DB(x, y)                 ; 游標底下的星域摘要（左下角那塊）
3705:0349(0)、3705:0284(ds:9588)、3705:0418()   ; 地圖畫回原樣
```

`113A:00BE`：先 `341B:02A3(ds:F144)`、`341B:02A3(ds:953A)`（把地圖視窗與
左下角摘要提到最上層，地圖才露出來），再 **`2B99:0392(艦隊[+0x06], 艦隊[+0x01], &允許)`** ——
與戰略 AI「從首都走得到嗎」同一支（`docs/spec/043`），只是起點換成艦隊
現在的星域。然後對 32 格：

```
允許[i] ＝ 可達[i] 且（擁有者[i] == A 或 == B 或 i == 現在位置）
顏色：i == 現在位置 → ds:2DA6[擁有者] ＝ {06, 05, 07}
      允許[i] == 0  → 3
      否則          → ds:2DAA[擁有者] ＝ {01, 0C, 07}
3705:03FD(顏色, i)
```

所以移動只能去**自己的**星域，但距離不限（伊謝爾倫也行，`fcx-mv-iserlohn`），
只要在 k ≤ 1 的可達表裡；費沙（中立）與巴拉特（敵方、走不到）都回
「這是無法前往的星系。」（`fcmd-far`）。

`113A:01AB(x, y, &允許)`：`341B:039D(x,y)` 找最上層視窗，不是地圖視窗
`ds:F144` 就回 0xFF（點在地圖外沒事）；`3705:00DC(x,y)` 換成星域，0xFF 也回；
`允許[星域] == 0` → `3826:0005(0, 0x97, ds:2DDC)`（只有「確認」的訊息框）回 0xFF；
`1213:0003(星域) == 0` → 回 0xFF（**沒讀**，本輪三個目的地都非零）；
`113A:023B(星域) == 0` → 回星域，否則 0xFF。

`113A:023B(星域)`：動詞 ＝ 星域 == 現在位置 ? `ds:2DF1`「待命」 : `ds:9884`；
`3ACA:001B` 用 `ds:2DF6`「`要%s\x03[%d,%s\x03[%d,%s星系嗎？  \n`」排版
（第一個顏色 ＝ `ds:6092[擁有者] | 0x90` ＝ 帝國 0x96／同盟 0x95／中立 0x97、
陣營名 `ds:60AE[擁有者]`、第二個顏色 0x97、星域名），`3826:0005(1, 0x97, 字串)`
是 中止／決定 兩顆鈕的訊息框，回 0 ＝ 決定。

### 7.1 底線畫在格子的最後一列

那一列、色 15。`docs/internals/25` 早就寫了「格子最後一列整條填色 15」，

40 個半形空白 ＝ 20 格；其餘四列是 `%50s` ＝ 25 格整列。底線旗標是
**寫進格子的**：`待命中` 三個字後印在列 7，樣式仍是 `0x01`。

### 7.2 清單那一列的反白

### 7.5 飛彈／戰鬥機百分比（`0DEA:06FE`，反組譯 `fcx0DEA-win.txt` +805E）

```
對 +0x0F 組：艦艇 = 池[組[0..1]]（78 bytes）；艦種列 = ds:4E3A + 陣營×0xD0 + 艦艇[+4]×0x1A
    艦種列[+0x0E] != 0xFF：飛彈上限 += 艦種列[+0x10] × 艦艇[+8]（艘數）；現量 += 艦艇[+0x0E..+0x11]
    艦種列[+0x12] != 0xFF：戰鬥機上限 += 艦種列[+0x14] × 艦艇[+8]；現量 += 艦艇[+0x12..+0x15]
上限 == 0 → 印 ds:2513「----」；否則 現量×100÷上限（3CC9:0009 乘、3CC9:0020 除）用 ds:250C「%3ld%%」
```

remake 目前的編制沒有每組的現量欄位，新編艦隊現量 ＝ 上限（印 100%）；
打過仗的艦隊要對上得把艦艇記錄的 `+0x0E`／`+0x12` 帶進 `FleetGroup`，
列在 `docs/spec/051` 的已知差異。

### 7.6 作戰選單五項的啟用規則（`0DEA:1037`，`fcx0DEA-loop.txt` +8997；讀自程式碼，收據只覆蓋全開那一種）

`ds:220A` 起每項 6 bytes、第一個 byte 是啟用旗標，先全設 1，再：

```
星域 = 艦隊[+0x06] 那一格
若 星域[+0x13] & 6（有戰鬥）或 星域[+0x12] != 艦隊[+0x01]（不是自己的星域）：
    項 1–4（占領／駐留／輸送／待命）← 0，只剩「移動」
若 艦隊[+0x00] & 1：項 1（占領）與項 3（輸送）← 0
3667:0004(&選單, ds:220A, 欄 0x1D, 列 0x0C, 5 項, 寬 2, 9, 色 0x97, 反白 0x27, 停用色 0x98)
341B:0145 畫；[+0x1C] ← 0xFF；3667:00F2 跑（回選到第幾項，0xFF ＝ 取消）；3667:00CB 關
```

本輪收據裡艦隊都停在自己的首都、`+0x00 ＝ 0`，五項全開；停用項印什麼色、
點了有沒有反應都沒錄——歸 issue #41。

### 7.7 左下角與右側面板都是「寫進去那一刻」的文字

三張收據把兩塊面板的更新時機定下來：

| 收據 | 左下角 | 右側首都摘要 |
|---|---|---|
| `dec1`／`fcmd-pick`（游標在星圖外）| 瓦爾哈拉 **艦隊 0：0** | 艦隊 0：0 |
| `fcmd-hover-home`（`dec1` 之後游標移到瓦爾哈拉）| 瓦爾哈拉 **艦隊 1：0** | 艦隊 0：0 |
| `fcmd-self`（選取時點瓦爾哈拉）| 瓦爾哈拉 艦隊 1：0 | 艦隊 0：0 |

而星域 0 的記錄 `+0x28`（線性 `5F2F4`）在 `fcmd-base`（＝ `dec1`）就已經是
**1**（探索批次 `fcx-peek-base`：`-load-state fcmd-base.state -steps 421000000
-peek lin:5F2F4:4` → `01 00 00 00`）——建艦隊那一刻就重數過了。所以
「0：0」不是記錄沒更新，是**面板沒重印**：左下角那塊是艦隊編成那幾張畫面
在編成**之前**寫上去的，右側面板是回合開頭印的；游標移過去重寫的那一次
才讀到新的數。remake 因此把兩塊都改成快照（`Game.hoverSnap`／
`capitalSnap`），只在「原版會重印」的時機重算。

### 7.8 左下角重寫的判準是「游標底下那一格變了」

`docs/re/284` 的規則四「從別的畫面回到地圖介面的那一次輸入不重算」在
`fcmd-win-rclick` 上不成立：艦隊視窗上按右鍵 (300,240) 回地圖，左下角換成
游標底下的艾流塞拉；同一個視窗按「結束」(490,350) 回來的 `fcmd-close`
仍是首都。兩張的差別只有游標在不在星圖上。把 `dec1`（回地圖、游標在
星圖外、那塊不變）一起看，唯一同時成立的規則是：

> 地圖迴圈記著上一次量到的「游標底下那一格」（星圖外 ＝ −1）；
> 這一次量到的與上一次相同就不重寫，不同才把那塊改寫成新的那一格
> （或清空）。畫面自己寫進去的內容不動這個記憶。

`dec1` 與 `fcmd-win`／`fcmd-close`：上一次是 −1（進子畫面前游標在命令列），
這一次還是 −1 → 不動。`fcmd-win-rclick`：−1 → 30 → 重寫。目的地選取
（`113A:0003`）是另一個迴圈，**記憶是自己的、從 −1 起算**：`fcmd-pick`
進場游標在星圖外不動；`fcmd-confirm`／`fcmd-far`／`fcmd-self` 點到哪格寫哪格；
`fcmd-cancel` 按「中止」回到選取，游標在框上（星圖外）→ 2 → −1 → 清空；
`fcmd-done` 按「決定」回**地圖迴圈**，用回地圖迴圈的記憶（仍是 −1）→ 那塊
留著亞爾提那。remake：`Game.hoverProbe` 與 `fleetCmd.probe`。
