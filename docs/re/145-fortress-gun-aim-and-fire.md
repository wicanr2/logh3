# 要塞砲：`+0x50` 是瞄準的方位，不是鎖定的目標

行星選單第四項「要塞砲」按下去之後會發生什麼，先前只讀到「寫兩個欄位就
結束」。這一輪把兩端都讀完了：玩家在瞄什麼、每回合誰去開火、電腦怎麼
決定要不要開。

## 出發點：誰讀 `+0x45` 與 `+0x50`

用 `tools/scripts/field_xref.py` 掃整份程式碼傾印（`workplace/codeall.bin`，
線性 `0x09000`–`0x3E000`），找 `mod=01` 且基底是 `bx`／`si`／`di` 的
`disp8` 存取——`bp` 是堆疊框，排掉才看得見結構欄位。`+0x45` 二十處、
`+0x50` 十處，其中五處立刻認得出來：

```
lin 22672  cmp  es:[bx+45],0      ; 2264:0032
lin 22679  dec  es:[bx+45]        ;   ↑ 同一支，每回合減 1
lin 18560  cmp  es:[bx+45],3      ; 181B:0385，==3 就呼叫 2264:0248
lin 22740  mov  es:[bx+50],ax     ; 2264:00FA，玩家左鍵
lin 30532  mov  es:[bx+50],ax     ; 303F:0142，電腦
```

三支迴圈的步進都是 `add [bp+n], 52h`——**82 bytes，行星記錄的大小**，
所以走的確實是行星表（`ds:CFF8`／`ds:CFFA` 是表的 far ptr、`ds:CFFC`
是筆數 81）。

> 2026-10-09 補記：`ds:CFFC` 是目前星域切片的筆數（基底狀態 `fcmd-base.state` 實測為 4，星域 0），不是整張表的 81。
> 迴圈只掃切片，見 [`docs/internals/29`](../internals/29-planets-and-economy.md) 與差異測試 `decomp/src/f_2264_000A.c`、`f_20B4_15E1.c`。

## `+0x50` 是角度

`2264:0049` 是玩家那條路：

```
2264:0049(圖形代號, 行星, 游標)：
    2264:0EC3(行星)                       ; ds:A772 長半軸、ds:A774 短半軸
    165F:0A71(長, 短, 0, &x, &y)          ; x,y ← 行星中心 ＋ 焦距偏移
    掛上圖形描述（色 4、種類 2 ＝ 橢圓、傾角 0）
    ds:A76A ← 0                           ; 「上一次的方位」
    loop:
        3765:0036(&事件, 0)
        方位 = 2264:0133(圖形, 行星, 事件)
        左鍵：行星[+0x50] ← 方位；行星[+0x45] ← 3
        右鍵：行星[+0x50] ← 0xFFFF；行星[+0x45] ← 0
```

而 `2264:0133` 做的是：

```
    1588:0362(游標) → 世界座標 (x, y)
    如果 (x,y) 正好是行星佔位框中心（+0x46 ＋ 7、+0x48 ＋ 7）：回舊方位
    方位 = 2BE1:011D(x − 中心x, y − 中心y)        ; atan2，一整圈 256
    方位 == ds:A76A 就直接回（不重畫）
    165F:0A71(長, 短, 方位, &cx, &cy)
    3870:01FC(圖形, 0, cx) / (圖形, 1, cy) / (圖形, 2, 方位)
    3870:00B0(圖形)                                ; 重畫
    ds:A76A ← 方位 ; 回方位
```

**回的是 atan2 的結果，左鍵把它原封不動寫進 `+0x50`。** 電腦那條路把
同一件事講得更白（`303F:00B0`）：

```
    ds:D616 ← 行星[+0x16] ÷ 200 ＋ 80 ; ds:D618 ← ÷ 4
    最佳分數 ← 0 ; 最佳方位 ← 0xFFFF
    for 方位 = 0; 方位 < 256; 方位 += 8:
        行星[+0x50] ← 方位                     ; ★ 直接塞角度
        n = 303F:015C(行星)                     ; 這個方位掃到幾個
        if n == 0: continue
        分數 = 303F:0391(n)                     ; 其中幾個是敵方
        if 分數 ≥ 最佳分數: 最佳分數 ← 分數 ; 最佳方位 ← 方位
    if 分數 × 3 ≥ 敵方總數  或  (敵方總數 ≥ 30 且 分數 ≥ 8)：
        行星[+0x50] ← 最佳方位 ; 行星[+0x45] ← 3
    else:
        行星[+0x50] ← 0xFFFF
```

八格一步掃一整圈、每一步把候選角度寫進 `+0x50` 再問「這樣掃得到幾個」
——一個存「目標編號」的欄位不會這樣用。敵方總數由 `303F:0061` 數
（艦艇池裡 `+0x00` 不等於 `ds:8F1D` 的筆數）。

## 要塞站在焦點上

`165F:0A71(長半軸, 短半軸, 方位, &x, &y)` 只有四行：

```
    c = 3870:0614(長半軸, 短半軸)
    (dx, dy) = (c, 0) 依方位旋轉（3A92:0001，與 rules.Rotate256 同一支）
    *x += dx ; *y += dy
```

也就是**橢圓的中心 ＝ 焦點 ＋ 沿瞄準方位走 c 個像素**，而傳進來的
(x, y) 是行星佔位框的中心。射程因此在瞄準的那一側長、背面短。

`3870:0614` 走 Borland 的 32 位元輔助函式，靜態讀不划算——改用收據量：
長 96、短 24 的那一張量到 **c ＝ 92**，而 √(96² − 24²) ＝ 92.95。
**無條件捨去**，四捨五入會得到 93。

## 曲線是中點圓演算法

`39D7:035E(cx, cy, 長, 短, 色, 傾角)`：

```
    x ← 長 ; err ← 長 ; y ← 0
    while x ≥ y:
        px ← x × 短 ÷ 長 ; py ← y × 短 ÷ 長
        對 (x, py)、(x, −py)、(y, px)、(y, −px) 四組：
            旋轉傾角 → (rx, ry)；與上一次相同就跳過
            畫 (cx ＋ rx, cy ＋ ry) 與 (cx − rx, cy − ry)
        err −= 2y − 1 ; y++
        if err < 0: err += 2(x − 1) ; x--
```

也就是「整數圓 → 另一軸乘 短/長 壓扁 → 旋轉 → 四組對稱點的正負兩端」。
畫是 XOR（EGA 的 Data Rotate 設成 18h），所以**同一個像素畫兩次等於
沒畫**——長 96／短 24 那一張有 4 個點正好被畫兩次。

一整圈只採 256 個角度會在長軸兩端留空隙：那樣產生的 236 個點裡有 91 個
落在沒被畫過的底色上。

## 對拍

兩張收據只差游標位置，其餘完全相同：

| 收據 | 游標（滑鼠） | 世界座標 | 傾角 |
|---|---|---|---|
| `s3fort` | (320, 240) | (1360, 820) | 18 |
| `s3fort2` | (150, 180) | (1190, 760) | 140 |

行星是 S3 的全域第 63 顆（雷奧米爾），poke 成有要塞（`+0x12` ← 1）、
座標移到視野中間 (1280, 780)、`+0x45` ← 0、`+0x50` ← 0xFFFF；防衛力
上限 3300 不動 → 長半軸 96、短半軸 24。焦點 ＝ (1287, 787) → 畫面
(247, 247)。

橢圓是 XOR 上去的，所以**兩張逐像素比出來的差異集合，必須剛好等於
兩條曲線的對稱差**——不必知道底圖長什麼樣。扣掉兩個游標框（游標本來
就移動了）之後：

```
觀察 786 個、預測 786 個、只在觀察 0 個、只在預測 0 個
```

`internal/screen.TestFortressRangeMatchesOracle`。兩個傾角 18／140 都
與 `rules.Atan256(游標世界座標 − 焦點)` 相同。

怎麼重跑：前置序列與 `s3plinfo`（`docs/re/144`）完全相同，只換三件事
——poke 的位址改成 `lin:54571`（行星 63 的 `+0x11`–`+0x51`，內容取自
`workplace/pl63.bin` 再改 `+0x12` ← 1、`+0x45` ← 0、`+0x46`／`+0x48`
← 1280／780、`+0x50` ← FFFF）、最後兩下點擊改成 `247,207`（開選單）與
`247,270`（第四項），再加 `-mouse-x/-mouse-y/-mouse-at` 把游標移到要瞄的
方向。完整旗標在 `workplace/oracle/s3fort*/flags.txt`。

## 開火是回合結算的一個階段

`181B:000A` 是戰場一回合的結算序列，八步：

```
181B:003F   補給／補充（1930:019D、1AAB:006D）
181B:00FA   移動與戰鬥
181B:0262   2526:00F8 兩次
181B:028C   （長，未讀）
181B:0385   ★ 要塞砲開火
181B:03D0   20B4:000C / 20B4:01C1
042F:086B(0)
181B:03F0
```

開火那一步很短：

```
181B:0385：
    對每一顆行星：
        +0x12 == 0 → 跳過                 ; 沒有要塞
        +0x45 != 3 → 跳過
        2264:0248(行星)
```

`2264:0248` 收目標的方式與畫圈的那一支同源：

```
2264:0248(行星)：
    2264:0EC3(行星)                     ; 長短半軸
    n = 2264:02D9(行星)                 ; 收候選，見下
    比較函式 = 行星[+0x11] == 0 ? 2264:052F : 2264:0612
    if n: 3C6A:000D(&ds:A49A, n, 2, 比較函式)      ; qsort
    2264:06F5(行星)                     ; 畫開火動畫（＋「要塞砲發射」訊息）
    if n: 1DD6:0152() ; 2264:080B(行星, n) ; 1DD6:026B()
```

```
2264:02D9(行星)：
    ds:A76E/A770 ← 行星 far ptr
    n1 = 17A0:00AC(0, +0x46, +0x48, 長半軸 × 2, &ds:A49A)
    n2 = 17A0:00AC(1, +0x46, +0x48, 長半軸 × 2, &ds:A49A ＋ n1×2)
    return 17A0:016C(2264:036E, &ds:A49A, &ds:A49A)     ; 用回呼原地篩
```

篩選回呼 `2264:036E(索引)`：艦艇池那一筆 `+0x08` 為 0（沒艘數）或
`+0x04 == 7`（索敵分遣隊）就淘汰，否則呼叫 `2264:03D9` 做橢圓判定，
結果寫進艦艇 `+0x3C` 並當回值。

`2264:03D9(行星, 艦艇)`：

```
    d  = 3310:0006(行星x, 行星y, 艦艇[+0x34], 艦艇[+0x36])     ; 32 位元距離
    θ  = 2BE1:011D(艦艇x − 行星x, 艦艇y − 行星y)
    Δ  = 2BE1:024A(θ, 行星[+0x50])        ; 兩個 byte 角度的正差
    return 2264:047C(d, Δ, 長半軸, 短半軸)
```

`2264:047C` 算的是**以焦點為極點的圓錐曲線**：查 `ds:573A` 拿
`cos Δ`，算 `1 − e·cos Δ`，再拿半正焦弦除它，與 `d` 比大小。細節走
Borland 的 32 位元輔助函式（`3CC9:*`、`39B5:*`），還沒逐行讀完，
所以判定式先標 **strong inference**：形狀（焦點極坐標）由畫出來的
橢圓中心偏移佐證，係數還沒量過。

電腦那條路的判定在 `303F:0221`，骨架相同，但量的是**艦隊**的座標
（`ds:C074` 那張表的 `+0x74`／`+0x76`），而且只查敵方陣營
（`3982:0250(ds:8F1D)`），也不檢查艘數。

## `+0x45` 是倒數，不是旗標

`2264:000A` 每回合跑一次，與其他三支收尾常式排在一起：

```
12CE4：25DB:0A5C() ; 2526:000E() ; 1930:000B() ; 1AAB:000E() ; 2264:000A()
```

```
2264:000A：
    對每一顆行星：
        +0x12 == 0 → 跳過
        +0x45 == 0 → 跳過
        +0x45--
```

配上右側面板那三句（`1D9E:0160`，字串在 `ds:436B`／`ds:4376`／`ds:4389`）
就完整了：

| `+0x45` | 面板 | 意思 |
|---|---|---|
| 3 | 要塞砲發射 | 下一次結算就開火 |
| 2、1 | 要塞砲填充　%1u 回 | 填充中 |
| 0 | 要塞砲待命中 | 可以重新瞄準 |

所以「只有 0 或 3 能重新瞄準」（`1D9E:0247`）的意思是：**還沒瞄、或
瞄好還沒打，可以改主意；打完的兩回合填充期間不能動。**
