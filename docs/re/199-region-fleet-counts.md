# 199 — 星域記錄 `+0x28`／`+0x29` 是兩個陣營在那一格的艦隊數

`docs/re/197` 讀完 `2E54:005D` 的 bit0 那一路之後留下一個未解的欄位：

```
參 = (ds:8F1D == 0) ? 星域[+0x29] : 星域[+0x28]
… 參 != 0 → 往首都退一格
```

`星域[+0x28]`／`+0x29` 當時只寫「一對以陣營分的欄位，語意未解」。

**答案早就在 `docs/re/40` 裡。** 那一輪反組譯過重數艦隊的迴圈
（`2703:087A` 清零、`2703:08CE` 遞增）：

```
mov es:[bx+29],al / mov es:[bx+28],al   ; 32 個星域的 +0x28、+0x29 ← 0
…
mul 7E / add si,A79C                    ; → 該艦隊所在星域的記錄
add si,28
mov al,es:[di+01]                       ; +0x01 ＝ 陣營
add si,ax                               ; +0x28 ＋ 陣營
inc byte es:[si]
```

`+0x28 ＋ 陣營`——**`+0x28` 是帝國、`+0x29` 是同盟，那一格有幾支艦隊**。
`2E54:005D` 的「參」因此是**敵方在這一格的支數**。

## 兩份數出來的佐證

### 一、25 份記憶體傾印：800 格對 799 格

執行期星域記錄在 `ds:A79C`（32 × 126），艦隊表在 `ds:C074`（32 × 122，
`+0x04` 是 `0xFF` ＝ 沒在用、`+0x01` 陣營、`+0x06` 所在星域）。
把艦隊表數出來的「每格各陣營幾支」拿去比 `+0x28`／`+0x29`：

| | |
|---|---|
| 1 MB 傾印 | 25 份 |
| 星域格 | 800 個 |
| `(+0x28, +0x29) == (帝國支數, 同盟支數)` | **799** |
| 不符 | 1（`openmem`）|

唯一不符的 `openmem` 是遊戲本體還沒被 EXEC 起來的那一份——艦隊表整片
沒有初始化，`+0x04` 一個 `0xFF` 都沒有，所以「數出來 32 支都在星域 0」
不是局面而是雜訊。

### 二、三個劇本的資料檔：96 格全對

`FLEET.DT[89A]` 與 `STELLAR.DT[89A]` 是同一個劇本的兩份檔，版面與執行期
相同（`docs/internals/33`、`docs/internals/22`）。同樣數一次：

| 劇本 | 在用艦隊 | 32 格相符 |
|---|---|---|
| `DT8` | 26（帝國 13、同盟 13）| **32／32** |
| `DT9` | 18（帝國 11、同盟 7）| **32／32** |
| `DTA` | 18（帝國 12、同盟 6）| **32／32** |

`DT8` 的 26 支正是 `docs/re/194` 數過的那 26 支，帝國同盟各半。

## 於是 `2E54:005D` 的那一條讀得出來了

```
參 = 敵方陣營在這一格的艦隊數
```

`ds:8F1D == 0` 是帝國在跑，敵方是同盟 → 讀 `+0x29`；
同盟在跑就讀 `+0x28`。整條規則因此是：

> `+0x00` bit0 有設的艦隊，**這一格有戰鬥、有敵方艦隊、或不是自己的，
> 就往首都退一格**；三個條件都不成立才原地出擊。

三個條件都在講同一件事——「這一格現在安不安全」。

## `+0x2A`／`+0x2B` 沒有一次非零

25 份傾印的 800 格、三個劇本的 96 格，`+0x2A` 與 `+0x2B` **全部是 0**。

這與 `docs/re/31` 的收據 `pnlFLT` 有一個對不上的地方：那一份把
`lin:5F2F4`（星域 0 的 `+0x28`）四個 byte 注入成 `0C 22 07 63`，
面板印出 `12：99` ——12 是 `+0x28`、99 是 `+0x2B`。也就是說**帝國玩家的
面板讀的是 `+0x28` 與 `+0x2B`，而遊戲維護的是 `+0x28` 與 `+0x29`**，
於是正常局面下面板的敵軍欄永遠是 0。

兩份證據各自都是一手的（一份是注入後的實測，一份是 121 份真實局面），
所以不是誰推翻誰。可能的解釋是 `+0x2A`／`+0x2B` 是「對方看得到的那一份」
——`docs/internals/22` 已經記著這一組有 `0xFF` ＝「看不到」的語意——
只在某個條件下才被填。**沒有證據，標假設待驗**；要分辨得拿一份
「敵方艦隊在自己看得到的星域裡」的局面去開面板。

## 實作

- `rules.RegionFleets(record, faction)` 讀 `+0x28`／`+0x29`。
- `ai.DecisionInput.EnemyFleets` 接上它，`DecisionPass` 補上 bit0 那一路
  （原地出擊 vs 退一格）與 `+0x08 == 4` 的跳過分支——這一趟之前只實作了
  bit0 沒設的那一條。
- `rules.Fleet` 補 `Flags`（`+0x00`）與 `Move`（`+0x08` 原值）。
  `Parked` 留著不動，它是 `Move == 5` 的簡寫，別處在用。

## 兩條方法

**寫「語意未解」之前先 grep 自己的 `docs/`。** 這一格的寫入迴圈在
`docs/re/40` 就整支反組譯出來了，`add si, 28` ＋ `add si, 陣營` 白紙黑字
——而 `docs/re/197` 仍然把它記成未解，於是後面每個讀到那一行的人都
會再查一次已經有答案的東西。**觸發時機是「正要把某項寫成未解」那一刻**，
不是稽核的時候。

**要驗一個「這格記的是什麼」的斷言，先去數，不必先去反組譯。**
兩份佐證都只是「把另一個地方已經知道的東西數一遍，看兩邊等不等」，
成本各是一支二十行的腳本。反組譯給的是機制，數出來的給的是覆蓋率
——895 格全對，比一段對得上的組合語言更難用巧合解釋。
