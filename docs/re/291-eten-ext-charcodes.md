## 1. 結果（confirmed）

`GRAPH.IMG` 的擴充區是 **Big5 `0xC6A1`–`0xC8D3` 共 365 個碼位**，
連續存放、不跳號：

```
offset = 16080 + (big5_index(code) - big5_index(0xC6A1)) * 30
```

worklist 問的那 302 格（`0x4632`–`0x6996`）是這 365 格的後段，
對應 `0xC6E0`–`0xC8D3`：`々〆〇ー［］✽` → 平假名 83 → 片假名 86 →
西里爾大寫 33 → 西里爾小寫 33 → 筆畫字根 13 → 數字合字 40 →
`￢￤＇＂㈱№℡`。前 63 格（`0xC6A1`–`0xC6DF`，`①`–`⑩ ⑴`–`⑽ ⅰ`–`ⅹ`
與部首）以前被算進「全形符號區的 471 格」裡，符號區其實只有 408 格。

## 2. 三條互相獨立的證據

**其一：程式自己的常式。** `ENDING.EXE` 是未打包的 MZ，字型 seek 常式
在檔案位移 `0x0D03`–`0x0E08`，`int 21h` AH=42h／AH=3Fh 各一次，每次
讀 30 bytes。分派那一段（`0x0D4B`，簽章 `50 53 51 52 8B C2 33 D2 86 C4 2C A1`）
把 `(前導序, 後隨序)` 併成一個 word 直接比大小，四條路的界線與基準：

| 比較 | 碼位 | 基準 |
|---|---|---|
| `cmp ax,025Dh` | `A140`–`A3BF` | `add ax,0F00h` ＝ 3840 |
| `cmp ax,2563h` | `A3C0`–`C6C5` | `sub ah,3` ＋ `add ax,6996h` ＝ 27030 |
| `cmp ax,2771h` | `C6C6`–`C8D3` | `sub ax,25A2h` ＋ `add ax,3ED0h` ＝ 16080 |
| 前導 ≥ `C9`，`cmp ax,309Ch` | `C940`–`F9FE` | `mov dx,1519h` ＝ 5401 ＋ 27030 |

`3ED0h` ＝ 16080 ＝ `3840 + 408*30`，`1519h` ＝ 5401 ＝ `6280-471-408`。
`sub ax,25A2h` 在併起來的表示上做減法，效果就是
`序號 − big5_index(0xC6A1)`——**基準碼位是 `C6A1`，不是 `C6E0`**。

**其二：拿原版自己的文字位元組走一遍。** `ENDING.EXE` 文字區
（`0x63FE`–`0x765C`）有兩行用到擴充區。把整行的原始位元組經上面的公式
查字型、畫成點陣（`text` 模式，圖在 `workplace/assets/font/knx-ending-lines.png`）：

```
@0x6A9F  … C7DB C7E5 A3B8 C7B4 C7E1        → Music Composition  ミラㄧジュ
@0x6E83  … C7B4 C7DF C7CD C7EF A144
           C7A9 C7C2 C77D C7D1 C77D C7E7 C7DC
                                            → (C)1988 田中芳樹．德間書局．
                                               德間ジャパン．キティフィルム
```

13 個相異的假名碼位，畫出來全部是該碼位在 ETen 表上的字，而且
`德間ジャパン`、`キティフィルム` 是真實存在的公司名。

**其三：兩端都用字形釘死。** `#0` 是 `々`、`#301` 是 `℡`，
`C6E0` 與 `C8D3` 各自對得上。中間 365 格照碼位連續排，任何一格錯位
兩端就對不上；而 `big5hkscs`（ETen 擴充表）認得的 319 格，逐格與點陣相符
——包含 `C876`–`C8A4` 那 13 個筆畫字根（`㇏𠃌乚𠂊刂䒑龰冈龱𧘇`），
那一段 HKSCS 與 ETen 的指派碰巧一致，正好當正對照。

## 3. 前一輪為什麼把 `C6A1` 的假說排除掉

`docs/internals/06` 舊文記「已排除『以 Big5 `0xC6A1` 為起點連續存放』
——依該假說算出的 `ジ`(`C7B4`) 位置實際上是西里爾大寫」。

那個假說是對的，錯的是**它把 `C6A1` 對到 `0x4632`**。真正的對應是
`C6A1` → 16080，`0x4632`（17970）是 `C6E0`。兩者差 63 格：
`ジ` 依舊假說算出序號 176，而序號 176 是 `Ж`——西里爾大寫。
`176 − 63 = 113`，113 才是 `ジ` 的正確序號。

**看起來被否證的假說，其實只差一個基準常數。** 當初的作法是從
「302 格從 `0x4632` 開始」反推碼位；這一輪反過來，先去程式裡找基準常數，
再驗字形。字形與版面都是二手推論，程式裡的立即數才是一手的。

## 4. `C6A1`–`C6DF` 那 63 格（強證據）

位移 16080–17970 的 63 格，畫出來是 `①②③④⑤⑥⑦⑧⑨⑩ ⑴`–`⑽
ⅰ`–`ⅹ 丶丿亅亠冂冖冫勹匸卩厶夊宀巛巜广廴彐彡攴无疒癶辵隶
¨ˆヽヾゝゞ〃仝`（`presym` 模式，圖 `knx-presym.png`），數量剛好填滿
符號區末端到 `0x4632` 之間，公式的基準也指向 `C6A1`。

但 `ENDING.EXE` 那支常式吃不到 `C6` 前導位元組：`sub ax,25A2h` 的後隨序
最大 156（`0x9C`）永遠小於 `0xA2`，前導序被多借掉 1，前導是 `C6` 時
前導序變成 `0xFF`，算出來的位移遠超過檔案長度；而 `C6A1`–`C6C5`
更早就被 `cmp ax,2563h` 收進漢字那一路（會畫出 `C940` 起的字）。
所以**這一份執行檔實際只畫得出 `C740`–`C8D3`**。版權行只用片假名，
缺陷不會顯現。`GIN3PS.EXE` 有 GLUE 外殼，它那一份還沒查——
所以這 63 格的字碼對應標**強證據**，不是 confirmed。

## 5. 沒解出來的：`C8A5`–`C8CC` 那 40 格（未知）

左半是粗體阿拉伯數字 0–9（垂直位置隨右側符號變動，所以左半 8 欄有
20 種圖樣），右半是橫線／豎線／帶橫槓的小方框等 16 種小符號。
ETen 與 HKSCS 表都查無。遊戲的文字裡沒有用到這一段，對 remake 沒有影響，
但**它們代表什麼字仍然未知**，字型要重畫時只能照點陣複製。

舊文說擴充區裡有「框線」與「圈號」、末尾是「`㊣No.正`」——整份 365 格
裡沒有框線字元；圈號在 `C6A1`–`C6BE`（前 63 格那一段），末尾三格是
`㈱№℡`。

## 6. 一個副產品：長音記號

`Music Composition` 那一行的第三個全形字是 `A3B8` ＝ 注音符號 `ㄧ`，
不是片假名長音符 `ー`。字型裡有 `ー`（`C6E3`，`presym` 之後的第 4 格），
畫出來與 `ㄧ` 幾乎一樣。所以那是中文化當時的輸入或排版取捨，
不是字型缺字。

## 7. 怎麼重跑

```
tools/py.sh tools/scripts/kana_charcodes.py checks    # 八項結構檢查
tools/py.sh tools/scripts/kana_charcodes.py emit      # 重出 365 筆對應表
tools/py.sh tools/scripts/kana_charcodes.py text      # 重畫版權行
tools/py.sh tools/scripts/kana_charcodes.py presym    # 前 63 格（C6A1–C6DF）

```

`sheet` 與 `art` 的序號是**後 302 格**的序號（0 ＝ `C6E0`），
前 63 格走 `presym`。

`checks` 會印 365 格字形的 SHA-256
（`564e99411ce03cb11922d867dce24f8ac23dda4df17c2cdef362b8b22944e376`，
10,950 bytes）——換 `GRAPH.IMG` 或改公式，這個數就會變。
