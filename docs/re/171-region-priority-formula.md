# 171 — 星域優先度就是「有幾個敵方鄰居」

`docs/re/170` 把 `2E54:019F` 讀完，剩下它每一格呼叫的 `2E54:0222`。
這一輪把算式讀出來，順帶看到 AI 的整條主流程。

## `2E54:0222(星域記錄) → 優先度`

```
敵方 = 1 − ds:8F1D
2B99:03D9(星域[+0x11], &鄰居[…], 星域[+0x12])      ; 取鄰居清單
分數 = 0
對每個鄰居 n（跳過自己）：
    若 星域[n][+0x12]（擁有者） != 敵方：跳過
    若 星域[n][+0x13] bit0 == 0：           分數 += 4
    否則若 ds:D54E[n] > 4：                 分數 += 4
    否則：                                  分數 += 2
回 分數
```

**優先度 ＝ 敵方鄰居的個數 × 4（某些鄰居只算 2）。** 沒有敵方鄰居的內地
是 0，`2E54:0978` 排序時就排到最後——所以 AI 的注意力天然集中在前線。

打折那一條要同時成立兩件事：鄰居的 `+0x13` bit0 有設、而且
`ds:D54E[鄰居] <= 4`。`+0x13` bit0 與 `ds:D54E` 的語意都還沒解，
但兩者一起出現的地方只有這裡與 `2E54:02C2`。

## `2E54:02C2(星域記錄, 陣營) → 0／1`

```
對每個鄰居 n：
    若 星域[n][+0x12] != 陣營：跳過
    若 星域[n][+0x13] bit0 != 0：跳過
    若 ds:D54E[n] != 0：回 1
回 0
```

「有沒有一個屬於<陣營>、`+0x13` bit0 沒設、而且 `ds:D54E` 非 0 的鄰居」。
兩支用的是同一組條件的正反面，所以 `+0x13` bit0 是**鄰居的某種通行性**
（假說：與 `ds:D54E` 一起決定這條邊算不算數）。

## AI 的一回合是兩支相鄰的呼叫

`0x2D121`／`0x2D126` 連續兩個 far call：

```
2E54:000C()      ; 清六張表、逐艦隊決定（2E54:005D）、2E54:1A76、填優先度（2E54:019F）
2E54:0344()      ; 五個階段：
                 ;   2E54:035E()
                 ;   2E54:0EC2()
                 ;   2E54:0725()
                 ;   2E54:08D3()   → 2D54:0000(); 2E54:08E3(); 2E54:0978();
                 ;   2E54:119E()
```

`2E54:0978` 就是 `docs/re/170` 那個「依優先度降冪派兵」的排序器，
在第四階段。

> `docs/re/170` 把那支三行的常式寫成 `2E54:08D2`，正確位址是
> **`2E54:08D3`**（`0x2EE13`；`0x2EE12` 是前一支的 `retf`）。
