# 275 — 從原版自己的 OPL 輸出錄 ＦＭ 配樂

日期：2026-09-11
執行器：dosgolem `docs/spec/190-opl-vgm-dump`（本輪新增，工作副本
`~/cht/dosgolem-logh3`）
狀態：**confirmed**（觸發與錄製逐首實跑；音色忠實度見第六節的限制）

一句話：**`_F` 那一組的音檔現在出自原版驅動送給 OPL 的暫存器寫入**，
不再是拿 MIDI 去套 General MIDI 音色庫。

## 一、為什麼要錄而不是合成

`.MDS` 已經解得夠清楚（`docs/internals/17`），轉成標準 MIDI 再用
FluidSynth 合成聽得出是同一首曲子。但 `_F` 是寫給 OPL 的
（`docs/re/274`：`'f'` 外皮接的是 OPL 播放常式），而 OPL 的聲音來自
**FM 合成的參數**——載波與調變的比率、回授、四段包絡、波形選擇。
那些參數在 `.MDS` 裡是一個音色編號，真正的數值在驅動的音色表裡。
拿 GM 音色庫去合，得到的是「同一首曲子、不同的音源」。

錄的是**驅動實際送進晶片的東西**，所以音色表、聲部配置、力度換算、
顫音這些全都在裡面，不必逐項逆向。

## 二、管線

```
原版 → dosgolem（-dump-vgm）→ VGM → AdPlug（opl2wav）→ WAV → ffmpeg → OGG
```

- 錄：`cmd/probe -dump-vgm`，時間基準是機器自己的 `IRQ0Every × PITHz`
  （dosgolem `docs/spec/190-opl-vgm-dump` §3）。
- 合成：`tools/opl2wav.cpp`（libadplug）。Debian bookworm **沒有**任何
  VGM 播放器，`adplug-utils` 也只裝 `adplugdb`；但 `libadplug-dev` 有，
  而 AdPlug 的 `CAdPlug::factory` 直接認得 VGM。三十行就夠。
- 腳本：`tools/music_fm_capture.sh`，收據寫 `workplace/assets/music/ogg/SOURCES.tsv`。

## 三、觸發：三條路，都不靠運氣

`docs/re/274` 把選曲的兩個位元組釘死了，於是逐首觸發變成一次 `-poke`。

### 3a. `BGM_0F`–`BGM_7F`：寫 `ds:8F34`

`ds:8F34` ＝ 平時配樂曲號，線性位址 `0x54B30 + 0x8F34 = 0x5DA64`
（DGROUP 基底與 `tools/scripts/read_ds_string.py` 同一個）。
輸入腳本沿用收據 `key1` 那一組（兩次點擊跳過開頭動畫並開新遊戲、
`-press 1,3,8,enter` 答防拷問答）：

```
-tick 20000 -clicks 40000000:300:170,95000000:300:170
-press 1,3,8,enter -press-at 105000000 -press-every 2000000 -click-hold 3000000
-poke lin:5DA64@117022200=<曲號>
```

八個曲號逐一實跑，開的檔逐一對上：

| poke 值 | 原版開的檔 |
|---|---|
| 00 | `BGM_0F.MDS` |
| 01 | `BGM_1F.MDS` |
| 02 | `BGM_2F.MDS` |
| 03 | `BGM_3F.MDS` |
| 04 | `BGM_4F.MDS` |
| 05 | `BGM_5F.MDS` |
| 06 | `BGM_6F.MDS` |
| 07 | `BGM_7F.MDS` |

**兩首戰鬥曲不必打到戰鬥。** 設定選單只讓玩家在 `0`–`5` 之間挑，
但 `play_music(0)` 是把 `[8F34]` 原封不動當成 `bgm_%1d%c.mds` 的 `%1d`
（`docs/re/274` §4），所以寫 6／7 就直接載入戰鬥曲。實跑證實。

### 3b. poke 的時間窗很窄，而且窗口不是監看找到的

音樂模組初始化會把 `[8F34]` 清成 0。實跑掃出來的窗口：

| poke 步數 | 結果 |
|---|---|
| 116,000,000 | `BGM_0F`（被清掉）|
| 117,000,000 | `BGM_0F`（被清掉）|
| **117,022,200** | **照 poke 的值** |
| 117,023,000 | `BGM_0F`（檔名已經 `sprintf` 完了）|

⚠ **那個「清成 0」的寫入在 `-watch` 上看不見。** `-watch` 只印**變化**，
而值本來就是 0，寫 0 不是變化。所以監看整段只看得到

```
[watch] #117022104 5DA63: 00 → 01   ← ds:8F33 設成「ＦＭ」
```

一行，看起來像「沒有人動過 `8F34`」——而 poke 在 116M 就是會失效。
**「監看沒印出來」不等於「沒有人寫」**，寫同一個值的情況它結構上看不到。
窗口是用四個 poke 步數掃出來的，不是推出來的。

改輸入腳本（步數、點擊時刻）就要重掃。

### 3c. `END_1F`／`END_2F`：**還沒走通**

`ENDING.EXE` 的曲號就是命令列第二個數字（`docs/re/274` §9），
所以觸發應該只是 `-args " 9 1"`／`" 9 2"`。實際上錄不到：

- 跑 **2,000,000,000 道指令**（約 172 秒遊戲時間）**沒有開過任何 `.MDS`**，
  寫過的埠裡也**沒有 388／389**。開的是 27 個 `.VO5` 語音檔。
- 加不加 `-empty-env`、加不加 `-adlib` 都一樣。
- 檔案層面：`ENDING.EXE` **有**那兩個外皮（`6A 66` ＝ push `'f'` 在
  `0x31C6`、`6A 6D` ＝ push `'m'` 在 `0x31F0`，與 `docs/re/274` §9 相符），
  也有 `end_%1d%c.mds`（`0xF80C`），**但整支裡一個 `0x0388` 字面值都沒有**
  ——`OPEN.EXE` 有兩處（`0x2065`、`0x21F5`，`mov dx,388h`）。

所以 OPL 埠不是寫死在這支裡的（可能從變數取），或者 ＦＭ 輸出常式
根本不在 `ENDING.EXE` 內。**狀態：未解**，留在 worklist `music-fm-capture`。

（`GIN3PS.EXE` 也搜不到 `BA 88 03`，但那是因為它被 GLUE 壓過；
`ENDING.EXE` 是普通 MZ、字串明碼，搜不到就是真的沒有。）

### 3d. `OPEN_F`：原版永遠不會開它

`OPEN.EXE` 兩個外皮都寫死 `'m'`（`docs/re/274` §8），所以出貨的遊戲
一律讀 `OPEN_M.MDS`，`OPEN_F.MDS` 是死素材。

這裡用**換檔案內容**取得它的 ＦＭ 演奏：暫存遊戲目錄裡把 `OPEN_M.MDS`
換成 `OPEN_F.MDS` 的位元組，原版的 OPL 驅動就會去演奏那份資料。
收據標 `FM(substituted)`。

> **它不是「玩家當年聽到的開頭音樂」。** 玩家聽到的是 OPL 演奏
> `OPEN_M`（＝ MIDI 用的那份資料跑在 ＦＭ 晶片上，那是原版的 bug）。
> 兩者都錄得下來，不要混為一談。

## 四、框曲子只能靠開檔那一刻

一次執行會連放好幾首（開頭動畫的 `OPEN_M` 在前面），暫存器串是接起來的，
中間沒有分隔符。所以 dosgolem 加了 `-vgm-clear-on-open <檔名>`：
開到那個檔時清掉序列，之後收到的就只有那一首。

沒有它的話，`BGM_0F` 的那份 VGM 前面會多出十幾秒的開頭動畫音樂——
而那份檔案完全合法、播得出來、檔名寫著 `BGM_0F`。

`-vgm-clear-on-open` 給了卻沒開到那個檔時，probe **不寫 VGM**。
這樣「poke 的時間窗跑掉」會變成缺檔，不會變成一份內容是別首的音檔。

**而且只切第一次開檔。** 開頭動畫跑完會重播一輪，`OPEN_M.MDS` 因此被開
兩次；「每次都切」留下的是最後那一小段——實測 94 秒變成 **7.2 秒**，
而那 7.2 秒的檔案完全合法、播得出來，只是短得莫名其妙。

## 四之二、量到的東西

| 曲目 | OPL 寫入筆數 | 錄到 | 峰值 |
|---|---:|---:|---:|
| `BGM_0F` | 11,930 | 127.1 s | −20.8 dBFS |
| `BGM_1F` | 11,942 | 127.1 s | −12.6 |
| `BGM_2F` | 2,875 | 127.1 s | −12.4 |
| `BGM_3F` | 10,404 | 127.1 s | −11.3 |
| `BGM_4F` | 6,928 | 127.0 s | −12.3 |
| `BGM_5F` | 10,051 | 127.1 s | −13.5 |
| `BGM_6F` | 17,936 | 127.1 s | −12.3 |
| `BGM_7F` | 9,220 | 127.1 s | −10.9 |
| `OPEN_F` | 4,819 | 101.3 s | −0.4 |

**開頭那一首比遊戲本體那八首高 10–20 dB。** 那不是錄壞：同一支驅動、
同一顆晶片、同一條管線，差別在原版自己寫進 OPL 音量暫存器的值。
（拿未替換的 `OPEN_M` 錄一次也是 −0.7 dBFS，所以與換檔無關。）

**逐位元組可重現**：`BGM_0F` 錄過兩次（中間還改過執行器的
`-vgm-clear-on-open` 語意），兩份 VGM 的 SHA-256 相同
（`fcb09b274c7c8e7d1d8c…`）。同一組輸入序列跑出同一份輸出，
這條路才算得上收據。

音量怎麼處理是**取捨，腳本不替人決定**：`FM_NORM=batch`（預設）
全批共用一個增益，保留曲子之間的關係；`FM_NORM=track` 每首各自推到
−1 dBFS，聽感一致但抹掉那個關係；`FM_NORM=off` 不動。
套用的值記進 `SOURCES.tsv`，`FM_RENDER_ONLY=1` 可以只重算不重錄。

## 五、`-adlib` 不必開（而且本來就沒開）

本作的 ＦＭ 偵測不是標準的 AdLib 偵測序列，是
`in al,388h; and al,F0h; jz 有`。dosgolem 的 `0x388` 讀取預設回 `0`，
對這一支判斷式剛好等於「有 OPL」（`docs/re/274` §11）。所以既有收據
一路讀 `_F`，本輪也沿用不加 `-adlib` ——**要和既有收據走同一條路**。

（加了也一樣：AdLib 存在而計時器沒啟動時狀態埠回 `0x00`，`and F0h`
還是 0。實跑兩種都試過，開的檔與埠清單相同。）

## 六、限制

- **只到暫存器串為止。** 波形要逐樣本一致不在這條路上：合成器
  （AdPlug 的 OPL 核心）不是當年那顆 YM3812。暫存器串是決定性的、
  可以逐筆比；波形不是。
- **錄幾秒是設定出來的，不是曲子的長度。** 曲子會循環，`-steps`
  決定錄多久（1.6 G 道指令 ≈ 135 秒）。循環點沒有偵測，VGM 的
  loop offset 一律 0，由 remake 自己循環播放。
- **`_M` 那一組不走這條路。** 它是寫給 MPU-401／GM 的，
  dosgolem 沒有 MPU-401，而且拿 GM 音色庫合本來就對。
