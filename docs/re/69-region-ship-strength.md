# 星域記錄 `+0x30` 起是兩個陣營各七種艦艇的兵力

艦隊組成畫面右半印著七列「待命部隊」與「數量」（`docs/re/67`）。
先用字型查表把它們讀成數字：

| 列 | 待命部隊 | 數量 |
|---|---:|---:|
| 戰艦 | 25 | 3000 |
| 高速戰艦 | 12 | 3000 |
| 巡航艦 | 27 | 4000 |
| 航空母艦 | 5 | 2000 |
| 驅逐艦 | 9 | 3000 |
| 運補艦 | 5 | 3000 |
| 修護艦 | 5 | 1000 |

## 找不到的那一輪

在這張畫面開著的時候倒資料段（收據 `fokds`）去找這兩排，**七種編碼
全部落空**（`docs/re/67`）。倒整個 1 MB（收據 `fokall`，畫面雜湊與
`fok` 相同）再找一次連續排列，**還是沒有**。

會落空是因為找錯形狀：這兩排在記憶體裡**既不連續、也不是同一個東西**。

## 找到的那一輪：改找「有跨距的排列」

不要求七個數字連續，只要求它們以固定跨距出現：

```
for stride in 2..128:
    找 p 使得 mem[p + k*stride] == 第 k 個值
```

「數量」那一排中了兩種跨距：

- **跨距 4，落在星域記錄裡**——`0x5F3F8`、`0x5F4F4`、`0x5F572`、`0x5F962`，
  換算成 `(星域, 位移)` 分別是 (2,0x30)、(4,0x30)、(5,0x30)、(13,0x30)。
  **同一個位移、四個不同的星域**：這不是巧合。
- 跨距 26，落在 `ds:4E3A` 與 `ds:4F0A`（相距 208 ＝ 8 × 26）。那是另一張表，
  這裡沒追。

## 結論（confirmed）

星域記錄 `+0x30` 起是 **14 個 32 位元的兵力**：前七個是帝國、後七個
（`+0x4C` 起）是同盟。存的是**人**，不是艘數。

畫面上的兩欄是同一個數字拆開來的：

```
待命部隊 = 兵力 ÷ 該艦種每艘的人數
數量     = 該艦種每艘的人數（常數，兩個陣營相同）
每艘人數 = [3000, 3000, 4000, 2000, 3000, 3000, 1000]
```

首都瓦爾哈拉（星域 0）：75000 / 36000 / 108000 / 10000 / 27000 / 15000 / 5000
÷ 上面那七個 ＝ **25 / 12 / 27 / 5 / 9 / 5 / 5**，與畫面完全相同。

## 為什麼算數

開局 22 個有兵力的星域、兩個陣營、七種艦艇——**每一格都整除，沒有一個
餘數**。同盟首都海尼森（星域 31）是 216000/60000/224000/72000/30000/12000/10000
＝ 72/20/56/36/10/4/10。

零餘數這件事同時定住了兩件事：位移是對的，而且七個常數兩個陣營共用
（單價是分陣營的，`docs/internals/32`——不能假設這一組也分）。

## 教訓

> 找不到一排數字時，先問「它在記憶體裡是不是一排」。
> 顯示成一欄的東西，在記憶體裡常常是**每筆記錄裡的一格**。
> 連續搜尋對這種形狀結構上找不到——換成「固定跨距」一次就中。

順帶：畫面上那七列是**兩個來源**——一欄是狀態、一欄是常數。
把它們當成同一張表去找，也是落空的原因之一。
