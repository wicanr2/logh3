# 206 — `ds:8FD4[陣營]` 是一個 0–4 的等級，變動時會跳訊息

建艦隊的閘門 `2D76:0060` 裡有一段「`ds:8FD4[陣營] >= 3` 就把預算打
七五折」（`docs/re/202`），那一格的語意一直沒查。整份 1 MB 傾印掃過
所有存取點之後，它的**形狀**清楚了；**名字仍然不知道**。

## 掃法

掃 disp16 ＝ `8FD4` 的所有定址形式（絕對 `mod=00 rm=110`、
`基底+disp16 mod=10`、累加器直接存取 `A0`–`A3`）。15 處候選裡
13 處是指令：

| 位址 | 指令 | 角色 |
|---|---|---|
| `0x09427` | `cmp byte [bx+8FD4], 4` | 上限檢查 |
| `0x09434` | `inc byte [bx+8FD4]` | **＋1** |
| `0x09444` | `cmp byte [bx+8FD4], 0` | 下限檢查 |
| `0x09451` | `dec byte [bx+8FD4]` | **−1** |
| `0x271CF` | `mov [8FD4], al` | 直接設（帝國那一格）|
| `0x2D526` | `mov [bx+8FD4], al` | 直接設 |
| 其餘七處 | `mov al,[bx+8FD4]` 之類 | 讀 |

`bx` 一律是 `ds:8F1D`（目前處理的陣營），所以它是**每個陣營一格的 byte**。

## 調整它的那一支

線性 `0x09413`：

```
f(delta):                              ; delta 是有號的
    di = 1
    delta > 0：
        ds:8FD4[陣營] >= 4 → 不動
        否則 ds:8FD4[陣營]++
    delta < 0：
        ds:8FD4[陣營] == 0 → 不動
        否則 ds:8FD4[陣營]--
    兩邊都沒動 → di = 0
    di != 0（真的變了）：
        090A:0B93(新值)
        090A:0E6D()                     ; 顯示層（docs/internals/54 記過同一支）
        …（往下還有兩個立即數 27h、97h 被推進去）
```

**所以它是一個 0–4 的五段等級**，一次只動一級，而且**只有真的變動時
才呼叫顯示層**——也就是變動會在畫面上跳一則訊息。

## 已知的用途

目前只找到一個：`2D76:0060` 拿它 `>= 3` 決定要不要把建艦隊的預算
（總稅收）打七五折（`docs/re/202`）。其餘七個讀取點還沒逐一讀。

## 仍然不知道的

**它是什麼**。0–4、每陣營一格、變動時跳訊息，這些都是形狀，不是語意。
要命名得再走一步：`090A:0E6D` 那一支印的是哪一則訊息——訊息文字會直接
說出這一格叫什麼。**不猜。**

## remake 怎麼處理

`Game.OriginalBrain()` 的 `Support.Money` 目前一律回 `tight = false`
（`internal/game/originalbrain.go` 有註解）。remake 還沒有這個等級，
所以建艦隊的預算不會被打折——與「這一格是 0」的局面相同。

## 一條方法

**「語意未解」的欄位，先掃出它的讀寫點再說。** 這一輪沒有讀懂它是什麼，
但「0–4、每陣營一格、`±1`、變動跳訊息、被建艦隊的預算門檻讀」這些
全部是掃出來的，而且已經足以讓 remake 知道**自己缺的是什麼**。
形狀比名字先到手，是正常的順序。
