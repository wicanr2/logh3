（`turn260mem`）是開局那一趟，三支艦隊都是當場新編的、全部滿編，

## 先量整補跑在哪

```

**一個 AI 回合跑一次**，而且第一次的時候艦隊剛建好、全部滿編。

## 注入

`-poke` 把提督 52 那一支的兩組艦艇的現有艘數（艦艇記錄 `+0x08`）
改成 1000（滿編 3000，`1000 × 4 < 3000 × 3` ＝ 缺編）：

```
-poke 'lin:66956@230000000=e8 03;lin:669a4@230000000=e8 03'
```

艦艇池的遠指標 `ds:CFB4` ＝ `02 00 8B 66` ＝ `668B:0002` ＝ 線性
`0x668B2`（`-peek 'lin:61AE4:4'` 印出來的），艦艇 #2 與 #3 的 `+0x08`
就是 `0x66956` 與 `0x669A4`。報告裡的
`改記憶體 lin:66956（66956）` 兩個數字相同 ＝ 位址沒有被當成 IDA 位址
換算（`CLAUDE.md` 的檢查點）。

**注入之後整補的步數變了**：`#242631032` → `#243072663`。第一次倒記憶體
取在 `#243000000`／`#244000000`，早了七萬條，白跑一趟——`-regs-at` 要
與 `-dump-mem-at` 同一跑才對得準。

## 逐步對上反組譯

`docs/re/229` 讀出來的規則代進去：

```

  滿編 3000；需要 = 3000 − (2000 mod 3000) = 1000
  待命部隊[0] = 3000 >= 1000 → 總和 = 3000
  3000 ÷ 3000 = 1 ≠ 0 → 兩組都拆掉

補編制（2D76:0A44），應有 4
  樣板鍵 04 第 1 格 (0,10)：a = 旗艦艦種 = 0
      2D76:0C4F：沒有槽 10 → 0（新增）

## 沒有走到的分支

- `2D76:0C4F` 回**非 0**（槽號相同但艦種不同 → 覆蓋那一槽）。
- 編制已滿要犧牲一組（`2D76:0D40` ＋ `2D76:0DB2`）。
- 替代清單裡的 `0xFE`（艦種 5／6 平衡，`docs/re/226`）。

三條都實作了，但這一份收據裁決不了。

## 一條方法

**注入會改變時序，所以量測與注入要在同一跑。** 先用 `-regs-at` 量到
整補在 `#242631032`，加上 `-poke` 之後變成 `#243072663`——差七萬條，
剛好夠讓 `-dump-mem-at` 落在整補之前，倒出兩份一模一樣的記憶體。
**注入之後的時間軸是新的時間軸。**
