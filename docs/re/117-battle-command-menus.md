# 117 — 戰場的命令選單：觸發、五張表、版面

`docs/re/114` 收尾寫著「哪一張表在什麼時候開、每一項各做什麼，都還沒查」，
而且右側分隊面板的觸發也是問號。這一輪兩件一起解掉。

## 全部的選單只有一支開啟常式

主程式所有選單都走 `3667:0004`，呼叫端把表的位址用
`mov bx, imm16 / push bx / push ss` 推進去。掃 `9A 04 00 67 36` 就能把
**整支遊戲的 22 張選單**列出來（`tools/scripts/menu_tables.py`，
結果在 [`docs/internals/data/menus.json`](../internals/data/menus.json)）。

參數順序（`push` 的反序）：

```
3667:0004(結構 ss:bp, 表 ds:off, x, y, 項目數, 內寬, 9, 0x97, 0x27, 0x98)
```

後面四個常數在**每一張選單都相同**——戰術選單、艦隊選單、分隊選單推的
位元組一個不差。所以配色與框線是全域的，每張選單只差
（位置、項目數、內寬、表）。

內寬的來源有兩種：戰術選單呼叫 `3C9E:0001(第一項的字串)` 算出來（
`實行  ` 六個位元組 → 6），單位選單直接寫死 2。

## 一筆選單項目

六個位元組：可選旗標（byte，0 ＝ 反白畫成不可選）＋ 補一個 0 ＋
指向名稱的遠指標。段一律是資料段。旗標是**用位元組寫的**——
`mov byte ptr ds:4158h, 0`，所以搜「誰改這一項」要搜 `C6 06`。

## 戰場上的五張表

| 表 | 項目 | 什麼時候開 |
|---|---|---|
| `ds:4120` | 移動／戰鬥／索敵 | 點到自己的**旗艦**（艦艇 `+0x03 ＝ 0`）|
| `ds:413C` | 移動／編隊 | 點到自己的分隊，艦種 0–4 |
| `ds:4158` | 移動／編隊／補給 | 艦種 5（運補艦）|
| `ds:417A` | 移動／編隊／修理 | 艦種 6（修護艦）|
| `ds:4196` | 移動／歸隊 | 艦種 7（索敵分遣隊）|

行星另有兩張（`ds:42EA` 情報／補給／補充、`ds:4318` 情報／補給／補充／
要塞砲），開啟常式在 `1CC5:1096` 附近，表由呼叫端當參數傳進來，
分派用 `ds:4396` 那張四項的跳躍表。哪一張在什麼時候開還沒查。

## 觸發鏈

```
戰場點擊
  └ 12AA:05BC   這個單位可不可以下命令？
                 索引 bit15 設了 → 可以（行星）
                 否則 艦艇 +0x00（陣營）== ds:8F1D（玩家陣營）才可以
  └ 1CC5:06A6   艦艇 +0x03 == 0（旗艦）→ 艦隊選單 1CC5:070D
                 否則             → 分隊分派 1CC5:09C6
  └ 1CC5:09C6   艦艇 +0x04（艦種）5／6／7 各一支，其餘走預設那支
```

**只有自己陣營的單位點得動**——這就是為什麼在收據 `s3aim` 的局面
（玩家是帝國、場上只有同盟的第 28／31 艦隊）怎麼點都只開得出戰術選單。

點下去的同時右側會換成**分隊面板**（`docs/re/114` 量過內容、當時
不知道怎麼開）：艦隊名／部隊序號／艦種與艘數／士氣值／艦隊行動／
三組武器數。艦隊選單與分隊選單都會換。

## 可選旗標怎麼算

艦隊選單（`1CC5:070D`）：

```
三項先全設成可選
if 艦隊 +0x00 bit0:            戰鬥、索敵 → 不可選
if 艦隊 +0x3A != 0FF 或 +0x3B != 0:  索敵 → 不可選
```

分隊選單（四支共用同一段）：

```
al = 艦艇 +0x1E（分隊行動，0x7F ＝ 沒有）
「移動」可選 = (al != 0 且 al != 3)
```

也就是**已經在移動或已經在歸隊的分隊不能再下移動**。

## 每一項做什麼

| 項目 | 進入點 |
|---|---|
| 移動 | `1CC5:0D1C`（四支分隊選單與艦隊選單共用）|
| 編隊 | `2BE1:0328` |
| 補給 | `1930:05EC` |
| 修理 | `1AAB:0583` |
| 歸隊 | 沒有子常式，直接 `艦艇 +0x1E ← 3` |
| 戰鬥／索敵 | 艦隊選單那三項的分派還沒讀 |

## 版面：一個公式蓋掉所有選單

位置是**格座標**——`341B:04DB` 的兩個輸出是 byte（`[bp+0]`、`[bp+1]`），
放不下 480，所以那是格不是像素。量到的三張：

| 選單 | 游標（畫面）| 格 | 框左上角 |
|---|---|---|---|
| 戰術（`s3menu`）| (240,240) | (14,11) | (225,221) |
| 分隊（`s3cmdsq3`）| (261,298) | (15,13) | (241,261) |
| 艦隊（`s3cmdfl3`）| (298,409) | (17,16) | (273,321) |

```
框左上角 = (格x × 16 + 1, 格y × 20 + 1)
格 = 游標所在格 − (1,1)，再由 3982:0198 夾進戰場可視範圍
     （夾的判準是 格y ≤ 19 − 項目數；艦隊那張從 19 被夾到 16）
框大小 = (內寬 × 16 + 30) × (項目數 × 20 + 38)
```

驗算：戰術 6×16+30 ＝ 126、7×20+38 ＝ 178；分隊 2×16+30 ＝ 62、
2×20+38 ＝ 78；艦隊 3×20+38 ＝ 98。三張都吻合。

框內的東西與戰術選單完全同一套（`docs/internals/data/battle-menu.json`）：

```
反白帶 = 框 + (15,19)，大小 (內寬 × 16) × 20
文字   = 反白帶 + (0,2)，欄距 16、列距 20
底色 9、字色 7、立體邊 3、反白色 2、框用 ui.MenuFrame
```

分隊選單那張逐像素看過：反白帶 (256,280) 32×20、框 (241,261) 62×78，
與公式一致。

## 收據

四份都用同一條前置序列（收據 `s3aim` 的 36 次點擊），只差最後一下：

| 收據 | 注入 | 最後一下（滑鼠）| 結果 |
|---|---|---|---|
| `s3cmd3` | 無 | (315,218) | 點在同盟單位上 → 只開戰術選單 |
| `s3cmdsq3` | `lin:69270@1394000000=00` | (261,258) | 分隊選單（移動／編隊）|
| `s3cmdfl3` | `lin:689E8@1394000000=00` | (298,369) | 艦隊選單（移動／戰鬥／索敵）|

注入的是**艦艇記錄 `+0x00` 的陣營位元組**：第 31 艦隊第 1 分隊
（池索引 137，線性 `0x69270`）與第 28 艦隊旗艦（池索引 109，
線性 `0x689E8`）從 1 改成 0，讓玩家點得動。改玩家陣營
（`ds:8F1D`）不行——可見度是相對玩家算的，一改單位就從畫面上消失。

畫面 y ＝ 滑鼠 y ＋ 40（`docs/re/52`）。
