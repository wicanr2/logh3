# 開頭動畫的畫面對不上：執行器忽略顯示起點（page flip）

`docs/re/72` 把解碼器解出來之後，剩一件事沒做到：拿解出來的畫格去比
執行器畫出來的畫面，**一格都對不上**。這一輪找出理由——不是解碼器，
是執行器少了一塊。

## 缺的是顯示起點

搬到 VRAM 那四趟 `rep movsw` 的目的地是 `cs:[001A]`，而那個變數在
**`0000` 與 `6D60` 之間交替**（`docs/re/36` 就記著「畫面在翻頁」）。
`0x6D60` ＝ 28,000 ＝ 350 × 80，正好是 mode 10h 一整頁。所以開頭動畫是
**雙緩衝**：解好的一格搬到背景頁，再把顯示起點切過去。

dosgolem 的 `PlanarPixels` 從 **VRAM 位移 0** 開始組像素，
CRTC 的顯示起點（`3D4` index `0C`／`0D`）根本沒有被記錄——
`grep 0x3D4` 在整個 repo 一個都找不到。所以遊戲顯示第 1 頁的時候，
倒出來的是第 0 頁。

## 這幾件事不是原因（查過了）

- **map mask 有生效。** 畫面的色號分布是
  `8`(11,891)、`4`(6,045)、`2`(2,504)、`6`(2,120)、`12`(1,596)、`1`(1,301)
  ——**四個 plane 拿到的位元組不一樣**，不然只會有 0 與 15 兩種色號。
- **`out dx,ax` 有拆成兩個埠。** 那段程式用的是
  `mov dx,03C4 / mov al,02 / mov ah,0X / out dx,ax`（16 位元 OUT），
  `internal/cpu/ops.go` 的 `0xEF` 寫 `dx` 與 `dx+1`，是對的。
- **`rep movsw` 有走 planar 路徑。** `Write16` 拆成兩個 `Write8`，
  `Write8` 對 `A0000–AFFFF` 會呼叫 `planarWrite`。

## 下一步

在 dosgolem 記下 CRTC 的 `0C`／`0D`，`PlanarPixels` 從那個位移開始組。
改完之後**顯示起點是 0 的畫面輸出不會變**——所有既有收據都是那種，
所以不必整批重做；但要實測確認起點真的是 0，不能用推的。

## 順帶：`cs:001C` 一輪只寫三次

同一輪對 `lin:0420C`（`cs:001C`）設寫入監看，45,000,000 步裡只有三次：

```
#34,706,915  0 → 38,991
#35,384,865  38,991 → 49,213
#36,682,236  49,213 → 57,395
```

三個值都**不是影格邊界**（±40 都試過）。`add cs:[001C],bx` 在反組譯裡
看起來是一格一次，那就對不起來——除非那個迴圈一次解的不只一格。
先記著，等畫面能對之後再看。
