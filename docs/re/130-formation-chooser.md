# 130 — 「編隊」的互動選擇器（`2BE1:0328` 整支）

`docs/re/126` 解出 41 格的隊形槽表，`docs/re/127` 量到「編隊」下完之後
艦艇記錄改了兩個位元組，但中間玩家實際上在做什麼一直沒讀。這一輪把
`2BE1:0328` 從頭到尾讀完——它就是那張選格子的畫面。

## 找到它的方法

`2BE1:06C5`（等點擊的那支）在整個 code space 裡**只有一個呼叫點**。
拿 `9A C5 06 E1 2B` 這五個位元組去掃倒出來的段（`tools/scripts/find_farcall.py`），
四個檔各中一次，換算成線性位址全是 `0x2C197` ＝ `2BE1:0387`——同一個地方
被四個重疊的段切片各看到一次。往前找函式頭就是 `2BE1:0328`。

## 整支的流程

```
2BE1:0328(艦艇 far ptr)
    艦隊 = ds:C074 + 艦艇[+0x01] × 122          ; +0x01 ＝ 所屬艦隊編號
    2BE1:0442(艦隊)                              ; 算出 41 格的世界座標
    2BE1:050F(艦隊)                              ; 已經有人的格子標成 1
    ds:D072[艦艇[+0x05]].flag = 0                ; 自己現在那一格放回可選
    2BE1:0564()                                  ; 每個可選格子放一個 16×16 標記
    槽 = 2BE1:06C5()                             ; 等點擊
    2BE1:0659()                                  ; 收掉標記
    若 槽 == 0xFFFF：結束                        ; 右鍵取消
    池索引 = (艦艇位址 − ds:CFB4/CFB6) ÷ 78
    找出 池索引 在 艦隊[+0x10] 那張分組表的第幾筆 i
    艦隊[+0x10 + i×4 + 3] = 槽                   ; 分組表那一筆的 [3]
    艦艇[+0x05] = 槽
    艦艇[+0x1E] = 0x7F                           ; 分隊行動清成「沒有」
    2BE1:0059(艦隊, 艦艇)                        ; 立刻算出新的目的地
    25DB:0AF8(池索引, 0)
    3765:006C(ds:8F38)
    25DB:0E04()
```

**分組表那一筆的 `[3]` 與艦艇 `+0x05` 是同一個值的兩份**，這裡一起寫。
`docs/internals/33` 對分組表 `[3]` 原本只寫「槽」，現在有了寫入點。

## 41 格的畫面表：`ds:D072`

`2BE1:0442` 把它整個重算，一筆 **10 bytes**、共 41 筆：

| 位移 | 內容 |
|---|---|
| `+0` | 世界座標 x |
| `+2` | 世界座標 y |
| `+4` | 0 ＝ 可選，非 0 ＝ 已經有人 |
| `+6` | 這一格那個顯示物件的 far ptr（`2BE1:0564` 填）|

```
for i in 0..40:
    (x, y) = ds:59BA + i×4                  ; 槽位偏移
    3A92:0001(&x, &y, 艦隊[+0x4A])           ; 依艦隊朝向旋轉
    x += 艦隊[+0x5C]；y += 艦隊[+0x5E]
    x 夾進 0–0x7FF、y 夾進 0–0x7F7
    flag = 0
```

夾的上限是 **0x7FF／0x7F7**，不是走一步用的 0x7EF／0x7E7
——又一個「捨去與夾值看呼叫點」的例子（`docs/internals/39`）。

`2BE1:050F` 接著跑一次分組表：`ds:D072[ 艦隊[+0x10+i×4+3] ].flag = 1`，
把已經有分隊站著的格子標掉；然後呼叫端把**自己那一格**放回 0，所以
「留在原地」也是合法選項。

## 畫出來的標記：`2BE1:0564`

對每一個 flag ＝ 0 的格子：

```
物件 = 3ABF:0000(0x28)              ; 配 40 bytes 的顯示物件
物件[+1]    = 0xFF
物件[+2]    = ds:9B9E
物件[+3]    = 0xFF
物件[+0x0A] = 16                    ; 寬
物件[+0x0B] = 16                    ; 高
物件[+0x0C] = 11                    ; 圖塊編號
物件[+0x0E] = 3982:0001(11)         ; 那個圖塊的資料
物件[+6]    = 格子.x − ds:9BF4      ; 減視野原點 → 畫面座標
物件[+8]    = 格子.y − ds:9BF6
35D1:0009(物件)                      ; 掛進顯示串列
```

最後 `25DB:108E()` 重畫。所以畫面上是**每個空格子一個 16×16 的圖塊
（編號 11）**，位置就是槽位旋轉之後減掉視野原點——與分隊本身的畫法
（`docs/re/85`：艦艇 `+0x2F` 的圖塊，左上角對齊世界座標）同一套。

## 點擊怎麼判

`2BE1:06C5` 是一個小型的模態迴圈：

```
loop:
    3765:0036(&事件)                 ; 等輸入
    事件 == 1（左鍵）：
        3765:0036 之外還先問 341B:039D(x, y) 落在哪一層，
        只有落在 ds:9B9A 那一層才算數，否則回 0xFFFF
        槽 = 2BE1:0739(x, y)
        結束
    事件 == 2（右鍵）：槽 = 0xFFFF，結束
回 槽
```

`2BE1:0739(x, y)` 先用 `1588:0362` 把畫面座標換成世界座標，然後**依序**
掃 41 筆，第一個滿足下面條件的就是答案：

```
flag == 0
且 格子.x <= 世界x < 格子.x + 16
且 格子.y <= 世界y < 格子.y + 16
```

命中框是 16×16，與圖塊同大；掃描順序是槽 0 → 40，**先中先贏**。
沒中就回 0xFFFF（等於取消）。

## 收據：`s3form`

走 `s3cmdsq3` 那條前置序列，最後多點一下 (270,270)——分隊選單第二項
「編隊」——然後用 `-dump-mem-at` 在第 14.5 億步把 `ds:D072`
（`lin:61BA2`，410 bytes）與整段資料區倒出來。

驗到三件事：

1. **41 格的世界座標 41／41 完全相同**。那一局艦隊 31 在 (1320,812)、
   朝向 168，拿 `ds:59BA` 旋轉加位置算出來，一格不差
   （`TestFormationTableMatchesOracle`）。
2. **有人的格子是 20、21、28、29、30、38 六格**——艦隊 31 有七個分隊，
   發令那一個自己的格子被放回可選，剩六格，與程式讀出來的規則一致。
3. **標記就是 `SPRITE.SPR` 的第 11 塊，色號 0 透空**。35 個空格子有 30 個
   逐位元組相同（`TestFormationMarksMatchOracle`）；另外五個底下有東西
   （三個坐著分隊、兩個被游標壓到），所以**分隊畫在標記之後**。

## 還沒解
- `25DB:0AF8`／`3765:006C`／`25DB:0E04` 三支收尾。
- 「透空」與「色號 0 換成 3」分不開——要一份空格子壓在格線上的收據。
