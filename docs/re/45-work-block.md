# RE 45 — `WORK.DT?` 就是 `ds:8F14` 起那 230 bytes

日期：2026-09-07
執行器：dosgolem-logh3 `8c8af90`
收據：`s2state`、`newload`、`watchwork`
狀態：**confirmed**（載入後的記憶體與檔案只差 3 個 byte）。

## 怎麼查到的

`docs/spec/009` 卡在一件事：新遊戲存不了，因為 `WORK` 那 230 bytes 只解出
三個欄位，其餘 227 沒有底稿可以抄。先前在資料段裡找過整份 `WORK.DTA`
的位元組**找不到**，所以以為它是存檔時從各處收集的。

改從另一頭問：載入 S2 的時候誰把回合數寫進 `ds:8F18`？設監看跑一輪
（收據 `watchwork`）——**一次都沒有**。載入前歸零之後就沒人再寫，
但倒出來的記憶體確實是 346。

寫入看不到，表示那不是 CPU 指令寫的——是 **DOS 的 int 21h 讀檔直接讀進去**。
既然是整塊讀進去，那塊就在記憶體裡；回合數是檔案的 `+0x04`，所以塊頭在
`ds:8F18 − 4 = ds:8F14`。對過去：

```
ds:8F14 起 230 bytes vs WORK.DT9：不同的位元組 3（位移 12、14、16）
```

那三個是跑起來之後被改過的（選單狀態之類）。**`WORK.DT?` 就是這一塊。**

## 對得上的欄位

先前當成獨立全域的那幾個，其實都是這一塊的欄位（`docs/internals/27`）：

| 全域 | 塊內位移 |
|---|---|
| `ds:8F18` 回合數 | `+0x04` |
| `ds:8F52` 軍事費 | `+0x3E` |
| `ds:8F6A` 總稅收 | `+0x56` |

`0x8F52 − 0x8F14 = 0x3E`、`0x8F6A − 0x8F14 = 0x56`，兩個都對得上。

## 新遊戲的那一份

`WORK.DTX` 不存在，所以新遊戲的初值只能從記憶體量（收據 `newload`，
第 71,200,000 道指令，剛載完）：

```
回合 0、軍事費 50000、總稅收 10201
```

**軍事費 50000 就是先前只能當「劇本給的起始值」的那個數**
（`docs/re/35`）——它其實存在這一塊裡。

量到的整塊寫進
[`data/work-796-01.json`](../internals/data/work-796-01.json)，
`rules.LoadWorkTemplate` 讀它，新遊戲存檔就有底稿了（`docs/spec/009`）。

## 還沒解的

塊內其餘 227 bytes。與 `WORK.DT9` 相比新遊戲那一份有 82 個 byte 不同，
所以裡面裝的東西會隨局面變——remake 沒有模型的那些欄位存出去會停在
796 年 1 月的初值，這一點寫在 `docs/spec/009` 的範圍說明裡。
