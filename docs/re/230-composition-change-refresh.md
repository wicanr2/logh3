# 230 — 編制一改，後面還有三支要跑

`docs/re/228` 讀 `297B:03EB` 只讀到組序同步那個迴圈就停了。迴圈之後
還有一段，而且它帶出兩支「改完編制要重算什麼」的常式。

## `297B:03EB` 的尾段

線性 `0x29C1C` 起：

```
艦艇 = 艦艇池 + 艦隊[+0x38] × 78          ; 不被十個槽引用的那一筆
艦艇[+0x03] = 0FFh                        ; 沒有組序
艦艇[+0x06] = 100
艦艇[+0x05] = 20                          ; 隊形槽 ＝ 20，與旗艦那一組同值
艦艇[+0x02] = 艦隊[+0x06]                 ; 所在星域
第二個參數 != 0 → 297B:08D8(艦隊, 星域, 星域)
第二個參數 == 0 → 297B:08D8(艦隊, 0FFh, 0FFh)
297B:0546(艦隊)
```

`艦隊[+0x38]` 那一筆就是 `docs/internals/30` 記過的
「**每支艦隊拿到一段連續編號，其中第二筆不被十個槽引用但有內容**」。
它的隊形槽是 20——與樣板第 0 組的 `slot3` 相同（十六個鍵都是 20，
`docs/re/225`）。

整補呼叫的是 `297B:03EB(艦隊編號, 0)`，所以走 `0FFh` 那一條。

## `297B:08D8(艦隊, a, b)`：把戰鬥狀態清掉

線性 `0x2A088`：

```
1588:00F6(艦隊[+0x06])
297B:0ABF(艦隊, a, b)
艦隊[+0x3A] = 0FFh；艦隊[+0x3B] = 0
艦隊[+0x48] = 4
艦隊[+0x5A] = 0FFh；艦隊[+0x5B] = 0FFh
2BE1:0000(艦隊)
（接著逐組再跑一個迴圈，沒讀）
```

## `297B:0546(艦隊)`：拿提督與副官重算

線性 `0x29CF6`：

```
提督 = ds:B77C + 艦隊[+0x04] × 28
副官 = 艦隊[+0x05] == 0FFh ? NULL : ds:B77C + 艦隊[+0x05] × 28
297B:05B2(艦隊, 提督, 副官)
297B:0E8B(艦隊)
090A:0E6D()                               ; 顯示層
```

**艦隊的能力是從提督 ＋ 副官算出來的**，所以編制一動就要重跑——
與 `docs/re/218` 的維持費算式（用 `+0x47`，來自 `max(提督, 副官)` 的
`+0x0E`）是同一件事的兩面。

## 對 remake 的意義

整補在 remake 這一側不只是「改編制陣列」：原版改完會

1. 同步艦艇記錄的組序、隊形槽與星域（`297B:03EB`）；
2. 清掉戰鬥用的欄位（`297B:08D8`）；
3. 用提督與副官重算艦隊能力（`297B:0546`）。

remake 的 `rules.Fleet` 把這些欄位攤在同一個結構上，第 1 項不用做
（沒有獨立的艦艇池），第 3 項對應的是重算 `Operations` 與 `Upkeep`
——**這兩個 `formFleet` 已經在做了**，整補要走同一條路。

## 仍然沒讀

`297B:0ABF`、`297B:05B2`、`297B:0E8B`、`1588:00F6`、`2BE1:0000`，
以及 `297B:08D8` 的逐組迴圈。都在「重算衍生欄位」這一層。

## 一條方法

**改完狀態要跑哪些「重算」，和「怎麼改」一樣是規格的一部分。**
只讀到「編制陣列變成什麼」就實作，remake 會得到一個編制對、
但能力與戰鬥欄位停在舊值的艦隊——而那種錯不會當場報錯。
