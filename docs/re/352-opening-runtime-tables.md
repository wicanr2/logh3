## 開局初始化與分配時機（proven）

IDA Pro 9.4／image `ida-pro-9.4-idapython:locked-v1`，只操作原資料庫複本。
`code2703.com` SHA-256 `e2f821b085353c1668511e8e2c57ba3db6b0ee915fa8231f1dc656def0916b72`；
其中段內 0–`0x1788` 與目前原版收據線性 `0x27030` 起逐位元組一致。
原 `.i64` 雜湊前後都是 `abadfa416b6db84595330110cfc0b08f455817f110d756373836c6857f5b15b1`。
IDA COM 映射：段內位移＝IDA 位址−`0x10200`。原始定位、指令與人工審查語意
保存於 [結構化證據](../internals/data/opening-runtime-tables.json)。
局部段資料庫沒有跨段關係；空交叉參照不當作「沒有呼叫者」，函式邊界未識別時保持未知。

- `2703:0035` 開局旗標清零；`004F` 呼叫 `159B`，`159B:0010` 即段內 `15AB`
  呼叫 `15D5`；`1653`／`1675`／`167E` 寫三方行星數。
- `169A` 將行星防衛力加到星域 `+0x20`，`16A8` 將行星防衛上限加到 `+0x22`。
  兩欄不是必然相同；舊欄位摘要的「同一個值兩份」需訂正。
- `16D0`–`16F7`：行星經濟力乘 100，除星域總經濟力，將商低 byte 寫行星 `+0x13`。
  同理 `1726`／`174C` 寫兩陣營經濟比例。由原始 PLADAT 經濟力算出的 81 個比例
  與研究 351 的原版命令階段全部相同；不能每次單純加總經濟力就擅自刷新比例。
- 初始化尾段 `0195` 建路徑表，`01C9` 重算態勢，`01E6` 彙總行星存量。
  首都成本新遊戲樣板 32 格全 0；無主格的態勢常式不寫成本，所以應保留 0。
- `056A:003E` 移動艦隊，`0048` 才呼叫 `2703:051D`，`0052` 重數艦隊。
  `051D` → `0540` → `0590` 分別處理兩陣營。這是實行階段，尚未按實行的開局
  命令階段不能提前分配。行星情報窗另有立即分配，見既有研究 319。

## 規格審查

以上寫入端與正常開局完整記憶體支持規格 065 五項契約，准升 **READY**。
僅校正已知的開局導出欄位，不改未知欄位、不改存檔格式；回合中彙總／回充時序
另立工作項，保留規格 039 的歷史問題。本輪整表一致範圍限於指定開局與五條預算路徑。
IDA 匯出首次因多參數使用 `sys.argv` 失敗，改既有 `idc.ARGV` 後同 image 重跑有非空輸出；
這是腳本問題，不是遊戲缺陷。

實作後星域 4032 bytes 已全對，行星剩 23 bytes：同盟首都行星 79 的艦種 4–6、
行星 80 全七種艦艇是 PLADAT 原值兩倍。規格退 DRAFT 補初始化寫入端，沒有增加排除區。
`2703:0214` 匯出只更新艦隊可見計數，不是這次加倍的寫入者；不因接近初始化尾段而猜語意。

## 補證：電腦座位首都艦艇加倍（proven）

正常冷啟動監看批次 `opening-stock-write-watch`：`-steps 165000000 -tick 20000
-clicks 40000000:300:170::3000000,95000000:300:170::3000000,130000000:432:300::300000
-press 1,3,8,enter -press-at 105000000 -press-every 2000000
-watch 54ab0-54ab3,54af2-54af5`，其餘共用旗標沿 `tools/oracle.sh`。
無記憶體注入；兩處都是 dosgolem 線性位址。`#117041007` 與 `#117041059`
由 `2703:04F3` 寫行星 79／80 的倍增值。來源輸入、執行器及 image 與本研究相同。

IDA `2703:046A` 以兩次 `3982:022D` 判定各陣營是否電腦；回 1 才呼叫
`04A3(首都星域記錄)`。`04CC`–`0503` 掃首都全部行星，七種艦艇 `+0x20+種類×4`
以 `04F0: 26 d1 24`（低 word 左移）與 `04F3: 26 d1 54 02`（高 word 帶進位左移）
原地乘二；`0510` 再呼叫 `12EB` 彙總。飛彈／艦載機沒有被倍增。
因此不能把初始艦艇全部保持原始值，也不能把分配後的行星值硬編回去。
此直接寫入證據支持規格新增電腦首都倍增條款，重新升 READY。
