# 271 — 頭像對到人物傳：`FACE.AMG` 第 n 張就是提督 n，「九張空白」是誤讀

要把 82 篇人物傳（`docs/lore/character-biographies.md`）各自對到 `FACE.AMG`
的一張頭像。舊結論是「第 n 張 ＝ 提督索引 n」，但只掛著 `strong inference`
——`docs/internals/09` 自己還留著兩句擋路的話：83 張比 82 人多一張，而且
「第 18、31、33–35、37–39、82 張是空白」。九張空白全部落在帝國那半邊，
1:1 就不可能對得起來。

先查那九張。

## 一、那八張不是空白，`+12` 也不是旗標

`face-amg.json` 的 `flag12` 取自影像標頭 `+12`，值 `0xFF` 的有九筆。可是
它們的位元組長度是 2858–3416，與正常頭像的 2710–3660 同一個量級；只有
第 82 筆是 44 bytes。長度不像空白。

解出來看：**八張都是完整的人像**，10–12 個色號，與其他 74 張並排看不出
異常。真正只有一格是空的——第 82 張整張單色 9（外框那個深青）。

`+12` 根本不是旗標，是壓縮資料的第一個位元組。反例測試：

| 從哪個位移開始解 | 剛好用完索引表寫的長度 |
|---|---:|
| `+12` | **83 / 83** |
| `+13` | 0 / 83 |

`internal/asset/amg.go` 與 `tools/scripts/amg_decode.py` 本來就從 `+12` 起解，
只有文件與 JSON 的欄位名寫成 `+13` 起、`+12` 是旗標。

第 82 張把這件事釘死：44 bytes ＝ 12 bytes 標頭 ＋ 32 bytes 資料，而 32 ＝
**8 組重複組 × 4 bytes**，每個 plane 兩組（255 ＋ 245 ＝ 500 個 word ＝
10 直行 × 50）。四個 plane 分別填 `FF`／`00`／`00`／`FF`，合成色號
1 ＋ 8 ＝ 9，與解出來的單色相符。位元組數、組數、色號三項同時對上，
資料起點不可能是 `+13`。

那八張的 `0xFF` 是什麼？把外框（色 6／9）的遮罩逐列比，第 17 張與第 18 張
**只有第 1 列與第 96 列不同**：一般張的第 0 列是色 6、第 1 列是色 6 接黑，
那八張的第 0 列是色 9、第 1 列才是色 6——**外框整個往下挪一列**。挪一列
讓第 0 直行 plane 0 的頭兩個 byte 從 `00 7F` 變成 `FF 00`，於是 `+12`
剛好是 `0xFF`。是畫的時候的差別，與內容無關。

## 二、制服的分界落在 39／40，兩個例外自己有交代

同盟制服用色號 4（`#306100` 深綠），帝國制服不用。整張數色 4 的像素：

| 編號 | 色 4 像素數 |
|---|---|
| 0–39 | 0（只有第 10、18、34、36 張各有 6–10 點雜訊）|
| 40–79 | 208 – 1304 |
| 80、81 | 0 |
| 82 | 0（單色格）|

`ADMIRAL.DTX` 的 `+1`（陣營）是 0–39 帝國、40–81 同盟。**分界對得上，
而且兩個例外自己解釋自己**：第 80、81 段人物傳寫的是梅爾卡茲與舒奈德
——帝國軍名將與他的副官，利普休達特戰役之後逃亡到自由行星同盟，
以客座提督身分任職。他們在同盟的名冊上，穿的是帝國制服。

同一組例外在提督記錄裡也看得到：82 筆的 `+0` 全是 `0xFF`，**只有第 80、
81 筆是 `0xFE`**。

這條檢查一次覆蓋 82 格，不是抽樣。順序若有任何錯位，綠色的分界就不會
剛好落在 39／40。

## 三、人物傳自己描述長相，逐項對得上

中譯的人物傳寫了外貌，可以直接拿去比像素：

| 編號 | 人物傳的字 | 量到的 |
|---|---|---|
| 0 萊因哈特 | 亮麗金髮 | 頭頂主色 5（`#F3B200` 金）× 264 |
| 1 吉爾菲艾斯 | 火紅色頭髮 | 頭頂主色 10（`#A20000` 暗紅）× 297 |
| 2 米達麥亞 | 蜂蜜色的頭髮 | 頭頂色 13／14／5 混色（褐＋金）|
| 3 羅嚴塔爾 | 黑色右眼和藍色左眼 | 頭頂主色 3（黑）× 358；**畫面內唯一的藍色像素在他的左眼**——色 1 三點 (55,47)(57,47)(56,48) ＋ 色 6 一點 (56,47)，右眼那一側一點都沒有 |
| 34 貝爾肯格林 | 擁有漂亮鬍鬚 | y56–76 整片色 12／13（褐）蓋住下半臉，只有嘴那幾列露膚色 |
| 49 伍蘭夫 | 淺黑色的皮膚 | 頰區主色 14（`#D3A261`）× 121，比一般的 11（`#F3E3B2`）暗一階 |
| 74 波布蘭 | 淡綠色的眼睛 | y42–46 只有兩處色 4，一邊一個：x34–37 與 x54–56，正是兩眼的虹膜位置 |

第 3 張最有力：**左右不對稱**的特徵，不可能是畫風巧合。第 34 張同樣
關鍵——它正是被誤標成「空白」的八張之一，而它的人物傳說這個人有鬍子，
圖上就有鬍子。

## 四、頭像編號不是提督記錄裡的欄位

`ADMIRAL.DTX`／`DT8` 的 28 個位移，**沒有任何一欄的值等於記錄索引**
（門檻放寬到 82 筆中對 20 筆都沒有），也沒有一欄等於陣營內序號。
所以繪圖端拿到的編號只能是索引本身。

## 結論與等級

**`FACE.AMG` 第 n 張 ＝ 提督索引 n ＝ `KEIREKI.DAT` 第 n 段**，`confirmed`。
第 82 格沒有人物；`KEIREKI.DAT` 的第 83 段同樣是空的（`offsets[82] ==
offsets[83]`）——兩個檔都是 83 格、最後一格空著，形狀一致。

還沒做的：**原版繪圖端「索引怎麼算出來」的那段程式碼還沒讀**。解碼常式在
`348A:02F9`（`docs/internals/09`），但呼叫端把 SI／編號準備好的那一段沒有
反組譯過——易主報告那條路上叫 `3958:0215`，`docs/spec/034` 的「還沒做」
早就列著它。目前的結論靠收據、制服分界與內容對應，不靠程式碼。

## 兩條方法

**說某一格是旗標之前，先問解碼器是不是把它當資料吃掉了。** `flag12` 這個
名字一取，就沒有人再去看那個值從哪來——而它與資料起點是同一個位元組，
兩種說法不可能同時對。差別在於前者要一眼，後者要一次反例測試。

**素材本身會回答身分問題。** 這一輪最強的兩條證據都不在程式碼裡：制服的
顏色分界（82 格一次驗完）與人物傳寫的髮色眼色。**逐位元組收據一次只釘一格，
而內容對應可以一次覆蓋整個檔案。**
