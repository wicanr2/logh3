# 185 — 「從首都走得到嗎」是查一張放在 EMS 的距離表

`docs/spec/029` 把 `2B99:0392`（從首都能不能走到）列成未讀，
`internal/ai` 於是把它做成注入點。這一輪把那一條鏈讀完。

## `2B99:0392(起點, 陣營, &旗標[32])`

```
對 i = 0 … 31：
    旗標[i] = (2B99:028F(起點, i, 陣營) < 0800h) ? 1 : 0
```

就這樣——它只是把 `2B99:028F` 的「走不走得到」攤成一張 32 格的布林表。

## `2B99:028F(a, b, 陣營)` 是查表，不是搜尋

```
3BAA:0062(0, 6)                                   ; 未讀，不影響傳回值
表 = (陣營 == 0) ? ds:D062 : ds:D066               ; 遠指標
回 表[a × 64 + b × 2]                              ; 32 × 32 的 word 矩陣
```

**是一張預先算好的 32×32 word 距離矩陣**，不是每次跑 BFS。
`>= 0x800` 就是「走不到」的哨兵值。

`docs/re/79`／`docs/re/166` 一直把它記成「到某處幾步／成本」，
形狀對，但當時不知道它是查表。

## 表在 EMS 裡，還沒取到

兩個遠指標解出來是 `E000:0000`（帝國）與 `E000:0800`（同盟）——
**EMS 頁框**，與中點矩陣同一個坑（`docs/re/183`）。拿平面傾印去讀，
得到的是 `0x5555`／`0xAAAA`／`0xFFFF` 這種一看就是別的頁的位元樣式。

所以：**距離的「數值」還沒取到**，`2B99:028F` 目前只能用在
「走不走得到」這個布林上。要取數值得用
`-regs-at 2B99:028F`（`-regs-from`／`-regs-max`）取樣，或在確定頁面映射
的時刻 peek `E000:0000`。

## 但「走不走得到」有答案

星圖是**全連通**的，兩邊都是：

- 相鄰圖從星域 0（瓦爾哈拉）BFS 走得到 **32／32** 格，從 31（巴拉特）也是。
- 兩張中點矩陣（`docs/internals/data/star-graph.json`）**1024 對全部解得開**，
  沒有一對走不通。

所以在任何正常局面下 `2B99:0392` 填的是**全 1**。`internal/ai` 的
`TurnInput.Reachable` 因此可以放心地以「全部走得到」為預設——
那不再是猜測，是量出來的（測試 `TestStarGraphFullyConnected` 釘住）。

> 什麼情況會不是全 1？只有距離表裡真的塞了 `>= 0x800` 的格子。
> 表還沒取到，所以這一點仍是**待驗**；若原版真的用它擋住某些通道
> （例如伊謝爾倫回廊），那會是一條還沒被發現的規則。

## 還沒讀

`3BAA:0062`（`2B99:028F` 與 `2B99:0302` 進門都呼叫，不影響傳回值）、
距離表本身的數值。
