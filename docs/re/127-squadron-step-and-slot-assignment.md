# 127 — 分隊自己走那一步、以及槽索引是誰指派的

`docs/re/126` 收尾列了三項。這一輪解掉兩項，第三項（行程的扣法）
確定要靠一次「同一回合內兩次傾印」的收據才分得開。

## 「編隊」做的就是換一個槽位（`2BE1:03BE`）

```
在艦隊的分隊表裡找到這一筆（比對池索引）
艦隊 +0x10 + i×4 + 3 ← 新槽索引        ; 分隊表那一筆的第 4 個位元組
艦艇 +0x05            ← 新槽索引
艦艇 +0x1E            ← 0x7F           ; 行動清成「沒有命令」
call 2BE1:0059(艦隊, 艦艇)             ; 立刻把新目的地算出來
…重畫
```

所以**艦隊的分隊表一筆四個位元組**：`[0..1]` 池索引、`[2]` 未解、
`[3]` 槽索引；艦艇 `+0x05` 是同一個值的複本。

「編隊」的互動選擇（`2BE1:06C5`）長什麼樣還沒量，但**它的結果只是這一個
位元組**——選完槽位、行動清成 `7F`，剩下的就交給
`docs/re/126` 那條隊形算式。

## 下了移動命令的分隊怎麼走（`1C61:03AA`）

```
if 艦艇 +0x34/+0x36 ＝＝ +0x28/+0x2A：已經到了 → 收工
if 艦艇 +0x04 == 7（索敵分遣隊）：跳過下面那條
if (32 位元) 艦艇 +0x26:+0x24 < 8：            ; 這一回合的行程不足一步
    艦艇 +0x1E ← 3（歸隊）                     ; ← 走不動就自動改成歸隊
    +0x24／+0x26 ← 0
    回 0
走一步：1C61:0444(艦艇, 8)
```

`1C61:0444` 與艦隊那支同一個形狀：先用 `3310:0006` 算現在到目的地的距離，
不到一步就直接歸位，否則沿方位走 8 像素。

**「行程不足一步就把命令改成歸隊」是一條實際的遊戲規則**——玩家下了移動
但那一回合走不動的分隊，會自己回到隊形位置。

## 行程的扣法：還是對不平

讀出來的規則：

- 轉向那一步（`1C03:0554`）在「一次轉到位」那條分支**既不檢查也不扣**；
  要轉滿一步才檢查 ≥ 8 並扣掉（扣的是 `cx:si`，看起來是 8.0 的 16.16 表示）。
- 前進那一步扣掉實際距離（16.16）。

但收據 `s3fltmove` 的數字對不上：`+0x56`／`+0x58` 從 430,448（16.16 的
6.57）變成 249,108（3.80），花掉 2.77；而朝向從 190 轉到 163 照規則要
兩步（一步轉滿 15、一步一次到位），只有第一步該扣，扣的又該是 8.0。
**三個數字（可用 6.57、該扣 8.0、實際扣 2.77）互相矛盾**，所以：

- 要嘛 `3CC9:00B9`／`3CC9:0070` 的參數配置我讀錯了（比較與扣的量不是
  8.0 而是別的刻度），
- 要嘛「之前」那個快照不在同一個回合邊界上（`s3cmd3` 與 `s3fltmove` 是
  兩次獨立的執行，中間差 20,000 萬步與四次點擊）。

**分不開之前不寫結論。** 要一份在同一次執行裡、`實行` 前後各傾印一次的
收據（`-dump-at` 兩個步數），才有辦法把「補」與「扣」分開。
