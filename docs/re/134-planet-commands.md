# 134 — 行星命令的四支常式

`docs/re/133` 解出行星選單開哪一張、哪一項可選，四項各自跳去哪裡。
這一輪把那四支讀掉三支半。

## 情報（`1373:1C71`）

```
視窗 = 1373:1CBC(行星)          ; 建一個 22 × 10 格的資訊視窗
loop: 3765:0036(&事件, 0)；事件 1 或 2 都結束
3603:00B4(視窗)                 ; 收掉
```

**按左鍵右鍵都是關掉**，沒有別的互動。視窗裡印什麼在 `1373:1CBC`，
還沒讀——那要收據才對得起來。

## 補給（`1930:0DA2`）與補充（`1AAB:0A33`）

兩支與艦艇版（`docs/re/131`）同一個骨架，只換三樣東西：

| | 艦艇版 | 行星版 |
|---|---|---|
| 中心 | 艦艇 `+0x34`／`+0x36` | 行星 `+0x46`／`+0x48` |
| 陣營 | 艦艇 `+0x00` | 行星 `+0x11` |
| 半徑 | 艦種列 `+0x06` × 6.4 | **`2AF5:01F7`**：防衛力夾在 1500–6000 再 ÷ 25 |

那個半徑就是 remake 已經有的 `rules.PlanetQueryRadius`（`docs/re/89`
量行星查詢範圍時解出來的同一支）。篩選函式 `1930:10B2` 與艦艇版
`1930:0485` 逐條相同：同陣營、艦種不是 5／6／7、距離 ≤ 半徑。
沒有候選時跳 `ds:3FB0`「沒有需要補給的船艦。」

### 存量放在行星身上

**補給**（`1930:113E`）：滿載量的算法與艦艇版一模一樣
（艦種列 `+0x10`／`+0x14` × 目標**現有**艘數），扣的是

| 行星位移 | 內容 |
|---|---|
| `+0x3C`（32 位元）| 飛彈存量 |
| `+0x40`（32 位元）| 艦載機存量 |

開局兩者相等，都約等於該行星經濟力的 1.3 倍。

**補充**（`1AAB:0D9F`）補的是艘數：

```
存量 = 行星 + 0x20 + 目標艦種 × 4      ; 32 位元，每個艦種一份
給   = min(目標 +0x0A − 目標 +0x08, 存量)
```

注意上限是 **`+0x0A`（建制滿編）**，與艦艇的「修理」補到 `+0x0C` 不同。

這一組正好解掉 `docs/internals/29` 標成「未解」的 `+0x20`–`+0x3B`：
**那是七個艦種各一份的補充存量**（艦種 0–6，`+0x20` 起每個 4 bytes）。
艦種 7 那一格會落在 `+0x3C` 與飛彈存量重疊，但索敵分遣隊本來就不在
補充的候選裡，所以撞不到。八個槽在 81 顆行星上的非 0 數分別是
23／20／40／20／53／20／20／81——最後那個 81 就是飛彈存量，不是艦種 7。

## 要塞砲（`2264:0049`）

它不開火，只**指定目標**：

```
2264:0EC3(行星)：
    ds:A772 = 行星[+0x16]（防衛力）÷ 200 ＋ 80      ; 外圈
    ds:A774 = ds:A772 ÷ 4                            ; 內圈
中心 = (行星[+0x46] ＋ 7, 行星[+0x48] ＋ 7)
掛一個帶兩個半徑的圖形上去（3870:001A）
loop:
    3765:0036(&事件, 0)
    目標 = 2264:0133(代號, 行星, 游標)
    左鍵：行星[+0x50] = 目標；行星[+0x45] = 3
    右鍵：行星[+0x50] = 0xFFFF；行星[+0x45] = 0
```

所以 `+0x45` 是要塞砲的狀態、`+0x50` 是鎖定的目標——**`docs/re/133` 那條
「`+0x45` 不是 0 也不是 3 就關掉要塞砲」的意思是：只有「沒鎖定」（0）或
「已鎖定」（3）兩種狀態下才能重新指定**。開局 81 顆全是 0。

伊謝爾倫防衛力 12800 → 外圈 12800 ÷ 200 ＋ 80 ＝ **144**、內圈 36。

**開火在哪裡結算還沒讀。**
