# 155 — 艦隊選點的外形：逐像素對上了

`docs/re/135` 把 `165F:004D` 讀出來、也接進了 remake，但驗收只做到
「每個方位的最大半徑差 1.5 像素內、15 個點」。這一輪把它推到逐像素：
**折線在戰場裡亮的 487 個像素，收據上一個不差。**

差別在三處：積分那一圈是 do-while、畫線是原版自己的四支、
以及畫之前要做端點裁切。

## 一、積分那一圈是 do-while，而且 `rem` 是 16 位元無號

```
+00FC  mov  word [bp+12h], 0        ; a = 0
+0101  mov  ax, [bp+10h]
+0104  mov  [bp+14h], ax            ; rem = i
+0107  ← 迴圈頂端，**直接落進來，沒有前置判斷**
       …累加…
+0151  add  [bp+12h], ax            ; a += 回轉速度
+0154  sub  [bp+14h], ax            ; rem -= 回轉速度
+015A  cmp  ax, [bp+48h]
+015D  jnb  +0107                   ; **無號**比較
```

所以 `i = 0` 那一點也走一步，然後 `rem` 減成 `0xFFF1` 繼續繞——
回轉速度 15 的話要繞 4369 次才扣回小於 15。繞掉的那些是整圈的正弦，
幾乎互相抵消，看起來只差一兩個像素：最遠的那一點寫成一般的 while
是半徑 240.3，do-while 是 239.3，而收據量到的是 **238.8–239.0**。

一兩個像素不是可以放過的量：**每個線段都差**。同一份收據上

| 積分那一圈 | 折線落在外形上的像素 |
|---|---|
| do-while（原版）| 480 / 501 |
| 一般的 while | 355 / 501 |

## 二、旋轉在產生端，不在消費端

`docs/re/135` 說消費端「沒有縮放、沒有旋轉」，那是對的——旋轉在
`165F:004D` 自己的第三圈：

```
+02F9  for k = 0; 2n > k; k++:
+0308      3A92:0001(&點[k].x, &點[k].y, 艦隊[+0x4A])
+033C  out[+8] = 2n                 ; 點數
```

`3A92:0001(&x, &y, 角度)` 是標準的整數旋轉，兩軸各

```
x' = (cos·x − sin·y + 512) >> 10
y' = (sin·x + cos·y + 512) >> 10
```

（`3A92:0062`／`3A92:0081`，正弦表 `ds:573A`）。第二圈是鏡射：
`點[2n−1−k] = (點[k].x, −點[k].y)`，所以 `p[0]` 與 `p[2n−1]` 在
`y = 0` 那一點上重合，折線是閉合的。

預算走完的那一支（`(i×16)÷回轉速度 > 距離`）會**把累加值清成 0 再存
一點**，也就是多一個落在圓心的點。收據這一組參數是先撞到「y 累加值
變負」那個出口，所以這一點沒被驗到。

## 三、畫線是原版自己的四支，畫之前先裁切端點

`39D7:0936` 依 `|Δx|` 與 `|Δy|` 分四支（`docs/internals/52`）。次要軸
用 0.16 定點累加、起始值 `0x8000`（等於四捨五入），**每畫完一點才
累加**；呼叫端 `3870:0833` 先把兩端按 x 排好。

裁切是 `3870:08FF` 的 Cohen–Sutherland（`3870:09F1` 算 outcode、
`3870:0A30` 把端點拉到邊界，除法往零截斷），矩形是
`ds:8D6A`／`8D6C`／`8D6E`／`8D70`，戰場那一組是 (16,60)–(463,419)。

**裁切換掉的是端點，不是「畫的時候跳過畫面外的點」。** 這一條是
最後兩個像素的來源：從 (108,394) 到 (117,427) 那一段，端點 y 超出
419，裁切之後變成 (115,419)——

```
x' = 117 + (419 − 427) × (117 − 108) ÷ (427 − 394)
   = 117 + (−72 ÷ 33)
   = 117 − 2 = 115                    ; 往零截斷
```

斜率因此從 9/33 變成 7/25，累加的相位跟著移，`y = 403` 與 `y = 414`
那兩點各往右一格——與收據相同。用「畫完再丟掉畫面外的點」得到的是
另外兩個像素。

## 四、共用端點會被 XOR 掉

折線每一段都含兩端，相鄰兩段共用的那個頂點因此被畫兩次；寫入是
**XOR**（`2376:1810` 把 Data Rotate/Function 設成 `0x18`），
所以每個轉折上少一個像素。收據上 13 個頂點正好都是底色，上下相鄰
的兩點才是外形的顏色——那不是漏畫。

## 收據怎麼比的

`s3cmdrange`（第 28 艦隊，回轉 15、巡航 30 → 距離 240、朝向 190，
圓心 (298,409)）。**顏色不能直接拿來當篩選條件**：外形的墨色是 1，
XOR 上去之後畫面上的顏色隨底色而定——

| 底色 | 是什麼 | 畫出來 |
|---|---|---|
| 3 | 戰場底色 | **2** |
| 6 | 藍色虛線格線 | 7 |
| 0 | 格線的洞 | 1 |

照上面三條走一遍，折線在戰場裡亮 **487** 個像素：482 個是色 2、
3 個是壓在格線上的色 7、2 個是色 1。**沒有一個落在解釋不了的顏色上。**
畫面上剩下的 358 個色 2 落在 26 個 16×16 的格子裡，是分隊的圖塊邊。

腳本 `tools/scripts/manoeuvre_shape_check.py`，測試
`internal/screen.TestManoeuvreOuterMatchesOracle`。
