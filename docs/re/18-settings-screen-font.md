# RE 18 — 設定畫面的字：粗體 ＋ 陰影

日期：2026-09-07
執行器：dosgolem-logh3 `8c8af90`
收據：`settings1e`
狀態：**已解**。事實整理進
[`docs/internals/25`](../internals/25-text-rendering.md)。

## 現象

遊戲設定畫面的標籤——「遊戲設定」「音源」「ＢＧＭ」「戰鬥ＢＧＭ」
「訊息速度」「動畫效果」「動畫速度」——用掃其他畫面那支 `read_line`
**一個都掃不出來**。把那一格的點陣拿去跟整張字型表比，最接近的一個
差 32 到 43 個位元：不是「差一點」，是不同的形狀。

## 字型檔沒有換（confirmed）

開設定畫面那一刻，probe 的檔案存取記錄裡全部都是 `GRAPH.IMG`，
一次 30 bytes（＝ 16 × 15 的全形字）：

```
#210450911 seek Graph.img → 44640   read 30 bytes
#210451495 seek Graph.img → 99240   read 30 bytes
#210452878 seek Graph.img → 100860  read 30 bytes
#210465735 seek Graph.img → 109500  read 30 bytes
```

沒有別的檔被開啟，所以字形資料是對的，差別在畫的時候。

## 追到寫 VRAM 的那一段

在那個字第一列的 VRAM 位址（`A1376`，＝ x 176、y 62）設監看，
寫入來自六個位址——`2376:10ED`／`10F1`、`110E`／`1112`、`1135`／`1139`。
監看報的是**指令執行完之後的 IP**，往回推出三對指令：

```
26 20 05      and es:[di],al        ; 結束在 10ED
26 20 65 01   and es:[di+1],ah      ; 結束在 10F1
26 20 05      and es:[di],al        ; 結束在 110E
26 20 65 01   and es:[di+1],ah      ; 結束在 1112
26 88 05      mov es:[di],al        ; 結束在 1135
26 88 45 01   mov es:[di+1],al      ; 結束在 1139
```

三對分別是**底色**、**陰影**、**本體**三趟。把三趟前後的程式讀完
就得到整個繪字流程，寫在 `docs/internals/25`。

## 變換是兩件事疊起來的

| 步驟 | 做什麼 |
|---|---|
| 加粗 | 字形緩衝區逐列 `v |= v >> 1`，往右加粗一格 |
| 陰影 | 第 r 列畫緩衝區第 r + 1 列、整列往左移一格，用色 3 或 7 |
| 本體 | 第 r 列畫緩衝區第 r 列，用屬性位元組的低四位 |

先前拿「原樣／加粗／放大兩倍」去比對畫面全部落空，是因為漏了
**兩個變換要一起套**，而且陰影與本體是**兩種顏色**——只抽色 7 的像素
會得到「加粗後的字身」，只抽色 3 會得到「陰影減掉字身」，兩種都不是
字型檔裡的形狀。

驗證方式是拿畫面上那一格的色 3 ＋ 色 7 聯集，對整張字型表 13,993 個
字形 × 12 種變換組合做最小差異搜尋（`tools/scripts/glyph_match.py`）：

```
最小差 0 位元 @ (176,62) 位移 126030(0x1EC4E) 變換「粗右+左上」
```

只取色 7 也是 0 位元，變換「粗右」——與「陰影先畫、本體後畫蓋上去」
一致。

## 硬體那一側不改形狀（confirmed）

`-vga-regs-at` 攔那一步的圖形控制器狀態：

```
GC  = 07 0F 00 00 00 0B 00 00 FF
      ^Set/Reset       ^Mode      ^Bit Mask
```

`Mode = 0x0B` ＝ write mode 3，CPU 寫出去的位元組就是位元遮罩，
只決定哪些像素上色。同一個 `Mode` 位元組的 bit 3 是 read mode 1，
配上 Color Don't Care ＝ 0，讀 VRAM 一律回 `FF`——所以
`and es:[di], al` 的遮罩就等於 `al`，那個 `and` 只是順手把 latch 讀進來。

## 順帶查到、與這件事無關的一段

寫入點往前約 `0xB7` bytes 有一支 **VRAM 對 VRAM 的搬運**：
設 write mode 1、`ds` 與 `es` 都指到 `A000`、來源與目的各算一組
`(x, y)` → `y*80 + x/8`。攔它的執行時參數，四次都在開場階段，
參數是「來源 (0, 480) → 目的 (240, 270)」——**來源 y ＝ 480 在螢幕之外**。
遊戲把素材放在離螢幕那段顯示記憶體裡再搬進畫面。

設定畫面開啟的那段時間它一次都沒被呼叫（`-regs-from 210260000` 攔到 0 次），
所以標籤不是這樣搬過去的。

## 結果
