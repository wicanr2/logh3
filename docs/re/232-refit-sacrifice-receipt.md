# 232 — 「編制已滿要犧牲一組」有收據了；順帶看到 `[2]` 會被刷回來

`docs/spec/031` 列了三條實作了但沒有收據的分支。這一輪拿到其中一條，
另一條的注入方法失敗——失敗本身是個發現。

## 收據 `refit3`

同一條輸入序列，兩個注入都下在 `#230000000`（第一個 AI 回合之後、
第二個之前）：

| 注入 | 目標 | 想測的分支 |
|---|---|---|
| `lin:61913=63` | 艦隊槽 28 組1 的 `[3]`（隊形槽）10 → **99** | 編制已滿要犧牲一組 |
| `lin:616B4=02` | 艦隊槽 23 組2 的 `[2]`（艦種）3 → **2** | `2D76:0C4F` 回非 0（覆蓋同槽）|

傾印 `refit3_pre.bin`（`#242800000`）與 `refit3_post.bin`（`#246000000`），
整補在 `#242631032`。

## 犧牲那一條：成立

艦隊槽 28（提督 52，類別鍵 04，編制 4／4 全滿），樣板前四格的隊形槽是
`20 10 12 29`：

```
前  組0 00 00 00 14   組1 02 00 00 63   組2 03 00 00 0c   組3 04 00 06 1d
後  組0 00 00 00 14   組1 02 00 00 0a   組2 03 00 00 0c   組3 04 00 06 1d
                                ^^
星域 30 待命部隊：前後都是 [3000 0 4000 0 3000 0 0]
```

代進 `docs/re/229` 的規則：

```
併殘部：四組都滿編 → 不動
補編制 樣板第 1 格 (0,10)：a = 旗艦艦種 = 0
    2D76:0C4F(艦隊, 0, 10)：沒有一組的槽是 10（被改成 99）→ 回 0
    編制已滿（+0x0F == +0x0E == 4）→ 2D76:0D40
        組0 槽 20 在樣板裡 → 不是
        組1 槽 99 不在樣板裡 → **回 1**
    2AD2:018C 拆掉組1：3000 艘還回待命部隊[0] → 6000
    重建：min(6000, 滿編 3000) = 3000 → 待命部隊[0] 回到 3000
    組1[3] = 樣板的 10                                   ← 傾印 0a ✓
樣板第 2、3 格：槽 12、29 都在而且艦種相同 → −1，跳過
```

**待命部隊前後相同**是因為「拆掉還回去」與「重建拿走」是同一個數，
不是因為什麼都沒做——`[3]` 從 99 變回 10 證明那一組真的被重建過。
艦艇索引仍然是 #2：`2AD2:018C` 把那一筆標成空槽（`+0x01 = 0FFh`），
`2AD2:0029` 再配置時拿到的就是同一格。

釘在 `TestRefitSacrificesStaleSlot`。

## 覆蓋那一條：注入沒有存活

艦隊槽 23 的組2 在 `#230000000` 被改成 `[2] = 2`，但 `#242800000` 的
傾印裡它又是 `03`：

```
前  組2 0c 00 03 05     ← 注入寫的是 02
```

**同一跑裡艦隊槽 28 的 `[3]` 注入活到最後，槽 23 的 `[2]` 沒有。**
所以不是注入機制的問題——是**有東西會把 `[2]` 從別處刷回來**，
而 `[3]` 不會。最可能的來源是艦艇記錄的 `+0x04`（`docs/re/224` 量到
兩者一直同值），但**誰刷的還沒查**。

三個佐證：這一跑的 `2D76:0732` 步數（`#213725680`、`#242631032`）與
完全沒有注入的 `refitwhen` 相同，而有效注入的 `refit2` 是
`#243072663`——所以槽 23 那個注入對執行路徑一點影響都沒有。

## 還缺收據的兩條

- `2D76:0C4F` 回**非 0**（覆蓋同槽但艦種不同）：要先找到 `[2]` 的刷新點，
  或改注入艦艇記錄的 `+0x04`。
- 替代清單裡的 `0xFE`（艦種 5／6 平衡）：要把那一格的艦種 0／2／4
  存量清成 0、5／6 留著。

## 一條方法

**注入之後要先確認它還在。** 這一輪兩個注入下在同一跑、同一個步數，
一個活著一個被蓋掉；如果只下了失敗的那一個，看到的會是「分支沒觸發」，
而結論會變成「規則讀錯了」。**傾印裡先驗注入值，再看結果**——
`-poke` 的報告只證明「寫進去了」，不證明「還在」。
