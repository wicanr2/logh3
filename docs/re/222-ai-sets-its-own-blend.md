# 222 — `Blend` 是戰略 AI 每回合自己按軍事費設的

`docs/re/207` 找 `ds:8FD4`（未安定度公式的 `Blend`）的升降事件，掃遍
1 MB 傾印之後說「`0x09413` 一個呼叫者都沒有，多半在沒載入的 overlay」。
`docs/re/220` 也把 `turn260` 那一趟的稅率下降接到同一支上，結論是
「要對上得先有 `Blend` 的升降事件，那一項還沒解」。

那個事件在 `turn260` 那一跑裡**真的發生過**，所以改用監看直接問它是誰。

`2D10` 就是戰略 AI 自己的段（`2D10:0005` 是 AI 入口）。位址回報的是
指令執行**之後**的 `CS:IP`，所以寫入指令在 `2D10:0426` ＝ 線性 `0x2D526`
——`docs/re/206` 那張表裡列過但沒讀的 `mov [bx+8FD4], al`。

**不是外部事件，是 AI 自己調的。**

## `2D10:0319` 全文

線性 `0x2D419`：

```
2D10:0319(旗標):                       ; 旗標在 [bp+0Eh]
    2703:09DD(&局部[0])                ; 回傳兩個位元組，之後沒有被讀
    若 ds:8F18 % 10 == 9：往下算       ; 月底（十次「實行」一個月）
    否則若 旗標 != 0：   往下算
    否則：等級 = 0，跳到寫入

    ; 軍事費 ＝ ds:8F52[陣營 × 4]，32 位元，比較走 3CC9:00B9
    軍事費 >= 50000 → 等級 = 2
    軍事費 >= 40000 → 等級 = 1
    軍事費 >= 10000 → 等級 = 2
    軍事費 >=  5000 → 等級 = 3
    軍事費 >=     0 → 等級 = 4
    軍事費 <      0 → 等級 = 2

寫入:
    ds:8FD4[ds:8F1D] = 等級
    090A:0B93(等級)                    ; 整批重算全國稅率（docs/re/223）
    090A:0E6D()                        ; 顯示層
```

`Base`（`ds:147E`）是 `50 75 100 150 200`，等級直接當下標，所以
**等級越高稅率越高**：40000–50000 那一段的 1 比 10000–40000 的 2 低一級。
頂端那一格（50000 以上回 2）與 10000–40000 同級，也與負值同級——
量到的就是這樣，不改寫成單調的。

## 誰呼叫它：只有 AI，而且一回合兩次

`farcall_to.py` 對線性 `0x2D419` 掃全傾印，兩處，都在 `2D10`：

| 呼叫點 | 位置 | 旗標 |
|---|---|---|
| `2D10:0010` | `2D10:0005` 的第一件事，在建艦隊之前 | **1** |
| `2D10:014D` | `2D10:0038` 裡，AI 回合的最後一支 | **0** |

所以一個 AI 回合的形狀是：

```
回合開始 → 等級 = f(軍事費) → 重算稅率 → 建艦隊、五個階段…
回合結束 → 月底才重算，否則等級 = 0 → 再重算一次稅率
```

**`Blend` 平時是 0，只有在 AI 自己的回合中間才是 `f(軍事費)`。**
建艦隊的預算門檻（`2D76:0060` 的 `ds:8FD4[陣營] >= 3` 打七五折，
`docs/re/202`）讀到的一定是這個中間值，換算過去就是
**軍事費不到 10000 才打折**。

玩家那一邊的座位不跑 AI，所以 `Blend` 完全不會動——`turn260` 兩份傾印
裡帝國（`5DB04`）從頭到尾都是 2，正是這個原因。

## 與收據對得上

`t260_pre.bin`／`t260_post.bin`（1 MB，`turn260mem`）：

| | 帝國 | 同盟 |
|---|---|---|
| 軍事費（`ds:8F52`）| 45592 | **45848** |
| `Blend` pre | 2 | 2 |
| `Blend` post | 2 | **1** |

45848 落在 40000–50000 → 等級 1，與監看抓到的 `02 → 01` 相同。
第二次的 `01 → 00` 是同一個 AI 回合結束時的 `2D10:0319(0)`：
回合數 260，`260 % 10 = 0` 不是月底，旗標是 0 → 等級 0。

## `2703:09DD`

`2D10:0319` 開頭把局部變數的位址（`ss:bp`）當成隱藏的結構回傳指標交給
`2703:09DD`。那一支先把回傳的兩個位元組清 0，再掃 32 個星域比擁有者
（`+0x12`）——形狀像兩個計數。**`2D10:0319` 沒有讀那兩個位元組。**

## 順帶量到的：統治者會在 AI 回合裡換

`t260_pre` 的 `ds:8F4F[同盟]` 是 60，`t260_post` 是 **63**。改寫點在
`2D10:0231`（線性 `0x2D3EE` 的 `mov [bx+8F4F], al`），換完同樣接
`090A:0B93(目前等級)` 重算一次稅率。`docs/re/220` 那份監看裡
`#214005767` 把星域 31 的稅率從 27 拉到 35，就是這一次
（換算見 `docs/re/223`）。**那一支還沒逐行讀。**

## 對 remake 的意義

`docs/re/220` 說「這一支差距目前補不了」——現在補得了。整條鏈是封閉的：

```
AI 回合開始 → Blend = f(軍事費) → 090A:0B93 重算稅率 → 總稅收改變
            → 建艦隊的閘門（維持費 × 20 >= 總稅收）提早或延後收手
```

`turn260` 那一趟同盟的總稅收 10599 → 7852，於是第四支艦隊沒有建成，
而 remake 停在 10599 建了四支（`docs/re/219`）。

## 一條方法

**靜態掃不到呼叫者，就換動態量。** `0x09413` 的呼叫者是真的不存在
（那一支在這份局面裡沒被走到），但「誰寫這一格」有另一個問法——
對那一格設監看，讓程式自己指出來。掃描回空只證明「用這個問法找不到」，
不證明「沒有」（`~/diagnosis-notes/docs/02-query-returned-empty/`）。
