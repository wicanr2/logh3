# 121 — 選目的地時原版檢查什麼

`docs/re/120` 停在「互動迴圈怎麼把游標夾進範圍裡」。答案是：**它不夾。**

## 點下去之後那條檢查鏈

點擊由 `2583:022B` 處理（`2583:013D` 的迴圈把它叫起來）：

```
1588:0362(模式, →x, →y, 畫面座標)     ; 畫面 → 世界；回 0 ＝ 點在戰場那一塊外面
  失敗 → 回 0FFFF（取消）
x < 0 或 x > 0x7EF（2031）  → 失敗
y < 0 或 y > 0x7E7（2023）  → 失敗
1588:04EA(x, y)                       ; 那個佔位框壓到的半格過不過得去
  回 0 → 印 ds:4A24「這是無法行動的地方。」（色 0x97），回 0FFFF
有朝向參數（艦隊層）→ 2583:02D9 再選一次抵達朝向
沒有（分隊層）      → 回 0FFFE，呼叫端就把座標寫下去
```

**兩個範圍圖形完全沒有出現在這條鏈裡。** `1588:04EA` 只收 (x,y)，是
地形判斷；距離、速度、朝向都沒有參與。所以 `docs/re/120` 量到的那兩圈
是**提示**，不是限制——點在圈外只要地形過得去就會被接受。

世界座標的上限 2031／2023 與戰場大小相符：128 × 102 格、格是 16 × 20
＝ 2048 × 2040 像素，扣掉一個 16 像素的佔位框就是 2032／2024。

## 艦隊層還要再選一次朝向

`2583:02D9` 建的是另一個圖形描述（`3870:001A` 掛上去畫）：

```
[+0]／[+2] = 選到的點（各 ＋7）
[+4] = 朝向（艦隊 +0x4A）    [+5] = 4   [+6] = 4   [+7] = 1
[+8] = 0x40（64 ＝ 1/4 圈）  [+0A] = 0x20  [+0C] = 0x20（各 45°）
[+0E] = 0FFFF
```

選完寫進 `ds:A77E`／`ds:A77F`，最後回到 `2583:0003` 寫進艦隊 `+0x4C`
（目標朝向）。所以**艦隊的「移動」是兩段互動：先點目的地、再選抵達
朝向**；那個朝向選擇器的版面與操作還沒量。

## 外形是「轉彎可達範圍」

`165F:004D` 的迴圈用 `ds:573A` 那張正弦表（一整圈 256、值 ＝ sin × 1024，
`docs/internals/41`）**沿著回轉速率積分**：每一步轉「回轉速度」那麼多，
位移取 `sin`／`cos` 左移 3 位累加；掃到剩下不足一步就把餘量算完，
再把「總路程 − 已經走掉的弧長」當直線加上去。也就是

> 先以固定回轉速率轉 θ、剩下的路程直行 —— 這些終點的軌跡

θ 由外層迴圈掃，點寫進 `ds:9C1A` 那張表。這解釋了 `docs/re/120` 量到的
「圓心在艦隊前方 46 像素、最大偏差 4.9（不是正圓）」。**逐點的定量重現
還沒做**（要照抄 `3CC9:0009`／`3CC9:0070` 的 32 位元乘除與捨去）。

## remake

分隊層的「移動」照這條鏈實作了（`docs/spec/024`）：邊界與
`rules.BattleTerrain.Passable`（本來就是 `1588:04EA` 的重寫）都套上，

規格裡。艦隊層的「移動」要等朝向選擇器，還沒接。
