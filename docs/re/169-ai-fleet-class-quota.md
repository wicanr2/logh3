# 169 — 艦隊有「類別」，AI 照 40／45／5／10 的配額補

`docs/re/168` 解 `2E54:1574` 時出現一個沒看過的東西：
`權重表[ ds:5F52[艦隊[+0x09]] ]`。把 `ds:5F52` 的三個讀取點都追過去之後，
浮出來的是一整套 AI 建艦隊的邏輯。

## `ds:5F52` ＝ 艦隊類別表

`ds:5F52` 前面是一張 8 筆的遠指標表（`ds:5F32`–`ds:5F51`），所以表確實從
`ds:5F52` 開始。三份記憶體 dump（`s3ai6`、`s3turn2`、`s3fltmove`）內容相同：

```
5F52: 00 00 00 00 00 02 00 00 00 00 01 01 02 02 03 03
```

**16 格，值 0–3**：`+0x09` 是 5 → 類別 2；10、11 → 類別 1；
12、13 → 類別 2；14、15 → 類別 3；其餘 → 類別 0。

值域 0–3 對得上兩件事：`2E54:1574` 的權重表只有四個 byte，
`ds:D506` 的計數器只 memset 8 bytes ＝ 四個 word。

## 三個讀取點

| 位址 | 用途 |
|---|---|
| `0x2FBB9`（`2E54:1574`）| 選 `2E54:143F` 那四個權重裡的哪一個 |
| `0x2D8E7`（`2D76:0187`）| 數各類別現有幾支 → `ds:D506` |
| `0x2F392`（`2E54:0E52`）| 類別 3 的艦隊不派去支援 |

## `ds:D506` ＝ 四個類別的缺額

`2D76:011B()`（`0x2D87B`）：

```
3C9C:000A(ds:D506, 0, 8)                  ; 四個 word 清成 0
筆數 = 297B:131C(&清單, 0FFh, 1)          ; 我方全部艦隊（星域 0FFh ＝ 不限）
對清單裡每一支：
    艦隊 = ds:C074 + 索引 × 122
    若 艦隊[+0x00] bit0（無法戰鬥）：跳過
    ds:D506[ ds:5F52[艦隊[+0x09]] ]++
回 有效艦隊數
```

`2D76:01A5(總數)`（`0x2D905`）把配額扣掉：

```
ds:D506 -= 總數 × 40 ÷ 100
ds:D508 -= 總數 × 45 ÷ 100
ds:D50A -= 總數 ×  5 ÷ 100
ds:D50C -= 總數 × 10 ÷ 100
```

扣完之後 `ds:D506` 存的是「**現有 − 應有**」，**負得越多代表越缺**。
接著把 `[0,1,2,3]` 用 `3C6A:000D`（qsort）依 `2D76:0251` 排序——那個比較
函式就是比兩個類別的 `ds:D506`，**升冪**，所以最缺的排最前面。然後照順序
`2D76:02FA(類別)` 一個個試，回非 0 就停；四個都不成回 0。

四類的目標比例是 **40％／45％／5％／10％**，寫死在程式裡。

## 整趟：`2D76:0002()`

```
首都星域 = (ds:8F1D == 0) ? 0 : 31            ; 帝國 0、同盟 31
若 星域表[首都][+0x12]（擁有者） != ds:8F1D：什麼都不做
重複：
    n = 2D76:0060()
    若 n == 0FFFFh：結束
    若 2D76:01A5(n) == 0：結束
```

首都丟了就不再建艦隊。`2D76:0060` 還沒讀（它應該是先呼叫 `2D76:011B`
把 `ds:D506` 填好、再回一個總數，`0xFFFF` ＝ 不能再建）。

## `2E54:0DE3(候選陣列, 個數, 目標星域)` ＝ 派支援

`docs/re/167` 列的三個未讀函式之一，這一輪一併解掉：

```
若 ds:D54E[目標星域]（word） >= 12：不派
支數 = 1
若 3CD5:000C() < 2000h（1／4）且 個數 >= 2：支數 = 2
對 k = 0 … 支數−1：
    艦隊 = 候選陣列[個數 − 1 − k]          ; 從尾端往前取
    若 ds:5F52[艦隊[+0x09]] == 3：跳過      ; 類別 3 不派
    艦隊[+0x08] = 1                        ; 移動
    艦隊[+0x07] = 目標星域
    艦隊[+0x79] = 1
```

陣列是**從尾端取**，代表呼叫端已經把最好的排在後面。
`ds:D54E` 是以星域為索引的 32 個 word（後面接著 `ds:D58E` 的 32 個 byte，
`0x2EF00` 讀它），語意還沒解，只知道 `>= 12` 就不再往那裡派。

## 艦隊 `+0x09` 是誰寫的

掃 `26 88/C6 <modrm> 09` 六個命中裡，寫**艦隊**（`ds:C074 + i×122`）的
只有 `0x2DE66`：

```
艦隊[+0x09] = 某筆記錄[+0x08] >> 4        ; 高四位，所以值域 0–15
```

那筆記錄的 `+0x07` 在同一個函式裡被拿去索引提督表（`ds:B77C`，一筆 28），
`+0x08` 的高四位給艦隊、低四位另有他用。**這筆記錄是什麼還沒解**，
所以「類別」的遊戲意義（艦種傾向？任務型態？）也還沒解——
目前只能說它是一個 0–15 的鍵，經 `ds:5F52` 收斂成四類。

其餘五個命中：`0x293EE`、`0x2D269`、`0x2D33A` 寫的是提督記錄的 `+0x09`
（`docs/internals/08` 的那個夾成 `0x7F` 與最高位旗標），`0x2DDF9` 那段是把
艦隊的 `+0x09` **複製**進提督記錄，`0x37EE3` 是別的結構的建構子。
