⚠ **`-dump-mem` 的檔名不能含連字號**：`probe` 用「字串裡有沒有 `-`」判斷是
`<addr>:<len>:<path>`（`lin:` 前綴）還是 `<lo>-<hi>:<path>`（純十六進位範圍）兩種寫法；
批次名習慣帶連字號（`fcx-r8-63-ds-security.bin`）會被誤判成範圍格式，
噴 `dump-mem 位址解不開: expected integer`。本輪改用無連字號檔名＋
`<lo>-<hi>:<path>` 範圍格式繞開，供之後的人參考。

⚠ **`-mouse-at`／`-clicks` 的步數是全程絕對步數，不是相對載入點的步數增量**：
從 `-save-state "S:path"` 存的檢查點載入後，後續事件的步數要填 **> S** 的絕對值
（例如檢查點存在 469999999，下一個動作要填 472000000 而非 2000000），
否則事件已經「過去」，`report.txt` 的「滑鼠輪詢 0 次／鍵盤中斷送出 0 次」
就是漏接的訊號。

往前找函式入口＝`0A0FD`（`retf` 緊接 `push bp; mov bp,sp`）。把整段切成 `.com`
（`seg_to_com.py <1MB dump> 0 A02 1200 …`，段值 `0A02` 是**程式碼裡的立即值**
`mov ax,0A02h`，不是本輪自訂的框——這一段的絕對段值本身是穩定的，變的只是
「線性位址」這個換算結果）反組譯：

```
0A02:017A(win_lo, win_hi)               ; 開情報收集畫面／每次分頁切換後的重繪
  al=97h → [bp+0]=[bp+1]=[bp+2]=97h     ; 三個分頁核取方塊先全部設「未選中」
  bl=ds:8F1E（現在的座位，既有全域，見 docs/re/175 等）
  al=ds:8F2F[bx]                        ; ← 本輪新解出的全域：目前分頁（0/1/2）
  switch(al):
    0: ds:9590:958E ← far 0A02:02CE（治安內容常式）; [bp+0]=27h（選中）
    1: ds:9590:958E ← far 0A02:0483（敵艦內容常式）; [bp+1]=27h
    2: ds:9590:958E ← far 0A02:06A3（勢力內容常式）; [bp+2]=27h
  37A9:02B1(win, &list[0x1738], [bp+0])  ; 畫治安核取方塊
  37A9:02B1(win, &list[0x1744], [bp+1])  ; 畫敵艦核取方塊（entry 1，位移 +0xC）
  37A9:02B1(win, &list[0x1750], [bp+2])  ; 畫勢力核取方塊（entry 2，位移 +0x18）
  call dword ptr ds:958E                 ; 間接遠呼叫目前分頁的內容常式
  341B:02E5(win)                         ; 顯示（與 docs/internals/59 的「印列」慣例同一支）
```

`37A9:02B1(win, 鈕, 屬性)` 與 `docs/internals/59`／`docs/re/327` 記的一覽表分頁
**是同一支登錄常式**，屬性選中 `0x27`／未選中 `0x97`，只是這裡三個分頁共用

**proven（位元組）**。

### 3. 點擊分派：`0A02:08E7`（每次輸入事件的處理常式）

```
0A02:08E7(..., win_lo=[bp+16], win_hi=[bp+18], cursor_x=[bp+1A], cursor_y=[bp+1C], ...)
  (ax,bx) = 341B:039D(cursor_x, cursor_y)      ; 全域命中測試，找游標下的視窗
  若 (ax,bx) == DS:F144（左上星圖，docs/internals/24 的視窗串列表）：
      3705:0DC(cursor_x,cursor_y) → 星域 index；星域名 hover、73F:5CB(region) ……
      （與本次任務無關的「地圖 hover 顯示星域名」既有機制，順手核對到）
  否則：
      (ax,bx) = 37A9:01F9(win, &ds:1738, cursor_x, cursor_y)   ; 命中測試（熱區清單 1738）
      若 (ax,bx)==(0,0)：無動作，回到共用出口
      否則：
        action = es:[bx+5]                     ; 熱區 +0x05＝動作碼（0..4）
        cmp action,4; ja 無效 → 共用出口
        jmp word ptr [action*2 + 19F6h]         ; 跳躍表，5 個入口
```

**跳躍表五個入口（本輪逐一讀過，proven（位元組））**：

| action | 對應標籤 | 做的事 |
|---|---|---|
| 0 | 治安 | `ds:8F2F[ds:8F1E] = 0`；呼叫 `0A02:017A` 整塊重繪（分頁框＋內容＋顯示）；跳共用出口 |
| 1 | 敵艦 | `ds:8F2F[ds:8F1E] = 1`；同上重繪；跳共用出口 |
| 2 | 勢力 | `ds:8F2F[ds:8F1E] = 2`；同上重繪；跳共用出口 |
| 3 | 參謀 | 把命中的熱區**閃一下選中色**（`37A9:02B1(...,0x27)`）→ 呼叫 `0A02:0AC4()`（見下）→ **再閃回 0x87**（`37A9:02B1(...,0x87)`，不是 0x97！）→ 重新呼叫 `ds:958E`（目前分頁內容常式）與 `341B:02E5`（顯示）→ 跳共用出口 |
| 4 | 確認 | 把命中的熱區閃一下選中色（`0x27`）→ **不重繪、不呼叫內容常式**，直接把本函式的回傳值設成 `0xFFFF`、`retf` |

**確認與參謀／分頁的關鍵差異**：0/1/2/3 四種都在最後跳到「共用出口」
（`+0x0B43` 起，見下段），4（確認）直接帶著 `0xFFFF` 提早 `retf`，**不經過共用出口**。
從行為看，`0xFFFF` 應該是回報給外層 modal 迴圈的「結束旗標」——這一段
（哪個函式在讀這個回傳值、怎麼判斷該不該關窗）本輪**沒有再往外追**，
標 `strong inference`（依 CLAUDE.md「右鍵＝離開目前畫面」同一套約定，
本輪用執行證據獨立驗證了「確認會關窗」，但外層迴圈怎麼消化 `0xFFFF`
是 `unknown`）。

### 3. 分頁狀態存在哪個全域變數，換座位／重開畫面記不記得

**proven（位元組＋執行期）**：`ds:8F2F[ds:8F1E]`（1 byte／座位，`ds:8F1E`
是既有、大量文件確認過的「現在的座位」索引，例如
`docs/internals/54-strategic-ai-decision.md`、`docs/re/175`／`186`／`187`／`198`
等一路沿用到現在；`ds:8F2F` 本身**本輪第一次解出**，之前沒有任何文件提過）。

- **執行期證據**：對治安／敵艦／勢力三個分頁各倒一份 DS 段（`54B30-64B30`，
  64KB）逐位元組比對，整段裡**唯一**同時符合「三份傾印在同一位置分別是
  0／1／2」的位址就是 `ds:8F2F`（線性 `0x5DA5F`）。
- **反組譯證據**：分頁 0/1/2 的處理常式各自執行
  `mov bl,ds:8F1Eh; mov byte ptr [bx-70D1h], <0|1|2>`（`-0x70D1` 在 16 位元
  環繞下等於 `+0x8F2F`，即 `ds:8F2F[bx]`），與畫面重繪時讀值的
  `mov al,[bx-70D1h]` 用的是同一個位址算式。
- **持久性**：`fcx-r8-63-enemy-confirm`（切到敵艦分頁 → 按確認關窗）→
  `fcx-r8-63-reopen`（重新走命令列「戰略命令→情報收集」開一次）
  結果畫面仍停在**敵艦分頁**（勾選框、地圖著色、圖例文字都是敵艦那組），
  `screen.bin` 與單獨開敵艦分頁的畫面吻合。**這條路徑等同右鍵關閉的另一種
  出口**（`確認`＝按鈕；一般畫面右鍵是另一條，本輪沒有另外測「右鍵關閉
  情報收集」是否也保留分頁——`ds:8F2F` 本身不會因為畫面關閉而被歸零
  （沒有任何反組譯到的路徑寫回 0/1/2 以外的值或清除它），所以理論上必然
  記得，本輪只用「確認」這條路徑做了執行期驗證，標 `proven（確認路徑）`／
  `strong inference（右鍵路徑，未單獨測試但無理由不同）`）。
- **换座位**：`ds:8F2F` 是 `[座位]` 陣列（每座位 1 byte），架構上與同一批
  既有的 `ds:8F23[座位]`／`ds:8F25[座位]`／`ds:8F29[座位]` 完全一致——
  這批全局變數都是「一個座位一格」的慣例陣列。本輪**沒有實際切到座位 1
  測試**（S3 開局是單人對電腦，沒有第二個人類座位好切换），所以「座位 1
  是否也各自獨立記住」標 `strong inference`（架構與既有大量同類變數一致，
  沒有找到任何反例，但沒有執行期收據）。

### 4. 游標經過會不會反白、點了之後外觀怎麼變

**proven（位元組＋執行期，byte-diff 逐一核對）**：

- **游標「經過但不點」不會讓熱區反白**：`fcx-r8-63-hover-only`（只搬滑鼠到
  勢力分頁上方、不點擊）與 `fcx-r8-63-open`（滑鼠停在原地）逐位元組比對，
  全畫面只差 249 個像素、外接矩形 `x400..436 y145..183`；限定在「勢力」
  熱區框本身（`x400-449,y158-179`）只差 99 個像素——大小與位置都吻合
  **游標箭頭圖案本身**（斜向移動、與熱區框邊緣部分重疊），沒有任何
  超出游標範圍、疑似「整顆按鈕變色」的像素。反組譯也支持這個結論：
  `0A02:08E7`（每次輸入事件的處理常式）只在**命中測試回傳非零**（代表
  這一下真的落在某個熱區裡）之後才走跳躍表，跳躍表五個入口全部是
  「點擊之後」的動作，沒有另外一條「游標移到熱區上但沒點」的分支。
  **結論：這三個分頁與參謀／確認鈕沒有 hover 反白，只有點擊才變色**——
  與提示裡舉例的 `37A9:02B1(win,鈕,選中 0x27／其餘 0x97)` 是**同一支登錄
  常式**，但那個 0x27/0x97 是「選中／未選中」的**持久**狀態，不是「游標
  正壓在上面」的**暫時**狀態。
- **點下去外觀的變化，兩種鈕不一樣**：
  - **分頁（kind=5，頁籤）**：點中的那個變成 `0x27`（核取方塊填色，紅框），
    其餘兩個變回 `0x97`（未選中）——**持久**，直到換別的分頁才會變。
  - **參謀／確認（kind=0，一般按鈕）**：點下去先閃一次 `0x27`
    （視覺上像被按下），**參謀**閃完之後、跑完子畫面流程再閃回 `0x87`
    （回到平常樣子，不是原本一般按鈕慣用的 `0x97`——`0x87`／`0x97` 兩者
    在本專案其他地方都出現過，這裡兩顆鈕的「平常」色碼哪個對，本輪只
    確認了位元組本身，沒有另外反查 `0x87` 與 `0x97` 的視覺差異，
    標 `hypothesis`）；**確認**閃了 `0x27` 之後就直接帶著結束旗標返回、
    畫面本身立刻被關掉的下一幀蓋掉，等於「閃一下顏色沒被畫出來就結束」，
    **本輪沒有另外錄一張「按下確認那一瞬間」的收據去看那個 0x27 到底有
    沒有真的畫出來一幀**，標 `unknown`。

`65535`／`192`／`21981`／`43742` 這種值成對重複的樣子**不像距離或索敵累計值，
