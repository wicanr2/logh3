# 182 — 提督 `+0x09` 的最高位 ＝ 這個提督沒有帶艦隊

`docs/re/181` 把新編艦隊停在 `07F9:02CB`（能不能編）與 `07F9:033A`
（副官合不合格）。兩支都在 `0x8xxx`，用 1 MB 完整傾印讀（`docs/re/181`
的工具洞）。讀完之後，一個從 `docs/re/43` 就掛著的旗標有了意義。

## `07F9:02CB(星域, 陣營, 艦種) → 0／1`

```
存量 = 星域[+0x30 + 陣營 × 28 + 艦種 × 4]        ; 32 位元
門檻 = ds:4E3A[陣營 × 208 + 艦種 × 26]           ; word（艦種表）
回 (存量 >= 門檻) ? 1 : 0
```

星域記錄 `+0x30` 起每個陣營 28 bytes ＝ **7 個 32 位元存量**（一個艦種一個），
與行星記錄 `+0x20` 起那 28 bytes 是同一個形狀（`docs/internals/29`）。
`ds:4E3A` 是艦種表（`docs/spec/018`），一筆 26 bytes、一個陣營 208 bytes ＝ 8 筆。

「艦種」這個索引來自 `提督[+0x08] & 0x0F`（`07F9:023B`）。
所以 **`提督[+0x08]` 的低四位決定他能帶哪一種艦，而編得成編不成看
那個星域有沒有足夠的該艦種存量。**

## `07F9:033A(提督) → 副官成不成立`

五個條件全成立才回 1：

```
副官 = 提督[+0x07]
副官 != 0FFh
副官[+0x09] bit7 有設
副官[+0x00] == 0FFh
副官[+0x0A] == 提督[+0x0A]           ; 同一個星域
副官[+0x06] <  提督[+0x06]           ; 副官的這一項要比主將小
```

## `+0x09` bit7 ＝ 沒有帶艦隊

把兩邊擺在一起就清楚了：

- `2D76:0611` 配到艦隊槽之前先 `提督[+0x09] &= 7Fh`——**編上艦隊就把
  這一位清掉**（`docs/re/181`）。
- `07F9:033A` 要求候選副官**這一位有設**——**只有沒帶艦隊的提督
  可以當副官**。

`+0x09` 的低七位是艦隊槽（`docs/re/180`），所以最高位就是
**「這個槽號還不算數／這個提督現在沒有帶艦隊」**。

這回頭解釋 `docs/re/43` 的不穩事件：它挑的是「在這個星域、
`+0x00 == 0xFF`、而且 `+0x09` 最高位有設」的提督——也就是
**在那一格、沒有職務、也沒有帶艦隊的閒置提督**。
`07F9:033A` 用的是同一組條件的前三項（`+0x00 == 0xFF`、bit7 有設），
兩處獨立的用法指向同一個語意。

> 與 `docs/spec/006`／`docs/internals/08` 的張力還在：那邊量到
> `ADMIRAL.DT*` 載入時 `+0x09` 被夾成 `0x7F`，最高位一定是 0，
> 於是開局沒有任何「閒置提督」。**若 bit7 真的是「沒帶艦隊」，
> 那載入後就不會有人符合當副官的條件**——要嘛載入之後另有一段把它補設
> 起來，要嘛夾值那一段的解讀要重看。這一輪沒有量，先記成待驗。

## 提督 `+0x06`

副官要求 `副官[+0x06] < 提督[+0x06]`。`admiral.json` 裡 `f6` 是
0–255 的值（第 0 筆是 39）。形狀像**階級／地位**（副官要比主將低），
但沒有其他證據，標假設。
