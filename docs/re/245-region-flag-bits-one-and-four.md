# 245 — 星域 `+0x13` 的 bit1 與 bit4：第二支逐格常式

`docs/re/244` 解出 `2703:0933` 寫 `+0x13` 的 bit0／bit2／bit3，並注意到它
`and 0F2h` 只清這三個位元——bit1 與 bit4 是別處維護的。**別處找到了**，
而且入口就藏在 `docs/re/105` 那份收據裡。

## 入口：`056A:04D6` 不是「進入戰鬥」

`docs/re/105` 把

```
#409750808 5FFAB: 08 → 0C  ← 056A:04D6
```

標成「進入戰鬥」。那個位址其實是一條指令的**下一個位址**：

```
056A:04D2  26 80 0f 04     or byte es:[bx], 4      ; +0x13 |= bit2
056A:04D6  eb 46           jmp …
```

它屬於 `056A:0468`——另一支逐格掃 32 個星域的常式，與 `2703:0933` 平行。

## `056A:0468`

```
056A:0468  push bp / push si / sub sp,0Eh / mov bp,sp
           call far 2703:09DD(&buf)                ; 先備一份東西
           for 星域 i in 0..31:
               [bp+1] = +0x13                      ; 存舊值
               and byte es:[bx+13h], 0E9h          ; 清 bit1 | bit2 | bit4
               297B:14F8(星域記錄, &帝國數, &同盟數)
               if 帝國數 != 0 && 同盟數 != 0:
                   +0x13 |= 04h                    ; bit2
               elif 帝國數 != 0 && 擁有者 != 帝國:
                   +0x13 |= 10h                    ; bit4
               elif 同盟數 != 0 && 擁有者 != 同盟:
                   +0x13 |= 10h                    ; bit4
               elif 2703:1789(i, &out) != 0:
                   +0x13 |= 02h                    ; bit1
               056A:053F(星域記錄, 舊的 +0x13)      ; 拿新舊比對
```

`0E9h` ＝ `11101001`，清掉的正是 bit1｜bit2｜bit4；`2703:0933` 的 `0F2h`
＝ `11110010` 清掉 bit0｜bit2｜bit3。**兩支互補，只有 bit2 兩邊都寫**，
而且條件相同（`297B:14F8` 回的兩個數都非零）——所以不會互相打架。

## bit4 ＝ 單方面占據

條件寫開就是「**有一方的艦隊停在不屬於它的星域裡，而另一方沒有艦隊**」。
擁有者是自己的話不算——艦隊待在自家地盤不設這個位元。

這解釋了 `docs/re/197` 看到的 `test byte es:[bx+13], 14h`（bit2｜bit4）：
`2E54:005D` 在艦隊 `+0x00` bit0 有設的那一路拿它當「**不能留在這裡**」的
第一個條件。兩種情形確實都待不住——這一格正在打，或者這一格被人單方面
占著。

## bit1 ＝ `2703:1789` 非零（尚未完全解）

`2703:1789(星域編號, &out)` 前半段是四個提早回 0 的條件：

```
星域 == 0（瓦爾哈拉）或 == 31（巴拉特）   → 0
擁有者 == 2（無主）                        → 0
星域記錄 +0x28 + 擁有者（該陣營在這一格的艦隊數）!= 0 → 0
```

也就是**首都不算、無主不算、自己有艦隊駐守就不算**。過了這三關之後
它查 `ds:8F4D[擁有者]` 那個提督編號、取提督記錄（`ds:B77C` ＋ 編號 × 28），
再擲一個 `亂數 % 400`。

**後半段還沒讀**，所以這裡只寫到「它是一個帶亂數的事件判定，前置條件是
沒有駐軍的非首都自方星域」。**不要當成規則實作。**

## 誰呼叫這兩支——沒找到

`056A:0468`（線性 `05B08`）與回合結束那支 `056A:078B`（線性 `05E2B`）
都掃不到呼叫點：`farcall_to.py` 枚舉所有段值回 0 處，段內 `E8` near call
也是 0 處。這個遊戲有模組管理器（`docs/re/04`），呼叫多半走間接向量
（`FF 1E`／`FF 1F`），靜態掃不到。

**所以這兩支的執行時機還沒釘住**，remake 先不實作 bit1 與 bit4——
`regionBlocked` 讀的 `& 0x14` 目前仍是載入時的位元組。要往下走得追那張
向量表，或對 `056A:0468` 設 `-regs-at` 從執行時間反推。

## 一條方法

**收據裡「某某位址寫了這一格」的位址是指令的下一個**，不是指令本身。
`056A:04D6` 被當成「進入戰鬥」寫在文件裡半年，其實是 `056A:04D2` 那條
`or` 的下一個位址——而那條 `or` 屬於一支完全不同的常式。位址對不上函式
邊界時，先往回退幾個位元組看看那條指令是什麼。

---

## 執行時機量到了（收據 `flagpass`）

`-regs-at 056A:0468,2703:08DE,2703:0933 -regs-max 120 -watch 5DA48-5DA49`，
新遊戲按一次「實行」：

```
#218118662   056A:0468        （bit1／bit2／bit4 那一輪，1 次）
#218904226   2703:08DE        （擁有者重算 → 重建路徑表 → 32 格態勢，1 次）
#221176818   2703:0933 第 64 次（＝ 2703:08DE 那一圈的最後一格）
#221187705   ds:8F18 回合計數器 00 → 01
```

`2703:0933` 一共 64 次：前 32 次在 `#70888555` 起（新遊戲初始化那一個
呼叫者），後 32 次在 `2703:08DE` 那一圈裡。

所以**一次「實行」的尾巴是**：

```
056A:0468  →  2703:08DE  →  回合計數器 +1
```

兩支都在回合遞增之前，`056A:0468` 在前。呼叫點靜態掃不到（走模組管理器
的間接向量），但時機這樣就夠 remake 定位了。

## `2703:09DD`：`056A:0468` 開頭那一支

```
out[0] = out[1] = 0
for 星域 i in 0..31:
    擁有者 == 2            → 跳過
    ds:B75C[i] == 2        → 跳過
    ds:B75C[i] == 擁有者   → 跳過
    out[ds:B75C[i]]++
```

`ds:B75C` 是另一份 32 格的擁有者表（值域 0／1／2）。這一支數的是
「相對於那份表，帝國與同盟各有幾格已經不是自己的」。`s3ai6` 那一刻
它與現況 20／32 相同——**那份表是什麼還沒定**，不寫進規則。

## remake

`rules.StarGraph.Occupations` ＋ `ApplyOccupation`，在 `recomputeRegions`
裡跑在 `Postures` 之前（照量到的順序）。**bit1 只清不設**——`2703:1789`
的後半段還沒讀，而 remake 目前沒有任何地方讀 bit1。
