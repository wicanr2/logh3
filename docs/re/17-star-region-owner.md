# RE 17 — 星域的勢力色從哪來

日期：2026-09-07
執行器：dosgolem-logh3（本輪加了 `-regs-max`）
輸入：原版未修改 `GIN3.COM`、`STELLAR.DTX`
狀態：**已解**（載入後有 10 個星域被改成無主，那一步未解）。

## 問題

`docs/internals/12` 解出了著色演算法（在遮罩範圍內只塗原圖留白的位元），
但顏色與遮罩由呼叫端傳進來，**來源沒追出來**。

## 從畫面往回追

`2376:0BAF` 是「塗一格」的常式，顏色在 `[bp+12]`。攔它 1,272 次：

| 趟 | 次數 | 內容 |
|---|---|---|
| 第一趟 | 626 | 顏色全 0（626 ＝ 32 個星域的總格數，先清一遍）|
| 第二趟 | 626 | 真正的勢力色，順序把星域 0 排在最後 |
| 第三趟 | 20 | 只有星域 0，顏色 `06` |

**首都會被塗兩次**：先跟其他帝國星域一樣塗色 1，再用色 6 重塗。

呼叫端（`375B0` 的前一行）取的是 `ds:[F162 + 星域編號]` 的 word，
只用低位元組——所以 `ds:F162` 起的 32 個 bytes 就是每個星域的色號。
拿它去比對第二、三趟的加權統計，逐色相符。

## 表是誰填的

監看 `ds:F162` 那 32 bytes 的寫入，寫入者只有一個：`3705:040C`。
那是個 setter：

```
3705:03FD  push bp; mov bp,sp
           mov al,[bp+08]      ; 顏色
           mov bl,[bp+06]      ; 星域編號
           mov [bx+F162],al
```

它的呼叫端（`37440`）長這樣：

```
les si,[bp+06]          ; si → 星域的執行期記錄
mov cl,es:[si+12]       ; ← 擁有者
add bx,cx
push es:[bx]            ; 顏色 ＝ 表[擁有者]，表在 ds:8BD2
push [bp+12]            ; 星域編號
call far 3705:03FD
```

攔 `3705:03E0` 看 `SI`：`A79C`、`A81A`、`A898`…**步進 0x7E ＝ 126**，
正是 `STELLAR.DT*` 一筆的大小。所以星域的執行期記錄就是那個檔案，
整份載在 `ds:A79C`。

## 兩張表

**擁有者 → 顏色**（`ds:8BD2`）：

| 擁有者 | 顏色 | 意義 |
|---|---|---|
| 0 | 1（深藍）| 帝國 |
| 1 | 12（棕）| 同盟 |
| 2 | 3（黑，等於底色）| 無主 |

首都另外用色 6（淺藍）重塗，色號取自同一張表的 `+8`。

**擁有者在 `STELLAR.DT*` 的 `+18`**（`docs/internals/22` 原本記成
「數值欄位，語意未知」的第一個 byte）。

## 驗算

記憶體裡 32 筆的 `+18` 查表之後，與實際塗上去的顏色 **31 / 32 相同**
——唯一不同的是首都那一格，因為它被色 6 重塗過。

## 擁有者是載入之後算出來的（confirmed）

檔案裡的 `+18` 是「陣營原本的疆域」：`DTX` 前 16 個是 0（帝國）、
後 16 個是 1（同盟），沒有 2。載入之後有 10 個星域被改成 2（無主）、
1 個從帝國改判同盟。

監看那個 byte 的寫入，寫入者是 `2703:15CD`；它寫的是
`call far 2703:15D5` 的回傳值。那個函式做兩件事：

1. 掃該星域的行星（記錄 82 bytes 一筆，就是 `PLADAT.DAT`），
   依行星的 `+0x11`（行星屬於誰）把數量累加到星域記錄的三個計數器：
   `+0x16` ＝ 帝國、`+0x17` ＝ 同盟、`+0x18` ＝ 其他。
2. 用三個計數器判定：

```
同盟 == 0 且 其他 == 0        → 擁有者 0（帝國）
否則 帝國 == 0 且 其他 == 0   → 擁有者 1（同盟）
否則                          → 擁有者 2（無主）
```

也就是**星域內的行星全屬同一方才算那一方的，只要混雜就是無主**。
796 年 1 月有 10 個星域是混雜的，所以在地圖上是黑的。

同一個函式也把該星域的人口與經濟力（行星 `+0x1A`／`+0x1C` 的 32 位元值）
加總寫進星域記錄的 `+0x20`／`+0x22`——主畫面右側面板那幾個數字
應該就是從這裡來的，**尚未驗證**。
