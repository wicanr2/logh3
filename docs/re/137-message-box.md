# 137 — 訊息框（`3826:0005`）

三個地方用它，版面都一樣：

- 選點不合法時的「這是無法行動的地方。」（`ds:4A24`，`docs/re/121`）
- 補給沒有對象時的「沒有需要補給的船艦。」（`ds:3F14`，`docs/re/131`）
- 修理沒有對象時的「沒有需要修理的船艦在附近。」（`ds:403E`）

三處都是 `3826:0005(2, 0x97, 字串)`。

## 它做什麼

```
3826:0005(種類, 色, 字串)
    樣板 = ds:8BEC ＋ 種類 × 6
    ds:F24E／ds:F250 = (ds:8CFA ＋ 種類 × 4) 那個遠指標
    3603:0006(&視窗, 色, 樣板[+0], [+1], [+2], [+3], [+4])
    3617:000A(&視窗, 字串)
    …
```

## 樣板表 `ds:8BEC`（一種 6 bytes）

| 種類 | bytes | 讀法 |
|---|---|---|
| 0 | `08 07 14 04 01 00` | 格 (8,7)、20 × 4 格 |
| 1 | `08 07 14 04 01 00` | 同上 |
| **2** | `04 07 14 04 01 00` | **格 (4,7)、20 × 4 格** ← 這三個訊息用的 |
| 3 | `04 07 14 04 01 00` | 同上 |
| 5 | `11 03 02 01 01 00` | 格 (17,3)、2 × 1 格 |

（種類 4 那一筆是字串資料，不是樣板——表只到 4 種。）

格是 16 × 20，與選單版面同一組（`docs/internals/44`、`docs/re/136`）。

## 收據 `s3msg`：幾何對上了

走 `s3cmdsq3` 的前置序列 → 點分隊選單第一項「移動」→ 點一個**過不去
的格子**（星域 26，用 remake 自己的地形表探出畫面 (448,100)，換成滑鼠
座標 (448,60)）。訊息框跳出來了，量到：

| | 收據 | 公式 |
|---|---|---|
| 框左上 | (65, 181) | `(格x×16＋1, (格y＋2)×20＋1)` |
| 大小 | 350 × 118 | `(寬×16＋30) × (高×20＋38)` |
| 填色 | (72,189)–(406,290)、色 9 | |
| 文字 | 左上約 (80, 201)、字色 7、陰影 3 | |

**大小的公式與命令選單完全相同**（`docs/internals/44`），位置也是同一組
格——**只有 y 多兩格**。樣板寫 `格y ＝ 7`，框頂卻是 181 ＝ (7＋2)×20＋1。

## `3603:0006` 讓那兩條公式合而為一

```
3603:0006(&視窗, 色, 格x, 格y, 寬, 高, 旗標)
    視窗指標是 0 → 配一個 0x22 bytes 的物件（[+1A] 記「自己配的」）
    視窗[+1] = 色     [+3] = 旗標
    視窗[+5] = 格x    [+6] = 格y
    旗標 != 0 → 視窗[+7] = 寬 ＋ 2、[+8] = 高 ＋ 2
    否則      → 視窗[+7] = 寬、    [+8] = 高
    341B:0054(視窗)                 ; 註冊成可點區域（docs/re/136）
```

`3826:0005` 傳的旗標是樣板的 `[+4]`，種類 2 那一筆是 **1**——所以視窗
實際佔 **22 × 6 格**。量到的 350 × 118 正好是

```
寬 ＝ 22 × 16 − 2      高 ＝ 6 × 20 − 2
```

**這把選單那條看起來很怪的公式也解釋掉了**：`(內寬×16＋30)` 其實就是
`((內寬＋2)×16−2)`、`(列數×20＋38)` 就是 `((列數＋2)×20−2)`。
拿 `docs/re/117` 量到的三張選單回頭對：分隊 62 × 78 ＝ (2＋2)×16−2 ×
(2＋2)×20−2 ✓、艦隊 62 × 98（3 列）✓、戰術 126 × 178（內寬 6、7 列）✓。
**選單與訊息框是同一個視窗系統，旗標決定要不要那兩格外框。**

`格y` 多的那兩格還沒解——旗標同時讓 `高` ＋2，但沒看到它動 `格y`；
`341B:0054` 之後那一段還沒讀。

## 框線的畫法不一樣（所以還不畫）

拿命令選單那一支 `ui.MenuFrame` 去畫，框內 41,300 個像素有 6,503 個
不同——差的集中在邊緣：

```
收據左緣  8 F 8 7 F F 3
畫出來的  8 3 F F 7 8 3
```

**填色與文字都對，差的整整是一圈框線**（5,480 個像素 ≈ 邊框周長）。
不是「洗底洗掉背景」造成的假差異——直接畫在收據上、上下試 ±2 列，
最好的一次還是差 5,480 個。

四邊量出來的剖面（收據 `s3msg`，框 (65,181) 350×118；`3` 是外面的底色、
`9` 是裡面的填色）：

```
左 (y=240)  x=65 起   F 8 F 7 F F 3 │ 9…
右 (y=240)  …9 │ x=407 起  3 3 8 8 7 F F F  →  x=414 止
上 (x=240)  y=181 起  F F F 7 8 8 3 3 │ 9…
下 (x=240)  …9 │ y=291 起  3 F F 7 8 8 8   →  y=298 止
```

對照命令選單同一條路量的（收據 `s3cmdsq3`，框 (241,261) 62×78）：

```
左 x=241 起  8 3 F F 7 8 3 │ 9…
上 y=261 起  F 7 F F 3 8 3 │ 9…
```

元素同一組（8／F／7／3），**排法不一樣**——所以兩種視窗的框線是兩套
美術，不是同一支畫的。邊框厚度也不對稱：左 7、上／右／下各 8，
像是「光從左上、右下有陰影」那種立體邊。

## 為什麼會是兩套：選單的視窗是「基本視窗 ＋ 幾個欄位」

`3603:0006`（訊息框）與 `3667:0004`（選單，`docs/re/117`）**是同一份
程式碼改出來的**：欄位配置一模一樣（`[+1]` 色、`[+2]` 0、`[+3]` 旗標、
`[+5]`／`[+6]` 格座標、`[+7]`／`[+8]` 格數，旗標非 0 就各 ＋2、
`[+1A]` 記是不是自己配的），差別只有兩處：

| | 訊息框 `3603:0006` | 選單 `3667:0004` |
|---|---|---|
| 物件大小 | `0x22` bytes | **`0x24` bytes** |
| 額外欄位 | — | `[+1B] ← 0xFF`、`[+1D] ← 色`、還有 `[+1C]`／`[+1E]` |
| 呼叫端給的顏色 | 一個（`0x97`）| **三個**（`0x97`、`0x27`、`0x98`）|

所以選單的框線比訊息框多兩層顏色——**兩邊的框線不同不是巧合，是選單
那一種多帶了資料**。remake 的 `ui.MenuFrame` 重建的是選單那一套，
訊息框要的是比較素的基本款。

## 視窗其實是一張字元格

`3603:0006` 本身不畫，它建好物件之後交給 `341B:0054`：

```
341B:0054(視窗)
    ds:D80C（開著的視窗數）>= 0x10 → 回 0xFFFF   ; 最多 16 個
    341B:057F(視窗, 0, 0)                        ; 掛進串列
    找一個空槽 i（ds:D80E[i] == 0）→ ds:D80E[i] = 0xFF、視窗[+4] = i
    視窗[+0] = 1                                 ; 種類 1 ＝ 視窗
    35AA:0006(視窗)                              ; 配內容緩衝區
    35AA:0068(視窗)                              ; 清乾淨
```

> `341B:039D` 的命中判定找的是**種類 2**（`docs/re/136`），視窗是種類 1
> ——所以視窗本身不是可點區域，可點區域另外註冊。

`35AA:0006`：

```
視窗[+0B] = 視窗[+7] − (旗標 ? 2 : 0)     ; 內容的格數 ＝ 框格數 − 2
視窗[+0C] = 視窗[+8] − (旗標 ? 2 : 0)
視窗[+0E]／[+10] = 配 [+0B] × [+0C] × 4 bytes
```

`35AA:0068` 把那塊緩衝區每一格填成 `0x2020`（兩個半形空白）＋ 視窗的
顏色 `[+1]`、旗標 0。

**所以視窗是一張 (寬−2) × (高−2) 的字元格，一格 4 bytes（字碼 word ＋
顏色 byte ＋ 旗標 byte）。** 訊息框的樣板寫 20 × 4 就是**內容**的格數，
旗標讓它外面再包兩格框——這也對上了收據量到的 22 × 6 格。

真正上色是重繪時走另一支（要同時吃 `0x22` 的基本視窗與 `0x24` 的選單
視窗），還沒找到。

**在那之前不畫**——框的位置與大小已經進
`docs/internals/data/message-box.json` 並逐項驗過
（`TestMessageBoxGeometryMatchesOracle`）。

`ds:8CFA + 種類 × 4` 指到 `ds:8C0A`／`8C2C`／`8C56`／`8C78` 四段，
內容還沒讀。
