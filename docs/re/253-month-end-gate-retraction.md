# 253 — 更正 `docs/re/252`：`2703:03AF` 是一次性的，月底閘門仍未定位

`docs/re/252` 說月底結算掛在 `2703:03AD`、閘門是「回合數是十的倍數」、
跑在開戰之前。**位址錯了一個指令，量到的東西也不是那一支。** 這一篇是更正。

## 錯在哪

往回找函式開頭時停早了兩個位元組：

```
273D8: 5e 02 83 c4 0a 5d cb 55 56 57 83 ec 04 89 e5 8a
                            ↑  ↑
                    273DD  5d cb   ← pop bp / retf（前一支的收尾）
                    273DF  55 56 57 83 ec 04 89 e5  ← 真正的開頭
```

`0x273DD` 是 `pop bp`，`0x273DF` 才是 `push bp`。所以進入點是
**`2703:03AF`**，不是 `2703:03AD`。

`-regs-at 2703:03AD` 斷在**前一個函式的 `pop bp`**——那一支是逐格呼叫的，
所以命中會成串出現（`monthgate` 的 41 次、`monthgate2` 的一輪 32 次）。
`docs/re/252` 把那些成串命中讀成「月底結算跑了」。

## 重跑：兩份完全相同

同一組旗標，只差 poke 的值，`-regs-at 2703:03AF`：

| 批次 | `ds:8F18` poke 成 | `2703:03AF` |
|---|---|---|
| `monthgate4` | 9 | 1 次，`#155479789` |
| `monthgate3` | 10 | 1 次，`#155479789` |

**兩份逐位元組相同的時點、同樣只有一次，而且都在按「實行」
（`#210000000`）之前。** 所以 `2703:03AF` 是**新遊戲初始化時算一次稅**
那一支，poke 回合計數器對它沒有影響。

`docs/re/252` 的「閘門是回合數的十的倍數」與「月底結算在開戰之前」
**兩句都收回**。

## 還站得住的部分

`docs/re/252` 裡靜態讀出來的東西不受影響：

- 整份傾印裡參照 `ds:8F52`（軍事費）的 17 處指令中，**只有一處是加法**
  （`lin 2745B  add [bx+8F52h], si`），其餘是維持費與移動費的減法。
- 含那一條的 `2703:03AF` 做的事：`ds:8FF8[陣營] ← ds:8FD4[陣營]`
  → 總稅收歸零 → 逐格 `2703:0AB8` 累加 → `+0x26` 抄進 `+0x27`
  → `軍事費 += 總稅收`。
- 所以 **`ds:8FF8` 是 `ds:8FD4`（Blend）的快照**（`docs/re/34` 的問號），
  這一條與閘門無關，仍然成立。

## 順帶量到的：一個回合裡三支的先後

`monthgate3` 的另外三個斷點（同一趟、同一個 poke）：

```
#212204671  2D10:0005   AI 進入點
#212389764  2D76:0002   建艦隊
#215832683  056A:09EB   維持費扣除
```

**AI → 建艦隊 → 維持費**，與 `docs/re/236` 量到的鏈一致。月底結算不在
這三個之間——因為這一趟它根本沒跑。

## 月底結算現在的狀態

**只知道那一條加法在 `2703:03AF` 裡，不知道每個月是誰去呼叫它。**
`2703:03AF` 的呼叫者掃不到（間接向量），而 poke 回合計數器沒有讓它再跑。

還沒排除的可能：月底那一次走的是**別的**路徑（例如同一段程式被模組管理器
從另一個入口叫進去，或月結另有一支），或者跨月的偵測不是看 `ds:8F18`
而是看別的欄位。要往下走，最省的是**對 `lin:2745B` 那一條指令設中斷**
（不是對函式入口），再跑一段真的會跨月的序列。

## 一條方法

**`-regs-at` 的位址要落在 `push bp`，不是它前面那個 `pop bp`。**
往回找函式開頭時，`5d cb`（`pop bp` / `retf`）與 `55`（`push bp`）只差
兩個位元組，很容易停早。**停在 `pop bp` 上不會報錯**——它照樣會命中，
只是命中的是別的函式，而且因為那支被逐格呼叫，看起來還「很像」月底在跑。

檢查點：對 `-regs-at` 的目標先 `hexat` 印四個位元組，確認是
`55 56`／`55 83` 這種 prologue 開頭再跑。
