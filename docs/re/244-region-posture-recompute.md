# 244 — 路徑表什麼時候重建，以及星域 `+0x13` 的四個位元誰寫的

`docs/re/243` 解出路徑表怎麼算，但它是**擁有者的函數**——星域一易主就得
重來。這一輪找重建時機，順著把重建之後那一圈重算讀完，
`docs/internals/22` 裡標「未知」的 `+0x13` bit0 與 bit3 也一起有了生產者。

## 三個重建點

`2B99:0003`（配置 ＋ 建初始矩陣 ＋ Floyd，`docs/re/243`）的呼叫點掃出三處：

| 線性位址 | 情境 |
|---|---|
| `0x04FD0` | 載入：前面剛把 `ds:8F1A` 設成 `0xFFFF`，後面接 `2703:0853`／`2703:043B` |
| `0x271C5` | 新遊戲：緊接著把 `ds:8FD4`／`ds:8FD5` 設成 2（開局 Blend，`docs/re/222`）|
| `0x27914` | `2703:08DE` 的第一行 |

第三處是一支獨立的常式：

```
2703:08DE:
    call 2B99:0003                      ; 重建四張表
    for 星域 i in 0..31:
        2703:0933(星域記錄)             ; 態勢旗標 ＋ 到首都的成本
        2703:12EB(星域記錄)             ; 艦艇與資源彙總
        2703:0DA1(星域記錄)             ; 未安定度（docs/re/24、34、43）
```

它只有一個呼叫點（`0x05EB1`），在**回合結束**那條線上。那一支的順序是：
逐格重算擁有者（`2703:159B`）、發現易主就走 `056A:0855(星域記錄, 舊擁有者)`，
32 格全跑完之後才呼叫 `2703:08DE`，最後判勝負——瓦爾哈拉（0）落到同盟手上
回 5、巴拉特（31）落到帝國手上回 4。

**順序是有意義的**：路徑表在「擁有者可能已經改變」之後才重建，而重建之後
才重算每一格的態勢。remake 若把路徑表當靜態資料，這條鏈整段都不成立。

## `2703:0933(星域記錄)` — 態勢旗標

```
and byte es:[bx+13h], 0F2h              ; 先清 bit0 | bit2 | bit3
297B:14F8(星域記錄, &帝國艦隊數, &同盟艦隊數)
if 帝國數 != 0 && 同盟數 != 0:
    or byte es:[bx+13h], 4              ; bit2
if 2703:0A48(星域記錄) != 0:
    or byte es:[bx+13h], 8              ; bit3
if 擁有者 != 2:                          ; 無主的不算
    ax = 2B99:028F(這一格, 3982:0329(擁有者), 擁有者)   ; 到自己首都的成本
    es:[bx+24h] = ax
    if ax >= 0400h:
        or byte es:[bx+13h], 1          ; bit0
```

於是：

- **`+0x24` ＝ 到自己陣營首都的路徑成本**（就是 `docs/re/243` 那張距離矩陣的
  值）。無主星域不寫，留著上一次的。
- **bit0 ＝ 那個成本 `>= 0x400`**，也就是 `k >= 1`：從這一格走回首都，
  路上至少有一條邊的兩端不全是自己的。**門檻是 `0x400` 不是 `0x800`**
  ——`2B99:0392` 那個「從首都走得到嗎」用的才是 `0x800`（`docs/re/185`）。
- bit2 ＝ 這一格雙方都有艦隊。
- bit3 ＝ 至少有一個相鄰星域的擁有者跟自己不同。

`0F2h` 保留 bit1、bit4–bit7，所以那幾個位元是別處維護的。

## `297B:14F8(星域記錄, &帝國數, &同盟數)`

`297B:131C(&buf, 星域編號, 0)` 取這一格的艦隊槽號清單，逐一查艦隊表
（`ds:C074`、每筆 122 位元組），**`+0x00` bit0 有設的跳過不計**，其餘照
`+0x01`（陣營）分別累加。兩個都非零，呼叫端就設 bit2。

跳過 bit0 那一條與 `docs/re/196` 對得起來：那個位元把艦隊分成兩類，
逐艦隊決定時走不同的分支。

## `2703:0A48(星域記錄)` — 前線判定

```
n = 2B99:03D9(星域編號, &out, 擁有者)    ; 鄰居清單
count = 0
for i in 0..n-1:
    if 星域表[out[i]] 的 +0x12 != 這一格的 +0x12: count++
return count
```

回「有幾個鄰居的擁有者跟自己不同」。所以 **bit3 ＝ 這一格是前線**。

## `2B99:03D9(星域, &out, 陣營)` — 鄰居是從路徑表反推的

```
3BAA:0062(0, 6)                          ; 映 EMS 分頁
表 = 陣營 ? ds:D06E : ds:D06A            ; 中點矩陣
for j in 0..31:
    if 表[星域 × 32 + j] == 0FFh: out[n++] = j
```

**鄰接不是查 `ds:533A`，是查中點矩陣的 `255`。** 而且 `mid[i][i]` 被
`memset` 填成 `0xFF` 之後再也不會被鬆弛（`d[i][i] = 0`，沒有東西比它小），
所以**這一格自己也在自己的鄰居清單裡**。對 `2703:0A48` 沒有影響
（自己跟自己擁有者一定相同），但別的呼叫端要留意。

### 領土罰則不會讓某條直接邊「消失」

既然鄰接是從路徑表反推的，就要問：被罰的直接邊會不會輸給沒被罰的繞路，
害那兩格不再算相鄰？**不會**，而且理由很乾淨：

一條路上的每條邊都沒被罰，需要路上每一格都屬於該陣營；那麼首尾兩格也屬於
該陣營，於是**直接邊也不會被罰**。反過來說，直接邊被罰時，任何一條路至少
帶一個罰則。所以

```
直接邊（被罰）  = 1024 + w        w <= 18   → 最多 1042
其他任何路      >= 1024 + 10 + 10           → 至少 1044
```

鬆弛用的是嚴格小於，所以直接邊永遠贏。判準是 `2 × 最小邊權 > 最大邊權`，
而實際是 **20 > 18**——只差 2。拿 300 組隨機擁有者 × 兩個陣營跑過，
反推出來的鄰居清單與 `ds:533A` 逐格相同，一次例外都沒有。

這也回頭補上了 `star-graph.json` 那份相鄰表的保證：它當初從「中點矩陣
== 255」推，只在一個局面上核對過；現在知道任何擁有者組合下都成立。

## `2703:12EB(星域記錄)` — 艦艇與資源彙總

先把 `+0x30`（56 位元組）、`+0x68`（8）、`+0x70`（8）清零，再用
`2AF5:0036(星域編號, 0)` 取這一格的行星清單，跳過 `+0x11 == 2`（無主）
的行星，把每顆行星的

```
+0x20 + 種類×4   （七種艦艇的艘數，32 位元）→ 星域 +0x30 + 擁有者×0x1C + 種類×4
+0x3C                                        → 星域 +0x68 + 擁有者×4
+0x40                                        → 星域 +0x70 + 擁有者×4
```

按**行星的擁有者**分兩份累加。`+0x30` 那 56 位元組 ＝ 2 陣營 × 7 種 × 4，
與 `docs/internals/22` 記的「`+0x30`–`+0x4B` 是帝國那七種艦艇的艘數」對得
起來——同盟那一份接在 `+0x4C`。

## 一條方法

**問「誰寫這個欄位」之前，先問「誰重建這張表」。** `+0x13` 的 bit0 與 bit3
在 `docs/internals/22` 掛了很久的「未知」，是因為一直從**讀**的那一端找
（`2E54:0222`／`2E54:005D` 拿它做什麼）。寫的那一端全部集中在重建之後
那一圈裡，找到重建點就一次拿到四個位元的定義。
