# 172 — 「這一格要派幾支」＝ 缺口 ÷ 4 ＋ 前線加成

`docs/re/170` 只知道 `2E54:0978` 拿 `ds:D58E[星域] != 0` 當閘門。
這一輪把填 `ds:D58E` 的那一支讀完，六張表的關係也跟著清楚了。

## `2E54:0725()` ＝ 兩支

```
2E54:0730()      ; 算每一格要派幾支
2E54:07D8()      ; 實際指派
```

## `2E54:0730` ＝ `ds:D58E` 的算式

```
3C9C:000A(ds:D58E, 0, 32)                    ; 32 byte
對 i = 0 … 31：
    若 星域[i][+0x12] != ds:8F1D：跳過        ; 只算自己的
    前線 = min(ds:D50E[i] ÷ 2, 1)             ; 0 或 1
    若 ds:D5CE[i] < ds:D54E[i]：
        ds:D58E[i] = (ds:D54E[i] − ds:D5CE[i]) ÷ 4
    否則：
        ds:D58E[i] = 0
    ds:D58E[i] += 前線
```

`ds:D50E` 是 `docs/re/171` 那個「敵方鄰居個數 × 4」，`÷ 2` 再夾成 1
之後只剩「**這一格是不是前線**」。所以：

**要派幾支 ＝ 缺口 ÷ 4 ＋（是前線就再加一支）。**
內地而且不缺兵的格子拿到 0，`2E54:0978` 直接跳過。

## 六張表的關係

| 表 | 版面 | 角色 | 證據 |
|---|---|---|---|
| `ds:D54E` | 32 word | **需求**（分母） | `2E54:1B06` 用 `add` 累加；這裡當被減數 |
| `ds:D5CE` | 32 word | **現有**（被減數的對照） | `2E54:016D` 一帶用 `inc word` 累加 |
| `ds:D58E` | 32 byte | **要派幾支** | 本節的算式；`2E54:0978` 的閘門 |
| `ds:D5AE` | 32 byte | **已經指派幾支** | `2E54:07D8` 每指派一支 `inc byte` |
| `ds:D50E` | 32 word | 優先度（排序鍵） | `docs/re/171` |
| `ds:D60E` | byte | 回合開頭寫 0 | 讀取點未追到 |

`ds:D54E` 與 `ds:D5CE` 的「需求／現有」是**強推論**——形狀（相減、
相差就是缺口）與 `2E54:088F` 的 `D5AE × 100 ÷ D58E` 滿足率互相支持，
但兩個累加點的內容還沒讀。`docs/re/170` 把 `D58E`／`D5AE` 寫成
「要幾支／有幾支」，方向是對的，只是那時還沒看到算式。

## `2E54:07D8` ＝ 指派（讀到一半）

```
3C9C:000A(ds:D5AE, 0, 32)
重複：
    星域 = 2E54:0842()                 ; 回 0FFh 就結束
    艦隊 = 2E54:143F(星域, 0)          ; ★ 模式 0（門檻 50、不要求編制滿）
    若 艦隊 == 0:0：…
    2E54:1B17(艦隊, 0, 星域)
    ds:D5AE[星域]++
```

`2E54:143F` 的三種模式終於各自找到用途：這裡是**模式 0**，
`2E54:0AAB` 的增援是**模式 1**（`docs/re/167`），模式 2 還沒看到呼叫者。
