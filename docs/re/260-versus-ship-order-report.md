# 260 — 對戰模式月初報告的中間那張也是船艦訂造報告

`docs/re/259` 把單人的月初報告串解出來（會計 → 訂造），但對戰模式那一路
留著一句「中間那張是不是訂造報告還沒量過」。量了，是。

## 收據

`vs5` 用兩下右鍵（`#205M`、`#240M`）關掉兩層報告，所以中間那張只要在兩下
之間倒一次就看得到。批次 `vsreports`（`vs5` 的旗標 ＋ `-dump-at`）：

```
#200M  796年 1月份會計報告        cc5ff774…
#225M  796年 1月份船艦訂造報告    20e24b0a…   ← 中間那張
#255M  地圖介面                   106538c7…（與單人那條 openreports 同一張）
```

`vs7` 是同一個狀態的正式收據（`-steps 230000000`，最後一張畫面就是它），
`screen.bin` SHA-256 `faca5c4a2af37fa3b3c94a6ccb1866845bf8a6f02561c5ab8f50824625cde355`，
PNG 與 `vsreports` 那一張逐位元組相同。

內容與單人那張（`ship1`）相同——`796年 1月份船艦訂造報告`、軍事專任參謀
梅克林格准將、七列造艦數／部隊數（戰艦 3790／1、高速戰艦 1260／0、
巡航艦 6830／1、航空母艦 630／0、驅逐艦 4550／1、運補艦 3250／1、
修護艦 1030／1）、右下「變更」「確認」兩顆。頭像是 `FACE.AMG` 第 **6** 張
（`face_find.py` 回 0 差異）。

底板是交棒之後那一張：右側面板已經畫了陣營那一行、只有「系統指令」一顆、
分頁鈕都在——與 `vs4` 的底板相同。

## remake

新狀態 `StateVersusShipOrder`，規格 `screen-versus-ship-order`
（`overlay_spec.py` 疊在 `screen-command-phase` 上量的，與 `screen-versus-account`
同一條管線）。右鍵鏈變成 `StateVersusAccount` → `StateVersusShipOrder` →
地圖介面。

**整張 640×480 逐位元組相同**（`TestVersusHandover` 裡的
`matches(t, g, "vs7")`）。中間卡在 32 個像素，全部落在游標那一小塊，
色號 3 與 7 互換——**七列數字畫在游標之後，把游標蓋掉了**。原版的游標在
最上層，而 `vs7` 的游標正好壓在「戰艦」那一列的數字上，所以這個順序在
`ship1`（游標停在「確認」上）身上看不出來。把 `drawShipOrder` 從
「`MainGameLayered` 之後」搬到 `afterWindow("overlay")` 就歸零。

## 一條方法

**差幾個像素要看在哪裡，不是看幾個。** 32 / 307,200 聽起來像「幾乎對了」，
但它全部集中在游標那一塊、而且是兩個色號互換——那是**畫序**的簽名，不是
座標或顏色差一點。`tools/scripts/diff_parts.py` 把差異切成連通分量再報
「原版這裡是什麼色、remake 是什麼色」，一眼就分得開。這一輪順手把
`matches()` 加上 `LOGH3_DUMP_REMAKE`：對不上的時候把 remake 那一側倒出來，
否則只知道差幾個像素，不知道差在哪。
