# 250 — `056A:089D`：易主報告那一支讀完了

`docs/re/249` 用四份收據量出星系名的字色與四句話，但留了一個問題：
字色是**依擁有者**還是**依敵我**？四份收據的座位都是帝國，分不開。
把那一支讀完就分開了——順帶撿到 `+0x13` bit4 的第三個寫入點。

## 位置

`056A:0855`（易主處理）看 `ds:8F21`／`ds:8F22`（座位）決定要不要跳，
真正組報告的是 **`056A:089D`（線性 `0x05F3D`）**，參數是
`(星域記錄, 座位陣營, 舊擁有者)`。

## 字色是依擁有者

```
05F6D  les  bx, [bp+5Ah]          ; 星域記錄
05F70  add  bx, 12h               ; → +0x12
05F76  mov  bl, es:[bx]           ; **擁有者**
05F79  xor  bh, bh
05F7B  mov  al, [bx+6096h]        ; ds:6096[擁有者]
05F81  push ax                    ; ← 格式字串的第一個 %d
05F83  mov  bx, 087Ah             ; ds:087A ＝ `\x1B[%d,%s\x1B[%d,星系`
05F8E  call far 3ACA:001B(…)      ; 印第 1 行
```

`ds:6096` 的前三格是

```
96 95 97      ← 擁有者 0／1／2
```

高位 `9` 是視窗底色、低位 `6`／`5`／`7` 是字色——與 `docs/re/249` 四份收據
量到的完全相同。**索引是擁有者，不是敵我**，所以 remake 照擁有者查表是對的
（那一篇留的問號可以收掉）。

## 四句話的選法

```
05F9B  cmp byte es:[bx], 2                ; 新擁有者 == 無主？
05F9F  jnz  05FCD
05FA1    cmp [bp+60h], [bp+5Eh]           ; 舊擁有者 == 座位陣營？
05FA7    jnz  05FBB
05FA9      ds:088B  「由於受到敵方艦隊入侵／部分地區已經無法掌控。」
05FBB      ds:08BC  「部分行星我軍已成功進駐。」
05FCD  and byte es:[bx+13h], 0EFh         ; ← 清 bit4
05FD5  cmp es:[bx+12h], [bp+5Eh]          ; 新擁有者 == 座位陣營？
05FDC  jnz  05FF0
05FDE    ds:08DA  「已被我方占領。」
05FF0    ds:08EE  「已被敵軍占領。」
0600C  call far 3826:0307(緩衝, 座位陣營, 0)   ; 顯示，等按鍵
```

與 `docs/re/249` 四份收據逐句相符，而且把兩句無主的判準寫死了：
**看的是「舊擁有者是不是自己」**，不是別的。

## bit4 的第三個寫入點

`05FCD` 的 `and byte es:[bx+13h], 0EFh` 把 `+0x13` 的 **bit4 清掉**，
而且只在「新擁有者不是無主」那一路。`docs/re/245` 找到的兩支
（`2703:0933` 的 `and 0F2h`、`056A:0468` 的 `and 0E9h`）都不含這一個時機。

語意上講得通：bit4 是「單方面占據」，而這一格剛剛正式易主，占據狀態
就結束了。之後 `056A:0468` 那一圈還會重新推一次，所以在 remake 的流程裡
這個清除會被覆蓋——但原版確實在這裡清，照做。

## 一條方法

**收據分不開的兩種假設，回去讀那一支多半就分開了。** 這一輪的問號是
「依擁有者還是依敵我」，要用收據回答得換一個座位跑（新遊戲怎麼選陣營
還沒解）；讀 `mov al, [bx+6096h]` 那一行只花幾分鐘，而且順帶多拿到
一張色表與一個 bit4 的寫入點。**先問「這件事在程式裡看得到嗎」，
再考慮造局面。**
