## 結論

### 勝負判定（已證實）

`056A:078E` 在回合尾端先看兩座首都：

- 瓦爾哈拉（星域 0）擁有者成為同盟 1，回傳 5，同盟獲勝；
- 巴拉特（星域 31）擁有者成為帝國 0，回傳 4，帝國獲勝；
- 其餘回傳 0，遊戲繼續。

`0374:0343` 把非零結果傳到線性 `0x037C5` 的呼叫端。呼叫端的四條分支顯示：

- 單人模式若人類獲勝，人類以勝方身分看一頁報告；
- 單人模式若電腦獲勝，仍只給人類座位看一頁敗北報告；
- 對戰模式兩邊皆為人類，但只由勝方座位看一頁報告；
- 報告後的結局參數是帝國勝 1、同盟勝 2，人類敗北則為 0。

因此原版不是「兩邊各看一頁」，而是每次勝負確定只選出一個人類 viewer。

### 報告組成（已證實）

`0374:0B7A` 建立報告場景後呼叫 `04C8:000A(reportKind, won)`；後者把 kind 4／5
正規化成帝國／同盟 viewer，再呼叫 `04C8:00F3(viewer, opponent, won)`。
兩份 dosgolem 收據中三個入口各命中一次。

`04C8:00F3` 建立格座標 `(10,5)`、內容 `20×10`、style 1 的視窗。內容依序是：

1. `ds:05DE` 日期；
2. 勝方用 `ds:05F9`、`0615`、`0624`，另列我方星系總數；
3. 敗方用 `ds:063D`、`0659`；
4. 兩者都用 `ds:0669`、`067A`、`0688` 顯示勝利點與雙方累積分數。

勝利點是 `ds:8FEC[viewer] - ds:8FEC[opponent]`；兩格 32 位元值對應
`WORK +0xD8/+0xDC`。頭像索引從 `ds:8F4B + viewer*4` 讀，經
`3958:0215(index,52,30)` 畫在 `(416,160)`；此處刻意保留原始運算式，沒有把
它誤稱成某個固定幕僚職。

### 結局素材路由（強推論）

帝國／同盟勝方分別接 `ENDT30.VO5`／`ENDD30.VO5`，與既有 T（帝國）／D（同盟）
素材族命名及已驗的帝國結局圖一致。完整結局播放順序仍未知；本次只把報告後轉場接到
兩個既有的結局預覽，不宣稱整段 ending parity。
