## 量到什麼

載入 S3「巴米利恩會戰」開「出擊命令」（畫面是「待命中提督資料」），
對提督篩選管線 `28E0:0103` 的出口（`28E0:021F`）設 `-regs-at`：

```
#305066752  [bp+00]=520B  [bp+10]=964E  [bp+12]=54B3  [bp+14]=00FF  [bp+16]=0025
```

照 `docs/re/43` 解出來的框架讀（`+0x10/+0x12` 緩衝區、`+0x14` 所在地、
`+0x16` 篩選位元、`+0x00` 筆數）：

| 參數 | 值 | 意思 |
|---|---|---|
| 緩衝區 | `ds:964E` | 結果放這裡 |
| 所在地 | `0xFF` | 不依星域篩 |
| 篩選位元 | `0x25` | `0x01` ＋ `0x04` ＋ `0x20` |
| **筆數** | **11** | |

**清單有 11 筆資料，畫面上卻是十四列全空。**

對得起來：`ADMIRAL.DTA` 裡 `+0x09` 有最高位的提督有 44 個，其中 `+0x00`
是 `FF` 的有 25 個，再套上位元 `0x01` 那一支（讀 `ds:8F1D`，看起來是玩家
陣營）就會收到十幾個。順帶解釋了 `docs/re/47` 為什麼 poke 沒有效——
那些提督本來就通過了。

（也修正一件事：`+0x09` 夾到 127 是**新遊戲**那條路徑量到的，
讀存檔沒有夾——`ADMIRAL.DTA` 裡就有 44 個帶最高位的。）

## 呼叫端在哪

出口那一筆的堆疊裡 `[bp+0C]／[bp+0E]` 是遠端返回位址：**`0C0A:0025`**。
倒那個段下來讀（收據 `code0C0A`）：

```
0C0A:0025  mov ds:96A0h, al        ; 筆數存進 ds:96A0
0C0A:002A  push [bp+10]/[bp+0E]/[bp+0C]
0C0A:0033  call far 0C0A:003C      ; 開畫面
0C0A:003C  …push 1,11h,12h,0,14h,97h, ds:962Ch → call far 3603:0006
0C0A:005D  …call far 0C0A:0086
0C0A:0086  …ds:1C22／ds:1C2B ＋ ds:962Ch → call far 3617:003A ×2
           …0,1,11h,10h ＋ ds:962Ch → call far 37A9:05EC
```

`ds:962C` 是這張清單的描述結構、`ds:96A0` 是筆數，畫的工作分給
`3603`／`3617`／`37A9`／`341B` 幾個段的視窗元件。
