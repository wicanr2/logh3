# 打行星的兩道閘門：`2583:0003` 不是搜尋，`+0x70` 是兩個距離帶

[`docs/spec/019`](../spec/019-planet-assault.md) 的前兩項開放問題。

## `2583:0003` 是玩家的選點迴圈

舊筆記寫「開頭把參數 ×8 與 ×8÷3 當成兩個半徑，再往下搜（`165F:0003`），
**看起來是**以艦隊為中心用自己的射程搜一圈」。讀完之後：那兩個半徑不是
搜尋範圍，是**畫在畫面上的兩個圖形**——就是
[`docs/re/120`](120-manoeuvre-shapes.md) 已經解過、remake 也已經在畫的
`screen.DrawManoeuvreRange`。

```
2583:0003(艦隊 far, 基準, 抵達朝向)：
    外 ＝ 基準 × 8 ; 內 ＝ 外 ÷ 3
    165F:0003(&圖形A, 艦隊, 內)              ; 內圈
    165F:004D(&圖形B, 艦隊, 外, 抵達朝向)    ; 外形
    掛上去（3870:001A 各拿一個代號）
    ax ＝ 2583:013D(&x, &y, 艦隊[+0x4A], 0)  ; 玩家選點
    if ax != 0xFFFF:
        艦隊[+0x60] ← 艦隊[+0x5C] ; 艦隊[+0x62] ← 艦隊[+0x5E]   ; 備份位置
        艦隊[+0x64] ← x ; 艦隊[+0x66] ← y                       ; 目的地
        艦隊[+0x4C] ← al                                        ; 抵達朝向
        回 1
    拆掉兩個圖形；回 0
```

所以 `docs/spec/019` 裡那條

```
if 2583:0003(艦隊, 艦隊[+0x4F], 艦隊[+0x4D]) != 0: 艦隊[+0x48] ← 1
```

的意思只是「**玩家成功下了『戰鬥』命令**」——與
[`docs/spec/027`](../spec/027-fleet-move-and-battle-order.md) 的
`BattleFleet.Action ← 1` 是同一件事，remake 早就有了。第一道閘門因此
不是新機制。

## `+0x70` 的兩個位元是兩個距離帶

開場先清乾淨（`20B4:000C`）：在場的每一支艦隊 `+0x70` ← 0、`+0x5A` ← 0xFF。
在場艦隊的索引清單在 `ds:9898`，筆數在 `ds:9894`。

然後逐顆行星跑 `20B4:0091(行星索引, 行星)`：

```
r ＝ 2AF5:01F7(行星)                     ; rules.PlanetQueryRadius
對每一支在場艦隊：
    旗艦 ＝ 池[艦隊[+0x10]]
    if 旗艦[+0x08] == 0: 跳過             ; 沒艘數
    if 行星[+0x11] == 艦隊[+0x01]: 跳過   ; 自己的行星不打
    d ＝ 3310:0006(行星[+0x46], 行星[+0x48], 艦隊[+0x5C], 艦隊[+0x5E])
    if d > 150: 跳過
    if 艦隊[+0x00] & 1: 跳過
    if (艦隊[+0x48] & 0x0F) != 1: 跳過    ; 必須在「戰鬥」狀態
    艦隊[+0x70] |= 1 ; 艦隊[+0x5A] ← 行星索引
    if d > r: 跳過
    if 行星[+0x12] != 0 且 行星[+0x45] == 3: 跳過      ; ★ 要塞砲已瞄準
    艦隊[+0x70] |= 2 ; 艦隊[+0x5A] ← 行星索引
```

距離都是 16.16（`3310:0006` 的回值，`docs/re/147`），所以那個常數是
`0x0096_0000` ＝ **150 像素**。`r` 是防衛力夾 1500–6000 再 ÷ 25，
也就是 60–240 像素。

- **bit 0**：離行星 150 像素內、而且這一支正處於「戰鬥」狀態。
- **bit 1**：還要在行星自己的查詢半徑內，而且那顆**不是「要塞砲已瞄準」
  的要塞**。

`20B4:08B1`（實際打）要的是 **bit 1**，所以

> **瞄好的要塞砲會讓敵方那一回合打不到這顆行星。**

這也是 `docs/re/148` 裡「跑兩次去比」失敗的原因。

## 誰先打

`20B4:01C1`：把在場艦隊裡 `+0x5A != 0xFF` 的收成一個 far ptr 陣列，
`3C6A:000D` 排序（元素 4 bytes、比較函式 `20B4:02A4`），再逐一結算。

## 還缺什麼才能進 READY

只剩**一份實際打下行星的收據**。要 poke 的東西現在都知道了：一支敵方
艦隊的 `+0x5C`／`+0x5E` 挪到行星 150 像素內、`+0x48` 的低四位設 1、
`+0x00` bit0 清掉，再把亂數種子一起釘住。
