# 135 — 艦隊選點的外形（`165F:004D`）：讀到一半，數字對不上

`docs/spec/027` 把「兩個範圍圖形沒有畫」列成已知差異，理由是外形的公式
沒讀。這一輪讀了那支常式，也量了收據——**兩邊差得太多，所以還是不畫。**

## 描述結構

```
165F:004D(&out, 艦隊, 距離, 回轉速度)
    out[+0] = 艦隊 +0x5C ＋ 8        ; 圓心 ＝ 旗艦圖塊中心
    out[+2] = 艦隊 +0x5E ＋ 8
    out[+4] = 0   out[+5] = 1   out[+6] = 5   out[+7] = 1
    out[+0A] = ds:9C1A（遠指標）      ; 點的陣列
```

與內圈（`165F:0003`，`docs/re/120`）同一套描述格式，差在 `[+6]` 是 5
不是 5／半徑那一格換成點陣列。

## 積分出來的邊界

外層迴圈跑 `i`，條件是

```
(i × 16) ÷ 回轉速度 ≤ 距離
```

第 28 艦隊：回轉 15、距離 240 → `i` 跑 0–225，**226 個點**（一整圈 256
差一點）。每個點的算法：

```
sx = sy = 0（32 位元）；a = 0；rem = i
while rem >= 回轉速度：
    sx += 正弦表[(a + 0x40) & 0xFF] << 3     ; cos，每步走 8 像素
    sy += 正弦表[a] << 3                      ; sin
    a += 回轉速度；rem -= 回轉速度
frac = (rem << 3) ÷ 回轉速度                  ; 不足一步的那一段
sx += frac × 正弦表[(i + 0x40) & 0xFF]
sy += frac × 正弦表[i]
直線 = 距離 − (i × 16) ÷ 回轉速度              ; 剩下的直直走
sx += 直線 × 正弦表[(i + 0x40) & 0xFF]
sy += 直線 × 正弦表[i]
```

正弦表是 sin × 1024，所以 `sx ÷ 1024` 才是像素。**轉彎每一步走 8 像素，
但迴圈條件每一步扣 16**——轉向在這個模型裡是雙倍代價。

## 收據說的不一樣

收據 `s3cmdrange`（第 28 艦隊，回轉 15、巡航 30、朝向 190）：色 6 同時
是外形與虛線格線，先把世界座標是 240 倍數的格線扣掉，剩 351 個像素。
**最遠的那些在半徑 143、方位 185–188（256 制）**——方向對得上艦隊的
朝向 190，但半徑對不上：上面的模型在 `i = 0` 時完全不轉、直線走滿
240，應該落在半徑 240。

拿模型的 226 個點去比收據，**0 個落在色 6 像素的 2 格內**。

## 所以還缺什麼

差 1.7 倍不是捨去誤差，是還沒讀完。三個候選：

- `[bp+10]`（`i`）的遞增量假設成 1，沒有真的讀到那一行；
- 點陣列 `ds:9C1A` 被 `3870:001A` 取用時可能還有一次縮放；
- 起始角：程式裡 `i` 從 0 起、正弦表的索引沒有加上艦隊朝向，但收據
  量到形狀**是照朝向擺的**——中間一定還有一步把它轉過去。

在這三點分開之前不畫。內圈那一個公式已經驗到 0.4 像素
（`docs/re/120`），但**只畫內圈不畫外形反而更不像原版**，所以兩個
一起留著。

> 量測的方法留著：`tools/scripts/range_outer.py` 會扣掉格線再依方位
> 統計半徑。之前用「四鄰接連通取最大塊」量出來的 120 是錯的——外形
> 是**虛線**，連通塊只有十幾個像素，最大塊根本不是最遠點。
