# 135 — 艦隊選點的外形（`165F:004D`）：讀到一半，數字對不上

`docs/spec/027` 把「兩個範圍圖形沒有畫」列成已知差異，理由是外形的公式
沒讀。這一輪讀了那支常式，也量了收據——**兩邊差得太多，所以還是不畫。**

## 描述結構

```
165F:004D(&out, 艦隊, 距離, 回轉速度)
    out[+0] = 艦隊 +0x5C ＋ 8        ; 圓心 ＝ 旗艦圖塊中心
    out[+2] = 艦隊 +0x5E ＋ 8
    out[+4] = 0   out[+5] = 1   out[+6] = 5   out[+7] = 1
    out[+0A] = ds:9C1A（遠指標）      ; 點的陣列
```

與內圈（`165F:0003`，`docs/re/120`）同一套描述格式，差在 `[+6]` 是 5
不是 5／半徑那一格換成點陣列。

## 積分出來的邊界

外層迴圈跑 `i`，條件是

```
(i × 16) ÷ 回轉速度 ≤ 距離
```

第 28 艦隊：回轉 15、距離 240 → `i` 跑 0–225，**226 個點**（一整圈 256
差一點）。每個點的算法：

```
sx = sy = 0（32 位元）；a = 0；rem = i
while rem >= 回轉速度：
    sx += 正弦表[(a + 0x40) & 0xFF] << 3     ; cos，每步走 8 像素
    sy += 正弦表[a] << 3                      ; sin
    a += 回轉速度；rem -= 回轉速度
frac = (rem << 3) ÷ 回轉速度                  ; 不足一步的那一段
sx += frac × 正弦表[(i + 0x40) & 0xFF]
sy += frac × 正弦表[i]
直線 = 距離 − (i × 16) ÷ 回轉速度              ; 剩下的直直走
sx += 直線 × 正弦表[(i + 0x40) & 0xFF]
sy += 直線 × 正弦表[i]
```

正弦表是 sin × 1024，所以 `sx ÷ 1024` 才是像素。**轉彎每一步走 8 像素，
但迴圈條件每一步扣 16**——轉向在這個模型裡是雙倍代價。

## 收據說的不一樣

收據 `s3cmdrange`（第 28 艦隊，回轉 15、巡航 30、朝向 190）：色 6 同時
是外形與虛線格線，先把世界座標是 240 倍數的格線扣掉，剩 351 個像素。
**最遠的那些在半徑 143、方位 185–188（256 制）**——方向對得上艦隊的
朝向 190，但半徑對不上：上面的模型在 `i = 0` 時完全不轉、直線走滿
240，應該落在半徑 240。

拿模型的 226 個點去比收據，**0 個落在色 6 像素的 2 格內**。

## 迴圈的尾巴（讀完了）

```
兩個 32 位元的累加值各右移 10 位（÷ 1024）→ 像素
ds:9C1A[點序][+0] = x 位移；[+2] = y 位移      ; **只存位移，不含圓心**
i += 8                                        ; ← 不是 1
點序 += 1
```

所以第 28 艦隊的點是 `i` ＝ 0, 8, 16 … 224，**29 個**，不是 226 個。
另外累加到一半有一個 `js` 出口（y 的累加值變負就停）。

## 消費端讀完了：沒有縮放，也沒有旋轉

`3870:001A(&描述, 16)`：

```
代號 = 3870:033E()                    ; 配一個槽，0xFF ＝ 沒了
ds:F254 + 代號 × 16 ← 描述（16 bytes）
若 描述[+7] == 1：3870:0296(槽)        ; 立刻畫
回 代號
```

`3870:0296(描述)` 把世界座標換成畫面座標再依 `[+6]` 分派：

```
畫面x = 描述[+0] − ds:9BF4 + 0x10
畫面y = 描述[+2] − ds:9BF6 + 0x14
switch 描述[+6]（0–5）→ ds:8D7A 的六個近位移
```

**戰場左上角是 (16, 20)**；這一份收據裡 `ds:9BF4`／`ds:9BF6` ＝
(1056, 560)，代回旗艦（世界 (1330,941)、畫面 (290,401)）剛好對上。

`[+6] ＝ 5` 那一支（`3870:055C`）是**折線**：

```
點數 = 描述[+8]；顏色參數 = 描述[+5]；點陣列 = 描述[+0A]
第一點 = 陣列[0] ＋ 畫面x, 陣列[2] ＋ 畫面y
其餘每一點與前一點連線（3870:0833）
```

點是**單純的位移**，取用時**沒有縮放、沒有旋轉**。所以「消費端還有一次
縮放」這個候選消掉了——差 1.7 倍的原因在產生端，我對 `165F:004D` 的
讀法有一處是錯的。

## 底層是 EGA 的 XOR 寫入（這解掉了顏色的疑問）

折線每一段走 `3870:0833(x0,y0,x1,y1,色,遮罩)`：先把兩點按 x 排好，
用 `3870:08FF` 裁切到畫面，再叫 `39D7:0936`。那一支：

```
2376:1810(ah ＝ 色)
es = 0A000h；di = 3C5B:00B2(x0, y0)     ; framebuffer 位移
ds:8F0E = 遮罩的低位元組                 ; 8 位元的虛線圖樣
out 3CE, 8                               ; EGA Graphics Controller index 8 ＝ Bit Mask
… 走 Bresenham，每畫一點就 ror ds:8F0E 一位
```

`2376:1810` 設的是：

```
out 3CE, 0005h    ; index 5 Mode ← 0（寫入模式 0）
out 3CE, 色:00    ; index 0 Set/Reset ← 色
out 3CE, 0F01h    ; index 1 Enable Set/Reset ← 0F（四個 plane 都吃 Set/Reset）
out 3CE, 1803h    ; index 3 Data Rotate/Function ← 18h
```

`18h` 的 bit 4–3 ＝ **11 ＝ XOR**。所以**圖形是 XOR 上去的**：

| | 描述 `[+5]` | 底色 | 畫出來 |
|---|---|---|---|
| 內圈 | 5 | 3 | **6** ✓（`docs/re/120` 量到的就是色 6）|
| 外形 | 1 | 3 | **2** |

而且遮罩是 8 位元的圖樣、每個像素 `ror` 一次——虛線就是這樣來的。

## 前兩輪找錯顏色了

外形是**色 2**，不是色 6。前兩輪拿色 6 去比對，比的是虛線格線與內圈。
換成色 2 之後收據上是一條乾淨的封閉曲線：

```
方位(256)   半徑
  130       189
  …         逐漸增加
  189–190   238–239   ← 最大值，正好落在艦隊的朝向 190
  …         逐漸減少
  227       212
```

**最大半徑 239 出現在朝向上**，而模型在 `i = 0`（完全不轉、直線走滿）
算出來是「朝向 190、半徑 240」——**對上了**。所謂「差 1.7 倍」整個是
比錯顏色的假象。

前幾個點也對得很好（模型半徑 vs 該方位量到的最大半徑）：

| `i` | 模型 | 收據 |
|---|---|---|
| 0 | 240.3 @ 190 | 239 @ 190 |
| 8 | 236.5 @ 198 | 234.6 @ 198 |
| 16 | 230.2 @ 205 | 229.9 @ 205 |
| 24 | 225.8 @ 213 | 224.9 @ 213 |

## 產生完之後：先鏡射、再整批旋轉

`165F:004D` 的後兩段（`+0x02B1` 起）：

```
; 鏡射：把 n 個點沿 x 軸翻成 2n 個
for k = 0 .. n−1：
    ds:9C1A[2n−1−k].x =  ds:9C1A[k].x
    ds:9C1A[2n−1−k].y = −ds:9C1A[k].y

; 旋轉：整批依艦隊 +0x4A 轉過去
for k = 0 .. 2n−1：
    ds:9C1A[k] = 旋轉(ds:9C1A[k], 艦隊 +0x4A)
```

**旋轉是最後才做的**，不在積分裡面——這就是之前找不到的那一步。

## 對上了

拿收據每個方位的最大半徑去比（外形是色 2，圓心 (298,409)）：

|---|---|---|---|
| 0 | 240.3 @ 189 | 239.4 | +0.9 |
| 8 | 235.6 @ 198 | 234.6 | +1.0 |
| 16 | 230.2 @ 205 | 229.9 | +0.3 |
| 24 | 225.7 @ 213 | 224.9 | +0.9 |
| 32 | 219.3 @ 220 | 219.5 | −0.1 |
| 40 | 213.8 @ 227 | 213.6 | +0.3 |

`i ≥ 48` 之後方位到 234 以上，那些點落在戰場右緣外面被
`3870:08FF` 裁掉，所以收據上本來就沒有。加上鏡射的那一半，
**落在戰場裡的 15 個點全部在 1.5 像素內**
（`TestManoeuvreBoundaryMatchesOracle`）。

## 進 remake

`rules.ManoeuvreBoundary(回轉速度, 距離, 朝向)` 回相對圓心的位移，
`rules.ManoeuvreInnerRadius(距離)` ＝ `距離 ÷ 3 ＋ 8`；
`screen.DrawManoeuvreRange` 用 XOR 把內圈（色 5）與外形（色 1）疊上去，
艦隊選點時畫。`docs/spec/027` 的「範圍圖形沒有畫」那一條可以拿掉。

在這三點分開之前不畫。內圈那一個公式已經驗到 0.4 像素
（`docs/re/120`），但**只畫內圈不畫外形反而更不像原版**，所以兩個
一起留著。

> 量測的方法留著：`tools/scripts/range_outer.py` 會扣掉格線再依方位
> 統計半徑。之前用「四鄰接連通取最大塊」量出來的 120 是錯的——外形
> 是**虛線**，連通塊只有十幾個像素，最大塊根本不是最遠點。


## 附：六種形狀分別是什麼（`ds:8D7A` 的跳躍表）

| `[+6]` | 常式 | 畫什麼 | 用到的欄位 |
|---|---|---|---|
| 0 | `3870:0372` | **什麼都不畫**（佔位）| — |
| 1 | `3870:037D` → `39D7:008C` | 正圓 | `[+8]` 半徑、`[+5]` 色 |
| 2 | `3870:03A3` → `39D7:035E` | **橢圓**（可傾斜）| `[+8]` 長半軸、`[+0A]` 短半軸、`[+5]` 色、`[+4]` 傾角 |
| 3 | `3870:03D4` | 未讀 | |
| 4 | `3870:042F` | 兩條交叉的線（`docs/re/122`）| `[+8]`／`[+0A]`／`[+0C]` 長度、`[+4]` 朝向 |
| 5 | `3870:055C` | 折線 | `[+8]` 點數、`[+0A]` 點陣列、`[+5]` 色 |

種類 2 那一支要求長半軸 > 短半軸，內部用 `(x × b) ÷ a` 把圓壓成橢圓
再依 `[+4]` 轉過去。**要塞砲的射程就是這一種**（`docs/re/134`：
長半軸 ＝ 防衛力 ÷ 200 ＋ 80、短半軸 ＝ 長半軸 ÷ 4，傾角初值 0）。
