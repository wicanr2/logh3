# RE 103 — 小地圖下緣 y=203 那一列是誰畫的

戰場畫面先前排除兩處：收據上的滑鼠游標，以及 **y=203、x 480–607 那
128 個像素**。2026-09-14 已查清後者：它是全域格表重畫空白內容格後留下的
固定底列，不是小地圖資料。

## 那一列不是面板，也不是地形

- 面板 `ANI_PNL0.A98` 在那一列整片是色 3（y=204 起兩邊逐位元組相同），
  所以是**後來被畫上去的**；
- 小地圖是 (480,75) 128×128，最後一列是 y=202。y=203 剛好多一列；
- 兩份收據（`s3ai6`、`s3fight`）那一列**完全相同**，所以是決定性的內容，
  不是殘留。

## 內容來自地圖緩衝區外面

那一列只有色 1 與色 3 兩種值。色 1 是小地圖的地形色、色 3 是空白色，
兩者只差一個 plane，所以把它當 1bpp 讀：

```
色 1 ＝ 位元 1  →  CE CE C5 CE C5 CE C5 CE E5 CE E5 CE E5 CE C5 CE
```

這 16 個位元組在 1 MB 記憶體裡**只出現一次**，在線性 `0x70EE6`。
星域地圖的緩衝區是 `ds:3C1A` → `0x6D3F4`，展開後 128×102 ＝ 13,056 個
位元組到 `0x706F4` 為止——`0x70EE6` 在那之後 2,034 個位元組。

拿圖塊→顏色的對照表去掃整份記憶體，找不到任何一段連續位元組能對出
那一列，所以**它不是照小地圖的畫法畫出來的**。

## 誰寫的

`-vram-at 3FAC`（y=203、x=480 那個位元組）的統計：

```
2376:1132 ×7    2376:110B ×7    2376:10EA ×7
```

那三處在同一組常式裡，畫的是**一塊 16×20**：

```
2376:10DF  cx ← 19       ; 第一趟：每列讀一個 word，整個 word 左轉一位，
2376:10EA  and es:[di]   ;         用 AND 蓋上去，一列走 80 個位元組
2376:1107  cx ← 20       ; 第二趟：不左轉，從同一列開始，**多走一列**
2376:110B  and es:[di]
2376:1120  cx ← 20       ; 第三趟：out dx,FF08h 之後整塊填單色
2376:1132  mov es:[di]
```

第一趟 19 列、第二趟與第三趟 20 列，而且第二趟的來源位址比第一趟早
兩個位元組（＝早一列）。**兩趟的列數不一樣**，多出來的那一列只被其中
幾個 plane 寫到——一整列色 1 與色 3 交錯，正是這種形狀。

## 2026-09-14 勘誤：來源是空白內容格

舊結論只在單一 VRAM 位址統計，所以把「同一畫面重畫七次」誤讀成七個不同
元件。用 dosgolem `e0b6a03` 重跑並在 `2376:10B7`、`10EA` 記錄暫存器後：

- 格表重畫呼叫端是 `341B:00EE`；鏈條為
  `341B:00EE → 2376:0E0D → 2376:10B7`；
- 輸入是空白內容格 `DX=0x0020`、顏色 `CX=0x0097`；
- 同一列有相鄰的格繪製，畫面共重畫七次，所以 `10EA`／`110B`／`1132`
  在 `-vram-at 3FAC` 才會各出現七次；
- `10B7` 的 19／20／20 列合成越過預期內容後，小地圖只覆蓋到 `y=202`，
  於是這一列保留下來。

這一列在 `s3ai6` 與 `s3fight` 完全相同，且與局面無關。正式契約移到
[`docs/spec/046`](../spec/046-battle-grid-residue.md)；remake 以獨立函式保存這個
原版繪圖瑕疵，不把它併入小地圖尺寸或地形取樣。
