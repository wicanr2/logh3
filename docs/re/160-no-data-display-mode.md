# 160 — 「資料」沒有顯示模式，只是把鏡頭移到那支艦隊

`docs/re/113` 從收據 `s3detail_back` 量到「戰場不是原來的樣子」，
把它記成一種**顯示模式**，`VERIFICATION-MATRIX` 的 4u 因此掛著
「怎麼切回正常顯示未解、remake 不畫」。

配一份記憶體傾印之後，答案是：**沒有模式**。

## 同一條序列，前後各倒一份

`s3detail_back` 的旗標加上傾印，跑兩次（`-dump-mem-at` 在最後一步不會
觸發，所以尾端那一份改用 `-dump-mem`）：

```
批次 s3detailmem   -dump-mem-at 1090000000:lin:0:1048576:…/dm_pre.bin
批次 s3detailmem2  -dump-mem lin:0:1048576:…/dm_post.bin
```

兩份的 `screen.bin` 與 `s3detail_back` 逐位元組相同，所以序列在
`ef5be47` 上仍然重現得出來。一次約 5 分鐘。

## 艦艇記錄一個位元組都沒變

艦艇池在 `ds:CFB4` → 線性 `0x668B2`，148 筆。

```
pre （1,090,000,000 步）：148 筆的 +0x17 全是 0
post（1,260,000,000 步）：148 筆的 +0x17 全是 0
兩份逐筆逐位元組比對：沒有任何一筆有差
```

**「資料」開關的過程沒有碰艦艇記錄。**

## 變的是鏡頭

```
ds:9BF4／ds:9BF6：(1056, 600) → (192, 100)
```

前後兩個視野裡的單位不是同一批：

| 傾印 | 鏡頭 | 視野內的分隊 | `+0x2F`（要畫哪一塊）|
|---|---|---|---|
| pre | (1056,600) | 31 筆 | **全部 255 ＝ 不畫** |
| post | (192,100) | 9 筆（艦隊 12） | 9、32、36、38 |

`+0x2F` 是塊號（`docs/re/85`），36 ＝ 20＋16＋艦種 0、38 ＝ 20＋16＋艦種 2
——就是顯示層級 2 那一組。所以 `s3detail_back` 上的方塊不是新畫法，
是**鏡頭移到了一支塊號本來就是層級 2 的艦隊**；而 `s3data0` 上看不到
方塊，是因為那個視野裡的 31 個分隊全部 `+0x2F = 255`，一個都沒畫。

三個方塊的位置逐一對得上（`螢幕 = 世界 − 鏡頭 + (16, 60)`）：

```
#86 世界 (424,213) → 螢幕 (248,173)
#87 世界 (396,255) → 螢幕 (220,215)
#88 世界 (349,272) → 螢幕 (173,232)
```

## 鏡頭是置中在旗艦上

```
艦隊 12 的旗艦（池索引 80）在世界 (416,280)
鏡頭 (192,100)
旗艦 − 鏡頭 = (224,180) = 戰場 448×360 的正中央
```

**鏡頭 ＝ 旗艦位置 − (224, 180)**，一個像素不差。

## 4u 剩下什麼

- ~~怎麼切回正常的戰場顯示~~：沒有東西要切回來，戰場的畫法從頭到尾沒變。
- ~~視野為什麼捲動~~：「資料」點下去把鏡頭置中到那支艦隊的旗艦。
- 右側面板換成分隊資料的**觸發條件**仍未證（面板本身已對拍，
  見 `docs/internals/45` 與矩陣 4s）；這一份收據裡選中的是哪一個分隊、
  由什麼決定，也還沒解。

## 教訓

**「畫面不一樣」有三種可能：畫法變了、資料變了、鏡頭變了。**
`docs/re/113` 逐項排除了前兩種裡的細節（字形、格線），卻沒有把第三種
列進候選——而它是最便宜的一種：一份傾印裡的兩個 word 就分得出來。
