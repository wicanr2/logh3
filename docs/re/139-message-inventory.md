# 139 — 全遊戲的訊息框清單

`docs/re/138` 把訊息框的機制解完之後，剩下的問題只是「它總共說過哪些話」。
這是一次掃得完的：`3826:0005` 的遠呼叫在整份常駐程式碼裡有 **21 處**。

## 怎麼掃的

`tools/scripts/msgbox_sites.py` 在程式碼傾印裡找 `9A 05 00 26 38`，
再往回讀 48 bytes 把四個推入解出來（`mov r,imm ; push r` 與 `push ds`
兩種碼形）。呼叫慣例是由後往前推「字串段、字串位移、色、種類」。

**認不出來的寫 `null`，不猜。** 21 處裡 16 處一次就解出來，剩下 5 處
（全在 `2BE1`）另外反組譯：

| 呼叫端 | 實際情形 |
|---|---|
| `2BE1:0A17` | 種類取 `ds:D20C`（變數），字串 `ds:5BBD`「磁碟片讀取時有發生錯誤。…請重新開機。」 |
| `2BE1:0B32` | 種類取 `ds:D20C`，字串 `ds:5BF1`「磁碟片載入時有發生錯誤。」 |
| `2BE1:10C5`／`112A`／`119A` | 四個參數原封不動往下傳——這三處是通用包裝，不是固定訊息 |

讀取失敗時種類取變數是合理的：那時候畫面可能停在任何地方，框要開在
哪一格得看當下。

## 結果

18 句訊息，全部進
[`docs/internals/48`](../internals/48-message-inventory.md) 與
[`data/message-sites.json`](../internals/data/message-sites.json)。
顏色一律 `0x97`；種類 0／2 是一顆「確認」，1／3 是「中止」＋「決定」。

## 可重用的規則

- **機制解完之後，順手把「它總共有幾個」掃一遍。** 訊息框的實作花了兩天，
  掃出全部 21 個呼叫端只花幾分鐘——而這一份清單同時是保存的成果、
  也是後面每一個缺口的工作清單（哪一句還沒接上玩家路徑，一看就知道）。
- **往回掃參數的解析器要能說「我不知道」。** 21 處裡有 5 處碼形不同，
  硬猜會得到 `種類 151、色 5BF1` 這種看起來像數字、實際上是把字串位移
  讀成顏色的答案。寫成 `null` 再逐一反組譯，五分鐘就補完。
