# 換手的條件：攻擊力追上剩下的防衛力

[`docs/re/150`](150-planet-capture-receipt.md) 量到「打完還有 428 防衛力，
擁有者已經換了」，所以條件不是歸零。這一輪把 `20B4:0503` 讀完。

## `20B4:0503(艦隊, 行星)`：一支艦隊對一顆行星的一輪

```
if 行星[+0x11] == 艦隊[+0x01]: 回                  ; 自己的行星不打
門檻 ＝ 行星[+0x14] × 100 ÷ 行星[+0x16]            ; 防衛力還剩幾成
if 艦隊[+0x3C] ≥ 門檻:
    r ＝ 20B4:0681(艦隊, 行星)                     ; 先開火
    if r ≤ 0: 20B4:08B1(艦隊, 行星)                ; 沒打下來才挨反擊
else:
    20B4:08B1(艦隊, 行星)                          ; 先挨反擊
    r ＝ 20B4:0681(艦隊, 行星)
if r != 0xFFFF 且 r != 0:
    行星[+0x11] ← 艦隊[+0x01]                      ; ★ 換手
    （接著是 docs/spec/019 已經記下的那幾格：存量清 0、飛彈右移一位、
      艦載機 ← 0、分數 ＋ 行星[+0x16] ÷ 10）
```

`艦隊[+0x3C]` 是 0–100 的一個值（收據裡五支是 100、100、100、100、99），
門檻是防衛力剩下的百分比（收據裡 2852 ÷ 3300 → 86）。**誰先動手由這兩個
數字決定**。

## 回值就是換手的條件

`20B4:0681` 的尾巴：

```
行星[+0x14] −= 量
ds:8FE4[攻方陣營] += 量 ÷ 20 ; ds:8FEC[攻方陣營] 同
203A:0743(艦隊, 量 ÷ 2)
回 20B4:0E2C(行星, A)
```

而 `20B4:0E2C` 只有八行：

```
20B4:0E2C(行星, A)：回 (A ≥ 行星[+0x14]) ? 1 : 0
```

`A` 就是 `203A:0424(艦隊)` ＝ 那一支的攻擊力
（[`docs/re/146`](146-battle-damage-helpers.md)）。所以

> **換手的條件是「這一支的攻擊力追上行星扣完之後剩下的防衛力」。**

收據對得上：扣完剩 428，五支艦隊的 A 分別是

| 艦隊 | 主力艘數 | `+0x40` | A | A ≥ 428 |
|---:|---:|---:|---:|---|
| 16 | 9000 | 101 | 856 | 是 |
| 17 | 3000 | 78 | 406 | 否 |
| 28 | 15000 | 120 | 1450 | 是 |
| 29 | 3000 | 88 | 426 | 否 |
| 31 | 9000 | 99 | 844 | 是 |

三支追上、兩支差一點——而行星確實換手了。

## 分數的組成也對得上

`ds:8FE4[1]` 這一步 ＋449。組成應該是「逐支 `量ᵢ ÷ 20`」加上換手獎金
`行星[+0x16] ÷ 10` ＝ 3300 ÷ 10 ＝ 330。449 − 330 ＝ **119**，而這一輪
的總傷害是 2852 − 428 ＝ 2424，2424 ÷ 20 ＝ 121——逐支捨去會比總和少
一點，五支艦隊剛好能吃掉那 2。

⚠ 這是**自洽檢查**，不是逐支量到的：要逐支驗得把亂數按排序順序接上，
而 `20B4:08B1` 消耗幾個 `rand()` 還沒讀。

## 還缺什麼

| 問題 | 卡在哪 |
|---|---|
| 逐支的傷害量 | 算式已知，但 `20B4:08B1` 消耗幾個亂數還沒讀，接不上序列 |
| 反擊怎麼分攤到 17 個分隊 | `20B4:0C4E`／`20B4:1370`／`20B4:08B1` 之後那幾支 |
| `艦隊[+0x3C]` 是什麼 | 值 99–100，看起來是戰意或編制完整度 |

## 可重用的規則

- **「回值代表什麼」要追到最後一支。** `20B4:0681` 看起來在算傷害，回的
  卻是一個八行的比較（`20B4:0E2C`）。中間讀到「量 ＝ …」就停下來的話，
  會把「量 > 0 就換手」當成結論——那等於「打一下就拿下」。
