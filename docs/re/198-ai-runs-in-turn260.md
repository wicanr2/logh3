# 198 — `turn260` 那三張收據裡，AI 跑過

`docs/re/189` 掃完 25 份記憶體傾印之後留下一個沒量的角落：
`turn260`／`turn320`／`turn450` 是**畫面**收據，沒有傾印，所以那一輪
的掃描碰不到它們，結論寫成「幾乎確定不變，但還沒直接量」。

量了。**AI 有跑。** 那句「幾乎確定不變」對這三張不成立。

## 怎麼量的

用 `turn260` 原本的旗標再跑一次，只多兩樣：對 `ds:D60E`（線性 `6213E`）
設監看、收尾 peek 三處。

```
tools/oracle.sh turn260ai -tick 20000 -press 1,3,8,enter -press-at 105000000
  -press-every 2000000 -steps 260000000
  -clicks '300,170,40000000,3000000;300,170,95000000,3000000;544,85,180000000,3000000;560,85,210000000,3000000'
  -rclicks '300,200,130000000,3000000;300,200,155000000,3000000'
  -watch 6213E-6213E
  -peek 'lin:6213E:2,lin:6203E:40,lin:5DA4D:8'
```

收據 `workplace/oracle/turn260ai/`，dosgolem HEAD `ef5be47`（工作樹乾淨），
`GIN3.COM` SHA-256 `770ed526…8918`。

**用監看不用 peek**，是因為 `ds:D60E` 在每個 AI 回合開頭會被清 0
（`2E54:0048` 的 `mov byte [D60E], 0`）——只看最後一刻的 peek 會把
「跑過但被清掉」讀成「沒跑過」。

## 結果

```
[watch] #66162324  6213E: 00 → EC  ← 63A1:002D
[watch] #68658443  6213E: EC → 00  ← 0349:01EA
[watch] #213747304 6213E: 00 → 02  ← 2E54:1188
[watch] #213750140 6213E: 02 → 03  ← 2E54:083B
```

前兩筆在 `gin3ps.exe` 被 EXEC 起來（#68658…）之前，那時候這塊記憶體
還不是遊戲的資料段，與 AI 無關。

後兩筆都在 `2E54`——戰略 AI 的程式碼段：

| 步數 | 回報的 CS:IP | 指令位址 | 在哪一支 |
|---|---|---|---|
| 213747304 | `2E54:1188` | `2E54:1183` `add byte [D60E], 2` | `2E54:1108`（階段二打無主，湊滿兩支）|
| 213750140 | `2E54:083B` | `2E54:0837` `inc byte [D60E]` | `2E54:07D8`（階段三的指派）|

監看回報的是**執行完那道指令之後**的 CS:IP，所以位址要減掉指令長度。

第四次「實行」的點擊排在 #210000000，AI 在它之後 3.7×10⁶ 步跑起來——
與 `docs/re/187` 的兩條座位迴圈一致：玩家階段先跑完，才輪到
`04F8:030E` 那條把電腦座位丟進 `2D10:0005`。

收尾的 peek 也對得上：

```
ds:D60E = 03
ds:D50E[13] = 1000h = 4096      （其餘 0..19 全 0）
ds:8F1D=0 8F1E=0 … 8F23=[0, 1]
```

`ds:8F23 = [0, 1]` ＝ 座位 0 是玩家（帝國）、座位 1 是電腦（同盟）；
跑完回到座位 0，所以 `ds:8F1E` 是 0。`ds:D50E` 只有伊謝爾倫非零，
正是同盟在態勢碼 0 的進軍路線表 `[[13]]`（`docs/re/178`）。

## 對那個待裁決事項的意義

把 `internal/ai` 的 `Original` 從「什麼都不做」換成 `OriginalStrategy`，
**在 `turn260`／`turn320`／`turn450` 上有真正的風險**——原版在那三張的
狀態裡確實跑過 AI，指派了三支艦隊。`internal/game` 的
`TestExecuteTurnMatchesOracle` 拿整張畫面比這三張，remake 目前是靠
「AI 什麼都不做」通過的。

反過來說，這三張**現在**能逐位元組通過，等於原版那三支指派在按完
「實行」的那一刻**沒有改變畫面上的任何東西**——指派寫的是艦隊記錄的
`+0x07`／`+0x79`，要到下一次推進才會動。所以換過去之後，這個測試
是不是還綠，取決於 remake 的 AI 有沒有多做原版沒做的事。**換之前先
跑一次那個測試就知道**，不需要再排長跑。

## 順帶：`ds:D60E` 有第十一個寫入點

`docs/re/197` 掃的是 `fe 06 0e d6`（`inc byte [D60E]`），漏掉了
`80 06 0e d6 02`（`add byte [D60E], 2`）。把絕對定址的形式一次掃完
（`modrm & 0xC7 == 0x06` 且 disp16 ＝ `D60E`，另加累加器直接存取），
整份 1 MB 傾印只有這 13 處：

| 位址 | 指令 | 角色 |
|---|---|---|
| `0x2E588` | `mov byte [D60E], 0` | 唯一的清 0（回合開頭）|
| `0x2E607`／`2E67A`／`2E6AF`／`2E6CA` | `inc` | `2E54:005D` |
| `0x2E978`／`2E9BB`／`2EA1F`／`2EA37` | `inc` | `2E54:03C3` 一帶 |
| `0x2EB68` | `inc` | `2E54:0513` |
| `0x2ED77` | `inc` | `2E54:07D8` |
| `0x2F6C3` | **`add …, 2`** | `2E54:1108`（一次派兩支）|
| `0x2F088` | `mov cl, [D60E]` | **讀**：`2E54:0AAB` 的「已到 ＋ `ds:D60E` < 16」|

`add …, 2` 落在 `2E54:1108` 裡「湊滿兩支才打無主星域」那一段的正後方
（`docs/internals/54`），語意與其他十處一致：**一次處理幾支就加幾**。
`docs/re/197` 的結論（它數的是整個回合，不是逐艦隊決定那一趟）不變，
只是遞增點是十一處不是十處。

方法上的一條：**掃一個變數的寫入點時，不要只掃你想得到的那個
opcode。** 掃「絕對定址 disp16 ＝ 這個位址」的全部形式，成本一樣，
而漏掉的那一個剛好是唯一一個一次加 2 的。

## 順帶二：收據跨了執行器三個版本仍然逐位元組相同

`turn260`／`turn320`／`turn450` 是在 dosgolem `2833ec9` 量的，這一跑是
`ef5be47`——中間隔著 `20e4583`「畫面輸出跟著 CRTC 的顯示起點走」，
一個會改顯示語意的提交。`screen.bin` 的 SHA-256 仍然是
`0a023a89…4bd3`，四份完全相同。

這一跑因此順便當了 `CLAUDE.md`「動到執行器的顯示語意之後先重跑收據」
那條的重跑：這三張在 `ef5be47` 上仍然有效。（這一格的顯示起點是 0，
所以 `20e4583` 對它沒有作用；顯示起點非 0 的收據要另外驗。）

## 順帶三：一份沒有 poke 過的 AI 局面

`s3aicomp`（`docs/re/176`）是把 `ds:8F23[0]` poke 成 1 逼出來的。
這一跑的 AI 是遊戲**自己**跑的：座位表原本就是 `[0, 1]`。

`ds:D50E[13] = 4096` 可以直接對算式：`(路線計數 + 1) × (2048 ÷ (威脅 + 1))`
＝ `2 × (2048 ÷ 1)`，也就是這一刻伊謝爾倫的 `ds:D54E` 是 0。
`s3aicomp` 上同一格是 `2 × (2048 ÷ 6) = 682`，威脅 5。兩個局面、
同一條算式。

要把它變成第二份完整收據，得在 #213750140 前後倒一份 1 MB 記憶體
（`ef5be47` 新加的 `-dump-mem-at` 剛好做得到），成本與這一跑相同：
2.6×10⁸ 步、一個容器、一核。**還沒跑。**
