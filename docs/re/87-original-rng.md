# 87：原版的亂數產生器

## 為什麼要它

戰損的算式裡有一項是 `亂數 mod 100`（`docs/re/86`），所以不重現
這個產生器就對不了任何一場戰鬥的結果。

## 是什麼

`3CD5:000C`：

```
+000E  mov  ax, ds:94DEh         ; 種子高位
+0011  mov  bx, ds:94DCh         ; 種子低位
+0015  mov  cx, 41C6h
+0018  mov  si, 4E6Dh            ; 乘數 0x41C64E6D
+001D  call far 3CC9h:9          ; 32 位元乘
+0022  add  bx, 3039h            ; 加數 0x3039
+0026  adc  ax, 0
+0029  mov  ds:94DEh, ax
+002C  mov  ds:94DCh, bx
+0030  mov  bx, ax
+0034  mov  ax, bx
+0036  and  ah, 7Fh              ; 回 (種子 >> 16) & 0x7FFF
+003B  retf
```

也就是標準的線性同餘：

```
種子 ＝ 種子 × 0x41C64E6D ＋ 0x3039     （32 位元）
回傳 (種子 >> 16) & 0x7FFF
```

`3CD5:003C` 是對應的 `srand`：種子高位清 0、低位放參數。

種子放在 **`ds:94DC`**（32 位元）。

## 驗證

四份收據的記憶體傾印裡，`ds:94DC` 的值是

| 收據 | 步數 | 種子 |
|---|---:|---|
| `s3ai6` | 900,000,000 | `B6E4B78A` |
| `s3turn2` | 1,150,000,000 | `290995CF` |
| `s3fight` | 1,400,000,000 | `3FA1A51D` |
| `s3kinds2` | 1,400,000,000 | `3FA1A51D` |

兩件事：

1. `s3fight` 與 `s3kinds2` 的序列只差幾筆 `-poke`（改的是艦種，
   不影響 `rand()` 被呼叫幾次），種子**完全相同**——決定性成立。
2. 從 `s3turn2` 的種子照上面的算式往前走，**走 10 步剛好等於
   `s3fight` 的種子**。乘數、加數、位寬任何一項錯了都走不到。

那八個回合只叫了 10 次 `rand()`。

## remake

`rules.Rand`（`internal/rules/rand.go`）。要接上原版某個局面時，
從收據的傾印讀 `ds:94DC` 餵給 `SetSeed`。
