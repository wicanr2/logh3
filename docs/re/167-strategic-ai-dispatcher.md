# 167 — 每個星域派幾支：`2E54:0AAB`，以及伊謝爾倫的特例

`docs/re/166` 讀完分配那一支（`2E54:0CD2`），剩下「目標與那一串艦隊是誰
選的」。呼叫者只有一個：`2E54:0AAB`。

## 收候選

```
2E54:0AAB(星域 [bp+90h])
    n = 0 ; 已到 = 0
    迴圈：
        艦隊far = 2E54:143F(星域, 1)        ; 迭代器，取下一支候選
        若 null：跳出
        清單[n++] = 艦隊far                  ; 4 bytes 一筆的 far 指標陣列
        d = 2B99:0450(星域, 艦隊[+0x06], 艦隊[+0x01])
        若 d <= 1：已到++ ; 艦隊[+0x79] = 6 ; **跳出**
        否則：      艦隊[+0x79] = 4 ; 繼續
    若 n == 0：結束
```

`+0x79`（這回合的決定）因此又多兩個值：**4 ＝ 候選、6 ＝ 已經到了**
（0 與 3 見 `docs/re/79`）。`2B99:0450` 是另一支距離函式，回 `<= 1`
代表「就在那一格或隔壁」。

## 三條分支

```
若 已到 < ds:D58E[星域]（還缺幾支）且 已到 + ds:D60E < 16：
    若 (缺幾支 − n) < 3：
        2E54:0CD2(&清單, n, 星域)                ; ← 直接分配（docs/re/166）
    否則：
        若 3CD5:000C() < 0x2000：                 ; 四分之一的機率
            2E54:0DE3(&清單, n, 星域)             ; 還沒讀
否則：
    若 星域 == 0x0D（伊謝爾倫）且 3CD5:000C() & 1：
        要派 = 已到
    否則：
        要派 = ds:D58E[星域]
    2E54:0BEB(&清單, 要派, 星域)                  ; 還沒讀
```

`ds:D60E` 是這一趟「已經決定了幾支」的計數器（`docs/re/79`）；16 是
一個陣營的艦隊槽數（`docs/re/166`）。

## 伊謝爾倫有一個寫死的特例

`cmp byte [bp+90h], 0Dh` ——**星域 13 是伊謝爾倫**（`stellar.json`，
防衛力 12800，就是 `docs/re/134` 那顆要塞）。當候選已經夠、或者全部
16 個槽都已經決定時，如果目標是伊謝爾倫，AI 會**丟一次銅板**
（`rand() & 1`）決定「只派已經到的那幾支」還是「照缺口派滿」。

全遊戲的 AI 裡目前只看到這一個寫死的星域編號。

## `3CD5:000C` 就是 `rand()`

```
3CD5:000C
    ds:94DE:ds:94DC = 種子 × 41C64E6Dh + 3039h
    回 (高位 word) & 7FFFh
```

與 `docs/re/87` 記的同一支；`docs/internals/51` 寫的 `3CC9:00CC` 是
**同一個線性位址的另一種段寫法**（`0x3CC90 + 0xCC` ＝ `0x3CD50 + 0x0C`
＝ `0x3CD5C`），不是另一支。

## 還沒讀

- `2E54:0BEB`（候選夠時走的那一支）與 `2E54:0DE3`（候選不夠、丟中銅板
  時走的那一支；開頭是 `若 ds:D54E[星域] < 0x0C：回`）。
- `2E54:143F` 那個迭代器怎麼挑候選。
- `2E54:0AAB` 自己的呼叫者（誰決定要處理哪個星域、順序是什麼）。

> `2E54:143F`、`2E54:0DE3` 已解：`docs/re/168`、`docs/re/169`。
> 上面寫的「`若 ds:D54E[星域] < 0x0C：回`」判斷方向相反——
> `jb` 是**繼續**，`>= 12` 才回。
