# 240 — 「已支付 移動經費」是 `ds:8F8A`；預算畫面十列全部對應完成

`docs/re/239` 把預算畫面四格裡的三格釘住，剩下「已支付 移動經費」
（y ＝ 222）的全域沒找到。它就在旁邊。

## 猜測有根據

已經確定的三格在資料段裡是**每 8 個位元組一格**（兩個陣營 × 32 位元）：

```
ds:8F72   本次預定 艦隊維持費
ds:8F7A   已支付   艦隊維持費
ds:8F82   本次預定 移動經費
ds:8F8A   ← 空著的那一格
ds:8F94   已支付   船艦建造費
```

照這個節奏，`ds:8F8A` 是唯一的候選。

## 收據 `fiscalpaid`

輸入序列與 `fiscalrows5` 相同，只把 `lin:5DABA`（＝ `ds:8F8A[帝國]`）
在 `#129.0M`–`#131.1M` 之間每 50k 條注入成 44444：

```
已支付  移動經費   ：   44444      ← ds:8F8A ✓
        預估軍事費 ：   16297      ＝ 60741 − 44444

        剩餘軍事費 ：    1112      ＝ 16297 − 15185
```

算式與 `docs/re/239` 量到的完全一致，只是這次只扣一格。

## 一條方法

**版面有節奏的時候，空格是可以算出來的。** 三個已知的全域間距都是 8，
中間空著一格、後面接已知的 `ds:8F94`——候選只剩一個，一跑就中。
前一題（`docs/re/239`）花了四跑，是因為當時連「要注入哪一刻」都不知道；
知道之後，同一個技巧一次就成。**先把便宜的結構線索用完，再開跑。**
