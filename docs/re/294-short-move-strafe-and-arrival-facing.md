### 位址的兩種寫法

`docs/re/122`／`129` 記的「`1C03:01B5`（實行）」是 **`1C00:01B5`** 的寫法——
線性 `0x1C1B5`，就是函式入口 **`1C03:0185`**（`55 56 57 83 EC 20`）。
`docs/re/123` 的「轉一步 `1C03:0554`」「前進一步 `1C03:02C6`」同樣是 `1C00` 基底，
換成 `1C03` 是 `1C03:0524`（函式入口）與 `1C03:0296`（`1C03:0185` 裡面的那一段，
不是獨立函式）。`docs/re/102` 的 `1C03:004F`／`0053` 是監看印的「寫完之後的 IP」。
本篇一律寫 **`1C03` 基底的指令位址**。

## 分派：`+0x48` 決定走哪一支

`181B:018B` 那個逐艦隊迴圈（在場清單 `ds:9898`、筆數 `ds:9894`）每一輪對每支艦隊叫
`1C03:006A`，回非 0 就表示「這一支這一輪還有動作」：

```
1C03:006A(艦隊):
    逐分隊：艦艇 +0x16 &= 0FDh；艦艇 +0x1E == 7Fh 且 位置 != 目的地 → +0x16 |= 2
    若 (32 位元) +0x58:+0x56 < 8.0：回 0
    依 +0x48（整個 byte）查 ds:4100：
        00h／10h／01h／11h → 1C03:0129 → r = 1C03:015C(艦隊)
        其他             → r = 0
    r != 0 → 25DB:0670(艦隊)                    ; 更新戰場圖示
    回 r

1C03:015C(艦隊):                                ; 26 F6 47 48 10 / 74 0D
    +0x48 & 10h → 1C03:0361(艦隊)
    否則         → 1C03:0185(艦隊)
```

`ds:4100` 在四份傾印裡都是 `00 00 10 00 01 00 11 00`（四個鍵）接
`29 01 29 01 29 01 29 01`（四個處理位址全是 `1C03:0129`）。
所以**只有「移動」（0）與「戰鬥」（1）會走實行常式**，bit4 是這兩個行動的修飾位元；
防禦、占領、待命那幾個值直接回 0、不動。

## `1C03:0361`：短程平移

```
1C03:0361(艦隊):                                ; 55 56 57 83 EC 1C 89 E5
    +0x49 &= 0FEh                               ; 1C03:0370
    若 位置(+0x5C,+0x5E) == 目的地(+0x64,+0x66)：
        若 +0x4A != +0x4C：回 1C03:0524(艦隊, +0x4C)    ; 1C03:039E，轉一步
        否則            ：回 0
    若 (32 位元) +0x58:+0x56 < 8.0：回 0         ; 1C03:03C7
    d = 3310:0006(位置, 目的地)                   ; 1C03:03FD
    若 d > 8.0：                                  ; 1C03:040B 比較、jg
        θ = 2BE1:011D(目的地 − 位置)              ; 1C03:0450
        (nx,ny) = 2BE1:026F(位置, θ, 8)           ; 1C03:0478（9A 6F 02 E1 2B）
    否則：(nx,ny) = 目的地
    s = 3310:0006(位置, (nx,ny))；s == 0 → s = 1
    +0x58:+0x56 −= s                              ; 1C03:04B4／04B8，先扣
    r = 2583:040C(nx, ny, +0x01)                  ; 後問站不站得住
    r == 0     → 位置 ← (nx,ny)
    r == FFFFh → 2583:0451(&+0x5C, &+0x5E, 8, 陣營)
    回 1
```

與 `1C03:0185`（`docs/re/129`）逐段對照：

| | `1C03:0185`（bit4 沒設）| `1C03:0361`（bit4 有設）|
|---|---|---|
| 到了 | 轉一步向 `+0x4C`，回轉一步的結果 | **相同** |
| 還沒到，先做的事 | θ ≠ `+0x4A` 就 `1C03:0524(θ)` 轉一步，轉了就 `+0x49 \|= 1` | **不轉**，也不碰 `+0x49` |
| 前進的方向 | 沿 **`+0x4A`**（`1C03:02A9` 推 `es:[bx+4Ah]`）| 沿 **θ**，每一步重算一次 |
| 行程、落點、擋住的處置 | 先扣後驗、0 當 1、`2583:0451` | **相同** |

所以 bit4 有設的艦隊**整段路朝向不變**，走直線（每一步重新瞄準目的地）；
朝向只在到了之後轉向 `+0x4C`。bit4 沒設的艦隊先轉向目的地方位再走，
到了之後同樣轉向 `+0x4C`——兩支都靠 `1C03:0524` 那一條：
`|角差| ≤ +0x4D` 一次轉到位**不扣**；否則轉 `±+0x4D`、扣 8.0，額度不足 8 就這一輪不轉。

一個直接的後果：**`+0x49` bit0 只有 `1C03:0185` 會設**，而且是在還沒到的那一段、
轉一步回 1 之後（`1C03:021E`）；兩支的抵達分支都不設。所以它的意思是「這一次實行
轉過身」，不是 `docs/re/95` 起記的「這一輪到位了」。讀它的 `1C03:093D` 拿它選
跟著隊形走的分隊（艦艇 `+0x1E == 7Fh`）一步的長度：有設 16、沒設 8，艦艇 `+0x16`
bit1（`1C03:006A` 設的「還沒到自己的隊形位置」）再 ×3/2，之後 `1C61:0444(艦艇, 步長)`；
`+0x1E` 不是 `7Fh` 的分隊一律 8。所以平移中的艦隊，它的分隊拿不到 16。
那支函式的入口與呼叫端這一輪沒讀。

## bit4 是誰設的：`2583:052C`

整份影像對 `+0x48` 做 `or …,10h` 的只有一處，`and …,0EFh` 一處都沒有：

```
2583:052C(艦隊):
    d   = 3310:0006(+0x5C, +0x5E, +0x64, +0x66)        ; 到目的地的距離
    thr = (+0x54:+0x52) ÷ 3 + 4.0                        ; 3CC9:0070 有號除；adc cx,4
    d < thr → +0x48 |= 10h                               ; 2583:057E：26 80 4F 48 10
```

七個呼叫點，**每一個前面都先把 `+0x48` 整個 byte 寫掉**（bit4 因此歸零）、
再把 `+0x52:+0x54` 換成這個行動的速度 × 8：

| 呼叫點 | 誰 | 之前寫的 `+0x48` | 行程用的速度 |
|---|---|---|---|
| `1CC5:0875` | 玩家「移動」（`1CC5:0849`：`26 88 47 48`，`al` ＝ 0）| 0 | `+0x4E` 巡航 |
| `1CC5:091E` | 玩家「戰鬥」（`1CC5:08F1`：`26 C6 47 48 01`）| 1 | `+0x4F` 戰鬥 |
| `307D:0EF7` | AI（`307D:0ED4`）| 1 | `+0x4F` |
| `307D:115F` | AI（`307D:10EC`）| 0 | `+0x4E` |
| `307D:1307`、`307D:14B8` | AI 打行星（`307D:11E5`、`307D:144D`）| 0 | `+0x4E` |
| `307D:15DB` | AI 打行星（`307D:1514`）| 1 | `+0x4F` |

換句話說：**下命令的那一刻，目的地離現在位置不到「一回合行程的三分之一再加 4」，
這一趟就是平移**；遠一點的才轉身走。bit4 只在下命令時算一次，走的途中不重算。

有一條 AI 移動**不叫** `2583:052C`：`307D:0201`–`0232` 把目的地設成先前沿某個方位
推出來、`1588:0891` 驗過直線通行的點，`+0x5B ← 0FFh`、`+0x48 ← 0`（`307D:0217`）、
行程換成巡航 × 8 就回去了。這條命令的 bit4 一律是 0，走一般路徑，也不寫 `+0x4C`。
（`307D:00EE` 寫 4（待命）那一條同樣不叫，但待命本來就不進實行常式。）

`2583:0003` 選點時畫的內圈半徑是 `(速度 × 8) ÷ 3 ＋ 8`（`docs/re/120`），與這條門檻
是同一個速度的三分之一。**「內圈就是在提示平移範圍」是 strong inference**——
兩個常數不同（圈是 ＋8、門檻是 ＋4.0，而且圈的除法是整數），所以圈線內緣
4 像素上下的點畫在圈裡、實際卻走一般路徑。

## `+0x4C` 怎麼算：四個寫入者

`field_xref.py 4C`（`mod=01` 與 `add reg,imm` 兩種形式）加上 `struct_window.py`
判基底之後，艦隊的 `+0x4C` 只有四處 byte 寫入：

| 位址（指令）| bytes | 值 |
|---|---|---|
| `297B:0BAB` | `26 88 47 4C` | 開戰：`2BE1:011D(0x3F8 − x, 0x3F4 − y)`，指向 (1016,1012)；同一個值也寫 `+0x4A`（`297B:0BA7`）與 `+0x4B`（`297B:0BAF`）（`docs/internals/39`、`docs/re/288`）|
| `2583:00BC` | `26 88 47 4C` | 玩家「移動／戰鬥」：選朝向那一段的回傳值 ＝ `2BE1:011D(游標 − 目的地)`，游標正好停在目的地上就是艦隊當時的 `+0x4A`（`2583:03A9`，`docs/re/120`／`122`）|
| `307D:0ED0` | `26 88 47 4C` | AI：`2BE1:011D(對方[+0x74] − 自己[+0x64], 對方[+0x76] − 自己[+0x66])`——**從目的地望向對方艦隊的預測落點**（`+0x74`／`+0x76`，`docs/re/288`）。緊接著 `+0x48 ← 1` |
| `307D:1157` | `26 88 47 4C` | AI：目的地 ← 另一筆艦隊記錄的 `+0x5C`／`+0x5E`，`+0x4C ← 2BE1:011D(目的地 − 自己現在位置)`——**行進方向**。緊接著叫 `2583:052C` |

AI 打行星那三條（`307D:1307`／`14B8`／`15DB`，目的地走 `31DB:0024` 換成行星座標）
**不寫 `+0x4C`**，艦隊到了之後轉向的是它原本留著的那個值。

讀 `+0x4C` 的只有三處：`1C03:01B5`（`1C03:0185` 的抵達分支）、`1C03:0391`
（`1C03:0361` 的抵達分支）、`3009:0314`（`26 8A 47 4C 26 88 47 78`：走得到目的地時
把 `+0x4C` 抄進預測朝向 `+0x78`，`docs/re/288`）。

## 收據對得起來的部分

整批 78 份傾印（1 MB 的，加上 `-dump-mem-at` 那些以 `0x60000` 為基底的 64 KB 片段）
裡 `+0x48` bit4 有設的在用艦隊共 32 筆，**31 筆已經停在目的地上**；
唯一在路上的是 `s3fltseq` 的槽 30：

| 時點 | 槽 | `+0x48` | `+0x4A` | `+0x4C` | 位置 → 目的地 | `+0x52` | `+0x56` |
|---|---|---|---|---|---|---|---|
| `ft01` | 28 | `00` | 190 | 190 | (1330,941) → (1240,840) | 240.0 | — |
| `ft02` | 28 | `01` | 190 | 190 | 同上 | 160.0 | — |
| `ft01` | 30 | `00` | 178 | 170 | (1169,1163) → (1168,1160) | 208.0 | 4.44 |
| `ft02` | 30 | **`10`** | 178 | 170 | 同上 | 208.0 | 4.44 |
| `ft03` | 30 | `10` | **170** | 170 | **(1168,1160)** 到了 | 208.0 | **`0x00CCD678`** |

- **門檻**：`ft01` → `ft02` 之間（1570M 步那一下點擊之後）兩支的 `+0x48` 都被重寫、
  `+0x52` 換成新行動的速度 × 8。bit4 唯一的設定者是 `2583:052C`，所以槽 30 一定經過它：
  距離 3.16、門檻 208.0 ÷ 3 ＋ 4 ＝ 73.33，bit4 有設 ✓。槽 28 變成「戰鬥」、行程 160.0，
  寫 `+0x48 ← 1` 又重設行程的三個位置（`1CC5:08F1`、`307D:0ED4`、`307D:1514`）後面都叫
  `2583:052C`：距離 135.28、門檻 57.33，bit4 沒設 ✓。是哪一個呼叫點這一輪沒分
  （`docs/re/126` 記為「引擎把行動改成戰鬥」）。有 `+0x60` 備份的記錄（玩家下過命令）
  掃出來五筆不重複的狀態，全部與門檻一致，但**五筆都是槽 28 的不同時點**，不算獨立樣本
  （`workplace/re294/bit4check.py`）。
- **抵達那一步逐位元對上**：`3310:0006((1169,1163),(1168,1160))` ＝ 3 × `fixSqrt(72817)`
  ＝ 3 × 69080 ＝ 207240；208.0 − 207240/65536 ＝ 13424248 ＝ **`0x00CCD678`**，與 `ft03` 相同。
  也就是說：一步走到目的地、扣掉那一步的長度；**轉向 178 → 170（|角差| 8 ≤ 回轉速度 10）
  一次轉到位、不扣**；**到了之後不再扣任何東西**（兩支常式在「到了、朝向對齊」時都直接回 0）。

**這組樣本分不出 `1C03:0361` 與 `1C03:0185`**：距離不到 8，兩支都直接把位置設成目的地；
`1C03:0185` 會先轉向方位 ≈ 179，差 1 同樣一次到位不扣，最後狀態一模一樣。
平移那一段（bit4 有設、距離 > 8、朝向與方位不同）**在現有收據裡一筆都沒有**。

## 對 remake 的影響（還沒改）

`internal/rules/fleetmove.go` 的 `AdvanceFleet` 只有 `1C03:0185` 那一支，而且抵達那一段不同：

1. **沒有 bit4**：下命令時不算門檻，短程移動也會先轉身再走，隊形（依 `+0x4A` 旋轉的
   41 個槽，`docs/re/126`）因此跟著轉；原版平移時整段路隊形不轉。
2. **到了之後不轉向 `+0x4C`**：原版叫 `1C03:0524` 逐步轉（可能跨回合、要扣 8.0）；
   `AdvanceFleet` 跳過轉向，改由 `internal/game/battle.go` 在 `Arrived` 時直接
   `f.Facing = f.TargetFacing`（`docs/spec/027` 已列為已知差異）。
3. **到了之後每叫一次扣 1**：`AdvanceFleet` 在位置等於目的地時仍然走「前進」那一段，
   `Distance16` 回 0 被當成 1 扣掉，一直扣到不足 8 為止；原版到了就回，
   `ft03` 那個 `0x00CCD678` 就是證據。拿槽 30 的起點直接跑 `RunFleetTurn`
   （一次性的量測，沒有留成測試）：第一次呼叫之後額度正好是 `0xCCD678`、位置到了，
   接著**再繞 12,899,962 次**才停，額度剩 `0x7FFFF`、朝向停在方位 179（原版 170），
   單這一支就花 0.87 秒。
