# RE 34 — 未安定度：四支子函式讀出來了（尚未實測）

日期：2026-09-07
執行器：dosgolem-logh3 `8c8af90`
來源：執行期記憶體傾印 `27C00` 起 4 KB，手工解碼
狀態：**從程式讀出來的，還沒有一個實測點**。不要當成規則實作。

`docs/re/33` 在 `2703:0DA1` 看到未安定度的骨架：

```
擁有者 == 2（無主） → 未安定度 = 100，結束
base = f1 − f2 − f3 + f4
星域記錄 +0x13 的 bit 2 → base −= 30
base < 0 → base = 0
未安定度 = base × 統治者提督的 +0x0E / 100
未安定度 > 200 → 200
```

四支子函式的位址是 `2703:0EF9`、`0FD7`、`100A`、`109D`。以下是它們的機器碼
解出來的樣子。**每一條都還沒有實測值撐著**——寫在這裡是為了下一輪
有地方接手，不是結論。

## f2（被減）：`2703:0FD7` — 民心

```
les bx,[bp+08]                ; 星域記錄
cmp byte es:[bx+12],0         ; 擁有者是帝國？
jnz alliance
  mov al,es:[bx+7C]           ; 直接取 +0x7C
  jmp done
alliance:
  mov ax,200
  sub ax,es:[bx+7C]           ; 200 − +0x7C
done:
  idiv 10
```

```
f2 = (擁有者 == 帝國 ? R[+0x7C] : 200 − R[+0x7C]) / 10
```

`+0x7C` 是未安定度（`+0x7D`）前面那一格，值域看起來是 0–200，
高的偏帝國、低的偏同盟——像是「民心」。**這一格之前沒被認出來過。**

## f1（基底）：`2703:0EF9` — 稅率壓成長

```
mov al,[bx+8FD4]              ; ds:8FD4[擁有者]
mov al,[bx+8FF8]              ; ds:8FF8[擁有者] → idx
shl idx,2                     ; ×4
mov ax,[idx+1480] / mov bx,[idx+147E]   ; 一組 32 位元的難度參數
mov ax,es:[bx+1E]             ; 星域的成長率
or ax,ax / jle ...            ; 成長率 <= 0 → 走另一條
  mov al,es:[bx+27]           ; 上個月的稅率
  imul 100
  idiv 成長率                 ; 稅率 × 100 / 成長率
```

方向講得通：**稅收得重、又長不快，就不安定**。`ds:8FD4`／`ds:8FF8` 是
兩張以陣營索引的表（難度或劇本參數），`ds:147E` 起是一組 32 位元的值；
夾限那一段落在傾印範圍外，還沒解。

## f3（被減）：`2703:100A` — 鄰居

```
call far 2B99:03D9            ; 取這個星域的鄰居清單（傳 +0x11、+0x12）
對每一個鄰居 j：
    鄰居記錄 = ds:A79C + j×126
    鄰居擁有者 == 自己 → 跳過
    鄰居擁有者 == 2（無主） → di += 3
    否則（敵方）           → di += 5
```

星域表的位址與長度（`ds:A79C`、126）都對得上（`docs/internals/22`），
鄰居清單那一支應該就是 `docs/internals/26` 那張相鄰表的讀取器。

它在呼叫端是**被減掉**的——鄰居越敵對，未安定度反而越低。
方向反直覺，所以更需要實測才能寫進規則。

## f4（被加）：`2703:109D` — 星域裡不是自己的行星

```
call far 2AF5:0036            ; 用星域的 +0x11 取一份清單 → ds:CFF8（指標）、ds:CFFC（筆數）
對每一筆（每筆 82 bytes ＝ 行星記錄長度）：
    該筆的擁有者 != 0 → 計數 +1
call far 2AF5:00B6            ; 收尾（釋放？）
回 計數 × 10
```

一筆 82 bytes 就是行星記錄，所以這是「這個星域裡有幾顆行星不屬於某一方」，
每顆加 10。方向也講得通：自己的星域裡卡著別人的行星就不安定。
