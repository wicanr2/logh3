# RE 34 — 未安定度：四支子函式讀出來了（尚未實測）

日期：2026-09-07
執行器：dosgolem-logh3 `8c8af90`
來源：執行期記憶體傾印 `27C00` 起 4 KB，手工解碼
狀態：**從程式讀出來的，還沒有一個實測點**。不要當成規則實作。

`docs/re/33` 在 `2703:0DA1` 看到未安定度的骨架：

```
擁有者 == 2（無主） → 未安定度 = 100，結束
base = f1 − f2 − f3 + f4
星域記錄 +0x13 的 bit 2 → base −= 30
base < 0 → base = 0
未安定度 = base × 統治者提督的 +0x0E / 100
未安定度 > 200 → 200
```

四支子函式的位址是 `2703:0EF9`、`0FD7`、`100A`、`109D`。以下是它們的機器碼
解出來的樣子。**每一條都還沒有實測值撐著**——寫在這裡是為了下一輪
有地方接手，不是結論。

## f2（被減）：`2703:0FD7` — 民心

```
les bx,[bp+08]                ; 星域記錄
cmp byte es:[bx+12],0         ; 擁有者是帝國？
jnz alliance
  mov al,es:[bx+7C]           ; 直接取 +0x7C
  jmp done
alliance:
  mov ax,200
  sub ax,es:[bx+7C]           ; 200 − +0x7C
done:
  idiv 10
```

```
f2 = (擁有者 == 帝國 ? R[+0x7C] : 200 − R[+0x7C]) / 10
```

`+0x7C` 是未安定度（`+0x7D`）前面那一格，值域看起來是 0–200，
高的偏帝國、低的偏同盟——像是「民心」。**這一格之前沒被認出來過。**

## f1（基底）：`2703:0EF9` — 稅率壓成長

```
mov al,[bx+8FD4]              ; ds:8FD4[擁有者]
mov al,[bx+8FF8]              ; ds:8FF8[擁有者] → idx
shl idx,2                     ; ×4
mov ax,[idx+1480] / mov bx,[idx+147E]   ; 一組 32 位元的難度參數
mov ax,es:[bx+1E]             ; 星域的成長率
or ax,ax / jle ...            ; 成長率 <= 0 → 走另一條
  mov al,es:[bx+27]           ; 上個月的稅率
  imul 100
  idiv 成長率                 ; 稅率 × 100 / 成長率
```

方向講得通：**稅收得重、又長不快，就不安定**。`ds:8FD4`／`ds:8FF8` 是
兩張以陣營索引的表（難度或劇本參數），`ds:147E` 起是一組 32 位元的值；
夾限那一段落在傾印範圍外，還沒解。

## f3（被減）：`2703:100A` — 鄰居

```
call far 2B99:03D9            ; 取這個星域的鄰居清單（傳 +0x11、+0x12）
對每一個鄰居 j：
    鄰居記錄 = ds:A79C + j×126
    鄰居擁有者 == 自己 → 跳過
    鄰居擁有者 == 2（無主） → di += 3
    否則（敵方）           → di += 5
```

星域表的位址與長度（`ds:A79C`、126）都對得上（`docs/internals/22`），
鄰居清單那一支應該就是 `docs/internals/26` 那張相鄰表的讀取器。

它在呼叫端是**被減掉**的——鄰居越敵對，未安定度反而越低。
方向反直覺，所以更需要實測才能寫進規則。

## f4（被加）：`2703:109D` — 星域裡不是自己的行星

```
call far 2AF5:0036            ; 用星域的 +0x11 取一份清單 → ds:CFF8（指標）、ds:CFFC（筆數）
對每一筆（每筆 82 bytes ＝ 行星記錄長度）：
    該筆的擁有者 != 0 → 計數 +1
call far 2AF5:00B6            ; 收尾（釋放？）
回 計數 × 10
```

一筆 82 bytes 就是行星記錄，所以這是「這個星域裡有幾顆行星不屬於某一方」，
每顆加 10。方向也講得通：自己的星域裡卡著別人的行星就不安定。

## 下一步

要把這條寫成規則，缺的是實測：拿幾個已知未安定度的星域（`docs/re/24`
量到六個帝國星域：36／38／27／32／44／50）代進去對。缺的輸入是

前兩個可以從記憶體倒，第三個在 `ADMIRAL.DT*` 裡。

## 把輸入倒出來對了一次：**模型不成立**

倒整個資料段（`lin:54B30` 起 48 KB，收據在
`workplace/explore/growth/ds-796-01.bin`），796 年 1 月的實際輸入：

| 位址 | 內容 |
|---|---|
| `ds:8F4F` | `16 60 00 24` ＝ 統治者的提督編號：帝國 16、同盟 60 |
| 提督 16／60 的 `+0x0E` | 118／119 |
| `ds:8FD4` | `02 02 14 0A` |
| `ds:8FF8` | `02 02 A6 DB` |
| `ds:147E` 起 | `32 00 00 00  4B 00 00 00  64 00 00 00  96 00 00 00  C8 00 00 00`（50／75／100／150／200）|

星域記錄的 `+0x7C`（f2 用的那一格）：**帝國一律 0、同盟一律 200、無主 100**。
所以 796/1 的 f2 對兩邊都是 0，這一項在開局完全不作用。
`+0x13` 只出現 `00` 與 `08`——程式測的是 bit 2（`test ...,4`），
所以那個 −30 在開局也不會發生。

代進去對不上：

| | 帝國 10 個星域 | 同盟 12 個星域 |
|---|---|---|
| f1 ＝ `+0x27 × 100 / +0x1E` | 70–71，幾乎是常數 | 74–76，幾乎是常數 |
| 反推的 base ＝ 未安定度 × 100 / 統治者能力 | 23–43 | 21–41 |
| f3（鄰居：敵 +5、無主 +3）| 帝國多半是 0 | 10–18 |
| f4（非帝國行星 × 10）| 全 0 | 20–50 |

`base ＝ f1 − f2 − f3 + f4` 代不進去：帝國十個星域的 f1、f2、f3、f4
幾乎都一樣，base 卻從 23 跑到 43。**所以上面那個讀法至少有一處是錯的。**

最可疑的三個地方：

1. f1 的夾限那一段（`cmp ax,0x90…`）落在傾印範圍外，還沒看到；
2. f3 呼叫的 `2B99:03D9` 到底回什麼還沒驗，`+0x11`／`+0x12` 當參數的用法是猜的；
3. f4 的清單由 `2AF5:0036` 取得，一筆 82 bytes 看起來是行星記錄，
   但比較的位移是 `+0x12`（行星的擁有者在 `+0x11`），差一格。

**在這三個弄清楚之前，未安定度不會進 `internal/rules`。**
