# 243 — 誰填距離表：`2B99:01B1` 是 Floyd–Warshall，`k` 在初始矩陣裡

`docs/re/241` 把兩張 32×32 的距離矩陣倒出來，形狀是 `1024 × k + 小成本`，
但沒解出 `k`；`docs/re/242` 消去了十個「路上有幾格不是自己的」候選，
最好的只有 743／1024，並指出「兩個可能都要先找到誰填這張表」。

找到了。填表的是兩支函式，`k` 是它們**加出來的**，不是路徑的性質。

## 怎麼找到寫入點

分頁框會換頁，線性位址上的監看抓到的不一定是這張表——所以不從記憶體找，
從**資料段位移**找。掃 `ds:D062`／`ds:D066`／`ds:D06A`／`ds:D06E` 這四個
far ptr 的所有存取點，全部落在同一個節區：

```
== D062 4:  2B9A6 (89 1e 存)  2BA1E (8b 1e 讀)  2BB1C (ff 36 推)  2BC5D (c4 3e les)
== D066 4:  2B9B6            2BA27            2BB34            2BC7D
== D06A 4:  2B9C6            2BB14            2BCAF            2BD8C
== D06E 4:  2B9D6            2BB2C            2BCB8            2BD95
```

節區基底 `2B99:0000` ＝ 線性 `0x2B990`。

## 配置：`2B99:0003`（`0x2B993`）

四張表擠在同一個 EMS 分頁裡，段取自 `ds:937A`，位移是寫死的：

```
2B993  push bp / sub sp,4 / mov bp,sp
       mov  bx, [937A]              ; 分頁框段
       mov  [D064], ax  [D062], 0     ; 帝國距離表   +0x0000
       or   bh, 08h  → [D068]/[D066] ; 同盟距離表   +0x0800
       or   bh, 10h  → [D06C]/[D06A] ; 帝國中點矩陣 +0x1000
       or   bh, 14h  → [D070]/[D06E] ; 同盟中點矩陣 +0x1400
       call far 3BAA:0062 (0, 6)      ; 映分頁
       call far 2B99:0068             ; 建初始矩陣（兩個陣營各一次）
       call far 2B99:0180             ; Floyd–Warshall（兩個陣營各一次）
```

版面與 `docs/re/241` 量到的 `E0000`／`E0800`／`E1000`／`E1400` 對得起來：
距離表 32×32 word ＝ 2 KB，中點矩陣 32×32 byte ＝ 1 KB。

## 初始矩陣：`2B99:007D`（`0x2BA0D`），`k` 就在這裡

`2B99:0068` 只是拿 0 與 1 各呼叫它一次。它的本體是一個 32×32 的雙重迴圈，
讀 **`ds:533A` 的 32×32 位元組邊權表**：

```
2BA76  cmp byte es:[533A + i*32 + j], 0FFh
2BA7A  jnz  2BA96
2BA8F    mov word es:[距離表 + i*64 + j*2], 7FFFh   ; 不相鄰
2BA94    jmp  下一格
2BA96  mov  cl, es:[533A + i*32 + j]                ; w ＝ 邊權
2BACF  mov  es:[距離表 + i*64 + j*2], cx
2BAD5  les  bx, [星域表 i] / mov al, es:[bx+12h]    ; 擁有者(i)
2BADC  cmp  al, [bp+20h]        ; 參數：陣營
2BADF  jnz  2BAED                                    ; 不是自己的 → 加
2BAE1  les  bx, [星域表 j] / mov al, es:[bx+12h]    ; 擁有者(j)
2BAE8  cmp  al, [bp+20h]
2BAEB  jz   下一格                                   ; 兩端都是自己的 → 不加
2BAF0  add  word es:[di], 0400h
```

也就是

```
邊權 == 0FFh                                        → 0x7FFF（不相鄰）
否則 w ＝ 邊權；擁有者(i) != 陣營 或 擁有者(j) != 陣營 → w += 0x400
```

**`0x400` ＝ 1024，就是 `docs/re/241` 看到的那個 `k` 的單位。** 它加在
**邊**上，不是格上——這是 `docs/re/242` 十個候選全部落空的原因：那些候選
都在數格子。星域表是 `ds:A79C`、每筆 126 位元組、擁有者在 `+0x12`
（`docs/internals/22`）。

## Floyd–Warshall：`2B99:01B1`（`0x2BB41`）

呼叫端 `2B99:0180`（`0x2BB10`）把 (距離表, 中點矩陣) 兩組 far ptr 各推一次：

```
2BB10  push [D06C]/[D06A]  push [D064]/[D062]  call far 2B99:01B1   ; 帝國
2BB26  push [D070]/[D06E]  push [D068]/[D066]  call far 2B99:01B1   ; 同盟
```

本體是教科書寫法，中點矩陣是它的**見證矩陣**：

```
2BB57  call far 3C9C:000A(中點矩陣, 0FFh, 400h)   ; 整張填 0FFh
2BB5E  for i in 0..31: 距離表[i][i] = 0
2BB87  for k in 0..31:
2BB95    for i in 0..31:
2BBA0      for j in 0..31:
2BBC7        dx = d[i][k] + d[k][j]
2BBE8        cmp dx, d[i][j]
2BBEA        jnb 跳過                              ; **無號**比較
2BBEC        d[i][j]   = dx
2BC05        mid[i][j] = k
```

比較用 `jnb`（無號）這件事讓 `0x7FFF` 當無限大是安全的：兩個相加溢成
`0xFFFE`，無號看仍然大於任何真值，不會誤鬆弛。

## 驗證：兩張表逐格重現

`tools/scripts/distance_build.py` 照上面重跑一次，跟 `docs/re/241` 那份
8 KB 頁框傾印對：

```
帝國：距離 1024/1024、中點 1024/1024 與傾印相同
同盟：距離 1024/1024、中點 1024/1024 與傾印相同
  值 ≠ 1024×k ＋ 邊權和 的格數：0
```

那一刻的星域擁有者是從表本身反解的：相鄰對走兩段路最少 20、任何單邊最多
18，所以 `距離[i][j] == 邊權[i][j]` 就代表那條直接邊沒被罰、兩端都是自己的。
23 格這樣直接定出來，其餘用約束傳播 ＋ 窮舉，再拿完整重建驗證。解是

```
00010000001100211111111001112111
```

（14 費沙與 28 是 `2` ＝ 無主，13 伊謝爾倫在帝國手上，與那一輪的局面相符。）

## `k` 的定義

```
距離[i][j] = 1024 × k + Σ 沿途邊權
k = 路徑上「兩端不全屬於該陣營」的**邊**數
```

1024 格全部成立，兩個陣營都是。

## 順帶解掉的三件事

**`docs/internals/26` 的「原版的路不一定是最短路」有解了。** 中點矩陣不是
步數最短路的見證，是**成本**最短路的見證；成本裡有那個 1024，所以路徑會
繞遠去走自己的地盤。帝國那張最遠 10 步、同盟 12 步，而廣度優先只要 9 步
——差的就是繞路避開別人領土。

**`docs/re/241` 記的 `"symmetric": false` 有解了。** 罰則本身是對稱的
（條件兩端對稱），邊權表也幾乎對稱，只有**一個位元組**不是：

```
ds:533A[2][6] = 0Fh (15)      ds:533A[6][2] = 0Dh (13)
```

90 條邊裡就這一條。把 `2→6` 改成 13 之後重跑，帝國那 64 格、同盟那 122 格
不對稱**全部歸零**——186 格不對稱全部出自這一個位元組。旁邊的
`ds:533A[6][3]` 也是 `0Dh`，看起來是原始資料的手誤，遊戲照著跑而已。

**`docs/internals/data/star-graph.json` 的相鄰表核對過了。** 它當初是從
「中點矩陣 == 255」推的，而 255 的真正語意是「沒有任何 k 改進過它」——
被罰的直接邊有可能輸給沒被罰的繞路，那樣就會漏一條邊。拿 `ds:533A` 逐格
比對，**32 列全部相同**，所以那份推導在這個局面下沒有踩到。

## 一條方法

**分頁的記憶體找不到寫入點時，改找資料段位移。** 監看的是線性位址，而分頁框
底下的頁會換；但存放 far ptr 的那幾個資料段位移不會動，掃它們的存取點就把
四張表的配置、填寫與查詢三處一次找齊。`docs/re/241` 卡在「頁框會換頁所以
監看抓到的不一定是這張表」——那是把工具當成唯一入口了。
