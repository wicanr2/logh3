# 174 — `2E54:0344` 的五個階段各做什麼

`docs/re/171` 只列出五個呼叫。這一輪把四個的骨架讀出來，
`ds:D50E`／`ds:D58E` **會被重算兩次**這件事也浮出來了。

```
2E54:0344()
    2E54:035E()      ; 一、守首都
    2E54:0EC2()      ; 二、排序後只處理第一名
    2E54:0725()      ; 三、按缺口補（docs/re/172）
    2E54:08D3()      ; 四、重算之後依優先度派兵
    2E54:119E()      ; 五、排序後只處理第一名
```

## 一、`2E54:035E` ＝ 守首都

```
首都 = 3982:0329(ds:8F1D)
若 ds:D54E[首都] == 0：什麼都不做          ; 首都沒有敵方兵力圖
n = min(ds:D54E[首都] ÷ 3 + 1, 16)
n -= 2E54:03C3(n)                          ; 先從現有的湊（docs/re/166）
若 n > 0：2E54:0513(n)                     ; 還缺就再叫一支（未讀）
```

**首都的防禦是獨立於整個配額系統的第一件事**，而且要幾支直接由
敵方兵力圖 `ds:D54E` 決定：威脅 ÷ 3 ＋ 1，上限 16（＝一個陣營的艦隊槽數）。

## 四、`2E54:08D3` 會**重算** `ds:D58E`

```
2E54:08D3()
    2D54:0000()      ; 重算 ds:D50E
    2E54:08E3()      ; 重算 ds:D58E
    2E54:0978()      ; 依 ds:D50E 降冪派兵（docs/re/170）
```

`2E54:08E3` 與 `2E54:0730`（`docs/re/172`）長得幾乎一樣，三處不同：

| | `2E54:0730`（階段三）| `2E54:08E3`（階段四）|
|---|---|---|
| 哪些格子算 | 擁有者 == `ds:8F1D` | `ds:D50E[i] != 0` |
| 除數 | `÷ 4` | `÷ 5` |
| 加成 | 前線加成 0 或 1 | **`RNG() % 4`（0–3）** |

所以同一回合裡「要派幾支」被算兩次，第二次帶亂數。
**這是原版 AI 少數幾個真的擲骰的地方之一**——`docs/re/167` 的伊謝爾倫
銅板、`docs/re/169` 的四分之一派兩支，加上這裡。

## 二、五、同一個形狀

```
2E54:0EC2():                          2E54:119E():
    n = 2E54:0F09(&清單)                  2D54:0000()
    若 n == 0：結束                       清單 = [0 … 31]
    qsort(清單, n, 1, 2E54:1001)          qsort(清單, 32, 1, 2E54:11F2)
    2E54:1108(清單[0])                    2E54:1243(清單[0])
```

兩支都是**排序之後只處理第一名**。這款遊戲的 AI 反覆出現這個形狀
（`2E54:0978` 也是排序，只是它整串走完）。

## `2D54:0000` ＝ 攻擊目標的優先度（讀到一半）

它把 `ds:D50E` 從「敵方鄰居個數」（`docs/re/171`）**整個換掉**：

```
3C9C:000A(ds:D50E, 0, 64)
我方首都 = (ds:8F1D == 0) ? 0 : 31；敵方首都 = 另一個
2B99:0392(我方首都, ds:8F1D, &連通[32])
…（中段未讀：走一條 0FFh 結尾的清單，對命中的格子 ds:D50E += 1）…
對 i = 0 … 31：
    若 連通[i] == 0：跳過
    若 星域[i][+0x12] != 3982:0250(ds:8F1D) 且 i != 敵方首都：跳過
    ds:D50E[i]++
    ds:D50E[i] = ds:D50E[i] × (2048 ÷ (ds:D54E[i] + 1))
```

**目標分 ＝ 累積分 × 2048 ÷ (敵方兵力 + 1)**——同樣的價值，
守得越薄分數越高。敵方首都無條件納入候選。
