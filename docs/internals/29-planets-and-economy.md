# `PLADAT.DAT` 與經濟力

資料：[`data/pladat.json`](data/pladat.json)
證據等級：檔頭、`+0x11`、`+0x14`／`+0x16`、`+0x1A` 與「星域經濟力 ＝ 行星加總」
**confirmed**（`docs/re/17`、[`docs/re/30`](../re/30-region-economy-from-planets.md)）；
成長算式 **未解**。

## 版面

6,706 bytes ＝ **64 bytes 檔頭 ＋ 81 筆 × 82 bytes**。

檔頭是 32 個 word，第 k 個是第 k 個星域有幾顆行星：

```
4 3 2 3 1 2 3 3 4 3 2 2 1 1 1 2 3 2 3 3 3 4 2 2 1 3 3 2 3 2 3 5   （合計 81）
```

行星按星域順序排，所以第 k 個星域的行星是「前 k 個數量加起來」開始的那一段。

**`ds:CFF8`／`ds:CFFA` 那個遠指標不是整張表，是「目前星域的行星切片」**
（`ds:CFFC` 是那個星域有幾顆）：戰略地圖上選著星域 0 時是 `5313:0002`／4，
S3 戰場（星域 26）時是 `5313:1430`／3，正好是上面檔頭的第 0 與第 26 項。
跟著它走的迴圈（要塞砲的 `181B:0385`／`2264:000A`、打行星的 `20B4:0059`）
**只掃目前那個星域**，而艦隊記錄 `+0x5A` 存的是**切片內的序號**
（[`docs/re/150`](../re/150-planet-capture-receipt.md)）。

執行期的行星表在段 `5313` 的 offset 2 起（線性 `53132`），**沒有檔頭**，
81 筆 82 bytes 排在一起（位址已用倒出來的表與 `PLADAT.DAT` 逐筆對名稱
驗過，`docs/re/57`）。存檔的 `PLANET.DT?` 與那張表逐位元組相同
（[`docs/internals/30`](30-save-format.md)），所以中局的行星擁有者與
經濟力直接讀存檔就有——`PLADAT.DAT` 只是開局那一份。

## 星域的經濟力是行星加出來的

星域記錄的 `+0x1A` 不是從 `STELLAR.DT*` 讀來的，是**現算的**：

```
星域經濟力 ＝ Σ 該星域每顆行星的 +0x1A
```

載入時算一次（`2703:00F8`），之後每個月底再算一次（`2703:0CA8`）。
`STELLAR.DT*` 檔案裡的 `+0x1A` 載入當下就被蓋掉，從來沒被用過。

星域 0（奧丁、布倫希爾、亞爾斯達、梅薩克）四顆行星的初值
52000 / 9800 / 12000 / 7500 相加 ＝ 81300，就是開局的星域經濟力。

## 月底：成長與收稅都是**逐行星**做的

```
對每一顆行星：
    經濟力 += 經濟力 × 成長率(經濟力, 防衛力) / 1000
    稅      = 經濟力 × 該星域稅率 / 1000        （捨去）
    經濟力 -= 稅
    總稅收 += 稅
星域經濟力 = Σ 該星域行星的經濟力
```

**兩個稅不是同一個數**（`docs/re/35`）：從行星身上扣掉的是逐顆捨去的和
（星域 0 是 2718），進國庫的是拿星域總和算一次捨去（2720）：

```
進國庫的稅 = (Σ 成長後、扣稅前的行星經濟力) × 星域稅率 / 1000   （捨去）
```

十個帝國星域結算後的經濟力與進國庫的錢都逐一相符
（`internal/rules.TestMonthEndEmpireTotal`，合計 10741）。

星域記錄的成長率 `+0x1E` 是**算出來的結果**，不是輸入：它等於
`Σ 成長量 × 1000 / Σ 經濟力`（星域 0：3720×1000/81300 ＝ 45.7 → 45，
畫面上的 4.5%）。

## 成長率階梯表

資料：[`data/growth-table.json`](data/growth-table.json)（`ds:4A68`，
一列 6 bytes ＝ 門檻 32 位元 ＋ 成長率 16 位元，32 列）。

查法照原版那支迴圈：**找到第一列 i 使得第 i+1 列的門檻 >= 經濟力**，
取第 i 列的成長率。經濟力越大長得越慢：

```
0→90‰  1000→82  …  10000→52  …  50000→41  …  100000→30  120000→26
180000→18  200000→0
```

行星防衛力（記錄 `+0x16`）低於 3000 時成長率再 ×3/2——這一條是從
程式讀出來的，還沒實測到。

五個實測點逐一相符（`docs/re/33`）：52000→41、9800→54、12000→52、
7500→58、16000→50。
