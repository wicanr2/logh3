# 文字視窗、儲存格格式與中文編碼

這是中文版最核心的一塊：整個中文介面是靠一套「文字視窗 ＋ 儲存格緩衝區」
畫出來的，而不是直接把字形塗進畫面。

## 1. 視窗記錄的版面（confirmed）

視窗記錄是一個結構（開機路徑上實測是放在堆疊上的區域變數）。目前確認的
欄位：

| 位移 | 型態 | 內容 |
|---|---|---|
| `+0x01` | byte | 清除時填入的屬性 |
| `+0x0B` | byte | 每列的儲存格數（實測 3）|
| `+0x0C` | byte | 列數（實測 12）|
| `+0x0E` | word | 儲存格緩衝區的**位移** |
| `+0x10` | word | 儲存格緩衝區的**段** |
| `+0x12` / `+0x14` | word | 串列前向指標：位移／段 |
| `+0x16` / `+0x18` | word | 串列後向指標：位移／段 |
| `+0x1D` | byte | 反白狀態的屬性 |
| `+0x1F` | byte | 正常狀態的屬性 |

`+0x0B` × `+0x0C` 是緩衝區的格數，也是建構子拿去算配置大小的兩個數
（`w × h × 4` bytes）。主選單實測 3 × 12 ＝ 36 格，而畫面上只用到 4 列
——**哪一個是欄、哪一個是列，以及為什麼配置 12 列，尚未確認（假說：
緩衝區按上限配置，實際用幾列由內容決定）**。

## 2. 儲存格格式（confirmed）

每格 **4 bytes**：

| 位移 | 內容 |
|---|---|
| `+0` | 字碼 word，值 ＝ `第一個 byte << 8 \| 第二個 byte` |
| `+2` | 屬性 |
| `+3` | 0 |

清除時整格填 `{word 0x2020, 記錄[+0x01], 0}`——`0x2020` 是兩個 ASCII
空格。

## 3. 清除迴圈（confirmed）

**位元組簽章**：`26 8A 47 0B 30 E4 26 8A 4F 0C 30 ED F7 E1`

```
base = rec[+0x0E] / rec[+0x10]        ; far 指標
for i in 0 .. rec[+0x0B] * rec[+0x0C] - 1:
    word[base + 4i]     = 0x2020
    byte[base + 4i + 2] = rec[+0x01]
    byte[base + 4i + 3] = 0
```

## 4. 寫字元（confirmed）

**位元組簽章**：`8A E0 32 C0 26 8A 4C 01 30 ED 03 C1`

```
al = src[0]
if al == 0: 結束
ax = (src[0] << 8) + src[1]           ; 兩個 byte 併成一個字碼
word[cell] = ax
attr = 旗標 ? rec[+0x1D] : rec[+0x1F] ; 反白／正常
byte[cell + 2] = attr
```

**字碼是「高位在前」的兩 byte 組合**，也就是原始 Big5 位元組序直接併成
word。這一點在讀記憶體傾印時很重要：word 的數值看起來像是位元組顛倒的，
但它其實就是 `B5 lead << 8 | trail`。

## 5. 編碼：Big5 ＋ ETen 假名擴充區（confirmed）

介面與劇情文字是 **Big5**。主選單四個項目在記憶體裡的字碼：

| 字碼 | 字 |
|---|---|
| `A650` | 同 |
| `A8FA` | 取 |
| `ABD7` | 度 |
| `B0EA` | 國 |
| `B669` | 進 |
| `B7F9` | 盟 |
| `B9EF` | 對 |
| `BED4` | 戰 |

（畫面上是「帝　國／同　盟／對　戰／取進度」。）

`ENDING.EXE` 的版權行還用到 **`0xC7xx` 區的日文假名**：

```
(C)1988  田中芳樹．德間書局．德間ジャパン．キティフィルム
```

那幾個字的原始位元組是 `C7 B4 C7 DF C7 CD C7 EF`（ジャパン）與
`C7 A9 C7 C2 C7 7D C7 D1 C7 7D C7 E7 C7 DC`（キティフィルム）。
**標準 Big5 表把這一區對到別的符號，要用 ETen／HKSCS 的擴充表才解得對**
（Python 的 `big5` 與 `cp950` 都會解錯，`big5hkscs` 才對）。處理這款遊戲
的文字一律用 ETen 擴充表。

另外，`Music Composition` 那一行是 `ミラㄧジュ`——長音記號 `ー` 被
**注音符號「ㄧ」**代用（強證據：字形相近，中文字型裡沒有片假名長音符）。
這是中文化當時的取捨痕跡，重製時要照原樣呈現還是修正，是設計決策。

## 6. 字型

主選單的中文字形實際畫得出來（`docs/re/06`），所以字型資料在開機路徑上
已經在記憶體裡。但**字型檔是哪一個、格式為何，尚未確認（未知）**。
字型是 **`GRAPH.IMG`**（confirmed）：半形 8×15、全形 16×15，內容與倚天
中文系統的 `ascfont.15`／`stdfont.15` 逐位元組相同。格式、索引公式與
存取方式見 [`06-font-graph-img.md`](06-font-graph-img.md)。

`BU16IBM.RGB` 不是字型，它是 48 bytes 的 16 色調色盤（confirmed）。
`IBM16.350`（1,764,911 bytes，整包最大）用途仍**未確認**。

## 7. 為什麼這一節值得單獨記

`docs/re/03` 與 `docs/re/04` 把這套程式讀成「模組管理器把中斷服務表寫進
IVT」，追了兩輪。實際上它是文字視窗在往一個 null 緩衝區寫選單文字，而
那八個看起來像段位址的值，逐位元組就是中文字。

**判準**：看到一批 4 bytes 一組、其中兩 bytes 落在 `A1`–`F9` × `40`–`FE`
範圍的資料，先當成 Big5 解一次再說。
