# `MAP00.CMP`–`MAP31.CMP` — 每個星域的戰場地圖

證據等級：**編碼 confirmed**（32 張全部展開成同一個格數 13,056，
一張都不例外）；**鋪出來的畫面 strong**（與收據 `s3ai6` 的戰場
比對，10,080 條圖塊列裡有 9,668 條逐位元組相同）。
工具：`tools/py.sh tools/scripts/cmp_map.py /orig/MAP26.CMP s3ai6 BLOCK_2.BLK`。

## 一個星域一張

檔名的數字就是星域編號（0–31，與 `STELLAR.DT?` 同一套）。跑進達希利
（26）的那一場開的就是 `MAP26.CMP`（`docs/re/81`）。

大小 3,364–9,118 bytes 不等——壓縮過。

## 編碼

```
byte >= 0x80  →  一格，圖塊編號 ＝ byte & 0x7F
byte <  0x80  →  再吃一個 byte：(圖塊, 次數)，那個圖塊重複「次數」格
```

就這兩條。**圖塊集正好 128 塊**（`docs/internals/35`），所以七個位元剛好
放得下一個編號，最高位拿來當「這是單格還是重複」的旗標。

重複那一條的次數可以到 255（`00 FF` ＝ 圖塊 0 重複 255 格），
所以第二個 byte 不一定小於 `0x80`——**照「兩個 byte 都要小於 0x80」去解
會漏掉一半的檔**（32 張裡有 16 張少算）。

## 展開之後是 128 欄 × 102 列

32 張全部是 **13,056 格 ＝ 128 × 102**。圖塊 16×20，所以整張戰場是
**2,048 × 2,040**——與艦隊記錄裡量到的戰場座標對得上
（`docs/internals/34`：帝國 (416,280)、同盟 (1536,1840)）。

## 畫面上看到的是其中 28 × 18 格

戰場視窗 (16,60)–(463,419) ＝ 28 欄 × 18 列（`docs/internals/34`）。
拿 `MAP26` 鋪出來、用 `BLOCK_2.BLK` 的圖塊，與 `s3ai6` 的畫面逐列比，
最合的視野起點是**格 (66,30)**，也就是座標 (1056,600)：

| 圖塊集 | 不合的圖塊列 |
|---|---:|
| `BLOCK_2.BLK` | 412 ／ 10,080 |
| `BLOCK_3.BLK` | 489 ／ 10,080 |

96% 逐位元組相同，`BLOCK_2` 略好。剩下那 4% 還沒查——可能是畫在地形
上面的東西（虛線格線、行星的動畫幀），也可能兩套圖塊各用一部分。

## 還沒解

- 剩下 4% 的差異。
- 視野起點是誰決定的（跟著哪一支艦隊、還是固定在戰場中心）。
- 40 種圖塊各是什麼地形、對戰鬥有沒有影響。
