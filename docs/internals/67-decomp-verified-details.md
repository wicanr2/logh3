## C runtime 函式庫（`3C5B` 到 `3D17`）

函式名稱（memset、strlen 等）是由行為對出來的強推論，不是出處證據。runtime 是 Datalight C 3.10（`docs/re/442`）。

| 函式 | 細節 | 舊文件 |
|---|---|---|
| `3CD9:0047`（malloc） | 從 head（`ds:94E2:94E0`）起步，先檢查 `head.next`，head 本身最後檢查；rover（`ds:94E6`／`94E8`）在 malloc 只寫不讀。大小規則：`(size + 3) & ~1 < 4`（size 為 0 或 `>= 0xFFFD`）直接回 `0:0`，其餘不足 6 的拉到 6 | `docs/internals/03` §5 第 3 步寫「從 rover 開始走環狀串列」、「大小下限 4」 |
| `3CD9:01FC`（free） | 真正拿 rover 當起點提示的是 free：rover 不小於區塊時改從 `54B3:94E0` 開始 | 同上 |
| `3C6A:000D`（qsort） | 梳狀排序。`gap × 10` 只取低 16 位元再除 13，`n >= 6554` 時與未截斷的算法不同。交換常式 `3C6A:011E`（逐字）與 `3C6A:0158`（逐位元組）不在函式台帳內，內建在 C 檔裡，其寫入效果只由整體寫入集合間接證實 | — |
| `3AC4:000D` | 台帳標 `video-dos`，實際是 DOS 記憶體呼叫（`int 21h` `AH = 4Ah`／`48h`，類似 sbrk），並在新區塊 `ES:0` 寫入大小字。目前以 `stubs` 取代 | 台帳分類需改 |
| `3CAB:0009`（getenv） | 環境項若是名稱的前綴（例如項目 `FO` 對名稱 `FOO`），在該項的 NUL 處直接回 `0:0`，不再看後面的項目 | — |
| `3CA8:0002` | 查 `ds:93D7 + c` 的表並取 bit 7；基底狀態下只有 `'0'` 到 `'9'` 的表項有 bit 7，像 isdigit（強推論） | — |
| `3CAF:00BD`、`3CAF:00C9` | 台帳標 size 1、class `runtime`，但映像該處位元組是 `CF`（`iret`），不是 `retf`：中斷處理常式的占位。far call 進去會 pop 旗標字造成堆疊失衡。台帳分類需改 | 台帳 |
| 沒做的 | `3CC9:0005`（`sti`）、`3CC9:0007`（`cli`）只動 IF，探針 `pack:flags` 只比 OF／SF／ZF／CF，沒有可觀測輸出；`3CAF:0006` 是 `jmp 036B:000E`，目標是 hw-dependent 函式；`3D08:0025`、`3D08:003D` 設 `AH` 後跳進 `int 21h` 共用尾巴 | — |

另有 13 個突變是「逾時才算抓到」的弱證據（`3CD9:01FC` 5 個、`3C6A:000D` 5 個、`3CD9:0047` 2 個、`3CAB:0009` 1 個），原因是改比較條件使迴圈不終止。
這四個函式其餘突變都是實際比出差異的，仍滿足「至少三個突變被全部抓到」。

## 溢位區與域外

- `203A:0424`（`docs/internals/66`）：remake 的 `int` 與原版 16 位元運算只在艘數合計 >= 65536 或 艘數合計 × 能力 ÷ 100 >= 65536 時不同，已知差異，類別 remake-owned。
- 上表「達不到的範圍」都是從 asm 推得，沒有逐一確認遊戲資料走不走得到。
