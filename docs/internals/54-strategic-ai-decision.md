# 54：戰略 AI

原版的戰略 AI：什麼時候跑、一個回合做哪些事、每一步的算式與資料表。

證據等級：算式與流程 **confirmed**（反組譯位元組，`docs/re/79`、
`docs/re/162`–`docs/re/189`）；其中敵方兵力圖、攻擊目標分與「要派幾支」
三條由收據 `s3aicomp` 對過（見末節）。

結構化資料在 [`data/strategic-ai.json`](data/strategic-ai.json) 與
[`data/ai-advance-routes.json`](data/ai-advance-routes.json)，
還沒解的項目也列在前者的 `unsolved`；規格是
[`docs/spec/029`](../spec/029-strategic-ai-turn.md)。

## 什麼時候會跑

```
; 0x052C8（在 codeall.bin 的 0x09000–0x3E000 之外）
若 ds:8F23[ds:8F1E] != 1：不呼叫              ; 這個座位不是電腦
call far 2D10:0005

2D10:0005():
    若 ds:8F46 != 0：清 0 並直接回              ; 「跳過這一次」
    2D10:0319(1)
    2D76:0002()      ; 建艦隊
    2D76:0732()
    2E54:000C()
    2E54:0344()
    2D10:0038()
    ds:8F46 = 0
```

座位表：`ds:8F1E` ＝ 現在的座位，`ds:8F23[座位]` ＝ 是不是電腦（1 ＝ 是，
開局選陣營那一頁決定），`ds:8F25[座位]` ＝ 陣營（`ds:8F1D` 從這裡抄）。

一個戰略回合把**兩個座位都跑一遍**（`0x05267`：`ds:8F1E = 0` → 
`04F8:030E()` → `ds:8F1E = 1` → `04F8:030E()`），而 `04F8:030E` 的最後
一步就是「這個座位是電腦就叫 `2D10:0005`」（`docs/re/186`）。
所以電腦座位**每個戰略回合都會跑 AI**。

玩家階段與電腦階段是**兩條分開的座位迴圈**（`docs/re/187`）：
`0x0510F` 對每個座位跑 `04F8:01B9`（只服務 `ds:8F23[座位] == 0` 的玩家），
`0x05267` 對每個座位跑 `04F8:030E`（只服務電腦）。既有收據
`ds:D60E = 0` 是因為第一次「實行」在玩家階段就切進伊謝爾倫的戰鬥畫面，
`0x05267` 那條根本沒跑到；`s3aicomp` 把 `ds:8F23[0]` poke 成 1 之後
座位 0 在玩家階段被跳過，回合才走得到 AI。

## AI 的一回合

`0x2D121`／`0x2D126` 連續呼叫兩支：

```
2E54:000C()      ; 清表 + 2E54:005D + 2E54:1A76 + 2E54:019F
2E54:0344()      ; 2E54:035E → 2E54:0EC2 → 2E54:0725 → 2E54:08D3 → 2E54:119E
```

`2E54:019F` 每一格的優先度由 `2E54:0222` 算：

```
敵方 = 1 − ds:8F1D
分數 = Σ（相鄰且擁有者 == 敵方的星域 n）:
        n[+0x13] bit0 沒設 或 ds:D54E[n] > 4 → 4
        否則                                 → 2
```

**優先度就是敵方鄰居的個數 × 4**（部分鄰居只算 2），內地是 0。

`2E54:02C2(星域, 陣營)` 是同一組條件的反面：有沒有一個屬於該陣營、
`+0x13` bit0 沒設、`ds:D54E` 非 0 的鄰居。

## 回合進入點與星域順序

```
2E54:000C()                       ; 戰略 AI 的一回合
    清 ds:D50E／ds:D5CE／ds:D54E（各 32 word）、ds:D60E = 0
    2E54:005D()                   ; 逐艦隊決定（docs/re/79）
    2E54:1A76()                   ; 未讀
    2E54:019F()                   ; 填 ds:D50E ＝ 每一格的優先度

2E54:08D3()
    2D54:0000()                   ; 另一條也填 ds:D50E 的路（未讀）
    2E54:08E3()                   ; 未讀
    2E54:0978()                   ; 依 ds:D50E 降冪排 32 個星域，
                                  ; ds:D58E[星域] != 0 的才 2E54:0AAB(星域)
```

`2E54:019F` 只給**與首都連通的我方星域**非 0 的優先度：
`2B99:0392(首都, 陣營, &旗標)` 標連通，擁有者是自己才呼叫 `2E54:0222`
算那一格的值。

以星域為索引的表：`ds:D50E`（32 word，優先度）、`ds:D54E`（32 word）、
`ds:D58E`（32 byte，要派幾支）、`ds:D5AE`（32 byte，已指派幾支）、
`ds:D5CE`（32 word，決定留守的支數）、`ds:D60E`（byte，這回合決定了幾支）。`2E54:088F(星域)` 回
`D5AE × 100 ÷ D58E`（`D58E <= D5AE` 回 `0xFF`；首都 0／31 回 0）。

### `2E54:0BEB`（差得多時走的那一支）

`3CD5:000C() % 5 == 0` 走 `2E54:0C27`（**只對 `+0x79 == 6`＝已經到了的
下命令**），其餘四分之五走 `2E54:0C83`（陣列裡每一支都下）。
下命令 ＝ `+0x08 = 1`、`+0x07 = 目標星域`、`+0x79 = 1`。

## 決定：`2E54:16F5(艦隊)`

`2E54:005D` 逐艦隊跑一趟（只處理 `ds:8F1D` 那個陣營），先把 `+0x79` 填
`0xFF`，再依下面的分支改寫；判斷本身交給 `2E54:16F5`（`docs/re/196`）：

```
若 艦隊[+0x08] == 4：+0x79 = 0、ds:D60E++、下一支
若 艦隊[+0x00] bit0 有設：
    （星域[+0x13] & 14h 或 星域[+0x28/29] != 0 的那一段未讀完）
    星域[+0x12] == 我方 → +0x08 = 3、+0x07 = +0x06（原地出擊）
    否則                → 2E54:1955（往首都退一格）
    +0x79 = 0、ds:D60E++
否則：
    若 星域[+0x13] bit2 沒設：**下一支**（+0x79 留 0FFh）★
    2E54:16F5 != 0 → +0x79 = 3、ds:D5CE[星域]++、ds:D60E++
    否則           → 2E54:1955、+0x79 = 0、ds:D60E++
```

★ 那一條就是「**哪些艦隊會留給後面五個階段挑**」的分水嶺：
`2E54:143F` 要求 `+0x79 == 0xFF`（`docs/re/168`）。

`+0x00` bit0 **有設**的那一路（`docs/re/197`）：

```
參 = (ds:8F1D == 0) ? 星域[+0x29] : 星域[+0x28]   ; ＝ 敵方在這一格的艦隊數
星域[+0x13] & 14h 有設、或 參 != 0、或 星域[+0x12] != 我方 → 2E54:1955（退一格）
否則 → +0x08 = 3、+0x07 = +0x06（原地出擊）
```

`+0x28`／`+0x29` 是兩個陣營各自在那一格的艦隊數（`2703:08CE` 對
`+0x28 ＋ 陣營` 遞增，`docs/re/40`、`docs/re/199`），
所以三個條件講的是同一件事——**這一格有戰鬥、有敵人、或不是自己的，
就往首都退一格**。

> **`ds:D60E` 數的是整個回合，不是這一趟。** 它有十一處遞增點：
> `2E54:005D` 四處、`2E54:03C3` 一帶四處、`2E54:0513`（新編）一處、
> `2E54:07D8`（階段三指派）一處各 `inc`，`2E54:1183`（`2E54:1108` 一次派
> 兩支）一處 `add …, 2`；清 0 只在回合開頭（`docs/re/197`、`docs/re/198`）。

| 情況 | 回 1 的條件 |
|---|---|
| 在自己陣營的首都星域（帝國 0、同盟 31）| 無條件 |
| 這一格是自己的 | 我方 × 4 ≥ 敵方，或 艦隊 `+0x3C` ＝ 100（編制滿）|
| 這一格無主（擁有者 2）| 我方 × 2 > 敵方 |
| 這一格是敵方的 | 我方 > 敵方 |

「我方」「敵方」是上面那個戰力總和，成員用
`297B:131C(&清單, 星域, 旗標)` 收（旗標 1 自軍、2 敵軍）。
對方陣營用 `3982:0250(陣營)` 換算。

回 1 → `+0x79 = 3`，同時 `ds:D5CE[星域]++`（`0xD5CE` 在反組譯裡
寫成 `−0x2A32`）與 `ds:D60E++`；
回 0 → 走 `2E54:1955`、`+0x79 = 0`（`docs/re/79`）。

## 戰力：`2E54:1876(星域, 索引清單, 幾支, 陣營)`

```
Σ（清單裡每支能戰的艦隊）Σ（它的每個分隊）
      ds:6032[艦種] × 現有艘數 × 1000 ÷ 滿編艘數
```

- 艦隊 `+0x00` bit0 有設（無法戰鬥）整支跳過。
- 分隊數在艦隊 `+0x0F`，池索引在 `+0x10` 起一組 4 bytes 的第一個 word。
- 艦艇的現有／滿編是 `+0x08`／`+0x0A`，艦種是 `+0x04`。
- 權重表 `ds:6032`：

| 艦種 | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| 權重 | 4 | 3 | 3 | 3 | 2 | 1 | 3 | 0 |

## 沒事做就回防：`2E54:1955(艦隊)`

```
若 這一格是自己的 且 星域[+0x13] bit2 沒設：
    先寫預設 +0x08 = 5（不動）、+0x07 = 0FFh、+0x79 = 3
在相鄰星域（2B99:03D9）裡挑「擁有者 ＝ 自己」而且
    2B99:028F(候選, 3982:0329(陣營), 陣營)（到自己首都幾步）最小的那一格
找到 → +0x08 = 0（會走）、+0x07 = 那一格
找不到 → +0x08 = 5、+0x07 = 0FFh
```

`+0x08`：**0 ＝ 會走、5 ＝ 不動**（`docs/internals/33`）。
**攻勢那一半還沒解**——`+0x07` 被設成敵方星域是哪一支寫的（`docs/re/164`）。

## 兵力圖與指派

`2E54:1A76()`（`2E54:000C` 的第二階段）畫敵方的兵力圖：

```
297B:131C(&清單, 0FFh, 2)                 ; 旗標 2 ＝ 敵軍
對每一支 f：行動 0／1 → 格 = 2B99:0302(f[+0x07], f[+0x06], f[+0x01])
           行動 5    → 格 = f[+0x06]
           其餘      → 跳過
    ds:D54E[格] += f[+0x0F]
```

**`ds:D54E[星域]` ＝ 敵方「下一步會在這一格」的編制槽總數**——移動中的
艦隊算在下一格，所以這是預測，不是現況。

`ds:D5CE[星域]` 在 `2E54:005D` 裡累加：`+0x79` 寫 3 的時候
`ds:D5CE[艦隊所在星域]++`；`ds:D60E` 則是「這回合決定了幾支」。
兩者的單位不同（槽數 vs 支數），`2E54:0730` 直接相減再 `÷ 4`。

星域 `+0x13` **bit2** 是 `2E54:16F5` 的入口條件。`docs/internals/34`
量到進入戰鬥時這個位元組**從 8 變成 12**——也就是 bit2 在該格開打時被
設起來，所以它是「**這一格有戰鬥**」（強推論：兩個獨立觀察一致，
還沒抓到寫入點）。

### 挑格與指派

```
2E54:0842()  → ds:D58E != 0 之中 2E54:088F 滿足率最低的那一格（0FFh ＝ 沒有）
2E54:1B17(艦隊, 行動, 星域):
    艦隊[+0x06] == 星域 → （若 +0x08 != 5）+0x08 = 5、+0x07 = 0FFh
    否則                → +0x08 = 行動、+0x07 = 星域
```

## `ds:D58E`（要派幾支）的算式

`2E54:0725()` ＝ `2E54:0730()`（算）＋ `2E54:07D8()`（指派）。

```
2E54:0730():
    ds:D58E[0..31] = 0
    對每個擁有者 == ds:8F1D 的星域 i：
        前線 = min(ds:D50E[i] ÷ 2, 1)
        ds:D58E[i] = (ds:D5CE[i] < ds:D54E[i]) ? (ds:D54E[i] − ds:D5CE[i]) ÷ 4 : 0
        ds:D58E[i] += 前線
```

**要派幾支 ＝ 缺口 ÷ 4 ＋（是前線就再加一支）。**

`2E54:07D8` 清掉 `ds:D5AE` 之後反覆 `2E54:0842()` 取星域（`0xFF` 結束）、
`2E54:143F(星域, 0)`（**模式 0**）取艦隊、`2E54:1B17(艦隊, 0, 星域)` 指派，
每指派一支 `ds:D5AE[星域]++`。

## `2E54:0344` 的五個階段

```
2E54:035E()   ; 守首都：n = min(ds:D54E[首都] ÷ 3 + 1, 16)，
              ;         先 2E54:03C3(n) 湊，不夠再 2E54:0513(缺)
2E54:0EC2()   ; 2E54:0F09 取清單 → 依 2E54:1001 排序 → 只處理第一名（2E54:1108）
2E54:0725()   ; 按缺口補（見上）
2E54:08D3()   ; 2D54:0000() → 2E54:08E3() → 2E54:0978()
2E54:119E()   ; 2D54:0000() → 32 個星域依 2E54:11F2 排序 → 只處理第一名（2E54:1243）
```

**`ds:D50E` 與 `ds:D58E` 在同一回合裡各被算兩次。** 階段四之前，
`2D54:0000` 把 `ds:D50E` 換成**攻擊目標分**，`2E54:08E3` 把 `ds:D58E`
換成另一組數：

| | `2E54:0730`（階段三）| `2E54:08E3`（階段四）|
|---|---|---|
| 哪些格子 | 擁有者 == `ds:8F1D` | `ds:D50E[i] != 0` |
| 除數 | `÷ 4` | `÷ 5` |
| 加成 | 前線 0／1 | `RNG() % 4` |

`2D54:0000` 的目標分：連通、而且（擁有者 == `3982:0250(陣營)` 或就是
敵方首都）的格子，`ds:D50E[i] = (累積分 + 1) × 2048 ÷ (ds:D54E[i] + 1)`
——**同樣的價值，守得越薄分數越高**。

## 階段一的補法

```
2E54:0513(還缺幾支):
    首都不是自己的 → 不做
    清單 = 28E0:0103(&清單, 首都, 25h, 0)        ; 提督編號
    依 2E54:063C 排序
    對每個提督：
        ds:8F49[陣營] >= 16 或 還缺幾支 == 0 → 結束
        2D76:0611(提督) == 0 → 跳過              ; 新編一支艦隊（docs/re/181）
        艦隊 = ds:C074 + ((陣營 == 0 ? 0 : 16) + 提督[+0x09]) × 122
        艦隊[+0x08] = 5、艦隊[+0x07] = 0FFh、ds:D60E++、還缺幾支--
```

**守首都缺兵是在首都新編艦隊補的**，不是把別處的調回來。
提督 `+0x09` 的低七位 ＝ 陣營內的艦隊槽（`docs/internals/08`）。

## 新編一支艦隊

```
2D76:0611(提督編號):
    07F9:023B(提督) == 0 → 回 0
    提督[+0x09] &= 7Fh
    提督[+0x09] = 07F9:03AC(提督)                 ; 配槽
    提督[+0x07] == 0FFh → 提督[+0x07] = ds:5F78[編號]   ; 預設副官
    07F9:033A(提督) != 0 → 副官[+0x09] = 提督[+0x09]
```

`07F9:03AC` 先看提督原本掛的槽是不是空的（`+0x04 == 0xFF`），
空著就重用，否則掃自己陣營的 16 個槽找第一個空的——
**提督換艦隊不會換槽號**。

`ds:5F78` 是 82 byte 的預設副官表，只有六對不是 `0xFF`
（41→75、42→63、43→73、46→69、47→64、53→56）。

## 編得成編不成

```
07F9:023B(提督)：艦種 = 提督[+0x08] & 0Fh；星域 = ds:A79C + 提督[+0x0A] × 126
07F9:02CB(星域, 陣營, 艦種)：
    星域[+0x30 + 陣營 × 28 + 艦種 × 4]（32 位元） >= ds:4E3A[陣營×208 + 艦種×26]
07F9:033A(提督)：副官 != 0FFh、副官[+0x09] bit7 有設、副官[+0x00] == 0FFh、
    副官[+0x0A] == 提督[+0x0A]、副官[+0x06] < 提督[+0x06]
```

**提督 `+0x09` 的最高位 ＝ 這個提督沒有帶艦隊**（`docs/internals/08`）。

## 階段二與階段五

```
2E54:0EC2()                       ; 階段二：打最近的無主星域
    n = 2E54:0F09(&清單)          ; 擁有者 == 2（無主）、走得到；距離存進星域 +0x78
                                  ; 星域 14 要 2E54:0F93() 非 0 才算
    依 +0x78 升冪排序（2E54:1001）
    2E54:1108(清單[0]):
        用 2E54:143F(星域, 2)（模式 2）取兩支，各寫 +0x79 = 1
        湊不滿兩支就不打；湊滿了對兩支都 2E54:1B17(f, 1, 星域)

2E54:119E()                       ; 階段五：收尾指派
    2D54:0000()                   ; 重算 ds:D50E ＝ 攻擊目標分
    依 ds:D50E 降冪排序（2E54:11F2）
    2E54:1243(清單[0]):
        目標 = 2E54:13A8(星域)
        對所有 +0x79 == 0FFh 的我方艦隊 f：
            f[+0x0F] == f[+0x0E]              → 2E54:1B17(f, 2, 首都)
            走得到目標：f[+0x3C] < 60 或 f[+0x08] == 3 → 1B17(f, 3, 目標)
                        否則                            → 1B17(f, 0, 目標)
            否則走得到首都                              → 1B17(f, 2, 首都)
```

**擁有者 `2` ＝ 無主**。階段二是 `docs/re/161`「無主行星是被打下來的」
那條路的起點，而且**湊不滿兩支就不打**。

模式 2 的唯一呼叫者是 `2E54:1108`。星域 14 是全遊戲第二個寫死的星域編號
（第一個是星域 13 ＝ 伊謝爾倫）。

## 每個星域派幾支：`2E54:0AAB(星域)`

先用 `2E54:143F` 逐一取候選艦隊，`2B99:0450(星域, 艦隊星域, 陣營) <= 1`
（就在那一格或隔壁）就記成「已到」並停止收集；其餘標成候選。

| 條件 | 做什麼 |
|---|---|
| 已到 < 缺幾支、已到 ＋ `ds:D60E` < 16、(缺幾支 − 候選數) < 3 | `2E54:0CD2` 分配 |
| 同上但差 ≥ 3 | `rand() < 0x2000`（1/4）才叫 `2E54:0DE3` |
| 其餘 | `2E54:0BEB(&清單, 要派, 星域)` |

最後一條有一個**寫死的特例**：目標是**星域 13（伊謝爾倫）**時丟一次
銅板（`rand() & 1`），中了就只派已經到的那幾支，否則照缺口派滿。
全遊戲的 AI 裡目前只有這一個寫死的星域編號（`docs/re/167`）。

`+0x79`（這回合的決定）目前見到四個值：**0 沒事做、3 有事做／就地待命、
4 候選、6 已經到了**。

## 候選怎麼挑：`2E54:143F(星域, 模式)`

回**分數最高的那一支**（`AX` 段、`BX` 位移；沒有就回 `0:0`）。過濾：在用、
我方、`+0x79` 還是 `0xFF`（這回合尚未決定）、`+0x3C` 不低於門檻，
模式 1／2 另外要求 `+0x0F == +0x0E`。

| 模式 | 完整度門檻 | 要求 `+0x0F == +0x0E` | 四個權重 | 主力門檻 |
|---|---|---|---|---|
| 0 | 50 | 否 | 3 2 8 1 | 0 |
| 1 | 90 | 是 | 4 6 1 2 | 0 |
| 2 | 80（艦隊已在目標星域時 50）| 是 | 3 4 0 0 | 4 |

`2E54:0AAB` 用模式 1。**`+0x79` 就是迭代器**：呼叫端取到一支就把它從
`0xFF` 改成 4 或 6，同一支不會被取第二次。

評分 `2E54:1574`（`docs/re/168`）：

```
無法戰鬥（+0x00 bit0）或走不到（2B99:028F >= 0800h）→ 0
艘數 = Σ 各編制槽艦艇[+0x08]；主力槽數 = 艦種 0 或 1 的槽數
分數 = (艘數 ÷ 10) × 艦隊[+0x3C] ÷ 100          ; 32 位元
     × 艦隊[+0x0F] ÷ 艦隊[+0x0E]
     × 權重表[ ds:5F52[艦隊[+0x09]] ]           ; 艦隊類別
     × (順路：+0x08 != 5 且 +0x07 == 目標星域 ? 2 : 1)
     ÷ (2B99:0450(目標, 艦隊星域, 陣營) × 2 + 1)
     ÷ (主力槽數 < 主力門檻 ? 4 : 1)
分數 == 0 → 1
```

## 分配：`2E54:0CD2(目標星域, 艦隊指標陣列, 幾支)`

```
集結點 = 目標星域的鄰居（2B99:03D9）裡「擁有者 ＝ ds:8F1D」
         而且 2B99:028F(鄰居, 我方首都, 陣營) 最小的那一格
對每一支艦隊：
    若 2B99:028F(艦隊[+0x06], 集結點, 艦隊[+0x01]) >= 0x800：跳過（走不到）
    艦隊[+0x08] = (艦隊[+0x06] == 我方首都) ? 3 : 0
    艦隊[+0x07] = 集結點
    艦隊[+0x79] = 0
```

**派去的是集結點，不是目標本身**（`docs/re/166`）。

## 派支援：`2E54:0DE3(候選陣列, 個數, 目標星域)`

`ds:D54E[目標星域] >= 12` 就不派。派 1 支；`3CD5:000C() < 0x2000`（1／4）
且候選 ≥ 2 時派 2 支。**從陣列尾端往前取**，`ds:5F52[+0x09] == 3` 的類別
跳過；派中的填 `+0x08 = 1`、`+0x07 = 目標星域`、`+0x79 = 1`。

## `2E54:13A8(星域)` ＝ 前進基地

在目標格的鄰居裡挑「擁有者 ＝ 自己、到自己首都步數最少」的那一格。
與 `2E54:1955`（往首都方向退一格）同形狀、方向相反。

## 戰略態勢碼：`2D54:0163()`

只看三件事——伊謝爾倫（星域 13）在誰手上、費沙（星域 14）在誰手上、
`ds:8F48` 有沒有設：

| 伊謝爾倫 | `ds:8F48` | 費沙 | n |
|---|---|---|---|
| 帝國 | 0 | — | 0 |
| 帝國 | ≠ 0 | 帝國／同盟／其他 | 1／2／3 |
| 同盟 | 0 | — | 4 |
| 同盟 | ≠ 0 | 帝國／同盟／其他 | 5／6／7 |
| 其他 | 0 | — | 8 |
| 其他 | ≠ 0 | 帝國／同盟／其他 | 9／10／11 |

`ds:5EF2`／`ds:5F22` 各 **12** 組（`0x5EF2`–`0x5F21`、`0x5F22`–`0x5F51`，
接著就是 `ds:5F52` 的艦隊類別表——三張表首尾相接）。

**伊謝爾倫不在自己手上時，路線表只有 `[13]`**：兵推的第一目標永遠是
伊謝爾倫，拿到才談推進。這是態勢碼與路線表的組合，不是另外寫的規則。

`ds:8F48` 唯一的寫入點在 `0x12397`，是 `0x1238D` 那支常式的第一件事，
緊接著 `2AF5:0036(&緩衝, 14, 0)` 處理費沙——**「費沙進入戰局」的事件**
（強推論）。

## 寫死的進軍路線

`2D54:0000` 的中段：

```
n = 2D54:0163()                                  ; 0–11，戰略態勢碼
表 = (ds:8F1D == 0) ? ds:5EF2[n] : ds:5F22[n]
對表裡每一份 0xFF 結尾的星域清單、每一格 r：ds:D50E[r]++
```

所以「累積分」＝ **這一格在這一組路線裡出現幾次**。帝國的每一條路線都
終止於巴拉特（31），同盟的終止於瓦爾哈拉（0）；被越多條路線經過的樞紐
分數越高，AI 的重心是路線表相加出來的，不是另外寫的規則。

資料：`docs/internals/data/ai-advance-routes.json`
（腳本 `tools/scripts/ai_script_lists.py`）。

### 伊謝爾倫（13）與費沙（14）

兩者各自是單獨一格的「路線」。費沙另外要過 `2E54:0F93()`：

```
ds:8F48 != 0 → 1
帝國：伊謝爾倫（ds:AE02）是同盟的 且 ds:8F18 < 238 → 0，否則 1
同盟：伊謝爾倫是帝國的       且 ds:8F18 < 318 → 0，否則 1
```

**伊謝爾倫還在敵方手上就不打費沙**，除非回合數過門檻——帝國 238、
同盟 318（十次「實行」一個月，約 23.8 與 31.8 個月）。

### 一個陣營最多 16 支艦隊

`2E54:0513` 的迴圈條件是 `ds:8F49[陣營] < 16`，與艦隊表每邊 16 個槽一致
（`docs/internals/33`）。

## 建艦隊的類別配額（`2D76:*`）

艦隊 `+0x09`（0–15）經 `ds:5F52` 這張 16 格表換成 **0–3 的類別**：

```
5F52: 00 00 00 00 00 02 00 00 00 00 01 01 02 02 03 03
```

`2D76:011C` 數各類別現有幾支放進 `ds:D506` 的四個 word，`2D76:01A5(總數)`
再減掉配額 **40％／45％／5％／10％**，於是那四個 word 變成「現有 − 應有」。
四個類別依這個值**升冪**排序（最缺的排前面，比較函式 `2D76:0251`），
照順序呼叫 `2D76:02FA(類別)` 試建，成功就停。

整趟由 `2D76:0002()` driven：首都星域（帝國 0、同盟 31）的擁有者不是自己
就不建。細節見 `docs/re/169`。

## 艦隊類別是什麼

四個類別各對應提督的一項能力（`2D76:0434`，`docs/re/190`）：

| 類別 | 乘上提督的 | 名稱 | AI 的目標比例 |
|---|---|---|---|
| 0 | `+0x14`（`+20`）| 未命名 | 40％ |
| 1 | `+0x13`（`+19`）| 占領 | 45％ |
| 2 | `+0x12`（`+18`）| 防禦 | 5％ |
| 3 | `+0x17`（`+23`）| 運用 | 10％ |

```
基底 = (同盟 且 錢 < 20000) ? ds:5FCA[等級] : 等級 × 2
分數 = 基底 × 統率力 ÷ 100 × 類別對應的能力
若 提督[+0x08] & 0Fh == 1：分數 × 3 ÷ 2
提督[+0x1A] = 分數
```

**占領型佔 45％、防禦型只佔 5％**——原版的電腦是進攻取向的，
而那是配額表寫死的，不是某個判斷式。

## 建艦隊的兩道閘門

```
2D76:0060():
    ds:8F49[陣營] >= 16 → 0FFFFh                ; 上限
    n = 2D76:011C()                             ; 現有艦隊數（順便填 ds:D506）
    n < 3 → 回 n                                ; 少於三支不看錢
    …看陣營的錢（ds:8F6A／ds:8F6C）與 ds:8FD4[陣營]…（未讀）

2D76:02FA(類別):
    清單 = 28E0:0103(&清單, 0FFh, 25h, 0)       ; 全部提督
    對每個提督 2D76:0434(提督, 類別) 評分、依 2D76:04FD 排序…（未讀）
```

`28E0:0103` 的 `0x25` 是**清單種類（提督）**，第二個參數才是星域
（`0xFF` ＝ 不限；`2E54:0513` 那邊給的是首都）。

排序之後的挑法（`docs/re/191`）：

```
r = 3CD5:000C()
r >= 7000h 且 筆數 >= 4 且 清單[3] 等級 >= 16 → 選第四名
r >= 6000h 且 筆數 >= 3 且 清單[2] 等級 >= 16 → 選第三名
…（往下未讀）
```

**電腦不會每次都派最強的提督**，各 1／8 的機率往下挑一名，
但被降格選中的那個人**自己要等級 ≥ 16**。

比較器 `2D76:04FD` 比的是 `提督[+0x1A]`（`2D76:0434` 剛算好的分數）。

> 建艦隊這條路每叫一次 `2D76:02FA` 就多一次亂數呼叫——
> `docs/re/184` 量到的「一回合四次」是**沒有建艦隊**的那一趟。

## 艦隊槽是固定分陣營的

`ds:C074` 32 槽 × 122 bytes：**0–15 帝國、16–31 同盟**，沒在用的
`+0x01` 是 `0xFF`（`2E54:03C3` 的起點 ＝ `(ds:8F1D == 0) ? 0 : 16`、
迴圈 16 次；`dm_pre.bin` 的 32 個槽驗過）。

`+0x08`（行動）目前見到三個值：**0 移動、3 從首都出擊／就地戰鬥、5 不動**。

## 收據：`s3aicomp`

把 `ds:8F23[0]` poke 成 1（座位 0 標成電腦）之後，AI 真的跑起來：
`ds:D60E = 5`、四支同盟艦隊拿到目的地與行動 0。三條算式被資料對上：

- `ds:D54E[星域]` ＝ 敵方艦隊 `+0x0F` 的總和（四格全中，含星域 25 的 69）
- `ds:D50E[星域]` ＝ (累積分 + 1) × (2048 ÷ (`ds:D54E` + 1))
- `ds:D58E[星域]` ＝ 缺口 ÷ 5 ＋ `RNG % 4`（`2E54:08E3`）

`ds:D5AE`（階段三留下）與 `ds:D58E`（階段四重算）落在**不同的格子**，
是「同一回合裡算兩次」的直接證據。
