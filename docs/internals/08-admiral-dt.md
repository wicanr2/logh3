# ADMIRAL.DT[89AX] — 提督能力表

資料：`docs/internals/data/admiral.json`（四個版本全欄位）
證據等級：版面 confirmed；欄位語意除 `+11` 外 未知。

## 版面

四個檔各 2296 bytes ＝ **82 筆 × 28 bytes**，沒有檔頭。
遊戲在防拷問答那一步整份讀進來（`docs/re/08` §2）。

| 位移 | 大小 | 內容 |
|---|---|---|
| +0 | 1 | 多為 `FF` |
| **+1** | 1 | **陣營：0 ＝ 銀河帝國、1 ＝ 自由行星同盟**（confirmed） |
| +2…+5 | 4 | 全 0 |
| +6…+10 | 5 | 小整數；`+9` 從 `0x80` 起逐筆遞增，像是編號 |
| **+11…+24** | 14 | **能力值**，實測值域 0x50–0x8C（80–140） |
| +25…+27 | 3 | 全 0 |

## +1 ＝ 陣營（confirmed）

`+1` 在 index 0–39 全為 0、40–81 全為 1，兩段值域完全不重疊；這條分界與
姓名表的順序一致（39 狄克爾／40 亞典波羅），也與人物傳的內容相符
（`docs/lore/character-biographies.md`）。`+10` 同樣切在 40（0 對 31），
語意未知。

## +11 ＝ 占領能力（confirmed，一個資料點）

防拷問答問「照片上帝國軍提督的占領能力數值」，照片是 `FACE.AMG` 的第 0 張；
`ADMIRAL.DTX` 第 0 筆的 `+11` ＝ `0x8A` ＝ 138，輸入 138 直接過關。
其餘 13 個欄位對應哪些能力 ＝ 未知。

第 0 筆的 14 個值：`138 110 118 100 119 114 110 117 126 120 140 130 115 95`。

## 四個版本的差別

`DT8`／`DT9`／`DTA` 是三格存檔（第 8／9／10 格），`DTX` 是新遊戲的樣板
（[`docs/internals/30`](30-save-format.md)）。版面相同，內容不同。
逐位元組比對 `DTX` 與其餘三份，
**只有這些位移會變**：

```
+0 +2 +3 +6 +7 +9 +10 +11..+19 +20 +23
```

`+21`、`+22`、`+24` 在四個版本完全一致——所以這三格比較像固定屬性，
不是會被存檔改動的數值（強證據）。

## `+9` 載入時被夾到 127

新遊戲載入 `ADMIRAL.DTX` 之後，記憶體裡的提督表（`ds:B77C`）與檔案
只差 6 個 byte，全部在 `+9`，而且全部是**大於 127 的值變成 127**：

```
提督 6   134 → 127     提督 13  141 → 127     提督 16  128 → 127
提督 58  128 → 127     提督 60  128 → 127     提督 79  128 → 127
```

夾在 `0x7F` 意味著這一欄當成**有號 byte** 用。語意仍然未知，
但這個夾限有一個看得到的後果：未安定度算式裡「提督」那一項要的是
`+0x09` 最高位有設的提督，夾成 `0x7F` 之後一個都沒有，所以那一項
恆等於 0（`docs/spec/006`）。
