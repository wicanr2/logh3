# 42：畫面的圖塊表 `ds:D81E`

`2376:0390` 那一段掃一張表把畫面畫出來：

```
+0390  mov  bx, 0D81Eh          ; 表的起點
+0393  mov  di, 0C80h           ; 畫面 offset（y=40 那一列）
+0396  mov  cx, 14h             ; 外層 20 次
+03A0  mov  cx, 28h             ; 內層 40 次
+03A3  mov  al, es:[bx]         ; 表項的旗標
+03A6  and  al, 0D0h
+03A8  test al, 80h             ; bit 7 要有
+03AC  test al, 40h             ; bit 6 要有
+03B0  test al, 10h             ; bit 4 要沒有
+03B4  cmp  byte es:[bx+3], 0   ; +0x03 要是 0
+03BB  and  byte es:[bx], 1Fh   ; 畫完把旗標清掉
+03CB  call blit                ; 畫這一格
+03DD  add  di, 2               ; 下一欄（16 像素）
+03E0  add  bx, 6               ; 下一筆
+03E7  add  di, 640h            ; 下一列（20 條掃描線）
```

所以那是一張 **40 欄 × 20 列的畫面圖塊表**，一筆 6 個位元組：

| 位移 | 是什麼 |
|---|---|
| `+0x00` | 旗標。bit 7、6 都有而 bit 4 沒有才畫；畫完 `and 1Fh` 清掉 |
| `+0x03` | 要是 0 才畫 |
| `+0x04` | 來源 offset（blit 的 `mov si, [si+4]` 取的就是它）|

40 × 16 ＝ 640、20 × 20 ＝ 400，正好蓋滿面板那一塊。**這是畫面的
髒格快取**：改到哪一格就把旗標點起來，下次重畫只畫點到的格。

## 單位不走這張表

戰場上的單位畫在分隊的世界座標換算出來的位置（`docs/re/85`），
`s3fight` 那一場的旗艦分隊落在畫面 x ＝ 280——**8 的倍數但不是 16 的
倍數**，而這張表的每一格固定 16 像素寬。所以單位是另一條路徑畫的。

來源 offset 也對不上：格 (17,13) 那一筆是 `0x6FBE`，配上 blit 設的
`ds ＝ 3D22` 是線性 `0x441DE`，而 `SPRITE.SPR` 載在
`0x401BE`–`0x4271E`，超出範圍。
