# 戰場地形的通行規則與集結點

證據等級：**confirmed**（收據 `s3tgt`；反組譯 `31DB:01B6`、`1588:891`、
`1588:4EA`、`1588:621`；查證過程見 `docs/re/100`）。
資料：`docs/internals/data/battle-terrain.json`。

## 三個尺度

| 尺度 | 大小 | 用在哪 |
|---|---|---|
| 格 | 16 × 20 | 地形圖 `MAP<nn>.CMP`，128 欄 × 102 列 |
| 半格 | 8 × 10 | 通行判定的最小單位，一格切成四個象限 |
| 佔位框 | 16 × 16 | 一支分隊佔多大，判定時壓到的半格全部要通 |

## 通行判定

半格 `(c, r)` 擋不擋（`1588:621`）：

```
圖塊 ＝ 地圖[(r >> 1) × 128 + (c >> 1)]
遮罩 ＝ 圖塊遮罩[圖塊]              ; ds:9BB4
象限 ＝ (r & 1) × 2 + (c & 1)
擋   ＝ 遮罩 & 象限位元[象限]        ; ds:3C3E ＝ [0, 2, 4, 8]
```

點 `(x, y)` 通不通（`1588:4EA`）——佔位框壓到的半格全部要通：

```
for c ＝ x ÷ 8 .. (x + 15) ÷ 8
    for r ＝ y ÷ 10 .. (y + 15) ÷ 10
        擋(c, r) → 不通
```

### 圖塊遮罩

`ds:9BB4` 的 64 個位元組只有兩種值：

| 圖塊 | 遮罩 | 意思 |
|---|---|---|
| 0–7、14、15、22、23、30、31 | `00` | 通 |
| 其餘（8–13、16–21、24–29、32–63）| `0F` | 不通 |

**四位元的象限設計實際上沒被用到**——一個圖塊要嘛整格通、要嘛整格不通。
行星（圖塊 6）與集結點（圖塊 1）都算通，所以艦隊可以停在行星上。

象限位元表的第 0 項是 `00`，也就是每個圖塊的左上四分之一永遠算通行。
佔位框 16×16 橫豎都至少壓到兩個半格，多數情形看不出差別。這裡照實記，
不推測原因。

## 兩點之間走不走得通

`1588:891(起點, 終點)` 沿直線每 8 像素試一格：

```
loop:
    到了 → 通
    剩下距離 < 8 → 直接跳到終點
    方位 ＝ atan2(終點 − 目前)          ; 2BE1:011D，一整圈 256
    目前 ← 沿方位前進 8                  ; 2BE1:026F
    不通行(目前) → 不通
```

## 集結點

**地圖上圖塊編號 1 的格子是集結點**，位置取格子的左上角
`(欄 × 16, 列 × 20)`——與行星取中央 `(欄 × 16 + 8, 列 × 20 + 12)`
（`docs/internals/29`）不同。

32 張圖每張都有 4–13 個。載入戰場時展開成 `ds:0D70C` 的 (x, y) 表，
筆數放 `ds:0D78C`。

## 戰術層怎麼用它

`31DB:01B6(艦隊, 參考點, &目標x, &目標y)`：

1. 以艦隊位置與參考點為對角線框一個方框，**短邊撐開成長邊**（補成正方形），
   中心留在兩點的中點；
2. 收框內（嚴格在界內）而且不等於艦隊現在位置的集結點當候選；
3. `rand() % (候選數 + 1)`，抽到最後一號就直接把目標設成參考點；
4. 抽中的候選要「艦隊 → 它」與「它 → 參考點」兩條直線都走得通；
5. 不通就把它從候選裡刪掉再抽，抽光了就用參考點。

**參考點是呼叫端傳進來的，那一層還沒逆向。**

寫進艦隊記錄的 `+0x64`／`+0x66`（`docs/internals/34`）。
