# 38：戰場上的單位是「分隊」，不是艦隊

一支艦隊在戰略地圖上是一個點，進了戰場會散成最多十個**分隊**，
各自有座標、各自移動。分隊就是艦艇池裡的一筆記錄——艦隊記錄
`+0x10` 起那十組 4 個位元組，第一個 word 就是艦艇池的索引
（`docs/internals/33`）。

艦艇池的位置從 `ds:CFB4` 的 far 指標拿，一筆 78 位元組。

## 第37輪分隊繪製次序

35D1:02AB先比較顯示物件+3的unsigned byte，較小先畫；相同時按+4的unsigned word由大到小，proven。
S1全部43邊界的135個分隊物件優先值均128，word+4低byte為SHIP+1艦隊索引，高byte為SHIP+3序號。
每幀135鍵全部唯一，偵察分隊序號為0xFF；typed的-1在繪製時轉uint8。
正式DrawBattleUnits只排序副本，不改規則或選取次序。43幀Field零差異，全畫面仍各差203列38點。
[研究377](../re/377-battle-render-order.md)、[分級索引](data/battle-draw-order.json)、[085](../spec/085-battle-unit-draw-order.md)
及[驗證045](../playtest/045-battle-movement-render.md)保存完整範圍。任意非分隊物件的相等鍵置換未驗。

## 執行期艦艇記錄的欄位

同一支艦隊的十個分隊並排比對出來的（`docs/re/83`）：

| 位移 | 型別 | 是什麼 |
|---|---|---|
| `+0x01` | byte | 屬於哪一支艦隊（艦隊表的索引，`docs/re/86`）|
| `+0x03` | byte | 分隊在艦隊裡的序號 0–9 |
| `+0x04` | byte | 艦種 0–7；`0xFF` ＝ 空的 |
| `+0x05` | byte | 艦艇編號 |
| `+0x08` | word | 現有艘數 |
| `+0x0A` | word | 滿編艘數 |
| `+0x0C` | word | **修理補得回來的上限**：「修理」把 `+0x08` 補到這一格為止（`1AAB:0879`，`docs/re/131`）。戰損也會扣它，但**扣得比 `+0x08` 少很多**——收據 `s3form` 裡有分隊掉了 84 艘而這一格只掉 1，所以 `203A:06C0` 那個 `cx` 不是 `+0x08` 扣掉的同一個數（扣多少還沒讀）|
| `+0x0E` | word | 隨艦種變（3000 艘的是 12000，4000 艘的是 48000）|
| `+0x12` | word | 隨艦種變（36000／20000／0）|
| `+0x16` | byte | bit0 ＝ 這一輪有沒有被重新看到（`docs/re/85`）|
| `+0x17` | byte | **敵方看它看得多清楚**；正常值0–3。索敵僅恰為3不增級，其餘按byte加1，4→5及255→0已驗；衰減見下節（[研究381](../re/381-battle-spotting-display.md)）|
| `+0x18` | byte | **升到第 3 級時才寫**的停留輪數（索敵給 2、防僵局那條給 6）；沒到過 3 的是 `0xFF` |
| `+0x16` | word | **攻擊力**：扣血算式的係數分子，也決定射程（`docs/re/86`、`docs/re/90`）|
| `+0x19` | byte | **小地圖標記的狀態機**：bit7 ＝ 要點、bit6 ＝ 目前點著、bit3–0 ＝ 點下去的顏色（陣營 0 → 5、陣營 1 → 9、其他 → 4）（`docs/re/154`）|
| `+0x1A`／`+0x1C` | word | **小地圖上的位置 X／Y**；`0xFFFF` ＝ 不點（`docs/re/89`）。由 `1727:0207` 點下去時一併寫進來，`1727:0298` 擦的時候讀它（`docs/re/154`）|
| `+0x1E` bit7 | flag | 設起來就不會被選進攻擊名單（`docs/re/90`），**也不會被索敵看到**（`17A0:00AC`，`docs/re/290`）。佈陣時一般分隊寫 `0x7F`、偵察隊寫 `0xFF`（線性 `0x2A124`／`0x2A184`）|
| `+0x1E`／`+0x20`／`+0x22` | word | 隨艦種變的三個常數，同艦種同值 |
| `+0x30` | byte | **選擇順位**：補給／修理／行星補給收完候選之後，`17A0:05B2` 從 `0x80` 開始沿排好的清單遞減寫進來（`17A0:064B`；旗艦另外傳進艦隊記錄）。排序用的比較函式 `17A0:044B` 讀的也是這一格（`docs/re/131`）| confirmed |
| **`+0x05`** | byte | **隊形槽索引**（0–40）：目的地 ＝ 艦隊位置 ＋ `ds:59BA` 第 N 筆偏移依艦隊朝向旋轉（`2BE1:0059`、`docs/re/126`）。旗艦是槽 20 ＝ (0,0) |
| `+0x24`／`+0x26` | dword | **這一回合剩下的行程**（16.16 定點）；每回合開頭從 `+0x21`（巡航速度）左移 19 位補滿 ＝ 速度 × 8，走一步扣實際距離，剩不到 8 就停（`1C61:0005`、`docs/re/124`）|
| **`+0x28`／`+0x2A`** | word | **要去的點 X／Y**；剛佈陣時與現在位置相同（`docs/re/119`）|
| **`+0x2F`** | byte | **戰場上畫哪一塊**（`SPRITE.SPR` 的塊號，`docs/re/85`）|
| **`+0x34`／`+0x36`** | word | **現在的位置 X／Y**——戰場上畫在這裡（`docs/re/119`）|
| `+0x46`／`+0x48` | word | **整場都是 `0xFFFF`**：載入時填一次，戰鬥期間沒有任何寫入，艦池前 200 筆也沒有一筆例外（`docs/re/96`）|

沒列到的位移在觀察到的局面裡都是 `0xFF` 或 `0`。

戰力算式（`docs/internals/33`）用的是 `+0x04`、`+0x08`、`+0x0A`
這三個欄位，位移與存檔裡的艦艇記錄一致。

## 小地圖上的點是 XOR 上去的，靠 `+0x19` 記著怎麼擦

小地圖那一層不是每幀重畫，是**點上去、擦掉**兩個動作各一支：

```
1727:0207(艦艇)     ; 點上去
    需要 +0x19 bit7 有、bit6 沒有、ds:A426 != 0
    色 = 陣營 0 → 5、陣營 1 → 9、其他 → 4
    1727:0324(艦艇[+0x34], 艦艇[+0x36], 色)
    +0x19 = 色 | 0C0h ; +0x1A = +0x34 ; +0x1C = +0x36

1727:0298(艦艇)     ; 擦掉
    需要 +0x19 bit7 有、bit6 有、ds:A426 != 0
    1727:0324(艦艇[+0x1A], 艦艇[+0x1C], +0x19 & 0Fh)
    +0x19 &= 0BFh

1727:02E2(艦艇, 旗標)   ; 開關
    旗標 == 0 且 +0x17 == 0 → 擦掉並清 bit7；否則設 bit7 並點上去
```

寫入是 EGA 的 XOR（`2376:1810`），同一點同一個顏色再寫一次就還原——
所以顏色要存在 `+0x19` 的低 4 位，擦的時候才不用重算，位置要存在
`+0x1A`／`+0x1C`，因為單位早就走掉了。

`1727:0324` 的座標換算（`docs/re/154`、`docs/internals/52`）：

```
實體像素 = (480 + 世界x ÷ 16, 76 + 世界y ÷ 16)
```

小地圖原點是 (480, 75)，所以縱向剛好差一列——`docs/re/89` 從收據量到
的 `unit_row_bias = 1` 就是這個。

## 艦隊記錄的座標是旗艦的複本

艦隊記錄的 `+0x5C`／`+0x5E` 等於第 0 個分隊的現在位置 `+0x34`／`+0x36`。
右側狀態欄讀的是艦隊記錄那一份；戰場上每個分隊各走各的，畫的是
分隊自己的 `+0x34`。

## 開場佈陣：以旗艦為原點的正交格點

每支艦隊有自己的朝向。取第 1、第 2 個分隊相對旗艦的位移當成
基底 `u` 與 `v`，兩者互相垂直、長度都是 22–23，其餘分隊都落在
`a·u + b·v` 的格點上：

| 艦隊 | 朝向 `u` | `v` | 分隊數 |
|---|---|---|---:|
| 帝國 1 | (22, 6) | (6, −22) | 10 |
| 帝國 3 | (21, 8) | (8, −21) | 9 |
| 帝國 4 | (21, 7) | (7, −21) | 7 |
| 帝國 6 | (22, 4) | (4, −22) | 8 |
| 帝國 8 | (−21, 8) | (8, 21) | 5 |
| 帝國 9 | (−23, 0) | (0, 23) | 8 |

`v` 是 `u` 轉 90°。用到的格點是

```
(0,0) (1,0) (0,1) (2,0) (0,2) (3,0) (2,1) (1,2) (0,3) (1,1)
```

分隊少的艦隊取其中一部分。`a` 或 `b` 到 2 以上時實際位移比
`a·u + b·v` 大 1–2，所以原版不是把基底整數倍加起來，而是
沿同一個角度取距離 0、23、45、67——每一步各自取整。

**還沒解**：朝向是誰決定的（不指著敵人，也不是固定值），
以及格點分配給哪一個分隊的順序（分隊數相同的兩支艦隊，
最後兩個格點的順序會對調）。

## 誰在這一場

艦隊記錄的 `+0x06`（所在星域）等於戰場那個星域的，才是參戰的。
`s3ai6` 那一場在星域 26：帝國第 13 艦隊對同盟六支（第 1、2、13、
14、15、16 艦隊）。

**其餘艦隊的戰場座標是存檔帶來的舊值**，不是這一場的佈陣。判讀
分隊位置時要先照 `+0x06` 篩過，不然會拿別的星域的資料下結論。

## 同一個入口進來的多支艦隊會錯開

同盟六支都從星域 27 進來，入口是 (1536,1840)（`docs/internals/39`）。
第一支就放在入口上，其餘五支相對它的位移是

```
(0,−32)  (32,−32)  (−32,32)  (−32,−32)  (0,−64)
```

全部是 32 的倍數，而且是**軸對齊**的——與分隊沿朝向排開不一樣。
32 ＝ 兩格寬。第幾支放哪一個位移還沒解。

## 畫面上怎麼呈現

分隊在戰場上畫成 `SPRITE.SPR` 的 16×16 圖塊，左上角對齊它的
`+0x34`（`docs/internals/34`、`docs/re/85`、`docs/re/119`）。

畫哪一塊由記錄自己帶著：塊號存在 `+0x2F`，繪製時直接取用。填它的是
`25DB:03E9`（[研究85勘誤](../re/85-units-are-sprite-tiles.md)、[研究374](../re/374-battle-marker-lifecycle.md)）：

```
基底 ＝ 陣營（艦艇記錄 +0x00）為 0 → 20，否則 → 50
force != 0 或 +0x17 == 3：
    序號 == 0       → 基底 ＋ 艦隊編號 − 1；FLEET+6A寫方向索引
    其餘            → 基底 ＋ 16 ＋ 艦種（含艦種7）
其餘：
    序號 == 0先將FLEET+6A寫9
    艦種 == 7       → 9
    +0x17 == 0      → 9
    +0x17 == 1      → 基底 ＋ 24
    +0x17 == 2      → 基底 ＋ 16 ＋ 艦種
    其他Detail      → 保留既有+2F，不寫新塊號
```

26E5:00AC輸入恢復caller對己方一般分隊force=1；已放出己方偵察隊亦為1，未放出為0。
因此己方已放出偵察隊圖塊為43／73，敵方偵察隊Detail3亦走完整分支。
來源為[研究381](../re/381-battle-spotting-display.md)及36案完整SHIP／FLEET原版收據，proven。

`+0x17` 是索敵的結果，而且是**累積**的：每被看到一輪往上爬一級、
上限 3，沒被看到就每輪掉一級，掉到 0 就不畫。所以同一個分隊在不同回合
會畫成不同的圖示。條件見下一節。

## 索敵：`+0x16`／`+0x17`／`+0x18` 怎麼變

證據等級 **confirmed**（反組譯 ＋ 九份傾印的分布，`docs/re/290`）。

移動後、戰鬥前（`181B:000A` → `181B:0262`，線性 `0x18412`），
**兩個座位各跑一次** `2526:00F8`（線性 `0x25358`）。一次是這樣：

```
陣營 = ds:8F25[座位]

觀測者 ＝
    這個陣營在場的每一支艦隊（清單 ds:9898、筆數 ds:9894）的
        旗艦分隊（艦隊 +0x10 那一組的池索引）          半徑 200
        索敵分遣隊（艦隊 +0x38），條件 艦隊[+0x3A] != 0xFF   半徑 250
    ＋ 這個陣營在目前星域的每一顆行星（ds:CFF8、顆數 ds:CFFC）
        半徑 ＝ clamp(行星[+0x14] 防衛力, 1500, 6000) ÷ 25    ; 60–240

    （半徑由 2526:01FE 決定：分隊 +0x04 艦種 == 7（偵察隊）→ 250，否則 200）

被看到的 ＝ 在場分隊清單（ds:98BA、筆數 ds:9896）裡同時符合
    分隊 +0x00 == 1 − 陣營            ; 是敵方
    分隊 +0x1E bit7 == 0              ; 由Out判定，不額外排除艦種7
    距離(觀測點, 分隊 +0x34/+0x36) ≤ 半徑

對每一個被看到的（2526:02D7，線性 0x25537）：
    若 +0x16 bit0 已設：跳過（一輪只算一次）
    +0x16 |= 1
    若 +0x17 == 3：跳過
    +0x17按byte加1                    ; 4→5、255→0也增級並加入發現清單
    若 +0x17 變成 3：+0x18 ← 2
```

衰減在回合開頭（`12AA:0245` → `2526:000E` → `2526:005A`），
對在場每一支艦隊的每一個分隊：

```
若 +0x16 bit0 沒設：                  ; 上一輪沒被看到
    +0x17 == 3 → 先 --+0x18，減到 0 才降成 2
    +0x17 == 2 → 1
    +0x17 == 1 → 0
+0x16 &= ~1
```

一個回合的順序：**衰減（回合開頭）→ 移動 → 索敵（戰鬥前）→ 戰鬥等其餘階段 →
回合數 `ds:8F1A` ＋＋**。

### 兩個繞過索敵、直接寫 3 的特例

| 何時 | 做什麼 | 位址 |
|---|---|---|
| 戰略層打行星，而那個星域**有主**（星域 `+0x12 != 2`）| 攻方艦隊的**全部**分隊 `+0x17` ← 3、`+0x18` ← 2 | `20B4:18C2`（線性 `0x22402`），呼叫點 `0x22221` |
| 電腦座位、`ds:8F1A >= 6`（畫面第 7 回合起），而且**一個敵方分隊都看不到** | 敵方**全部**分隊 `+0x16` bit0 ← 1、`+0x17` ← 3、`+0x18` ← 6 | `3009:008D`（線性 `0x3011D`），呼叫點 `0x300AC` |

第二條是防僵局的規則：`+0x18` 給 6 而不是 2，就是要它撐住六個回合。

### 清成 0 的三處

| 線性 | 何時 |
|---|---|
| `0x0429D` | 某個星域的所有艦隊：`+0x48` ← 4（待命）、每個分隊 `+0x17` ← 0 |
| `0x2A12B` | 佈陣：一般分隊（同時 `+0x16` ← 0、`+0x19` ← `0x3F`、`+0x1E` ← `0x7F`）|
| `0x2A18B` | 佈陣：偵察隊（`+0x1E` ← `0xFF`，所以它自己看不見於敵方）|

### 對 remake 的意義

`+0x17` **只有一份**，由雙方的索敵共同推動。這不是簡化：一個分隊的敵人
只有一方，所以這一格的意思就是「敵方現在看它看得多清楚」。

規則可以自己開口：`tools/scripts/scout_vision.py` 把上面的觀測者與半徑
重算一次，跟傾印裡的 `+0x17` 並排。九份傾印裡「在敵方視野內卻
`+0x17 == 0`」的只有偵察隊，「視野外卻 `+0x17 != 0`」的只有一筆剛離開
圈外 22 像素、`+0x17` 正在掉的。

## 戰鬥會扣艦艇

推進到雙方接觸之後，艦艇記錄的 `+0x08`（現有艘數）會往下掉：
`s3fight` 量到同盟第 13 艦隊 27,000 → 26,785、第 16 艦隊
22,000 → 21,602。扣的那支常式是 `203A:0593`，善後在 `203A:06C0`（`docs/re/86`）。

分攤的算式（`21A0:0250`）：

```
份額 ＝ 總損失 × (這一支的現有艘數 × 100 ÷ 全隊現有艘數) ÷ 100
```

每一支至少留一艘，實扣是 `min(現有艘數, 份額)`，扣不滿的留給後面的
分隊。**艦種 7 完全不扣。** 扣完之後 `+0x0C` 跟著減、`+0x0E` 與 `+0x12`
按「剩下 ÷ 原有」等比例縮小。

拿 `s3turn2` → `s3fight` 那八個回合的實測對照，九個分隊算出來的數字
與原版量到的完全相同（`rules.DistributeLosses`）。

**一輪的總損失怎麼算出來的還沒解。**
