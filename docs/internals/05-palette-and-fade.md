# 調色盤與淡入淡出

## 1. 色彩鏈（confirmed）

顯示模式是 VGA mode 12h（640×480×16）。16 色模式的色彩鏈是三層：

```
plane 組出的 4 位元色號  →  屬性暫存器（16 個）  →  DAC（6 位元 RGB）
```

遊戲同時動這兩層，而且用的是 `int 10h AH=10h` 的不同子功能——
**接錯不會報錯，只會讓顏色安靜地變成別的東西**。

## 2. 調色盤檔（confirmed）

`.RGB` 是 **16 色調色盤，每筆 3 bytes**。`BU16IBM.RGB` 48 bytes 已驗；
分量是 **0–15 的 4 位元值**，不是 6 位元 DAC 值。

`BU16IBM.RGB` 的內容是一條灰階漸層：

```
00 00 00  00 00 01  01 01 01  02 02 03  03 03 03  04 04 05
05 05 05  06 06 07  07 07 07  08 08 09  09 09 09  0a 0a 0b
0b 0b 0b  0c 0c 0d  0d 0d 0d  0e 0e 0f  0f 0f ...
```

同副檔名還有 `SPTIT.RGB` 與 `TITSPT.RGB`，各 48 bytes，**內容不同**
（SHA-256 `19807af6…` 與 `adb006d1…`）——名字互為顛倒但是兩份調色盤。

## 3. 調色盤模組（confirmed）

模組的資料段變數：

| 位移 | 內容 |
|---|---|
| `ds:F2D4` | **淡入等級**，`0` ＝ 全黑、`0x10` ＝ 全亮 |
| `ds:F2D6` | 來源調色盤的 far 指標：位移 |
| `ds:F2D8` | 來源調色盤的 far 指標：段 |

來源調色盤在資料段內，實測用過的位移有 `0x8D86`、`0x8DB6`、`0x8DE6`
——**三份不同的調色盤，各 16 筆 × 3 bytes（48 bytes），間隔 0x30**
（強證據：間隔恰好等於一份的大小）。

### 套用公式（confirmed）

**位元組簽章**：`F7 26 D4 F2 D1 E8 D1 E8 50`

```
for i in 0 .. 15:
    r = src[3i+0] * ds:F2D4 >> 2
    g = src[3i+1] * ds:F2D4 >> 2
    b = src[3i+2] * ds:F2D4 >> 2
    setDAC(i, r, g, b)
```

分量是 4 位元（0–15），等級 `0x10` 時 `15 × 16 >> 2 = 60`，正好落在
6 位元 DAC 的範圍內（上限 63）。**等級就是淡入的進度**：0 到 0x10。

### 設等級的入口（confirmed）

```
if (arg != 0) ds:F2D4 = 0x10; else ds:F2D4 = 0;
呼叫套用常式
```

所以「淡出」與「淡入」是同一支常式配不同等級。

## 4. 用到的 BIOS 介面（confirmed）

`int 10h AH=10h`，實測用到五種子功能：

| AL | 動的是 | 介面 | 開機路徑上的次數 |
|---|---|---|---:|
| `02h` | 屬性暫存器全份 | `ES:DX` → **17 bytes**（16 個 ＋ overscan）| 2 |
| `09h` | 屬性暫存器全份（讀回）| `ES:DX` ← 17 bytes | 1 |
| `10h` | **DAC 單筆** | `BX` ＝ 索引、`DH` ＝ R、`CH` ＝ G、`CL` ＝ B | 32 |
| `12h` | **DAC 一段** | `BX` ＝ 起始、`CX` ＝ 個數、`ES:DX` → 3×CX bytes | 2+ |
| `17h` | **DAC 一段（讀回）** | `BX` ＝ 起始、`CX` ＝ 個數、`ES:DX` ← 3×CX bytes | 1 |

設單筆 DAC 的包裝常式（簽章
`8A 5E 06 32 FF 8A 4E 08 8A 76 0A 8A 6E 0C B8 10 10 CD 10`）的參數順序是
`(索引, 藍, 紅, 綠)`——**藍在紅之前**。

### 讀回的那半是必要的（confirmed）

遊戲切換畫面的流程是：

```
AL=09h 讀回屬性暫存器  →  AL=17h 讀回 16 筆 DAC  →  存起來
AL=02h 設屬性暫存器    →  AL=10h ×16 塗黑        →  畫新畫面
                        →  用存起來的值淡回去
```

只實作寫入、不實作讀回，畫面會**永遠是黑的**，而且寫入路徑完全正常，
從症狀看不出責任在哪（`docs/re/06`）。

## 5. 一個模擬器層面的陷阱（confirmed）

套用調色盤那一段是透過 C runtime 的 `int86x` 呼叫 BIOS 的，而那支常式
**不發 `int nn`**：它用 `int 21h AH=35h` 取向量、自己疊中斷框架、再
`iret` 跳進 handler。模擬器如果只在「執行 `INT` 指令」時攔截服務，
這條路會完全繞過去，落在向量指的位置上什麼也不做。

寫模擬器或分析工具時，**中斷向量指到的位置必須是真的能執行的程式碼**，
不能只是一個 `iret`。
