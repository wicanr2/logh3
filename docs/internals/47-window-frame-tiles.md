# 47：視窗外框的圖塊（`FRAME.BLK`）

證據等級：檔案版面、字碼對應、樣式索引與顏色規則都 confirmed
（[`docs/re/138`](../re/138-window-frame-tiles.md)）。已對過四份收據，
其中訊息框那一圈 16,640 個像素逐位元組相同。

## 檔案

`FRAME.BLK`，5,280 bytes，**沒有檔頭也沒有索引**：33 張 16 × 20 的四平面
圖塊接在一起，一張 160 bytes。版面與 `SPRITE.SPR` 相同——每一列依序放
plane 0–3 各一個 word（`asset.DecodeTiles` 直接可用）。

開機時整份載進資料段，主遊戲的執行期位址是 `ds:6BF4`（`ds = 0x54B3`）。
內容與檔案逐位元組相同。

## 四組外框

一組八張，順序固定：

| 相對編號 | 位置 |
|---|---|
| 0 | 左上 |
| 1 | 上 |
| 2 | 右上 |
| 3 | 左 |
| 4 | 右 |
| 5 | 左下 |
| 6 | 下 |
| 7 | 右下 |

| 起始碼 | 圖塊 | 用途 |
|---|---|---|
| 1 | 0–7 | 戰場大面板、訊息框、清單面板 |
| 9 | 8–15 | 主選單與各種小選單 |
| 17 | 16–23 | 尚未在收據上看到 |
| 25 | 24–31 | 尚未在收據上看到 |

「起始碼」就是視窗結構的 `[+3]`；圖塊索引 ＝ `起始碼 − 1 ＋ 相對編號`。
第三、四組沒有色號 0。第 32 張落單，用途未知。

**四個角沒有規則**：斜角在角落的切法是這四張圖上畫的，不是算出來的
（`docs/re/289`）。拿線條去重建會在左上與右下各差幾個像素，而那幾個
像素就是圖塊在那一點的色號——不是「角落規則」。

## 色號 0 是底色，不是黑

畫的時候每一列先算「四個平面都沒有位元」的像素遮罩，再把**視窗顏色的
高四位**（一平面一位元）填進去。所以：

```
畫面色號 = 圖塊色號 != 0 ? 圖塊色號 : (視窗顏色 >> 4)
```

訊息框的顏色是 `0x97`，底色就是 9。同一組圖塊換顏色就是另一種框。

## 格與像素

畫面格表是 40 × 20 格，一格 16 × 20 像素，**原點在畫面上方 40 像素處**。
所以格 `(cx, cy)` 的左上角像素是

```
x = cx × 16          y = cy × 20 ＋ 40
```

視窗的 `[+3]` 非 0 時，建構函式讓寬高各 ＋2 格，那兩格就是外框佔的位置。
一個「內寬 w 格、h 列」的視窗實際佔 `(w＋2) × (h＋2)` 格，畫出來是
`((w＋2)×16 − 2) × ((h＋2)×20 − 2)` 像素——最外圈那一像素是圖塊的邊，
色號通常等於底色，所以肉眼上框看起來小一圈。

## 結構位移

視窗（`0x22` bytes；選單是 `0x24`）：

| 位移 | 內容 |
|---|---|
| `[+0]` | 1 ＝ 已建立、2 ＝ 已顯示（命中測試只認 2） |
| `[+1]` | 顏色（高四位是底色） |
| `[+3]` | 外框樣式起始碼，0 ＝ 不畫框 |
| `[+4]` | 槽位編號（畫面格表用低四位記擁有者） |
| `[+5]`／`[+6]` | 格 x／格 y |
| `[+7]`／`[+8]` | 格寬／格高（含外框那兩格） |
| `[+0B]`／`[+0C]` | 內容格寬／格高 |
| `[+0E]`／`[+10]` | 內容緩衝區遠指標（一格 4 bytes：兩個字碼 ＋ 兩個顏色） |
| `[+1A]` | 1 ＝ 結構是建構函式自己配的 |
| `[+1E]`／`[+20]` | 內容緩衝區的游標，建構時等於 `[+0E]`／`[+10]` |

畫面格表 `ds:D81E`（40 × 20 格，一格 6 bytes）：

| 位移 | 內容 |
|---|---|
| `[+0]` | bit7 髒、bit6 走圖塊、bit5 鎖住、bit4 走字模、低四位 ＝ 擁有者槽位 |
| `[+2]` | 字碼（`0xFF00 ＋ 起始碼 ＋ n` ＝ 外框；`>= 0x80` ＝ 全形；否則兩個半形） |
| `[+4]`／`[+5]` | 顏色 |

## 訊息框的字

一行純文字，從內容格的左上角往下 2 像素起畫，欄距 16、字色 7、陰影 3、
陰影往上一列、不加粗。收據 `s3msg` 逐位元組 0 差異
（`docs/internals/data/message-box.json` 的 `text`）。

## 子元件表（按鈕）

`ds:8CFA ＋ 種類 × 4` 指到一張 12 bytes 一筆的表，`[+0]`／`[+1]` 都是
`0xFF` 結束：

| 位移 | 內容 |
|---|---|
| `[+0]`／`[+1]` | 內容格 x／y |
| `[+2]`／`[+3]` | 格寬／格高 |
| `[+4]` | 旗標 |
| `[+5]` | 種類 |
| `[+8]`–`[+0B]` | 遠指標 → 字串 |

種類 0／2 一顆按鈕「確認」（格 (17,3) 2×1），種類 1／3 兩顆
（格 (14,3)「中止」＋ 格 (17,3)「決定」）。

按鈕不是另一種視窗，是**內容格的旗標**：文字那幾格拿顏色 `0x87`
（底 8、字 7）與旗標 `0x08`，左邊多一格拿 `0x10`、右邊多一格拿 `0x20`
（左右兩格不換顏色，底仍是視窗的 9）。

## 內容格旗標 ＝ 裝飾位元

| 位元 | 效果 |
|---|---|
| `0x01` | 字上方一條線（色 15）|
| `0x02` | 網點（`0x5555`／`0xAAAA` 交錯）|
| `0x04` | 加粗（每列 OR 右移一位）|
| `0x08` | 按鈕上下邊：第 0、1 列整格 ← 7；第 18、19 列整格 ← 3 |
| `0x10` | 按鈕左端：第 0–18 列的第 14、15 行 ← 7；第 19 列 第 14 行 ← 7、第 15 行 ← 3 |
| `0x20` | 按鈕右端：第 1–19 列的第 0、1 行 ← 3；第 0 列 第 0 行 ← 7、第 1 行 ← 3 |

裝飾**最後**畫，會蓋掉字的立體邊。
