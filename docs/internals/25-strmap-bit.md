# `STRMAP.BIT` — 主畫面的星圖底圖

產生：`tools/py.sh tools/scripts/strmap_export.py` → `workplace/assets/strmap.png`
查證過程：`docs/re/17`
推論等級：版面 **confirmed**（改記憶體逐塊問出來的）；
高兩個位元來自檔案 **confirmed**；低兩個位元是執行期畫上去的 **強證據**。

## 版面

| | |
|---|---|
| 大小 | 48,000 bytes |
| 影像 | 320 × 300，16 色 |
| 單位 | **16 × 20 的格子**，20 欄 × 15 列 ＝ 300 格 |
| 每格 | 160 bytes（`16 × 20 / 2`）|
| 格順序 | row-major（先左到右，再往下）|
| 格內 | 每列 8 bytes ＝ **四個平面各 2 bytes 交錯**，`bit0` 的平面在前 |
| 每個 word | 高位在左（bit15 是最左邊的像素）|

16 × 20 正是整個 UI 的格子單位（`docs/internals/23`），而星圖視窗
`54B3:F144` 正是 20 × 15 格（`docs/internals/24`）。**星圖就是一格一格存的。**

## 怎麼問出來的

把載入後的緩衝區某個位移起 64 bytes 改掉，看畫面哪裡變色：

| 位移 | 變化的區域 |
|---|---|
| 0 | x 0–15, y 40–47 |
| 160 | x 16–31 |
| 320 | x 32–47 |
| 1600 | x 160–175 |
| 2400 | x 240–255 |

每 160 bytes 前進 16 個像素。位移 4–7 改成 `FF` 會把色 3 變成色 F
（加上 bit2 與 bit3），所以那八個 bytes 是**同一列**的四個平面，不是四列。

## 低兩個位元是執行期塗上去的

位移 2–3 清成 `00`（照版面應該把 bit1 拿掉）**畫面完全不變**，
而位移 4–7 的改動看得到。載入後的緩衝區從位移 `0x30` 起也與檔案不同。

合起來：`bit2`／`bit3` 是檔案裡的線稿（星系連線、星球、名稱、邊框），
`bit0`／`bit1` 由遊戲依勢力與治安重畫——所以戰略情報報告那張圖
可以整張換色而線稿不動。

拿檔案解出來的圖跟主畫面比：全色相同 77.5%，**只比高兩個位元相同 92.0%**。

## 圖上有什麼

一整張已經畫好的銀河圖：星系名稱（英文）、航路連線、星球圖示、
帝國徽章（左上）、費沙的多面體（右下）。名稱是**畫進點陣圖的**，
不是用字型排出來的。
