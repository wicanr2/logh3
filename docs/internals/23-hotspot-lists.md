# 熱區清單與按鈕標籤

資料：`docs/internals/data/hotspot-lists.json`
產生：`tools/py.sh tools/scripts/hotspot_scan.py` → `hotspot_labels.py`
查證過程：`docs/re/14`
推論等級：清單版面 **confirmed**；`+8` 指向 `\0` 結尾的 Big5 字串 **confirmed**
（25 份解出來全部是通順的中文，沒有一份是亂碼）；那串字**是不是畫在按鈕上**
**未確認**——主畫面那兩筆的字是「確認」「變更」，但畫面上對應位置是兩個
沒有字的灰色小框，所以它比較像動作名稱或狀態列文字；哪一份清單屬於哪個畫面
**多數未知**。

## 一筆熱區的版面

12 bytes（`docs/re/09`）：

| 位移 | 內容 |
|---|---|
| `+0` | 格子 x（相對視窗原點）|
| `+1` | 格子 y |
| `+2` | 寬（格）|
| `+3` | 高（格）|
| `+4` | 啟用旗標，0 ＝ 跳過 |
| `+5` | 項目索引，同一份清單內從 0 遞增 |
| `+6`／`+7` | 未知 |
| `+8` | far 指標 → `\0` 結尾的 Big5 字串（該項的中文名稱），或三個位元組的動作碼 |

清單以 `FF FF` 結束。格子是 16 × 20 像素。

## 登錄動作的位元組簽章（confirmed）

把一份清單掛到一個視窗上的呼叫長這樣：

```
1E BB <清單位移> 53        push ds; mov bx,清單; push bx
<推視窗指標的兩個 push>     FF 76 xx FF 76 xx（區域變數）
                           或 FF 36 xx xx（全域）
                           或 1E BB <視窗位移> 53（靜態結構）
9A 0F 00 A9 37             call far ── 登錄常式
```

`9A 0F 00 A9 37` 是可以直接拿去 `-find` 的簽章（段值 `37A9` 會隨記憶體
佈局改變，但這五個位元組在同一份 binary 內不變）。掃整份記憶體找到
**25 處登錄呼叫**，正好等於清單數。

其中 14 處可以從程式碼直接讀出清單位移：

| 清單 | 登錄碼位址（該次執行的線性）| 視窗指標來自 |
|---|---|---|
| `0578` | `04F0E` | 區域變數 `bp+0/2` |
| `09D6` | `06CAD` | 區域變數 `bp+0/2` |
| `0C52` | `053BD`／`0586C` | **靜態結構 `ds:955C`**（另一個 `ds:9518`）|
| `10BC` | `087A6` | 區域變數 `bp+4/6` |
| `14A8` | `0972D` | 區域變數 `bp+12/14` |
| `1738` | `0A15B` | 區域變數 `bp+6/8` |

**多數視窗指標是參數**，所以原點是執行期才決定的，靜態讀不出來。
要知道某個畫面用哪一份清單、原點多少，得在這些位址上攔一次——
這是下一步。

## 視窗原點：知道格子還不夠

熱區的格子座標是**相對視窗原點**的，換算成畫面座標要
`px = (格子 x ＋ 原點 x) × 16`（`docs/re/09`）。主畫面那份（`09D6`）
的原點是格子 (10,3)，所以 (17,13) 落在像素 (432,320)——與實測一致。

**其餘 24 份的原點未知**，所以光有格子座標還點不到。拿主畫面的原點
去套 `0C52`（戰略命令那一列）點三個位置，畫面 0 差異。
下一步是找出「當下畫面用的是哪一份清單、原點是多少」，
而不是繼續試座標。

## 這張表說了什麼

**遊戲的介面比目前走到的多得多。** 光看標籤就知道還有：

- 頂層命令列：戰略命令／一覽表／系統指令（`0C52`，格子 (1,0)、(7,0)、(13,0)）
- 艦隊編成：戰艦／高速戰艦／巡航艦 ＋ 決定／陣形／中止（`2A00`）
- 出擊與作戰：出擊、作戰、陣形（`1F34`、`21C0`）
- 戰鬥中的命令：占領、待命（`2DB8`）
- 一覽表：治安、敵艦、勢力（`1738`）
- 系統設定：自動１／手動１／自動２／手動２、顯示／不顯示（`902C`）
  ——「自動／手動」兩組各一，配上 `MUSIC.INI` 與 `.MDS` 的 `_F`／`_M`
  兩個版本，像是音源選擇（假說）

動作碼 `FF 17 00` 與 `FF 18 00` 只出現在成對的上下箭頭上（`14A8`、`26E2`），
`17`／`18` 分別是加與減（`docs/re/11` 量到建造計劃左欄加、右欄減）。

## 未知

- 25 份清單各屬於哪個畫面，目前只確定兩份：`09D6` 是遊戲主畫面、
  `26E2` 是次月份船艦建造計劃。
- `+6`／`+7` 兩個位元組的用途。
- 四份指標無效的清單（`0DA4`、`1C0C`、`1FBC`、`8F0E`）是尚未初始化，
  還是用另一種方式分派。
