# `ANI_PNL0.A98` — 戰鬥畫面的底圖

證據等級：**confirmed**（解出來畫在 y=40，遮掉疊在上面那三塊之後
**0 個像素不同**；測試 `internal/asset.TestANIPanelIsAMG`）。

## 就是 `.AMG` 那一套編碼

`FACE.AMG` 的檔案結構是「索引表 ＋ 多張影像」（`docs/internals/09`），
每一張影像自己的檔頭在 `+8`／`+10` 放尺寸、資料從 `+12` 開始。

**`ANI_PNL?.A98` 整個檔就是一張那樣的影像**，沒有前面那張索引表：

```
+0  01 00            格數 1
+2  00               格種 0（覆寫）
+3  00               旗標（不讀）
+4  C8 49            到下一格的距離 18888（從 +6 起算 ＝ 檔案大小 − 6）
+6  00 00            VRAM 位移 0
+8  50 00            80 直行（× 8 ＝ 640 像素）
+10 C8 00            200 組（× 2 ＝ 400 列）
+12 …                資料，與 .AMG 同一套狀態機
```

也就是 **`COMANI.BMG` 的一段、只有一格**（[`20-comani-bmg.md`](20-comani-bmg.md)），由同一支
`348A:01DC` 畫。先前把 `+0`／`+4` 讀成「u32 固定 1」「u32 大小 − 6」數值上也對，但欄位邊界不是那樣
（`docs/re/328`）。

所以 `internal/asset` 的解碼抽成 `DecodeAMGImage`，兩邊共用。

## 畫在 y=40

解出來的 640×400 與收據 `s3ai6` 的畫面比：最合的起點是 **y=40**，
整張 256,000 個像素裡有 40,790 個不同——那些全部落在**疊在上面**的
三塊裡（戰場、小地圖、狀態欄，`docs/internals/34`）。

把那三塊遮掉之後：

```
不同 0 ／ 31,040
```

**外圈那套金屬邊框逐位元組就是這個檔。**

## 三個檔

`ANI_PNL0.A98`（18,894）、`ANI_PNL1.A98`（12,938）、
`ANI_PNL2.A98`（11,604）。戰鬥時載的是 `0`；另外兩個還沒對到畫面。
