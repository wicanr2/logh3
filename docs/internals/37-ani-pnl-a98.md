## 就是 `.AMG` 那一套編碼

`FACE.AMG` 的檔案結構是「索引表 ＋ 多張影像」（`docs/internals/09`），
每一張影像自己的檔頭在 `+8`／`+10` 放尺寸、資料從 `+12` 開始。

**`ANI_PNL?.A98` 整個檔就是一張那樣的影像**，沒有前面那張索引表：

```
+0  01 00            格數 1
+2  00               格種 0（覆寫）
+3  00               旗標（不讀）
+4  C8 49            到下一格的距離 18888（從 +6 起算 ＝ 檔案大小 − 6）
+6  00 00            VRAM 位移 0
+8  50 00            80 直行（× 8 ＝ 640 像素）
+10 C8 00            200 組（× 2 ＝ 400 列）
+12 …                資料，與 .AMG 同一套狀態機
```

也就是 **`COMANI.BMG` 的一段、只有一格**（[`20-comani-bmg.md`](20-comani-bmg.md)），由同一支
`348A:01DC` 畫。先前把 `+0`／`+4` 讀成「u32 固定 1」「u32 大小 − 6」數值上也對，但欄位邊界不是那樣
（`docs/re/328`）。

所以 `internal/asset` 的解碼抽成 `DecodeAMGImage`，兩邊共用。

## 畫在 y=40

整張 256,000 個像素裡有 40,790 個不同——那些全部落在**疊在上面**的
三塊裡（戰場、小地圖、狀態欄，`docs/internals/34`）。

把那三塊遮掉之後：

```
不同 0 ／ 31,040
```

**外圈那套金屬邊框逐位元組就是這個檔。**

## 交戰量表

證據等級proven，限定原版局部量表。原始定位321F:0D11／0DF7，IDA9.4、
dosgolem f7523f9ac7ed6f17bc4e37686b10748c5e9bf89c，GIN3.COM與父狀態雜湊見
[研究405](../re/405-engagement-gauges.md)；原始bytes、地址基準與輸出雜湊在
[結構化收據](data/engagement-gauges.json)。

- FLEET+3C是編制完整度，量表高度為完整度×66÷100。不是剩餘艘數／滿編艘數。
- PLANET+14是防衛力；量表分母由caller給203A:0424艦隊攻擊力。不是PLANET+16上限。
- 防衛攻擊20B4:08B1在反擊前後各讀一次完整度並重算攻擊力；登陸20B4:0681沿用06A6保存的攻擊力。
- 艦隊陣營0畫左，1畫右；行星畫在艦隊對側。原生framebuffer左x298..308、右x333..343，y63..128，端點皆包含。
- 高0全黑；底部往上填。左側填14／邊3，右側填12／邊7。首欄及末三欄為邊，內七欄為填色。

完整取整與word溢位契約、非法輸入處理及正式接線限制見[094](../spec/094-engagement-gauges.md)。
32案各重跑兩次，23,232色號像素零差；不由此宣稱整場或正常玩家路徑same-state。
