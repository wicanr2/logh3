# 要塞砲

資料：行星記錄的 `+0x12`／`+0x16`／`+0x45`／`+0x50`
（[`docs/internals/29`](29-planets-and-economy.md)）。
證據等級：瞄準、射程幾何與狀態機 **confirmed**
（收據 `s3fort`／`s3fort2`，[`docs/re/145`](../re/145-fortress-gun-aim-and-fire.md)）；
命中判定的係數 **strong inference**；開火的結算 **未解**。

八十一顆行星裡有八顆帶要塞（`+0x12` 非 0）。戰場上點自己的要塞會多出
第四項「要塞砲」，做的事是**瞄一個方位**，不是點一支分隊。

## 記錄裡的兩格

| 位移 | 內容 |
|---|---|
| `+0x45` | 狀態，也是倒數：3 ＝ 下一次結算開火、2／1 ＝ 填充中、0 ＝ 待命。每回合減 1（`2264:000A`），只有 0 或 3 能重新瞄準（`1D9E:0247`）|
| `+0x50` | **瞄準的方位**，一整圈 256；`0xFFFF` ＝ 沒瞄準 |

右側面板照 `+0x45` 印三句（字串 `ds:436B`／`ds:4376`／`ds:4389`）：

```
3       要塞砲發射
2、1    要塞砲填充　%1u 回
0       要塞砲待命中
```

## 射程是一個橢圓，要塞在焦點上

```
長半軸 a ＝ 行星[+0x16]（防衛力上限）÷ 200 ＋ 80
短半軸 b ＝ a ÷ 4
焦距   c ＝ ⌊√(a² − b²)⌋
中心     ＝ 焦點 ＋ (c, 0) 依瞄準方位旋轉
焦點     ＝ (行星[+0x46] ＋ 7, 行星[+0x48] ＋ 7)   佔位框中心
```

伊謝爾倫的 12800 → 144／36／139；收據那顆的 3300 → 96／24／92。
射程因此在瞄準的那一側長（a ＋ c）、背面短（a − c）。

畫法是**中點圓演算法**（`39D7:035E`）：拿長半軸畫整數圓，每個點的另一
軸乘 b/a 壓扁，旋轉之後畫四組對稱點的正負兩端，色號 4 用 XOR 疊上去。
一圈只採 256 個角度會在長軸兩端留空隙，與原版對不上。

`rules.FortressRange`／`rules.FortressFocalDistance`／
`screen.FortressRangePoints`。

## 瞄準

玩家（`2264:0049`／`2264:0133`）：方位 ＝ `atan2(游標世界座標 − 焦點)`，
游標停在焦點那一格時方位不變。左鍵寫 `+0x50` ← 方位、`+0x45` ← 3；
右鍵寫 `0xFFFF`／0。

電腦（`303F:0007`／`303F:00B0`）：對自己陣營、`+0x45 == 0` 的要塞，
**八格一步掃一整圈**，每一步把候選方位寫進 `+0x50` 再問「這樣掃得到
幾個敵方」，取分數最高的一個。開火門檻：

```
命中數 × 3 ≥ 敵方總數   或   (敵方總數 ≥ 30 且 命中數 ≥ 8)
```

不過門檻就寫回 `0xFFFF`（不瞄）。敵方總數由 `303F:0061` 數整個艦艇池。

## 開火

`181B:000A`（戰場一回合的結算）第五步是 `181B:0385`：對每一顆
`+0x12 != 0` 且 `+0x45 == 3` 的行星呼叫 `2264:0248`。

```
2264:0248(行星)：
    收候選：以焦點為心、半徑 = 長半軸 × 2 各查一次陣營 0 與 1
            （17A0:00AC），再用 2264:036E 篩
    篩選：艦艇 +0x08 為 0（沒艘數）或 +0x04 == 7（索敵分遣隊）淘汰；
          其餘做橢圓判定，結果寫進艦艇 +0x3C
    排序：qsort，比較函式看行星陣營（帝國 2264:052F、同盟 2264:0612），
          先依艦艇 +0x01（艦隊編號）遞減、再依 +0x03 遞增
    2264:06F5  畫開火動畫與訊息
    2264:080B  逐筆結算（算式與既有收據見規格 028）
```

橢圓判定 `2264:047C(距離, Δ方位, a, b)`（confirmed，
[`docs/re/147`](../re/147-fortress-gun-damage.md)）：

```
距離(16.16) ≤ ℓ ÷ (1 − e × cos Δ)      ; ℓ ＝ b² ÷ a、e ＝ √(1 − (b/a)²)
```

`2264:080B` 逐筆的損失算式也解出來了，寫在
[`docs/spec/028`](../spec/028-fortress-gun-fire.md)（READY，有指定收據）：
防禦係數取**艦種自己的裝甲橢圓**在「砲來的方向」上的半徑
（艦種表 word 11／12），再乘艦隊能力第 0 項 ÷ 100；基準量
`艘數 × 40 × (防衛力上限 ÷ 防禦係數) ÷ 12800`，套的是與艦隊戰鬥同一條
「基準 ＋ 亂數%基準 − 基準÷2 ＋ 亂數%100」。

## remake 現況

瞄準、射程幾何、狀態機及開火結算已有正式接線；指定原版候選集合、扣量範圍與庫存
副作用回歸見 `TestFortressGunMatchesOracle`，原版種子條件與驗證限制見
[`docs/spec/028`](../spec/028-fortress-gun-fire.md)。不能因此宣稱完整八步流程一致。

2026-10-02 已證實（proven）：扣損原始分支對種類 5 無條件縮兩格庫存，
其他種類分別檢查艦種表 `+0x0E`／`+0x12` 是否為 FF；公式是先除原艘數再乘剩餘艘數。
100 艘、庫存 1003／301、量 30、旗標 FF，種類 5 得 70 艘、庫存 700／210。
完整來源雜湊、工具地址空間及原始分支簽章見[研究 366](../re/366-battle-rule-corrections.md)，
輸出值在[欄位摘要](data/battle-rule-corrections.json)，契約為[規格 078](../spec/078-battle-rule-corrections.md)。
