# 啟動鏈、記憶體佈局與堆積配置器

證據全部來自 dosgolem 執行原版未修改的 `GIN3.COM`（`docs/re/01`–`06`）。
段值不穩定，見 [`00-README`](00-README.md)；這裡記位移、結構與演算法。

## 1. 啟動鏈（confirmed）

```
GIN3.COM  →  OPEN.EXE  →  GIN3PS.EXE  →  ENDING.EXE
（啟動器）    （開頭動畫）   （遊戲本體）     （結局）
```

`GIN3.COM` 只有 622 bytes，做三件事：

1. **偵測 EMS**：`int 21h AH=3D` 開字元裝置 `EMMXXXX0`。開不起來就印
   `EMS Driver not found...` 並以離開碼 3 結束。
2. **問 EMS 頁數**：`int 67h AH=40h`（狀態）、`AH=42h`（未使用頁數）。
   `cmp bx,8` ——**少於 8 頁就不繼續**。
3. **依序 EXEC**：`int 21h AX=4B00h` 執行 `OPEN.EXE`、`GIN3PS.EXE`、
   `ENDING.EXE`，每支之間用 `AH=4Dh` 取回碼決定下一步。
   給 `GIN3PS.EXE` 的命令列尾巴是 `9 1` 或 `9 2`（confirmed，用途未知）。

`AH=4Dh` 的 AH 必須是 0：啟動器拿**整個 AX** 去比較（`or ax,ax`／
`cmp ax,1`），AH 留垃圾會讓「回碼 0」被讀成非 0。

## 2. 開機到主選單會載入的檔（confirmed，依序）

```
EMMXXXX0  open.exe  BU16IBM.RGB  gin3ps.exe  EMMXXXX0  MUSIC.INI
GIN3SP.VOC  GRAPH.IMG  COMANI.BMG  FRAME.BLK  SPRITE.SPR  BLOCK_3.BLK
3DBLOCK.SPR  COM_FLAG.SPR  PLADAT.DAT  PLADAT.DAT  ADMIRAL.DTX
STELLAR.DTX  ATTR.DAT
```

`PLADAT.DAT` 開兩次。`BU16IBM.RGB` 由 `OPEN.EXE` 讀取，48 bytes ＝
16 色 × 3 bytes，分量是 0–15 的 4 位元值（confirmed，見
[`05`](05-palette-and-fade.md)）。

## 3. EMS 用法（confirmed）

本體對 EMS 的使用在開機路徑上是：
`AH=41h` 取頁框段 ×1、`AH=43h` 配置 ×1、**`AH=44h` 映射 ×152**。
沒有觀察到 `AH=45h`（釋放）。所以 EMS 是資料倉庫，頻繁換頁。

## 4. 記憶體佈局（confirmed 機制，數值依環境而定）

本體啟動後用 `int 21h AH=4Ah` 把自己的程式區塊**擴到最大**，作法是
「先要一個大的、被拒之後拿回可用值、再要一次」：

```
AH=4A BX=6A07 → 失敗（可用 66DD）
AH=4A BX=66DD → 成功
```

`0x6A07` 段 ≈ 434 KB。這個數字是本體的胃口：**它需要程式區塊起點加上
約 434 KB 的空間**。起點太高就要不到，而要不到的後果不是報錯，是堆積
配置器後面拿到假指標（見 §5 與 `docs/re/05`）。

實務含意：`OPEN.EXE` 結束時它的記憶體必須真的還給系統，本體才載得夠低。
真 DOS 的 `AH=4Ch` 會釋放終止 PSP 名下所有區塊。

## 5. C runtime 的堆積配置器（confirmed）

**位元組簽章**（malloc 入口）：`83 3E E6 94 FF 75 1A`

資料段（DGROUP）內的變數：

| 位移 | 內容 |
|---|---|
| `ds:94E0` | 自由串列頭：far 指標的**位移** |
| `ds:94E2` | 自由串列頭：far 指標的**段** |
| `ds:94E6` | 巡覽指標（rover）位移；值為 `FFFFh` 表示「尚未初始化」 |
| `ds:94E8` | 巡覽指標段 |

自由區塊的欄位：

| 位移 | 內容 |
|---|---|
| `+0x00` | 下一個自由區塊的位移 |
| `+0x02` | 下一個自由區塊的段 |
| `+0x04` | 這個區塊的大小 |

演算法：

1. `ds:94E6 == FFFFh` 時做初始化：把 `ds:94E0/94E2` 當種子正規化
   （呼叫一支把 far 指標正規化的常式），存回頭與 rover。
   種子指向變數自己（`DGROUP:94E0`），所以空串列是「自己指自己」的環。
2. 要求大小 `(size + 3) & ~1`，下限 4，再拉到下限 6。
3. 從 rover 開始走環狀串列，找第一個 `要求 ≤ 區塊[+4]` 的區塊。
4. 走完一圈沒找到 → 要求拉到至少 `0x200`，呼叫向系統要記憶體的常式；
   回傳 `BX == FFFFh` 代表失敗；成功則 `BX += 2` 後丟進 free 併入串列，
   再從頭重試。
5. 切出來的區塊在 `[bx]` 寫入大小，**回傳 `bx + 2`**——所以已配置區塊的
   版面是「2 bytes 大小 ＋ 資料」，與自由區塊的版面不同（強證據）。

配置器的回傳約定是 **far 指標放在 `AX:BX`**（AX ＝ 段、BX ＝ 位移），
不是常見的 `DX:AX`。

### malloc 包裝（confirmed）

**位元組簽章**：`83 F8 00 75 27 83 FB 00 75 22`

```
p = malloc(size);
if (p.seg != 0) return p;
if (p.off != 0) return p;
（寫 I/O 埠 0x37 值 6、呼叫某常式傳 0x3C、寫埠 0x37 值 7、再呼叫一次，然後無限重試）
```

**失敗判定是「段與位移都為 0」**，所以 `0000:0002` 這種指標會被當成配置
成功。這正是 `docs/re/05` 那次崩潰的放大器：配置器從一個位在 `0000:0000`
的假區塊切出 `0000:0002`，包裝層放行，呼叫端就把選單文字寫進中斷向量表。

埠 `0x37` 的語意**未知**；開機到主選單的路徑上這條分支沒有跑到
（寫過的 I/O 埠清單裡沒有 `0x37`）。

## 6. 視窗管理器（confirmed）

**位元組簽章**（配置視窗代號）：`80 3E 0C D8 10 72 09 B8 FF FF`

| 位移 | 內容 |
|---|---|
| `ds:D804` / `ds:D806` | 串列頭：位移／段 |
| `ds:D808` / `ds:D80A` | 串列尾：位移／段 |
| `ds:D80C` | 已使用的視窗數，**上限 16** |
| `ds:D80E` 起 | 每個視窗一個 byte 的佔用表（`0` ＝ 空、`FFh` ＝ 已用）|

配置流程：`ds:D80C >= 0x10` 就回 `AX = FFFFh`（滿）；否則計數加一、
建立節點、插進串列、在佔用表找第一個 0 的位置標成 `FFh`。

雙向串列的插入常式（簽章 `26 89 44 14 26 89 5C 12 8E C0 83 C3 16`）
第二個參數是「插在誰後面」，**傳 `0000:0000` 代表插到最前面**——那是
哨兵值，不是壞指標。節點的連結欄位見 [`04`](04-text-windows-and-big5.md)。
