# `BLOCK_3.BLK` — 戰場的圖塊集

證據等級：**confirmed**（128 塊裡有 7 塊在戰鬥畫面上逐像素找得到，
而且落點全部對齊同一個格盤）。
工具：`tools/py.sh tools/scripts/tile_match.py s3ai6 BLOCK_3.BLK 16 20`。

## 版面

20,480 bytes ＝ **128 塊 × 16×20**，4 位元色號，沒有檔頭。
每一列依序放 plane 0–3 各 2 bytes（與 `SPRITE.SPR` 同一套，
`docs/internals/10`），一列 8 bytes、一塊 20 列 ＝ 160 bytes。

**圖塊尺寸與星域地圖相同**（16×20，`docs/internals/12`）——同一套引擎。

## 戰場就是這些圖塊鋪出來的

拿 `s3ai6` 的畫面逐塊比對，命中的落點是

```
(16,180) (160,60) (160,180) (272,260) (288,260) (272,280) (288,280)
```

x 全部是 16 的倍數、y 全部是 20 的倍數，起點 (16,60) 正好是戰場的左上角
（`docs/internals/34`）。戰場 (16,60)–(463,419) ＝ **28 欄 × 18 列**。

命中的內容也對得上：`(160,60)`／`(160,180)` 是虛線格線交會的地方，
`(272,260)`–`(288,280)` 那四塊是中央那顆行星（2×2 塊）。

## 怎麼確定尺寸的

先用 `find_in_asset.py` 拿畫面上一段 64 像素的 planar 位元組去搜整個檔，
**沒中**——因為圖塊拼出來的畫面，一段連續的 64 像素在檔案裡本來就分散
在四塊裡。改成「把檔案解成圖塊、逐塊到畫面上找」就找到了。

16×16（160 塊）也除得盡，也中了 5 塊；但 16×20 中 7 塊，而且落點
**全部對齊 20 的倍數**——16×16 那幾個落點有 y=168／252／264／284，
對不齊任何一致的格線。所以是 16×20。
