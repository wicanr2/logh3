# 艦艇池：`SHIP.DT[89AX]` 一筆 78 bytes

證據等級：**confirmed**（`docs/re/42`、`docs/re/344`；反組譯 ＋ 執行期池傾印互證）。
執行期在 `ds:CFB4` 的遠指標後面，352 筆 × 78 bytes；存檔就是那張表原樣寫出去
（`docs/re/41`）。**池的一筆 ＝ 一個「分隊」**——戰場上的單位（`docs/internals/38`）
與戰略地圖上艦隊的一組編制，是同一筆記錄的兩種看法。

整池在 `2AD2:0000` 初始化時被整塊填 `0xFF`；`+0x01 == 0xFF` 就是空槽。

## 欄位

| 位移 | 寬 | 內容 |
|---|---|---|
| `+0x00` | b | 陣營（0 帝國、1 同盟），抄艦隊記錄 `+0x01` |
| `+0x01` | b | **擁有者** ＝ 艦隊表槽號 0–31（抄 `+0x03`）；`0xFF` ＝ 空槽／已作廢 |
| `+0x02` | b | **所在星域**（抄艦隊記錄 `+0x06`，編制一動就同步）|
| `+0x03` | b | 組序：建立時一律 0，事後由 `297B:03EB` 寫成真正的 0–9；**索敵分遣隊固定 `0xFF`**，永遠不會被改 |
| `+0x04` | b | 艦種 0–7（`7` ＝ 索敵分遣隊）；`0xFF` ＝ 空 |
| `+0x05` | b | 隊形槽 0–40。**建立當下不設**，等 `297B:03EB` 才寫 |
| `+0x06` | b | 分隊士氣 ＝ `(滿編 − 折算損失) × 100 ÷ 滿編`（`1261:03FB` 每次扣艘數後寫）。**建立當下不設** |
| `+0x08` | w | 現有艘數。建立時艦種 7 直接拿滿編，其餘 `min(星域存量, 滿編)` |
| `+0x0A` | w | 滿編艘數（艦種表 `ds:4E3A` 的 word 0）|
| `+0x0C` | w | **修理／損失上限**：建立時 ＝ `+0x08`；戰損時 `203A:0593` 用 `Σ實扣² ÷ 滿編` 往下扣 |
| `+0x0E` | **dw** | **飛彈存量**。建立時 `2703:14CF` 寫成「艦種表 `+0x10`（飛彈每艘幾發）× 現有艘數」（`docs/re/345`）；艦種 7 恆 0。戰損時 `新 ＝ 舊 ÷ 原艘數 × (原艘數 − 實扣)`。艦種 6（修護艦）的係數是 0，但自家星域補充每回合把這一格重設成現有艘數（`1AAB:1286`）|
| `+0x12` | **dw** | **艦載機存量**，建立時 ＝ 艦種表 `+0x14`（每艘幾架）× 現有艘數，同樣等比例縮 |
| `+0x17` | b | 索敵等級 0–3（被看到 ＋1、沒被看到 −1）|
| `+0x18` | b | 升到第 3 級時的停留輪數 |
| `+0x19`／`+0x1A`／`+0x1C` | b／w／w | 小地圖標記狀態與座標快照 |
| `+0x1E` | b | bit7 ＝ 不進攻擊名單、不被索敵看到。**索敵分遣隊在建立當下就先設 bit7** |
| `+0x1F`／`+0x21`／`+0x22` | b | 回轉／巡航／戰鬥速度：一般組依艦種、艦隊能力與機動力折減；索敵隊直接取艦種表，詳見下節 |
| `+0x24`／`+0x26` | dw | 這回合剩下的行程（16.16）|
| `+0x28`／`+0x2A` | w | 要去的集結點 |
| `+0x2F` | b | 戰場圖塊編號（`SPRITE.SPR`）|
| `+0x30` | b | 顯示／補給／修理候選共用的順位；25DB:01AC圖示建立設80，0915刷新物件+3。研究131／392 |
| `+0x34`／`+0x36` | w | 現在位置 |
| `+0x38`／`+0x3A` | far | 戰場上的圖示物件（建立時清 0；作廢時**非 0 才**釋放再清 0）|
| `+0x3C`–`+0x4D` | 18 | **建立時不寫**，維持池初始化的 `0xFF`。語意未解——`docs/re/42` 的「三格存檔完全相同」是因為從沒被寫過，不是固定屬性 |

`+0x16` 有兩種並存的讀法（byte 索敵旗標 `docs/re/290` vs word 攻擊力 `docs/re/86`），
整個word的其他用途仍未裁決。移動對低byte bit1的操作已由研究371／372證實；
依該契約修改此bit不代表已裁決其他讀法。

## 配置與作廢

- **挑空槽**：`2AD2:0151()` 從索引 0 線性掃第一個 `+0x01 == 0xFF`（first-fit）。
  滿了回 `0xFFFF`，**呼叫端不檢查**。
- **配置**：`2AD2:0029(艦隊, 艦種, p3)` 填上表那幾格，現有艘數從星域存量扣。
- **建新艦隊**：`297B:0066` **無條件配兩筆**——旗艦（`p3=0`）與**索敵分遣隊**
  （艦種 7、`p3=0xFF`），後者寫進艦隊記錄 `+0x38`，**不在 `+0x10` 那十個槽裡**。
  這就是 `docs/re/42` 當年「每支艦隊多一筆沒被引用的記錄」的答案。
- **作廢**：`2AD2:018C(星域記錄, 艦艇索引)` 退回存量（艦種 7 不退）、
  `2AD2:01EF(艦艇)` 不退；兩支都把 `+0x01` 寫 `0xFF`、`+0x38` 非 0 就先釋放。
- **時序**：編輯器是在**「放置」那一刻**（`0FF4:0C80`）配置艦艇，不是按「決定」時；
  「決定」（`0FF4:10C1`）只是把工作表寫回艦隊記錄。

## remake

`rules.Slot.Ship` 就是這張表（存檔原樣）。`rules.FleetGroup` 帶艦種、艘數／滿編、
隊形、位置、池索引、士氣、修理上限與兩項存量；其餘欄位從原始底稿保留。
保存前由 `Slot.SyncFleets` 同步（[規格 067](../spec/067-live-fleet-save.md)）。

## 三項速度（已證實）

一般組基礎回轉／巡航／戰鬥速度依序是 `kind[08]*fleet[43]/100`、
`kind[06]*fleet[42]/80`、`kind[07]*fleet[42]/60`；先整數除法，再計
`p=(270-2*fleet[46])*mobility[groups]/100`，各自扣 `speed*p/100`。
艦隊取各組最小值。索敵隊直接抄艦種 7 的 `08/06/07`，不套這個折減。
來源：[研究 355](../re/355-live-fleet-save.md)、
[分級索引／輸入雜湊／工具版本](data/live-fleet-save.json)，19 組執行期原版樣本全部相同。
定位以結構位移及 `26 88 07`／`26 88 05` 寫入簽章搭配讀寫鏈保存，不以可變段值作唯一依據。

## 移動階段額度與停止條件

證據等級：**proven**；[研究371](../re/371-battle-movement-phase.md)保存IDA Pro9.4
原始指令、輸入／輸出雜湊、dosgolem版本及可重播命令，
[分級索引](data/battle-movement-phase.json)供匯出自動合併，不以自訂名稱取代原定位。
正式完整移動依[規格080](../spec/080-battle-movement-phase.md)的READY契約；
畫面診斷見[驗證045](../playtest/045-battle-movement-render.md)，完整同狀態門檻仍待補。

一般分隊與啟用索敵隊的`+24/+26`是有號32位16.16額度。初始化讀`+21`巡航速度，
新增量為`speed<<19`；嚴格`0<舊額度<8<<16`才累加，其餘覆蓋。
艦隊`+3A=FF`時索敵隊不初始化。7艦隊／55分隊初始化及14案邊界已直接互證。

Action=0自主移動到點或一般分隊餘額不足8.0時改3並清額度；
索敵隊未到點且不足一步時保留Action／餘額。6案常式停止分支已直接互證。
Action=7F跟隊時，艦隊`+49 bit0`選16／8步長，分隊`+16 bit1`設起再乘3/2；
Action=3固定8。這是移動用途的byte旗標，不裁決`+16`整個word的其他用途。

分隊步進最後固定扣8.0；現在座標`+34/+36`及集結點`+28/+2A`的定位由寫入指令確認。
步長、碰撞、收回的常式動態案例已由[研究372](../re/372-battle-step-and-collision.md)補102案原版雙跑；
第31輪已接正式交錯與分隊原池保存，結果見[研究373](../re/373-battle-interleaved-movement.md)。
艦隊單步的38案及9案碰撞另依[規格081](../spec/081-battle-fleet-step.md)限定驗收，
不將原版雙跑當作整階段remake已符合。
