# 執行期艦隊表（`ds:C074`）

資料：無獨立檔案——這張表是執行期結構，`SHIP.DT?`／存檔另有各自的版面
（`docs/internals/30`）。
證據等級：長度與筆數 **confirmed**（`docs/re/66`）；下面標 confirmed 的
欄位來自對寫入設監看（`docs/re/70`）或直接讀反組譯。**122 bytes 現在逐格都有
交代**——不是每一格都有名字，有六格的結論是「整份影像沒有任何讀取指令」
（[`../re/288`](../re/288-fleet-record-remaining-fields.md)）。

## 版面

`ds:C074` 起 **32 筆 × 122 bytes**。開局時第 0 筆全是 `0xFF`
（`docs/re/66`：那時整張表沒有任何艦隊）。

### 逐格總表（122 bytes 全覆蓋）

一格一格看的快速索引；每一項的證據與算式在下面各節。`w` ＝ word（低位在前）、
`d` ＝ 32 位元、`p` ＝ 遠指標（位移在前、段在後）。**標「無消費者」的那幾格
是「整份程式影像找不到任何讀取指令」**，判準與掃描形式見
[`../re/288`](../re/288-fleet-record-remaining-fields.md)。

## 槽是固定分陣營的（confirmed）

`ds:C074` 的 32 個槽**不是共用的**：**0–15 是帝國、16–31 是同盟**。
`2E54:03C3` 逐艦隊掃的時候起點就是 `(ds:8F1D == 0) ? 0 : 16`、只跑 16 次
（`docs/re/166`）；`dm_pre.bin` 的 32 個槽 `+0x01` 正好是前 16 個 0、
後 16 個 1，沒在用的是 `0xFF`。

## 寫了沒人讀，與完全沒有消費者的那幾格

「沒有語意」與「沒有消費者」是兩件事，這一節只放後者。判準是
**三種掃描形式在四份不同階段的 1 MB 傾印上都是零**：`loadbyte.py`
（Borland 讀 `unsigned char` 的固定形狀）、`field_xref.py` 的 `mod=01`
（`es:[bx+NN]`），以及同一支新增的 `add bx/si/di, imm8` 形式——
**最後那一種是關鍵**，取欄位位址傳出去的寫法只走它，少掃就會憑空得到
一堆「沒有消費者」。每一次都同時掃已知有人用的位移當正對照。
完整清單與逐處歸屬在 [`../re/288`](../re/288-fleet-record-remaining-fields.md)。

| 位移 | 狀況 |
|---|---|
| `+0x4B` | `297B:0BAF` 把進戰場時的朝向同時寫進 `+0x4A`／`+0x4C`／`+0x4B`；前兩格之後各自變，這一格停在初始值，**沒有任何讀取** |
| `+0x50` | 見上；寫得到值（恆 `0xFF`），**沒有任何讀取** |
| `+0x51` | 連寫入者都沒有（`+0x50` 是 byte 寫入，順帶都碰不到），84 筆全 `0xFF` |
| `+0x68`／`+0x69` | 沒有任何存取，84 筆全 `0xFF`。看起來像消費者的七處 `add si,68h` 全部屬於**星域記錄**（飛彈存量）|
| `+0x71` | 沒有獨立存取；只被 `20B4:0045` 的 `mov word es:[si+70h],0` 順手清掉 |
| `+0x72`／`+0x73` | 沒有任何存取，84 筆全 `0xFF` |

> **值全是 `0xFF` 不能當「沒人寫」的證據。** `+0x6B` 在同一批傾印裡也全是
> `0xFF`，但它有寫入者（`17A0:0699`）也有讀取者（`25DB:0865`）——只是那條路
> 在這四個時點都沒被走到。同一個現象、兩個相反的結論，差別只在有沒有去讀程式。

## 能力那 11 個 byte 的順序

`ADMIRAL.DT*` 的位移依序是
`+15`、`+16`、`+17`、`+19`、`+18`、`+12`、`+13`、`+20`、`+22`、`+23`、`+14`
——**第 10 個是 `+14`（營運）**：收據 `turn260mem` 的三支
`max(提督, 副官)` 的 `+14` ＝ 102／128／120，與量到的 `+0x47` 逐一相同，
而 `+19` 三支全不中（`docs/re/218`）。

十四個能力欄位裡沒被抄進來的是 `+11`（統率力）、`+21`、`+24`。

第 7、第 8 項（`+0x44` ← 提督 `+20`、`+0x45` ← 提督 `+22`）**兩張明細畫面都
沒有印**（戰術「資料」那張與艦隊組成那張），但各有一個消費者
（[`../re/287`](../re/287-admiral-remaining-fields.md)）：

- `+0x44`：`307D:03B5` 算 `ds:D61A ＝ (+0x44 ÷ 2 > 編制完整度百分比)`，
  也就是「這一支打到剩不到 `+20` 的一半就換一種評估模式」；
  `307D:001B` 之後會用三分之一機率把它清掉。
- `+0x45`：`1F6F:024C` 拿 `亂數 × (+0x45) ÷ 100` 與 8192／16384 比，
  決定一個分隊取排序後第 0／1／2 個攻擊目標——**值愈大愈常打分數最高的那個**。

合成是 `297B:05B2` 做的（線性 `0x29D62`），逐項的位移在
線性 `0x29F2B` 起可以直讀，與 `docs/re/70` 從收據反推的那張表一致。

## 戰力值怎麼算（`2E54:1876`，`docs/re/79`）

一群艦隊的戰力 ＝ 每一支每一組編制的

```
    ds:6032[艦種 +0x04] × 艦種 +0x08（一單位幾艘）× 1000 ÷ 艦種 +0x0A
```

加總（32 位元）。`+0x00` bit0 有設的艦隊不算。原版拿它比較兩個陣營在
某一帶的強弱。

## 誰把整張表跑過一遍

`056A:03E0`：`i` 從 0 到 31，指標每次 `+0x7A`（122），`+0x04` 是 `0xFF`
就跳過，其餘呼叫 `113A:0350`。**版面那三件事（位址、筆數、每筆長度）
在這一支裡一次全證實**（`docs/re/78`）。

## 移動要花的就是軍事費

`ds:8F52`（每個陣營一份的 32 位元存量）在載入 S2 的畫面上寫著
**軍事費 150,000**——與 dump 裡的值相同（收據 `s2ai0`）。所以移動扣的
是軍事費，不是另一種資源。

## 移動要花錢

`113A:047D` 寫 `+0x06` 之前先呼叫 `113A:06C3`：拿每個陣營一份的 32 位元
存量（`ds:8F52`，陣營 ×4）比艦隊記錄的 `+0x0C`（這一支移動的花費，
量到 183–288），不夠就不能動（回 0 → 呼叫端跳「由於移動經費不足無法移動」
`113A:0A4E`），夠就扣掉，並把整筆付進行星的經濟力（自己擁有離開的那一格
就付給它，否則付給走到的那一格；`2703:1C11`，`docs/re/313` §3.1）。存量在
四份 dump 裡是 150,000／160,000（帝國）與 30,000（同盟），而且**沒移動的
一方也在減**——它不只被移動扣（`docs/re/77`）。維持費那一支（`056A:09EB`）
同樣把 `+0x0A` 的一半付進所在（自己的）星域的行星。

`113A:047D` 走之前還比擁有者：現在格與下一格都不是自己的 → 「無法前往敵方
的星系」（`113A:0797`，命令清掉 `+0x08 ← 5`、`+0x07 ← 0xFF`）；下一格不是
自己的且 `+0x08 != 1`（不是占領）→ 同一張報告；`+0x08 == 1` → 占領那一路
（`113A:0545` 起，沒讀）。
