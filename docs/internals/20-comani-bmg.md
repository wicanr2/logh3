# `COMANI.BMG` — 交戰演出的動畫庫

證據等級：檔案與格的結構、兩種格的解碼、視窗座標 **proven**（反組譯 `348A:01DC`／`0228`／`02F9`／
`03A3`、`3958:0041`、`3A8D:003A`；254 段 1,438 格每格剛好吃完；交戰演出用到的三段逐格與收據
`eng-text`／`eng-mid`／`eng-mid2`／`eng-end` 兩個視窗逐位元組相同）。名字的語意 **hypothesis**。
調查紀錄：[`docs/re/328`](../re/328-comani-bmg-codec.md)（編碼）、[`docs/re/324`](../re/324-engagement-scene.md)（演出本身）。
資料：`docs/internals/data/comani-bmg.json`（每段每格的格頭、底圖來源、視窗像素雜湊）
素材：`assets/original/comani/<段名>/fNN.png`（1,438 張 256×102，「畫完第 NN 格之後」；段名第二個字元
寫成前兩字元的十六進位）
產生：`tools/py.sh tools/scripts/bmg_export.py`；解碼器 `internal/asset/bmg.go`

檔案 1,036,159 bytes，SHA-256 `08954a638bfb115b356cb07c66f1d58b8b796d6b0b7cd4aed7441c741db89435`。

## 檔案

```
+0        u16   目錄長度 ＝ 10 × 筆數（2540 → 254 筆）
+2        目錄，每筆 10 bytes：char[4] 名、u16 長度、u32 位移
+2＋位移  段（長度 bytes）
```

**位移從檔案 +2 算起**（原版 seek 到「位移＋2」）。段與段之間沒有洞，第 254 筆 `PZD2`（1,730 bytes）
收在檔尾。

## 段與格

```
段：+0 u16 格數（4–14），接著一串格
格：+0  u8   格種：0 覆寫（210 格）／1 XOR 差分（1,228 格）
    +1  u8   全 0，程式碼跳過不讀
    +2  u16  到下一格的距離，從 +4 起算
    +4  u16  VRAM 位移，相對於視窗原點：列 × 80 ＋ 位元組欄（mode 12h 一列 80 bytes）
    +6  u16  直行數（一欄 8 像素；只讀低位元組）
    +8  u16  高：格種 0 是組數（× 2 列）、格種 1 是列數（只讀低位元組）
    +10      壓縮資料
```

所有格都落在 32 欄 × 102 列裡 ＝ 視窗 256×102。

- **格種 0**（`348A:02F9`）就是 `.AMG`／`ANI_PNL` 那一套（[`09-face-amg.md`](09-face-amg.md)）：直行掃描、
  一次兩個 byte 寫相鄰兩列；兩個相同是重複組（後接第二個值與次數）；走完一直行換下一直行、走完
  全部直行換下一個 plane，四個 plane 共用同一個狀態。
- **格種 1**（`348A:03A3`；GC 先設成 read mode 1 ＋ XOR，`2376:17E0`）：一次一個 byte、一 byte 一列。
  非 0 → 那一列 `^=` 它；0 → 後面一個 byte 是「跳過幾列」，可以跨直行、跨 plane。

## 畫在哪、怎麼叫

`3958:0041(記錄, 靜圖?, 動畫?)`：`ds:8F36`（動畫效果）是 0 就不畫；組四字名 → `332E:0D1C` 讀進
`ds:F138`；陣營 0 畫左視窗、否則右視窗；靜圖 `348A:01DC` 只畫第 0 格，動畫 `348A:0228` 畫整段，
每一格之前在 `348A:0281` 等計時器 `ds:8EFE` 到 0、再設成 `ds:8F10[ds:8F37]`（動畫速度的間隔表）。

視窗原點 `3A8D:003A(x, y)` ＝ VRAM `y × 320 ＋ x ＋ 0xC80`：x＝1、y＝4 → 像素 (8,56)；x＝47 → (376,56)。

## 名字（`3958:0041`，表在 `ds:8E16` 起）

```
[0][1]  記錄+1（種類）是 9／10／11 → 'P' ＋ "BHCADTEPLPFZ"[種類]（PP／PF／PZ）
        否則 [0] ＝ "EF"[記錄+0]（E 帝國、F 同盟）
             [1] ＝ 記錄+4 != 0 ? "BHCADTEPLPFZ"[記錄+1] : ds:8E34[記錄+5]（0xB1… 個別艦代碼）
[2][3]  靜圖 → "D0"
        否則 [2] ＝ "AD"[記錄+2]；'D' → [3] ＝ "012BMF"[記錄+3]；'A' → [3] ＝ "012BMF"[3 ＋ 記錄+3]
        （種類 10／11 且 記錄+3 ＝ 1 時例外：陣營 0 → 'M'、否則 'F'）
```

組法 proven；語意 hypothesis：`D0` 靜圖（整段是中彈那一串）、`AB`／`AM`／`AF` 光束／飛彈／艦載機、
`D1`／`D2` 更重的中彈。記錄欄位（`+2` 行動、`+3` 子類、`+5` 個別艦、`+6` 音效）只從這支的用法推。

## 底圖（匯出時）

開頭是 XOR 格的段（201 段）要疊在某張圖上。交戰演出裡 `PPAB` 疊在 `PPD0` 第 0 格上是收據證實的；
匯出時其餘段一律疊同一單位的 `D0` 第 0 格（strong inference，JSON 的 `base` 欄寫明）。
