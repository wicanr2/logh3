# `STELLAR.DT[89AX]` — 星域資料

資料：`docs/internals/data/stellar.json`（四個版本全欄位）
可讀版本：`docs/lore/star-regions.md`
產生：`tools/py.sh tools/scripts/stellar_export.py`
證據等級：版面與名稱 **confirmed**；執行期記錄的欄位語意見下表，
標 confirmed 的都對過畫面或反組譯（`docs/re/17`、`23`、`24`、`26`、`30`）；
檔案裡 `+0x13` 之後那一段沒對過的欄位仍是 **未知**。

## 版面

四個檔各 4,032 bytes ＝ **32 筆 × 126 bytes**，沒有檔頭。

32 筆正好對上 `STRMAP.RGN` 的 32 個星域區塊，名字也對得上遊戲畫面上
印在地圖旁的字（`KASTOROP`、`GANDHALVA`、`ALDEBARAN` 等）。

| 位移 | 內容 |
|---|---|
| +0 起 | Big5（倚天）名稱，`\0` 結束、後面補 0；最長 12 bytes（「艾爾•法西爾」）|
| +18 | **擁有者**：0 ＝ 帝國、1 ＝ 同盟、2 ＝ 無主（`docs/re/17`）|
| +19 起 | 數值欄位，語意未知 |

## 四個版本的差別

`DT8`／`DT9`／`DTA` 是**三格存檔**（第 8／9／10 格，副檔名最後一個字
是槽位編號的十六進位），`DTX` 是新遊戲的樣板
（[`docs/internals/30`](30-save-format.md)）。版面相同、內容不同。
逐位元組比對，**只有 +18 之後會變**，名稱區完全一致。會變的位移：

```
18–24, 26–28, 30, 32–36, 38–41, 48–49, 52–53, 56–57, 60–61, 64–65,
68–69, 72–73, 76–77, 80–81, 84–86, 88–89, 92–93, 96–97, 100–101,
104–106, 108–110, 112–114, 116–118, 124–125
```

從 48 起是很整齊的「每 4 bytes 動 2 bytes」——看起來是一組 u16 陣列
（每個星域對 N 個對象各有一個值，例如與各勢力的關係或各行星的狀態）。
確認要等能進到用得到它的畫面。

## 執行期就是這份記錄

整個檔案載在 `ds:A79C`，一筆 126 bytes。載入的時候**擁有者、行星數、
經濟力與未安定度會重算**，其餘欄位原封不動——拿 S3 那一格存檔
（`STELLAR.DTA`）與載入後的記憶體比，32 × 126 bytes 裡只有 22 個
`+0x7D` 不一樣（`docs/re/41`）。星圖的勢力色直接讀
每一筆的 `+18` 去查 `ds:8BD2` 的「擁有者 → 色號」表（0→色 1 帝國藍、
1→色 12 同盟棕、2→色 3 黑）。首都另外用色 6 重塗。

檔案裡的 `+18` 是陣營原本的疆域（`DTX` 前 16 個 0、後 16 個 1）；
**載入之後會依行星重算**：掃該星域的行星（`PLADAT.DAT`，82 bytes 一筆），
依行星的 `+0x11` 把數量累加到星域記錄的 `+0x16`（帝國）、`+0x17`（同盟）、
`+0x18`（其他），然後

```
同盟 == 0 且 其他 == 0        → 0（帝國）
否則 帝國 == 0 且 其他 == 0   → 1（同盟）
否則                          → 2（無主）
```

796 年 1 月有 10 個星域因此變成無主（`docs/re/17`）。

## 與 `PLADAT.DAT` 的關係

`PLADAT.DAT` 的 64 bytes 檔頭是 32 個 word，**第 k 個就是第 k 個星域有幾顆行星**
（合計 81 ＝ 筆數）。行星在檔案裡按星域順序排，所以第 k 個星域的行星就是
前面數量累加起來那一段。詳見 [`29-planets-and-economy.md`](29-planets-and-economy.md)。

星域記錄裡好幾格其實是「把自己的行星加起來」：擁有者、行星數、防衛力、
**經濟力**都是載入時算出來的，檔案裡的原值當場被蓋掉。

## 執行期記錄的欄位（confirmed，`docs/re/23`）

整份載在 `ds:A79C`，一筆 126 bytes。載入之後這幾格會被重算：

| 位移 | 內容 |
|---|---|
| `+0x12` | 擁有者：0 帝國、1 同盟、2 無主（由行星重算，見 `docs/re/17`）|
| `+0x14`／`+0x15` | 帝國／同盟佔該星域經濟力的**百分比**（`docs/re/57`）|
| `+0x16`／`+0x17`／`+0x18` | 帝國／同盟／其他 各有幾顆行星 |
| `+0x1A` | 經濟力（32 位元）|
| `+0x20`／`+0x22` | 防衛力（同一個值兩份）＝ 該星域行星 `+0x14` 相加 |
| `+0x1E` | 成長率（千分之一）。瓦爾哈拉 45 ＝ 畫面上的 4.5% |
| `+0x26` | 稅率（千分之一）。**每個星域各自一個**，畫面右側那個 3.2% 是首都的。**`ds:8FD4`（`Blend`）一變就由 `090A:0B93` 把該陣營每一格重算一次**（夾在 1–200，`docs/re/220`）|
| `+0x27` | 上個月的稅率（月底結算時從 `+0x26` 抄過來）|
| `+0x28`／`+0x29` | **這一格有幾支艦隊**：`+0x28` 帝國、`+0x29` 同盟。`2703:08CE` 對 `+0x28 ＋ 陣營` 遞增（`docs/re/40`）；25 份執行期傾印 800 格對 799 格、三個劇本的資料檔 96 格全對（`docs/re/199`）。戰略 AI 的 `2E54:005D` 讀敵方那一格決定要不要退（`rules.RegionFleets`）|
| `+0x2A`／`+0x2B` | 同一組的另外兩格。**在 25 份傾印與三個劇本的資料檔裡全部是 0**；帝國玩家的面板卻是從 `+0x2B` 取敵軍數（收據 `pnlFLT`，`docs/re/31`），於是正常局面下那一欄永遠印 0。`0xFF` ＝ 看不到。兩者怎麼並存**假設待驗**（`docs/re/199`）|
| `+0x30`–`+0x4B` | **帝國**在這個星域的七種艦艇**艘數**，各 32 位元（`docs/re/69`）；同盟那一份接在 `+0x4C`。`2703:12EB` 每回合清零重算：把這一格每顆行星的 `+0x20 + 種類×4` 按**行星的擁有者**累加（`docs/re/244`）。新編一組編制時 `2703:1433` 從這裡搬走 `min(存量, 滿編艘數)` 並**就地扣掉**（`docs/re/215`、`rules.TakeRegionShips`）|
| `+0x4C`–`+0x67` | **同盟**的同一組七個 |

畫面上的「行星 n/m」＝ 玩家陣營的行星數 / 該星域行星總數。

艦艇那兩組存的是**艘數**。艦隊組成畫面上的「待命部隊」＝ 艘數 ÷
一單位幾艘，「數量」欄印的就是一單位幾艘
（`[3000, 3000, 4000, 2000, 3000, 3000, 1000]`，兩個陣營相同，
`docs/internals/32`）。開局 22 個有艦艇的星域、兩個陣營、七種艦艇
全部整除，沒有一個餘數（`docs/re/69`）。
| `+0x7C` | 民心：0–200，高的偏帝國。未安定度的算式取「帝國星域原值、同盟星域 `200 −` 原值」再除以 10（`docs/spec/006`，**已對拍**）|
| `+0x7D` | 未安定度。畫面上的治安 ＝ `(200 − 未安定度) / 2`（`docs/re/24`），
只有自己這一方的星域才印數字，其餘印 `----`。無主星域一律 100。|

`+0x7D` 的**開局值**不等於四個 `STELLAR.DT*` 檔案的最後一個 byte，
載入時被重算過，那一步未解。

## 執行期星域記錄（`ds:A79C`，32 × 126）的 `+0x13`

**兩支常式各管一半**，只有 bit2 兩邊都寫而且條件相同（`docs/re/245`）：

| 常式 | 先清 | 重填 |
|---|---|---|
| `2703:0933(星域記錄)` | `and 0F2h`（bit0｜bit2｜bit3）| bit0、bit2、bit3 與 `+0x24` |
| `056A:0468`（掃 32 格）| `and 0E9h`（bit1｜bit2｜bit4）| bit1、bit2、bit4 |

所以 bit5–bit7 兩邊都不動。**執行順序量到了**（收據 `flagpass`）：
一次「實行」的尾巴是 `056A:0468` → `2703:08DE`（它裡面跑 32 次
`2703:0933`）→ 回合計數器 `ds:8F18` 進位。呼叫點靜態掃不到（走模組管理器
的間接向量），但時機這樣就夠了。

| 位元 | 內容 | 等級 |
|---|---|---|
| bit0 | **到自己陣營首都的路徑成本 `>= 0x400`**，也就是 `k >= 1`：路上至少有一條邊的兩端不全是自己的（`docs/re/243`、`244`）。成本本身寫在 `+0x24`。無主星域不寫這個位元。讀的一端是 `2E54:0222`／`2E54:02C2`，拿它與 `ds:D54E` 一起判一個鄰居算不算數（`docs/re/171`）| confirmed |
| bit2 | **這一格雙方都有艦隊**：`297B:14F8` 分別數帝國與同盟在這一格的艦隊（跳過艦隊 `+0x00` bit0 有設的），兩邊都非零才設（`docs/re/244`）。`docs/internals/34` 量到進入戰鬥時 `+0x13` 從 8 變 12；`2E54:005D` 拿它當「要不要走 `2E54:16F5`」的入口條件（`docs/re/173`）| confirmed |
| bit3 | **這一格是前線**：`2703:0A48` 數「有幾個鄰居的擁有者跟自己不同」，非零就設（`docs/re/244`）| confirmed |
| bit1 | **這一格這回合發生叛亂**（`056A:0468` → `2703:1789`，`docs/re/245`、`247`）。前置條件是「不是首都、不是無主、而且該陣營在這一格**沒有駐軍**（`+0x28 + 擁有者` 為 0）」，過關之後查統治者提督記錄再擲 `亂數 % 400`。定性的依據是報告訊息表的 `ds:085D`＋`ds:086F`：`〈星系名〉星系　發生叛亂。` 後半段（亂數怎麼判、叛亂的效果）仍未讀 | 強推論 |
| bit4 | **單方面占據**：有一方的艦隊停在不屬於它的星域裡，而另一方沒有艦隊（`056A:0468`，`docs/re/245`）。`2E54:005D` 把它與 bit2 **一起測**（`test byte es:[bx+13], 14h`）當「不能留在這裡」——兩種情形都待不住（`docs/re/196`、`197`）| confirmed |

`+0x11` ＝ 這一格自己的編號、`+0x12` ＝ 擁有者（`docs/re/171` 的兩支都用）。
`+0x24` ＝ **到自己陣營首都的路徑成本**（`docs/internals/26` 那張距離矩陣的
值；無主星域不更新，留著上一次的）。

## 重算時機

`2703:08DE` 先重建路徑表（`2B99:0003`），再對 32 個星域各跑三支：
`2703:0933`（上面這些旗標與 `+0x24`）、`2703:12EB`（`+0x30`／`+0x68`／`+0x70`
的彙總）、`2703:0DA1`（未安定度）。它在**回合結束**、逐格重算擁有者與處理
易主之後跑，勝負判定之前（`docs/re/244`）。路徑表是擁有者的函數，所以這個
順序不能換。
