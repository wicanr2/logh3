## 版面

四個檔各 4,032 bytes ＝ **32 筆 × 126 bytes**，沒有檔頭。

32 筆正好對上 `STRMAP.RGN` 的 32 個星域區塊，名字也對得上遊戲畫面上
印在地圖旁的字（`KASTOROP`、`GANDHALVA`、`ALDEBARAN` 等）。

| 位移 | 內容 |
|---|---|
| +0 起 | Big5（倚天）名稱，`\0` 結束、後面補 0；最長 12 bytes（「艾爾•法西爾」）|
| +18 | **擁有者**：0 ＝ 帝國、1 ＝ 同盟、2 ＝ 無主（`docs/re/17`）|
| +19 起 | 數值欄位，語意未知 |

## 四個版本的差別

`DT8`／`DT9`／`DTA` 是**三格存檔**（第 8／9／10 格，副檔名最後一個字
是槽位編號的十六進位），`DTX` 是新遊戲的樣板
（[`docs/internals/30`](30-save-format.md)）。版面相同、內容不同。
逐位元組比對，**只有 +18 之後會變**，名稱區完全一致。會變的位移：

```
18–24, 26–28, 30, 32–36, 38–41, 48–49, 52–53, 56–57, 60–61, 64–65,
68–69, 72–73, 76–77, 80–81, 84–86, 88–89, 92–93, 96–97, 100–101,
104–106, 108–110, 112–114, 116–118, 124–125
```

從 48 起是很整齊的「每 4 bytes 動 2 bytes」——看起來是一組 u16 陣列
（每個星域對 N 個對象各有一個值，例如與各勢力的關係或各行星的狀態）。
確認要等能進到用得到它的畫面。

## 執行期就是這份記錄

整個檔案載在 `ds:A79C`，一筆 126 bytes。載入的時候**擁有者、行星數、
經濟力與未安定度會重算**，其餘欄位原封不動——拿 S3 那一格存檔
（`STELLAR.DTA`）與載入後的記憶體比，32 × 126 bytes 裡只有 22 個
`+0x7D` 不一樣（`docs/re/41`）。星圖的勢力色直接讀
每一筆的 `+18` 去查 `ds:8BD2` 的「擁有者 → 色號」表（0→色 1 帝國藍、
1→色 12 同盟棕、2→色 3 黑）。首都另外用色 6 重塗。

檔案裡的 `+18` 是陣營原本的疆域（`DTX` 前 16 個 0、後 16 個 1）；
**載入之後會依行星重算**：掃該星域的行星（`PLADAT.DAT`，82 bytes 一筆），
依行星的 `+0x11` 把數量累加到星域記錄的 `+0x16`（帝國）、`+0x17`（同盟）、
`+0x18`（其他），然後

```
同盟 == 0 且 其他 == 0        → 0（帝國）
否則 帝國 == 0 且 其他 == 0   → 1（同盟）
否則                          → 2（無主）
```

796 年 1 月有 10 個星域因此變成無主（`docs/re/17`）。

## 與 `PLADAT.DAT` 的關係

`PLADAT.DAT` 的 64 bytes 檔頭是 32 個 word，**第 k 個就是第 k 個星域有幾顆行星**
（合計 81 ＝ 筆數）。行星在檔案裡按星域順序排，所以第 k 個星域的行星就是
前面數量累加起來那一段。詳見 [`29-planets-and-economy.md`](29-planets-and-economy.md)。

星域記錄裡好幾格其實是「把自己的行星加起來」：擁有者、行星數、防衛力、
**經濟力**都是載入時算出來的，檔案裡的原值當場被蓋掉。

## 執行期星域記錄（`ds:A79C`，32 × 126）的 `+0x13`

**兩支常式各管一半**，只有 bit2 兩邊都寫而且條件相同（`docs/re/245`）：

| 常式 | 先清 | 重填 |
|---|---|---|
| `2703:0933(星域記錄)` | `and 0F2h`（bit0｜bit2｜bit3）| bit0、bit2、bit3 與 `+0x24` |
| `056A:0469`（掃 32 格）| `and 0E9h`（bit1｜bit2｜bit4）| bit1、bit2、bit4 |
| `056A:089D`（易主報告，逐則）| `and 0EFh`（bit4）| 不重填（`docs/re/250`）|

所以 bit5–bit7 兩邊都不動。**執行順序**：`056A:0469` 是命令階段那一串

|---|---|---|

## 叛亂（bit1）的效果

`0374:0556` 讀到 bit1 就呼叫 `2703:1908(星域編號, 0)`：星域 `+0x12` 先寫成 2，
再依未安定度決定翻幾顆行星（`>160` 整格、`>120` 兩顆、其餘一顆），每顆走
`2703:1ADB`（行星 `+0x11` ← 2、經濟力 `+0x1A` 剩三分之二、防衛力 `+0x14` 扣掉
上限 `+0x16` 的三分之一，扣不夠就歸零）。`+0x12` 那一行是暫時的——擁有者每回合
都依行星重算；真正留下來的是行星的 `+0x11`。細節與收據見
[`../re/292`](../re/292-rebellion-decision-and-effect.md)。

`ds:B75C`（32 bytes）是**新遊戲開局的擁有者快照**，只有 `2703:0068` 寫，在
`2703:0000` 那支初始化迴圈裡（同一圈把 `+0x13`／`+0x28`／`+0x29`／
`+0x2C`／`+0x2E` 歸零、依行星重算擁有者，再依擁有者把民心 `+0x7C` 設成
帝國 0／同盟 200／無主 100）。叛亂機率的分母 `已失格數` 就是拿它比現況數出來的。
`2703:0000` 唯一的呼叫者是新遊戲初始化的 `0374:0327`；讀存檔的 `2C5D:061A`
不經過它（`../re/295`），**讀檔之後 `ds:B75C` 仍然是 796 年 1 月開局那一份**
（25 份 S3 起跑的傾印逐位元組相同，[`../re/297`](../re/297-rebellion-garrison-recount-and-rng.md)）。

判定的駐軍閘門（`+0x28 ＋ 擁有者`）讀的是 `2703:0853` 剛重數的值：它在
`056A:000C` 那一串裡緊接在 `056A:0469` 前一步，照艦隊移動之後的位置數
（`../re/297`）。判定一格固定抽十次亂數、擋在閘門的格子一次都不抽，
收據 `rbx297w` 逐格量過。remake：`rules.DecideRebellions`／`rules.Rebel`，
接在 `Game.advanceTurn` 的艦隊移動之後（[`../spec/041`](../spec/041-rebellion.md)）。

## 重算時機

`2703:08DE` 先重建路徑表（`2B99:0003`），再對 32 個星域各跑三支：
`2703:0933`（上面這些旗標與 `+0x24`）、`2703:12EB`（`+0x30`／`+0x68`／`+0x70`
的彙總）、`2703:0DA1`（未安定度）。它在**回合結束**、逐格重算擁有者與處理
易主之後跑，勝負判定之前（`docs/re/244`）。路徑表是擁有者的函數，所以這個
順序不能換。

路徑表另外在新遊戲初始化（`2703:0195`）與座位回合開頭（`04F8:003E`）重建；
未安定度另外由 `090A:0E6D` 在回合中重算好幾次（見上表 `+0x7D`，
[`../re/299`](../re/299-region-unrest-writers-and-recompute.md)）。戰鬥與叛亂效果則由
`0374:03E8` 依星域編號交錯：較小編號戰鬥的艦隊清理先經 `090A:0E6D` 重算，
較大編號星域的 `2703:1908` 才讀新 `+0x7D`（[`../re/310`](../re/310-unrest-battle-region-scan-order.md)、
[`../spec/042`](../spec/042-region-unrest-recompute.md)）。
