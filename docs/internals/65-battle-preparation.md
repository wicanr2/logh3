# 65 — 戰場第一階段的自動補給與修理

事實來源與完整雜湊：[研究367](../re/367-battle-preparation.md)、
[分級指令索引](data/battle-preparation-semantics.json)、[十六案欄位](data/battle-preparation.json)。
只保存解出的規則；原始 dump、資料庫及完整注入 bytes 留在本機。

- **已證實**：先運補艦／行星補彈藥，再修護艦／行星補艦數，重算士氣並即時報告，最後回復防衛力。
- **已證實**：運補艦自動初選半徑取6.4倍速度的整數部分；修護艦取速度×6。
  修護艦後續篩選仍比6.4倍定點半徑，初選排掉者不會重新加入。
- **已證實**：修護艦可修運補艦；自動行星補艦數無手動選取的種類5／6排除。
- **已證實**：同艦隊依分隊序處理，庫存不足時前面的先取。
- **已證實**：行星實際補 `n` 艘時，艘數增加 `n`、該種類32位庫存減 `n`，
  修理上限以16位加 `n` 再以滿編夾限。沒有實際補充時不動修理上限。
- **已證實**：防衛力不足上限才回復；增量為乘積低16位再除100。
  現有值以16位加法回繞再比上限；無主也適用，已超上限原樣保留。
- **已證實**：自動候選採梳狀排序，間距乘10除13，9／10改11，降到1且無交換才返回。
  同艦隊比較分隊序；不同艦隊優先來源艦隊，其他艦隊平手。平手的相對順序可能因交換改變，
  不能使用穩定排序或艦隊槽號序。72案完整清單雙跑相同並符合診斷模型。
- **已證實**：行星補彈藥沿用最後一筆艦艇的來源指標A42E／A430，包含索敵分遣隊；
  補艦數沿用最後一艘修護艦的A440／A442，本次沒有修護艦就保留前值。
  修護艦庫存為0也更新來源。三案行星優先分配已取得原版雙跑。
- **已證實，固定執行器範圍**：兩次正常開機主選單的A42E／A440都是零；
  零來源比較器讀實體位址1，本執行器該byte為0，不能誤解為艦艇池槽0。
- **已證實**：手動運補／修理開始找候選之前保存引數來源；電腦前置修理也有寫入端。
  來源保留後讀的是池槽目前的艦隊byte；明示重用該槽的兩次修理診斷，優先對象隨之改變。
- **已證實**：人類補給與修理結果是右側面板，刷新後自行返回；士氣報告另有等待，
  結束後才接回防衛力回復。這些是原版固定局面雙跑，不是remake整步驗收。
- **已證實，指定入口**：冷開機初始化先清零；注入有效來源後，正常新遊戲初始化、S3讀檔與達希利
  戰場入口保留池身份。三組雙跑完整記憶體／畫面／色盤相同；未涵蓋所有存檔或第二戰場。
- **已證實**：修理目標在艦種與損壞艘數之前印兩列身分，旗艦姓名最多16 bytes；
  其他組依種類7印索敵部隊，或以分隊byte加1印第N部隊。`1629:023B`至`0362`原指令見研究370。
- remake正式第一階段已接`AdvanceBattleTurn`；資源、來源、士氣及防衛力的限定原版比對、
  完整結果面板、正常實行及正式存讀見對拍042。不宣稱整個戰場或八步一致。
