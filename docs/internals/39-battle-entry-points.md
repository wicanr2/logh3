# 39：戰場入口表

打進某個星域的艦隊，開場放在哪一格，是查表決定的，不是算出來的。

## 表在哪

`ds:4B2E` 起是 32 個 far 指標，用**戰場所在的星域編號**索引；
指到的那張表一筆 4 個位元組：

| 位移 | 是什麼 |
|---|---|
| `+0` | 鍵：從哪個星域打進來。等於星域自己 ＝ 本來就在這裡的守方 |
| `+1` | 格欄 |
| `+2` | 格列 |
| `+3` | 觀察到的全部是 0 |

`0xFF` 結尾。查法在 `113A:0D2C`（`docs/re/84`）：照順序找第一個鍵
相同的，找到就把格欄與格列寫回呼叫端，回 1；走到 `0xFF` 回 0。

找到之後 `297B:0AFF`／`0B0D` 把它換成艦隊記錄的座標：

```
+0x5C  X ＝ 格欄 × 16
+0x5E  Y ＝ 格列 × 20
```

16 與 20 就是戰場圖塊的寬高（`docs/internals/36`）。

## 表的內容

倒出來放在 `docs/internals/data/battle-entry-points.json`
（`tools/scripts/deploy_table.py`）。每個星域有 2 到 5 個入口，
格座標全部落在 128×102 的邊緣一帶——入口在戰場的邊上。

鍵的集合與星域相鄰圖（`docs/internals/data/star-graph.json`）對得起來：
每個鍵不是該星域的鄰域，就是星域自己。兩張表的來源完全不同
（一張是 `ds:4B2E` 的表，一張是 EMS 裡的中點矩陣），所以這是
一次獨立的交叉驗證。

收據 `s3ai6` 那一場在星域 26 打，帝國第 13 艦隊從星域 28 進來，
表上寫格 (26,14)，量到的座標是 (416,280) ＝ (26×16, 14×20)。

## 分隊怎麼散開

艦隊放好之後，它的分隊排在旗艦周圍的正交格點上，間距 22–23
（`docs/internals/38`）。朝向怎麼決定還沒解——`297B:0B9D` 會拿
「艦隊相對 (1016,1012) 的位移」呼叫 `2BE1:011D`，把回來的位元組
填進 `+0x4A`／`+0x4B`／`+0x4C`，那三處看起來是朝向，但還沒對上
分隊實際散開的方向。
