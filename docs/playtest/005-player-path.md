# 收據 005 — 正常玩家路徑（主選單 → 防拷問答 → 遊戲本體）

比較等級：**`same-state`**，未核准差異 **0**（三個畫面各自逐位元組一致）。

這一份與 001／003／004 的差別是**怎麼到達那個畫面**：那三份是各自把
畫面畫出來比對，這一份是從主選單開始，用滑鼠與鍵盤一步步走過去，
每一步的畫面都要對得上。診斷用的 direct-entry 不能代替這條路徑。

## 序列

```
tools/go.sh run ./cmd/play -script "move 300 170; click; type 138; enter; click 448 330"
```

| 步 | 輸入 | 狀態 | 對照收據 | 差異 |

| 1 | `move 300 170` | 主選單（第 0 列反白） | `r0` | 0 / 307,200 |
| 2 | `click` | 防拷問答 | `cb1` | 0 / 307,200 |
| 3 | `type 138` | 防拷問答（輸入中） | — | 畫面不變（見未確認） |
| 4 | `enter` | 遊戲本體 | `key1` | 0 / 307,200 |
| 5 | `click 448 330` | 船艦訂造報告 | `ship1` | 0 / 307,200 |

回歸測試：`internal/game/game_test.go` 的 `TestPlayerPathReachesGame`。

## 狀態機

`internal/game` 只做「輸入 → 狀態 → 畫面」，不碰渲染後端；畫面永遠是
640×480 的色號陣列，所以同一份邏輯可以無頭跑對拍，也可以接上任何顯示層。

規則來自逆向：

- 主選單的點擊要落在某一列上才算數（`docs/re/08`）。
- 防拷問答的答案是那張照片對應的 `ADMIRAL.DT*` 記錄的 `+11`
  （占領能力，`docs/internals/08`）；照片編號在畫面規格裡。
