# 012 — 戰場索敵 55 筆欄位對照

日期：2026-09-14

比較等級：`same-state`（只裁決一輪索敵後 55 筆在場分隊的 `+0x17` 與
`+0x16` bit0；前態由同一份收據的「本輪已看到」位元反推，不宣稱整張畫面
或跨多輪亂數流程一致）。

## 原版輸入

- 傾印：`workplace/s3fltmove.bin`，1,048,576 bytes，線性位址 0 起。
- SHA-256：`f365c46fa6087590b2da4db001109e457e6d604218a73f946829297aac3e9758`。
- 來源與注入限制：`docs/re/290` 的「注入過的收據要另外看」；其中艦隊 28
  旗艦的分隊 `+0x00` 被改成 0，所以它依原版 `2526:01FE` 真的成為帝國側
  觀測者。fixture 保留這個分隊欄位，不用艦隊陣營替換。

測試只摘錄不具美術或音訊內容的數值事實：在場 55 筆分隊的艦隊、組號、
陣營、艦種、目的地、`+0x1E` bit7、`+0x16` bit0 與 `+0x17`，以及三顆
行星的擁有者、座標與防衛力；原版 1 MB dump 不加入 Git。

## 比較方法

收據切在回合末索敵之後、下一輪衰減之前。對每一筆：

- `+0x16 bit0 = 1`：本輪剛被看到；索敵前 `Detail = 最終 +0x17 − 1`；
- `+0x16 bit0 = 0`：本輪沒有升級；索敵前 `Detail = 最終 +0x17`。

以上只反推 `UpdateSpotting` 的直接輸入，不拿它證明前一輪衰減；衰減另由
`TestSpottingRiseAndDecay` 逐狀態核對。把 55 筆前態與三顆行星交給 remake
後，逐筆比較最終 `Detail` 與 `Seen`。

## 結果

`TestSpottingMatchesS3FleetMoveReceipt` 的 55／55 筆一致：

- 原版視野內的一般敵方分隊各升一級；同輪多個觀測者沒有重複升級；
- 五支艦隊的旗艦以 200 為半徑，已放出的艦種 7 偵察隊以 250 為半徑；
- 三顆行星依防衛力得到 114、152、188 的半徑；
- `+0x1E bit7` 設起來的五筆偵察隊保持 `Detail=0`、`Seen=false`；
- 艦隊 31 的組 0–2 從 2 升到 3 並得到 `DetailHold=2`，組 3–6 從 1
  升到 2，與 `docs/re/290` 的原版分布相同。

同批規則測試另涵蓋視野外衰減、層級 3 的停留輪數、打有主行星立即揭露，
以及 AI 第 7 回合起完全失明時的六輪揭露。命令：

```text
./tools/go.sh test ./internal/rules -count=1 -run 'TestSpotting'
./tools/go.sh test ./internal/game -count=1 -run 'Battle|Scout'
```

兩者均通過。主觀可讀性、動畫感受與實機平台觀察不在本收據範圍。
